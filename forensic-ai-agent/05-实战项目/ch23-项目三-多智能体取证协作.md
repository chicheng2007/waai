## 23.1 为什么需要多智能体

单个 Agent 有能力上限：

- **上下文有限**：一个人记不下所有信息；
- **专业有限**：一个 Agent 很难同时精通日志、样本、内存、网络；
- **视角单一**：容易陷入自己的思路。

多智能体（Multi-Agent）借鉴"团队协作"：让不同专长的 Agent 分工，各司其职，然后协作汇总。就像真实的取证团队——有人查日志，有人看样本，有人写报告，有人做总协调。

**优势**：

1. **专业化**：每个 Agent 专注一个领域；
2. **并行**：多个任务同时进行；
3. **交叉验证**：不同 Agent 互相校验，减少错误；
4. **可扩展**：加一个专家 Agent 就能扩展能力。

## 23.2 设计取证团队

我们设计一个"虚拟取证团队"，四个角色：

| 角色 | 职责 | 工具/能力 |
|---|---|---|
| **协调员（Coordinator）** | 分解任务、分配、汇总 | 规划能力（ch19） |
| **日志分析员（Log Analyst）** | 分析日志，找异常 | 项目一的工具 |
| **样本分析员（Malware Analyst）** | 分析恶意样本 | 项目二的工具 |
| **报告员（Reporter）** | 整合发现，生成报告 | 报告生成（ch21） |

工作流程：

```
协调员接到案件 → 分解任务
  → 日志分析员分析日志 → 返回发现
  → 样本分析员分析样本 → 返回发现
  → 协调员汇总发现
  → 报告员生成最终报告
```

## 23.3 用 AutoGen 实现

AutoGen 是微软的多智能体框架，适合实现"对话协作"式多 Agent。

### 安装

```bash
pip install autogen-agentchat autogen-ext[openai]
```

### 定义 Agent

```python
from autogen import AssistantAgent, UserProxyAgent

config = [{
    "model": "local-model",
    "base_url": "http://localhost:1234/v1",
    "api_key": "not-needed"
}]

# 协调员
coordinator = AssistantAgent(
    name="coordinator",
    system_message="你是取证团队协调员。分解任务、分配、汇总各方发现。",
    llm_config={"config_list": config}
)

# 日志分析员
log_analyst = AssistantAgent(
    name="log_analyst",
    system_message="你是日志分析专家。分析日志找异常，用grep_log和analyze_log工具。",
    llm_config={"config_list": config}
)

# 样本分析员
malware_analyst = AssistantAgent(
    name="malware_analyst",
    system_message="你是恶意软件分析专家。分析样本静态特征。",
    llm_config={"config_list": config}
)

# 报告员
reporter = AssistantAgent(
    name="reporter",
    system_message="你是报告撰写专家。整合所有发现，生成结构化取证报告。",
    llm_config={"config_list": config}
)

# 用户代理（代表用户发起任务）
user = UserProxyAgent(
    name="user",
    human_input_mode="NEVER",  # 自动化运行
    max_consecutive_auto_reply=10
)
```

### 编排对话

```python
# 启动协作
user.initiate_chat(
    coordinator,
    message="分析星海案：starsea_firewall.log 和 samples/suspicious.exe"
)
```

AutoGen 的 Agent 之间通过对话协作：协调员发言，其他 Agent 响应，互相传递发现。你可以观察它们的"群聊"过程。

## 23.4 用 CrewAI 实现（另一种方式）

CrewAI 更强调"角色 + 任务 + 流程"：

```python
from crewai import Agent, Task, Crew

# 定义 Agent（带角色、目标、背景）
log_analyst = Agent(
    role="日志分析员",
    goal="从日志中发现所有异常事件和可疑IP",
    backstory="你是一个有10年经验的日志分析专家，擅长从海量日志中找线索。"
)

malware_analyst = Agent(
    role="样本分析员",
    goal="分析恶意样本的特征和行为",
    backstory="你是恶意软件分析专家，精通静态分析和逆向工程。"
)

reporter = Agent(
    role="报告员",
    goal="整合所有发现生成专业报告",
    backstory="你是取证报告撰写专家，擅长把技术发现写成清晰的报告。"
)

# 定义任务
task1 = Task(description="分析 starsea_firewall.log", agent=log_analyst)
task2 = Task(description="分析 samples/suspicious.exe", agent=malware_analyst)
task3 = Task(description="整合发现生成报告", agent=reporter)

# 组建团队
crew = Crew(agents=[log_analyst, malware_analyst, reporter],
            tasks=[task1, task2, task3])
result = crew.kickoff()
```

CrewAI 的优势是"角色感"强，代码清晰，适合模拟真实团队分工。

## 23.5 多智能体的挑战

多智能体不是万能的，有明显挑战：

1. **成本爆炸**：多个 Agent 多轮对话，token 消耗是单 Agent 的数倍；
2. **沟通噪音**：Agent 之间可能说废话、重复、跑题；
3. **错误传播**：一个 Agent 的错误会被其他 Agent 当作事实继续传播；
4. **调试困难**：多个 Agent 交互，出问题难定位；
5. **不确定性**：结果可能每次不同。

**应对**：

- 设置明确的角色边界和终止条件；
- 加"协调员"把控流程；
- 关键发现交叉验证（不同 Agent 独立判断，结果一致才采信）；
- 保留完整对话记录，方便审计和调试。

## 23.6 交叉验证机制

多智能体的一个重要价值是交叉验证。实现思路：

```python
def cross_validate(finding, agents):
    """让多个 Agent 独立判断同一发现是否可信"""
    votes = []
    for agent in agents:
        result = agent.check(finding)  # 让每个 Agent 独立判断
        votes.append(result)
    # 多数投票
    return sum(votes) > len(votes) / 2
```

比如日志分析员发现"IP 203.0.113.5 可疑"，让样本分析员也从样本里找这个 IP，两边都确认才算数。这能减少单一 Agent 的误判。
