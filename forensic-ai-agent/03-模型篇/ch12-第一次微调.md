## 12.1 从试跑到正式训练

ch11 我们用 1000 条数据试跑，验证了环境。现在放开限制，用完整数据训练。

修改配置：

```yaml
# 把测试配置改成正式配置
max_samples: null              # 放开，用全部数据
cutoff_len: 1024
per_device_train_batch_size: 2 # 显存够的话加大
gradient_accumulation_steps: 8
num_train_epochs: 3.0          # 训练 3 轮
save_steps: 200
eval_steps: 200
output_dir: saves/starsea_lora_v1
```

然后在云端（或显存够的本地）执行：

```bash
llamafactory-cli train starsea_lora.yaml
```

## 12.2 读懂训练日志

训练时终端会不断输出信息，新手容易看晕。重点看这几项：

```text
{"loss": 1.234, "gradient_norm": 0.5, "learning_rate": 0.0002, "epoch": 0.5}
```

| 字段 | 含义 | 健康的表现 |
|---|---|---|
| `loss` | 损失值，越低越好 | 稳步下降 |
| `learning_rate` | 当前学习率 | 按计划变化（warmup 后上升再下降） |
| `epoch` | 训练进度 | 从 0 到 3 |
| `gradient_norm` | 梯度范数 | 稳定，不爆炸 |

**loss 下降**是最核心的信号。如果 loss 一直不降，说明有问题：

- 学习率太小 → 调大；
- 数据有问题 → 检查格式；
- 模型没真正训练 → 检查 LoRA 配置。

如果 loss 降到底后又反弹，可能过拟合了——ch14 讲怎么处理。

### 训练多长时间

取决于数据量和硬件。我们的数据约 1.8 万条，7B 模型 + QLoRA，在 3090 上大概几十分钟到几小时。**耐心等，别急着中断。**

---

## 12.3 训练中画图看趋势

配置里写了 `plot_loss: true`，训练完会在输出目录生成 `training_loss.png`。看看曲线：

- **理想**：loss 平滑下降，最后趋于平缓；
- **震荡太大**：学习率可能太高，调小；
- **不下降**：检查数据和配置；
- **先降后升**：可能过拟合，减少 epoch。

这张图是判断训练好坏的第一手资料，一定要看。

---

## 12.4 保存了什么

训练完，`saves/starsea_lora_v1/` 目录里主要有：

| 文件 | 内容 |
|---|---|
| `adapter_model.safetensors` | **LoRA 补丁权重**（核心产物） |
| `adapter_config.json` | LoRA 配置 |
| `training_args.bin` | 训练参数记录 |
| `trainer_state.json` | 训练状态（loss 历史等） |
| `training_loss.png` | loss 曲线图 |

注意：我们保存的是**LoRA 补丁**，不是完整模型。补丁很小（几十 MB），但要配合原模型使用。

## 12.5 加载模型对话

### 方式一：用 LLaMA-Factory 推理

```bash
llamafactory-cli chat saves/starsea_lora_v1
```

但这样需要指定原模型。更完整的方式：

```bash
llamafactory-cli chat \
  --model_name_or_path /path/to/Qwen2.5-7B-Instruct \
  --adapter_name_or_path saves/starsea_lora_v1 \
  --template qwen \
  --finetuning_type lora
```

然后输入一条日志，看它的回答。

### 方式二：用 Python 加载

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import PeftModel

base_path = "/path/to/Qwen2.5-7B-Instruct"
adapter_path = "saves/starsea_lora_v1"

tokenizer = AutoTokenizer.from_pretrained(base_path)
model = AutoModelForCausalLM.from_pretrained(
    base_path, device_map="auto", torch_dtype="auto"
)
model = PeftModel.from_pretrained(model, adapter_path)

# 对话
messages = [
    {"role": "system", "content": "你是专业的数字取证分析助手。"},
    {"role": "user", "content": "分析这段日志：\n2026-10-15 02:03:11 DENY 203.0.113.5->10.0.2.10:23 size=60"}
]
text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
inputs = tokenizer([text], return_tensors="pt").to(model.device)
outputs = model.generate(**inputs, max_new_tokens=200)
print(tokenizer.decode(outputs[0][inputs.input_ids.shape[1]:], skip_special_tokens=True))
```

### 方式三：合并成完整模型（便于部署）

如果想得到一个独立的模型（不依赖原模型 + 补丁）：

```bash
llamafactory-cli export \
  --model_name_or_path /path/to/Qwen2.5-7B-Instruct \
  --adapter_name_or_path saves/starsea_lora_v1 \
  --template qwen \
  --finetuning_type lora \
  --export_dir saves/starsea_merged \
  --export_size 2
```

合并后的模型可以直接部署（ch24 讲）。

## 12.6 对比微调前后

这是最有成就感的时刻。同一个问题，问原模型和微调模型：

**问题**：

```
分析这段日志：
2026-10-15 02:03:11 DENY 203.0.113.5->10.0.2.10:23 size=60
```

**原模型可能回答**：

> 这是一条被拒绝的连接记录。来源 IP 尝试连接目标 IP 的 23 端口。这可能是正常的网络活动，也可能表示某种安全问题，建议进一步分析。

（泛泛而谈，没有明确结论）

**微调后应该回答**：

> 结论：端口扫描。依据：来源 IP 203.0.113.5 访问 23 端口（SSH/Telnet 相关），属于外部地址，短时间内单端口连接。建议：封禁来源 IP 并检查目标主机开放端口。

（按三段式，结论明确，有依据和建议）

这个对比直观展示了微调的价值——**模型学会了你教的思考方式和表达格式**。

## 12.7 如果效果不好

第一次微调效果不理想很正常。检查清单：

1. **数据量够吗**：1.8 万条够入门，但要更好效果需要更多；
2. **数据质量好吗**：回答有没有错误？格式统一吗？
3. **训练充分吗**：loss 降到底了吗？epoch 够吗？
4. **超参数合适吗**：学习率、rank 要不要调？ch14 讲；
5. **是不是过拟合**：验证集表现如何？ch13 讲。

**微调是个迭代过程**：训练 → 评估 → 调整 → 再训练。很少一次成功。

## 12.8 动手任务

1. **完成正式训练**：用全部数据训练 3 个 epoch，保存模型。
2. **看 loss 曲线**：打开 `training_loss.png`，描述曲线形状。
3. **对比测试**：同一条日志，分别问原模型和微调模型，记录两者回答的差异。
4. **测 10 条**：从验证集抽 10 条，看微调模型的回答是否符合三段式格式。
5. **保存成果**：把模型、配置、loss 图、对比结果都备份好。

## 12.9 小结

- 正式训练：放开 max_samples，用全部数据，训练 3 个 epoch；
- 看训练日志：重点看 loss 是否稳步下降；
- 看 loss 曲线：判断训练是否健康；
- 保存的是 LoRA 补丁（小），配合原模型使用；
- 三种用法：LLaMA-Factory 对话、Python 加载、合并导出；
- **对比微调前后**，直观感受微调价值；
- 效果不好很正常，微调是迭代过程。
