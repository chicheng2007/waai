## 14.1 显存溢出（OOM）

**症状**：训练刚开始就报 `CUDA out of memory`。

**原因**：显存不够，模型 + 梯度 + 优化器塞不下。

**解决办法**（按优先级）：

1. 减小 `per_device_train_batch_size`（如 2 → 1）；
2. 减小 `cutoff_len`（如 1024 → 512）；
3. 减小 `lora_rank`（如 16 → 8）；
4. 增大 `gradient_accumulation_steps`（保持等效 batch 不变）；
5. 开启 `gradient_checkpointing`（用时间换显存）；
6. 确认用了 4bit 量化（`quantization_bit: 4`）；
7. 关掉其他占显存的程序（如 LM Studio）。

配置示例：

```yaml
per_device_train_batch_size: 1
gradient_accumulation_steps: 16
cutoff_len: 512
lora_rank: 8
gradient_checkpointing: true
```

**经验**：8GB 显卡跑 7B QLoRA，`batch=1, cutoff=512, rank=8` 基本不会 OOM。慢一点，但能跑。

## 14.2 loss 不下降

**症状**：训练很久，loss 一直在 2.0 左右晃，不降。

**排查**：

1. **数据格式对吗**：检查 JSONL 是否合法，`messages` 角色对不对；
2. **数据集注册对吗**：`dataset_info.json` 的字段映射是否正确；
3. **学习率太小**：2e-4 太低？试 5e-4；
4. **模板对吗**：`template: qwen` 是否匹配模型；
5. **LoRA  target 对吗**：`lora_target` 是否包含了正确的层名。

**快速验证**：拿 1 条数据，手动跑一次前向传播，看输出是不是合理的文本。如果输出乱码，说明模型加载或模板有问题。

---

## 14.3 过拟合

**症状**：训练集 loss 很低，但验证集表现差，回答僵硬、只会背原话。

**解决办法**：

1. **减少 epoch**：3 → 2 或 1；
2. **降低 rank**：16 → 8（减少模型容量）；
3. **增加数据**：用 ch08 的方法扩充数据多样性；
4. **加 dropout**：在 LoRA 配置里加 `lora_dropout: 0.05`；
5. **早停**：监控验证集 loss，不好就停。

配置：

```yaml
num_train_epochs: 2.0
lora_rank: 8
lora_dropout: 0.05
```

## 14.4 回答出现幻觉

**症状**：模型回答里出现日志中没有的信息，比如编造不存在的 IP 或结论。

**原因**：训练数据里有错误回答，或者模型本身倾向编造。

**解决办法**：

1. **检查训练数据**：回答是否都有输入依据？删掉"无中生有"的样本；
2. **强化"依据"格式**：训练数据里要求引用输入中的具体内容；
3. **降低 temperature**：推理时用 0.1 以下；
4. **加 RAG**：让模型基于检索到的真实内容回答（ch19）；
5. **提示词约束**：在 system 提示里明确"只基于给定日志回答，不知道就说不知道"。

> 记住：微调不能消除幻觉，只能减轻。**最终防线是人工审核和工具验证**（ch02 红线四）。

## 14.5 格式不符合预期

**症状**：模型不按"结论/依据/建议"回答，输出自由散漫。

**原因**：训练数据里格式不统一，或者格式样本太少。

**解决办法**：

1. 检查训练数据：所有回答是否严格三段式？
2. 增加格式一致的样本比例；
3. 在 system 提示里强调格式；
4. 训练时增大这类样本的权重（多复制几份）。

## 14.6 关键超参数怎么调

### 学习率（learning_rate）

LoRA 常用 1e-4 ~ 2e-4。

- 太小：学不动，loss 不降；
- 太大：不稳定，loss 震荡甚至爆炸；
- **建议**：先用 2e-4，不行再调。

### LoRA rank（r）

常用 8 / 16 / 32。

- 大：能力强，但占显存、易过拟合；
- 小：省显存、不易过拟合，但能力有限；
- **建议**：取证风格类任务，16 足够；显存紧张用 8。

### epoch

常用 2-3。

- 少：学不充分；
- 多：过拟合；
- **建议**：先 2，看验证集，不够再加。

### batch size + 梯度累积

显存小就用小 batch + 大累积：

```yaml
per_device_train_batch_size: 1
gradient_accumulation_steps: 16   # 等效 batch 16
```

**等效 batch = batch_size × 累积步数**。保持等效 batch 在 16 左右比较稳。

### cutoff_len

单条样本最大长度。太长浪费显存，太短截断信息。

- 我们的日志样本短，512-1024 够用；
- 如果样本长，用 2048，但显存吃紧。

## 14.7 调参的正确姿势

不要一次调多个参数——你不知道是哪个起了作用。

**科学方法**：

1. 固定其他参数，只调一个；
2. 每次实验记录配置和结果（用表格或 MLflow）；
3. 小数据快速验证，再全量训练；
4. 一次只改一个变量，观察指标变化。

推荐做一个实验记录表：

| 实验 | rank | lr | epoch | 准确率 | 召回率 | 备注 |
|---|---|---|---|---|---|---|
| v1 | 16 | 2e-4 | 3 | 0.88 | 0.81 | 基线 |
| v2 | 8 | 2e-4 | 3 | 0.86 | 0.80 | rank 小，略降 |
| v3 | 16 | 1e-4 | 3 | 0.87 | 0.79 | lr 小，无提升 |

这样一目了然。

## 14.8 踩坑速查表

| 症状 | 最可能原因 | 首选解法 |
|---|---|---|
| OOM | 显存不够 | 降 batch/cutoff/rank |
| loss 不降 | 数据/学习率问题 | 查数据、调大 lr |
| loss 震荡 | lr 太大 | 调小 lr |
| 过拟合 | 训练过度 | 减 epoch、降 rank |
| 幻觉 | 数据有误 | 清洗数据、加约束 |
| 格式乱 | 数据格式不一 | 统一格式样本 |
| 模型不加载 | 路径/版本问题 | 查路径、重装依赖 |

## 14.9 动手任务

1. **故意制造 OOM**：把 batch 设很大跑一次，观察报错，然后用 14.1 的方法修复。
2. **超参实验**：固定其他参数，分别用 rank=8 和 rank=16 训练，对比效果。
3. **建实验记录表**：用表格记录每次实验的配置和结果。
4. **幻觉排查**：找 10 条模型回答，检查有没有幻觉，分析原因。
5. **整理踩坑笔记**：把你遇到的问题和解法记下来，形成自己的排障手册。

---

## 14.10 小结

- OOM：降 batch/cutoff/rank，加梯度累积和 checkpointing；
- loss 不降：查数据格式、调学习率、查模板；
- 过拟合：减 epoch、降 rank、加 dropout、增数据；
- 幻觉：清洗数据、格式约束、降低 temperature、人工审核；
- 关键超参：lr（1e-4~2e-4）、rank（8~16）、epoch（2~3）、等效 batch（16）；
- **调参要一次只改一个变量，做好实验记录**。
