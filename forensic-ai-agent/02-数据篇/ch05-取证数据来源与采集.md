## 5.1 为什么数据比算法更重要

在 AI 圈有句话："数据是新的石油。"这句话在取证 AI 上尤其成立。

原因很简单：取证是个高度专业的领域，通用大模型虽然读了很多文本，但它没读过**你们公司的日志格式**、没见过**你们行业的攻击模式**。要让它懂行，就得喂它专业数据。

一个残酷的现实是：**同样的算法，数据质量差十倍，效果可能差几十倍**。很多时候，与其花一周调模型参数，不如花一天把数据整理干净。这也是为什么本书把"数据篇"放在"模型篇"之前——先有好数据，再谈好模型。

数据采集要解决三个问题：

1. **去哪找**（来源）；
2. **怎么拿**（采集方法）；
3. **能不能用**（合法性）。

一个都不能少。

## 5.2 取证数据的四类来源

### 来源一：公开数据集（最适合入门）

已经有人整理好的、可以直接下载使用的取证数据集。这是新手的第一选择。

| 数据集 | 内容 | 适合做什么 | 获取方式 |
|---|---|---|---|
| CIC-IDS2017 | 网络入侵检测流量 | 异常流量分类 | 加拿大网络安全研究所官网 |
| UNSW-NB15 | 网络流量 + 攻击类型标注 | 流量分类 | 澳大利亚 UNSW 官网 |
| UGR16 | 网络流量攻击数据集 | 流量分析 | 公开学术数据集 |
| picoCTF / HackTheBox | CTF 题目与解题记录 | 练习题、Agent 训练 | 各平台官网 |
| CTF-Dojo（amazon-science/CTF-Dojo） | 658 道容器化 CTF 题 + 轨迹 | Agent 轨迹训练 | GitHub |
| Apache/Nginx 公开日志样本 | Web 访问日志 | 日志解析练习 | 各开源社区 |

**本书主要用哪几个？**

- 日志分析：用合成日志 + 公开 Web 日志样本；
- Agent 轨迹：参考 CTF-Dojo 的思路（这正是我们之前那篇报告的内容）；
- 星海案：用我们自己合成的数据集（5.4 节讲）。

> **出处提示**：CTF-Dojo 数据集来自论文 *Training Language Model Agents to Find Vulnerabilities with CTF-Dojo*（arXiv:2508.18370v2），详见本仓库 [reference/CTF-Dojo 论文解读.md](../reference/CTF-Dojo-论文解读.md)。

### 来源二：自己合成的数据（最可控）

公开数据集虽好，但不一定匹配你的场景。这时候可以自己合成。

合成的意思是用脚本或大模型生成"假但真实"的数据：

- 用脚本生成模拟的防火墙日志（正常流量 + 注入异常）；
- 用大模型生成"日志片段 + 分析结论"的问答对；
- 用规则造出带标签的样本。

**优点**：标签准确、量可控、完全合法。
**缺点**：可能与真实数据有差距（domain gap）。

本书的"星海案"主要靠合成数据。ch08 会详细讲数据合成方法。

### 来源三：脱敏的真实数据（最真实，但要小心）

如果你在实习或工作中有机会接触真实日志，脱敏后可以用。脱敏包括：

- 替换真实 IP 为保留地址（如 192.168.x.x、10.x.x.x）；
- 替换用户名、主机名、邮箱为假名；
- 去掉可能暴露身份的字段。

**红线**：脱敏必须彻底，且要有数据使用授权。脱敏不彻底的数据泄露出去，比不用它还糟糕。

### 来源四：公开威胁情报（补充用）

一些公开平台提供 IOC（失陷指标，如恶意 IP、域名、文件哈希）：

- AbuseIPDB、VirusTotal（部分公开）；
- MITRE ATT&CK（攻击手法知识库）；
- 各类安全厂商的威胁报告。

这些数据适合做"知识库"，配合 RAG 使用（ch19 会讲）。

## 5.3 采集的合法性：再说一遍红线

第二章讲过红线，这里针对数据采集再强调一次，因为这是最容易踩坑的地方。

| 做法 | 是否合法 | 说明 |
|---|---|---|
| 下载公开数据集 | ✅ 合法 | 遵守数据集许可协议即可 |
| 自己合成数据 | ✅ 合法 | 完全没问题 |
| 脱敏后的自有日志 | ✅ 一般合法 | 需彻底脱敏 + 有授权 |
| 爬取他人系统日志 | ❌ 违法 | 未经授权的访问 |
| 用真实用户信息不脱敏 | ❌ 违法 | 违反个人信息保护法 |
| 把客户数据传上公网模型 API | ⚠️ 高风险 | 可能违反保密协议 |

**特别提醒最后一条**：很多人图省事，把公司日志直接贴给 ChatGPT / 在线大模型分析。这可能违反公司的保密规定，甚至泄露客户隐私。本书强调**本地模型**的价值——数据不出本机，就没有这个风险。这也是为什么我们花了一整章讲本地部署。

## 5.4 动手：为"星海案"合成第一批日志

 theory 讲完了，动手。我们来给"星海案"合成一份模拟的防火墙日志。这份日志会在后面的章节反复使用。

### 设计数据分布

真实日志里，绝大多数是正常流量，极少数是异常。我们按这个比例合成：

- 正常流量：9500 条
- 异常流量：500 条（占比 5%）

异常里再细分：

- 端口扫描：200 条
- 异常时间登录：150 条
- 大流量外传：100 条
- 登录爆破：50 条

### 写合成脚本

创建一个文件 `generate_logs.py`：

```python
import random
import datetime

random.seed(42)  # 固定种子，保证可复现

# 正常 IP 池
normal_ips = [f"10.0.1.{i}" for i in range(2, 50)]
external_ips = [f"203.0.113.{i}" for i in range(1, 30)]

def normal_event(t):
    """正常流量：工作时间、常见端口、小流量"""
    src = random.choice(normal_ips)
    dst = random.choice(["10.0.2.10", "10.0.2.20"])
    port = random.choice([80, 443, 53])
    size = random.randint(200, 5000)
    return f"{t} ALLOW {src}->{dst}:{port} size={size}"

def port_scan(t):
    """端口扫描：同一来源短时间访问大量端口"""
    src = random.choice(external_ips)
    ports = random.sample(range(1, 1024), 20)
    return " | ".join(
        f"{t} DENY {src}->10.0.2.10:{p} size=60" for p in ports
    )

def odd_hour_login(t):
    """异常时间登录：凌晨的外部登录"""
    src = random.choice(external_ips)
    return f"{t} ALLOW {src}->10.0.2.10:22 size=800 action=login"

def large_transfer(t):
    """大流量外传"""
    src = random.choice(normal_ips)
    dst = random.choice(external_ips)
    return f"{t} ALLOW {src}->{dst}:443 size={random.randint(50_000_000, 500_000_000)}"

def brute_force(t):
    """登录爆破：同一 IP 多次失败"""
    src = random.choice(external_ips)
    return " | ".join(
        f"{t} DENY {src}->10.0.2.10:22 size=400 action=login result=fail"
        for _ in range(10)
    )

# 生成时间基准
base = datetime.datetime(2026, 10, 15, 0, 0, 0)

lines = []
# 正常流量
for i in range(9500):
    t = base + datetime.timedelta(seconds=i * 8)
    lines.append(normal_event(t.strftime("%Y-%m-%d %H:%M:%S")))

# 异常流量
for i in range(200):
    t = base + datetime.timedelta(hours=2, minutes=i)
    lines.append(port_scan(t.strftime("%Y-%m-%d %H:%M:%S")))
for i in range(150):
    t = base + datetime.timedelta(hours=3, minutes=i)
    lines.append(odd_hour_login(t.strftime("%Y-%m-%d %H:%M:%S")))
for i in range(100):
    t = base + datetime.timedelta(hours=4, minutes=i)
    lines.append(large_transfer(t.strftime("%Y-%m-%d %H:%M:%S")))
for i in range(50):
    t = base + datetime.timedelta(hours=5, minutes=i)
    lines.append(brute_force(t.strftime("%Y-%m-%d %H:%M:%S")))

random.shuffle(lines)
with open("starsea_firewall.log", "w") as f:
    f.write("\n".join(lines))

print(f"生成 {len(lines)} 条记录")
```

运行：

```bash
python generate_logs.py
```

你会得到一个约 1MB 的日志文件，里面混着正常和异常流量。**这就是星海案的原始数据。**

### 为什么用保留 IP？

脚本里用了 `10.x.x.x` 和 `203.0.113.x`——这些都是**文档/测试专用地址段**（RFC 5737），不会对应真实主机。这是合成数据的基本规范：**永远不要用真实公网 IP 当假数据**，避免误伤或隐私风险。

## 5.5 采集 checklist

每次采集数据，对照这个清单：

- [ ] 数据来源合法吗？有授权吗？
- [ ] 敏感信息脱敏了吗？（IP、用户名、邮箱、账号）
- [ ] 记录了数据的出处和采集时间吗？
- [ ] 数据格式统一吗？（时间戳格式、字段分隔符）
- [ ] 有标签吗？标签准确吗？
- [ ] 存到安全的地方了吗？（不要传公网）

## 5.6 动手任务

1. **跑通合成脚本**：把上面的代码保存运行，生成 `starsea_firewall.log`，看看前 20 行长什么样。
2. **找一份公开数据集**：去 UCI 或 Kaggle 搜 "intrusion detection" 或 "firewall log"，下载一个小数据集，看看它的格式。
3. **写采集记录**：为你的数据建一个 `DATA.md`，记录每份数据的来源、采集时间、用途、许可协议。养成习惯，后面会感谢自己。
4. **脱敏练习**：找一段带 IP 和用户名的文本（可以自己编），写个脚本把它们替换成假值。

## 5.7 小结

- 数据比算法更重要，取证 AI 尤其如此；
- 四类数据源：公开数据集、自己合成、脱敏真实数据、公开威胁情报；
- 新手首选公开数据集 + 自己合成，最安全可控；
- **合法红线**：不爬他人系统、不脱敏不传播、不把敏感数据传公网模型；
- 动手合成了"星海案"的防火墙日志，用保留 IP 段，固定随机种子保证可复现；
- 养成记录数据出处的习惯（DATA.md）。
