# ch17 函数调用与工具使用

> **本章目标**：掌握 Function Calling（函数调用）——让大模型能调用外部工具的机制。你会学会定义工具、让模型决定是否调用、执行工具并把结果喂回模型。这是 Agent 的"手脚"。

## 17.1 什么是函数调用

大模型本身只能"说话"（生成文本），不能"做事"（读文件、执行命令）。函数调用（Function Calling）就是给模型一组工具的定义，让它能输出"我要调用某个工具，参数是这些"，然后程序执行工具，把结果返回给模型。

流程：

```
1. 你告诉模型有哪些工具可用（工具定义）
2. 模型判断要不要调用、调哪个、参数是什么
3. 你的程序执行这个工具
4. 把执行结果返回给模型
5. 模型基于结果继续回答
```

关键：**模型不执行工具，它只是"提出请求"**。真正的执行在你的代码里。这样安全、可控。

---

## 17.2 定义工具

工具定义是一个 JSON Schema，描述工具的名字、作用、参数。以取证场景为例：

```python
tools = [
    {
        "type": "function",
        "function": {
            "name": "grep_log",
            "description": "在日志文件中搜索关键词，返回匹配的行",
            "parameters": {
                "type": "object",
                "properties": {
                    "file": {"type": "string", "description": "日志文件路径"},
                    "pattern": {"type": "string", "description": "搜索关键词或正则"}
                },
                "required": ["file", "pattern"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "analyze_log_line",
            "description": "用取证模型分析单条日志，返回三段式分析",
            "parameters": {
                "type": "object",
                "properties": {
                    "log_line": {"type": "string", "description": "要分析的日志行"}
                },
                "required": ["log_line"]
            }
        }
    }
]
```

写好 `description` 非常重要——模型靠它理解"这个工具是干嘛的"。描述越清楚，模型越会用。

## 17.3 让模型调用工具

用 OpenAI 兼容的接口（本地 LM Studio 也支持）：

```python
from openai import OpenAI
client = OpenAI(base_url="http://localhost:1234/v1", api_key="not-needed")

messages = [
    {"role": "system", "content": "你是取证助手，可以使用工具分析日志。"},
    {"role": "user", "content": "帮我查一下日志里所有来自 203.0.113.5 的记录"}
]

resp = client.chat.completions.create(
    model="local-model",
    messages=messages,
    tools=tools,
    tool_choice="auto"  # 让模型自己决定
)

# 看模型想调用什么工具
msg = resp.choices[0].message
if msg.tool_calls:
    for call in msg.tool_calls:
        print(f"调用工具: {call.function.name}")
        print(f"参数: {call.function.arguments}")
```

模型会输出类似：

```
调用工具: grep_log
参数: {"file": "starsea_firewall.log", "pattern": "203.0.113.5"}
```

注意：**模型没有真的执行**，它只是告诉你"我想搜这个"。执行在你的代码里。

## 17.4 执行工具并回传结果

```python
import json
import subprocess

def execute_tool(name, args):
    """真正执行工具"""
    if name == "grep_log":
        # 用 grep 搜索（注意安全：pattern 要转义）
        result = subprocess.run(
            ["grep", args["pattern"], args["file"]],
            capture_output=True, text=True, timeout=10
        )
        return result.stdout[:2000]  # 限制长度
    elif name == "analyze_log_line":
        # 调用我们的取证模型（ch15 的 ForensicQA）
        return qa.analyze(args["log_line"])
    return "未知工具"

# 执行模型请求的工具
tool_results = []
for call in msg.tool_calls:
    args = json.loads(call.function.arguments)
    result = execute_tool(call.function.name, args)
    tool_results.append({
        "tool_call_id": call.id,
        "role": "tool",
        "content": result
    })

# 把工具结果加入对话，让模型继续
messages.append(msg)
messages.extend(tool_results)

resp2 = client.chat.completions.create(
    model="local-model",
    messages=messages,
    tools=tools
)
print(resp2.choices[0].message.content)
```

模型拿到工具结果后，就能给出最终回答："日志中有 15 条来自 203.0.113.5 的记录，均为对 23 端口的连接尝试，疑似端口扫描……"

## 17.5 完整的工具循环

把上面的逻辑封装成循环，就是 Agent 的核心：

```python
def agent_loop(question, max_steps=5):
    messages = [
        {"role": "system", "content": "你是取证助手，可使用工具。"},
        {"role": "user", "content": question}
    ]
    for step in range(max_steps):
        resp = client.chat.completions.create(
            model="local-model", messages=messages, tools=tools
        )
        msg = resp.choices[0].message
        messages.append(msg)

        if msg.tool_calls:
            # 执行工具，回传结果
            for call in msg.tool_calls:
                args = json.loads(call.function.arguments)
                result = execute_tool(call.function.name, args)
                messages.append({
                    "tool_call_id": call.id, "role": "tool", "content": result
                })
        else:
            # 模型给出最终回答，循环结束
            return msg.content
    return "达到最大步数，未完成任务"
```

**max_steps 很重要**：防止模型陷入死循环（反复调用同一工具）。取证场景一般 5-10 步足够。

## 17.6 工具设计的最佳实践

1. **描述清晰**：`description` 要让模型一眼懂这个工具干嘛；
2. **参数精简**：参数越少越好，必填参数明确；
3. **结果限长**：工具返回可能很长（grep 出几万行），要截断（如 2000 字符）；
4. **错误处理**：工具执行失败要返回错误信息，让模型知道并重试；
5. **安全保障**：工具执行要沙箱化，防止模型执行危险命令（如 `rm -rf`）。

**安全重点**：不要让模型执行任意 shell 命令！用白名单限制它能调用的工具。取证场景尤其要注意——你处理的是证据，误操作会破坏数据（ch02 红线）。

## 17.7 本地模型的函数调用支持

**注意**：不是所有本地模型都稳定支持 Function Calling。Qwen2.5/Qwen3.5 系列支持较好，但小模型（7B 量化版）可能不稳定。

如果函数调用不work：

1. 换更大的模型（14B）或更高精度（Q5/Q6）；
2. 用提示词模拟：在 system 提示里规定输出格式（如"输出 JSON：{tool, args}"），然后自己解析；
3. 上云用更强的模型（如 GPT-4o、Claude）做 Agent 大脑，本地模型做具体工具。

**混合方案很实用**：强模型当"调度大脑"（决定调用什么工具），微调小模型当"专业工具"（分析日志）。这样既稳定又专业。

## 17.8 动手任务

1. **定义工具**：为取证场景定义 3-5 个工具（读文件、grep、查IP、分析日志等）。
2. **测试调用**：用本地 Qwen 测试函数调用，看它能不能正确选择工具和参数。
3. **实现 execute_tool**：写出工具执行函数，注意结果限长和错误处理。
4. **跑通循环**：实现 17.5 的 `agent_loop`，让它完成"查某个 IP 的记录"任务。
5. **加安全限制**：给工具执行加白名单，禁止危险命令。

---

## 17.9 小结

- 函数调用让模型能"提出"调用工具的请求，真正的执行在代码里；
- 工具定义用 JSON Schema，`description` 要清楚；
- 完整流程：定义工具 → 模型请求 → 执行 → 回传结果 → 继续；
- 封装成循环就是 Agent 核心，加 max_steps 防死循环；
- 工具设计：描述清晰、参数精简、结果限长、错误处理、安全保障；
- 本地小模型函数调用可能不稳，可用强模型调度 + 小模型执行的混合方案。
