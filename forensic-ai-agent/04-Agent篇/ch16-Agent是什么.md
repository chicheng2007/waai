# ch16 Agent 是什么

> **本章目标**：理解 AI Agent 的本质——从"被动问答"到"主动行动"。搞清 Agent 的核心组成部分，以及为什么取证工作特别需要 Agent 而不是简单的问答模型。

## 16.1 从问答模型到 Agent

上一章我们做出的是**问答模型**：你问一句，它答一句。它是被动的——不给输入就不动，也不会自己找信息。

但真实的取证任务不是这样。回顾"星海案"：分析师要做的不是回答一个问题，而是**完成一个多步骤的任务**：

1. 先看有哪些日志文件；
2. 读日志，找异常；
3. 对可疑 IP 查归属；
4. 把事件按时间排成时间线；
5. 生成报告。

这不是一次问答能完成的。它需要**自己决定下一步做什么、调用工具、根据结果调整**。这就是 Agent。

### 一句话定义

> **Agent = 大模型（大脑）+ 工具（手脚）+ 记忆 + 规划能力**。它能感知环境、做决策、执行动作，循环往复直到完成任务。

如果说问答模型是"百科全书"，Agent 就是"能干活的助手"。

---

## 16.2 Agent 的四个核心组件

### 组件一：大脑（LLM）

负责理解任务、推理、决策。就是我们的大模型（可以是微调后的取证模型）。它回答："下一步该做什么？"

### 组件二：工具（Tools）

Agent 能调用外部函数来完成具体事情。取证场景的工具：

- 读文件、查日志；
- 执行 shell 命令（grep、jq）；
- 查 IP 归属（API）；
- 调用我们的 `ForensicQA` 模型分析日志；
- 写报告文件。

**模型负责"想"，工具负责"做"**。这是 Agent 的关键分工。

### 组件三：记忆（Memory）

- **短期记忆**：当前任务的上下文（已经做了什么、发现了什么）；
- **长期记忆**：跨任务的知识（如知识库、历史案例），通常用向量数据库（RAG）。

### 组件四：规划（Planning）

把大任务拆成小步骤，按顺序执行，根据中间结果调整。比如"分析入侵"拆成"读日志→找异常→查IP→理时间线→写报告"。

---

## 16.3 Agent 的工作循环

Agent 跑起来是一个循环（Loop）：

```
观察(Observation) → 思考(Thought) → 行动(Action) → 观察结果 → ...
```

这个循环叫 **ReAct**（Reasoning + Acting），ch18 详细讲。举个例子：

```
任务：找出日志里的可疑 IP

第1轮：
  思考：我需要先看看日志文件有哪些
  行动：调用 list_files() 工具
  观察：发现 starsea_firewall.log

第2轮：
  思考：我要读日志，找外部 IP
  行动：调用 grep_external_ips("starsea_firewall.log")
  观察：找到 203.0.113.5 等 5 个外部 IP

第3轮：
  思考：查一下这些 IP 的归属
  行动：调用 ip_lookup("203.0.113.5")
  观察：...（返回归属信息）

第4轮：
  思考：信息够了，可以总结
  行动：输出最终结论
```

这个循环让 Agent 能完成复杂的多步任务。

## 16.4 为什么取证特别需要 Agent

取证工作有几个特点，正好匹配 Agent 的能力：

1. **多步骤**：取证是流程化的，需要一步步来（ch02 的六步）；
2. **工具密集**：取证依赖大量专业工具（grep、tshark、Volatility）；
3. **数据海量**：需要筛选、检索，而不是一次性读完；
4. **需要推理**：从零散线索推出结论，需要多步推理。

**Agent 能把我们的取证问答模型从"单兵"升级成"团队"**：模型负责判断，工具负责执行，循环负责推进。

---

## 16.5 Agent 的局限

不要神化 Agent。它有明显局限：

- **不稳定**：同样的任务，跑两次可能结果不同（模型随机性）；
- **会犯错**：可能选错工具、误解结果、陷入死循环；
- **成本高**：多轮调用消耗大量 token；
- **调试难**：出了问题，很难定位是哪一步错了。

所以实践中要：
- 加**最大步数限制**（防止死循环）；
- 加**人在回路**（关键决策让人确认）；
- 做好**日志记录**（每步都记下来，方便调试）。

## 16.6 主流 Agent 框架

实现 Agent 可以用现成框架：

| 框架 | 特点 | 适合 |
|---|---|---|
| LangChain | 生态全、文档多 | 通用入门 |
| LangGraph | 强调流程控制 | 复杂工作流 |
| AutoGen | 多 Agent 协作 | 多智能体（ch23） |
| CrewAI | 角色化多 Agent | 团队协作 |
| 原生实现 | 自己写循环 | 学习原理、轻量需求 |

本书建议：**先用原生代码实现一个最小 Agent**（ch20），理解原理，再用框架（LangChain）做复杂项目（ch21）。不要一上来就用框架，否则你不知道框架在干什么。

## 16.7 动手任务

1. **拆解任务**：把"星海案"的分析目标拆成 5-8 个步骤，写成清单。这就是你未来 Agent 的"计划"。
2. **列出工具**：为每一步列出需要的工具（读文件、grep、查IP、分析模型等）。
3. **画循环图**：画出 ReAct 循环的流程图，标出"思考/行动/观察"。
4. **装 LangChain**：`pip install langchain`，先装上，ch17 开始用。

---

## 16.8 小结

- Agent = 大脑（LLM）+ 工具 + 记忆 + 规划，能主动完成任务；
- 四个组件：大脑、工具、记忆、规划；
- 工作循环：观察→思考→行动→观察（ReAct）；
- 取证工作多步骤、工具密集、数据海量、需推理，特别适合 Agent；
- Agent 不稳定、会犯错，要加步数限制和人在回路；
- 先用原生代码实现最小 Agent，再上框架。
