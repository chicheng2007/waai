## 19.1 为什么需要记忆和规划

前面的 Agent 有个问题：**它只适合短任务**。面对"完整分析星海案"这种大任务，它会：

- 记不住前面发现了什么（没有长期记忆）；
- 不知道该分几步、先做什么（没有规划）；
- 上下文塞不下所有日志（需要检索）。

记忆和规划就是解决这些问题的。

- **记忆**：让 Agent 记住历史发现和知识；
- **规划**：让 Agent 把大任务拆成可管理的小任务。

---

## 19.2 短期记忆：任务内的上下文

短期记忆就是当前对话的历史（ReAct 的 Thought/Action/Observation 序列）。问题是：**历史会越来越长，最终超出上下文限制**。

解决办法：

### 方法一：滑动窗口

只保留最近 N 轮：

```python
history = history[-6:]  # 只保留最近 3 轮（每轮 2 条）
```

简单，但会丢失早期的重要发现。

### 方法二：摘要压缩（Summarizer）

把早期历史压缩成一段摘要：

```python
def summarize(history):
    prompt = f"""把下面的 Agent 执行历史总结成一段话，保留关键发现：
{history}
摘要："""
    return client.chat.completions.create(
        model="local-model",
        messages=[{"role": "user", "content": prompt}],
        max_tokens=300
    ).choices[0].message.content

# 当历史太长时压缩
if len(history) > 20:
    summary = summarize(history[:10])
    history = [{"role": "system", "content": f"此前发现：{summary}"}] + history[10:]
```

**这正是 CTF-Dojo 的 EnIGMA+ 用轻量 summarizer 的原因**——避免二进制反编译等长输出填满上下文。我们这里用它压缩取证历史。

### 方法三：结构化记忆

把发现存成结构化数据（字典/数据库），而不是堆在对话里：

```python
memory = {
    "suspicious_ips": ["203.0.113.5", "203.0.113.8"],
    "timeline": [{"time": "02:03", "event": "端口扫描"}],
    "conclusions": ["发现外部 IP 扫描行为"]
}
```

每轮把关键发现更新到 memory，Agent 需要时查询。这样上下文里只放当前步骤 + memory 摘要。

## 19.3 长期记忆：RAG 检索增强

长期记忆通常是**知识库 + 向量检索**，即 RAG（Retrieval-Augmented Generation）。

### RAG 的流程

```
1. 把知识文档切成小块（chunk）
2. 用 embedding 模型把每块转成向量，存入向量数据库
3. 用户提问时，把问题也转成向量
4. 在数据库里找最相似的几个块（检索）
5. 把检索到的块 + 问题一起喂给模型
6. 模型基于检索内容回答
```

### 取证场景的 RAG

把什么存进知识库？

- 历史案件的分析报告；
- 攻击手法知识（MITRE ATT&CK）；
- 内部取证规范、SOP；
- 常见日志格式说明。

这样 Agent 遇到问题时，能检索到相关知识，而不是凭空回答。**这能显著减少幻觉**——因为回答有据可依。

### 用 LangChain 实现简单 RAG

```python
from langchain.document_loaders import TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain.embeddings import HuggingFaceEmbeddings
from langchain.vectorstores import Chroma

# 1. 加载知识文档
loader = TextLoader("forensic_knowledge.md")
docs = loader.load()

# 2. 切块
splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)
chunks = splitter.split_documents(docs)

# 3. 向量化并存储（用本地 embedding 模型）
embeddings = HuggingFaceEmbeddings(model_name="sentence-transformers/all-MiniLM-L6-v2")
db = Chroma.from_documents(chunks, embeddings, persist_directory="./chroma_db")

# 4. 检索
def retrieve(query, k=3):
    return db.similarity_search(query, k=k)

# 5. 把检索结果加入 Prompt
def answer_with_rag(question):
    docs = retrieve(question)
    context = "\n".join(d.page_content for d in docs)
    prompt = f"""基于以下资料回答问题，不要编造资料中没有的内容。

资料：
{context}

问题：{question}
回答："""
    return client.chat.completions.create(
        model="local-model",
        messages=[{"role": "user", "content": prompt}]
    ).choices[0].message.content
```

**提示**：embedding 模型可以用本地小模型，不占 GPU，CPU 就能跑。检索速度快。

## 19.4 规划：任务分解

规划就是把大任务拆成小任务。方法：

### 方法一：让模型一次性规划

```python
def plan(task):
    prompt = f"""你是取证任务规划器。把下面的任务拆成有序的步骤。
每步写清楚：做什么、用什么工具、期望得到什么。

任务：{task}

步骤：
1."""
    resp = client.chat.completions.create(
        model="local-model",
        messages=[{"role": "user", "content": prompt}],
        temperature=0.1
    )
    return resp.choices[0].message.content
```

输出可能是：

```
1. 列出日志目录，确认有哪些日志文件 —— 用 list_files
2. 在防火墙日志中搜索外部 IP —— 用 grep_log
3. 对每个可疑 IP 分析相关日志 —— 用 analyze_log_line
4. 查询外部 IP 归属 —— 用 ip_lookup
5. 按时间整理成时间线 —— 用 sort_timeline
6. 生成分析报告 —— 用 write_report
```

然后 Agent 按顺序执行每一步（每步内部用 ReAct）。这就是 **Plan-and-Execute** 模式。

### 方法二：动态 replanning

执行中发现计划不合适，重新规划。比如某一步失败，让模型调整后续步骤。这更灵活但更复杂。

---

## 19.5 Plan-and-Execute vs ReAct

| 模式 | 特点 | 适合 |
|---|---|---|
| 纯 ReAct | 边想边做，灵活但可能绕路 | 探索性任务 |
| Plan-and-Execute | 先规划再执行，有序但不够灵活 | 流程化任务 |
| 混合 | 先规划大框架，每步用 ReAct | 复杂取证任务 |

**取证是流程化工作**（ch02 六步），所以 Plan-and-Execute 很适合。可以用规划器定框架，每步内部用 ReAct 灵活处理。

## 19.6 多步任务的完整架构

把前面的组件组合起来，一个完整的取证 Agent 架构：

```
用户任务
   ↓
[规划器] 拆成步骤
   ↓
[执行器] 对每步：
   ├─ [记忆] 查询历史发现 + RAG 知识
   ├─ [ReAct] 思考 → 调用工具 → 观察
   └─ [更新记忆] 记录新发现
   ↓
[汇总器] 生成最终报告
   ↓
结果 + 完整记录（可审计）
```

这个架构在 ch20 会实现成一个可运行的骨架，ch21-23 的项目都基于它。

## 19.8 小结

- 短期记忆：滑动窗口、摘要压缩（Summarizer）、结构化记忆；
- 摘要压缩借鉴 CTF-Dojo 的 EnIGMA+，防止上下文超限；
- 长期记忆：RAG = 切块 → 向量化 → 检索 → 基于检索回答，能减少幻觉；
- 规划：Plan-and-Execute，把大任务拆成小步骤；
- 三种模式：纯 ReAct、Plan-and-Execute、混合；取证流程化，适合 Plan-and-Execute；
- 完整架构：规划 → 执行（记忆+ReAct+工具）→ 汇总 → 报告 + 记录。
