# 第 2 章 环境搭建与第一个 Go 程序

## 本章目标

- 安装 Go

- 创建第一个 Go 项目
- 掌握 go 常用命令

---

## 2.1 安装 Go

### 2.1.1 下载安装

1. 打开官网：<https://go.dev/dl/>
2. 下载对应系统的安装包
3. Windows：双击 `.msi` 安装；macOS：双击 `.pkg`；Linux：解压到 `/usr/local/go`

验证：

```bash
go version
```

### 2.1.2 配置

现代 Go（1.11+）用 Go Modules，不需要配置 GOPATH。只需确认：

```bash
go env GOPATH    # 默认 ~/go
go env GOMODCACHE  # 模块缓存目录
```

## 2.2 第一个程序

创建 `hello.go`：

```go
package main

import "fmt"

func main() {
    fmt.Println("Hello, Go!")
}
```

运行：

```bash
go run hello.go
```

编译：

```bash
go build -o hello hello.go
./hello
```

要点：

- `package main`：声明包名，`main` 包是可执行程序的入口
- `import "fmt"`：导入格式化输出包
- `func main()`：主函数，程序入口
- `fmt.Println`：打印并换行

## 2.3 Go Modules：依赖管理

### 2.3.1 创建模块

```bash
mkdir myproject
cd myproject
go mod init github.com/yourname/myproject
```

生成 `go.mod`：

```
module github.com/yourname/myproject

go 1.21
```

### 2.3.2 添加依赖

```bash
go get github.com/xxx/yyy
```

代码中 import 后，`go mod tidy` 自动整理依赖：

```bash
go mod tidy   # 清理无用依赖，添加缺失依赖
```

### 2.3.3 常用命令

```bash
go run .            # 运行当前模块
go build            # 编译
go build -o app     # 指定输出名
go test ./...       # 运行所有测试
go mod tidy         # 整理依赖
go get <package>    # 添加/更新依赖
go env              # 查看环境配置
go fmt ./...        # 格式化代码
```

> **gofmt**：Go 强制统一代码格式。`go fmt` 自动格式化，团队不用争论代码风格，这是 Go 的设计智慧。

## 2.4 跨平台编译（安全工具必备）

Go 能轻松交叉编译：

```bash
# 编译出 Windows 64位版本
GOOS=windows GOARCH=amd64 go build -o app.exe main.go

# Linux
GOOS=linux GOARCH=amd64 go build -o app_linux main.go

# macOS
GOOS=darwin GOARCH=amd64 go build -o app_mac main.go
```

> **红队场景**：一次编译出多平台木马/代理工具（授权测试），拷贝到目标机器直接运行，无需装环境。这是 Go 在安全工具中流行的关键原因。

## 2.6 Go 项目结构最佳实践

一个规范的 Go 项目通常这样组织：

```
myproject/
├── go.mod              # 模块定义
├── go.sum              # 依赖校验
├── main.go             # 程序入口
├── cmd/                # 多个可执行程序
│   └── server/
│       └── main.go
├── internal/           # 内部包（外部无法导入）
│   ├── scanner/
│   └── utils/
├── pkg/                # 可被外部复用的公共库
├── config/             # 配置文件
├── test/               # 测试数据和脚本
└── README.md
```

**关键约定**：

- `internal/`：Go 特有，只有本项目内的代码能导入，适合放内部实现
- `pkg/`：放通用的、希望别人能复用的库
- `cmd/`：每个子目录对应一个可执行程序

> **安全场景**：写安全工具时，把核心扫描逻辑放 `internal/scanner`，把命令行入口放 `cmd/tool/main.go`，结构清晰，便于测试和复用。

## 2.7 常见问题排查

**问题 1：`go: cannot find main module`**

原因：没初始化 go.mod。
解决：`go mod init <模块名>`。

**问题 2：下载依赖慢/失败**

原因：默认从 proxy.golang.org 下载，国内可能慢。
解决：配置国内代理：
```bash
go env -w GOPROXY=https://goproxy.cn,direct
```

**问题 3：`go build` 生成的文件太大**

Go 默认包含调试信息。用 `-ldflags="-s -w"` 减小体积：
```bash
go build -ldflags="-s -w" -o app main.go
```

> 安全工具（尤其红队场景）常需要小体积、难分析的二进制，这个技巧很实用。

**问题 4：交叉编译失败**

确保代码没有依赖特定平台的 cgo。纯 Go 代码交叉编译无障碍，用了 cgo 就需要对应平台的 C 编译器。
