# 第 6 章 错误处理：Result 与 Option

## 本章目标

- 理解 panic 与可恢复错误
- 掌握 Result 和错误传播
- 掌握 `?` 运算符
- 理解何时 panic、何时返回 Result
- 掌握自定义错误类型

Rust 把错误分为两类：不可恢复的（panic）和可恢复的（Result）。这种区分让错误处理更清晰、更健壮。

---

## 6.1 两种错误

### 6.1.1 Panic（不可恢复）

```rust
fn main() {
    panic!("严重错误，程序终止！");
}
```

或运行时 panic：

```rust
let v = vec![1, 2, 3];
// v[99];   // panic: index out of bounds
```

panic 会打印错误信息、展开栈（unwind）、退出程序。适合"无法继续"的严重错误。

> **注意**：panic 不会导致内存不安全，Rust 会正确清理资源。但服务程序通常不希望因一个小错误就整体崩溃。

### 6.1.2 Result（可恢复）

```rust
use std::fs::File;

let result = File::open("config.txt");  // Result<File, io::Error>
```

可恢复错误用 Result 返回，调用者决定如何处理。

---

## 6.2 Result 详解

### 6.2.1 基本处理

```rust
use std::fs::File;

match File::open("config.txt") {
    Ok(f) => println!("打开成功: {:?}", f),
    Err(e) => println!("打开失败: {}", e),
}
```

### 6.2.2 unwrap 与 expect

```rust
let f = File::open("config.txt").unwrap();  // 失败则 panic
let f = File::open("config.txt").expect("配置文件必须存在");  // 带自定义信息
```

> **使用原则**：在原型、测试、或"确定不会失败"时用 unwrap；生产代码用 `?` 或 match 正确处理。

### 6.2.3 `?` 运算符（错误传播）

```rust
use std::fs::File;
use std::io::{self, Read};

fn read_config() -> Result<String, io::Error> {
    let mut file = File::open("config.txt")?;   // 失败则提前返回 Err
    let mut contents = String::new();
    file.read_to_string(&mut contents)?;        // 失败则提前返回 Err
    Ok(contents)
}
```

`?` 的作用：如果是 Ok，取出值继续；如果是 Err，立即返回这个 Err。这大大简化了错误传播代码。

对比不用 `?`：

```rust
fn read_config() -> Result<String, io::Error> {
    let mut file = match File::open("config.txt") {
        Ok(f) => f,
        Err(e) => return Err(e),
    };
    let mut contents = String::new();
    match file.read_to_string(&mut contents) {
        Ok(_) => Ok(contents),
        Err(e) => Err(e),
    }
}
```

`?` 让代码清爽很多。

### 6.2.4 main 返回 Result

```rust
fn main() -> Result<(), Box<dyn std::error::Error>> {
    let contents = read_config()?;
    println!("{}", contents);
    Ok(())
}
```

`Box<dyn Error>` 是错误类型的"万能容器"，能装各种错误。

## 6.3 自定义错误类型

```rust
use std::fmt;

#[derive(Debug)]
enum ScanError {
    InvalidIp(String),
    ConnectionTimeout(String),
    PermissionDenied,
}

impl fmt::Display for ScanError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            ScanError::InvalidIp(ip) => write!(f, "非法IP: {}", ip),
            ScanError::ConnectionTimeout(ip) => write!(f, "连接超时: {}", ip),
            ScanError::PermissionDenied => write!(f, "权限不足"),
        }
    }
}

impl std::error::Error for ScanError {}

fn scan(ip: &str) -> Result<Vec<u16>, ScanError> {
    if ip.is_empty() {
        return Err(ScanError::InvalidIp(ip.into()));
    }
    // 模拟扫描
    Ok(vec![80, 443])
}
```

## 6.4 Option 的错误处理

```rust
fn find_port(ports: &[u16], target: u16) -> Option<usize> {
    ports.iter().position(|&p| p == target)
}

// 用 ok_or 把 Option 转 Result
fn find_port_or_error(ports: &[u16], target: u16) -> Result<usize, String> {
    find_port(ports, target).ok_or_else(|| format!("端口 {} 未找到", target))
}
```

常用组合器：

```rust
let x = Some(5);
x.map(|v| v * 2)              // Some(10)
 .filter(|v| *v > 5)          // Some(10)
 .unwrap_or(0);               // 10
```

## 6.5 catch_unwind（谨慎）

Rust 也能"捕获" panic，但**不推荐**用作常规错误处理（它主要用于 FFI 边界、测试）：

```rust
use std::panic;

let result = panic::catch_unwind(|| {
    // 可能 panic 的代码
    risky_operation();
});
match result {
    Ok(_) => println!("成功"),
    Err(_) => println!("捕获到 panic"),
}
```

> **警告**：catch_unwind 不能捕获所有情况（如 abort），且可能留下不一致的状态。不要用异常做正常控制流。

## 6.6 实战：健壮的配置加载器

```rust
use std::fs;
use std::error::Error;
use std::fmt;

#[derive(Debug)]
enum ConfigError {
    ReadError(String),
    ParseError(String),
}

impl fmt::Display for ConfigError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            ConfigError::ReadError(s) => write!(f, "读取失败: {}", s),
            ConfigError::ParseError(s) => write!(f, "解析失败: {}", s),
        }
    }
}
impl Error for ConfigError {}

struct Config {
    host: String,
    port: u16,
}

fn load_config(path: &str) -> Result<Config, ConfigError> {
    let content = fs::read_to_string(path)
        .map_err(|e| ConfigError::ReadError(e.to_string()))?;
    
    let mut host = String::new();
    let mut port = 0;
    
    for line in content.lines() {
        if let Some((key, value)) = line.split_once('=') {
            match key.trim() {
                "host" => host = value.trim().to_string(),
                "port" => port = value.trim().parse()
                    .map_err(|_| ConfigError::ParseError("端口格式错误".into()))?,
                _ => {}
            }
        }
    }
    
    if host.is_empty() {
        return Err(ConfigError::ParseError("缺少 host".into()));
    }
    
    Ok(Config { host, port })
}

fn main() {
    match load_config("config.txt") {
        Ok(cfg) => println!("主机: {}, 端口: {}", cfg.host, cfg.port),
        Err(e) => eprintln!("配置错误: {}", e),
    }
}
```

## 6.7 thiserror 与 anyhow（错误处理神器）

手写错误类型样板代码多，社区有两个几乎是标配的 crate：

### 6.7.1 thiserror：定义错误类型

```rust
// Cargo.toml: thiserror = "1"
use thiserror::Error;

#[derive(Error, Debug)]
enum ScanError {
    #[error("非法 IP 地址: {0}")]
    InvalidIp(String),
    
    #[error("连接超时: {ip}")]
    Timeout { ip: String },
    
    #[error("IO 错误: {0}")]
    Io(#[from] std::io::Error),   // 自动实现 From，支持 ? 转换
}
```

一个 `#[derive(Error)]` 就自动生成了 Display + Error + From 实现，比手写简洁太多。

### 6.7.2 anyhow：应用层的灵活错误

```rust
// Cargo.toml: anyhow = "1"
use anyhow::{Result, Context, anyhow};

fn load_config(path: &str) -> Result<String> {
    let content = std::fs::read_to_string(path)
        .with_context(|| format!("读取配置 {} 失败", path))?;
    
    if content.is_empty() {
        return Err(anyhow!("配置文件为空"));
    }
    Ok(content)
}

fn main() -> Result<()> {
    let cfg = load_config("config.toml")?;
    println!("{}", cfg);
    Ok(())
}
```

`anyhow::Result` 能装任意错误，`with_context` 添加上下文信息，链式追踪错误来源。适合应用程序（库通常用 thiserror 定义具体错误类型）。

> **最佳实践**：库（library）用 `thiserror` 定义明确的错误类型；应用程序（binary）用 `anyhow` 灵活传播。这是 Rust 社区的主流做法。

## 6.8 错误处理的工程原则

### 6.8.1 什么时候用 panic

| 场景 | 用 panic 吗 |
|------|-----------|
| 普通业务逻辑错误 | ❌ 用 Result |
| 用户输入错误 | ❌ 用 Result |
| 文件不存在、网络错误 | ❌ 用 Result |
| 程序内部不变量被破坏（bug） | ✅ 可以 panic |
| 测试断言 | ✅ panic |
| 启动时必要配置缺失 | ✅ 可以 panic（fail fast） |

> **Fail Fast**：对于"程序无法正确运行"的情况（如必需配置缺失），启动时直接 panic 比带着错误状态运行更安全。

### 6.8.2 错误信息要具体

```rust
// 不好：信息模糊
return Err("出错了".into());

// 好：包含上下文
return Err(anyhow!("解析 IP '{}' 失败: 期望 IPv4 格式", ip));
```

好的错误信息能让运维快速定位问题。这也是可观测性（observability）的一部分。

### 6.8.3 不要吞掉错误

```rust
// 反面教材
let result = do_something();
if let Err(_) = result {
    // 静默忽略，什么都不做
}

// 正确：至少记录
if let Err(e) = do_something() {
    eprintln!("警告: {}", e);
}
```

静默吞掉错误是很多隐蔽 bug 的根源。

## 6.9 本章总结

| 知识点 | 内容 |
|--------|------|
| panic | 不可恢复错误；内存安全但程序退出 |
| Result | Ok/Err；可恢复错误 |
| `?` 运算符 | 自动传播错误，简化代码 |
| unwrap/expect | 快速取值，失败 panic；谨慎用 |
| 自定义错误 | 实现 Display + Error trait |
| thiserror | derive 自动生成错误类型 |
| anyhow | 应用层灵活错误 + 上下文 |
| Option 组合器 | map/filter/ok_or |
| 原则 | 可恢复用 Result，不可恢复用 panic；不吞错误 |
