## 5.1 结构体

### 5.1.1 定义与实例化

```rust
struct PortRule {
    ip: String,
    port: u16,
    action: String,
}

fn main() {
    let rule = PortRule {
        ip: String::from("192.168.1.1"),
        port: 22,
        action: String::from("ALLOW"),
    };
    println!("{}:{} -> {}", rule.ip, rule.port, rule.action);
}
```

### 5.1.2 方法

```rust
impl PortRule {
    // 关联函数（类似静态方法）
    fn new(ip: String, port: u16, action: String) -> Self {
        Self { ip, port, action }
    }
    
    // 方法（&self 借用）
    fn is_dangerous(&self) -> bool {
        matches!(self.port, 23 | 445 | 3389)
    }
    
    fn describe(&self) -> String {
        format!("规则: {}:{} {}", self.ip, self.port, self.action)
    }
}
```

> `&self` 表示借用自身，不转移所有权。这是方法定义的常规写法。

### 5.1.3 元组结构体

```rust
struct IpAddr(u8, u8, u8, u8);
let ip = IpAddr(192, 168, 1, 1);
println!("{}", ip.0);
```

## 5.2 枚举

### 5.2.1 基本枚举

```rust
enum Protocol {
    TCP,
    UDP,
    ICMP,
}

let proto = Protocol::TCP;
```

### 5.2.2 带数据的枚举（强大之处）

```rust
enum Threat {
    Malware { name: String, severity: u8 },
    Phishing { url: String },
    Scan { ip: String, ports: Vec<u16> },
    Unknown,
}

let t = Threat::Malware {
    name: String::from("WannaCry"),
    severity: 9,
};
```

Rust 的枚举每个变体可以带不同类型和数量的数据，这比 C 的枚举强大得多，可以表达复杂的领域模型。

## 5.3 模式匹配（match）

### 5.3.1 match 表达式

```rust
fn describe_threat(t: &Threat) -> String {
    match t {
        Threat::Malware { name, severity } => 
            format!("恶意软件 {} (危险等级 {})", name, severity),
        Threat::Phishing { url } => 
            format!("钓鱼攻击: {}", url),
        Threat::Scan { ip, ports } => 
            format!("扫描: {} 扫描了 {} 个端口", ip, ports.len()),
        Threat::Unknown => 
            String::from("未知威胁"),
    }
}
```

> **穷尽性检查**：Rust 要求 match 覆盖所有可能的变体，否则编译错误。这保证了你不会漏掉任何一种情况——比 C 的 switch 安全得多。

### 5.3.2 if let（简化匹配）

```rust
// 只关心一种情况
if let Threat::Malware { name, .. } = &t {
    println!("发现恶意软件: {}", name);
}
```

### 5.3.3 matches! 宏

```rust
let is_high = matches!(t, Threat::Malware { severity: 9..=10, .. });
```

## 5.4 Option：取代 null

### 5.4.1 问题背景

C/C++ 的 null 指针是"十亿美元的错误"（发明者 Tony Hoare 语）。空指针解引用导致无数崩溃和漏洞。

Rust 没有 null，用 `Option<T>` 表达"可能有值，可能没有"：

```rust
enum Option<T> {
    Some(T),   // 有值
    None,      // 没有
}
```

### 5.4.2 使用 Option

```rust
fn find_port(ports: &[u16], target: u16) -> Option<usize> {
    for (i, &p) in ports.iter().enumerate() {
        if p == target {
            return Some(i);   // 找到了
        }
    }
    None   // 没找到
}

let result = find_port(&[22, 80, 443], 80);
match result {
    Some(index) => println!("位置: {}", index),
    None => println!("未找到"),
}
```

> **安全性**：编译器强制你处理 `None` 的情况，不可能"忘记检查空值"就解引用。这是 Rust 消除空指针崩溃的方式。

### 5.4.3 unwrap 与 ? 运算符

```rust
// unwrap：直接取值，如果是 None 会 panic（谨慎使用）
let x = Some(5).unwrap();   // 5

// ? 运算符：如果是 None 就提前返回 None（函数式传播）
fn get_first(ports: &[u16]) -> Option<u16> {
    let first = *ports.get(0)?;   // get 返回 Option<&u16>
    Some(first)
}
```

## 5.5 Result：错误处理基础

```rust
enum Result<T, E> {
    Ok(T),   // 成功，含结果
    Err(E),  // 失败，含错误
```

```rust
let f = File::open("config.txt");

}
```

## 5.6 实战：威胁分类器

```rust
#[derive(Debug)]
enum Threat {
    Malware { name: String, severity: u8 },
    Phishing { url: String },
    Scan { ip: String, count: usize },
}

#[derive(Debug)]
enum Verdict {
    Critical,
    High,
    Low,
}

fn classify(t: &Threat) -> Verdict {
    match t {
        Threat::Malware { severity, .. } if *severity >= 8 => Verdict::Critical,
        Threat::Malware { .. } => Verdict::High,
        Threat::Phishing { .. } => Verdict::High,
        Threat::Scan { count, .. } if *count > 1000 => Verdict::Critical,
        Threat::Scan { .. } => Verdict::Low,
    }
}

fn main() {
    let threats = vec![
        Threat::Malware { name: "WannaCry".into(), severity: 9 },
        Threat::Phishing { url: "http://fake-bank.com".into() },
        Threat::Scan { ip: "10.0.0.1".into(), count: 5000 },
    ];
    
    for t in &threats {
        println!("{:?} -> {:?}", t, classify(t));
    }
}
```

> 注意 `match` 中的 guard（`if *severity >= 8`），可以在匹配时加额外条件。

## 5.7 模式匹配的进阶用法

### 5.7.1 解构

match 能解构复杂的数据结构：

```rust
struct LogEntry {
    ip: String,
    port: u16,
    action: String,
}

let log = LogEntry {
    ip: "192.168.1.1".into(),
    port: 22,
    action: "ALLOW".into(),
};

// 解构结构体
let LogEntry { ip, port, action } = log;
println!("{}:{} {}", ip, port, action);

// 解构时重命名、忽略字段
let LogEntry { ip: addr, port: p, .. } = &log;
```

### 5.7.2 绑定值（@）

```rust
match threat {
    Threat::Malware { severity: s @ 8..=10, .. } => {
        println!("严重恶意软件，等级 {}", s);   // s 绑定了匹配到的值
    }
    ...
}
```

`@` 能在匹配范围的同时把值绑定到一个变量。

### 5.7.3 通配符与占位

```rust
match value {
    Some(x) => println!("值: {}", x),
    None => {}        // 什么都不做
    _ => {}           // 通配符，匹配其他所有
}
```

### 5.7.4 枚举的内存布局（安全视角）

```rust
enum Small {
    A,           // 无数据
    B(u8),       // 1 字节数据
}
// 大小可能只有 2 字节（1 字节判别式 + 1 字节数据）

enum Mixed {
    A,              // 无数据
    B(String),      // 24 字节
    C([u8; 100]),   // 100 字节
}
// 整体大小由最大变体决定（约 100+ 字节），有内存浪费
```

> **优化提示**：如果枚举变体大小差异巨大，可以用 `Box` 把大变体放到堆上，减小枚举本身大小：
> ```rust
> enum Optimized {
>     A,
>     C(Box<[u8; 100]>),   // 只存一个指针
> }
> ```
> 这在安全工具处理大量日志对象时，能显著减少内存占用。
