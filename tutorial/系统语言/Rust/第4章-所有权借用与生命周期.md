# 第 4 章 所有权、借用与生命周期（核心）

## 本章目标

- 透彻理解所有权（Ownership）三规则
- 理解移动（Move）与克隆（Clone）
- 掌握借用（Borrowing）与引用
- 理解可变借用的排他性
- 理解生命周期（Lifetime）的基本概念

**这是整套 Rust 教程最重要、也是最难的一章。** 所有权系统是 Rust 的核心创新，它让 Rust 在无需 GC 的情况下保证内存安全。学懂这一章，Rust 就通了大半。

---

## 4.1 所有权三规则

Rust 的内存管理基于三条规则：

1. **每个值都有一个所有者（owner）**
2. **同一时刻，一个值只能有一个所有者**
3. **所有者离开作用域，值被丢弃（drop）**

```rust
fn main() {
    let s = String::from("hello");  // s 是 "hello" 的所有者
    // s 离开作用域，String 自动调用 drop 释放内存
}
```

不需要手动 free，也没有 GC——编译器在编译时插入释放代码。这就是"零成本"的自动内存管理。

---

## 4.2 移动（Move）

### 4.2.1 变量的转移

```rust
let s1 = String::from("hello");
let s2 = s1;   // s1 的所有权"移动"到 s2
// println!("{}", s1);   // 编译错误！s1 已失效
println!("{}", s2);      // OK
```

**为什么？** 看内存布局：

```
String 由三部分组成（栈上）：
┌──────────┬──────┬──────┐
│ ptr      │ len  │ cap  │  ← 栈上的描述符
└──────────┬┴──────┴──────┘
           │
           ↓
    ┌──────────────┐
    │ 堆上的 "hello" │
    └──────────────┘
```

当 `let s2 = s1`，Rust 只复制栈上的描述符（ptr/len/cap），**不复制堆上的数据**。如果两个变量都认为自己是堆数据的所有者，函数结束时会有"双重释放"（Double Free）——这正是 C++ 的隐患。

所以 Rust 让 `s1` 失效，保证**只有一个所有者**。

> **这就是 Rust 在编译期消除 Double Free 的方式！**

### 4.2.2 克隆（Clone）

如果真的想要深拷贝：

```rust
let s1 = String::from("hello");
let s2 = s1.clone();   // 深拷贝，堆数据也复制
println!("{}", s1);    // OK
println!("{}", s2);    // OK
```

### 4.2.3 Copy 类型

有些类型在栈上，复制很 cheap，不需要移动：

```rust
let x = 5;
let y = x;      // i32 是 Copy 类型，复制而非移动
println!("{}", x);  // OK，x 仍可用
```

**Copy 类型**：所有整数、浮点、bool、char、元组（如果元素都是 Copy）。

**非 Copy 类型**：String、Vec、大部分自定义类型（拥有堆数据的）。

## 4.3 所有权与函数

```rust
fn main() {
    let s = String::from("hello");
    take_ownership(s);        // s 的所有权移入函数
    // println!("{}", s);     // 编译错误！s 已失效
    
    let x = 5;
    makes_copy(x);            // i32 是 Copy，x 仍有效
    println!("{}", x);        // OK
}

fn take_ownership(some_string: String) {
    println!("{}", some_string);
    // some_string 离开作用域，被 drop
}

fn gives_back() -> String {
    let s = String::from("hello");
    s   // 返回 s，所有权转移给调用者
}
```

> 返回值也能转移所有权。这保证任何时候都有且只有一个所有者。

## 4.4 借用（Borrowing）与引用

### 4.4.1 不可变借用

每次都转移所有权很麻烦。用**引用**（`&`）借用：

```rust
fn main() {
    let s = String::from("hello");
    let len = calculate_length(&s);   // 借用 s，不转移所有权
    println!("'{}' 的长度是 {}", s, len);   // s 仍可用
}

fn calculate_length(s: &String) -> usize {
    s.len()
}
```

`&s` 是引用，指向 s 但不拥有它。函数结束后，s 的所有者（main 里的 s）仍然有效。

### 4.4.2 可变借用

```rust
fn main() {
    let mut s = String::from("hello");
    change(&mut s);   // 可变借用
    println!("{}", s);   // hello world
}

fn change(s: &mut String) {
    s.push_str(" world");
}
```

要点：

- 变量必须声明为 `mut`
- 借用时用 `&mut`
- 函数参数用 `&mut String`

### 4.4.3 可变借用的排他性（重点）

```rust
let mut s = String::from("hello");

let r1 = &mut s;
let r2 = &mut s;   // 编译错误！不能同时有两个可变借用
println!("{}, {}", r1, r2);
```

**规则**：

- 可以有多个不可变借用（`&T`）
- 只能有一个可变借用（`&mut T`）
- **不可变借用和可变借用不能同时存在**

```rust
let mut s = String::from("hello");
let r1 = &s;       // 不可变借用
let r2 = &s;       // OK，多个不可变借用
println!("{} {}", r1, r2);
let r3 = &mut s;   // OK，因为 r1/r2 最后一次使用后不再用了
println!("{}", r3);
```

> **为什么这么严格？** 为了在编译期防止**数据竞争**。数据竞争的三个条件：
> 1. 两个指针同时访问同一数据
> 2. 至少一个在写
> 3. 没有同步机制
>
> Rust 借用规则直接禁止这种情况，让并发编程更安全——编译器保证你的并发代码没有数据竞争。

### 4.4.4 悬垂引用

```rust
fn dangle() -> &String {
    let s = String::from("hello");
    &s   // 编译错误！返回局部变量的引用
}       // s 在这里被 drop，引用会悬垂
```

Rust 编译器直接拒绝这种代码，从根本上杜绝了悬垂指针（C/C++ 的 UAF）。

## 4.5 生命周期（Lifetime）

### 4.5.1 问题引入

```rust
fn longest(x: &str, y: &str) -> &str {
    if x.len() > y.len() { x } else { y }
}
```

编译错误！编译器不知道返回的引用是 x 还是 y 的，无法确认它的生命周期。

### 4.5.2 生命周期标注

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &str {
    if x.len() > y.len() { x } else { y }
}
```

`'a` 是生命周期参数，表示 x、y 和返回值共享同一个生命周期。含义：**返回的引用的有效期不超过 x 和 y 中较短的那个**。

### 4.5.3 生命周期的本质

生命周期标注**不改变**引用的实际生命周期，只是告诉编译器"这些引用的关系"，让编译器能做检查。

> **直觉理解**：生命周期就是"引用能活多久"。Rust 要确保引用不会比它指向的数据活得更久（防止悬垂引用）。

大多数情况下，编译器能自动推断生命周期（省略标注）。只有多个引用参数且返回引用时，才需要手动标注。

## 4.6 切片（Slice）

```rust
let s = String::from("hello world");
let hello = &s[0..5];    // "hello"
let world = &s[6..11];   // "world"
```

切片是引用，不拥有数据。这体现了借用的思想。

---

## 4.7 与 C/C++ 的安全对比

| 问题 | C/C++ | Rust |
|------|-------|------|
| Double Free | 可能，运行时崩溃/漏洞 | 所有权规则，编译期禁止 |
| UAF | 可能，漏洞利用常见手法 | 借用检查，编译期禁止 |
| 数据竞争 | 可能，并发 bug | 借用规则，编译期禁止 |
| 空指针 | 可能 | Option 类型强制处理 |

```cpp
// C++: 编译通过，运行时 UAF
std::string* p = new std::string("hello");
delete p;
std::cout << *p;  // UAF！
```

```rust
// Rust: 编译期就拒绝
// 编译器会在你犯错时告诉你
```

> **这就是为什么 Rust 是"安全的系统语言"**——它把 C/C++ 里运行时的内存错误，提前到编译期发现。

## 4.8 切片类型与所有权

切片（slice）是另一类引用，它不拥有数据：

```rust
let s = String::from("hello world");
let slice = &s[0..5];   // &str 类型，是对 String 的借用
```

切片的内存模型：

```
String (所有者):
┌──────┬─────┬─────┐
│ ptr  │ len │ cap │
└──────┴─────┴─────┘
       │
       ↓ 堆上数据 "hello world"

&str 切片:
┌──────┬─────┐
│ ptr  │ len │   ← 指向堆上数据的一部分，长度 5
└──────┴─────┘
```

注意 `&str` 没有 `cap` 字段——它只是借用，不能扩容。这就是为什么函数参数推荐用 `&str` 而不是 `&String`：

```rust
// 更好：能接受 String、&str、切片
fn print_name(name: &str) { println!("{}", name); }

// 受限：只能接受 String 的引用
fn print_name2(name: &String) { println!("{}", name); }
```

> **最佳实践**：函数参数用 `&str` 而不是 `&String`，用 `&[T]` 而不是 `&Vec<T>`——更通用、更灵活。这是 Rust 社区的惯例。

## 4.9 内部可变性（进阶）

借用规则很严格，但有时我们需要"看起来不可变，实际能修改"的场景。Rust 提供了内部可变性模式：

```rust
use std::cell::Cell;

struct Counter {
    value: Cell<i32>,   // Cell 允许通过 &Counter 修改内部值
}

impl Counter {
    fn increment(&self) {
        self.value.set(self.value.get() + 1);
    }
    fn get(&self) -> i32 { self.value.get() }
}
```

**Cell / RefCell 的区别**：

| 类型 | 适用 | 检查时机 |
|------|------|---------|
| `Cell<T>` | Copy 类型 | 编译期（无借用，直接读写） |
| `RefCell<T>` | 非 Copy 类型 | 运行时（借用检查推迟到运行时） |

```rust
use std::rc::Rc;
use std::cell::RefCell;

// 共享的可变数据（单线程）
let shared = Rc::new(RefCell::new(vec![1, 2, 3]));
shared.borrow_mut().push(4);   // 运行时检查借用
```

> **注意**：RefCell 把借用检查从编译期推迟到运行时——如果违反规则，程序会 panic 而不是编译失败。它是"逃生舱"，但默认优先用编译期检查的常规借用。

多线程场景用 `Mutex`（见第 8 章），它在运行时检查 + 加锁。

## 4.10 常见编译错误解读

初学者常被借用检查器的报错"劝退"。学会读懂报错很重要：

**错误 1：use of moved value**

```
error[E0382]: borrow of moved value: `s`
```

含义：尝试使用了已经移动的变量。解决：用 clone，或用引用借用。

**错误 2：cannot borrow as mutable**

```
error[E0596]: cannot borrow `x` as mutable, as it is not declared as mutable
```

含义：想可变借用但变量没声明 mut。解决：加 `mut`。

**错误 3：cannot borrow as immutable because it is also borrowed as mutable**

```
error[E0502]: cannot borrow `s` as immutable because it is also borrowed as mutable
```

含义：同时有可变和不可变借用。解决：调整借用作用域，让第一个借用先用完。

**错误 4：missing lifetime specifier**

```
error[E0106]: missing lifetime specifier
```

含义：返回引用但编译器无法确定生命周期。解决：加生命周期标注 `'a`。

> **心态**：这些报错不是"阻碍"，而是编译器在免费帮你做代码审查。C/C++ 程序员写出的 UAF、Double Free，在 Rust 里编译都过不了。这种"严格"正是安全的保证。

## 4.11 本章总结

| 概念 | 核心要点 |
|------|---------|
| 所有权三规则 | 一个所有者、同一时刻唯一、离开作用域 drop |
| 移动 Move | 转移所有权，原变量失效（防 Double Free） |
| 克隆 Clone | 深拷贝 |
| Copy 类型 | 栈上简单类型，复制而非移动 |
| 借用 | `&T` 不可变、`&mut T` 可变；不转移所有权 |
| 借用规则 | 多个不可变 OR 一个可变；不能同时 |
| 切片 | `&str`/`&[T]`，无所有权，函数参数优选 |
| 内部可变性 | Cell/RefCell，运行时借用检查 |
| 生命周期 | `'a` 标注；防止悬垂引用 |
| 安全价值 | 编译期消除 Double Free、UAF、数据竞争 |
