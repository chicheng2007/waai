## 2.1 理解编译型语言

Python 是**解释型**语言：写完代码直接运行，Python 解释器一边翻译一边执行。

C/C++ 是**编译型**语言：写完代码要先"编译"成机器码（可执行文件），再运行。

```
Python:  hello.py ──→ Python解释器 ──→ 执行
C:       hello.c ──→ 编译器 ──→ hello.exe ──→ 执行
                    (编译)
```

编译型语言的好处：运行快、能直接操作硬件；代价：多一个编译步骤。

### 2.1.1 编译的四个阶段

```c
源代码 hello.c
    ↓ 预处理（处理 #include、#define）
    ↓ 编译（翻译成汇编）
    ↓ 汇编（汇编翻译成机器码 .o 文件）
    ↓ 链接（把库函数链接进来）
可执行文件 hello
```

理解这个过程，对后面解决"链接错误"很有帮助。

## 2.2 安装编译器

### 2.2.1 Windows

推荐安装 **MinGW-w64** 或直接使用 **Dev-C++ / Visual Studio**：

**方案一：MinGW-w64（轻量）**

1. 下载 MinGW-w64（推荐从 <https://www.mingw-w64.org/> 或 MSYS2 安装）
2. 把 `bin` 目录加入 PATH 环境变量
3. 验证：命令行输入 `gcc --version`，显示版本即成功

**方案二：Dev-C++（新手友好，集成 IDE）**

1. 下载 Dev-C++（如 TDM-GCC 版本）
2. 安装后直接写代码、点"编译运行"按钮

**方案三：Visual Studio（专业，体积大）**

适合做大型 C++ 项目。

### 2.2.2 macOS

打开终端，安装 Xcode 命令行工具：

```bash
xcode-select --install
```

验证：

```bash
gcc --version
```

macOS 的 `gcc` 实际是 Clang，用法兼容。

### 2.2.3 Linux（Ubuntu）

```bash
sudo apt update
sudo apt install build-essential gdb
```

`build-essential` 包含 gcc、g++、make 等工具，`gdb` 是调试器。

## 2.3 第一个 C 程序

创建文件 `hello.c`：

```c
#include <stdio.h>

int main() {
    printf("Hello, World!\n");
    return 0;
}
```

逐行解释：

- `#include <stdio.h>`：包含标准输入输出头文件，因为要用 `printf`
- `int main()`：主函数，程序执行的入口。`int` 表示返回一个整数
- `printf("Hello, World!\n");`：打印字符串。`\n` 是换行符。分号 `;` 表示语句结束
- `return 0;`：返回 0，表示程序正常结束

### 2.3.1 编译运行

```bash
# 编译
gcc hello.c -o hello

# 运行（Linux/macOS）
./hello

# Windows
hello.exe
```

输出：

```
Hello, World!
```

`gcc hello.c -o hello`：`-o hello` 指定输出文件名。不加的话默认生成 `a.out`。

### 2.3.2 编译 C++ 程序

C++ 文件后缀是 `.cpp`，用 `g++` 编译：

```cpp
// hello.cpp
#include <iostream>

int main() {
    std::cout << "Hello, C++!" << std::endl;
    return 0;
}
```

```bash
g++ hello.cpp -o hello
./hello
```

C++ 用 `std::cout` 输出，`<<` 是输出运算符，`std::endl` 是换行。

## 2.4 常用编译选项

```bash
# 开启所有警告（强烈推荐！能发现潜在 bug）
gcc -Wall hello.c -o hello

# 开启优化（生产环境用，-O2 是常用级别）
gcc -O2 hello.c -o hello

# 调试模式（生成调试信息，配合 gdb）
gcc -g hello.c -o hello

# 组合使用
gcc -Wall -g -O2 hello.c -o hello
```

> **重要**：永远开着 `-Wall`！很多安全漏洞（如格式化字符串问题）编译器会给出警告，认真对待这些警告能避免很多麻烦。

## 2.5 体验"段错误"（Segmentation Fault）

C 语言最著名的崩溃就是段错误。让我们故意写一个：

```c
// segfault.c
#include <stdio.h>

int main() {
    int *p = NULL;        // 空指针
    printf("%d\n", *p);   // 解引用空指针 → 段错误！
    return 0;
}
```

```bash
gcc -g segfault.c -o segfault
./segfault
```

运行结果：

```
Segmentation fault (core dumped)
```

程序崩溃了。这就是 C 语言的"残酷"——它不会保护你，访问非法内存直接崩溃。

> **这就是安全漏洞的源头**：如果攻击者能控制指针，就能让程序访问任意内存——这是漏洞利用的基础。第 10 章会深入讲。

### 2.5.1 用 gdb 定位崩溃

```bash
gdb ./segfault
(gdb) run
Program received signal SIGSEGV, ...
(gdb) backtrace    # 查看崩溃时的调用栈
```

gdb 能告诉你崩溃发生在哪一行、什么原因。学会调试是 C/C++ 程序员的必备技能。
