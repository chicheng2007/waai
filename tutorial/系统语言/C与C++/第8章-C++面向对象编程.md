从本章开始进入 C++。C++ 在保留 C 底层能力的同时，加入了面向对象，让代码更易组织、更安全。但要注意：C++ 依然允许直接操作内存，所以安全责任仍在程序员手上。

## 8.1 C++ 初印象

### 8.1.1 第一个 C++ 程序

```cpp
#include <iostream>
#include <string>

int main() {
    std::string name = "AI安全";
    std::cout << "你好, " << name << std::endl;
    return 0;
}
```

对比 C：

- 用 `std::cout` 代替 `printf`（类型安全，不用记格式符）
- 用 `std::string` 代替字符数组（自动管理内存，更安全）
- 用 `iostream` 头文件

编译：

```bash
g++ -Wall -std=c++17 hello.cpp -o hello
```

### 8.1.2 C++ 的安全改进

```cpp
// C 风格：容易出错
char buf[8];
strcpy(buf, "超长字符串...");   // 溢出！

// C++ 风格：自动管理
#include <string>
std::string s = "超长字符串...";   // 自动分配，不会溢出
```

`std::string`、`std::vector` 等标准库容器自动管理内存，大大减少了内存错误。这是 C++ 相比 C 的重要安全进步。

## 8.2 类与对象

### 8.2.1 定义类

```cpp
#include <iostream>
#include <string>

class PortScanner {
private:
    std::string target;        // 私有属性
    int timeout;
    
public:
    // 构造函数
    PortScanner(std::string t, int to = 500) : target(t), timeout(to) {}
    
    // 方法
    void scan() {
        std::cout << "扫描 " << target << std::endl;
    }
    
    std::string getTarget() const { return target; }  // const 成员函数
};

int main() {
    PortScanner scanner("127.0.0.1");
    scanner.scan();
    return 0;
}
```

### 8.2.2 访问控制

| 关键字 | 含义 |
|--------|------|
| `public` | 外部可访问 |
| `private` | 只有类内部可访问（默认） |
| `protected` | 类内部和子类可访问 |

> **封装的意义**：把数据藏起来，只暴露安全的接口。比如 `target` 是私有的，外部不能直接改，必须通过方法，这样可以在方法里加验证。

### 8.2.3 构造函数与析构函数（RAII）

```cpp
class Buffer {
private:
    char *data;
    size_t size;
    
public:
    // 构造：申请资源
    Buffer(size_t n) : size(n) {
        data = new char[n];
        std::cout << "分配 " << n << " 字节\n";
    }
    
    // 析构：自动释放资源
    ~Buffer() {
        delete[] data;
        std::cout << "释放内存\n";
    }
};

int main() {
    Buffer buf(100);   // 自动调用构造
    // ... 使用 buf
    return 0;          // 自动调用析构，内存被释放！
}
```

> **RAII（Resource Acquisition Is Initialization）**：资源在构造时获取，析构时释放。这是 C++ 管理资源的核心思想，能有效避免内存泄漏。对象离开作用域，析构函数自动调用，资源自动释放——比 C 的手动 malloc/free 安全得多。

## 8.3 三大特性

### 8.3.1 封装

```cpp
class BankAccount {
private:
    double balance;
public:
    BankAccount(double b) : balance(b) {}
    
    void deposit(double amount) {
        if (amount > 0) balance += amount;   // 验证逻辑
    }
    
    double getBalance() const { return balance; }
};
```

### 8.3.2 继承

```cpp
// 基类
class Threat {
protected:
    std::string name;
public:
    Threat(std::string n) : name(n) {}
    virtual void analyze() {   // 虚函数
        std::cout << "分析威胁: " << name << std::endl;
    }
    virtual ~Threat() = default;   // 虚析构函数（重要！）
};

// 派生类
class Malware : public Threat {
public:
    Malware(std::string n) : Threat(n) {}
    void analyze() override {   // 重写
        std::cout << "分析恶意软件: " << name << std::endl;
    }
};

class Phishing : public Threat {
public:
    Phishing(std::string n) : Threat(n) {}
    void analyze() override {
        std::cout << "分析钓鱼攻击: " << name << std::endl;
    }
};
```

> **虚析构函数**：如果类可能被继承，析构函数必须声明为 `virtual`，否则通过基类指针删除派生类对象时，派生类的析构不会被调用，导致资源泄漏。

### 8.3.3 多态

```cpp
#include <vector>
#include <memory>

int main() {
    std::vector<std::unique_ptr<Threat>> threats;
    threats.push_back(std::make_unique<Malware>("WannaCry"));
    threats.push_back(std::make_unique<Phishing>("钓鱼邮件"));
    
    for (auto &t : threats) {
        t->analyze();   // 同一个调用，不同的行为（多态）
    }
    return 0;
}
```

输出：

```
分析恶意软件: WannaCry
分析钓鱼攻击: 钓鱼邮件
```

### 8.3.4 虚函数的底层原理（安全视角）

虚函数通过**虚函数表（vtable）**实现：

```
对象内存布局：
┌──────────────┐
│ vptr (虚表指针) │ ← 指向虚函数表
├──────────────┤
│ 成员变量      │
└──────────────┘

虚函数表：
[&Malware::analyze, &Malware::其他虚函数...]
```

> **安全关联**：C++ 对象的虚表指针（vptr）是攻击者的重要目标。通过 UAF（释放后使用）或越界写覆盖 vptr，可以劫持虚函数调用，实现任意代码执行。这是浏览器漏洞利用的经典手法。理解 vtable 布局，才能理解这类攻击。

## 8.4 智能指针（现代 C++ 的安全利器）

```cpp
#include <memory>

// unique_ptr：独占所有权，自动释放
std::unique_ptr<int> p = std::make_unique<int>(10);

// shared_ptr：共享所有权，引用计数
std::shared_ptr<int> sp = std::make_shared<int>(20);
std::shared_ptr<int> sp2 = sp;   // 引用计数 +1

// weak_ptr：弱引用，避免循环引用
```

> **智能指针的意义**：自动管理内存，避免忘记 delete、避免 UAF。现代 C++ 提倡用智能指针代替裸指针（raw pointer），这是 C++ 安全编码的重要实践。
