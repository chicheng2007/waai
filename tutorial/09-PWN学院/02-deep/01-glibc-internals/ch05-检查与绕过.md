# 第 5 章 堆检查机制与绕过思路总览

> 这一章把前四章涉及的检查按版本梳理成一张「年表」，并总结出绕过检查的通用思路。

---

## 5.1 glibc 版本检查年表

| 版本 | 引入的检查 | 失效的经典技术 | 催生的新技术 |
| --- | --- | --- | --- |
| 2.26 | tcache 引入 | — | tcache dup / poisoning（无检查黄金期） |
| 2.28 | — | — | unsorted bin attack 最后的有效版本 |
| 2.29 | tcache key、unlink 双向检查、top chunk 检查、unsorted `bck->fd` 检查 | unsorted bin attack、经典 unlink、House of Force（部分） | largebin attack、伪造合法链表 |
| 2.32 | safe-linking（指针编码）、fastbin 对齐检查 | 直接伪造 fd 的 tcache/fastbin attack | 需先泄露堆地址再编码 |
| 2.34 | 移除 malloc/free/realloc hooks | 所有 hook 劫持 | IO_FILE 利用、House of Apple |
| 2.35 | vtable 检查加强 | 传统 FSOP | House of Apple 2/3 |

## 5.2 各类检查的原理与绕过

### 5.2.1 指针编码（safe-linking）

**检查**：fd/next 指针必须能正确解码解码成一个合法地址。

**绕过**：
1. 泄露堆地址（unsorted bin leak、tcache 结构泄露）
2. 用 `(chunk_addr >> 12) ^ target` 计算编码后的值

### 5.2.2 双链表完整性检查

**检查**：`FD->bk == P && BK->fd == P`

**绕过**：
1. 构造「自洽的假链表」——在伪造位置同时写入合法的指针
2. 用两个连续的写操作先构造检查条件，再触发 unlink
3. 改用不受此检查的路径（如 tcache 的单向链表）

### 5.2.3 size 匹配检查

**检查**：fake chunk 的 size 必须匹配目标 bin 的索引。

**绕过**：
1. 在内存中找「天然的」fake chunk（某个位置的字节恰好是合适的 size）
2. 用 UAF 同时控制 size 和 fd（先写 size 再写 fd）

### 5.2.4 hook 移除

**检查**：没有 hook 可劫持。

**绕过**：
1. IO_FILE 利用（改写 stdout 的 write_base 泄露、vtable 劫持）
2. `__exit_funcs`（exit 处理函数链）
3. GOT 覆写（如果 Partial RELRO）

## 5.3 绕过的通用思路

### 思路一：找到不受检查的路径

tcache 是单向链表，没有双链表检查 → 所以 tcache poisoning 一直是主流。

当 tcache 被 safe-linking 保护后 → 转向 IO_FILE（不受堆检查影响）。

### 思路二：让检查的条件成立

不是绕过检查，而是**满足它**。比如伪造 unlink 时，同时构造 `FD->bk = P` 和 `BK->fd = P` 的环境。

### 思路三：信息泄露先行

现代 glibc 的很多检查依赖「攻击者不知道地址」这个前提。泄露堆地址/libc 地址后，很多检查都能被满足（比如 safe-linking 的编码需要堆地址）。

### 思路四：利用程序自身的逻辑

不直接攻击堆结构，而是让程序自己调用危险函数（比如通过 UAF 改写函数指针，让程序调用 system）。这是最稳妥的思路。

## 5.4 选择攻击路径的决策树

```text
拿到题目
   │
   ├─ 有 UAF？
   │    ├─ 是 → 能泄露 libc？
   │    │        ├─ 是 → tcache poisoning → IO_FILE/hook
   │    │        └─ 否 → 先泄露（unsorted bin leak / 格式化字符串）
   │    └─ 否 ↓
   ├─ 有 double free？
   │    ├─ glibc < 2.29 → 直接 dup
   │    ├─ 2.29~2.31 → 清 key 或 malloc 后重 free
   │    └─ 2.32+ → 需要堆地址 + safe-linking 编码
   ├─ 有 off-by-one？
   │    └─ null byte poisoning → House of Einherjar / chunk 重叠
   ├─ 能改 top chunk size？
   │    └─ glibc < 2.29 → House of Force
   └─ 能分配任意大小？
        └─ House of Orange → FSOP
```

## 5.5 小结

这一章我们梳理了 glibc 堆检查的演化史和绕过思路。核心规律：

> **检查只在「攻击者不具备某能力」时有效。一旦你通过信息泄露获得那个能力，检查就不攻自破。**
