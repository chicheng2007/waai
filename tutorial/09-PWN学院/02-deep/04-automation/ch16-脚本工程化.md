# 第 16 章 利用脚本工程化

> 写 exp 不只是「能跑通」，还要易维护、可复用、能快速适配本地和远程。这一章讲利用脚本的工程化实践。

---

## 16.1 为什么要工程化

一个复杂的 exp 可能有几百行，包含：

- 本地调试和远程利用两套逻辑
- 多个阶段的 payload 构造
- 大量的偏移量和地址计算
- 调试开关

如果不组织好，改一个偏移量可能要翻遍整个文件。

---

## 16.2 模块化结构

推荐的 exp 结构：

```python
#!/usr/bin/env python3
from pwn import *

# ========== 配置区 ==========
BINARY = './vuln'
LIBC = './libc.so.6'
REMOTE_HOST = 'chall.ctf.com'
REMOTE_PORT = 31337

OFFSET = 72
POP_RDI = 0x4012a3

# ========== 初始化 ==========
context.arch = 'amd64'
context.log_level = 'info'

elf = ELF(BINARY, checksec=False)
libc = ELF(LIBC, checksec=False)

# ========== 工具函数 ==========
def start():
    if args.REMOTE:
        return remote(REMOTE_HOST, REMOTE_PORT)
    if args.GDB:
        return gdb.debug(BINARY, 'b main')
    return process(BINARY)

def leak_libc(p):
    """泄露 libc 基址"""
    pass

def get_shell(p):
    """获取 shell"""
    pass

# ========== 主逻辑 ==========
def main():
    p = start()
    
    libc.address = leak_libc(p)
    log.success(f'libc base: {hex(libc.address)}')
    
    get_shell(p)
    p.interactive()

if __name__ == '__main__':
    main()
```

## 16.3 多环境适配

```python
# 支持本地/远程/GDB 三种模式
def start():
    if args.REMOTE:
        return remote(HOST, PORT)
    elif args.GDB:
        return gdb.debug([elf.path], gdbscript='''
            b *0x401234
            continue
        ''')
    else:
        return process(elf.path)
```

运行时：

```bash
python3 exp.py           # 本地
python3 exp.py GDB       # 带 gdb
python3 exp.py REMOTE    # 打远程
```

## 16.4 配置与代码分离

把偏移量、地址等配置放到单独的文件：

```python
# config.py
BINARY = './vuln'
OFFSET = 72
POP_RDI = 0x4012a3
RET = 0x40101a
```

## 16.6 错误处理

```python
try:
    p.sendline(payload)
    data = p.recvline(timeout=2)
    if b'fail' in data:
        log.warning('利用失败，重试...')
except EOFError:
    log.error('连接断开')
```

## 16.7 小结

这一章我们讲了 exp 的工程化：

- 模块化结构（配置、初始化、工具函数、主逻辑）
- 多环境适配（本地/GDB/远程）
- 配置与代码分离
- 分阶段日志与错误处理

好的 exp 结构能让你在比赛中快速调整思路，而不是被自己的代码绕晕。
