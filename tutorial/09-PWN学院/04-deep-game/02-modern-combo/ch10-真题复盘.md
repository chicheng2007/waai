# 第 10 关 · BOSS 复盘：一道 2.35 真题的完整思路

## 🎬 游戏开场

现在是现代连招篇的高潮:完整走一遍 glibc 2.35 堆题的解题思路。

我们假设一道典型的菜单堆题:有 add/delete/edit/show,Free 后指针没清空(UAF),glibc 2.35(无 hook、有 key、有 safe-linking)。目标是拿 shell。

把前 9 关串起来,节奏是这样的:

```
① 判断版本 → 定策略
② 泄露 libc(unsorted bin)
③ 泄露堆地址(safe-linking需要)
④ largebin attack → 任意写
⑤ 伪造 FILE + House of Apple
⑥ 触发 exit → system("/bin/sh")
```

---

## 🧠 完整思路（游戏化）

### ① 判断版本,定策略

```bash
checksec + 泄漏libc版本
```

结论:2.35 → 无 __free_hook(第 4 关),must 用 IO_FILE / House of Apple(第 6 关)。

游戏翻译:看了反作弊版本,知道老路(钩子)死了,得走存档系统这条路。

### ② 泄露 libc

利用 UAF 读:申请大 chunk,free 进 unsorted bin,show 读出 fd(main_arena)→ libc 基址(基础篇第 21 关)。

### ③ 泄露堆地址

safe-linking 需要堆地址(第 4 关)。同样通过 UAF 读一个 tcache chunk 的(编码后的)next,或直接看 chunk 内容里的堆指针,反推堆基址。

游戏翻译:打码的密码需要门牌号——先搞到门牌号。

### ④ largebin attack → 任意写

布置两个大小不同的 large chunk,利用 UAF 篡改 bk_nextsize(编码需堆址),触发 largebin 插入,把 fake FILE 的地址写进 `_IO_list_all`(第 8 关)。

游戏翻译:用分类架攻击,把"存档链表头"改成指向我们堆上的假存档卡。

### ⑤ 伪造 FILE + House of Apple

在堆上构造 fake `_IO_FILE`:

- flags 设成满足条件的值
- vtable 指向 `_IO_wfile_jumps + offset`(合法偏移,绕过检查)
- `_wide_data` 等字段布置好攻击链

游戏翻译:造一张假存档卡,技能清单指向真清单的特殊按钮,备注栏写好 system。

### ⑥ 触发

程序走到 `exit()`(或 `puts`),遍历 FILE 链表 → 刷到假卡 → 合法 vtable 偏移被调用 → 执行 system("/bin/sh")。

```

flag{modern_heap_master}
```
