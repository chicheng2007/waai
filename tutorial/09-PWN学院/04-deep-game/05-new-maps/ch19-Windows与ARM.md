# 第 19 关 · 换台游戏机：Windows 与 ARM 入门

## 🎬 游戏开场

你已经是 Linux x86-64 的高手了。但世界上还有很多"游戏机":

- **Windows**:另一款主流操作系统,规则完全不同。
- **ARM/AArch64**:手机、嵌入式设备用的 CPU,指令集精简。

这一关作为进阶篇的收官,带你"换个地图"看看。核心思想不变——**找漏洞、控制 rip、拿权限**——但具体实现天差地别。

---

## 🧠 核心概念（游戏版）

### 1. Windows PWN vs Linux PWN

| 方面 | Linux | Windows |
| --- | --- | --- |
| 可执行文件格式 | ELF | PE |
| 保护机制 | Canary/NX/ASLR/RELRO | GS/DEP/ASLR/CFG |
| 栈保护 | Canary | GS Cookie(类似Canary) |
| 调用约定 | 参数放寄存器 | x64用rcx/rdx/r8/r9;x86用栈 |
| 系统库 | libc | kernel32/ntdll |
| 堆管理器 | ptmalloc | Windows Heap |

游戏翻译:换了个游戏,地图格式(PE vs ELF)、保护名字(GS vs Canary)、传参方式都变了,但"叠盘子、改卷轴"的本质一样。

### 2. Windows 的独特机制

- **SEH(结构化异常处理)**:Windows 的异常处理机制,栈上有个"异常处理链表",覆盖它能劫持控制流(经典的 SEH overwrite)。
- **GS Cookie**:Windows 版的 Canary,函数返回前检查。
- **CFG(控制流保护)**:类似间接调用检查。

游戏翻译:Windows 有自己的"警报器"(GS)和"异常处理程序"(SEH)——后者被覆盖能变成攻击入口,这是 Windows 特有的招式。

### 3. ARM/AArch64

ARM 是精简指令集(RISC),常见于手机、路由器、嵌入式:

- **ARM32**:32位,指令定长4字节,有 ARM/Thumb 两种模式。
- **AArch64**:64位,31个通用寄存器(x0-x30),调用约定参数放 x0-x7。

游戏翻译:换了台掌机,按键布局(寄存器)和指令更精简,但"改返回地址控制流"的道理一样。ARM 的返回地址存在 **LR 寄存器**(链接寄存器),栈溢出要覆盖的是 LR 或栈上的返回地址。

### 4. 跨平台的核心思维

无论哪个平台,PWN 的本质不变:

```
① 找到内存破坏漏洞(溢出/UAF/...)
② 控制程序计数器(rip/eip/PC/LR)
③ 让程序执行你想要的逻辑(get shell / 提权 / 读flag)
```

变的只是:

- 用什么指令集(汇编)
- 什么格式的地图(ELF/PE/Mach-O)
- 什么保护机制(Canary/GS/...)
- 什么利用原语(ROP/JOP/...)

游戏翻译:换了游戏机,按钮名字变了,但"作弊的思路"通用——找到系统的漏洞,让它按你的意思运行。

### 5. 如何继续深入

- **Windows PWN**:推荐看《Windows 内核安全技术》、学习 SEH、堆利用。
- **ARM**:用 qemu-arm 搭建环境,练 Thumb 模式的 ROP。
- 硬核版教程也有跨平台章节。
