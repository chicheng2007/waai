# 第 17 关 · 管理员模式：内核世界初探

## 🎬 游戏开场

基础篇第 25 关我们初探了内核(管理员模式)。这一季我们深入一点:看看内核世界的"游戏规则"到底有什么不同,以及内核漏洞利用的独特性。

内核 PWN 和用户态最大的区别:

- **用户态**:程序崩了就崩了,不影响系统。
- **内核态**:崩了就是 kernel panic,整个系统挂掉。

而且内核里没有 libc、没有栈保护那一套,取而代之的是 slab 分配器、cred 结构、系统调用接口。 gameplay 完全不同。

---

## 🧠 核心概念（游戏版）

### 1. 内核世界的地图

```
用户空间 (ring 3)  ← 普通玩家
  │ syscall 系统调用(服务窗口)
  ▼
内核空间 (ring 0)  ← 管理员办公区
  ├─ 内核代码/数据
  ├─ slab 分配器(内核储物柜)
  ├─ 驱动模块(.ko)  ← 漏洞往往在这
  └─ 进程凭证 cred
```

游戏翻译:玩家通过"服务窗口"(syscall)请管理员办事。管理员办公区里有自己的储物柜系统(slab)和身份卡(cred)。漏洞常藏在你加载的"外挂模块"(驱动 .ko)里。

### 2. 内核的"堆":slab/slub

用户态 malloc → 内核态 `kmalloc`,用 **slab** 分配器。它也有"空闲对象链表"(freelist),也有 UAF、overflow 漏洞。

游戏翻译:内核也有储物柜中心,只是柜子里放的是内核对象(结构体会),规则和用户态的 tcache 不同。

### 3. 交互接口:驱动模块

内核题通常给你一个**有漏洞的驱动模块**(.ko),它创建了一个设备文件(如 `/dev/vuln`)。你通过 `open/read/write/ioctl` 跟它交互:

```c
int fd = open("/dev/vuln", 0);
ioctl(fd, 命令, 参数);   // 很多内核漏洞在ioctl里
```

游戏翻译:你通过一个"服务窗口"(设备文件)给管理员递纸条,某些命令会触发管理员的错误操作(漏洞)。

### 4. 常见内核漏洞类型

| 漏洞 | 游戏说法 |
| --- | --- |
| 内核 UAF | 退租管理员装备后继续用 |
| 越界读写(OOB) | 往隔壁柜子塞/拿东西 |
| 栈溢出 | 内核栈上堆菜 |
| 条件竞争 | 趁管理员转身动手(竞态) |
| 空指针解引用 | 无效坐标 |

### 5. 环境准备

内核 PWN 需要专门环境:

```bash
# QEMU 启动
qemu-system-x86_64 \
  -kernel bzImage \
  -initrd rootfs.cpio.gz \
  -append "console=ttyS0" \
  -nographic

# 题目文件
bzImage      # 内核镜像
rootfs.cpio  # 文件系统(含漏洞驱动)
vmlinux      # 带符号内核(调试用)
```

## 🎯 本关任务:启动你的第一个内核环境

1. 下载一个入门内核题(如 CTFWiki 的 kernel 题)。
2. 用 QEMU 启动,进去执行 `id` 看当前身份。
3. 找到漏洞驱动的设备文件,看看 `/dev/` 下面有什么。
4. 理解目标:利用驱动漏洞把自己变成 root。
