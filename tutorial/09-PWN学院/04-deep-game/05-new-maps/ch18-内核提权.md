# 第 18 关 · kernel ROP：在管理员模式里提权

## 🎬 游戏开场

用户态的目标是"拿 shell",内核态的目标通常是**提权**——把当前进程从普通玩家变成 root(uid=0)。

内核里有个经典的两连招:

```c
commit_creds(prepare_kernel_cred(0));
```

- `prepare_kernel_cred(0)`:造一张"root 身份卡"(cred)。
- `commit_creds(...)`:把这张卡给当前进程。

执行完这两句,当前进程就是 root 了。回到用户态,你就是超级管理员。

游戏翻译:内核里有"造管理员身份卡"和"给卡"两个官方函数,你想办法让内核帮你调用它们——你就升级成管理员了。

---

## 🧠 核心概念（游戏版）

### 1. 提权的几种方式

| 方式 | 游戏说法 |
| --- | --- |
| 直接调 `commit_creds(prepare_kernel_cred(0))` | 让管理员亲手给你发管理员卡 |
| 改写当前进程的 `cred` 结构字段 | 偷偷把自己身份卡上的 uid 涂成0 |
| 劫持控制流执行上述代码 | 抢占管理员的笔,自己填卡 |

### 2. 内核态 ROP

和用户态 ROP 类似,但环境不同:

- gadget 来自内核代码(vmlinux),不是 libc。
- 需要绕过 **SMEP/SMAP**(内核的保护:禁止执行用户态代码、禁止访问用户态数据)。

绕过方法:

- **SMEP 绕过**:用内核里的 ROP gadget 执行提权代码(不跳到用户态 shellcode)。
- **SMAP 绕过**:通过 ROP gadget 读写用户态数据,或关闭 SMAP(改 CR4 寄存器)。

游戏翻译:内核开了"禁止用玩家提供的代码"的规矩(SMEP)。你不能像用户态那样跳到自己的 shellcode,只能在内核自己的代码里找积木(内核ROP)拼出提权操作。

### 3. 经典的 ret2usr 与 kernel ROP

- **ret2usr**(老套路):把内核控制流劫持到用户态的提权代码。SMEP 开启后失效。
- **kernel ROP**(现代):完全用内核 gadget 拼链,调用 commit_creds 等。

### 4. 提权后回到用户态

提权后需要安全返回用户态:

```asm
swapgs          ; 切换gs段寄存器
iretq           ; 返回用户态
```

还得布置好 iretq 需要的寄存器(用户态的 rip/cs/rflags/rsp/ss)。

游戏翻译:升级成管理员后,还得"正常下班回大厅"(用 swapgs; iretq 回用户态),否则回不去。

### 5. 拿到 root 后

回到用户态执行 `system("/bin/sh")`,你就是 root shell:

```bash
# id
uid=0(root) gid=0(root)
```
