# 第 13 关 · stdout 泄露：让游戏自己报答案

## 🎬 游戏开场

有个巧妙的泄露技巧:不靠格式化字符串,也不靠 UAF 读,而是**操纵 stdout(标准输出)的缓冲区指针**,让程序在打印时,把你指定的一段内存"顺便"打印出来。

游戏比喻:你不黑进游戏数据库,而是改了"公告栏"的指针,让游戏自己把机密写在公告栏上给你看——游戏亲手把答案报给你。

这叫 **stdout 泄露**,是 IO_FILE 利用的经典应用。

---

## 🧠 核心概念（游戏版）

### 1. stdout 的缓冲机制

`printf` 输出时,数据先进 stdout 的缓冲区,缓冲区满了或刷新时才真正写到屏幕。stdout 结构里有两个关键指针:

- `_IO_write_base`:缓冲区起点(从哪开始写屏幕)
- `_IO_write_ptr`:缓冲区当前位置(写到哪)

刷新时,程序把 `[_IO_write_base, _IO_write_ptr)` 这段内容写到 fd 1(屏幕)。

游戏翻译:公告栏有两根指针——"从哪开始念"和"念到哪"。程序刷新时把这两根指针之间的内容念出来。

### 2. 泄露原理

如果你能把 `_IO_write_base` 改成一个你想读的地址(比如 GOT 表),同时保证 `_IO_write_ptr` 在它后面,然后触发一次刷新——程序就会把 `[write_base, write_ptr)` 这段内存打印出来!

游戏翻译:把"从哪开始念"的指针偷偷挪到机密文件的位置,程序刷新公告栏时,就把机密念出来了。

**限制**:

- 要能改写 stdout 结构(通过任意写,或 stdout 位于可写区)。
- 泄露的长度受 write_ptr - write_base 控制。
- 常配合 partial overwrite(只改 write_base 的低几个字节,因为 stdout 地址高位不变)。

### 3. 典型套路:_IO_2_1_stdout_ 部分改写

stdout 结构位于 libc 的数据区,地址随 ASLR 变,但低 12 位固定。如果只有 "1字节/2字节任意写"的能力(如 formatted string 的 `%hhn`),可以只改 stdout 的 `_IO_write_base` 低字节,让它指向 GOT 附近,然后触发打印泄露 libc。

游戏翻译:你只能改门牌号的最后几位,但刚好能把"从哪念"挪到机密区——足够了。

### 4. 和 House of Apple 的关系

stdout 泄露是"IO_FILE 用来读"的路线;House of Apple 是"IO_FILE 用来控制流劫持"的路线。两者都是 IO_FILE 利用家族的成员,前置都是"能改 FILE 结构"。

## 🎯 本关任务:观察 stdout 指针

```bash
gdb ./程序
(gdb) p _IO_2_1_stdout_. _IO_write_base
(gdb) p _IO_2_1_stdout_. _IO_write_ptr
(gdb) p _IO_2_1_stdout_.fileno
```

看看这俩指针指向哪、差值多大(通常是缓冲区的 0x1000 左右)。理解"程序会把这段内容写到屏幕"。
