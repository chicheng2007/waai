# 第 1 章 写在前面的话：为什么学 PWN

>  suppose you're in a CTF competition, staring at a binary file that seems harmless—until you realize it's hiding a secret that only the right input can unlock. This chapter is about why you should care.

*（上面那句话划掉，我们说中文。）*

> 你正盯着一个看起来人畜无害的二进制文件，直到你意识到：只要输入一段精心构造的数据，就能让它乖乖交出 shell。这一章，我们来聊聊为什么这件事值得你花时间。

---

## 1.1 一个场景

先来描述一个很多 pwner 都经历过的场景。

比赛还有三小时结束，你的队伍在 PWN 题上一筹莫展。同队的 Web 手已经拿下了三道题，Reverse 手正在爆杀一道混淆题，而你面前这个叫 `baby_heap` 的程序，你连它用了 glibc 哪个版本都还没搞明白。

你打开 gdb，按下 `r`，程序跑起来，提示你输入。你随便打了几个 `A`，程序崩溃了——Segmentation fault。你觉得有点意思，开始调偏移、看汇编、画堆块结构图。时间一分一秒过去，榜上的分数在涨，你的 exp 还是跑不通。

就在你准备放弃的时候，你突然发现：那个 free 之后的 chunk 的 fd 指针，竟然还能被你控制。

你的手心开始出汗。你迅速写下一个 payload，按下回车——

```
[*] Switching to interactive mode
$ cat flag
flag{you_are_a_pwner_now}
```

那一刻的肾上腺素，是任何游戏都给不了的。

**这就是 PWN 的魅力。** 它是一场你与程序编写者之间的智力对决：他设计了层层防护，你则要找到那一个被遗忘的缝隙，然后用手里的输入，把整个程序的控制权夺过来。

这个教程，就是教你如何成为那个找到缝隙的人。

---

## 1.2 什么是 CTF

在正式开始之前，先把几个名词解释清楚。

**CTF（Capture The Flag，夺旗赛）** 是网络安全领域最流行的竞赛形式。简单说，就是主办方出一系列与安全相关的题目，参赛队伍解题拿到「flag」（一段形如 `flag{...}` 的字符串），提交得分，得分高者获胜。

CTF 题目通常分为五大方向：

| 方向 | 英文名 | 考什么 |
| --- | --- | --- |
| Web | Web | SQL 注入、XSS、文件上传、反序列化等 Web 安全漏洞 |
| Reverse | Reverse Engineering | 逆向工程，分析二进制程序逻辑，找出隐藏信息 |
| PWN | PWN | 二进制漏洞利用，通过漏洞控制程序执行流程 |
| Crypto | Cryptography | 密码学，古典密码、现代密码、数论 |
| Misc | Miscellaneous | 杂项，隐写术、取证、编码、脑洞题 |

除了这五大方向，还有 Mobile（安卓/iOS）、Blockchain（区块链）、AI Security（AI 安全）等新兴方向。

CTF 主要有两种赛制：

- **解题赛（Jeopardy）**：像考试一样，题目按难度和分值列出，自己选题做。我们上面描述的场景就是解题赛。
- **攻防赛（Attack & Defense）**：每支队伍有自己的服务，既要攻击别人的服务拿 flag，又要修补自己服务的漏洞。这种赛制节奏极快，非常刺激。

对于新手，我建议从解题赛开始，尤其是解题赛里的 PWN 题——它们通常有明确的难度梯度，适合循序渐进。

## 1.3 什么是 PWN

「PWN」这个词源自黑客文化中的「own」，意思是「拥有、征服」。在黑客语境里，攻破一台机器叫「own a box」，写成谐音梗就是「pwn」。后来这个词进入 CTF，专指**通过漏洞利用（Exploitation）拿到程序的控制权**。

在 CTF 题目里，一道典型的 PWN 题会给你：

1. 一个编译好的二进制程序（有时附带源码，更多时候没有）
2. 一个运行这个程序的远程服务地址（IP + 端口）
3. 偶尔会给你 libc 文件

你的任务是：找到程序里的漏洞，构造一段输入（payload），让程序执行你想要的代码——通常是执行 `system("/bin/sh")` 拿到一个 shell，然后用 shell 读取服务器上的 flag 文件。

这个过程听起来简单，做起来需要你掌握一整套技能链：

```
C 语言 → 汇编 → 操作系统内存管理 → 二进制文件结构
  → 漏洞原理 → 利用技术 → 工具使用 → 调试技巧
```

是不是有点吓人？别担心。这个教程就是按照这条链路，一环一环带你走下来的。很多人觉得 PWN 难，不是因为每一个环节都难，而是因为**没有人把这条链清晰地铺在面前**。你现在有了。

## 1.4 常见误解，先打消掉

在我带过的学生里，新手最常问的问题无非是这几个。这里先一次性回答。

### 「我数学不好，能学 PWN 吗？」

能。PWN 对数学的要求远没有 Crypto 方向那么高。你需要的是逻辑思维和系统性的推理能力，而不是数论或抽象代数。当然，如果你擅长数学，会有一点帮助（比如理解地址计算），但绝不是门槛。

### 「我英语不好，能学吗？」

能。这个教程是中文的，而且 PWN 领域的核心术语就那么多（push、pop、ret、libc、heap……），看几天就熟悉了。需要读英文资料时，现在的翻译工具也足够好用。英语是加分项，不是必选项。

### 「我没有计算机专业背景，能学吗？」

能，但要做好补基础的准备。你需要补的是：一点点 C 语言、一点点汇编、操作系统的基本概念。这些教程里都会讲，而且讲得比教材通俗。真正难的不是「有没有专业背景」，而是「愿不愿意动手敲」。

### 「学 PWN 是不是违法？」

**技术本身不违法，违法的是未经授权的使用。** CTF 是一个合法的、被行业广泛认可的竞赛形式，企业招聘时非常看重 CTF 经历。你在这个教程里学到的一切，都应该只用在：

- 自己搭建的实验环境
- CTF 比赛平台
- 明确授权的渗透测试项目

任何时候，未经授权对他人系统使用这些技术都是违法的。请守住这条线。

### 「我要学多久才能入门？」

这取决于你每天投入多少时间。一个比较现实的估计：

- 每天 2~3 小时，坚持 2~3 个月：能解决基础的栈溢出和 ret2libc 题目
- 每天 2~3 小时，坚持 6~12 个月：能解决中等难度的堆题
- 想成为高手：这是一个以年计的过程，而且永远有新的东西要学

**关键的不是速度，而是持续性。** 每天写一点、调一点，三个月后的你会惊讶于自己的进步。

### 「需要很贵的设备吗？」

不需要。一台能跑虚拟机的普通笔记本就够了（建议 8GB 内存以上）。教程里的所有实验都可以在虚拟机里完成，云靶场和在线 CTF 平台也提供了现成的环境。

## 1.5 本教程怎么用

这本教程有几个设计原则，了解它们能帮你更好地使用教程：

### 原则一：原理优先

我不会给你一堆可以背下来的 payload 模板就完事。每个技术点，我都会讲清楚「为什么这样构造」。因为 CTF 题目千变万化，只有理解了原理，你才能在考场上现场推导。当然，教程最后会给你一份速查模板（见附录），但那是理解之后的总结，不是起点。

### 原则二：循序渐进

章节之间有严格的依赖关系。上一篇不理解，下一篇就会寸步难行。所以请按顺序读，不要跳级。特别是不要因为「堆题很火」就直接跳到堆篇——那是劝退新最快的路径。

### 原则三：动手至上

PWN 是手艺活。看懂了不等于会了，会了不等于熟练。每一章我都会给出可运行的最小示例，请你务必：

1. 照着敲一遍代码
2. 编译、运行、用 gdb 调试
3. 尝试修改代码，看看会发生什么

如果你只是读，那和看小说没什么区别。

### 关于符号约定

教程中会使用以下标记：

> 💡 **提示**：一些有助于理解的小技巧或背景知识。

> ⚠️ **注意**：容易出错的地方，或者需要特别留意的环境差异。

> 🔥 **实战**：可以动手尝试的练习。

> **名词**：第一次出现的专业术语会加粗，并在附录的名词解释里收录。

代码块会标注语言，例如：

```c
// 这是一个 C 语言代码块
#include <stdio.h>
int main() { return 0; }
```

```python
# 这是一个 Python 代码块
from pwn import *
```

## 1.6 你需要准备的心态

最后，在正式开始之前，我想和你聊聊心态。因为技术上的困难可以克服，心态上的崩盘才是大多数人放弃的真正原因。

**第一，接受卡壳。** 你会遇到调了三天都跑不通的 exp，会遇到明明照着教程做却得到不同结果的情况。这不是你笨，这是常态。PWN 老手们也都经历过这些，只不过他们学会了和卡壳共处。卡住的时候，去睡觉、去散步、去做别的事，很多问题会在你放松的时候突然想通。

**第二，不要和别人比。** CTF 圈里永远有天才少年，他们可能在初中就拿了国赛一等奖。但学习不是竞赛，每个人的节奏不同。专注于今天的自己比昨天的自己进步了多少，而不是别人做了什么。

**第三，享受过程。** 如果你只盯着「学会 PWN」这个目标，过程会显得漫长而痛苦。但如果你能享受「搞懂一个机制」「调通一个 payload」的瞬间快乐，这条路会走得轻松得多。

**第四，保持好奇。** 多问几个「为什么」。为什么栈要向下生长？为什么 Canary 要放在返回地址前面？为什么 free 之后 chunk 的内容还在？好奇心是最好的老师。
