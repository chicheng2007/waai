# 第 33 章 二进制审计方法论

> 拿到一个没有源码的二进制文件，如何快速找到漏洞？这一章我们总结一套系统的审计流程：从危险函数入手，逆向关键逻辑，定位漏洞点。

---

## 33.1 审计的整体流程

```text
1. 收集信息（file、checksec、strings）
      ↓
2. 找危险函数（哪些函数被导入/使用）
      ↓
3. 定位危险函数的调用点
      ↓
4. 逆向分析周围的逻辑（参数怎么来的）
      ↓
5. 判断是否存在漏洞（能否控制参数）
      ↓
6. 构造利用
```

---

## 33.2 第一步：信息收集

```bash
# 文件类型与架构
file ./vuln

# 保护机制
checksec --file=./vuln

# 字符串（常能发现提示、路径、后门）
strings -a -t x ./vuln | less

# 动态链接信息（依赖的库、导入的函数）
readelf -d ./vuln

# 所有符号
nm ./vuln
nm -D ./vuln              # 动态符号（导入导出函数）
```

从 strings 的输出中，留意：

- 程序提示语（"Input:"、"Password:"）→ 找到交互点
- 文件路径（"/flag"）→ 找到目标
- 可疑字符串（"backdoor"、"secret"）→ 可能是后门

---

## 33.3 第二步：找危险函数

用 objdump 列出程序调用的所有外部函数：

```bash
objdump -T ./vuln | grep -E 'gets|read|scanf|strcpy|strcat|sprintf|printf|malloc|free'
```

常见危险函数清单：

| 函数 | 潜在漏洞 |
| --- | --- |
| `gets` | 栈溢出（无条件） |
| `read` | 栈/堆溢出（如果长度参数可控） |
| `scanf("%s")` | 栈溢出 |
| `strcpy` / `strcat` | 栈/堆溢出 |
| `sprintf` | 栈溢出 |
| `printf` / `fprintf` | 格式化字符串（如果格式串可控） |
| `malloc` / `free` | 堆相关漏洞（UAF、double free） |
| `memcpy` | 溢出（如果长度可控） |

> 💡 **提示**：`read` 是 CTF 题目中最常见的输入函数，因为它能读二进制数据。重点看它的第三个参数（读取长度）是不是写死的，以及目标缓冲区有多大。

---

## 33.4 第三步：定位调用点

用 objdump 反汇编，搜索危险函数的调用：

```bash
objdump -d -M intel ./vuln | grep -B10 -A5 'call.*<gets@plt>'
```

或者用 radare2 / ghidra 等工具看伪代码（如果有条件，ghidra 的 decompiler 非常强大）。

在反汇编中，重点关注：

- 传给危险函数的参数从哪来
- 缓冲区在栈上还是堆上
- 有没有长度检查

---

## 33.5 第四步：逆向关键逻辑

### 33.5.1 识别函数边界

即使没有符号，pwndbg 也能帮你识别函数：

```gdb
# 反汇编当前函数
disassemble

# 查看函数边界
info functions
```

### 33.5.2 识别变量和缓冲区

栈上的局部变量通常通过 `[rbp - offset]` 访问：

```asm
sub rsp, 0x40                   ; 分配 0x40 字节栈空间
lea rax, [rbp-0x40]             ; buf 的地址
mov rdi, rax
call gets                       ; gets(buf)
```

从 `sub rsp, N` 和 `lea rax, [rbp-X]` 可以推断缓冲区的大小。

### 33.5.3 用 gdb 动态验证

静态分析有疑问时，用 gdb 动态验证：

```gdb
b *0x401234              # 在可疑 call 前下断点
run
# 观察参数
x/10i $rip               # 看即将执行的指令
info registers rdi rsi rdx   # 看参数寄存器
```

---

## 33.6 第五步：判断漏洞

问自己几个问题：

1. **输入长度可控吗？** read 的长度是常量还是变量？变量能否被控制？
2. **缓冲区有多大？** 从汇编里推算。
3. **返回地址/函数指针在缓冲区后面吗？** 栈溢出的关键。
4. **有保护机制吗？** Canary 需要额外泄露，NX 需要 ROP，PIE 需要泄露基址。
5. **有信息泄露吗？** 程序会不会打印内存内容（格式化字符串、UAF 读）？

---

## 33.7 常见漏洞模式速查

### 栈溢出模式

```asm
sub rsp, 0x40                ; 小缓冲区
lea rax, [rbp-0x40]
mov rdi, rax
call <gets@plt>              ; 无长度检查 → 栈溢出
```

### 格式化字符串模式

```asm
lea rax, [rbp-0x100]
mov rdi, rax
mov eax, 0
call <gets@plt>              ; 读入用户输入
mov rdi, rax                 ; 直接作为格式串
mov eax, 0
call <printf@plt>            ; 格式化字符串漏洞
```

### 堆 UAF 模式

```asm
call <free@plt>              ; 释放
; ... 没有把指针置 NULL ...
mov rax, [rbp-0x8]           ; 再次使用旧指针
call <some_function>         ; UAF
```

## 33.8 工具推荐

| 工具 | 用途 |
| --- | --- |
| **Ghidra** | 免费的反编译器，能把汇编转成伪代码 |
| **IDA Pro** | 业界标准反汇编工具（收费） |
| **radare2** | 开源逆向框架 |
| **Binary Ninja** | 现代化的逆向工具 |
| **checksec** | 检查保护机制 |
| **ROPgadget** | 找 ROP gadget |

> 💡 **提示**：对新手来说，Ghidra 的 Decompiler（F5 功能）是神器。它能把汇编还原成类似 C 的伪代码，大大降低审计门槛。但不要完全依赖它——理解底层汇编才是真功夫。

---

## 33.9 小结

这一章我们总结了二进制审计的方法：

- **流程**：信息收集 → 找危险函数 → 定位调用点 → 逆向逻辑 → 判断漏洞 → 构造利用
- **危险函数**：gets、read、strcpy、printf 等是重点
- **逆向技巧**：通过 `sub rsp, N` 和 `[rbp-X]` 推断缓冲区
- **工具**：Ghidra、IDA、radare2 辅助分析
