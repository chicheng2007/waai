# 第 6 关 · 保护机制：游戏的难度旋钮

## 🎬 游戏开场

同一款游戏，有"简单/普通/困难/噩梦"难度。难度越高，敌人越强，你的套路越不灵。

程序世界也是这样。现代编译器和操作系统给程序加了一层层**保护机制**。你带着新手村的"栈溢出"大招去打一个全保护的敌人，会被瞬间教做人。

但别慌——**每一种保护，都有对应的破解套路**。这一关就是教你看"敌人开了哪些 Buff"，并记住每个 Buff 的破法。这是新手村的毕业考，也是整个教程的"防御地图"。

---

## 🧠 核心概念（游戏版）

### 1. Canary：餐桌上的警报器

**它是什么**：程序启动时，悄悄在栈上放一个随机数字（金丝雀），紧挨着局部变量。函数返回前会检查这个数字有没有被改动。

**游戏比喻**：就像餐桌上放了个警报器。你往盘子里堆菜（栈溢出），一旦菜碰到警报器，它"叮铃铃"响，程序立刻崩溃，游戏结束（`*** stack smashing detected ***`）。

**怎么破**：

- **不能直接撞**：碰到就死。
- **偷看口令再利用**：先用一个漏洞（比如格式化字符串）**泄露出 Canary 的值**，然后在你的溢出 payload 里，把原来位置原样填回去。警报器看到口令没变，就不响了。

> 记忆口诀：**Canary 不能被覆盖，但可以被"原样奉还"。**

### 2. NX（No eXecute）：禁止在数据区跑代码

**它是什么**：把栈、堆标记为"只存数据，不许执行"。就算你把 shellcode 塞进栈上，跳过去执行时 CPU 也会拒绝。

**游戏比喻**：游戏规定"数据区只能放东西，不能从这里发起动作"。你的自写作弊码写在餐巾纸上（栈），游戏不认。

**怎么破**：

- **别自己写代码，借用现成的**：系统库（libc）里有大量现成代码。用 ROP 技术拼凑它们（第 11 关）。
- **ret2libc**：直接调用 `system("/bin/sh")`（第 10 关）。

> 记忆口诀：**NX 让你不能"自带代码"，但你能"借代码"。**

### 3. ASLR / PIE：每次开局重新洗牌

**它是什么**：

- **ASLR**（地址空间布局随机化）：系统每次启动程序，栈、堆、libc 的地址都会随机变化。
- **PIE**（位置无关可执行文件）：程序自己的代码地址也随机。

**游戏比喻**：以前地图是固定的，你能背下"隐藏关卡在 0x400123"。现在每次开局，整个城市重新洗牌，门牌号全变了。你背的地址全失效。

**怎么破**：

- **先泄露，再计算**：用一个漏洞泄露出某个已知函数的真实地址，减去它的固定偏移，算出"基址"，再推导其他所有地址。
- **利用相对偏移**：如果漏洞本身不依赖绝对地址，或用 partial overwrite（只改低几位），可以绕过。

> 记忆口诀：**ASLR 让地址变，但"泄露一个点就能推出全部"。**

### 4. RELRO：用胶水固定公告板

**它是什么**：保护 GOT 表。

- **Partial RELRO**（部分）：GOT 的一部分可写。
- **Full RELRO**（完全）：程序启动后，把 GOT 表标记为只读，再也改不动。

**游戏比喻**：GOT 那块公告板，以前你能涂改（GOT 劫持），现在 Full RELRO 用胶水把它焊死了。

**怎么破**：

- **Partial RELRO**：照样打 GOT 劫持。
- **Full RELRO**：别想改 GOT 了，换用 ROP 直接调函数，或攻击其他可写内存（如 `__free_hook`，第 23 关）。

> 记忆口诀：**RELRO 封住了公告板，但还有别的路。**

### 5. 快速看敌人 Buff：checksec

游戏开局前先"侦察敌情"，用 checksec：

```bash
checksec --file=hello
```

输出类似：

```
    Arch:     amd64-64-little
    RELRO:    Partial RELRO
    Stack:    No canary found
    NX:       NX enabled
    PIE:      No PIE (0x400000)
```

翻译成游戏语言：

| 输出 | 游戏意思 | 你的策略 |
| --- | --- | --- |
| `Canary found` | 有警报器 | 先泄露 Canary |
| `NX enabled` | 数据区不能跑代码 | 用 ROP / ret2libc |
| `PIE enabled` | 程序地址随机 | 先泄露基址 |
| `Full RELRO` | 公告板焊死 | 别改 GOT，改用钩子 |
| `No canary` + `No PIE` | **新手福利关** | 直接栈溢出 ret2text |

## 🔧 真实世界对照

| 保护 | 英文 | 编译器开关（关闭） | 破解核心 |
| --- | --- | --- | --- |
| 栈保护 | Canary / Stack Protector | `-fno-stack-protector` | 泄露后原样填回 |
| 不可执行 | NX / DEP | `-z execstack` | ROP / ret2libc |
| 地址随机 | ASLR | `setarch -R`（临时） | 泄露地址算基址 |
| 位置无关 | PIE | `-no-pie` | 泄露基址 |
| 只读重定位 | RELRO | `-z norelro` | 绕过或换目标 |

**注意**：编译题时常见的组合：

```bash
# 新手村福利关（啥保护都不开）
gcc -fno-stack-protector -no-pie -z execstack -z norelro hello.c -o hello

# 现实世界默认（Canary + NX + PIE + Full RELRO 全开）
gcc hello.c -o hello
```

CTF 题目通常会**故意关掉一些保护**来考察特定技巧。看到 checksec 输出，你就要立刻判断"这题想考我什么"。

## 🎯 闯关任务：当好侦察兵

把第 1 关的 `hello` 分别这样编译，并用 checksec 观察区别：

```bash
gcc hello.c -o hello_default
gcc -fno-stack-protector -no-pie -z execstack hello.c -o hello_easy
checksec --file=hello_default
checksec --file=hello_easy
```

对比两次输出，回答：

1. `hello_easy` 关掉了哪些保护？
2. 在这两个程序里，如果你想直接栈溢出跳到某个固定函数，哪个更容易？为什么？

（答案：easy 版没有 Canary、没有 NX、没有 PIE，是新手福利关，可以直接跳。）

## 📌 本关小结 —— 新手村毕业典礼

| 保护 | 游戏比喻 | 一句话破法 |
| --- | --- | --- |
| Canary | 警报器 | 泄露口令，原样填回 |
| NX | 禁跑区 | 借代码（ROP/ret2libc） |
| ASLR/PIE | 洗牌地图 | 泄露一个点，推出所有地址 |
| RELRO | 焊死的公告板 | 换个攻击目标 |
