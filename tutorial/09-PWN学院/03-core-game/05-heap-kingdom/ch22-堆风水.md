# 第 22 关 · 堆风水：提前摆好储物柜

## 🎬 游戏开场

你学会了各种"偷柜子套路"(UAF、double free、tcache poisoning),但你会发现一个尴尬:

> 招式我都会,可真实题目里,目标柜子**不在我需要的位置**!

就像你会开锁,但保险箱不在你面前。怎么办?

答案是**堆风水(Heap Feng Shui)**:在发动攻击前,先通过一连串精心的 malloc/free,把堆"整理"成你想要的布局——让目标 chunk 恰好挨着你的漏洞 chunk,让回收筐里的指针恰好指向你要的地方。

游戏比喻:下棋时你不只是"走一步看一步",而是提前布好局,让十几步之后自己能吃掉对方的车。**堆风水就是提前摆好所有储物柜,让攻击时机成熟时一切水到渠成。**

这招是区分"会招式的新手"和"能做真实堆题的高手"的分水岭。

---

## 🧠 核心概念（游戏版）

### 1. 为什么需要布局?

回顾 tcache poisoning:你需要 target 地址出现在某个空闲 chunk 的 next 指针位置。但程序不会乖乖把 chunk 释放到那。你要**主动创造**这个状态:

- 想让两个 chunk 相邻 → 连续 malloc 相同大小。
- 想让某 chunk 进 tcache → 先 free 它。
- 想让目标地址"看起来像个 chunk" → 提前在那写好 size 字段。

### 2. 堆风水的常用手法

**① 占位(grooming)**

先用一批 malloc 把堆"填"到特定状态,让后续分配落在你预测的位置。

游戏比喻:先把储物柜中心的其他柜子都租满,这样下一个新来的必定只能租到你想让他租的那个位置。

**② 制造相邻(feng shui 布局)**

```c
a = malloc(0x80);   // 目标chunk
b = malloc(0x80);   // 相邻chunk,防止a与top合并
free(a);            // a进回收站,且b在它上面
```

连续分配 + 精确释放,让"受害者"和"攻击者"挨在一起。

**③ 占位符 / 屏障 chunk**

用一个 chunk 当"墙",防止 free 时和 top chunk 合并(合并会破坏你的布局)。

**④ 触发整理**

 malloc 一个超大 chunk,迫使系统整理回收站,让 bin 里的 chunk 重新排列到你想的位置。

### 3. 一个完整的布局思路(以 tcache poisoning 为例)

假设你要把 `__free_hook` 改成 system:

```
目标:让 tcache 的 next 指向 __free_hook

步骤:
1. 布置:malloc 两个 chunk A、B(与 hook 附近大小匹配)
2. free A → free B → free A  (dup,制造环)
3. 现在 tcache 链: A → B → A
4. malloc A → 写 A 的 next = (__free_hook - 0x10)  [或考虑safe-linking编码]
5. malloc B → 正常
6. malloc A → 正常
7. malloc → 返回 __free_hook 附近的假chunk!
8. 往里写 system 地址 → __free_hook = system
9. 之后 free 一个含 "/bin/sh" 的 chunk → 触发 system("/bin/sh")
```

每一步的 malloc/free 顺序都是精心设计的——这就是堆风水。顺序错一步,布局就毁了。

### 4. 调试堆布局的工具

工欲善其事,必先利其器:

- **gdb + pwndbg**:`heap` 命令直接显示所有 chunk 的布局和状态(必装!)。
- **gef 的 heap 命令**。
- 可视化观察:每次 malloc/free 后 `heap` 一下,看布局变化。

```bash
# pwndbg 里
heap        # 显示chunk布局
bins        # 显示各bin的链表
find_fake_fast  # 找可用的假chunk
```

游戏比喻:这些工具是"堆布局的地图透视挂"——没有它你就是在黑暗里摆柜子。
