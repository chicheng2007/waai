# 第 2 关 · 指针：藏宝图上的坐标

## 🎬 游戏开场

你在城市里捡到一张藏宝图，上面写着：

> **"宝石在 0x7fff1234 号小屋。"**

注意，这张纸上**不是宝石本身**，而是一个**地址**。你得按着这个门牌号走到那间小屋，才能拿到宝石。

游戏里有两种房子：

- **普通小屋**：里面住着"东西"（数字、字符等数据）。
- **地图小屋**：里面住着**另一间小屋的门牌号**。

第二种就是**指针（pointer）**。它不装宝贝，它装的是"宝贝在哪"。

---

## 🧠 核心概念（游戏版）

### 1. 指针 = 装地址的盒子

假设城市的一条街上有这些房间：

```
门牌号:   100    101    102    103    104
        ┌──────┬──────┬──────┬──────┬──────┐
内容:    │  42  │      │  100 │      │   'A'│
        └──────┴──────┴──────┴──────┴──────┘
          ↑              ↑
        宝石在 100    地图上写着"100"
```

房间 102 里住着 `100`——这就是一张藏宝图，指向房间 100 里的宝石 `42`。

在 C 语言里：

```c
int gem = 42;        // 宝石房：变量 gem 住在某间小屋，里面是 42
int *map = &gem;     // 地图房：变量 map 里住的是 gem 的门牌号
```

- `&gem` 读作"取 gem 的门牌号"（取地址）。
- `int *map` 表示"map 是一张地图，指向 int 类型的宝石"。
- 想按图取宝，用 `*map`（解引用）：

```c
printf("%d", *map);  // 顺着地图走，打印出 42
```

### 2. 为什么需要指针？

你可能会问：直接把宝石放在盒子里不就行了，为什么要多此一举写个地址？

在游戏里，这是因为：

- **有些东西太大**：一整个宝箱（数组、结构体）搬不动，你只能记下它的位置。
- **有些东西会变**：你要把宝箱交给别的玩家处理，给地址比搬箱子方便。
- **有些东西要共享**：多个地图指向同一个宝箱，谁改了大家都能看到。

PWN 世界里，指针无处不在。**栈溢出攻击的本质，就是篡改某个"地图"里的坐标**，让程序按我们的意思去取东西。

### 3. 危险坐标：空指针与野指针

藏宝图也有坑：

- **空指针（NULL）**：地图上写着"0 号房间"。城市里 0 号房间是禁区，去就会触发"段错误"（Segmentation Fault）——游戏直接崩溃。
- **野指针（wild pointer）**：地图上的房间号是随机的、无效的，或者那个房间已经被拆了（内存已释放）。按它去寻宝，轻则崩溃，重则……（这正是第 18 关 UAF 的伏笔）。

> 🎮 **Pwner 的嗅觉**：看到程序里出现 `NULL` 指针解引用、或"释放后还在用"的指针，两眼放光——漏洞可能就在眼前。

### 4. 指针的"步长"

藏宝图上写"下一间房"，到底跳几米？这取决于地图类型：

```c
char  *p;  p + 1;  // 跳 1 个字节
int   *p;  p + 1;  // 跳 4 个字节
long  *p;  p + 1;  // 跳 8 个字节
```

就像游戏里"向前走一步"，角色是蚂蚁还是巨人，步长完全不同。**类型决定了指针的步长**。

## 🔧 真实世界对照

| 游戏说法 | 真实术语 | 例子 |
| --- | --- | --- |
| 藏宝图 | 指针变量 | `int *p` |
| 门牌号 | 内存地址 | `0x7ffd1234` |
| 按图取宝 | 解引用 | `*p` |
| 问宝箱的门牌号 | 取地址 | `&x` |
| 0 号禁区 | NULL 指针 | `(void*)0` |
| 拆了的房间 | 已释放内存 | `free()` 之后 |
| 崩溃 | 段错误 | Segmentation fault |

在 64 位程序里，一个地址是 **8 个字节**。你会在 payload 里反复看到 `p64(地址)` 这个写法——意思就是把 8 字节的地址按小端序写进去。

## 🎯 闯关任务：当一次寻宝者

写这个程序，编译运行，看看地图里的坐标：

```c
// pointer.c
#include <stdio.h>
int main() {
    int gem = 42;
    int *map = &gem;

    printf("宝石房间地址: %p\n", (void*)&gem);
    printf("地图里写的:   %p\n", (void*)map);
    printf("按图取宝:     %d\n", *map);

    *map = 99;   // 按着地图去改宝石！
    printf("改完后宝石:   %d\n", gem);
    return 0;
}
```

```bash
gcc -g pointer.c -o pointer && ./pointer
```

你会看到类似输出：

```
宝石房间地址: 0x7ffc8a4b1234
地图里写的:   0x7ffc8a4b1234
按图取宝:     42
改完后宝石:   99
```

**关键观察**：`*map = 99` 明明改的是"地图指向的地方"，结果 `gem` 真的变了。这就是"隔空取物/改物"——PWN 攻击的核心能力就是获得这种能力。

思考题：如果地图里的地址被我们改成另一个变量的地址，会怎样？（这就是"任意地址写"漏洞的雏形，第 15 关揭晓。）

## 📌 本关小结

| 你学会了 | 一句话记忆 |
| --- | --- |
| 指针 | 装门牌号的盒子，本身不是宝贝 |
| `&` 取地址 | 问"你家几号" |
| `*` 解引用 | 按门牌号去拿/改东西 |
| 步长 | 类型决定一次跳几字节 |
| 野指针 | 无效地图 = 崩溃或漏洞 |

**Pwner 眼光**：以后看代码，看到 `*p = x` 这种"往指针指向的地方写值"的语句，要养成习惯想："`p` 是从哪来的？我能控制它吗？" 能控制 = 任意地址写 = 大杀器。
