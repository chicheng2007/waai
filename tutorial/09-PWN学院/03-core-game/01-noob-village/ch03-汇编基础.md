# 第 3 关 · 汇编：游戏里的"快捷键"

## 🎬 游戏开场

你玩一个策略游戏，界面上有漂亮的按钮，你点一下"攻击"，角色就挥刀。

但如果有人绕过界面，直接在游戏的**控制台**里敲：

```
move player to (100, 200)
attack target_37
give player 9999 gold
```

游戏照样会执行——因为它真正听懂的，是这些**最底层的指令**，而不是按钮。

程序世界也是这样：

- 你写的 C 语言 `printf("hi")` 是"漂亮的按钮"。
- 编译之后，它变成一堆 `mov`、`call`、`push`——这就是**汇编语言**，CPU 真正听懂的"控制台指令"。

作为 Pwner，你必须学会看这个控制台。因为漏洞发生在那一层，你的作弊码也要在那一层写。

好消息是：**你只需要认识十来条指令**。坏消息是，它们名字都很短，看起来像乱码。我们一个一个游戏化。

---

## 🧠 核心概念（游戏版）

### 1. 寄存器 = 角色的随身口袋

游戏角色身上只有几个口袋（CPU 里只有几个**寄存器**），放东西取东西极快。64 位游戏机（x86-64）的主要口袋：

| 口袋名 | 游戏绰号 | 真实用途 |
| --- | --- | --- |
| `rax` | 万能口袋 | 算数、放返回值 |
| `rdi` | 1号传参口袋 | 函数的第 1 个参数 |
| `rsi` | 2号传参口袋 | 函数的第 2 个参数 |
| `rdx` | 3号传参口袋 | 函数的第 3 个参数 |
| `rsp` | 盘子顶指针 | 永远指向栈的最上面 |
| `rbp` | 本关底座 | 标记当前函数的栈帧底部 |
| `rip` | 游戏进度条 | 指向"下一条要执行的指令" |

**`rip` 是老大**——它指到哪，游戏就演到哪。PWN 的终极目标，就是**改成 rip 的内容**（控制程序计数器）。记住这句话，后面所有攻击都是它的变体。

### 2. 十条"快捷键"

| 指令 | 游戏化解释 | 例子 |
| --- | --- | --- |
| `mov A, B` | 把 B 装进 A 口袋 | `mov rax, 1` 万能口袋放 1 |
| `push X` | 往盘子堆顶放一个盘子 | `push rbp` |
| `pop X` | 从盘子堆顶拿走一个盘子放进 X | `pop rdi` |
| `call 地址` | 传送到某任务，并记下回来路 | `call 0x400500` |
| `ret` | 从盘子堆顶拿到"回城坐标"，传送回去 | `ret` |
| `add A, B` | A 口袋的东西加 B | `add rax, 2` |
| `sub A, B` | 减法 | `sub rsp, 0x10` |
| `cmp A, B` | 对比两个口袋（为判断做准备） | `cmp rax, 10` |
| `jmp 地址` | 无条件跳到某处 | `jmp 0x401000` |
| `leave` | 拆掉当前栈帧（相当于 `mov rsp,rbp; pop rbp`） | 函数收尾 |

看到 `ret` 了吗？**它从栈上拿一个值，然后跳过去**。栈溢出攻击就是把这个值换成我们的目标地址——第 7 关见。

### 3. 函数调用的"传送协议"

游戏里调用一个技能（函数），要遵守协议：

```
1. call 技能位置        ← 传送过去，同时把"返回地址"压到盘子上
2. [技能执行]           ← 技能干活
3. ret                  ← 从盘子上取回返回地址，传送回来
```

参数怎么传？Linux 64 位游戏机规定：

> **前 6 个参数依次放在 `rdi, rsi, rdx, rcx, r8, r9` 六个口袋里。**

这个约定叫 **System V AMD64 ABI**。你以后构造 ROP 链时，就是在找"能给 rdi 赋值的碎片"（pop rdi; ret），第 11 关详述。

### 4. 一段真实的"控制台记录"

C 代码：

```c
int add(int a, int b) { return a + b; }
int main() { return add(2, 3); }
```

汇编（简化）：

```asm
<main>:
    mov edi, 2         ; 第1个参数放2
    mov esi, 3         ; 第2个参数放3
    call <add>         ; 传送到add，并记录返回地址
    ret                ; 返回

<add>:
    push rbp           ; 放一个盘子（保存旧底座）
    mov rbp, rsp       ; 建立新底座
    mov eax, edi       ; 取参数a
    add eax, esi       ; 加参数b
    pop rbp            ; 收盘子
    ret                ; 返回到main
```

看懂这段，你就有了"透视挂"的一半。剩下的一半是 gdb（第 27 关）。

## 🔧 真实世界对照

| 游戏说法 | 真实术语 |
| --- | --- |
| 控制台指令 | 汇编指令（assembly） |
| 口袋 | 寄存器（register） |
| 盘子堆 | 栈（stack） |
| 进度条 rip | 指令指针 / 程序计数器（EIP/RIP） |
| 传送并返回 | 函数调用（call/ret） |
| 传参口袋 | 参数寄存器（rdi/rsi/rdx...） |

**常见坑**：

- `mov eax, 1` 和 `mov rax, 1` 的区别：`eax` 是 `rax` 的低 32 位。往 eax 写值会把 rax 的高 32 位清零。
- 64 位地址是 8 字节，所以你会看到 `movabs rax, 0x...` 这种写法。
- 汇编有 AT&T 和 Intel 两种写法，本教程用 **Intel 格式**（`mov 目的, 源`），pwntools 和 objdump 默认也是这个。

## 🎯 闯关任务：偷看游戏的控制台

写个小程序并反汇编它：

```c
// add.c
#include <stdio.h>
int add(int a, int b){ return a+b; }
int main(){ printf("%d\n", add(2,3)); return 0; }
```

```bash
gcc -O0 -g add.c -o add
objdump -d -M intel add | less
```

在输出里找到 `<add>` 和 `<main>` 两个标签，对照上面那段汇编看看能不能认出 `call`、`ret`、`mov edi`。

想要更友好？用 gdb 单步执行：

```bash
gdb ./add
(gdb) start
(gdb) disassemble      # 看到当前函数的汇编
(gdb) stepi            # 一次执行一条汇编指令
(gdb) info registers   # 查看所有"口袋"里的值
```

按 `stepi` 一条一条走，观察 `rip` 怎么变化、`rdi` 和 `rsi` 怎么被赋值。这就是"透视挂"的第一次开机测试。
