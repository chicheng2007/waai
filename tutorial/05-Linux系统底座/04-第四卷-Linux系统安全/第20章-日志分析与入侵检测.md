## 20.1 Linux 日志系统

### 20.1.1 日志的价值

日志是系统的"黑匣子"，记录了谁在什么时候做了什么。对安全而言：

- **检测**：发现异常行为（暴力破解、异常登录）
- **溯源**：还原攻击过程（攻击者做了什么）
- **取证**：留下证据（应急响应、审计合规）

> 攻击者入侵后常做的第一件事就是**清除日志**（`> /var/log/auth.log`、删除 history）。所以保护日志的完整性至关重要（第 21 章讲）。

### 20.1.2 日志系统架构

现代 Linux（systemd）有两条日志渠道：

1. **journald**：systemd 的日志服务，收集内核和服务的结构化日志，用 `journalctl` 查看。
2. **rsyslog/syslog-ng**：传统日志服务，把日志写到 `/var/log/` 下的文本文件。

很多系统两者并存：journald 收集 → rsyslog 转存到文件。

### 20.1.3 关键日志文件

| 文件 | 内容 | 安全价值 |
|------|------|---------|
| `/var/log/auth.log` | 认证日志（Debian/Ubuntu） | 登录、sudo、SSH 暴力破解 ★★★ |
| `/var/log/secure` | 认证日志（RHEL/CentOS） | 同上 |
| `/var/log/syslog` | 系统综合日志 | 各种服务消息 |
| `/var/log/messages` | 系统日志（RHEL） | 同上 |
| `/var/log/kern.log` | 内核日志 | 驱动、硬件、内核级事件 |
| `/var/log/dmesg` | 启动日志 | 启动时的硬件检测 |
| `/var/log/nginx/access.log` | Web 访问日志 | Web 攻击、扫描 ★★★ |
| `/var/log/nginx/error.log` | Web 错误日志 | 攻击导致的错误 |
| `/var/log/faillog` | 失败登录记录 | 暴力破解 |
| `/var/log/lastlog` | 用户最后登录 | 异常登录时间 |
| `/var/log/wtmp` | 登录记录（二进制） | `last` 命令数据源 |
| `/var/log/btmp` | 失败登录（二进制） | `lastb` 命令数据源 |

## 20.2 journalctl：systemd 日志

```bash
journalctl                        # 查看所有日志
journalctl -u ssh.service         # 查看某服务的日志
journalctl -f                     # 实时跟踪（类似 tail -f）
journalctl -n 50                  # 显示最后 50 行
journalctl --since "2026-11-25"   # 从指定时间开始
journalctl --since "1 hour ago"   # 最近 1 小时
journalctl -p err                 # 只看错误级别及以上
journalctl -o json                # JSON 格式输出（便于程序处理）
journalctl -k                     # 只看内核日志
```

实用组合：

```bash
# 查看 SSH 服务今天的错误
journalctl -u ssh --since today -p err

# 统计某服务的日志量
journalctl -u nginx --since "1 hour ago" | wc -l
```

## 20.3 日志分析实战（命令复习）

### 20.3.1 暴力破解检测

```bash
# 统计失败登录次数
grep -c "Failed password" /var/log/auth.log

# 找出攻击来源 IP（次数排序）
grep "Failed password" /var/log/auth.log \
  | awk '{print $11}' | sort | uniq -c | sort -rn | head -20

# 查看针对哪些用户
grep "Failed password" /var/log/auth.log \
  | awk '{for(i=1;i<=NF;i++) if($i=="for") print $(i+1)}' \
  | sort | uniq -c | sort -rn

# 找出成功登录（可能是破解成功！）
grep "Accepted password" /var/log/auth.log
```

> **关键**：`Failed password` 后面跟着 `for root from 1.2.3.4`，用 awk 提取 IP 和用户名。大量失败 + 某个 IP 成功 = 破解可能成功，要立即排查。

### 20.3.2 异常提权检测

```bash
# 查看 sudo 使用记录
grep "sudo:" /var/log/auth.log

# 查看谁切换到了 root
grep "su:" /var/log/auth.log

# 查看新增用户（auth.log 里的 useradd）
grep "useradd\|adduser" /var/log/auth.log
```

### 20.3.3 Web 攻击检测

```bash
# 扫描器 User-Agent
grep -iE 'sqlmap|nmap|nikto|masscan|acunetix' /var/log/nginx/access.log

# SQL 注入特征
grep -iE 'union.*select|select.*from|or.*1=1' /var/log/nginx/access.log

# 目录遍历
grep -E '\.\./|\.\.\\' /var/log/nginx/access.log

# 可疑文件上传
grep -E 'POST.*\.php|shell|webshell' /var/log/nginx/access.log

# 404 暴增（目录扫描）
awk '$9==404 {print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head
```

### 20.3.4 登录时间分析

```bash
# 查看所有登录历史
last

# 查看最近失败登录
lastb | head -20

# 查看每个用户最后登录
lastlog

# 找出非工作时间的登录（如凌晨 2-5 点）
last | grep -E " (02|03|04):"
```

## 20.4 入侵痕迹识别清单

攻击者入侵后常留下这些痕迹，逐一排查：

| 检查项 | 命令 | 可疑迹象 |
|--------|------|---------|
| 异常账户 | `awk -F: '$3==0' /etc/passwd` | 多个 UID=0 账户 |
| 空密码账户 | `sudo awk -F: '($2=="")' /etc/shadow` | 有空密码账户 |
| 异常登录 | `last`、`lastlog` | 陌生 IP、异常时间 |
| 可疑进程 | `ps aux --sort=-%cpu` | 高 CPU、随机名字 |
| 异常外联 | `ss -tunap` | 连向陌生 IP |
| 恶意 cron | `crontab -l`、`ls /etc/cron.d/` | 陌生的定时任务 |
| SUID 后门 | `find / -perm -4000 -type f` | 异常 SUID 文件 |
| 启动项 | `systemctl list-unit-files` | 陌生服务 |
| 文件篡改 | AIDE 校验 | 关键文件哈希变化 |
| 历史清除 | `cat ~/.bash_history` | history 被清空或异常 |
| SSH 公钥 | `cat ~/.ssh/authorized_keys` | 陌生的公钥 |

综合排查脚本：

```bash
#!/bin/bash
# 入侵痕迹快速排查（仅授权环境）
echo "=== 1. UID=0 账户 ==="
awk -F: '$3==0 {print $1}' /etc/passwd
echo "=== 2. 最近成功登录 ==="
last -n 10
echo "=== 3. 失败登录 TOP IP ==="
grep "Failed password" /var/log/auth.log 2>/dev/null | awk '{print $11}' | sort | uniq -c | sort -rn | head
echo "=== 4. 高 CPU 进程 ==="
ps aux --sort=-%cpu | head -8
echo "=== 5. 网络连接 ==="
ss -tunap | head -20
echo "=== 6. root 的 cron ==="
sudo crontab -l 2>/dev/null
echo "=== 7. 可疑 SUID ==="
find / -perm -4000 -type f 2>/dev/null | grep -vE '^/(usr|bin|sbin|lib)' | head
echo "=== 8. SSH 授权公钥 ==="
cat /root/.ssh/authorized_keys 2>/dev/null
```

## 20.5 检测工具

### 20.5.1 logwatch：日志摘要报告

```bash
sudo apt install logwatch
sudo logwatch --detail High --range today --output stdout
```

每天把日志汇总成易读的报告，邮件发给管理员。适合"快速浏览系统发生了什么"。

### 20.5.2 AIDE：文件完整性检查

AIDE（Advanced Intrusion Detection Environment）给关键文件建立哈希数据库，文件被改动就报警——这是检测"文件篡改"的利器。

```bash
sudo apt install aide

# 初始化数据库（在系统干净时做！）
sudo aideinit

# 日常检查
sudo aide --check
```

> **重要**：AIDE 数据库必须在系统**确认干净**时建立，否则把已被篡改的文件当基准就失去意义。数据库要保存在安全的地方（最好离线或只读）。

### 20.5.3 OSSEC / Wazuh：主机入侵检测系统（HIDS）

OSSEC（及其分支 Wazuh）是开源的 HIDS，提供：

- 日志分析、文件完整性检查、rootkit 检测
- 实时告警、主动响应（自动封禁 IP）
- 集中管理（多台主机上报到服务器）

这是企业级的检测方案，部署较复杂，但功能强大。

### 20.5.4 其他工具

| 工具 | 用途 |
|------|------|
| `rkhunter` / `chkrootkit` | rootkit 检测 |
| `tripwire` | 文件完整性（商业/开源） |
| `auditd` | Linux 审计系统，记录详细系统调用 |
| `fail2ban` | 见第 19 章，防暴力破解 |

## 20.6 构建简单的检测规则

用 shell 脚本 + cron 实现"简易 IDS"：

```bash
#!/bin/bash
# 简易入侵检测：发现异常就告警
ALERT_LOG=/var/log/my_ids.log

alert() {
    echo "[$(date)] 告警: $*" | tee -a "$ALERT_LOG"
}

# 规则 1：失败登录超过 50 次
FAILS=$(grep -c "Failed password" /var/log/auth.log 2>/dev/null || echo 0)
if [ "$FAILS" -gt 50 ]; then
    alert "检测到 $FAILS 次失败登录，疑似暴力破解"
fi

# 规则 2：出现新的 UID=0 账户
ROOT_USERS=$(awk -F: '$3==0' /etc/passwd | wc -l)
if [ "$ROOT_USERS" -gt 1 ]; then
    alert "检测到 $ROOT_USERS 个 UID=0 账户，疑似后门账户"
fi

# 规则 3：root 的 authorized_keys 非空
if [ -s /root/.ssh/authorized_keys ]; then
    alert "root 存在 SSH 授权公钥，请核实"
fi

# 规则 4：异常外联（非内网网段）
SUSPECT=$(ss -tunap | grep ESTAB | grep -vE '192\.168\.|10\.|172\.(1[6-9]|2[0-9]|3[01])\.' | wc -l)
if [ "$SUSPECT" -gt 0 ]; then
    alert "检测到 $SUSPECT 个可疑外网连接"
fi
```

配合 cron 每 10 分钟运行一次，就成了一个基本的自动化检测系统。

> **提示**：这只是一个简化示例。生产环境建议用 OSSEC/Wazuh 等成熟方案，它们有更完善的规则引擎和告警机制。

## 20.7 应急响应流程

发现入侵后的标准流程（**仅供参考，实际操作需专业训练**）：

1. **隔离**：断开网络（防止扩散 and 数据外泄），但不要立即关机（内存中的证据会丢失）。
2. **取证**：备份日志、内存、进程列表、网络连接——**先取证再清理**。
3. **研判**：分析攻击路径（怎么进来的）、影响范围（做了什么）。
4. **遏制**：封禁攻击 IP、修改密码、禁用可疑账户。
5. **根除**：删除恶意文件、清除后门（cron、SUID、启动项）、修复漏洞。
6. **恢复**：从干净备份恢复系统、重新加固。
7. **复盘**：总结教训，更新防御措施，防止再次发生。

> **记住**：应急响应黄金法则——**先取证，后处置**。很多新手一发现入侵就 kill 进程、删文件、重启，结果证据全没了，无法溯源。

## 20.8 本章总结

| 知识点 | 内容 |
|--------|------|
| 日志价值 | 检测、溯源、取证；攻击者常清除日志 |
| 日志系统 | journald（journalctl）+ rsyslog（/var/log/） |
| 关键日志 | auth.log/secure、syslog、nginx access.log ★ |
| journalctl | `-u` 服务、`-f` 跟踪、`--since`、`-p err` |
| 暴力破解检测 | grep Failed password → awk 提取 IP → 排序 |
| 入侵痕迹 | 异常账户、登录、进程、外联、cron、SUID、公钥 |
| 检测工具 | logwatch、AIDE（完整性）、OSSEC/Wazuh（HIDS）、auditd |
| 应急响应 | 隔离→取证→研判→遏制→根除→恢复→复盘；先取证后处置 |
