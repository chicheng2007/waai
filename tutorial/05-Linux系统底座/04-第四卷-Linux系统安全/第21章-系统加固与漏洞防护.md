## 21.1 系统加固概述

### 21.1.1 什么是加固

加固（Hardening）是通过收紧系统配置，减少攻击面（attack surface）的过程。核心思想：

- **最小化**：只保留必需的账户、服务、端口、权限
- **默认拒绝**：默认关闭，按需开启
- **纵深防御**：多层防护叠加
- **及时更新**：修补已知漏洞

### 21.1.2 加固框架参考

业界有成熟的加固基线标准：

| 标准 | 说明 |
|------|------|
| **CIS Benchmark** | 互联网安全中心基线，最权威，分级别 |
| **STIG** | 美国国防部安全指南，极严格 |
| **等保 2.0** | 中国网络安全等级保护制度 |

我们不必死记标准，但要理解其背后的思路：减少暴露、最小权限、可审计。

## 21.2 账户与密码加固

### 21.2.1 密码策略

强制强密码和定期更换（`/etc/login.defs` 和 PAM 配置）：

```bash
# /etc/login.defs 关键项
PASS_MAX_DAYS   90       # 密码最长有效 90 天
PASS_MIN_DAYS   1        # 两次修改间隔至少 1 天
PASS_MIN_LEN    12       # 密码最小长度 12
PASS_WARN_AGE   7        # 过期前 7 天提醒
```

用 `chage` 管理单个用户：

```bash
sudo chage -M 90 -m 7 -W 7 alice    # 最大90天、最小7天、提前7天警告
sudo chage -l alice                  # 查看用户密码策略
sudo chage -d 0 alice                # 强制下次登录改密码
```

### 21.2.2 密码复杂度（PAM）

`/etc/pam.d/common-password`（Debian）配置：

```bash
password requisite pam_pwquality.so retry=3 minlen=12 difok=3 ucredit=-1 lcredit=-1 dcredit=-1 ocredit=-1
```

含义：最少 12 位、与旧密码至少 3 位不同、至少 1 个大写/小写/数字/特殊字符。

### 21.2.3 账户锁定策略

失败多次锁定账户（PAM `faillock` 或 `pam_tally2`）：

```bash
# /etc/pam.d/common-auth 加入（Debian）
auth required pam_faillock.so preauth audit deny=5 unlock_time=900
```

含义：失败 5 次锁定 15 分钟（900 秒）。

查看/解锁：

```bash
faillock --user alice
sudo faillock --user alice --reset
```

### 21.2.4 账户清理

```bash
# 锁定不需要的账户
sudo passwd -l username

# 检查空密码账户
sudo awk -F: '($2=="") {print $1}' /etc/shadow

# 检查长期未用的账户
lastlog | grep -i "never\|很久以前"
```

> **原则**：删除或锁定不必要的系统账户（如 `games`、`lp` 等），减少可被利用的入口。

## 21.3 内核参数加固（sysctl）

`/etc/sysctl.conf` 或 `/etc/sysctl.d/` 下的配置能加固内核网络栈。

推荐配置：

```bash
# 禁用 IP 转发（非路由器不需要）
net.ipv4.ip_forward = 0

# 禁用 ICMP 重定向接收（防中间人）
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.all.send_redirects = 0

# 启用反向路径过滤（防 IP 欺骗）
net.ipv4.conf.all.rp_filter = 1

# 忽略 ping（减少暴露）
net.ipv4.icmp_echo_ignore_all = 1

# 记录可疑包
net.ipv4.conf.all.log_martians = 1

# 防 SYN Flood
net.ipv4.tcp_syncookies = 1

# 限制 core dump（防止敏感信息泄露）
fs.suid_dumpable = 0

# 启用 ASLR（地址空间随机化，防内存攻击）
kernel.randomize_va_space = 2
```

应用：

```bash
sudo sysctl -p              # 从 /etc/sysctl.conf 加载
sudo sysctl -a              # 查看所有参数
sudo sysctl net.ipv4.ip_forward=0   # 临时修改
```

> **小白问**：ASLR 是什么？
>
> 地址空间随机化（ASLR）让程序每次运行时内存地址都不同，攻击者就难以预测"返回地址在哪"，从而难以实施缓冲区溢出攻击。这是对抗内存漏洞的重要防线（呼应系统语言卷讲的栈溢出）。

## 21.4 服务最小化

### 21.4.1 减少攻击面

每个运行的服务都是一个潜在入口。原则：**不需要的服务一律关闭**。

```bash
# 查看运行的服务
systemctl list-units --type=service --state=running

# 查看开机自启
systemctl list-unit-files --state=enabled

# 关闭并禁用不需要的服务
sudo systemctl stop 服务名
sudo systemctl disable 服务名
```

常见可关闭的服务（视情况）：`avahi-daemon`（局域网发现）、`cups`（打印）、`bluetooth`、`nfs` 等。

### 21.4.2 端口收敛

```bash
# 查看监听端口
ss -tulnp

# 找出端口对应的服务
sudo lsof -i :端口
```

结合第 18 章防火墙，只开放必需端口。

### 21.4.3 服务降权

让服务以非 root 用户运行：

```bash
# 在 systemd unit 文件里指定
[Service]
User=www-data
Group=www-data
```

即使服务被攻破，攻击者也只拿到低权限用户，而非 root。

## 21.5 漏洞管理

### 21.5.1 漏洞生命周期

1. **发现**：安全研究员/厂商发现漏洞（CVE 编号）
2. **披露**：公开漏洞细节
3. **补丁**：厂商发布修复
4. **利用**：攻击者编写 exploit（可能在补丁前就有 0day）
5. **修复**：管理员打补丁

**黄金法则**：补丁发布后尽快应用——攻击者会逆向补丁来写 exploit（"补丁星期二，漏洞星期三"）。

### 21.5.2 定期更新

```bash
# 自动安全更新（Ubuntu）
sudo apt install unattended-upgrades
sudo dpkg-reconfigure --priority=low unattended-upgrades

# 查看可更新的包
apt list --upgradable

# 检查内核是否需要更新
uname -r
```

### 21.5.3 漏洞扫描

```bash
# 检查已知漏洞（需要相应工具/订阅）
# 开源方案：OpenVAS、Nessus（家庭版）
# 检查特定软件版本是否存在已知漏洞

# 用 apt 检查安全更新
sudo apt audit   # 部分系统支持

# 检查是否有过时的内核、软件
apt list --upgradable | grep -i security
```

> **合规提醒**：漏洞扫描只针对自己的系统或授权目标。对外的扫描需要书面授权。

## 21.6 加固基线工具

### 21.6.1 Lynis：系统加固审计

```bash
sudo apt install lynis
sudo lynis audit system
```

Lynis 会检查几百项配置，给出加固建议和评分（hardening index）。输出保存到 `/var/log/lynis.log`。

这是最易用的加固审计工具之一，强烈推荐新手使用——它会告诉你"哪些地方没做好"。

### 21.6.2 OpenSCAP：合规基线检查

```bash
sudo apt install oscap
# 下载 CIS/OVAL 基线文件后用 oscap 检查
oscap oval eval --results results.xml definition.xml
```

用于等保、CIS 等合规性检查，企业级场景。

### 21.6.3 加固脚本

很多组织有自动化加固脚本，可以自己编写（见 21.7），或使用开源基线脚本。

## 21.7 综合实战：编写系统加固脚本

把本章知识整合成一个加固脚本：

```bash
#!/bin/bash
# Linux 系统加固脚本（实验环境使用）
# ⚠️ 生产环境请先测试，逐步应用，避免影响业务
set -euo pipefail

echo "===== Linux 系统加固开始 ====="

# 1. 密码策略
echo "[1/6] 配置密码策略..."
sed -i 's/^PASS_MAX_DAYS.*/PASS_MAX_DAYS   90/' /etc/login.defs
sed -i 's/^PASS_MIN_LEN.*/PASS_MIN_LEN    12/' /etc/login.defs

# 2. 内核参数加固
echo "[2/6] 加固内核参数..."
cat > /etc/sysctl.d/99-hardening.conf <<EOF
net.ipv4.conf.all.rp_filter = 1
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.tcp_syncookies = 1
net.ipv4.icmp_echo_ignore_all = 1
fs.suid_dumpable = 0
kernel.randomize_va_space = 2
EOF
sysctl -p /etc/sysctl.d/99-hardening.conf >/dev/null

# 3. SSH 加固（谨慎！确保已有密钥登录）
echo "[3/6] 检查 SSH 配置..."
grep -q "^PermitRootLogin no" /etc/ssh/sshd_config || \
  echo "提示: 建议设置 PermitRootLogin no"

# 4. 检查空密码账户
echo "[4/6] 检查空密码账户..."
EMPTY=$(awk -F: '($2=="") {print $1}' /etc/shadow)
[ -n "$EMPTY" ] && echo "警告: 发现空密码账户: $EMPTY" || echo "无空密码账户"

# 5. 检查 UID=0 账户
echo "[5/6] 检查 UID=0 账户..."
awk -F: '$3==0 {print "  UID=0:", $1}' /etc/passwd

# 6. 检查世界可写目录
echo "[6/6] 检查异常的 777 目录..."
find / -maxdepth 4 -type d -perm -o=w 2>/dev/null | grep -vE '^/(tmp|var/tmp|dev|run|proc|sys)' | head

echo "===== 加固检查完成 ====="
echo "建议运行 'sudo lynis audit system' 获取详细加固建议"
```

> ⚠️ **重要提醒**：
> 1. 加固脚本**必须先在实验环境测试**，确认不影响正常服务。
> 2. 生产环境要**逐项应用、逐步验证**，不要一次性全上。
> 3. SSH 加固尤其要小心——确保密钥登录可用后再禁密码，保留会话防锁死。
> 4. 加固前先**备份**配置文件。

## 21.8 加固效果验证

加固后如何验证：

```bash
# 用 Lynis 评分（加固前后对比）
sudo lynis audit system | grep "Hardening index"

# 检查端口是否收敛
ss -tulnp

# 检查密码策略是否生效
chage -l 用户名

# 检查内核参数
sysctl net.ipv4.tcp_syncookies

# 用 nmap 从外部扫描自己（授权环境）
nmap -sV 127.0.0.1
```
