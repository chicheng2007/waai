## 28.1 性能分析框架

### 28.1.1 四大资源

系统性能瓶颈通常落在一个或多个资源上：

| 资源 | 典型症状 | 主要工具 |
|------|---------|---------|
| CPU | 使用率高、负载高 | top、htop、mpstat、perf |
| 内存 | 使用率高、swap 频繁 | free、vmstat、smem |
| 磁盘 IO | iowait 高、读写慢 | iostat、iotop、df |
| 网络 | 带宽满、延迟高、丢包 | sar -n、iftop、ss |

### 28.1.2 系统化方法（USE 方法）

性能分析大师 Brendan Gregg 提出的 USE 方法：对每个资源检查：

- **U**tilization（利用率）：资源多忙？
- **S**aturation（饱和度）：有多少在排队？
- **E**rrors（错误）：有没有错误？

按这个框架逐个排查，不会遗漏。

> **小白问**：load average（负载）是什么？
>
> `uptime` 显示的负载平均值，表示"正在运行 + 等待运行"的任务数。如果负载持续超过 CPU 核数，说明系统过载。用 `nproc` 查核数。

## 28.2 CPU 分析

### 28.2.1 查看 CPU

```bash
nproc                          # CPU 核数
top / htop                     # 实时看 CPU 使用
mpstat 1                       # 每个 CPU 核心的使用率（sysstat 包）
uptime                         # 负载
```

top 里的 CPU 状态：

| 指标 | 含义 |
|------|------|
| us | 用户态（应用程序） |
| sy | 内核态（系统调用） |
| ni | 调整过优先级的进程 |
| id | 空闲 |
| wa | 等待 IO（高说明磁盘瓶颈） |
| si | 软中断 |
| st | 虚拟机偷取时间 |

### 28.2.2 perf：性能剖析

```bash
sudo apt install linux-tools-common linux-tools-$(uname -r)

perf top                       # 实时看热点函数
perf record -g ./program       # 采样记录（含调用栈）
perf report                    # 查看采样报告
perf stat ./program            # 统计性能事件（指令数、缓存命中率等）
```

perf 能告诉你"程序把时间花在哪个函数上"，是定位 CPU 瓶颈的利器。

### 28.2.3 高 CPU 排查流程

```bash
# 1. 找出高 CPU 进程
ps aux --sort=-%cpu | head

# 2. 看该进程的线程
top -H -p PID

# 3. 用 perf 剖析
sudo perf top -p PID

# 4. 如果是 Python，用 py-spy
pip install py-spy
py-spy top --pid PID
```

## 28.3 内存分析

### 28.3.1 查看内存

```bash
free -h                        # 总览（注意 available 列，不是 free）
vmstat 1                       # 虚拟内存统计（si/so 表示 swap 换入换出）
cat /proc/meminfo
smem -t                        # 按进程统计实际内存（需安装）
```

> **小白问**：free 显示内存快满了，是不是内存不够？
>
> 不一定。Linux 会用空闲内存做缓存（buff/cache），所以 free 列可能很小。真正要看的是 `available` 列——它估算"应用还能用多少内存"。如果 available 充足，就没问题。

### 28.3.2 Swap

当物理内存不够，系统把不用的页换到磁盘（swap），但磁盘比内存慢几千倍。swap 频繁（si/so 持续非零）说明内存压力大。

```bash
swapon -s                      # 查看 swap
sudo sysctl vm.swappiness=10   # 调整 swap 倾向（0-100，越小越不用 swap）
```

### 28.3.3 内存泄漏排查

```bash
# 观察进程内存是否持续增长
watch -n 1 'ps -p PID -o rss,vsz,cmd'

# 用 valgrind 检测（C/C++）
valgrind --leak-check=full ./program
```

## 28.4 磁盘 IO 分析

### 28.4.1 查看 IO

```bash
iostat -x 1                    # 详细 IO 统计（sysstat）
iotop                          # 实时看进程的 IO（需安装）
df -h                          # 磁盘空间
df -i                          # inode 使用
du -sh dir/                    # 目录大小
```

iostat 关键指标：

| 指标 | 含义 |
|------|------|
| %util | 磁盘利用率（接近 100% 说明饱和） |
| await | IO 等待时间（ms） |
| r/s, w/s | 每秒读写次数 |

### 28.4.2 高 iowait 排查

top 里 `wa` 高说明进程在等磁盘。排查：

```bash
iotop -o                       # 只看有 IO 的进程
iostat -x 1
```

常见原因：大量日志写入、数据库查询、磁盘满、机械盘随机读写慢。

### 28.4.3 IO 优化思路

- 用 SSD 替代机械盘
- 减少不必要的日志/刷盘
- 调整 I/O 调度器（`cat /sys/block/sda/queue/scheduler`）
- 增加缓存、批量写入

## 28.5 网络分析

```bash
sar -n DEV 1                   # 网络流量统计
iftop                          # 实时带宽（需安装）
ss -tunap                      # 连接
ping / traceroute              # 延迟和路径
```

> **重点**：网络慢不一定是带宽问题，可能是延迟、丢包、DNS 解析慢。逐项排查。

## 28.6 综合监控工具

### 28.6.1 sysstat 套件

```bash
sudo apt install sysstat
# 包含：iostat、mpstat、sar、pidstat

sar -u 1                       # CPU 历史
sar -r 1                       # 内存
sar -n DEV 1                   # 网络
pidstat -u 1                   # 按进程 CPU
```

sar 能记录历史数据（`/var/log/sa/`），适合分析"昨天下午 3 点系统为什么慢"。

### 28.6.2 一站式工具

```bash
# glances：综合监控
sudo apt install glances
glances

# btop：漂亮的 top 替代品
sudo apt install btop
btop
```

## 28.7 性能调优实战

### 28.7.1 AI 训练慢的排查

```bash
# 1. GPU 是否在用（第 29 章详解）
nvidia-smi

# 2. CPU 是否瓶颈
top

# 3. 数据读取是否瓶颈（IO）
iotop

# 4. 内存是否够
free -h

# 5. Python 代码热点
py-spy top --pid PID
```

常见优化：数据预加载、批量处理、用 SSD、增加 DataLoader workers、混合精度训练。

### 28.7.2 安全工具卡慢的排查

```bash
# 扫描器慢？看是 CPU 还是网络还是 IO
top
sar -n DEV 1
iotop
```

### 28.7.3 系统级调优参数

```bash
# 文件描述符上限（高并发服务需要）
ulimit -n
sudo vim /etc/security/limits.conf
# * soft nofile 65536
# * hard nofile 65536

# TCP 参数（高并发网络服务）
sudo sysctl -w net.core.somaxconn=1024
```

> **提示**：调优要基于数据，不要盲目改参数。先测量、找瓶颈、再针对性优化、最后验证效果——这是性能工程的基本循环。

## 28.8 本章总结

| 知识点 | 内容 |
|--------|------|
| 四维度 | CPU、内存、IO、网络；USE 方法（利用率/饱和度/错误） |

## 本章练习

1. 用 `uptime` 和 `nproc` 查看负载和 CPU 核数，判断是否过载。
2. 用 `free -h` 查看内存，理解 available 与 free 的区别。
3. 用 `vmstat 1` 观察 si/so，看是否有 swap。
4. 用 `iostat -x 1` 查看磁盘 IO 指标。
5. 安装 sysstat，用 `sar -u 1` 观察 CPU 历史数据。
6. 安装 glances 或 btop，用它做一次系统体检。
7. 写一个 CPU 密集的 Python 程序，用 top 找到它，用 py-spy 看热点。
8. 思考：USE 方法三个维度分别是什么？为什么"先测量再调优"很重要？
