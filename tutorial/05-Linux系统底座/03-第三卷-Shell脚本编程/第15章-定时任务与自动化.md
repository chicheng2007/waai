## 15.1 cron：周期任务的守护者

### 15.1.1 什么是 cron

**cron** 是 Linux 的定时任务守护进程（daemon），它在后台运行，按你设定的时间表自动执行命令。系统自身的很多例行任务（日志轮转、清理临时文件）也靠它。

每个用户有自己的 **crontab**（cron 表），定义"什么时候执行什么命令"。

### 15.1.2 crontab 基本操作

```bash
crontab -l            # 列出当前用户的定时任务
crontab -e            # 编辑定时任务（首次会让你选编辑器）
crontab -r            # 删除所有定时任务（小心！）
sudo crontab -u alice -l   # root 查看 alice 的任务
```

> ⚠️ `crontab -r` 会删除全部任务且无确认。想删单条，用 `crontab -e` 编辑。

### 15.1.3 crontab 语法

一行定时任务的格式：

```bash
分 时 日 月 周  命令
```

| 字段 | 范围 | 说明 |
|------|------|------|
| 分 | 0–59 | 第几分钟 |
| 时 | 0–23 | 第几小时 |
| 日 | 1–31 | 几号 |
| 月 | 1–12 | 几月 |
| 周 | 0–7 | 周几（0 和 7 都是周日） |

特殊符号：

| 符号 | 含义 | 示例 |
|------|------|------|
| `*` | 任意值 | `*` 在分字段 = 每分钟 |
| `,` | 多个值 | `1,15,30` = 1、15、30 分 |
| `-` | 范围 | `1-5` = 1 到 5 |
| `*/n` | 每隔 n | `*/10` = 每 10 分钟 |

### 15.1.4 常见示例

```bash
# 每天 8:30 执行
30 8 * * * /home/user/script.sh

# 每 5 分钟执行一次
*/5 * * * * /home/user/check.sh

# 每天凌晨 2 点执行
0 2 * * * /home/user/backup.sh

# 每周一 9 点执行
0 9 * * 1 /home/user/report.sh

# 每月 1 号凌晨 3 点
0 3 1 * * /home/user/monthly.sh

# 每小时的 0 分和 30 分
0,30 * * * * /home/user/task.sh

# 工作日（周一到周五）18 点
0 18 * * 1-5 /home/user/workday.sh
```

> **记忆技巧**：从左到右是"分 时 日 月 周"，分钟在最前。写完后念一遍："在第 X 分、第 X 小时、第 X 日……"

### 15.1.5 环境变量问题（大坑）

cron 执行任务时的环境与你的登录 Shell 不同——**PATH 很有限**，可能找不到你常用的命令。

解决方案：

1. **用绝对路径**：脚本里所有命令（包括 python3、nmap 等）都用完整路径。用 `which python3` 查路径。
2. **在 crontab 顶部定义 PATH**：

```bash
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
30 8 * * * /home/user/script.sh
```

3. **在脚本开头设置环境**：脚本里 `source` 需要的环境（如 Python 虚拟环境）。

### 15.1.6 输出处理

cron 任务的 stdout/stderr 默认会通过邮件发送（如果配置了邮件）。常见做法是把输出重定向：

```bash
# 丢弃所有输出
0 2 * * * /home/user/backup.sh >/dev/null 2>&1

# 追加到日志文件
*/5 * * * * /home/user/check.sh >> /home/user/check.log 2>&1
```

> **调试技巧**：刚设置的任务先让输出写到日志，观察几次确认正常，再决定是否丢弃。看到 "No such file or directory" 多半是路径或环境变量问题。

### 15.1.7 系统级 crontab

除了用户 crontab，还有系统级配置文件：

- `/etc/crontab`
- `/etc/cron.d/`
- `/etc/cron.hourly/`、`/etc/cron.daily/`、`/etc/cron.weekly/`、`/etc/cron.monthly/`

系统级 crontab 的格式**多一个"用户"字段**：

```bash
分 时 日 月 周 用户 命令
30 2 * * * root /usr/bin/backup.sh
```

## 15.2 systemd timer：现代替代方案

systemd 系统（Ubuntu 16.04+）提供了 timer 单元，功能更强、日志更好查。

### 15.2.1 基本用法

创建服务单元 `/etc/systemd/system/check.service`：

```ini
[Unit]
Description=安全检查任务

[Service]
Type=oneshot
ExecStart=/home/user/check.sh
```

创建定时器 `/etc/systemd/system/check.timer`：

```ini
[Unit]
Description=每天 8:30 运行安全检查

[Timer]
OnCalendar=*-*-* 08:30:00
Persistent=true

[Install]
WantedBy=timers.target
```

启用：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now check.timer
systemctl list-timers          # 查看所有定时器
```

### 15.2.2 cron vs systemd timer

| 对比 | cron | systemd timer |
|------|------|---------------|
| 语法 | 简单五字段 | OnCalendar 更灵活 |
| 日志 | 需自己重定向 | `journalctl -u check.service` 统一查看 |
| 错过执行 | 不会补跑 | `Persistent=true` 可补跑 |
| 依赖管理 | 无 | 可定义服务依赖 |
| 适合 | 简单周期任务 | 复杂、需要日志与依赖的任务 |

> **建议**：简单任务用 crontab（上手快）；重要任务、需要日志和可靠性用 systemd timer。

## 15.3 at：一次性定时任务

想在"某个时间点"执行一次任务（不是周期性的），用 `at`：

```bash
echo "命令" | at 时间
```

示例：

```bash
# 今天 15:30 执行
echo "echo '时间到'" | at 15:30

# 明天 9 点执行脚本
echo "/home/user/task.sh" | at 09:00 tomorrow

# 20 分钟后执行
echo "/home/user/task.sh" | at now + 20 minutes

# 查看待执行任务
atq

# 删除任务
atrm 任务编号
```

首次使用可能需要启动 atd 服务：

```bash
sudo systemctl start atd
```

## 15.4 日志轮转：logrotate

日志会无限增长，撑爆磁盘。**logrotate** 定期切割、压缩、删除旧日志。

配置文件：`/etc/logrotate.conf` 和 `/etc/logrotate.d/`。

示例（为自定义应用配置）：

```bash
# /etc/logrotate.d/myapp
/var/log/myapp/*.log {
    daily              # 每天轮转
    rotate 7           # 保留 7 份
    compress           # 压缩旧日志（gzip）
    delaycompress      # 延迟一轮再压缩
    missingok          # 日志不存在不报错
    notifempty         # 空日志不轮转
    create 640 root adm  # 新日志的权限和属主
    postrotate             # 轮转后执行的命令
        systemctl reload myapp >/dev/null 2>&1 || true
    endscript
}
```

调试：

```bash
sudo logrotate -d /etc/logrotate.d/myapp    # 调试模式，不实际执行
sudo logrotate -f /etc/logrotate.d/myapp    # 强制执行一次
```

> **安全意义**：日志是取证的关键，但磁盘满了日志就写不进去（攻击者有时故意制造日志撑爆磁盘来"致盲"监控）。合理的轮转策略保证日志持续可用，同时保留足够历史。

## 15.5 实战：自动化安全监控

### 15.5.1 定时安全检查脚本 + cron

脚本 `~/security_check.sh`：

```bash
#!/bin/bash
# 安全检查并把结果写入带时间戳的报告
REPORT=/var/log/security_reports
mkdir -p "$REPORT"
OUT="$REPORT/check_$(date +%F_%H%M).txt"

{
    echo "=== 安全检查 $(date) ==="
    echo "--- 失败登录次数 ---"
    grep -c "Failed password" /var/log/auth.log 2>/dev/null
    echo "--- 可疑外联 ---"
    ss -tunap | grep ESTAB
    echo "--- SUID 文件数 ---"
    find / -perm -4000 -type f 2>/dev/null | wc -l
    echo "--- 新增用户（最近修改的 passwd） ---"
    ls -l /etc/passwd
} > "$OUT" 2>&1

echo "报告已生成: $OUT"
```

设置 cron（每 6 小时检查一次）：

```bash
crontab -e
# 加入：
0 */6 * * * /home/user/security_check.sh >> /var/log/cron_security.log 2>&1
```

### 15.5.2 定时备份

```bash
# 每天凌晨 3 点备份配置目录
0 3 * * * tar -czf /backup/etc_$(date +\%F).tar.gz /etc 2>&1
```

> ⚠️ **注意**：crontab 里 `%` 是特殊字符（表示换行），必须用 `\%` 转义！这是极常见的坑。在脚本里写 `$(date +%F)` 没问题，但直接写在 crontab 里要写成 `\%F`。

### 15.5.3 定时生成日志统计报告

```bash
#!/bin/bash
# 每日登录统计
YESTERDAY=$(date -d yesterday +%b\ %e)
grep "$YESTERDAY" /var/log/auth.log \
  | grep "Accepted password" \
  | awk '{print $9}' | sort | uniq -c \
  > /var/log/reports/login_$(date +%F).txt
```

设置每天 8 点运行：

```bash
0 8 * * * /home/user/login_report.sh >/dev/null 2>&1
```

## 15.6 定时任务的安全风险

定时任务本身也是攻击面：

| 风险 | 说明 | 防护 |
|------|------|------|
| 恶意 cron | 攻击者在 crontab 里植入后门任务 | 定期审查 `crontab -l` 和 `/etc/cron.d/` |
| 脚本被篡改 | 定时任务执行的脚本被替换 | 脚本权限设为仅 root 可写；定期校验哈希 |
| PATH 劫持 | cron 的 PATH 被改成恶意目录 | 脚本用绝对路径；审计 PATH 设置 |
| 权限过高 | 用 root 跑不必要的任务 | 最小权限，用专门用户 |

审计命令：

```bash
# 检查所有用户的 crontab
sudo ls /var/spool/cron/crontabs/
for u in $(sudo ls /var/spool/cron/crontabs/); do echo "=== $u ==="; sudo crontab -u "$u" -l; done

# 检查系统 cron 目录
ls -la /etc/cron.d/ /etc/cron.daily/

# 检查 systemd timer
systemctl list-timers --all
```

> **安全场景**：攻击者在入侵后常添加 cron 任务来"持久化"（保持访问权限）。蓝队应急响应时，检查 crontab 是必做步骤。

## 15.7 常见报错与解决

| 现象 | 原因 | 解决 |
|------|------|------|
| 任务不执行 | PATH 找不到命令 | 用绝对路径；crontab 顶部设 PATH |
| `date +%F` 报错 | crontab 里 `%` 未转义 | 写成 `\%F` |
| 看不到输出 | 输出被丢弃 | 先重定向到日志调试 |
| cron 服务没运行 | cron 未启动 | `sudo systemctl start cron` |
| 脚本手动能跑、cron 不能 | 环境变量差异 | 在脚本里 source 环境或设绝对路径 |

## 15.8 本章总结

| 知识点 | 内容 |
|--------|------|
| crontab | `crontab -l/-e/-r`；格式 `分 时 日 月 周 命令` |
| 符号 | `*` 任意、`,` 多值、`-` 范围、`*/n` 每隔 n |
| 环境变量 | cron 的 PATH 有限；用绝对路径或定义 PATH |
| `%` 转义 | crontab 里 `%` 要写成 `\%` |
| systemd timer | OnCalendar、Persistent、journalctl 日志 |
| at | 一次性任务：`at 时间`、`atq`、`atrm` |
| logrotate | 日志切割压缩；daily/rotate/compress/create |
| 安全 | 审查 crontab 防持久化后门；脚本最小权限 |
