# 第 11 章 Shell 脚本基础

## 本章目标

读完这一章，你将能够：

- 理解什么是 Shell 脚本，它为什么强大
- 写出第一个可执行的 Shell 脚本
- 理解 shebang、执行权限、脚本运行的几种方式
- 掌握脚本中的注释、echo、read
- 理解退出码（exit status）及其在脚本中的作用

---

## 11.1 什么是 Shell 脚本

前面你学的每一条命令，都是"敲一条、执行一条"。**Shell 脚本**就是把一堆命令写进一个文本文件，让 Shell 一次性顺序执行——这就是"批处理/自动化"。

脚本能做什么：

- 批量检查系统配置（安全基线检查）
- 定时统计日志、生成报告
- 自动化部署、批量创建用户
- 把复杂的多步操作固化下来，一键运行

> **小白问**：脚本和手动敲命令有什么区别？
>
> 本质没区别，脚本里的每一行就是你平时敲的命令。好处是：可重复运行、可保存复用、可加入判断和循环（第 12 章）、可定时执行（第 15 章）。手动敲十遍会累会错，脚本写一次跑一万遍都一样。

## 11.2 第一个 Shell 脚本

### 11.2.1 编写脚本

用一个文本编辑器（如 `nano` 或 `vim`）创建文件：

```bash
nano hello.sh
```

输入内容：

```bash
#!/bin/bash
# 这是我的第一个 Shell 脚本
echo "Hello, Linux!"
echo "当前时间: $(date)"
whoami
pwd
```

保存退出（nano 用 `Ctrl+O` 保存，`Ctrl+X` 退出）。

### 11.2.2 逐行解释

| 行 | 含义 |
|----|------|
| `#!/bin/bash` | **shebang**，指定用 `/bin/bash` 来解释执行这个脚本 |
| `# 这是我的...` | 注释，`#` 后面的内容被忽略 |
| `echo "Hello, Linux!"` | 输出文字 |
| `echo "当前时间: $(date)"` | 命令替换：`date` 的输出嵌入字符串 |
| `whoami`、`pwd` | 普通命令 |

**shebang（#!）很重要**：它告诉系统"用哪个解释器运行我"。如果脚本开头没有它，直接执行时系统会用默认的 Shell（可能是 sh），导致某些 bash 特性失效。写 bash 脚本，**永远在第一行写 `#!/bin/bash`**。

### 11.2.3 运行脚本的两种方式

**方式一：赋予执行权限后直接运行**

```bash
chmod +x hello.sh
./hello.sh
```

注意要写 `./hello.sh` 而不是 `hello.sh`——因为当前目录通常不在 PATH 里（第 4 章讲过），写全路径才能找到。

**方式二：用 bash 解释执行（不需要执行权限）**

```bash
bash hello.sh
```

这种方式不要求文件有 `x` 权限，适合还没调试好、临时运行的脚本。

> **小白问**：两种方式有什么区别？
>
> `./hello.sh` 依赖 shebang 指定的解释器；`bash hello.sh` 明确用 bash 运行，忽略 shebang。调试时常用 `bash -x hello.sh`（-x 显示每条命令的执行过程），非常有助于排错。

## 11.3 脚本的基础要素

### 11.3.1 注释

```bash
# 单行注释

# 多行说明
# 每一行都要以 # 开头
```

> 好脚本应该有清晰的注释：说明脚本用途、作者、关键逻辑。这既是给别人的，也是给几个月后的自己的。

### 11.3.2 echo：输出

```bash
echo "Hello"
echo Hello            # 不加引号也行，但建议加
echo -n "不换行"      # -n 不输出结尾换行
echo -e "a\nb"        # -e 解释转义字符（\n 换行、\t 制表）
```

> **注意**：`echo` 在不同 Shell 里行为略有差异。追求可移植性时，复杂输出用 `printf`：
> ```bash
> printf "名字: %s, 年龄: %d\n" "张三" 20
> ```

### 11.3.3 read：读取输入

```bash
read name
echo "你好, $name"

read -p "请输入用户名: " user    # -p 显示提示
read -s -p "请输入密码: " pwd    # -s 隐藏输入（密码场景）
```

**注意变量前要加 `$` 才能取到值**（`$name`），赋值时则不加（`name=...`）。

### 11.3.4 一个交互小例子

```bash
#!/bin/bash
read -p "请输入你的名字: " name
echo "你好，$name！欢迎学习 Shell 脚本。"
echo "今天日期是: $(date +%F)"
```

## 11.4 退出码（Exit Status）

### 11.4.1 每个命令都有退出码

命令执行完会返回一个数字（0–255）给 Shell：

| 退出码 | 含义 |
|--------|------|
| 0 | 成功 |
| 非 0 | 失败（不同数字代表不同错误） |

查看上一条命令的退出码：

```bash
ls /etc
echo $?        # 输出 0，表示 ls 成功
ls /nonexist
echo $?        # 输出 2，表示失败
```

`$?` 是"上一条命令的退出码"。

### 11.4.2 在脚本中使用退出码

```bash
#!/bin/bash
ping -c 1 8.8.8.8 > /dev/null 2>&1
if [ $? -eq 0 ]; then
    echo "网络正常"
else
    echo "网络不通"
fi
```

这正是第 4 章 `&&`、`||` 背后的机制——它们根据退出码决定是否执行后面的命令。

### 11.4.3 exit：指定脚本退出码

```bash
#!/bin/bash
if [ ! -f /etc/passwd ]; then
    echo "错误：/etc/passwd 不存在" >&2
    exit 1        # 以退出码 1 结束脚本，表示失败
fi
echo "一切正常"
exit 0            # 成功结束
```

> **最佳实践**：脚本成功用 `exit 0`，失败用非 0。这样脚本可以被其他脚本或定时任务判断成功与否，做自动化编排。错误信息用 `>&2` 输出到 stderr，符合规范。

## 11.5 编写一个实用的安全检查脚本

把前面学的组合起来，写一个真实的脚本：

```bash
#!/bin/bash
# 简易系统安全检查脚本
# 用法: sudo bash check.sh

echo "=== 系统安全检查报告 ==="
echo "生成时间: $(date)"
echo ""

echo "--- 1. 当前用户 ---"
whoami

echo "--- 2. UID 为 0 的账户（应只有 root） ---"
awk -F: '$3==0 {print $1}' /etc/passwd

echo "--- 3. SUID 文件数量 ---"
find / -perm -4000 -type f 2>/dev/null | wc -l

echo "--- 4. 失败的登录次数 ---"
grep -c "Failed password" /var/log/auth.log 2>/dev/null || echo "无法读取日志"

echo "--- 5. 监听端口 ---"
ss -tuln

echo "=== 检查完成 ==="
```

这个脚本把第 6、8、9 章的命令串在一起，一键运行就出报告。你可以根据自己的需要扩展它——这就是脚本的魅力。

## 11.6 脚本编写规范

好的脚本应该：

1. **有 shebang**：`#!/bin/bash`
2. **有注释**：说明用途、作者、日期、参数
3. **有错误处理**：关键命令检查退出码；必要时 `set -e`（遇到错误立即退出）
4. **有清晰输出**：用 echo 分隔段落，让人看得懂
5. **注意安全**：不要硬编码密码；对用户输入做校验；谨慎使用 `rm -rf`

一个启用严格模式的开头：

```bash
#!/bin/bash
set -euo pipefail
```

- `-e`：命令失败时立即退出
- `-u`：使用未定义变量时报错
- `-o pipefail`：管道中任一命令失败，整个管道算失败

> **小白问**：`set -euo pipefail` 总是要用吗？
>
> 在重要脚本（自动化运维、安全脚本）中强烈推荐，能及早发现问题、避免"带着错误继续跑造成更大破坏"。初学写小练习脚本时可以先不用，熟悉后再加上。

## 11.7 常见报错与解决

| 现象 | 原因 | 解决 |
|------|------|------|
| `Permission denied` 运行脚本 | 没执行权限 | `chmod +x script.sh` 或用 `bash script.sh` |
| `bad interpreter` | shebang 路径错 / Windows 换行符 | 检查 `#!/bin/bash`；用 `dos2unix` 转换 |
| 脚本里命令找不到 | PATH 问题 | 用绝对路径；检查 PATH |
| 变量为空 | 忘了 `$` 或拼写错 | 检查变量引用；`set -u` 帮忙发现 |

> **Windows 换行符坑**：在 Windows 上编辑的脚本传到 Linux，行尾是 `\r\n`，可能导致 `bad interpreter`。用 `dos2unix script.sh` 转换，或用 `sed -i 's/\r$//' script.sh`。

## 11.8 本章总结

| 知识点 | 内容 |
|--------|------|
| 脚本 | 把命令写进文件批量执行，可复用、可自动化 |
| shebang | 第一行 `#!/bin/bash` 指定解释器 |
| 运行方式 | `chmod +x` 后 `./script.sh`；或 `bash script.sh` |
| 注释 | `#` 开头；好脚本要有说明 |
| echo / read | 输出 / 读取输入（`read -p` 提示、`-s` 隐藏） |
| 退出码 | `$?` 查看；0 成功、非 0 失败；`exit` 指定脚本退出码 |
| 规范 | shebang、注释、错误处理、`set -euo pipefail` |
