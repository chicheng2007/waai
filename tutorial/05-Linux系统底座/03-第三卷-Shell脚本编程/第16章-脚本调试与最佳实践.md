## 16.1 调试脚本

### 16.1.1 `bash -x`：跟踪执行过程

```bash
bash -x script.sh
```

`-x`（xtrace）会打印每一条命令及其展开后的参数，前面带 `+` 号。这是定位"脚本为什么不对"的第一工具。

示例输出：

```bash
+ name=zhangsan
+ echo '你好, zhangsan'
你好, zhangsan
+ [ -f /etc/passwd ]
```

你能清楚看到变量展开成了什么、条件判断的结果。

### 16.1.2 `set -x` / `set +x`：脚本内开关调试

```bash
#!/bin/bash
set -x              # 打开调试
echo "调试中..."
set +x              # 关闭调试
echo "正常执行"
```

可以只调试脚本的某一段。

### 16.1.3 `set -euo pipefail`：严格模式

前面提过，这里详解：

```bash
#!/bin/bash
set -e                # errexit：任何命令失败（非0）立即退出
set -u                # nounset：使用未定义变量时报错退出
set -o pipefail       # 管道中任一命令失败，整个管道算失败
```

三行常合写为：

```bash
set -euo pipefail
```

作用：

- `-e`：避免"前面失败了还继续跑，造成更大破坏"
- `-u`：拼错变量名时能立刻发现（而不是静默变成空字符串）
- `-o pipefail`：默认管道只看最后一个命令的退出码，加上后任何一个失败都会算失败

> **注意**：`-e` 有时会让"故意失败"的命令（如 `grep` 没找到）导致脚本退出。解决办法是用 `|| true` 显式忽略：
> ```bash
> grep "pattern" file || true
> ```

### 16.1.4 调试技巧小结

| 技巧 | 用途 |
|------|------|
| `bash -n script.sh` | 只检查语法，不执行（noexec） |
| `bash -x script.sh` | 跟踪每条命令的执行 |
| `set -x` / `set +x` | 脚本内局部开关调试 |
| `echo` 打印变量 | 最朴素有效的调试 |
| `shellcheck` | 静态分析，发现潜在问题 |

## 16.2 trap：捕获信号与清理

### 16.2.1 什么是信号

信号（signal）是系统发给进程的"通知"。常见：

| 信号 | 编号 | 触发 |
|------|------|------|
| SIGINT | 2 | Ctrl+C |
| SIGTERM | 15 | `kill` 默认信号 |
| SIGHUP | 1 | 终端断开 |
| EXIT | — | 脚本退出时（trap 特有） |

### 16.2.2 trap 语法

```bash
trap '命令' 信号
```

示例：

```bash
#!/bin/bash
trap 'echo "收到 Ctrl+C，清理中..."; exit 1' INT

echo "开始工作（按 Ctrl+C 中断）"
while true; do
    sleep 1
done
```

按 Ctrl+C 时，不是直接退出，而是先执行 trap 里的命令。

### 16.2.3 EXIT 陷阱：自动清理临时文件

```bash
#!/bin/bash
TMP=$(mktemp -d)
trap 'rm -rf "$TMP"' EXIT       # 无论脚本如何退出，都删除临时目录

echo "临时目录: $TMP"
# ... 使用 TMP 做各种事 ...
```

`trap ... EXIT` 保证脚本结束时（正常或异常）都执行清理，避免留下垃圾。这是专业脚本的标准做法。

> **注意**：`trap 'rm -rf "$TMP"' EXIT` 里用**单引号**，这样 `$TMP` 在 trap 触发时才展开，能拿到正确的值。用双引号会在设置 trap 时就展开。

### 16.2.4 忽略信号

```bash
trap '' INT        # 忽略 Ctrl+C
```

## 16.3 shellcheck：脚本静态检查

**ShellCheck** 是 Shell 脚本的静态分析工具，能发现大量潜在 bug 和不良实践。

```bash
sudo apt install shellcheck
shellcheck script.sh
```

它会指出：

- 变量未加引号（空格问题）
- 用了过时的写法
- 条件判断的常见错误
- 潜在的注入风险

示例输出：

```bash
In script.sh line 3:
echo $name
      ^-- SC2086: Double quote to prevent globbing and word splitting.
```

> **强烈建议**：写完脚本后用 shellcheck 过一遍。很多" mysterious bug"它能一眼看出。VS Code 装 ShellCheck 插件还能实时提示。

## 16.4 脚本最佳实践

### 16.4.1 可移植性

- 用 `#!/bin/bash` 明确解释器；如果要在 sh 上跑，避免 bash 特有语法（如 `[[ ]]`、数组）。
- 用 POSIX 标准写法（如 `[[ ]]` 换成 `[ ]`）能提高兼容性。
- 换行符用 LF（Windows 编辑器注意）。

### 16.4.2 安全性

| 原则 | 说明 |
|------|------|
| 引用变量 | `"$var"` 防止空格和通配符问题 |
| 校验输入 | 对用户输入做检查，防止注入 |
| 避免 eval | `eval` 会执行任意代码，极度危险 |
| 用绝对路径 | 尤其 sudo、cron 场景，防 PATH 劫持 |
| 最小权限 | 不用 root 就不 root；临时提权用 sudo |
| 敏感信息 | 不硬编码密码、密钥；用环境变量或配置文件（权限 600） |

**注入风险示例**：

```bash
# 危险：用户输入直接当命令执行
read -p "文件名: " f
cat $f              # 用户输入 "; rm -rf /" 会怎样？（在 bash 里需更巧妙的注入）

# 安全：加引号 + 校验
read -p "文件名: " f
case "$f" in
    *[!a-zA-Z0-9._/-]*) echo "非法字符"; exit 1;;
esac
cat -- "$f"
```

### 16.4.3 可维护性

- **注释清晰**：开头写用途、作者、参数、用法。
- **函数分层**：主流程调用高层函数，细节封装在低层函数（第 13 章）。
- **统一日志**：用 `log()` 函数统一输出格式。
- **错误处理**：关键操作检查退出码，失败时给出明确提示。
- **命名规范**：函数名用动词（`check_`、`get_`），变量名有意义。

### 16.4.4 一个高质量的脚本模板

```bash
#!/bin/bash
# 脚本名称: security_scan.sh
# 用途: 对指定主机做端口安全检查（仅授权环境）
# 作者: YourName
# 用法: bash security_scan.sh <IP> [IP...]
# 版本: 1.0

set -euo pipefail

# ---- 配置 ----
readonly PORTS=(22 80 443 3306)
readonly LOG_FILE="/var/log/security_scan.log"

# ---- 函数区 ----
log() {
    local level=$1; shift
    echo "[$(date +'%F %T')] [$level] $*" | tee -a "$LOG_FILE"
}

usage() {
    echo "用法: $0 <IP> [IP...]"
    echo "示例: $0 127.0.0.1"
}

check_port() {
    local host=$1 port=$2
    if (echo > "/dev/tcp/$host/$port") >/dev/null 2>&1; then
        log "INFO" "$host:$port 开放"
    else
        log "INFO" "$host:$port 关闭"
    fi
}

# ---- 主流程 ----
main() {
    if [ $# -eq 0 ]; then
        usage
        exit 1
    fi

    log "INFO" "===== 扫描开始 ====="
    for host in "$@"; do
        for port in "${PORTS[@]}"; do
            check_port "$host" "$port"
        done
    done
    log "INFO" "===== 扫描结束 ====="
}

main "$@"
```

这个模板体现了：shebang、注释、严格模式、readonly 配置、函数分层、统一日志、参数校验、主流程清晰。

## 16.5 综合实战：自动化安全巡检系统

把第三卷所有知识整合，做一个完整的巡检系统：

**需求**：
1. 每天定时检查系统安全状态
2. 生成带时间戳的报告
3. 发现异常时记录日志
4. 自动清理过期报告

**结构**：

```
~/security-monitor/
├── bin/
│   ├── check_system.sh      # 主检查脚本
│   ├── check_auth.sh        # 认证检查模块
│   ├── check_network.sh     # 网络检查模块
│   └── cleanup.sh           # 清理脚本
├── reports/                 # 报告目录
└── logs/                    # 日志目录
```

主脚本 `check_system.sh`：

```bash
#!/bin/bash
# 自动化安全巡检主脚本
set -euo pipefail

BASE="$(cd "$(dirname "$0")/.." && pwd)"   # 获取项目根目录
REPORT_DIR="$BASE/reports"
LOG_DIR="$BASE/logs"
LOG="$LOG_DIR/monitor.log"
REPORT="$REPORT_DIR/report_$(date +%F_%H%M).txt"

mkdir -p "$REPORT_DIR" "$LOG_DIR"

log() {
    echo "[$(date +'%F %T')] $*" | tee -a "$LOG"
}

trap 'log "巡检被中断"; exit 1' INT TERM

log "===== 开始巡检 ====="

{
    echo "系统安全巡检报告"
    echo "生成时间: $(date)"
    echo "主机: $(hostname)"
    echo ""

    echo "=== 1. 认证安全 ==="
    echo "失败登录次数: $(grep -c 'Failed password' /var/log/auth.log 2>/dev/null || echo 0)"
    echo "UID=0 的账户: $(awk -F: '$3==0 {print $1}' /etc/passwd | tr '\n' ' ')"
    echo ""

    echo "=== 2. 网络状态 ==="
    echo "监听端口:"
    ss -tuln
    echo ""

    echo "=== 3. 进程检查 ==="
    echo "CPU 占用前 5:"
    ps aux --sort=-%cpu | head -6
    echo ""

    echo "=== 4. 权限检查 ==="
    echo "SUID 文件数: $(find / -perm -4000 -type f 2>/dev/null | wc -l)"
    echo "可写的 /etc 文件:"
    find /etc -type f -perm -o=w 2>/dev/null | head -10
} > "$REPORT" 2>&1

log "报告已生成: $REPORT"

# 清理 30 天前的报告
find "$REPORT_DIR" -name "report_*.txt" -mtime +30 -delete
log "过期报告已清理"
```

设置定时任务：

```bash
crontab -e
# 每天 8 点和 20 点各巡检一次
0 8,20 * * * /home/user/security-monitor/bin/check_system.sh
```

**这个系统综合了你学到的**：变量、函数、数组、条件、循环、管道、重定向、正则、文本处理、find、ps、ss、cron、trap、严格模式——第三卷的知识全部用上了。

## 16.6 常见报错与解决

| 现象 | 原因 | 解决 |
|------|------|------|
| `set -e` 导致脚本意外退出 | 某命令返回非 0 | 用 `|| true` 显式忽略预期的失败 |
| 未定义变量没报错 | 没加 `set -u` | 加严格模式 |
| trap 里变量为空 | 用了双引号提前展开 | trap 命令用单引号 |
| shellcheck 警告满屏 | 逐步修复即可 | 优先修 error 和 warning 级 |
| 脚本在 sh 下报错 | 用了 bash 特性 | 用 bash 运行或改写为 POSIX 语法 |
