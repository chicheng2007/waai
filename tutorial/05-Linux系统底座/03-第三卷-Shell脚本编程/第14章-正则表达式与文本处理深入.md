## 14.1 正则表达式是什么

**正则表达式（Regular Expression，regex）** 是一种描述"文本模式"的语言。它让你用一小串字符，精确表达"我要找什么样的文本"。

比如：

- `\d{3}-\d{4}` 匹配 "123-4567" 这样的电话格式
- `^192\.168\.` 匹配以 "192.168." 开头的行
- `[a-zA-Z0-9_]+` 匹配由字母数字下划线组成的字符串

正则不是 Linux 独有的，几乎所有编程语言和安全工具都支持。学会它，受益终身。

> **小白问**：正则看起来像"天书"，怎么学？
>
> 不要试图一次记住所有符号。从最常用的入手：`^ $ . * [] +`，边查边用。把本章当字典，用到什么查什么。做几道题就熟了。

## 14.2 正则语法速查

### 14.2.1 基础元字符

| 符号 | 含义 | 示例 |
|------|------|------|
| `.` | 匹配任意单个字符（除换行） | `a.c` → abc, a1c |
| `^` | 匹配行首 | `^root` → 以 root 开头 |
| `$` | 匹配行尾 | `bash$` → 以 bash 结尾 |
| `*` | 前一个字符重复 0 次或多次 | `ab*` → a, ab, abbb |
| `+` | 前一个字符重复 1 次或多次（ERE） | `ab+` → ab, abbb（不含单独的 a） |
| `?` | 前一个字符重复 0 次或 1 次（ERE） | `ab?` → a, ab |
| `{n}` | 前一个字符恰好 n 次（ERE） | `a{3}` → aaa |
| `{n,m}` | 前一个字符 n 到 m 次（ERE） | `a{2,4}` → aa, aaa, aaaa |
| `[]` | 字符集合 | `[abc]` → a/b/c 任一 |
| `[^]` | 否定字符集合 | `[^0-9]` → 非数字 |
| `\|` | 或（BRE 要转义，ERE 直接 `|`） | `cat\|dog`（BRE）、`cat|dog`（ERE） |
| `()` | 分组（BRE 要转义，ERE 直接） | `(ab)+` |

### 14.2.2 字符类

| 写法 | 含义 |
|------|------|
| `[0-9]` | 任意数字 |
| `[a-z]` | 任意小写字母 |
| `[A-Z]` | 任意大写字母 |
| `[a-zA-Z]` | 任意字母 |
| `[0-9a-fA-F]` | 十六进制字符 |
| `\d` | 数字（部分工具支持，如 grep -P、PCRE） |
| `\w` | 单词字符（字母数字下划线） |
| `\s` | 空白字符（空格、制表符） |

### 14.2.3 转义

想匹配元字符本身，用 `\` 转义：

```bash
\.    # 匹配字面的点
\*    # 匹配字面的星号
\[    # 匹配字面的 [
\\    # 匹配字面的反斜杠
```

匹配 IP 地址时就要转义点：`192\.168\.1\.1`。

## 14.3 BRE 与 ERE：两种正则方言

grep 支持两种正则：

| 类型 | 名称 | 启用方式 | 特点 |
|------|------|---------|------|
| BRE | 基本正则 | 默认 | `+ ? { } ( ) |` 需转义为 `\+ \? \{ \} \( \) \|` |
| ERE | 扩展正则 | `grep -E` 或 `egrep` | 这些符号直接用，不需转义 |

> **建议**：现代用法优先用 `grep -E`（ERE），语法更直观。本章例子默认用 ERE。

对比：

```bash
# BRE：分组和或要转义
grep 'error\|warn' log.txt
grep '\(ab\)\+' file.txt

# ERE：直接写
grep -E 'error|warn' log.txt
grep -E '(ab)+' file.txt
```

还有 `grep -P`（PCRE，Perl 兼容正则），支持 `\d`、`\w`、前瞻等高级特性，但并非所有系统都有。

## 14.4 用正则做日志分析

### 14.4.1 提取 IP 地址

IPv4 的简单正则（不够严谨但实用）：

```bash
grep -oE '([0-9]{1,3}\.){3}[0-9]{1,3}' /var/log/auth.log | sort -u
```

拆解：`([0-9]{1,3}\.){3}` 表示"1-3 位数字+点"重复 3 次，再接 `[0-9]{1,3}`。

严谨版（每段 0-255）比较复杂，实践中简单版够用。

### 14.4.2 提取特定字段

```bash
# 提取日志里 "from IP" 后面的 IP
grep -oP 'from \K([0-9]{1,3}\.){3}[0-9]{1,3}' /var/log/auth.log
```

`\K` 是 PCRE 特性，表示"丢弃前面匹配的部分，只输出后面的"。

### 14.4.3 匹配时间范围

```bash
# 匹配 2026 年 11 月的日志
grep -E '^Nov [0-9]{1,2} [0-9:]{8}' /var/log/syslog
```

### 14.4.4 常见安全特征匹配

```bash
# 找扫描器特征（如 sqlmap、nmap 的 User-Agent）
grep -iE 'sqlmap|nmap|nikto|masscan' /var/log/nginx/access.log

# 找可能的 Web 攻击载荷
grep -iE '(\.\./|select.+from|union.+select|<script|cmd=|exec\()' /var/log/nginx/access.log

# 找可疑的 base64 编码串（常见于 webshell）
grep -E '[A-Za-z0-9+/]{40,}={0,2}' suspicious.txt
```

> **合规提醒**：这些正则用于**防守检测**（在自己的日志里找攻击痕迹），请只在授权环境使用。

## 14.5 sed 高级替换

### 14.5.1 分组与反向引用

用 `()` 分组，用 `\1`、`\2` 引用分组内容：

```bash
# 把 "姓名:张三" 改成 "张三"
echo "姓名:张三" | sed -E 's/姓名:(.*)/\1/'

# 交换两个字段："abc def" → "def abc"
echo "abc def" | sed -E 's/([a-z]+) ([a-z]+)/\2 \1/'

# 给 IP 加引号
echo "192.168.1.1" | sed -E 's/([0-9.]+)/"\1"/'
```

`\1` 是第一个括号捕获的内容，`\2` 是第二个，以此类推。`&` 代表整个匹配。

```bash
# 在匹配内容两边加括号
echo "hello world" | sed 's/hello/[&]/'    # [hello] world
```

### 14.5.2 地址范围与多行

```bash
# 只在第 2-5 行替换
sed '2,5s/foo/bar/g' file

# 只在含 "ERROR" 的行替换
sed '/ERROR/s/foo/bar/g' file

# 在匹配行前插入文本
sed '/pattern/i\插入的内容' file

# 在匹配行后追加
sed '/pattern/a\追加的内容' file
```

### 14.5.3 实用替换案例

```bash
# 去掉行首空白
sed 's/^[[:space:]]*//' file

# 去掉行尾空白
sed 's/[[:space:]]*$//' file

# 把 CRLF 换行（Windows）转成 LF（Linux）
sed -i 's/\r$//' file

# 给每行加行号前缀
sed '=' file | sed 'N;s/\n/ /'
```

`[[:space:]]` 是 POSIX 字符类，表示空白字符（比 `\s` 兼容性更好）。

## 14.6 awk 正则与字段进阶

### 14.6.1 正则作为字段分隔符

```bash
# 用冒号分隔（/etc/passwd）
awk -F: '{print $1}' /etc/passwd

# 用多个字符作分隔符（正则）
awk -F'[:,]' '{print $1, $2}' file

# 用连续空白分隔（默认行为）
awk '{print $2}' file
```

### 14.6.2 正则匹配

```bash
# 打印匹配正则的行
awk '/^root/ {print}' /etc/passwd

# 第 1 列匹配 IP 格式的行
awk '$1 ~ /^[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+$/ {print}' access.log

# 不匹配的行
awk '$1 !~ /test/ {print}' file
```

`~` 是匹配运算符，`!~` 是不匹配。

### 14.6.3 条件与统计进阶

```bash
# 统计不同状态码的数量
awk '{count[$9]++} END {for (code in count) print code, count[code]}' access.log

# 计算平均响应时间（假设 $NF 是响应时间）
awk '{sum+=$NF; n++} END {print "平均:", sum/n}' access.log

# 多条件
awk '$9>=400 && $9<500 {print $1, $7, $9}' access.log
```

### 14.6.4 格式化报表

```bash
awk 'BEGIN {printf "%-15s %s\n", "IP", "次数"}
     {count[$1]++}
     END {for (ip in count) printf "%-15s %d\n", ip, count[ip]}' access.log | sort -k2 -rn | head
```

## 14.7 综合实战：从日志里提取攻击画像

```bash
#!/bin/bash
# 攻击画像分析：从 nginx 日志提取可疑信息
LOG=/var/log/nginx/access.log

echo "=== 1. 访问量前 10 的 IP ==="
awk '{print $1}' "$LOG" | sort | uniq -c | sort -rn | head -10

echo "=== 2. 404 最多的 URL（可能在扫描） ==="
awk '$9==404 {print $7}' "$LOG" | sort | uniq -c | sort -rn | head -10

echo "=== 3. 含攻击特征的请求 ==="
grep -iE '(select.+from|union.+select|\.\./|<script|cmd=|wget|curl)' "$LOG" | head -20

echo "=== 4. 可疑 User-Agent ==="
grep -iE 'sqlmap|nmap|nikto|python-requests|masscan' "$LOG" | awk -F'"' '{print $6}' | sort | uniq -c | sort -rn

echo "=== 5. 状态码分布 ==="
awk '{print $9}' "$LOG" | sort | uniq -c | sort -rn
```

这个脚本综合了正则、awk、管道、排序——是安全日志分析的典型工作流。

## 14.8 常见报错与解决

| 现象 | 原因 | 解决 |
|------|------|------|
| grep 正则不生效 | 用了 BRE 却期待 ERE 语法 | 改用 `grep -E` |
| `\{` 报错 | BRE/ERE 转义混用 | 统一用 `grep -E`，去掉多余转义 |
| sed 分组不工作 | 没加 `-E`，括号没转义 | 用 `sed -E 's/(...)/\1/'` |
| 匹配到太多 | 正则太宽松 | 加锚点 `^ $` 或精确字符类 |
| 中文匹配异常 | 编码/locale 问题 | 设置 `LANG=C.UTF-8` |

## 14.9 本章总结

| 知识点 | 内容 |
|--------|------|
| 元字符 | `.` 任意、`^` 行首、`$` 行尾、`*` 0+、`+` 1+、`?` 0/1、`{n,m}` 次数 |
| 字符类 | `[0-9]`、`[a-z]`、`[^]` 否定、`\d` `\w` `\s`（PCRE） |
| 分组 | `()` 分组、`\|` 或（ERE 直接写，BRE 转义） |
| BRE/ERE | `grep -E` 用扩展正则，语法更直观 |
| sed 高级 | `sed -E 's/(...)/\1/'` 分组反向引用；`&` 整个匹配 |
| awk 正则 | `$1 ~ /正则/` 匹配、`~` 和 `!~`；`-F'正则'` 分隔符 |
| 安全应用 | IP 提取、攻击特征匹配、User-Agent 识别、日志画像 |
