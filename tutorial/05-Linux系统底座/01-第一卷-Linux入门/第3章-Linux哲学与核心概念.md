# 第 3 章 Linux 哲学与核心概念

## 本章目标

读完这一章，你将能够：

- 真正理解"一切皆文件"的含义及其威力
- 记住 Linux 目录结构，知道什么东西放在哪里
- 理解用户、组、权限的雏形
- 理解 Shell 在 Linux 中的角色
- 把零散命令串联成一套思维框架

---

## 3.1 一切皆文件

这是 Linux 最重要、最独特的设计思想。

### 3.1.1 这句话是什么意思

在 Windows 里，你有"C 盘文件""进程""网络设备""注册表"等完全不同的东西，要用不同的工具管理。

在 Linux 里，这些东西**几乎都被抽象成"文件"**：

- 普通数据文件 → 当然是文件
- 目录 → 一种特殊文件
- 硬盘、U 盘等设备 → `/dev/sda` 这样的设备文件
- 进程信息 → `/proc/1234/` 这样的目录，里面是文件
- 网络连接、内核参数 → `/proc/sys/` 下的文件
- 终端、打印机 → `/dev/tty`、`/dev/lp0` 等设备文件

这意味着：**你可以用同一套命令（cat、ls、echo 等）去读配置和查状态。**

例如，查看 CPU 信息：

```bash
cat /proc/cpuinfo
```

查看内存信息：

```bash
cat /proc/meminfo
```

查看系统内核版本：

```bash
cat /proc/version
```

你看，不需要专门的"CPU 信息工具"，直接 `cat` 一个"文件"就行。这就是"一切皆文件"的威力——**统一的接口，极简的工具集**。

> **小白问**：`/proc` 是真的文件存在硬盘上吗？
>
> 不是。`/proc` 是"虚拟文件系统"，内容是内核动态生成的，存在于内存中。你 `cat` 它时，内核实时把信息"装扮"成文件给你看。所以这些文件没有实际大小（常常显示 0 字节），但能读出丰富内容。这是 Linux 的一个精妙设计。

### 3.1.2 这个哲学的安全意义

对安全工程师来说，"一切皆文件"意味着：

1. **可以用文本工具分析一切**：日志是文本、配置是文本、进程信息也是文本。`grep`、`awk`、`sed` 三剑客能横扫所有分析任务。
2. **权限模型统一**：既然一切都是文件，那么"读/写/执行"三种权限就能覆盖几乎所有资源。文件权限管好了，系统就安全了一大半（第 8 章详解）。
3. **可审计、可脚本化**：所有状态都能用命令读取，就能写进脚本自动检查、自动告警。

## 3.2 Linux 目录结构

Linux 没有 Windows 的"C 盘、D 盘"，只有一个根目录 `/`，所有东西都挂在它下面，形成一棵树。

### 3.2.1 根目录及主要子目录

```
/                    根目录，一切起点
├── bin/             基础命令（二进制文件），如 ls、cat
├── sbin/            系统管理命令，如 fdisk、iptables
├── etc/             配置文件（重中之重）
│   ├── passwd       用户信息
│   ├── shadow       密码哈希（仅 root 可读）
│   └── ssh/         SSH 配置
├── home/            普通用户的家目录
│   └── zhangsan/    用户 zhangsan 的家
├── root/            root 用户的家目录
├── usr/             用户程序与资源（类似 Windows 的 Program Files）
│   ├── bin/         大部分应用程序
│   └── lib/         库文件
├── var/             经常变化的数据
│   ├── log/         系统日志（安全分析金矿）
│   ├── lib/         数据库等可变数据
│   └── tmp/         临时文件
├── tmp/             临时文件（重启可能清空）
├── dev/             设备文件
├── proc/            进程与内核信息的虚拟文件系统
├── opt/             第三方软件安装位置
├── boot/            启动相关文件（内核、grub）
└── lib/             共享库
```

### 3.2.2 安全视角下的关键目录

记住这几个，对你做安全特别有用：

| 目录 / 文件 | 安全意义 |
|------------|---------|
| `/etc/passwd` | 用户账户列表（所有用户可读） |
| `/etc/shadow` | 密码哈希（仅 root 可读，是攻击者的目标） |
| `/etc/sudoers` | sudo 权限配置（谁能提权） |
| `/etc/ssh/sshd_config` | SSH 服务配置（加固重点，第 19 章详解） |
| `/var/log/auth.log` | 认证日志（看到登录、sudo、暴力破解痕迹） |
| `/var/log/syslog` | 系统日志 |
| `/proc/` | 进程、网络、内核参数的实时信息 |
| `/home/` | 用户数据，可能藏有敏感信息 |

> **小白问**：为什么密码不放在 `/etc/passwd` 里？
>
> 早期 Unix 确实把密码哈希放在 `/etc/passwd`，但这个文件所有用户都能读，攻击者可以拿去离线破解。后来改进为放在 `/etc/shadow`，只有 root 能读——这就是"权限分离"思想的体现。

### 3.2.3 路径：绝对路径与相对路径

- **绝对路径**：从根目录 `/` 开始写全，如 `/home/zhangsan/Documents/file.txt`。无论你在哪，它都指向同一个地方。
- **相对路径**：相对当前目录，如 `./file.txt`（当前目录的文件）、`../file.txt`（上级目录的文件）。

几个特殊符号：

| 符号 | 含义 |
|------|------|
| `/` | 根目录；路径分隔符 |
| `.` | 当前目录 |
| `..` | 上级目录 |
| `~` | 当前用户的家目录 |
| `-` | 上一个所在目录（cd - 用） |

实践一下：

```bash
cd /            # 切到根目录
pwd             # 显示 /
cd /etc         # 切到 etc 目录
pwd             # 显示 /etc
cd ~            # 回到家目录
pwd             # 显示 /home/你的用户名
cd -            # 回到上一个目录（/etc）
```

`cd` = change directory，是最常用的命令之一。

## 3.3 用户、组与权限的雏形

Linux 是**多用户系统**，这是它和 Windows 家庭版的一个本质区别。

### 3.3.1 用户与组

- **用户（User）**：每个使用者有一个账户，如 `zhangsan`。系统用 UID（用户 ID）数字标识用户。
- **组（Group）**：用户的集合，用 GID（组 ID）标识。一个用户可以属于多个组。

为什么要分组？为了方便授权。比如把一群人加入 `developers` 组，然后让这个组能访问项目目录，不用一个个设置。

### 3.3.2 三种基本权限

每个文件/目录对三类对象设定权限：

| 对象 | 缩写 | 含义 |
|------|------|------|
| 所有者（Owner） | `u` (user) | 文件的创建者/拥有者 |
| 同组用户（Group） | `g` | 与所有者同组的用户 |
| 其他人（Others） | `o` | 既不是所有者也不同组的人 |

每种对象有三种权限：

| 权限 | 缩写 | 对文件 | 对目录 |
|------|------|--------|--------|
| 读 | `r` (read) | 能看内容 | 能列出目录里的文件名 |
| 写 | `w` (write) | 能改内容 | 能在目录里增删文件 |
| 执行 | `x` (execute) | 能运行程序/脚本 | 能进入该目录 |

用 `ls -l` 可以看到权限：

```bash
ls -l
```

输出类似：

```bash
-rw-r--r-- 1 zhangsan zhangsan 4096 Nov 25 10:30 note.txt
```

拆解 `-rw-r--r--`：

| 位置 | 含义 |
|------|------|
| 第 1 位 `-` | 文件类型（`-` 普通文件，`d` 目录，`l` 链接） |
| `rw-` | 所有者权限：可读、可写、不可执行 |
| `r--` | 同组用户：只读 |
| `r--` | 其他人：只读 |

这是安全的基本功。第 8 章会详解如何修改权限（`chmod`、`chown`），第 17 章会讲权限模型如何防护系统。

> **小白问**：为什么脚本文件要有"执行"权限？
>
> 因为 Linux 通过"执行"权限来判断一个文件是否可以作为程序运行。没有 `x` 权限，即使内容是合法的脚本，也会被拒绝执行——这个设计防止了误运行和恶意程序扩散。

## 3.4 Shell：你和内核之间的翻译官

### 3.4.1 什么是 Shell

你敲的命令（如 `ls`）并不是内核直接认识的。中间有一个程序负责：接收你的输入 → 解释 → 调用内核 → 把结果显示给你。这个程序就是 **Shell（壳）**。

```
你  ↔  Shell（命令行解释器）  ↔  内核  ↔  硬件
```

Linux 有多种 Shell：

| Shell | 名称 | 特点 |
|-------|------|------|
| **bash** | Bourne Again Shell | 最常用，本教程主角 |
| sh | Bourne Shell | 老牌，很多系统脚本用 |
| zsh | Z Shell | 功能强、可定制（oh-my-zsh） |
| fish | Friendly Interactive Shell | 用户友好，自动补全强 |

Ubuntu 默认用 **bash**。用这条命令查看你当前的 Shell：

```bash
echo $SHELL
```

> **小白问**：`$SHELL` 里的 `$` 是什么？
>
> `$` 表示引用一个"环境变量"的值。`$SHELL` 就是变量 SHELL 的内容。环境变量是 Shell 里的一些全局设置，后面第 12 章会详解。

### 3.4.2 交互式与非交互式

Shell 有两种工作方式：

- **交互式**：你敲一条，它执行一条，看到结果再敲下一条（平时开终端就是这样）。
- **非交互式**：把一堆命令写进文件，Shell 一次性执行——这就是**Shell 脚本**（第三卷的主题）。

这个区别很重要：你今天学的每一条命令，既可以手动敲，也可以写进脚本自动跑。第三卷会把它们变成自动化武器。

## 3.5 建立你的思维框架

到这里，你已经有了理解 Linux 的核心框架：

1. **一切皆文件** → 用同一套工具（cat、grep、ls、echo）操作一切。
2. **单根树形目录** → 所有东西从 `/` 开始，各司其职（配置在 `/etc`，日志在 `/var/log`）。
3. **多用户 + 权限** → 每个文件都有"谁能读/写/执行"的标记，这是安全的基石。
4. **Shell 作桥梁** → 你通过 Shell 向内核发命令，命令可手动敲也可写成脚本。

后面所有章节，都是在这个框架上添砖加瓦。当你忘记某条命令时，想想"它属于哪一类"：是操作文件？处理文本？管理用户？看进程？这样记忆会牢固得多。

## 3.6 本章总结

| 概念 | 核心要点 |
|------|---------|
| 一切皆文件 | 硬件、进程、网络都以文件形式呈现，统一用 cat/ls 等命令操作 |
| /proc | 虚拟文件系统，实时反映内核与进程状态 |
| 目录结构 | 单根树；`/etc` 配置、`/var/log` 日志、`/home` 用户数据、`/dev` 设备 |
| 绝对路径 | 从 `/` 开始；相对路径从 `.` 开始；`~` 是家目录 |
| 用户与组 | UID/GID 标识；分组便于批量授权 |
| 三种权限 | r 读、w 写、x 执行；分属 u 所有者、g 同组、o 其他人 |
| Shell | 命令解释器；bash 最常用；连接你与内核的桥梁 |
