# 第 7 章 管道、重定向与通配符

## 本章目标

读完这一章，你将能够：

- 用通配符 `*` `?` `[]` 批量匹配文件

- 理解 /dev/null 这个"黑洞"的妙用

## 7.1 管道 `|`：把命令连成流水线

管道是 Linux 最优雅的设计之一。它把前一个命令的**输出**，直接作为后一个命令的**输入**。

```bash
命令1 | 命令2 | 命令3
```

数据流向：`命令1的输出 → 命令2的输入 → 命令2的输出 → 命令3的输入`

### 7.1.1 基础示例

```bash
# 列出所有文件，只看含 "log" 的
ls -la | grep "log"

# 查看进程，只看 python 相关的
ps aux | grep python

# 查看 /etc/passwd，数一数有多少用户
cat /etc/passwd | wc -l
```

### 7.1.2 经典流水线

第 6 章的日志分析就是管道的经典应用：

```bash
grep "Failed password" /var/log/auth.log \
  | awk '{print $11}' \
  | sort \
  | uniq -c \
  | sort -rn \
  | head
```

每个命令只做一件事，用管道组合成强大的分析工具。这正是 Unix 哲学"每个程序只做一件事并把它做好"的体现。

### 7.1.3 `tee`：分流输出

```bash
cat file.txt | tee output.txt | grep "ERROR"
```

`tee` 把数据"分叉"：一份写到文件，一份继续传给下一个命令。相当于水管上的三通。

```bash
command | tee -a log.txt    # -a 追加到文件末尾
```

> **安全场景**：运行扫描时既想看实时输出，又想保存结果：
> ```bash
> nmap -sV 192.168.1.0/24 | tee scan_results.txt
> ```

## 7.2 重定向：改变数据流向

### 7.2.1 三种标准流

Linux 为每个程序预设了三个"数据通道"：

| 名称 | 中文 | 文件描述符 | 默认来源/去向 |
|------|------|-----------|--------------|
| stdin | 标准输入 | 0 | 键盘 |
| stdout | 标准输出 | 1 | 屏幕 |
| stderr | 标准错误 | 2 | 屏幕 |

文件描述符（FD）是内核用来标识打开文件的数字。理解它，才能真正理解重定向。

### 7.2.2 输出重定向

```bash
command > file.txt      # stdout 写到文件（覆盖原有内容）
command >> file.txt     # stdout 追加到文件末尾
```

```bash
echo "hello" > note.txt
echo "world" >> note.txt
cat note.txt
# hello
# world
```

### 7.2.3 输入重定向

```bash
command < file.txt      # 从文件读 stdin，而不是键盘
```

```bash
wc -l < /etc/passwd     # 统计文件行数
```

很多命令既接受文件名参数，也接受 stdin，所以 `<` 用得比 `>` 少。

### 7.2.4 错误重定向

```bash
command 2> error.txt       # stderr 写到文件
command 2>> error.txt      # stderr 追加到文件
command > out.txt 2> err.txt   # 输出和错误分别写到不同文件
command > all.txt 2>&1     # 把 stderr 合并到 stdout，一起写入 all.txt
command &> all.txt         # 同上，简写形式（bash 支持）
```

`2>&1` 的含义：把文件描述符 2（stderr）重定向到文件描述符 1（stdout）指向的地方。注意顺序——`> file 2>&1` 和 `2>&1 > file` 效果不同，前者正确。

> **小白问**：`2>/dev/null` 为什么能"隐藏错误"？
>
> `/dev/null` 是一个特殊的设备文件，写入它的东西会被直接丢弃（黑洞）。把 stderr 重定向到它，错误信息就"消失"了。这在第 5 章的 `find / -perm -4000 2>/dev/null` 里用过——避免满屏的权限报错干扰结果。

### 7.2.5 Here Document 与 Here String

```bash
# Here Document：多行输入
cat << EOF > file.txt
line 1
line 2
EOF

# Here String：单行输入
cat <<< "hello world"
```

`<< EOF` 表示"下面的内容作为输入，直到遇到 EOF 这一行为止"。常用于写配置文件或脚本里生成内容。

### 7.2.6 重定向与管道的区别

| 特性 | 管道 `|` | 重定向 `>` |
|------|---------|-----------|
| 连接对象 | 命令 → 命令 | 命令 → 文件 |
| 数据流 | 进程之间 | 进程与文件之间 |
| 副作用 | 不产生文件 | 产生/覆盖文件 |

## 7.3 通配符：批量匹配文件

通配符让 Shell 帮你"猜"文件名，免去手敲一长串。

| 通配符 | 含义 | 示例 |
|--------|------|------|
| `*` | 任意长度任意字符 | `*.txt` 匹配所有 txt 文件 |
| `?` | 恰好一个字符 | `file?.txt` 匹配 file1.txt、fileA.txt |
| `[abc]` | 括号内的任一字符 | `file[123].txt` |
| `[a-z]` | 范围内的字符 | `[a-z]*.log` |
| `[!abc]` | 不在括号内的字符 | `file[!1].txt` |

```bash
ls *.log                  # 列出所有 .log 文件
rm -i *.tmp               # 删除所有 .tmp 文件（加 -i 确认）
cp /etc/*.conf ./backup/  # 复制所有 .conf 文件
```

> **安全提示**：通配符由 Shell 展开后再传给命令。如果目录里有名字奇怪的文件（如 `-rf`），`rm *` 可能变成 `rm -rf ...` 造成灾难。删除大量文件前，先用 `ls` 预览通配符匹配到了什么：
> ```bash
> ls *.tmp      # 先看看会匹配到哪些
> rm -i *.tmp   # 确认后再删
> ```

### 7.3.1 通配符 vs 正则表达式

很多人混淆两者：

| | 通配符（glob） | 正则表达式（regex） |
|---|---|---|
| 用途 | Shell 匹配**文件名** | grep/sed/awk 匹配**文本内容** |
| `*` 含义 | 任意字符序列 | 前一个字符重复 0+ 次 |
| 处理者 | Shell | 命令（grep 等） |

记住：**文件名用通配符，文本内容用正则**。

## 7.4 引号：控制 Shell 的展开

Shell 会对某些字符做特殊处理（空格分词、变量展开、通配符展开）。引号用来控制这些行为。

| 引号 | 行为 |
|------|------|
| 单引号 `' '` | 完全原样，禁止一切展开 |
| 双引号 `" "` | 允许变量展开（`$`），但阻止通配符和空格分词 |
| 反引号 `` ` ` `` | 命令替换（已过时，用 `$()` 代替） |
| `$()` | 命令替换：执行命令并用其输出替换 |

示例：

```bash
echo $HOME              # 展开变量，输出家目录
echo '$HOME'            # 单引号，原样输出 $HOME
echo "$HOME"            # 双引号，展开变量

echo "今天是 $(date)"    # 命令替换
echo "文件数: $(ls | wc -l)"
```

> **关键点**：双引号保护空格。如果文件名含空格，不加引号会被拆成多个参数：
> ```bash
> rm "my file.txt"      # 正确：删一个文件
> rm my file.txt        # 错误：试图删 my 和 file.txt 两个文件
> ```

## 7.5 综合实战：一条命令完成复杂分析

把本章所学组合起来：

```bash
# 找出 /var/log 下所有 .log 文件里含 "Failed" 的行，统计各 IP 次数，取前 5，保存到报告
grep -r "Failed" /var/log --include="*.log" 2>/dev/null \
  | awk '{print $NF}' \
  | sort | uniq -c | sort -rn | head -5 \
  | tee /tmp/report.txt > /dev/null
```

拆解：

- `grep -r --include="*.log"`：递归搜索，只看 .log 文件
- `2>/dev/null`：丢弃权限错误
- `awk '{print $NF}'`：取最后一列（假设是 IP）
- `sort | uniq -c | sort -rn`：统计排序
- `head -5`：取前 5
- `tee /tmp/report.txt > /dev/null`：保存到文件，同时把屏幕输出丢掉（只留文件）

再来看一个"批量检查文件权限"的例子：

```bash
# 找出家目录下所有人可读的 .sh 脚本，列出详情
find ~ -name "*.sh" -perm -o=r -ls 2>/dev/null | tee ~/perm_check.txt
```

这就是安全审计的日常——用十几行命令，完成手工要点很久的工作。

## 7.6 常见报错与解决

| 现象 | 原因 | 解决 |
|------|------|------|
| `> file` 后屏幕没输出 | 输出被写到文件了 | 用 `cat file` 看，或用 `tee` |
| 变量没展开 | 用了单引号 | 改用双引号 |
| `rm` 删错文件 | 通配符匹配超预期 | 先 `ls` 预览，加 `-i` |
| `2>&1` 顺序错 | 位置放反 | 用 `> file 2>&1` |
| 管道两边不连通 | 后一个命令不读 stdin | 检查命令是否支持 stdin 输入 |

## 7.7 本章总结

| 特性 | 语法 |
|------|------|
| 管道 | `cmd1 \| cmd2`，前一个输出作后一个输入 |
| tee | `cmd \| tee file` 分流，同时看和存 |
| 输出重定向 | `>` 覆盖、`>>` 追加 |
| 输入重定向 | `<` 从文件读入 |
| 错误重定向 | `2>`；`> file 2>&1` 合并；`2>/dev/null` 丢弃 |
| /dev/null | 黑洞设备，丢弃不需要的输出 |
| 通配符 | `*` 任意、`?` 单字符、`[]` 范围（匹配文件名） |
| 引号 | 单引号原样、双引号允许变量、`$()` 命令替换 |
