# 第 8 章 用户、组与权限管理

## 本章目标

读完这一章，你将能够：

- 用权限知识完成安全审计

## 8.1 Linux 多用户模型

### 8.1.1 为什么是多用户

Linux 从设计之初就是多用户系统——多个账户可以同时使用一台机器，各自有独立的空间和权限。这带来的好处：

- **隔离**：一个用户搞砸了，不会毁掉别人的数据。
- **安全**：每个程序以某个用户身份运行，权限被限制在该用户范围内。
- **审计**：能追踪"谁在什么时候做了什么"。

服务器尤其依赖这个模型：Web 服务用 `www-data` 用户跑、数据库用 `mysql` 用户跑，即使 Web 服务被攻破，攻击者也拿不到 root 权限。这就是**最小权限原则**的实践。

### 8.1.2 用户与 UID

系统用数字 **UID（User ID）** 标识用户：

| UID | 含义 |
|-----|------|
| 0 | root，超级管理员 |
| 1–999 | 系统用户（服务账户，如 www-data、mysql） |
| 1000+ | 普通用户（Ubuntu 从 1000 开始） |

查看当前用户身份：

```bash
whoami          # 用户名
id              # 详细：uid、gid、所属组
id zhangsan     # 查看指定用户
```

输出示例：

```bash
uid=1000(zhangsan) gid=1000(zhangsan) groups=1000(zhangsan),27(sudo)
```

### 8.1.3 组与 GID

**组（Group）** 是用户的集合，用 **GID（Group ID）** 标识。用途：

- 批量授权：让一组用户共享某目录的访问权限。
- 服务隔离：服务账户属于特定组。

一个用户可以属于多个组：主组（primary group，在 `/etc/passwd` 里）+ 附加组（supplementary groups）。

> **小白问**：如何看用户属于哪些组？
>
> `groups 用户名` 或 `id 用户名`。我们前面看到 zhangsan 属于 `sudo` 组，所以能用 sudo 提权。

### 8.1.4 关键配置文件

| 文件 | 内容 |
|------|------|
| `/etc/passwd` | 用户账户信息（所有用户可读） |
| `/etc/shadow` | 密码哈希与过期信息（仅 root 可读） |
| `/etc/group` | 组信息 |
| `/etc/gshadow` | 组密码（仅 root 可读） |

`/etc/passwd` 每行格式（冒号分隔）：

```bash
zhangsan:x:1000:1000:Zhang San:/home/zhangsan:/bin/bash
```

字段依次是：用户名、密码占位符（x，真正密码在 shadow）、UID、GID、备注、家目录、登录 Shell。

> **安全提示**：如果某用户的 shell 是 `/sbin/nologin` 或 `/usr/sbin/nologin`，说明它不能登录，通常是系统服务账户。审计时留意有没有异常的可登录账户。

## 8.2 用户与组的管理命令

> 以下命令都需要 root 权限（用 `sudo`）。

### 8.2.1 创建用户

```bash
sudo useradd -m -s /bin/bash alice
```

- `-m`：创建家目录（`/home/alice`）
- `-s`：指定登录 Shell

然后设置密码：

```bash
sudo passwd alice
```

> **小白问**：`useradd` 和 `adduser` 有什么区别？
>
> `useradd` 是底层命令，参数多；`adduser` 是 Debian/Ubuntu 提供的友好封装，交互式提问、自动建家目录。零基础推荐用 `adduser`：
> ```bash
> sudo adduser alice
> ```

### 8.2.2 修改用户

```bash
sudo usermod -aG sudo alice      # 把 alice 加入 sudo 组（获得提权能力）
sudo usermod -l newname alice    # 改用户名
sudo usermod -s /sbin/nologin alice  # 禁止登录
sudo usermod -L alice            # 锁定账户
sudo usermod -U alice            # 解锁账户
```

`-aG` 的 `-a` 是 append（追加），`-G` 是指定附加组。**忘记 `-a` 会把用户从其他组移除**，这是个常见坑。

### 8.2.3 删除用户

```bash
sudo userdel alice               # 删除用户，保留家目录
sudo userdel -r alice            # 删除用户及其家目录和邮件
```

### 8.2.4 组的创建与管理

```bash
sudo groupadd developers          # 创建组
sudo groupdel developers          # 删除组
sudo gpasswd -a alice developers  # 把 alice 加入 developers 组
sudo gpasswd -d alice developers  # 移出组
```

### 8.2.5 切换用户

```bash
su - alice            # 切换到 alice（带 - 会加载其环境）
sudo -i               # 切换到 root 环境
sudo -u alice command # 以 alice 身份执行一条命令
```

`su` 需要目标用户的密码；`sudo` 需要当前用户的密码（且当前用户要有 sudo 权限）。

## 8.3 权限详解

### 8.3.1 权限的表示

`ls -l` 输出的权限字符串有 10 位：

```bash
-rwxr-xr--
```

拆解：

| 位置 | 含义 |
|------|------|
| 第 1 位 | 文件类型：`-` 普通文件、`d` 目录、`l` 链接、`c` 字符设备、`b` 块设备 |
| 2–4 位 | 所有者（u）权限 |
| 5–7 位 | 同组用户（g）权限 |
| 8–10 位 | 其他人（o）权限 |

每 3 位中：`r`=读（4）、`w`=写（2）、`x`=执行（1），`-` 表示无此权限。

### 8.3.2 数字表示法（八进制）

因为 r=4、w=2、x=1，所以每组权限可以相加成一个数字：

| 权限 | 数字 | 计算 |
|------|------|------|
| `rwx` | 7 | 4+2+1 |
| `rw-` | 6 | 4+2 |
| `r-x` | 5 | 4+1 |
| `r--` | 4 | 4 |
| `---` | 0 | 0 |

常见权限组合：

| 数字 | 权限 | 用途 |
|------|------|------|
| 755 | `rwxr-xr-x` | 可执行程序、目录（最常见） |
| 644 | `rw-r--r--` | 普通文件、配置 |
| 700 | `rwx------` | 私密目录/脚本，仅自己可用 |
| 600 | `rw-------` | 私密文件（如 SSH 私钥） |

### 8.3.3 chmod：修改权限

```bash
chmod 755 script.sh          # 数字法
chmod u+x script.sh          # 符号法：给所有者加执行权限
chmod go-w file.txt          # 去掉组和其他人的写权限
chmod a+r file.txt           # 给所有人（a=all）加读权限
chmod -R 700 private_dir/    # 递归修改目录及其内容
```

> **最佳实践**：能用数字法就别用符号法（更明确）；改目录时记得 `-R`。

### 8.3.4 chown / chgrp：修改所有者

```bash
sudo chown alice file.txt                 # 改所有者
sudo chown alice:developers file.txt      # 同时改所有者和组
sudo chown -R alice:developers /data/     # 递归
sudo chgrp developers file.txt            # 只改组
```

## 8.4 目录权限的特殊性

对目录来说，权限含义与文件不同：

| 权限 | 对目录的含义 |
|------|-------------|
| `r` | 能列出目录里的文件名（`ls`） |
| `w` | 能在目录里创建、删除、重命名文件 |
| `x` | 能进入目录（`cd`）、访问里面文件的元数据 |

**关键点**：删除一个文件，取决于**该文件所在目录的写权限**，而不是文件本身的权限！

例如：一个文件是 `644`（所有者可写），但如果它在你拥有 `w` 权限的目录里，你依然能删掉它——哪怕你不是文件所有者。这就是为什么 `/tmp` 目录要设置 Sticky Bit（下面讲）。

> **安全场景**：攻击者如果能在某个目录写文件，就可能替换掉该目录下的程序或配置。所以重要目录（`/etc`、`/usr/bin`）不能对普通用户开放写权限。

## 8.5 特殊权限：SUID / SGID / Sticky Bit

除了 rwx，Linux 还有三个特殊权限位，是安全审计的重点。

### 8.5.1 SUID（Set User ID）

当文件设置了 SUID 位，任何用户执行它时，**以文件所有者的身份运行**，而不是执行者。

经典例子：`/usr/bin/passwd`。普通用户改自己的密码需要写 `/etc/shadow`（root 才能写），但 `passwd` 程序设置了 SUID：

```bash
ls -l /usr/bin/passwd
# -rwsr-xr-x 1 root root ... /usr/bin/passwd
```

注意所有者的 `x` 变成了 `s`——这就是 SUID 标记。

设置方法：

```bash
chmod u+s file        # 符号法
chmod 4755 file       # 数字法，最前面的 4 就是 SUID
```

> ⚠️ **安全风险**：SUID 程序以 root 权限运行，如果程序有漏洞，攻击者就能提权到 root。所以**找出并审计 SUID 文件是安全加固的必做项**：
> ```bash
> find / -perm -4000 -type f 2>/dev/null
> ```
> 任何来路不明的 SUID 文件都要警惕——这是攻击者留后门的常见手法。

### 8.5.2 SGID（Set Group ID）

类似 SUID，但以文件所属组的身份运行（数字位 2）：

```bash
chmod g+s file
chmod 2755 file
```

对目录设置 SGID 时，目录里新建的文件会继承目录的组，便于团队协作。

### 8.5.3 Sticky Bit（粘滞位）

对目录设置 Sticky Bit 后，**只有文件的所有者才能删除自己的文件**，即使其他人有目录写权限。

经典例子：`/tmp`：

```bash
ls -ld /tmp
# drwxrwxrwt 1 root root ... /tmp
```

其他人的 `x` 变成了 `t`。这防止了用户互相删除对方在临时目录的文件。

```bash
chmod +t directory
chmod 1777 directory   # 最前面的 1 是 Sticky Bit
```

### 8.5.4 特殊权限总结

| 权限 | 数字 | 符号位置 | 作用 | 风险 |
|------|------|---------|------|------|
| SUID | 4 | u 的 x 位变 s | 以所有者身份运行 | 程序有漏洞可提权 |
| SGID | 2 | g 的 x 位变 s | 以组身份运行 / 目录继承组 | 类似 SUID |
| Sticky | 1 | o 的 x 位变 t | 目录内只能删自己的文件 | 无（是保护措施） |

## 8.6 sudo：受控提权

### 8.6.1 sudo 的工作方式

`sudo` 允许授权用户以其他用户（默认 root）身份执行命令，同时记录日志。相比直接用 root 登录，它更安全：

- 不需要暴露 root 密码
- 精确到"谁能执行什么"
- 所有提权操作都有日志（`/var/log/auth.log`）

```bash
sudo command           # 以 root 执行
sudo -u alice command  # 以 alice 执行
sudo -l                # 查看当前用户被授权执行什么
```

### 8.6.2 sudoers 配置

配置通过 `visudo` 编辑（它会检查语法，避免改错把系统锁死）：

```bash
sudo visudo
```

典型条目：

```bash
# 允许用户 alice 执行任意命令
alice ALL=(ALL:ALL) ALL

# 允许用户 bob 只执行特定命令（更安全）
bob ALL=(root) /usr/bin/apt, /usr/bin/systemctl restart nginx

# 允许 sudo 组的所有成员
%sudo ALL=(ALL:ALL) ALL
```

格式：`用户 主机=(以谁的身份) 可以执行的命令`

> **最小权限原则**： production 环境中，不要给普通用户无限制的 sudo。精确授权到具体命令，能大幅降低误操作和恶意提权的风险。

### 8.6.3 sudo 的安全加固

```bash
# 禁用 root 密码登录（第 19 章详解 SSH 时再展开）
sudo passwd -l root

# 要求输入密码（默认就是，有些配置禁用了 NOPASSWD，注意审计）
sudo visudo   # 检查有没有 NOPASSWD: ALL 这种危险配置
```

> **安全场景**：攻击者拿到一个普通用户后，第一件事往往是 `sudo -l` 看有没有可利用的提权路径。审计时要检查：
> - 有没有不该有的 NOPASSWD 条目
> - 授权的脚本是否可被普通用户修改（可被替换成恶意命令）
> - 有没有授权危险命令（如 vim、find，它们能逃逸出 shell）

## 8.7 权限安全审计实战

综合所用，做一次权限审计：

```bash
# 1. 找出所有 SUID 文件（提权入口）
find / -perm -4000 -type f 2>/dev/null

# 2. 找出所有人可写的目录（检查是否误设 777）
find / -type d -perm -o=w 2>/dev/null | head -20

# 3. 检查 /etc/passwd 有没有 UID=0 的异常账户
awk -F: '$3==0 {print $1}' /etc/passwd

# 4. 检查空密码账户
sudo awk -F: '($2=="") {print $1}' /etc/shadow

# 5. 检查 sudo 权限配置
sudo -l

# 6. 看最近的特权操作
sudo grep "sudo:" /var/log/auth.log | tail -20
```

这些命令是蓝队/运维做基线检查的常用组合。

## 8.8 常见报错与解决

| 报错 | 原因 | 解决 |
|------|------|------|
| `Permission denied` | 权限不足 | 加 `sudo`；检查文件权限 |
| `must be root` | 需要 root | 用 `sudo` |
| `sudo: ... not in the sudoers file` | 用户无 sudo 权限 | 让 root 用 `visudo` 授权 |
| `chmod: invalid mode` | 权限格式错 | 检查数字/符号格式 |

## 8.9 本章总结

| 知识点 | 内容 |
|--------|------|
| 多用户模型 | UID 0=root，1-999=系统用户，1000+=普通用户；组用 GID 标识 |
| 配置文件 | `/etc/passwd`（账户）、`/etc/shadow`（密码哈希）、`/etc/group`（组） |
| 用户命令 | `useradd`/`adduser`、`usermod`、`userdel`、`passwd`、`su`、`sudo` |
| 权限 | rwx 对应 421；755 程序、644 文件、600 私密文件 |
| 修改权限 | `chmod`（权限）、`chown`（所有者）、`chgrp`（组） |
| 目录权限 | w 决定能否删文件；x 决定能否进入 |
| 特殊权限 | SUID(4) 提权风险、SGID(2)、Sticky(1) 保护共享目录 |
| sudo | 受控提权、有日志；用 `visudo` 安全配置；遵循最小权限 |
