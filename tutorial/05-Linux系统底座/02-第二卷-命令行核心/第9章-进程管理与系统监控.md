# 第 9 章 进程管理与系统监控

## 本章目标

读完这一章，你将能够：

- 理解进程、线程、PID 等核心概念
- 用 `ps`、`top`、`htop` 查看和管理进程
- 用 `kill`、`killall`、`pkill` 终止进程
- 理解前台/后台任务与 `jobs`、`&`、`nohup`、`tmux`
- 用系统监控命令排查性能问题与异常进程
- 识别常见的恶意进程特征

## 9.1 进程基础

### 9.1.1 什么是进程

**进程（Process）** 是"正在运行的程序"。你敲 `ls`，系统就创建一个 `ls` 进程；你打开浏览器，就有一个浏览器进程。

每个进程有唯一的 **PID（进程 ID）**。系统通过 PID 管理进程。

> **小白问**：进程和程序有什么区别？
>
> 程序是躺在硬盘上的静态文件（如 `/bin/ls`），进程是程序被加载到内存、开始执行后的动态实例。就像"菜谱"和"按菜谱做菜的过程"——菜谱是程序，做菜的过程是进程。同一个程序可以启动多个进程（多个 PID）。

### 9.1.2 进程的生命周期

一个进程从创建到结束，会经历：创建 → 就绪 → 运行 → 阻塞（等待 I/O） → 终止。当你敲一个命令，Shell 创建子进程，子进程运行完退出，Shell 收回它。

### 9.1.3 父进程与子进程

进程由其他进程创建，创建者叫父进程（PPID）。Linux 所有进程追溯源头都是 **init 进程（PID 1）**（systemd）。

用 `ps -ef` 能看到 PPID 列。理解父子关系对排查"谁启动了这个可疑进程"很重要。

## 9.2 查看进程

### 9.2.1 `ps`：进程快照

```bash
ps              # 查看当前终端的进程
ps -ef          # 查看所有进程，完整格式（标准语法）
ps aux          # 查看所有进程，BSD 格式（更常用，信息更全）
ps -ef | grep python   # 找 python 相关进程
```

`ps aux` 输出示例：

```bash
USER  PID  %CPU %MEM  VSZ  RSS TTY  STAT START TIME COMMAND
root  1234  0.5  1.2  ...  ... ?    Ss   10:30 0:05 /usr/bin/python3 app.py
zhangsan 5678 99.9 30.0 ... ... pts/0 R 10:35 2:30 ./miner
```

关键列：

| 列 | 含义 |
|----|------|
| USER | 进程所属用户 |
| PID | 进程 ID |
| %CPU / %MEM | CPU / 内存占用率 |
| STAT | 进程状态（R=运行、S=睡眠、D=不可中断睡眠、Z=僵尸、T=停止） |
| START / TIME | 启动时间 / 累计占用 CPU 时间 |
| COMMAND | 启动的命令 |

> **安全场景**：看到一个陌生用户运行的、CPU 占用 99% 的进程（如上面的 `./miner` 挖矿程序），就要高度警惕。`ps aux` 是排查入侵的第一手工具。

### 9.2.2 `top`：动态监控

```bash
top
```

实时显示系统资源和进程状态，类似 Windows 任务管理器。

操作：

| 按键 | 作用 |
|------|------|
| `q` | 退出 |
| `P` | 按 CPU 占用排序 |
| `M` | 按内存占用排序 |
| `k` | 输入 PID 杀死进程 |
| `u` | 只看某用户的进程 |
| `1` | 显示每个 CPU 核心 |

顶部概要信息：

- `load average`：系统负载（1/5/15 分钟平均值），超过 CPU 核数说明过载
- `%Cpu(s)`：CPU 使用分布（us 用户、sy 系统、id 空闲、wa 等待 I/O）
- `MiB Mem` / `MiB Swap`：内存和交换分区使用

### 9.2.3 `htop`：更好用的 top

```bash
sudo apt install htop
htop
```

`htop` 是 `top` 的增强版：彩色界面、支持鼠标、可横向滚动看完整命令、操作更直观。强烈推荐安装。

### 9.2.4 查看进程树

```bash
pstree           # 树状显示进程父子关系
ps -ef --forest  # 带缩进的树形格式
```

> **安全场景**：看到可疑进程时，用 `pstree -p` 追溯它的父进程。如果父进程是 `bash` 或某个 Web 服务，能帮你判断入侵入口（如通过 Web 漏洞执行命令）。

## 9.3 终止进程

### 9.3.1 `kill`：按 PID 终止

```bash
kill PID              # 发送 TERM 信号（15），优雅终止，默认
kill -9 PID           # 发送 KILL 信号（9），强制杀死，不可忽略
kill -l               # 列出所有信号
```

常见信号：

| 信号 | 编号 | 含义 |
|------|------|------|
| TERM | 15 | 终止（默认，程序可清理资源） |
| KILL | 9 | 强制杀死（程序无法捕获，立即终止） |
| HUP | 1 | 挂起/重新加载配置 |
| INT | 2 | 中断（等同 Ctrl+C） |
| STOP | 19 | 暂停进程 |

> **最佳实践**：先用 `kill PID`（TERM），给程序清理的机会；无效再用 `kill -9`。直接 `-9` 可能导致数据丢失或残留锁文件。

### 9.3.2 `killall` / `pkill`：按名字终止

```bash
killall python3        # 杀死所有名为 python3 的进程
pkill -f "app.py"      # 杀死命令行含 "app.py" 的进程（-f 匹配完整命令）
pkill -u alice         # 杀死 alice 用户的所有进程
```

> ⚠️ 按名字杀进程要小心，可能误杀正常服务。先用 `ps` 确认，再动手。

### 9.3.3 僵尸进程

状态为 `Z` 的进程是"僵尸进程"——已经结束但父进程没回收它。少量僵尸无害，大量僵尸说明父进程有问题，需要排查或直接重启相关服务（僵尸不能用 kill 杀死，因为它已经"死"了）。

## 9.4 前后台任务

### 9.4.1 后台运行

在命令后加 `&`，让它在后台运行：

```bash
python3 long_task.py &
```

Shell 会返回任务编号和 PID。

### 9.4.2 任务管理

```bash
jobs              # 查看当前 Shell 的后台任务
fg %1             # 把后台任务 1 调到前台
bg %1             # 让暂停的任务在后台继续
Ctrl + Z          # 暂停当前前台任务
```

### 9.4.3 `nohup`：断开终端也不中断

默认情况下，关闭终端会终止它启动的后台任务。`nohup`（no hangup）让命令忽略挂起信号：

```bash
nohup python3 long_task.py > task.log 2>&1 &
```

这条命令的含义：后台运行 Python 脚本，输出和错误都写到 `task.log`，关闭终端也不停止。

> **场景**：训练模型要跑几小时，用 `nohup` 或 `tmux` 保持任务，否则 SSH 断开训练就中断了。

### 9.4.4 `tmux`：终端复用器（强烈推荐）

```bash
sudo apt install tmux
tmux                    # 新建会话
tmux new -s train       # 新建名为 train 的会话
```

操作（前缀键默认是 `Ctrl+B`，然后按后面的键）：

| 操作 | 作用 |
|------|------|
| `Ctrl+B` 然后 `D` | 脱离会话（任务继续在后台跑） |
| `tmux attach -t train` | 重新接入会话 |
| `Ctrl+B` 然后 `C` | 新建窗口 |
| `Ctrl+B` 然后 `N`/`P` | 切换窗口 |
| `tmux ls` | 列出所有会话 |

> **AI 场景**：用 tmux 启动训练任务，脱离会话，回家睡觉；第二天 `tmux attach` 回来，训练还在跑，结果都在。这是 AI 工程师的必备技能。

## 9.5 系统监控命令

### 9.5.1 资源概览

```bash
uptime          # 运行时间、负载平均值
free -h         # 内存使用（人类可读）
df -h           # 磁盘空间
du -sh dir/     # 目录占用空间（du = disk usage）
df -i           # inode 使用情况（inode 耗尽也会导致无法写文件）
```

### 9.5.2 找出资源大户

```bash
# CPU 占用前 10
ps aux --sort=-%cpu | head -11

# 内存占用前 10
ps aux --sort=-%mem | head -11

# 找最大的文件
du -ah /var/log | sort -rh | head -10
```

### 9.5.3 网络连接

```bash
ss -tunap          # 查看所有网络连接（推荐，比 netstat 快）
netstat -tunap     # 老牌命令（需安装 net-tools）
ss -tulnp          # 只看监听端口及对应进程
```

> **安全场景**：检查有没有异常外联：
> ```bash
> ss -tunap | grep ESTAB
> ```
> 看到本机连向陌生 IP 的 established 连接，尤其来自可疑进程，要立即排查。

## 9.6 恶意进程识别实战

综合所学，做一次"进程排查"：

```bash
# 1. 看 CPU/内存占用异常高的进程
ps aux --sort=-%cpu | head -15

# 2. 看进程树，找父子关系异常
pstree -p | head -50

# 3. 看网络连接，找异常外联
ss -tunap

# 4. 看进程的可执行文件路径（/proc/PID/exe）
ls -l /proc/5678/exe

# 5. 看进程启动时的完整命令
tr '\0' ' ' < /proc/5678/cmdline; echo

# 6. 看该进程打开的文件
lsof -p 5678
```

可疑特征清单：

- 进程名伪装成系统进程（如 `kworkerds`、`[kthreadd]` 带奇怪后缀）
- 藏在 `/tmp`、`/dev/shm`、`/var/tmp` 里运行的可执行文件
- 无规律的随机名字进程
- CPU 长期 90%+ 占用（挖矿特征）
- 连向境外陌生 IP 的连接
- 进程的父进程异常（如 Web 服务启动了 `bash`）

> ⚠️ 发现可疑进程不要直接 `kill -9` 了事——先记录信息（PID、路径、连接、父进程），因为进程被杀后证据就消失了。专业做法是：先取证，再隔离，再清除，最后溯源。

## 9.7 常见报错与解决

| 现象 | 原因 | 解决 |
|------|------|------|
| `kill: No such process` | PID 不存在（已结束） | 用 `ps` 重新确认 |
| `kill: Operation not permitted` | 不是进程所有者 | 用 `sudo` |
| 后台任务被关闭 | 终端退出发 HUP 信号 | 用 `nohup` 或 `tmux` |
| top 里看不到进程 | 权限不足或被隐藏 | 用 `sudo top` |

## 9.8 本章总结

| 知识点 | 内容 |
|--------|------|
| 进程 | 运行中的程序；PID 唯一标识；父进程 PPID |
| 查看 | `ps aux`（快照）、`top`/`htop`（动态）、`pstree`（树） |
| 终止 | `kill PID`、`kill -9 PID`、`killall`、`pkill`；先 TERM 后 KILL |
| 前后台 | `&` 后台、`jobs`、`fg`/`bg`、`Ctrl+Z` |
| 持久化 | `nohup ... &`、`tmux`（AI 训练必备） |
| 监控 | `uptime`、`free -h`、`df -h`、`du -sh`、`ss -tunap` |
| 恶意进程 | 高 CPU、陌生路径、异常外联、伪装名称；先取证再处理 |
