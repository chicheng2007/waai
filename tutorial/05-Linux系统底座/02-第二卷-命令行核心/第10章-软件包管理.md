## 10.1 软件包管理基础

### 10.1.1 没有包管理器会怎样

在 Windows 里装软件，你去官网下载 `.exe`，一路下一步。但这种方式在 Linux 有几个问题：

- 软件之间互相依赖（A 软件需要 B 库），你得手动找齐所有依赖。
- 不知道软件装到了哪里，卸载时留下一堆残留文件。
- 更新要一个个手动下载，容易遗漏安全补丁。

**包管理器**解决了这一切：它从一个中心仓库下载软件，自动解析并安装所有依赖，记录每个文件的位置，卸载时干净移除，还能一键更新全部软件。

### 10.1.2 两大包管理家族

| 家族 | 发行版 | 包格式 | 包管理器 |
|------|--------|--------|---------|
| Debian 系 | Ubuntu、Debian、Kali | `.deb` | `apt` / `dpkg` |
| Red Hat 系 | RHEL、CentOS、Fedora、Rocky | `.rpm` | `dnf` / `yum` / `rpm` |

本教程以 Debian 系的 `apt` 为主。

### 10.1.3 软件仓库（Repository）

包管理器从哪里下载软件？答案是**软件仓库（repo / 源）**——存放软件包及其索引信息的服务器。

配置文件：

- `/etc/apt/sources.list`
- `/etc/apt/sources.list.d/` 目录下的 `.list` / `.sources` 文件

仓库地址形如：

```bash
deb http://archive.ubuntu.com/ubuntu jammy main restricted universe multiverse
```

拆解：`deb`（二进制包）+ URL + 发行版代号（jammy=22.04）+ 组件（main 主、universe 社区等）。

> **小白问**：为什么国内要换源？
>
> 默认仓库服务器在国外，下载慢。换成国内镜像（清华、阿里、中科大）速度快很多。这是国内 Linux 用户的第一步优化。

### 10.1.4 依赖关系

软件 A 依赖库 B，库 B 依赖库 C……这就是依赖关系。包管理器会自动解析并安装所有需要的依赖。这也是为什么 `apt install` 经常一下装好几个包。

## 10.2 apt：Debian/Ubuntu 包管理

### 10.2.1 更新软件索引

```bash
sudo apt update
```

从仓库下载最新的软件包索引（版本信息、依赖关系）。**安装软件前先 update**，否则可能找不到新版本或装到旧版。

> `apt update` 只是更新索引，不装任何软件。很多人误以为它"升级系统"，其实真正的升级是 `apt upgrade`。

### 10.2.2 安装软件

```bash
sudo apt install nmap           # 安装 nmap
sudo apt install -y nmap        # -y 自动确认，脚本中常用
sudo apt install nmap vim htop  # 一次装多个
```

### 10.2.3 升级软件

```bash
sudo apt upgrade                # 升级所有可升级的包
sudo apt full-upgrade           # 更激进的升级（可增删包），谨慎用
sudo apt dist-upgrade           # 老写法，等同 full-upgrade
```

> **安全提示**：定期 `apt update && apt upgrade` 是打安全补丁的基本功。漏洞曝光后，修复包通常很快进入仓库，及时升级能堵住已知漏洞。

### 10.2.4 卸载软件

```bash
sudo apt remove nmap            # 卸载软件，保留配置文件
sudo apt purge nmap             # 卸载并删除配置文件（更彻底）
sudo apt autoremove             # 自动清理不再需要的依赖包
```

`autoremove` 很有用：卸载软件后，当初为它装的依赖如果没人用了，可以一键清掉，节省空间。

### 10.2.5 查询软件

```bash
apt search keyword              # 按关键词搜索可用软件
apt show nmap                   # 查看软件包详细信息
dpkg -l                         # 列出所有已安装的包
dpkg -l | grep nmap             # 查某个包是否安装
which nmap                      # 查看命令在哪个路径（是否已安装）
```

示例：

```bash
apt search "port scanner"       # 找端口扫描工具
apt show nmap | head -20        # 看 nmap 的版本、依赖、描述
```

### 10.2.6 清理缓存

```bash
sudo apt clean                  # 清空下载的包缓存（/var/cache/apt/archives）
sudo apt autoclean              # 只清理过期的包缓存
```

### 10.2.7 常用的组合命令

```bash
# 一键更新系统（最常用）
sudo apt update && sudo apt upgrade -y

# 安装一批安全工具
sudo apt install -y nmap htop tcpdump wireshark

# 换源后重建索引
sudo apt update
```

## 10.3 更换国内软件源

以 Ubuntu 22.04 为例：

### 方法一：图形界面
"软件和更新" → "下载自" → 选择"镜像站" → 选一个国内的（如阿里云）。

### 方法二：修改配置文件

```bash
# 先备份
sudo cp /etc/apt/sources.list /etc/apt/sources.list.bak

# 用 sed 替换（把官方源换成清华源）
sudo sed -i 's|http://archive.ubuntu.com/ubuntu|https://mirrors.tuna.tsinghua.edu.cn/ubuntu|g' /etc/apt/sources.list
sudo sed -i 's|http://security.ubuntu.com/ubuntu|https://mirrors.tuna.tsinghua.edu.cn/ubuntu|g' /etc/apt/sources.list

# 更新索引
sudo apt update
```

> Ubuntu 24.04+ 使用 `/etc/apt/sources.list.d/ubuntu.sources` 的新格式，改法略有不同，注意查对应教程。

## 10.4 Red Hat 系：dnf / yum

```bash
sudo dnf update                 # 更新（CentOS 8+/Fedora）
sudo yum update                 # 老版本（CentOS 7）
sudo dnf install nmap           # 安装
sudo dnf remove nmap            # 卸载
sudo dnf search keyword         # 搜索
sudo dnf info nmap              # 查看信息
rpm -qa | grep nmap             # 查已安装的包
```

对应关系：

| 操作 | apt (Debian) | dnf/yum (RHEL) |
|------|-------------|----------------|
| 更新索引 | `apt update` | （自动） |
| 安装 | `apt install` | `dnf install` |
| 升级 | `apt upgrade` | `dnf update` |
| 卸载 | `apt remove` | `dnf remove` |
| 搜索 | `apt search` | `dnf search` |
| 查已装 | `dpkg -l` | `rpm -qa` |

## 10.5 源码编译安装

有些软件仓库里没有，或需要特定版本/配置，就要从源码编译安装。

基本流程：

```bash
# 1. 安装编译工具
sudo apt install build-essential

# 2. 下载源码并解压
wget https://example.com/software.tar.gz
tar -xzvf software.tar.gz
cd software/

# 3. 配置（检查环境、生成 Makefile）
./configure --prefix=/usr/local

# 4. 编译
make -j$(nproc)      # -j 并行编译，nproc 是 CPU 核数，加快速度

# 5. 安装
sudo make install
```

卸载时（如果源码目录还在）：

```bash
sudo make uninstall
```

如果没提供 uninstall，只能手动删除安装的文件——这正是包管理器的优势：它记录所有安装的文件，卸载很干净。

> **AI 场景**：编译安装特定版本的 Python、CUDA 相关库、或从源码编译安全工具（如某些渗透工具）时，会用到这个流程。第 26 章详解编译工具链。

## 10.6 安全视角的包管理

### 10.6.1 供应链安全

你安装的软件来自仓库，仓库的维护者负责任维护。但如果添加了不可信的第三方源，就可能装到被植入后门的软件——这就是**供应链攻击**。

原则：

- 只添加可信的官方源和知名第三方源。
- 添加新源时核实来源（GPG 签名验证）。
- 定期检查 `/etc/apt/sources.list.d/` 有没有异常源。

```bash
# 检查当前启用的所有源
apt-cache policy        # 查看包来源优先级
grep -rh "^deb " /etc/apt/sources.list /etc/apt/sources.list.d/  # 列出所有源
```

### 10.6.2 及时打补丁

```bash
# 查看有哪些包有新版本（特别是安全更新）
apt list --upgradable

#  Ubuntu 的安全更新有单独标记，可用 unattended-upgrades 自动安装
sudo apt install unattended-upgrades
sudo dpkg-reconfigure unattended-upgrades
```

服务器的很多入侵事件，根源是系统或软件有已知漏洞但没打补丁。**定期更新是最有效的安全措施之一**。

### 10.6.3 审计已安装软件

```bash
# 列出所有已安装包（可能很多，配合 grep 找目标）
dpkg -l

# 查看某个包安装了哪些文件（排查可疑文件来源）
dpkg -L nmap

# 查看某个文件属于哪个包
dpkg -S /usr/bin/nmap
```

> **安全场景**：在系统里发现一个可疑文件，用 `dpkg -S 文件路径` 查它属于哪个包。如果查不到，说明它可能是手工放置的（攻击者常用手法，值得深查）。

## 10.7 常见报错与解决

| 报错 | 原因 | 解决 |
|------|------|------|
| `Unable to locate package` | 索引没更新 / 包名错 / 源里没有 | 先 `apt update`；检查拼写 |
| `Could not get lock` | 另一个 apt 进程在跑 | 等它结束；或 `sudo rm /var/lib/dpkg/lock*` 后重试 |
| `404 Not Found` | 源地址失效 | 换源或 `apt update` |
| `E: Broken packages` | 依赖冲突 | `sudo apt --fix-broken install` |
| `dpkg: error processing` | 包状态损坏 | `sudo dpkg --configure -a` |

## 10.8 本章总结

| 知识点 | 内容 |
|--------|------|
| 包管理器 | 自动下载、解析依赖、安装/卸载/更新软件 |
| 两大体系 | Debian 系 apt（.deb）；Red Hat 系 dnf/yum（.rpm） |
| 仓库 | 软件包来源；配置在 `/etc/apt/sources.list` 等 |
| apt 常用 | `update`（更新索引）、`install`、`upgrade`、`remove`/`purge`、`search`、`show` |
| 清理 | `autoremove` 清理无用依赖；`clean` 清缓存 |
| 换源 | 国内用镜像站加速，改完要 `apt update` |
| 源码编译 | `./configure → make → make install` |
| 安全 | 只信可信源、及时打补丁、`dpkg -S` 审计文件来源 |
