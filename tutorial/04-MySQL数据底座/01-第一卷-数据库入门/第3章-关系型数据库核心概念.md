# 第 3 章 关系型数据库核心概念

## 本章目标

读完这一章，你将能够：

- 说清楚关系型数据库的六个核心概念（库、表、行、列、主键、外键）
- 理解 SQL 的四大分类（DDL/DML/DQL/DCL）
- 知道什么是"关系"，为什么它重要
- 理解客户端-服务器架构

## 3.1 从一张"资产清单"说起

假设你是安全管理员，要管理公司的服务器资产。你可能会画这样一张表：

| 编号 | IP 地址 | 操作系统 | 负责人 | 状态 |
|------|---------|---------|--------|------|
| 1 | 192.168.1.10 | Ubuntu 22.04 | 张三 | 运行中 |
| 2 | 192.168.1.11 | Windows 11 | 李四 | 运行中 |
| 3 | 10.0.0.5 | CentOS 7 | 王五 | 已下线 |

这就是一张**关系型表**——由行和列组成的二维结构。关系型数据库就是由若干张这样的表组成的。

> **小白问**："关系型"的"关系"指什么？
> 不是说表里的数据有亲戚关系，而是指**表与表之间通过共同的字段建立关联**。比如"负责人"这一列，可以关联到另一张"员工表"。后面讲外键时你会彻底明白。

## 3.2 六个核心概念

### 1. 数据库（Database / Schema）

数据库是表的容器。一个 MySQL 实例里可以有多个数据库，每个数据库里有多张表。

```
MySQL 服务器
├── security_lab（数据库）
│   ├── hosts（主机表）
│   ├── login_logs（登录日志表）
│   └── threat_intel（威胁情报表）
└── company（另一个数据库）
    ├── employees（员工表）
    └── departments（部门表）
```

> **小白问**：Database 和 Schema 有区别吗？
> 在 MySQL 里基本是一个意思（`CREATE DATABASE` 等价于 `CREATE SCHEMA`）。在其他数据库（如 PostgreSQL、SQL Server）里可能有区别。先按一个理解。

### 2. 表（Table）

表是数据的集合，有固定的列和可变的行。表必须有名字，且在同一库里唯一。

### 3. 行（Row / Record）

一行就是一条记录。如下表里的"编号 1 的主机"就是一行。行也叫记录（Record）。

### 4. 列（Column / Field）

一列是一个字段，有名字和数据类型。所有行都有相同的列。列也叫字段（Field）。

### 5. 主键（Primary Key）

主键是**唯一标识一行**的列（或列的组合）。特点：

- 不能重复
- 不能为空（NULL）
- 一张表只能有一个主键

比如资产清单里的"编号"。为什么需要主键？因为光靠 IP 可能不唯一（比如 NAT 环境），需要一个绝对唯一的标识。

```sql
CREATE TABLE hosts (
    id INT AUTO_INCREMENT PRIMARY KEY,  -- id 是主键，自动递增
    ip VARCHAR(64) NOT NULL,
    ...
);
```

`AUTO_INCREMENT` 让 MySQL 自动为每行分配递增的数字，省得手动编号。

### 6. 外键（Foreign Key）

外键是**引用另一张表主键的列**，用来建立表与表的关联。

比如我们有张"员工表"：

```sql
CREATE TABLE employees (
    emp_id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(64) NOT NULL,
    dept_id INT,
    FOREIGN KEY (dept_id) REFERENCES departments(dept_id)
);
```

`dept_id` 是外键，指向部门表的主键。这样"张三属于哪个部门"就通过编号关联起来了，而不是在员工表里重复存部门名称。

**外键的好处**：

- 避免数据冗余（部门名只存一份）
- 保证数据一致性（不能引用不存在的部门）
- 级联操作（删部门时自动处理相关员工）

> **小白问**：外键听着好复杂，一定要用吗？
> 不一定。很多互联网公司（尤其高并发场景）反而**不用外键**，而是在应用层保证一致性，因为外键会影响写入性能。作为初学者，先理解概念，实际项目里根据情况决定。第 12 章会详细讲。

## 3.3 表的"关系"：一对一、一对多、多对多

表之间的关联有三种基本类型：

### 一对一（1:1）

一个员工对应一个身份证。

```
employees(员工)  ←→  id_cards(身份证)
```

实现方式：在任意一张表加唯一外键。

### 一对多（1:N）

一个部门有多个员工，一个员工属于一个部门。这是最常见的。

```
departments(部门)  →  employees(员工)
```

实现方式：在"多"的一方（员工表）加外键指向"一"的一方（部门表）。

### 多对多（M:N）

一个员工可以参与多个项目，一个项目有多个员工。

```
employees(员工)  ←→  projects(项目)
```

实现方式：加一张**中间表**（也叫连接表）：

```sql
CREATE TABLE emp_project (
    emp_id INT,
    proj_id INT,
    PRIMARY KEY (emp_id, proj_id),
    FOREIGN KEY (emp_id) REFERENCES employees(emp_id),
    FOREIGN KEY (proj_id) REFERENCES projects(proj_id)
);
```

中间表把多对多拆成两个一对多。这是数据库设计的经典技巧。

## 3.4 SQL 语言的四大分类

SQL（Structured Query Language，结构化查询语言）按功能分四类：

| 分类 | 英文 | 作用 | 主要语句 |
|------|------|------|---------|
| DDL | Data Definition Language | 定义结构 | CREATE / ALTER / DROP |
| DML | Data Manipulation Language | 操作数据 | INSERT / UPDATE / DELETE |
| DQL | Data Query Language | 查询数据 | SELECT |
| DCL | Data Control Language | 控制权限 | GRANT / REVOKE |

还有一类常被单独提：**TCL（Transaction Control Language）事务控制**，包括 COMMIT / ROLLBACK。

这套教程的安排：

- 第二卷（4–10 章）讲 DDL / DML / DQL
- 第四卷（18 章）讲 DCL
- 第三卷（16 章）讲 TCL

> **小白问**：DQL 算不算 DML？
> 严格说 SELECT 是 DQL，但很多资料把它归进 DML（因为它操作数据）。不用纠结分类，知道每条语句干嘛就行。

## 3.5 客户端-服务器架构

MySQL 是典型的 **C/S（客户端-服务器）架构**：

```
你的程序（客户端）  ──SQL──▶  MySQL 服务器（mysqld）
   mysql 命令行               ├─ 连接管理
   Workbench                  ├─ 查询解析
   Python/C++/Go 程序         ├─ 执行引擎
                              └─ 存储引擎（InnoDB 等）
```

- **服务器端**：`mysqld` 是真正的数据库进程，负责存数据、执行 SQL。
- **客户端**：你用的命令行、`mysql` 命令、图形工具、程序里的驱动，都是客户端。它们把 SQL 发给服务器，拿回结果。

理解这点很重要：

1. MySQL 服务可以跑在另一台机器上，程序通过网络连它
2. 多个客户端可以同时连同一个服务器
3. 权限、连接数、网络超时都是服务器层面的配置

> **小白问**：我装的 MySQL 既是客户端又是服务器？
> 对，官方安装包把两者都装了。`mysql` 命令是客户端，`mysqld` 是服务器。Docker 装的通常只是服务器，客户端用宿主机的或容器里的都行。

## 3.6 存储引擎：InnoDB

MySQL 有个独特的概念——**存储引擎**。表用什么引擎存储数据，行为差别很大。

| 引擎 | 特点 | 用途 |
|------|------|------|
| InnoDB | 支持事务、行级锁、外键 | ✅ 默认，绝大多数场景 |
| MyISAM | 不支持事务、表级锁、快 | 只读场景，逐渐淘汰 |
| MEMORY | 数据存内存，极快，断电丢失 | 临时表、缓存 |
| ARCHIVE | 高压缩，只支持插入查询 | 归档日志 |

**本教程默认用 InnoDB**。它是 MySQL 5.5 之后的默认引擎，支持事务和行级锁，是安全可靠的选择。第 16、17 章讲事务和锁时，都是基于 InnoDB。

查看当前默认引擎：

```sql
SHOW ENGINES;
```

## 3.7 本章总结

| 概念 | 核心要点 |
|------|---------|
| 数据库 | 表的容器；一个实例可有多个库 |
| 表 | 行列的二维结构；有固定列、可变行 |
| 行 | 一条记录 |
| 列 | 一个字段，有名字和类型 |
| 主键 | 唯一标识一行；非空、唯一、单表一个 |
| 外键 | 引用另一表主键；建立表关联 |
| 表关系 | 一对一、一对多（外键在多的一方）、多对多（中间表） |
| SQL 分类 | DDL 定义、DML 操作、DQL 查询、DCL 控制、TCL 事务 |
| 架构 | C/S 架构；mysqld 是服务器，mysql 命令是客户端 |
| 存储引擎 | InnoDB 默认，支持事务和行锁 |
