# 第 1 章 为什么学 MySQL（AI + 安全的视角）

## 本章目标

读完这一章，你将能够：

- 用大白话说清楚"数据库"到底是什么，为什么不用 Excel 或文本文件
- 理解 MySQL 在 AI + 网络安全里的位置
- 知道学 MySQL 要学哪些东西，形成整体认知
- 建立起"数据是资产，数据库是底座"的思维

## 1.1 从一个真实问题说起

假设你在做一个安全项目：**记录服务器上的所有登录尝试**，然后分析哪些 IP 在暴力破解。

一开始你用文本文件记：

```
2026-01-01 10:00:01, 192.168.1.10, admin, SUCCESS
2026-01-01 10:00:05, 192.168.1.10, admin, FAILED
2026-01-01 10:00:09, 45.33.22.11, root, FAILED
...
```

跑了一天，文件有 10 万行。现在你想知道：

> "过去 24 小时里，哪些 IP 登录失败超过 50 次？按失败次数从高到低排。"

用文本文件和 Python 怎么写？你得读整个文件、逐行解析、用字典统计、再排序。代码几十行，而且每次查询都要重新读一遍文件。数据涨到 1000 万行时，光读文件就要几分钟。

如果你用 MySQL，这个问题就是一条语句：

```sql
SELECT ip, COUNT(*) AS fail_count
FROM login_logs
WHERE result = 'FAILED' AND login_time >= NOW() - INTERVAL 1 DAY
GROUP BY ip
HAVING fail_count > 50
ORDER BY fail_count DESC;
```

一行 SQL，秒级返回。这就是数据库的价值：**把"怎么查"交给数据库，你只说"查什么"**。

> **小白问**：SQL 是不是很难？
> 完全不是。SQL 是声明式语言——你描述"要什么"，机器决定"怎么拿"。上面那句几乎就是英语。真正难的是后面的设计、优化、安全，但那些都有规律，一步步来。

## 1.2 数据库到底是什么

**数据库（Database）** 就是"有组织的数据集合"。类比一下：

| 概念 | 生活类比 | 说明 |
|------|---------|------|
| 数据库 | 一个文件柜 | 存放相关数据的集合 |
| 表（Table） | 文件柜里的一个抽屉 | 一类数据的集合，如"登录日志" |
| 行（Row） | 抽屉里的一张卡片 | 一条记录，如一次登录 |
| 列（Column） | 卡片上的一个字段 | 一个属性，如 IP、时间、结果 |
| 主键（Primary Key） | 卡片的编号 | 唯一标识一条记录 |

数据库和文本文件的本质区别：

1. **结构化**：每一列有明确的类型（IP 是字符串、时间是日期、次数是整数）
2. **可查询**：用 SQL 精确描述要什么数据
3. **可索引**：像书的目录，不用从头翻到尾
4. **并发安全**：多个人同时读写不会乱
5. **完整性**：可以强制"每条日志必须有 IP 和时间"

## 1.3 为什么是 MySQL

数据库有很多：MySQL、PostgreSQL、Oracle、SQL Server、SQLite、MongoDB……

为什么 AI + 安全领域 MySQL 最常见？

**1. 免费开源**

MySQL 是开源软件，个人和企业都能免费用。做安全研究、搭靶场、写实验项目，不用花一分钱。

**2. 生态成熟**

全球无数系统在用，教程、文档、工具、社区资源极其丰富。遇到问题，搜一下基本都有答案。

**3. 性能可靠**

支撑着全世界大量高并发网站。对安全日志这种"写多读多"的场景完全够用。

**4. 和编程语言配合好**

Python、C/C++、Rust、Go 都有成熟的 MySQL 驱动。我们第六卷会逐一讲。

**5. 安全教学的标准靶场**

DVWA、sqli-labs 这些经典 Web 安全靶场，底层几乎都是 MySQL。学 SQL 注入，绕不开 MySQL。

> **小白问**：PostgreSQL 是不是更好？
> 各有千秋。PostgreSQL 功能更强（支持更复杂的数据类型、JSON、全文检索），MySQL 更轻量、普及度更高。先学 MySQL，打好 SQL 基础，将来切 PostgreSQL 很容易——SQL 是通用的。

## 1.4 MySQL 在 AI + 网络安全里的 6 个典型场景

### 场景 1：安全日志存储与分析

```sql
-- 建一张登录日志表
CREATE TABLE login_logs (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    ip VARCHAR(64) NOT NULL,
    username VARCHAR(64),
    login_time DATETIME NOT NULL,
    result ENUM('SUCCESS', 'FAILED') NOT NULL
);
```

然后每秒几千条日志写进来，随时统计分析。这是 SOC（安全运营中心）的基础。

### 场景 2：威胁情报库

存储恶意 IP、恶意域名、攻击特征：

```sql
CREATE TABLE threat_intel (
    id INT AUTO_INCREMENT PRIMARY KEY,
    indicator VARCHAR(255) NOT NULL,   -- 特征，如 IP 或域名
    type ENUM('IP', 'DOMAIN', 'HASH', 'URL') NOT NULL,
    severity TINYINT NOT NULL,          -- 严重等级 1-5
    source VARCHAR(64),
    updated_at DATETIME NOT NULL
);
```

查询时，把流量里的 IP 拿去这个表里比对，命中就是威胁。

### 场景 3：用户与权限系统

堡垒机、扫描平台、AI 服务后台，都需要用户登录、角色权限。这些存在 MySQL 里，配合权限表做访问控制。第 18 章会详细讲。

### 场景 4：AI 数据管道

训练一个恶意软件检测模型，需要存：

- 样本特征向量
- 标注结果（恶意/正常）
- 模型版本、训练参数、评估指标
- 实验记录

这些都落在 MySQL，方便追踪和复现实验。第 30 章专门讲。

### 场景 5：向量检索的元数据

现在大模型应用常用向量数据库，但向量的**元数据**（文本、来源、时间、标签）往往还是存在 MySQL。检索时先向量召回，再回 MySQL 取详情。

### 场景 6：SQL 注入攻防

这是 Web 安全的头号漏洞。想防御 SQL 注入，必须深刻理解 SQL 是怎么被拼接、怎么被篡改的。第 19 章会用专门的靶场讲清楚原理、利用和防御。

## 1.5 这套教程会教你什么

我们把学习 MySQL 拆成三层：

```
第一层：会用（SQL 语言）
  ├─ 建库建表、增删改查
  ├─ 条件、排序、分组、联表、子查询
  └─ 能写出"找出异常登录 IP"这样的查询

第二层：会设计（原理与高级特性）
  ├─ 数据类型、约束、范式
  ├─ 索引、事务、锁
  └─ 视图、存储过程、触发器

第三层：会守会管（安全与运维）
  ├─ 用户权限、SQL 注入防御、安全加固、审计
  ├─ 执行计划、备份恢复、主从复制、监控调优
  └─ 多语言集成、AI 系统落地
```

**学习心法**：先会写 SQL 跑通，再理解原理，最后补安全和运维。不要一开始就啃 B+ 树和事务隔离级别——先跑起来，看到结果，再回头理解，记得最牢。
