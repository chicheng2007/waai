# 第 11 章 数据类型详解

## 本章目标

读完这一章，你将能够：

- 掌握 MySQL 三大类数据类型：数值、字符串、日期时间
- 理解 ENUM、SET、JSON 等特殊类型
- 知道怎么为字段选合适的数据类型
- 理解数据类型的选择对性能和安全的影响

---

## 11.1 为什么数据类型很重要

选错数据类型会怎样？

- `ip VARCHAR(15)`：IPv6 地址存不下（最长 39 字符）
- `port TINYINT`：端口 65535 存不下（TINYINT 最大 127/255）
- `score FLOAT`：金额计算精度丢失（0.1 + 0.2 ≠ 0.3）
- `created_at VARCHAR(30)`：没法做时间比较和计算

数据类型的选择影响：**存储空间、查询性能、数据正确性、安全**。这一章讲清楚。

---

## 11.2 数值类型

### 整数类型

| 类型 | 字节 | 有符号范围 | 无符号范围 | 典型用途 |
|------|------|-----------|-----------|---------|
| TINYINT | 1 | -128~127 | 0~255 | 状态码、等级（1-5） |
| SMALLINT | 2 | -32768~32767 | 0~65535 | 端口号 |
| MEDIUMINT | 3 | ±800万 | 0~1600万 | 中等计数 |
| INT | 4 | ±21亿 | 0~42亿 | ID、数量（最常用） |
| BIGINT | 8 | ±9e18 | 0~1.8e19 | 大 ID、时间戳（毫秒） |

**关键决策：**

1. **够用就行**：端口号用 SMALLINT UNSIGNED（0-65535 刚好），别用 INT 浪费空间。
2. **无符号加 UNSIGNED**：ID、端口、数量不会是负数，加 UNSIGNED 能多用一倍范围。
3. **主键用 BIGINT**：数据量可能很大时，INT 会溢出。日志表主键推荐 `BIGINT UNSIGNED`。

```sql
CREATE TABLE example_types (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    port SMALLINT UNSIGNED NOT NULL,
    severity TINYINT UNSIGNED NOT NULL DEFAULT 1,
    status TINYINT NOT NULL DEFAULT 0
);
```

### 显示宽度（已废弃）

老教程里会写 `INT(11)`，括号里的 11 是"显示宽度"，MySQL 8.0 已废弃，没实际意义。直接写 `INT` 即可。

### 小数类型

| 类型 | 说明 | 用途 |
|------|------|------|
| DECIMAL(M,D) | 精确小数，字符串存储 | ✅ 金额、评分等需要精确的 |
| FLOAT | 单精度浮点，约 7 位有效数字 | 科学计算 |
| DOUBLE | 双精度浮点，约 15 位有效数字 | 科学计算 |

**重要：金额、精确计算必须用 DECIMAL！**

```sql
CREATE TABLE payments (
    id INT AUTO_INCREMENT PRIMARY KEY,
    amount DECIMAL(10, 2) NOT NULL COMMENT '金额，10位数字含2位小数'
);
```

`DECIMAL(10,2)` 能存到 99999999.99。FLOAT/DOUBLE 是二进制浮点，有精度误差——金融系统用 FLOAT 是要出事故的。

> **小白问**：FLOAT 的精度误差到底多大？
> 试试 `SELECT 0.1 + 0.2 = 0.3;`——结果是 0（false）！因为 0.1 和 0.2 在二进制里是无限循环小数。DECIMAL 用字符串存，没这个问题。

### 位类型

`BIT(M)` 存二进制位，M 是位数（1-64）。存布尔值、标志位时用。但用得少，通常用 TINYINT(1) 代替。

## 11.3 字符串类型

### CHAR vs VARCHAR

| 类型 | 特点 | 用途 |
|------|------|------|
| CHAR(n) | 固定长度，总是占 n 个字符 | 定长数据：MD5(32)、状态码(2) |
| VARCHAR(n) | 可变长度，按实际长度+1字节 | 变长数据：用户名、IP、URL |

```sql
CREATE TABLE string_example (
    md5 CHAR(32) NOT NULL COMMENT 'MD5 固定32位',
    ip VARCHAR(64) NOT NULL COMMENT 'IP 变长，兼容IPv6',
    username VARCHAR(64) NOT NULL
);
```

**选择原则**：

- 长度固定 → CHAR（快，无长度开销）
- 长度变化 → VARCHAR（省空间）
- IPv4 用 VARCHAR(15) 够，但要兼容 IPv6 得 VARCHAR(39) 或更大

> **小白问**：VARCHAR(64) 里的 64 是字节还是字符？
> MySQL 8.0 里是**字符**（utf8mb4 下一个字符最多 4 字节）。老版本（5.0 之前）是字节。所以 VARCHAR(64) 能存 64 个汉字。

### TEXT 系列

存大文本：

| 类型 | 最大长度 | 用途 |
|------|---------|------|
| TINYTEXT | 255 字节 | 短文本 |
| TEXT | 64 KB | 一般长文本 |
| MEDIUMTEXT | 16 MB | 长文本 |
| LONGTEXT | 4 GB | 超长文本 |

存漏洞详情、HTTP 响应体、日志内容用 TEXT。

> **注意**：TEXT 列不能有默认值，且不能作为普通索引的完整列（只能前缀索引）。查询大 TEXT 会消耗内存，能不用尽量不用。

### BLOB 系列

存二进制数据：TINYBLOB / BLOB / MEDIUMBLOB / LONGBLOB。

存文件、图片、序列化数据。但**一般不推荐把文件存数据库**——存文件路径更好，文件放对象存储（如 MinIO、S3）。

### ENUM 枚举

```sql
severity ENUM('INFO', 'LOW', 'MEDIUM', 'HIGH', 'CRITICAL') NOT NULL DEFAULT 'INFO'
```

优点：

- 限制取值范围，防脏数据
- 内部用数字存储，省空间
- 排序按定义顺序（方便按严重级别排）

缺点：

- 改枚举值要 ALTER TABLE
- 移植性差

适合：状态、级别、类型等固定选项。

### SET 集合

```sql
permissions SET('READ', 'WRITE', 'EXECUTE', 'DELETE')
```

可以存多个值的组合（ENUM 只能存一个）。用得不多，权限系统更常用关联表。

## 11.4 日期时间类型

| 类型 | 格式 | 范围 | 用途 |
|------|------|------|------|
| DATETIME | '2026-01-15 10:30:00' | 1000-9999 年 | ✅ 推荐，常用 |
| TIMESTAMP | '2026-01-15 10:30:00' | 1970-2038 年 | 自动时区转换 |
| DATE | '2026-01-15' | 1000-9999 年 | 只要日期 |
| TIME | '10:30:00' | -838:59:59 ~ 838:59:59 | 只要时间 |
| YEAR | 2026 | 1901-2155 | 只要年份 |

### DATETIME vs TIMESTAMP

| 对比 | DATETIME | TIMESTAMP |
|------|----------|-----------|
| 范围 | 1000-9999 年 | 1970-2038 年（有 2038 问题） |
| 时区 | 存什么显示什么 | 存 UTC，按会话时区显示 |
| 自动更新 | 需显式设置 | 可自动初始化/更新 |

**推荐用 DATETIME**：范围大、无时区坑、无 2038 问题。需要跨时区时用 TIMESTAMP 或存 UTC 时间戳。

```sql
CREATE TABLE time_example (
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    event_date DATE,
    duration TIME
);
```

### 时间戳的坑

用 INT/BIGINT 存 Unix 时间戳（秒/毫秒）也有人用：

```sql
event_ts BIGINT COMMENT '毫秒时间戳'
```

优点：跨语言方便、比较快。缺点：可读性差，SQL 里要转换（`FROM_UNIXTIME(event_ts/1000)`）。

## 11.5 JSON 类型（MySQL 5.7+）

MySQL 支持原生 JSON 类型：

```sql
CREATE TABLE threat_intel_extended (
    id INT AUTO_INCREMENT PRIMARY KEY,
    indicator VARCHAR(255) NOT NULL,
    extra JSON COMMENT '扩展信息，结构化但不固定'
);

INSERT INTO threat_intel_extended (indicator, extra) VALUES
('45.33.22.11', '{"country": "US", "asn": "AS14061", "tags": ["scanner", "botnet"]}');
```

查询 JSON：

```sql
-- 取字段
SELECT indicator, extra->>'$.country' AS country
FROM threat_intel_extended;

-- 按 JSON 字段过滤
SELECT * FROM threat_intel_extended
WHERE extra->>'$.country' = 'US';

-- 判断 JSON 里是否有某键
SELECT * FROM threat_intel_extended
WHERE JSON_CONTAINS_PATH(extra, 'one', '$.tags');
```

JSON 类型的适用场景：**半结构化数据**——字段不固定、经常变化、需要存嵌套结构。威胁情报的扩展字段、扫描结果的可变详情都适合。

JSON vs TEXT 存 JSON 字符串：JSON 类型会自动校验格式、支持函数查询、可建函数索引。优先用 JSON 类型。

## 11.6 二进制与布尔

MySQL 没有真正的 BOOLEAN 类型，`BOOLEAN` 是 `TINYINT(1)` 的别名：

```sql
is_active BOOLEAN NOT NULL DEFAULT TRUE  -- 实际是 TINYINT(1)
```

存 0/1，查询时也用 0/1。`TRUE` = 1，`FALSE` = 0。

## 11.7 数据类型选择的实战原则

### 原则 1：最小够用

能用 TINYINT 不用 INT，能用 VARCHAR(64) 不用 VARCHAR(255)。省空间就是省 IO、省内存。

### 原则 2：精确用 DECIMAL

金额、评分、任何需要精确的小数，用 DECIMAL。

### 原则 3：时间用 DATETIME

避免 TIMESTAMP 的 2038 问题和时区坑。

### 原则 4：有限选项用 ENUM

状态、级别、类型，用 ENUM 约束取值。

### 原则 5：可变结构用 JSON

字段不固定的扩展信息，用 JSON。

### 原则 6：注意字符集

字符串列跟随表字符集 utf8mb4。特殊场景（如存二进制 hash）用 BINARY/VARBINARY 或 HEX 字符串。

## 11.8 一个设计良好的安全表

综合应用：

```sql
CREATE TABLE security_events (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY COMMENT '事件ID',
    event_type ENUM('LOGIN_FAIL', 'PORT_SCAN', 'SQL_INJECT', 'MALWARE') NOT NULL COMMENT '事件类型',
    severity TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '严重级别1-5',
    source_ip VARCHAR(64) NOT NULL COMMENT '来源IP，兼容IPv6',
    target_port SMALLINT UNSIGNED COMMENT '目标端口',
    confidence DECIMAL(4,3) COMMENT '置信度0.000-1.000',
    raw_data JSON COMMENT '原始事件数据',
    is_blocked BOOLEAN NOT NULL DEFAULT FALSE COMMENT '是否已阻断',
    occurred_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '发生时间'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='安全事件表';
```

每一列的类型都经过斟酌：BIGINT 主键、ENUM 类型、TINYINT 级别、VARCHAR 兼容 IPv6、SMALLINT 端口、DECIMAL 置信度、JSON 扩展、BOOLEAN 标志、DATETIME 时间。这就是专业的表设计。

## 11.9 本章总结

| 类型分类 | 关键类型 | 要点 |
|---------|---------|------|
| 整数 | TINYINT/SMALLINT/INT/BIGINT | 够用就行；ID 用 BIGINT UNSIGNED |
| 小数 | DECIMAL/FLOAT/DOUBLE | 精确计算用 DECIMAL |
| 字符串 | CHAR/VARCHAR/TEXT | 定长 CHAR、变长 VARCHAR、长文 TEXT |
| 枚举 | ENUM/SET | 有限选项用 ENUM |
| 日期 | DATETIME/TIMESTAMP/DATE/TIME | 推荐 DATETIME |
| JSON | JSON | 半结构化数据；支持函数查询 |
| 布尔 | BOOLEAN (=TINYINT(1)) | 存 0/1 |
| 设计原则 | 最小够用、精确 DECIMAL、时间 DATETIME、选项 ENUM、可变 JSON | |
