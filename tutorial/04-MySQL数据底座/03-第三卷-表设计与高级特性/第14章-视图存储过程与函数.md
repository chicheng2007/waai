# 第 14 章 视图、存储过程与函数

## 14.1 视图（View）：保存的查询

**视图**是一张"虚拟表"——它本身不存数据，而是保存一条 SELECT 查询。你查视图，等于执行那条查询。

```sql
CREATE VIEW v_high_risk AS
SELECT
    id, host, port, severity, found_at
FROM scan_results
WHERE severity IN ('HIGH', 'CRITICAL');
```

之后要查高危漏洞，直接：

```sql
SELECT * FROM v_high_risk;
```

不用每次都写一遍 WHERE 条件。视图把复杂查询"封装"起来了。

### 视图的价值

1. **简化复杂查询**：把多表 JOIN、复杂 WHERE 封装成一张"表"
2. **统一逻辑**：所有人查同一视图，口径一致
3. **权限控制**：只给用户看视图，不给他看原表（隐藏敏感列）
4. **逻辑独立**：表结构变化时，改视图定义即可，不影响用视图的程序

安全场景示例：给分析员一个视图，只看脱敏后的数据：

```sql
CREATE VIEW v_login_public AS
SELECT
    id,
    CONCAT(LEFT(ip, 8), '***') AS ip_masked,  -- IP 脱敏
    username,
    login_time,
    result
FROM login_logs;
```

分析员查视图，看不到完整 IP——数据脱敏。

### 管理视图

```sql
SHOW CREATE VIEW v_high_risk;   -- 查看定义
DROP VIEW v_high_risk;          -- 删除
CREATE OR REPLACE VIEW v_high_risk AS ...;  -- 修改（替换）
```

### 视图的限制

- 视图一般**不可更新**（尤其是含聚合、DISTINCT、GROUP BY、JOIN 的）
- 简单视图（单表、无计算）可以更新，但会写回基表
- 视图依赖基表，基表删了视图就失效
- 视图本身不提升性能（它只是保存查询，不是缓存）

> **小白问**：视图是不是把查询结果存起来，所以查得快？
> 不是。普通视图只是保存 SQL 定义，每次查都重新执行。MySQL 没有"物化视图"（某些数据库有）。所以视图是为了简化逻辑，不是为了加速。

## 14.2 存储过程（Stored Procedure）

**存储过程**是一组预编译的 SQL 语句，保存在数据库里，可以像函数一样调用。

### 基本语法

```sql
DELIMITER $$

CREATE PROCEDURE sp_count_vulns()
BEGIN
    SELECT COUNT(*) AS total FROM scan_results;
END$$

DELIMITER ;
```

调用：

```sql
CALL sp_count_vulns();
```

**DELIMITER 解释**：MySQL 默认用分号 `;` 作为语句结束符。但存储过程内部也有分号，会和外部冲突。所以先用 `DELIMITER $$` 把结束符改成 `$$`，存储过程体里的分号就不会提前结束定义，最后用 `END$$` 结束，再改回 `;`。

### 带参数的存储过程

```sql
DELIMITER $$

CREATE PROCEDURE sp_get_host_vulns(IN host_ip VARCHAR(64))
BEGIN
    SELECT port, severity, found_at
    FROM scan_results
    WHERE host = host_ip
    ORDER BY found_at DESC;
END$$

DELIMITER ;
```

调用：

```sql
CALL sp_get_host_vulns('192.168.1.10');
```

参数类型：

- `IN`：输入参数（默认）
- `OUT`：输出参数
- `INOUT`：既可输入也可输出

### 带 OUT 参数的例子

```sql
DELIMITER $$

CREATE PROCEDURE sp_count_by_severity(
    IN sev VARCHAR(16),
    OUT cnt INT
)
BEGIN
    SELECT COUNT(*) INTO cnt FROM scan_results WHERE severity = sev;
END$$

DELIMITER ;

-- 调用
CALL sp_count_by_severity('HIGH', @n);
SELECT @n;
```

`@n` 是用户变量，接收 OUT 参数的值。

### 存储过程的优缺点

**优点**：

- 封装复杂逻辑，应用调用简单
- 减少网络传输（逻辑在数据库端执行）
- 可复用、集中管理

**缺点**：

- 调试困难
- 移植性差（各数据库语法不同）
- 增加数据库服务器负担
- 版本管理不方便（不像代码在 Git 里）

> **现代实践**：很多互联网公司**不用存储过程**，把逻辑放应用层（更容易测试、版本控制、扩展）。但老系统里存储过程很常见，读懂很重要。学习阶段了解即可。

## 14.3 存储函数（Function）

存储函数和存储过程类似，但**必须返回一个值**，且可以在 SQL 语句里直接调用。

```sql
DELIMITER $$

CREATE FUNCTION fn_risk_score(sev VARCHAR(16))
RETURNS INT
DETERMINISTIC
BEGIN
    DECLARE score INT;
    CASE sev
        WHEN 'CRITICAL' THEN SET score = 5;
        WHEN 'HIGH' THEN SET score = 4;
        WHEN 'MEDIUM' THEN SET score = 3;
        WHEN 'LOW' THEN SET score = 2;
        ELSE SET score = 1;
    END CASE;
    RETURN score;
END$$

DELIMITER ;
```

在 SQL 里调用：

```sql
SELECT host, port, fn_risk_score(severity) AS risk
FROM scan_results;
```

**注意**：

- `RETURNS INT` 声明返回类型
- `DETERMINISTIC` 表示相同输入总是相同输出（MySQL 要求声明，否则可能拒绝创建）
- 函数里不能返回结果集（不能 SELECT 返回多行），只能返回一个值

### 内置函数 vs 自定义函数

MySQL 有大量内置函数，常用的：

- 字符串：CONCAT、LEFT、RIGHT、SUBSTRING、UPPER、LOWER、REPLACE
- 数学：ROUND、ABS、CEIL、FLOOR、RAND
- 日期：NOW、DATE、DATEDIFF、DATE_ADD、UNIX_TIMESTAMP
- 条件：IF、IFNULL、COALESCE、CASE

这些前面章节都用过。自定义函数是补充。

## 14.4 变量与流程控制

### 变量

```sql
DECLARE var_name INT DEFAULT 0;    -- 局部变量（在 BEGIN...END 里）
SET var_name = 10;
SELECT COUNT(*) INTO var_name FROM scan_results;  -- 查询结果赋值给变量
```

用户变量（会话级，用 @ 开头）：

```sql
SET @my_var = 100;
SELECT @my_var;
```

### IF 语句

```sql
IF condition THEN
    statements;
ELSEIF condition2 THEN
    statements;
ELSE
    statements;
END IF;
```

示例：

```sql
CREATE PROCEDURE sp_threat_level(IN cnt INT, OUT level VARCHAR(16))
BEGIN
    IF cnt >= 100 THEN
        SET level = '严重';
    ELSEIF cnt >= 50 THEN
        SET level = '高危';
    ELSEIF cnt >= 10 THEN
        SET level = '中危';
    ELSE
        SET level = '低危';
    END IF;
END
```

### CASE 语句

```sql
CASE expression
    WHEN value1 THEN statements;
    WHEN value2 THEN statements;
    ELSE statements;
END CASE;
```

### 循环：WHILE / LOOP / REPEAT

```sql
-- WHILE
WHILE i < 10 DO
    SET i = i + 1;
END WHILE;

-- REPEAT（类似 do-while）
REPEAT
    SET i = i + 1;
UNTIL i >= 10 END REPEAT;

-- LOOP + LEAVE（跳出）
loop_label: LOOP
    SET i = i + 1;
    IF i >= 10 THEN
        LEAVE loop_label;
    END IF;
END LOOP loop_label;
```

## 14.5 错误处理（DECLARE ... HANDLER）

存储过程中可以捕获错误：

```sql
DECLARE CONTINUE HANDLER FOR SQLEXCEPTION
BEGIN
    -- 出错时执行的处理
    SELECT '发生错误' AS msg;
END;
```

或者回滚事务：

```sql
DECLARE EXIT HANDLER FOR SQLEXCEPTION
BEGIN
    ROLLBACK;
    RESIGNAL;  -- 重新抛出错误
END;
```

这让存储过程更健壮——出错时能优雅处理，而不是直接崩。

## 14.6 完整案例：安全统计存储过程

```sql
DELIMITER $$

CREATE PROCEDURE sp_security_report(IN days INT)
BEGIN
    -- 声明变量
    DECLARE total_events INT DEFAULT 0;
    DECLARE critical_count INT DEFAULT 0;

    -- 统计
    SELECT COUNT(*) INTO total_events
    FROM security_events
    WHERE occurred_at >= NOW() - INTERVAL days DAY;

    SELECT COUNT(*) INTO critical_count
    FROM security_events
    WHERE occurred_at >= NOW() - INTERVAL days DAY
      AND severity = 5;

    -- 输出结果
    SELECT total_events AS '事件总数',
           critical_count AS '严重事件数',
           days AS '统计天数';
END$$

DELIMITER ;
```

调用：

```sql
CALL sp_security_report(7);  -- 最近 7 天的安全报告
```

## 14.7 本章总结

| 知识点 | 内容 |
|--------|------|
| 视图 | 保存的 SELECT；虚拟表，不存数据；简化查询、权限控制、脱敏 |
| 视图限制 | 多不可更新；不提升性能；依赖基表 |
| 存储过程 | 一组 SQL；CALL 调用；IN/OUT/INOUT 参数 |
| DELIMITER | 改结束符，解决过程体内分号冲突 |
| 存储函数 | 必须返回值；可在 SQL 中调用；DETERMINISTIC |
| 变量 | DECLARE 局部；SET 赋值；SELECT INTO；@用户变量 |
| 流程控制 | IF / CASE / WHILE / REPEAT / LOOP |
| 错误处理 | DECLARE HANDLER 捕获 SQLEXCEPTION |
| 现代实践 | 互联网公司多把逻辑放应用层，存储过程了解即可 |
