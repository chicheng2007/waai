# 第 12 章 约束：主键、外键、唯一、非空、检查

## 本章目标

读完这一章，你将能够：

- 理解约束的作用——保证数据正确性
- 掌握六大约束：NOT NULL、DEFAULT、PRIMARY KEY、UNIQUE、FOREIGN KEY、CHECK
- 理解外键的级联操作（CASCADE / RESTRICT / SET NULL）
- 知道什么时候该用约束、什么时候在应用层控制

---

## 12.1 约束是什么，为什么需要

**约束（Constraint）** 是加在表上的规则，数据库会自动强制执行。违反规则的操作会被拒绝。

比如：

- "每条日志必须有 IP" → NOT NULL 约束
- "IP 不能重复" → UNIQUE 约束
- "严重级别只能是 1-5" → CHECK 约束
- "结果的 task_id 必须对应存在的任务" → FOREIGN KEY 约束

约束的价值：

1. **数据正确性**：脏数据在数据库层就被挡住
2. **减少应用代码**：不用每个程序都写一遍校验
3. **统一规则**：不管 Python、Go 还是手工操作，规则都生效

> **小白问**：在代码里校验不行吗？
> 可以，但数据库约束是"最后一道防线"。代码可能有 bug、有人会直接用客户端改数据、多个程序可能规则不一致。数据库约束兜底，最可靠。

## 12.2 NOT NULL（非空约束）

```sql
CREATE TABLE hosts (
    id INT AUTO_INCREMENT PRIMARY KEY,
    ip VARCHAR(64) NOT NULL COMMENT 'IP 必须有',
    os VARCHAR(64) COMMENT '操作系统可为空'
);
```

`NOT NULL` 保证这一列必须有值。插入时不给值会报错：

```sql
INSERT INTO hosts (os) VALUES ('Ubuntu');  -- 报错：ip 没有默认值
```

**原则**：业务上必须有的字段，一律 NOT NULL。能空的才允许 NULL。NULL 会带来很多麻烦（比较要用 IS NULL、索引效果差、NOT IN 陷阱）。

---

## 12.3 DEFAULT（默认值）

```sql
status VARCHAR(16) NOT NULL DEFAULT 'UP',
priority TINYINT NOT NULL DEFAULT 5,
created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
```

插入时不提供这些列，就用默认值。

> **注意**：如果列是 NOT NULL 又没有 DEFAULT，插入时必须提供值。所以 NOT NULL 通常配 DEFAULT。

---

## 12.4 PRIMARY KEY（主键约束）

主键 = NOT NULL + UNIQUE，唯一标识一行。

```sql
-- 单列主键
id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY

-- 联合主键（多列组合唯一）
CREATE TABLE emp_project (
    emp_id INT,
    proj_id INT,
    PRIMARY KEY (emp_id, proj_id)
);
```

主键的特点：

- 唯一、非空
- 一张表只能有一个主键（但可以是联合主键）
- InnoDB 里主键就是聚簇索引——数据按主键顺序存储（第 13 章讲）

**主键设计原则**：

1. 用代理主键（AUTO_INCREMENT 的 id），别用业务字段（IP、用户名可能变）
2. 用 BIGINT UNSIGNED，别用 INT（防溢出）
3. 尽量短、单调递增（对索引友好）

---

## 12.5 UNIQUE（唯一约束）

唯一约束保证列的值不重复（允许多个 NULL）。

```sql
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(64) NOT NULL UNIQUE COMMENT '用户名唯一',
    email VARCHAR(128) UNIQUE COMMENT '邮箱唯一'
);
```

插入重复值会报错：

```sql
INSERT INTO users (username) VALUES ('admin');
INSERT INTO users (username) VALUES ('admin');  -- 报错：Duplicate entry
```

### 联合唯一

```sql
CREATE TABLE login_logs (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    ip VARCHAR(64) NOT NULL,
    login_time DATETIME NOT NULL,
    UNIQUE KEY uk_ip_time (ip, login_time)
);
```

按 (ip, login_time) 组合去重。

### UNIQUE 与主键的区别

| 对比 | PRIMARY KEY | UNIQUE |
|------|-------------|--------|
| 唯一性 | ✅ | ✅ |
| 非空 | ✅ 必须 | ❌ 允许 NULL |
| 数量 | 每表一个 | 可多个 |
| 聚簇索引 | InnoDB 中是 | 不是 |

## 12.6 FOREIGN KEY（外键约束）

外键保证"引用的值必须存在"。

```sql
CREATE TABLE scan_results (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    task_id BIGINT UNSIGNED NOT NULL,
    host VARCHAR(255) NOT NULL,
    FOREIGN KEY (task_id) REFERENCES scan_tasks(id)
);
```

现在插入一个不存在的 task_id 会报错：

```sql
INSERT INTO scan_results (task_id, host) VALUES (999, '1.1.1.1');
-- 报错：Cannot add or update a child row: a foreign key constraint fails
```

这就是外键的保护作用——防止孤儿记录。

### 外键的 Cascading 操作

当父表记录被删除或更新时，子表怎么办？

```sql
FOREIGN KEY (task_id) REFERENCES scan_tasks(id)
    ON DELETE CASCADE
    ON UPDATE CASCADE
```

| 操作 | 含义 |
|------|------|
| CASCADE | 父表删除/更新，子表跟着删除/更新 |
| RESTRICT / NO ACTION | 拒绝删除/更新（默认） |
| SET NULL | 子表外键设为 NULL（要求外键列允许 NULL） |

**CASCADE 示例**：删除任务时自动删除其所有结果——方便但要小心，误删父记录会连带删掉子数据。

**RESTRICT 示例**：有结果的任务不能删除，先删结果——更安全。

> **小白问**：外键在生产环境到底用不用？
> 争议话题。优点是数据一致性由数据库保证；缺点是影响写入性能、增加死锁风险、分布式场景不好用。互联网公司常**不用外键**，在应用层保证一致性。初学者建议：理解原理，小项目可以用，大项目根据团队规范决定。

### 删除外键

```sql
ALTER TABLE scan_results DROP FOREIGN KEY 外键名;
```

外键名可以通过 `SHOW CREATE TABLE` 查看（不指定名字时 MySQL 会自动生成）。

## 12.7 CHECK（检查约束，MySQL 8.0+）

CHECK 保证列值满足条件。

```sql
CREATE TABLE security_events (
    id INT AUTO_INCREMENT PRIMARY KEY,
    severity TINYINT NOT NULL,
    port SMALLINT UNSIGNED,
    CHECK (severity BETWEEN 1 AND 5),
    CHECK (port BETWEEN 1 AND 65535)
);
```

插入 severity=9 会报错。

**注意**：MySQL 5.7 会解析但不执行 CHECK（等于没有），MySQL 8.0.16+ 才真正支持。本教程基于 8.0。

CHECK 的应用：

```sql
-- 确保结束时间晚于开始时间
CHECK (end_time > start_time)

-- 确保状态是允许的值（其实 ENUM 也能做）
CHECK (status IN ('PENDING', 'RUNNING', 'DONE'))
```

## 12.8 约束的完整示例

```sql
CREATE TABLE well_designed_logs (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY COMMENT '主键',
    ip VARCHAR(64) NOT NULL COMMENT '非空',
    username VARCHAR(64) NOT NULL DEFAULT 'unknown' COMMENT '非空+默认',
    severity TINYINT UNSIGNED NOT NULL COMMENT '非空',
    port SMALLINT UNSIGNED COMMENT '可空',
    scanner_id INT,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_unique_event (ip, username, created_at) COMMENT '唯一约束',
    CHECK (severity BETWEEN 1 AND 5) COMMENT '检查约束',
    CONSTRAINT fk_scanner FOREIGN KEY (scanner_id) REFERENCES scanners(id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

一张表用了：主键、非空、默认值、唯一、检查、外键（带 SET NULL）。这就是规范的数据库设计。

## 12.9 查看约束

```sql
SHOW CREATE TABLE well_designed_logs;  -- 看完整定义
DESC well_designed_logs;               -- 看列约束（Key 列会显示 PRI/UNI/MUL）
```

`Key` 列的含义：

- `PRI`：主键
- `UNI`：唯一索引（UNIQUE）
- `MUL`：普通索引（可能是外键）

## 12.10 约束与性能

约束不是免费的：

- 每次 INSERT/UPDATE 都要检查约束（NOT NULL、CHECK、UNIQUE、外键）
- UNIQUE 和外键需要索引
- 外键可能引入锁竞争

但为了数据正确性，这点开销通常是值得的。只有在超高并发场景，才会为了性能在应用层做校验。

**我的建议**：学习阶段和小项目——多用约束，养成好习惯。大项目——理解权衡，根据团队规范。

---

## 12.11 本章总结

| 约束 | 作用 | 要点 |
|------|------|------|
| NOT NULL | 列不能为空 | 业务必须字段都加上 |
| DEFAULT | 默认值 | 常配 NOT NULL 用 |
| PRIMARY KEY | 唯一非空标识 | 用 BIGINT UNSIGNED AUTO_INCREMENT |
| UNIQUE | 列值唯一 | 允许多个 NULL；可联合唯一 |
| FOREIGN KEY | 引用父表存在的值 | 防孤儿记录；CASCADE/RESTRICT/SET NULL |
| CHECK | 值满足条件 | MySQL 8.0.16+ 真正支持 |
| 权衡 | 正确性 vs 性能 | 小项目多用，大项目看规范 |
