# 第 23 章 备份与恢复

## 本章目标

读完这一章，你将能够：

- 理解备份的重要性与类型
- 用 mysqldump 做逻辑备份
- 用 binlog 做增量备份
- 恢复误删的数据
- 制定备份策略

---

## 23.1 为什么要备份

数据无价。以下情况都可能让数据丢失：

- 误操作（`DELETE` 忘写 WHERE、`DROP TABLE`）
- 硬件故障（磁盘损坏）
- 病毒/勒索软件
- 攻击者的破坏
- 软件 bug

**备份是最后的安全网**。没有备份，一切恢复手段都是空中楼阁。

> **真实教训**：无数公司因为没备份或备份没验证，在数据丢失后彻底崩溃。备份不难，难的是**坚持做、定期验证能恢复**。

---

## 23.2 备份的类型

| 分类维度 | 类型 | 说明 |
|---------|------|------|
| 方式 | 逻辑备份 | 导出 SQL 语句（mysqldump） |
| | 物理备份 | 复制数据文件（Percona XtraBackup） |
| 范围 | 全量备份 | 备份全部数据 |
| | 增量备份 | 只备份变化的部分 |
| 状态 | 热备份 | 不停机备份 |
| | 冷备份 | 停机备份 |

本教程重点讲 **mysqldump（逻辑备份）+ binlog（增量）** 的组合，这是最常用、最容易上手的方案。

---

## 23.3 mysqldump 逻辑备份

### 备份单个库

```bash
mysqldump -u root -p security_lab > security_lab_20260115.sql
```

### 备份多个库

```bash
mysqldump -u root -p --databases security_lab vulnscan > backup.sql
```

### 备份所有库

```bash
mysqldump -u root -p --all-databases > full_backup.sql
```

### 备份单张表

```bash
mysqldump -u root -p security_lab login_logs > login_logs.sql
```

### 常用选项

| 选项 | 作用 |
|------|------|
| `--single-transaction` | InnoDB 一致性热备份，不锁表 |
| `--routines` | 备份存储过程和函数 |
| `--triggers` | 备份触发器（默认包含） |
| `--events` | 备份事件 |
| `--master-data=2` | 记录 binlog 位置（做增量恢复用） |
| `--where='条件'` | 只备份符合条件的数据 |

推荐的完整备份命令：

```bash
mysqldump -u root -p \
  --single-transaction \
  --routines --triggers --events \
  --master-data=2 \
  --all-databases > full_backup_$(date +%Y%m%d).sql
```

`--single-transaction` 对 InnoDB 表做一致性快照，备份时不影响业务写入——生产备份必备。

## 23.4 恢复数据

### 从备份恢复

```bash
mysql -u root -p < backup.sql
```

或者在 MySQL 里：

```sql
SOURCE /path/to/backup.sql;
```

### 恢复单张表

先建空库，再导入：

```bash
mysql -u root -p security_lab < login_logs.sql
```

## 23.5 binlog 增量备份与时间点恢复

mysqldump 做的是"某一时刻"的全量备份。两次全量备份之间的数据变化，靠 binlog 记录。

### 开启 binlog

```ini
[mysqld]
log-bin=mysql-bin
server-id=1
binlog_format=ROW
```

### 时间点恢复（PITR）场景

假设：

- 每天凌晨 2 点全量备份
- 上午 10:00 有人误删了重要表
- 需要恢复到 09:59:59 的状态

步骤：

**1. 先恢复最近的全量备份**（凌晨 2 点的）：

```bash
mysql -u root -p < full_backup_20260115.sql
```

**2. 再用 binlog 重放 2 点到 9:59:59 之间的操作**：

```bash
mysqlbinlog mysql-bin.000123 \
  --start-datetime="2026-01-15 02:00:00" \
  --stop-datetime="2026-01-15 09:59:59" | mysql -u root -p
```

这样数据就恢复到误删前一秒的状态。

### 查看 binlog 内容

```bash
# 查看所有 binlog 文件
SHOW BINARY LOGS;

# 查看某个 binlog 的内容
mysqlbinlog mysql-bin.000123

# 按时间过滤
mysqlbinlog mysql-bin.000123 --start-datetime="2026-01-15 09:00:00"

# 找误删的位置
mysqlbinlog mysql-bin.000123 | grep -n "DROP TABLE"
```

### 基于 position 的恢复

比时间更精确的是 position（位置）：

```bash
mysqlbinlog mysql-bin.000123 \
  --stop-position=1234567 | mysql -u root -p
```

## 23.6 误删数据的紧急处理

发现误删后，**第一件事不是慌，是冻结操作**：

1. **立即停止应用写入**——防止新数据覆盖 binlog 中的位置
2. **不要重启数据库**（可能刷新 binlog）
3. **拷贝当前 binlog 文件**到安全位置备份
4. **用最近的备份 + binlog 恢复**
5. **恢复后验证数据完整性**

```
紧急处理清单：
□ 停应用
□ 备份当前 binlog
□ 确认误删时间点
□ 恢复全量备份
□ binlog 重放到误删前
□ 验证数据
□ 恢复应用
```

## 23.7 物理备份（了解）

**Percona XtraBackup** 是专业的物理备份工具：

```bash
# 全量备份
xtrabackup --backup --target-dir=/backup/full

# 准备（使备份可用）
xtrabackup --prepare --target-dir=/backup/full

# 恢复（停库后）
xtrabackup --copy-back --target-dir=/backup/full
```

优点：备份/恢复速度快，适合大数据库（几百 GB、TB 级）。缺点：操作复杂，需要停库恢复。

小中型项目用 mysqldump 足够，大项目考虑 XtraBackup。

## 23.8 备份策略

### 推荐的备份策略

| 层级 | 频率 | 保留 | 存储 |
|------|------|------|------|
| 全量备份 | 每天凌晨 | 7 天 + 每月一份 | 本地 + 异地 |
| 增量备份（binlog） | 实时/每小时 | 7 天 | 本地 + 异地 |
| 异地备份 | 每天 | 30 天 | 云存储/另一机房 |

### 自动备份脚本

```bash
#!/bin/bash
# backup.sh
DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_DIR=/backup/mysql
mysqldump -u root -p'密码' --single-transaction \
  --routines --triggers --events --all-databases \
  --master-data=2 > $BACKUP_DIR/full_$DATE.sql

# 删除 7 天前的备份
find $BACKUP_DIR -name "full_*.sql" -mtime +7 -delete
```

用 crontab 定时执行：

```bash
# 每天凌晨 2 点备份
0 2 * * * /bin/bash /path/to/backup.sh
```

### 备份的黄金法则

1. **3-2-1 原则**：3 份副本，2 种介质，1 份异地
2. **定期验证**：备份了不等于能恢复——每月演练一次恢复
3. **加密存储**：备份含敏感数据，要加密
4. **监控备份**：备份失败要告警

> **小白问**：备份多久验证一次？
> 至少每月一次恢复到测试环境验证。很多公司"备份了几年，出事时发现备份是坏的"——血的教训。

## 23.9 本章总结

| 知识点 | 内容 |
|--------|------|
| 备份重要性 | 数据丢失的最后安全网；坚持做+定期验证 |
| 备份类型 | 逻辑/物理、全量/增量、热/冷 |
| mysqldump | 逻辑备份；`--single-transaction` 热备；`--master-data` 记 binlog 位 |

| 物理备份 | XtraBackup，适合大数据库 |
| 备份策略 | 3-2-1 原则、定期验证、加密、监控 |
