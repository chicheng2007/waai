## 32.1 项目需求

威胁情报平台（Threat Intelligence Platform）用于：

1. 存储威胁指标（IOC：IP、域名、文件哈希、URL）
2. 记录情报来源、严重级别、标签、有效期
3. 支持批量查询：给定一批 IP，快速判断是否命中威胁情报
4. 支持情报更新、过期清理
5. 提供统计报表

## 32.2 数据库设计

```sql
CREATE DATABASE IF NOT EXISTS threat_intel DEFAULT CHARSET utf8mb4;
USE threat_intel;

-- 1. 情报主表
CREATE TABLE indicators (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    indicator VARCHAR(512) NOT NULL COMMENT '指标值（IP/域名/哈希/URL）',
    type ENUM('IP','DOMAIN','HASH','URL','EMAIL') NOT NULL COMMENT '类型',
    severity TINYINT UNSIGNED NOT NULL DEFAULT 3 COMMENT '严重级别1-5',
    confidence DECIMAL(4,3) DEFAULT 0.800 COMMENT '置信度',
    source VARCHAR(128) COMMENT '情报来源',
    tags JSON COMMENT '标签（如 scanner, botnet, c2）',
    description TEXT COMMENT '描述',
    first_seen DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '首次发现',
    last_seen DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '最近发现',
    expires_at DATETIME COMMENT '过期时间',
    is_active BOOLEAN DEFAULT TRUE COMMENT '是否有效',
    UNIQUE KEY uk_indicator_type (indicator, type),
    INDEX idx_type_severity (type, severity),
    INDEX idx_active (is_active),
    INDEX idx_expires (expires_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='威胁指标表';

-- 2. 情报来源表
CREATE TABLE intel_sources (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(128) NOT NULL UNIQUE,
    url VARCHAR(512),
    reliability TINYINT UNSIGNED DEFAULT 3 COMMENT '可靠性1-5',
    last_update DATETIME
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 3. 命中记录表
CREATE TABLE intel_hits (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    indicator VARCHAR(512) NOT NULL,
    hit_context VARCHAR(255) COMMENT '命中场景（如 login、firewall）',
    hit_count INT DEFAULT 1,
    first_hit DATETIME DEFAULT CURRENT_TIMESTAMP,
    last_hit DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_indicator (indicator),
    INDEX idx_context (hit_context)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='命中记录';
```

设计要点：

- `UNIQUE KEY (indicator, type)`：同一指标同一类型不重复
- `expires_at` + `is_active`：支持情报过期管理
- `tags` JSON：灵活标签
- `confidence` DECIMAL：精确置信度
- `intel_hits`：记录情报被命中的情况，用于分析

## 32.3 导入情报数据

### 单条插入（带去重）

```sql
INSERT INTO indicators (indicator, type, severity, source, tags, description)
VALUES ('45.33.22.11', 'IP', 4, '公开情报源',
        '["scanner", "bruteforce"]', '暴力破解来源IP')
ON DUPLICATE KEY UPDATE
    severity = GREATEST(severity, VALUES(severity)),
    last_seen = NOW(),
    is_active = TRUE;
```

`ON DUPLICATE KEY UPDATE` 让重复导入时更新而不是报错——情报源经常重复推送，`GREATEST` 保留更高的严重级别。

### 批量导入多条

```sql
INSERT INTO indicators (indicator, type, severity, source, tags) VALUES
('45.33.22.11', 'IP', 4, 'feed-A', '["scanner"]'),
('evil-example.com', 'DOMAIN', 5, 'feed-A', '["c2", "malware"]'),
('d41d8cd98f00b204e9800998ecf8427e', 'HASH', 5, 'feed-B', '["malware"]'),
('http://evil-example.com/payload', 'URL', 4, 'feed-B', '["phishing"]')
ON DUPLICATE KEY UPDATE
    severity = GREATEST(severity, VALUES(severity)),
    last_seen = NOW();
```

### 用 LOAD DATA 导入大文件

如果有 CSV 文件：

```sql
LOAD DATA LOCAL INFILE '/path/to/ioc.csv'
INTO TABLE indicators
FIELDS TERMINATED BY ','
LINES TERMINATED BY '\n'
(indicator, type, severity, source);
```

> **安全提醒**：LOAD DATA LOCAL INFILE 有安全风险（第 20 章讲过），生产环境应该用 `secure_file_priv` 限制或关闭。

## 32.4 情报查询

### 查某 IP 是否在情报库

```sql
SELECT indicator, type, severity, confidence, source, tags, description
FROM indicators
WHERE indicator = '45.33.22.11'
  AND type = 'IP'
  AND is_active = TRUE
  AND (expires_at IS NULL OR expires_at > NOW());
```

### 批量比对（核心功能）

给定一批 IP，找出命中的：

```sql
SELECT indicator, severity, source, tags
FROM indicators
WHERE type = 'IP'
  AND is_active = TRUE
  AND indicator IN (
      '45.33.22.11', '1.2.3.4', '192.168.1.10', '8.8.8.8'
  );
```

### 带严重级别的批量比对（更实用）

```sql
-- 只关心高危（>=4）的情报
SELECT indicator, severity, confidence, tags
FROM indicators
WHERE type = 'IP'
  AND severity >= 4
  AND is_active = TRUE
  AND indicator IN ('45.33.22.11', '1.2.3.4', '8.8.8.8')
ORDER BY severity DESC;
```

## 32.5 情报统计报表

```sql
-- 按类型统计
SELECT type, COUNT(*) AS count,
       AVG(severity) AS avg_severity,
       SUM(severity >= 4) AS high_risk
FROM indicators
WHERE is_active = TRUE
GROUP BY type;

-- 按来源统计
SELECT source, COUNT(*) AS count, MAX(last_seen) AS latest
FROM indicators
GROUP BY source
ORDER BY count DESC;

-- 按标签统计（JSON）
SELECT
    JSON_UNQUOTE(JSON_EXTRACT(tags, '$[0]')) AS tag,
    COUNT(*) AS count
FROM indicators
WHERE tags IS NOT NULL
GROUP BY tag
ORDER BY count DESC;
```

## 32.6 记录命中

每次情报被命中，记录到 intel_hits：

```sql
INSERT INTO intel_hits (indicator, hit_context, hit_count) VALUES
('45.33.22.11', 'login', 1)
ON DUPLICATE KEY UPDATE
    hit_count = hit_count + 1,
    last_hit = NOW();
```

> **注意**：这个写法需要 `intel_hits` 有 `(indicator, hit_context)` 的 UNIQUE 才能正确 ON DUPLICATE。实际设计时加上：
> ```sql
> ALTER TABLE intel_hits ADD UNIQUE KEY uk_indicator_context (indicator, hit_context);
> ```

## 32.7 过期情报清理

用事件定期清理过期情报（第 15 章）：

```sql
DELIMITER $$

CREATE EVENT evt_expire_indicators
ON SCHEDULE EVERY 1 DAY
DO
BEGIN
    -- 标记过期情报为无效
    UPDATE indicators
    SET is_active = FALSE
    WHERE expires_at IS NOT NULL
      AND expires_at < NOW()
      AND is_active = TRUE;

    -- 删除 90 天前的命中记录
    DELETE FROM intel_hits
    WHERE last_hit < NOW() - INTERVAL 90 DAY;
END$$

DELIMITER ;
```

## 32.8 Python 实现查询接口

```python
import pymysql
import os
import json

DB_CONFIG = {
    'host': 'localhost',
    'user': 'secapp',
    'password': os.environ.get('DB_PASSWORD'),
    'database': 'threat_intel',
    'charset': 'utf8mb4'
}

def check_indicators(values, ioc_type='IP', min_severity=1):
    """批量检查指标是否命中威胁情报"""
    if not values:
        return []

    conn = pymysql.connect(**DB_CONFIG)
    try:
        placeholders = ','.join(['%s'] * len(values))
        sql = f"""
            SELECT indicator, type, severity, confidence, source, tags, description
            FROM indicators
            WHERE type = %s
              AND severity >= %s
              AND is_active = TRUE
              AND (expires_at IS NULL OR expires_at > NOW())
              AND indicator IN ({placeholders})
            ORDER BY severity DESC
        """
        params = [ioc_type, min_severity] + list(values)
        with conn.cursor(pymysql.cursors.DictCursor) as cur:
            cur.execute(sql, params)
            hits = cur.fetchall()

        # 记录命中
        for hit in hits:
            with conn.cursor() as cur:
                cur.execute("""
                    INSERT INTO intel_hits (indicator, hit_context, hit_count)
                    VALUES (%s, 'api_check', 1)
                    ON DUPLICATE KEY UPDATE hit_count=hit_count+1, last_hit=NOW()
                """, (hit['indicator'],))
        conn.commit()

        # 解析 tags JSON
        for hit in hits:
            if hit['tags']:
                hit['tags'] = json.loads(hit['tags'])
        return hits
    finally:
        conn.close()

if __name__ == '__main__':
    ips = ['45.33.22.11', '8.8.8.8', '1.1.1.1']
    hits = check_indicators(ips, 'IP', min_severity=4)
    print(f"命中 {len(hits)} 条威胁情报:")
    for h in hits:
        print(f"  [{h['severity']}] {h['indicator']} - {h['source']} - {h['tags']}")
```

**关键点**：

- 动态生成占位符 `placeholders`（注意：类型、级别是参数，值也是参数——全是参数化，防注入）
- 批量查询一次搞定，不用循环查
- 命中记录自动写入
- JSON tags 自动解析

> **安全提醒**：`f"...{placeholders}..."` 看起来像拼接，但 placeholders 是由 `%s` 组成的固定字符串（数量由列表长度决定），实际值仍通过参数传入——这是安全的。真正危险的是把**用户输入的值**拼进去。
