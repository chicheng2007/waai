# 第 7 章 条件、排序与分页（WHERE / ORDER BY / LIMIT）

## 本章目标

读完这一章，你将能够：

- 用 WHERE 做精确过滤（比较、范围、集合、模糊、空值）
- 用 AND/OR/IN/NOT 组合复杂条件
- 用 LIKE 做模糊匹配（安全场景常用）
- 用 ORDER BY 排序（多列、升降序）
- 理解查询条件的优先级和括号

---

## 7.1 WHERE 的作用

WHERE 用来**过滤行**——只保留符合条件的记录。它在逻辑执行顺序里排第二（FROM 之后）。

```sql
SELECT * FROM hosts WHERE status = 'UP';
```

---

## 7.2 比较运算符

| 运算符 | 含义 | 示例 |
|--------|------|------|
| `=` | 等于 | `WHERE status = 'UP'` |
| `<>` 或 `!=` | 不等于 | `WHERE status <> 'DOWN'` |
| `>` | 大于 | `WHERE port > 1024` |
| `<` | 小于 | `WHERE port < 1024` |
| `>=` | 大于等于 | `WHERE priority >= 8` |
| `<=` | 小于等于 | `WHERE priority <= 3` |

安全场景：找出所有知名端口（<1024）的扫描结果：

```sql
SELECT host, port, service FROM scan_results WHERE port < 1024;
```

---

## 7.3 范围：BETWEEN

```sql
SELECT * FROM scan_results WHERE port BETWEEN 1 AND 1024;
```

等价于 `port >= 1 AND port <= 1024`，包含边界。

时间范围查询（安全分析高频）：

```sql
SELECT * FROM login_logs
WHERE login_time BETWEEN '2026-01-01 00:00:00' AND '2026-01-31 23:59:59';
```

更优雅的时间范围写法：

```sql
SELECT * FROM login_logs
WHERE login_time >= '2026-01-01' AND login_time < '2026-02-01';
```

> **小白问**：为什么推荐 `>= 起始 AND < 结束` 而不是 BETWEEN？
> 因为 BETWEEN 包含结束边界，如果结束时间写成 `'2026-01-31'`，实际是 `'2026-01-31 00:00:00'`，当天的其他时间会漏掉。用左闭右开区间最稳妥。

---

## 7.4 集合：IN / NOT IN

```sql
SELECT * FROM scan_results WHERE port IN (22, 80, 443, 3389);
```

找出常见攻击目标端口。等价于 `port = 22 OR port = 80 OR ...`，但更简洁。

```sql
SELECT * FROM hosts WHERE status NOT IN ('DOWN', 'UNKNOWN');
```

> **注意**：`IN` 列表里不能有 NULL，否则结果可能是 UNKNOWN。比如 `WHERE status NOT IN ('DOWN', NULL)` 永远返回空——因为 NULL 参与比较结果是 UNKNOWN。

---

## 7.5 模糊查询：LIKE（安全场景重点）

LIKE 用于字符串的模式匹配，配合两个通配符：

- `%`：任意多个字符（包括 0 个）
- `_`：恰好一个字符

```sql
-- 查找以 192.168 开头的 IP
SELECT * FROM hosts WHERE ip LIKE '192.168.%';

-- 查找包含 'admin' 的用户名
SELECT * FROM login_logs WHERE username LIKE '%admin%';

-- 查找以 'evil' 结尾的域名
SELECT * FROM threat_intel WHERE indicator LIKE '%evil' AND type = 'DOMAIN';

-- 查找长度为 5 的主机名（5 个下划线）
SELECT * FROM hosts WHERE hostname LIKE '_____';
```

**转义**：如果要匹配字面的 `%` 或 `_`，用反斜杠转义：

```sql
SELECT * FROM logs WHERE message LIKE '%\%%';  -- 匹配包含 % 的
```

### LIKE 与安全的关系

**1. SQL 注入常利用 LIKE 构造条件**（第 19 章讲）

**2. WAF 规则常基于 LIKE 模式匹配攻击特征**

**3. LIKE 前置通配符无法用普通索引**：

```sql
WHERE username LIKE 'admin%'  -- 可以用索引（前缀确定）
WHERE username LIKE '%admin'  -- 不能用普通索引（前缀不确定），全表扫描
```

这是重要的性能知识点。前缀匹配快，后缀/包含匹配慢。第 22 章会深入讲。

> **小白问**：`LIKE '%admin%'` 这么慢，为什么还用？
> 因为有时候就是要"包含"查询。数据量大时，可以考虑全文索引（FULLTEXT）或搜索引擎（Elasticsearch）。小表用 LIKE 完全没问题。

## 7.6 逻辑运算符：AND / OR / NOT

```sql
-- AND：两个条件都满足
SELECT * FROM scan_results
WHERE severity = 'HIGH' AND port = 3306;

-- OR：满足任一条件
SELECT * FROM scan_results
WHERE port = 22 OR port = 3389;

-- NOT：取反
SELECT * FROM hosts WHERE NOT status = 'DOWN';
```

### 优先级陷阱

AND 的优先级高于 OR。这意味着：

```sql
WHERE severity = 'HIGH' OR port = 22 AND status = 'OPEN'
```

实际等价于：

```sql
WHERE severity = 'HIGH' OR (port = 22 AND status = 'OPEN')
```

可能不是你想要的！**永远用括号明确优先级**：

```sql
WHERE (severity = 'HIGH' OR port = 22) AND status = 'OPEN'
```

> **专业习惯**：写复杂条件时，哪怕不加括号也对，也加上括号。这既避免歧义，也让读代码的人一眼看懂。

---

## 7.7 排序：ORDER BY

```sql
-- 单列升序（ASC，默认）
SELECT * FROM scan_results ORDER BY found_at ASC;

-- 单列降序（DESC）
SELECT * FROM scan_results ORDER BY severity DESC;

-- 多列排序：先按严重级别降序，同级别按时间降序
SELECT * FROM scan_results
ORDER BY severity DESC, found_at DESC;
```

注意：ENUM 类型排序按定义顺序，而不是字母顺序。如果 severity 定义为 `('INFO','LOW','MEDIUM','HIGH','CRITICAL')`，那么 `ORDER BY severity DESC` 会把 CRITICAL 排在最前——正好符合需求。

按计算列排序：

```sql
SELECT host, port, severity FROM scan_results
ORDER BY CASE severity
    WHEN 'CRITICAL' THEN 5
    WHEN 'HIGH' THEN 4
    WHEN 'MEDIUM' THEN 3
    WHEN 'LOW' THEN 2
    ELSE 1
END DESC;
```

按中文别名排序（因为 ORDER BY 在 SELECT 之后执行）：

```sql
SELECT host, port, severity, found_at AS '发现时间'
FROM scan_results
ORDER BY '发现时间' DESC;
```

### 排序的性能

排序会消耗 CPU 和内存（filesort）。如果排序字段有索引，可以利用索引的有序性避免排序。第 13 章讲索引，第 22 章讲优化。

## 7.8 综合示例：安全日志分析查询

把本章所有知识点串起来：

```sql
USE security_lab;

-- 查询：过去 7 天内，来自 192.168.1.* 网段、登录失败次数多的记录
-- 按时间倒序，取前 20 条
SELECT
    ip,
    username,
    login_time,
    result
FROM login_logs
WHERE login_time >= NOW() - INTERVAL 7 DAY
  AND ip LIKE '192.168.1.%'
  AND (result = 'FAILED' OR username LIKE '%admin%')
ORDER BY login_time DESC
LIMIT 20;
```

逐块解读：

- `login_time >= NOW() - INTERVAL 7 DAY`：时间范围过滤
- `ip LIKE '192.168.1.%'`：网段过滤（前缀匹配，可用索引）
- `(result = 'FAILED' OR username LIKE '%admin%')`：括号明确逻辑
- `ORDER BY login_time DESC`：最新的排前面
- `LIMIT 20`：只要 20 条

这就是日常安全分析写的查询——不复杂，但每个部分都有讲究。

## 7.9 本章总结

| 知识点 | 内容 |
|--------|------|
| 比较运算 | =, <>, >, <, >=, <= |
| BETWEEN | 范围查询，含边界；时间用左闭右开更安全 |
| IN / NOT IN | 集合查询；列表里别放 NULL |
| LIKE | % 任意多个、_ 恰好一个；前置 % 无法用索引 |
| 逻辑运算 | AND 优先级高于 OR；用括号明确 |
| ORDER BY | ASC/DESC 升降序；多列排序；ENGINE 枚举按定义序 |
| 排序性能 | 排序耗时；索引可优化 |
| 综合 | 时间+网段+逻辑组合+排序+分页是安全查询标配 |
