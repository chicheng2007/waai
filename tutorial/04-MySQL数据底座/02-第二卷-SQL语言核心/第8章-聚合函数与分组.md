# 第 8 章 聚合函数与分组（GROUP BY / HAVING）

## 本章目标

读完这一章，你将能够：

- 使用 COUNT / SUM / AVG / MAX / MIN 做统计
- 用 GROUP BY 对数据进行分组统计
- 用 HAVING 过滤分组结果
- 分清 WHERE 和 HAVING 的区别
- 写出"找出暴力破解 IP"这样的统计查询

---

## 8.1 聚合函数

聚合函数对**一组值**进行计算，返回一个结果。

| 函数 | 作用 | 示例 |
|------|------|------|
| `COUNT()` | 计数 | `COUNT(*)` 统计行数 |
| `SUM()` | 求和 | `SUM(fail_count)` |
| `AVG()` | 平均 | `AVG(score)` |
| `MAX()` | 最大 | `MAX(login_time)` |
| `MIN()` | 最小 | `MIN(login_time)` |
| `GROUP_CONCAT()` | 拼接组内值 | `GROUP_CONCAT(ip)` |

### COUNT 的用法

```sql
-- 总行数
SELECT COUNT(*) FROM login_logs;

-- 某列非 NULL 的行数
SELECT COUNT(ip) FROM login_logs;

-- 去重计数
SELECT COUNT(DISTINCT ip) FROM login_logs;
```

`COUNT(*)` 统计所有行（包括 NULL 行），`COUNT(列)` 只统计该列非 NULL 的行。

> **小白问**：`COUNT(*)` 和 `COUNT(1)` 有区别吗？
> 在 InnoDB 里没区别，性能一样。MySQL 对 `COUNT(*)` 做了专门优化，推荐直接用 `COUNT(*)`。

### 实战：基本统计

```sql
USE security_lab;

SELECT
    COUNT(*) AS total_logs,
    COUNT(DISTINCT ip) AS unique_ips,
    MIN(login_time) AS first_login,
    MAX(login_time) AS last_login
FROM login_logs;
```

一次查出：总日志数、不同 IP 数、最早/最晚登录时间。

## 8.2 GROUP BY：分组统计

GROUP BY 把数据按某列分组，每组单独统计。

**经典问题：统计每个 IP 的登录失败次数**

```sql
SELECT
    ip,
    COUNT(*) AS fail_count
FROM login_logs
WHERE result = 'FAILED'
GROUP BY ip
ORDER BY fail_count DESC;
```

这句话的逻辑：

1. `WHERE result='FAILED'`：先过滤出失败的日志
2. `GROUP BY ip`：按 IP 分组（相同 IP 的行归为一组）
3. `COUNT(*)`：每组数一下有多少行
4. `ORDER BY fail_count DESC`：按次数从多到少排

结果可能：

```
+---------------+------------+
| ip            | fail_count |
+---------------+------------+
| 45.33.22.11   | 312        |
| 192.168.1.10  | 8          |
+---------------+------------+
```

一眼看出 45.33.22.11 在暴力破解！这就是聚合分组的安全价值。

### 多列分组

```sql
SELECT
    ip,
    username,
    COUNT(*) AS attempts
FROM login_logs
WHERE result = 'FAILED'
GROUP BY ip, username
ORDER BY attempts DESC;
```

按 (IP, 用户名) 的组合分组——能发现"针对 admin 账号的定向爆破"。

### 按时间分组

```sql
SELECT
    DATE(login_time) AS day,
    COUNT(*) AS fail_count
FROM login_logs
WHERE result = 'FAILED'
GROUP BY DATE(login_time)
ORDER BY day;
```

按天统计失败次数，可以看攻击趋势。`DATE()` 提取日期部分。

## 8.3 HAVING：过滤分组结果

HAVING 是对**分组后的结果**进行过滤。它和 WHERE 的区别是本章重点。

```sql
-- 找出失败次数超过 50 次的 IP（疑似暴力破解）
SELECT
    ip,
    COUNT(*) AS fail_count
FROM login_logs
WHERE result = 'FAILED'
GROUP BY ip
HAVING fail_count > 50
ORDER BY fail_count DESC;
```

**WHERE vs HAVING：**

| 对比 | WHERE | HAVING |
|------|-------|--------|
| 过滤对象 | 原始行 | 分组后的组 |
| 执行时机 | 分组前 | 分组后 |
| 能用聚合函数 | ❌ | ✅ |
| 能用普通列 | ✅ | 需出现在 GROUP BY 或聚合中 |

> **小白问**：为什么 WHERE 里不能写 `COUNT(*) > 50`？
> 因为 WHERE 执行时还没分组，根本不知道每组有多少行。HAVING 在分组后执行，这时每组的统计值才算出来。记住执行顺序：WHERE → GROUP BY → HAVING。

### 完整示例：漏洞统计报表

```sql
USE vulnscan;

SELECT
    severity,
    COUNT(*) AS vuln_count,
    COUNT(DISTINCT host) AS affected_hosts
FROM scan_results
WHERE found_at >= NOW() - INTERVAL 30 DAY
GROUP BY severity
HAVING COUNT(*) >= 5
ORDER BY
    CASE severity
        WHEN 'CRITICAL' THEN 5
        WHEN 'HIGH' THEN 4
        WHEN 'MEDIUM' THEN 3
        WHEN 'LOW' THEN 2
        ELSE 1
    END DESC;
```

这条查询：统计最近 30 天各严重级别的漏洞数、受影响主机数，只显示数量≥5 的级别，按严重程度排序。

## 8.4 GROUP_CONCAT：组内拼接

把每组的多个值拼成一个字符串：

```sql
SELECT
    ip,
    COUNT(*) AS fail_count,
    GROUP_CONCAT(DISTINCT username ORDER BY username SEPARATOR ',') AS usernames
FROM login_logs
WHERE result = 'FAILED'
GROUP BY ip
HAVING fail_count > 10;
```

结果可能是：

```
+---------------+------------+------------------+
| ip            | fail_count | usernames        |
+---------------+------------+------------------+
| 45.33.22.11   | 312        | admin,root,test  |
+---------------+------------+------------------+
```

一次看到这个 IP 尝试了哪些用户名——攻击者在进行用户枚举。

> **注意**：GROUP_CONCAT 有长度限制（默认 1024 字节），超长会被截断。可以调 `group_concat_max_len` 系统变量。

## 8.5 聚合函数的 NULL 处理

聚合函数一般忽略 NULL：

```sql
SELECT AVG(score) FROM results;  -- NULL 的 score 不参与平均
```

但 `COUNT(*)` 统计所有行，`COUNT(列)` 忽略该列为 NULL 的行。

如果想把 NULL 当 0 处理：

```sql
SELECT AVG(IFNULL(score, 0)) FROM results;
```

## 8.6 ONLY_FULL_GROUP_BY 模式

MySQL 5.7+ 默认开启 `ONLY_FULL_GROUP_BY` 模式，要求：

> SELECT 里的普通列必须出现在 GROUP BY 中，或者被聚合函数包住。

```sql
-- 错误：status 既不在 GROUP BY 也不在聚合函数里
SELECT ip, status, COUNT(*) FROM login_logs GROUP BY ip;

-- 正确
SELECT ip, MAX(status) AS status, COUNT(*) FROM login_logs GROUP BY ip;
-- 或把 status 加进 GROUP BY
SELECT ip, status, COUNT(*) FROM login_logs GROUP BY ip, status;
```

这个模式是为了防止语义模糊——一组里有多行时，SELECT 一个未分组的列，MySQL 不知道该返回哪一行的值。

> **小白问**：老教程里经常写"非法"的 GROUP BY 查询，为什么他们能跑？
> 因为老版本 MySQL 没默认开 ONLY_FULL_GROUP_BY。现在新版默认开了，写规范点总没错。

## 8.7 WITH ROLLUP：分组小计与总计

```sql
SELECT
    severity,
    COUNT(*) AS cnt
FROM scan_results
GROUP BY severity WITH ROLLUP;
```

会在结果末尾加一行 NULL，表示所有分组的总计。做报表时很方便。

## 8.8 本章总结

| 知识点 | 内容 |
|--------|------|
| 聚合函数 | COUNT / SUM / AVG / MAX / MIN / GROUP_CONCAT |
| COUNT | `COUNT(*)` 统计所有行；`COUNT(DISTINCT 列)` 去重计数 |
| GROUP BY | 按列分组，每组单独统计 |
| 多列分组 | `GROUP BY ip, username` 按组合分组 |
| HAVING | 过滤分组结果；可用聚合函数；WHERE 在分组前、HAVING 在分组后 |
| GROUP_CONCAT | 组内拼接；可去重、排序、自定义分隔符 |
| NULL 处理 | 聚合函数忽略 NULL；IFNULL 可当 0 |
| ONLY_FULL_GROUP_BY | SELECT 的普通列必须在 GROUP BY 中或被聚合 |
| WITH ROLLUP | 生成分组小计和总计 |
