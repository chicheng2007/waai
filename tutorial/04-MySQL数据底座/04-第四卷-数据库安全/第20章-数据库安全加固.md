# 第 20 章 数据库安全加固

> **伦理声明**：本章内容用于合法授权的系统加固。请确保你对要加固的数据库拥有管理权限。

## 本章目标

读完这一章，你将能够：

- 知道 MySQL 安装后的安全初始化
- 从网络、账号、文件、功能、日志多维度加固数据库
- 理解最小暴露面原则
- 建立数据库安全检查清单

---

## 20.1 安全加固的思路

数据库安全加固遵循**纵深防御**和**最小暴露面**原则：

```
网络层  → 谁能连到数据库
账号层  → 谁能登录、能做什么
文件层  → 数据文件、配置文件的权限
功能层  → 哪些危险功能要禁用
补丁层  → 及时修复已知漏洞
审计层  → 记录谁做了什么
```

一层层加固，每层都减少攻击面。

---

## 20.2 安装后第一件事：安全初始化

MySQL 安装完成后，运行：

```bash
mysql_secure_installation
```

它会引导你做这些事：

1. 设置 root 密码（如果没设）
2. 删除匿名账号
3. 禁止 root 远程登录
4. 删除 test 测试数据库
5. 刷新权限表

**这一步必做**。默认安装的 MySQL 有很多不安全的默认值。

## 20.3 网络层加固

### 1. 不要暴露到公网

数据库不该直接暴露在公网。用防火墙/安全组限制访问来源：

```bash
# Linux iptables 示例：只允许内网访问 3306
iptables -A INPUT -p tcp --dport 3306 -s 10.0.0.0/8 -j ACCEPT
iptables -A INPUT -p tcp --dport 3306 -j DROP
```

云环境用安全组，只允许应用服务器的 IP 访问。

### 2. 修改默认端口（可选）

把 3306 改成非标准端口，能减少自动化扫描：

```ini
# my.cnf 或 my.ini
[mysqld]
port=33066
```

> **注意**：改端口是"隐蔽即安全"的手段，作用有限，别当主要防御。真正的防御是网络隔离和强认证。

### 3. 绑定地址

```ini
[mysqld]
bind-address=127.0.0.1
```

只监听本地回环地址，外部无法连接。如果需要远程，绑定到特定内网 IP。

### 4. 使用 SSL/TLS

远程连接时，启用 SSL 加密传输，防止中间人窃听：

```sql
SHOW VARIABLES LIKE '%ssl%';
```

强制用户使用 SSL：

```sql
ALTER USER 'user'@'host' REQUIRE SSL;
```

## 20.4 账号层加固

### 1. 强密码策略

```ini
[mysqld]
validate_password.policy=STRONG
validate_password.length=12
validate_password.mixed_case_count=1
validate_password.number_count=1
validate_password.special_char_count=1
```

### 2. 最小权限（回顾第 18 章）

应用账号只给必要的库表权限，绝不用 root。

### 3. 限制登录失败次数

安装 connection_control 插件，防止暴力破解：

```ini
[mysqld]
plugin-load-add=connection_control.so
connection_control_failed_connections_threshold=3
connection_control_min_connection_delay=1000
```

连续失败 3 次后，每次失败延迟递增——让暴力破解变得极慢。

### 4. 定期审计账号

```sql
-- 查看所有账号
SELECT user, host, account_locked FROM mysql.user;

-- 找出空密码账号
SELECT user, host FROM mysql.user WHERE authentication_string='';

-- 找出非本地的 root
SELECT user, host FROM mysql.user WHERE user='root' AND host NOT IN ('localhost','127.0.0.1','::1');
```

## 20.5 文件层加固

### 1. 配置文件权限

```bash
chmod 640 /etc/mysql/my.cnf
chown root:mysql /etc/mysql/my.cnf
```

### 2. 数据目录权限

MySQL 数据目录（默认 `/var/lib/mysql`）只允许 mysql 用户访问：

```bash
chown -R mysql:mysql /var/lib/mysql
chmod -R 750 /var/lib/mysql
```

### 3. 禁用 local_infile

`LOAD DATA LOCAL INFILE` 允许客户端读取本地文件传给服务器。如果应用有注入，攻击者可能利用它读服务器文件：

```sql
SHOW VARIABLES LIKE 'local_infile';
SET GLOBAL local_infile = OFF;
```

或在配置里：

```ini
[mysqld]
local_infile=OFF
```

### 4. secure_file_priv

限制 `LOAD DATA`、`SELECT INTO OUTFILE`、`LOAD_FILE` 能操作的目录：

```ini
[mysqld]
secure_file_priv=/var/lib/mysql-files
```

设为 `NULL` 则完全禁止这些操作——最安全。

```sql
SHOW VARIABLES LIKE 'secure_file_priv';
```

## 20.6 功能层加固：禁用危险功能

### 1. 禁用符号链接

```ini
[mysqld]
symbolic-links=0
```

防止通过符号链接访问未授权文件。

### 2. 限制LOAD_FILE

通过 `secure_file_priv` 控制（见上）。

### 3. 谨慎使用 FILE 权限

不要给普通用户 FILE 权限——它能读写服务器文件。

```sql
REVOKE FILE ON *.* FROM 'user'@'host';
```

### 4. 禁用不需要的插件

```sql
SHOW PLUGINS;
```

禁用不用的插件，减少攻击面。

---

## 20.7 补丁层：及时更新

MySQL 会不断修复安全漏洞。**定期更新到最新的补丁版本**：

```bash
# Ubuntu
sudo apt update && sudo apt upgrade mysql-server

# 查看当前版本
mysql --version
```

关注 MySQL 官方安全公告，重大漏洞（如 CVSS 高分漏洞）要及时打补丁。

## 20.8 审计层：启用日志

### 1. 错误日志

```ini
[mysqld]
log-error=/var/log/mysql/error.log
```

记录启动、运行错误，排查问题用。

### 2. 慢查询日志

```ini
[mysqld]
slow_query_log=1
long_query_time=2
slow_query_log_file=/var/log/mysql/slow.log
```

记录执行超过 2 秒的查询，既优化性能也发现异常查询。

### 3. 二进制日志（binlog）

```ini
[mysqld]
log-bin=mysql-bin
server-id=1
```

记录所有数据变更，用于主从复制、数据恢复、审计追踪。

### 4. 通用查询日志（谨慎开启）

```ini
[mysqld]
general_log=1
general_log_file=/var/log/mysql/general.log
```

记录所有 SQL——审计最全，但性能开销大，生产环境按需开启。

### 5. 审计插件

MySQL Enterprise 有官方审计插件，社区版可用 MariaDB Audit Plugin 或 McAfee 的审计插件，实现细粒度审计。

第 21 章专门讲审计与日志分析。

## 20.9 安全检查清单

```
□ 运行了 mysql_secure_installation
□ root 密码强度足够
□ 删除了匿名账号和测试库
□ root 禁止远程登录
□ 应用账号遵循最小权限
□ 数据库不暴露公网（防火墙/安全组）
□ bind-address 限制监听地址
□ validate_password 强密码策略开启
□ connection_control 防暴力破解
□ local_infile=OFF
□ secure_file_priv 已限制
□ symbolic-links=0
□ 普通账号无 FILE 权限
□ 数据文件和配置文件权限正确
□ 错误日志、慢查询日志、binlog 已开启
□ 及时更新补丁
□ 定期审计账号和权限
```

## 20.10 用脚本自动检查

```sql
-- 综合安全检查查询
SELECT
    @@version AS '版本',
    @@port AS '端口',
    @@bind_address AS '绑定地址',
    @@local_infile AS 'local_infile',
    @@secure_file_priv AS 'secure_file_priv',
    @@have_ssl AS 'SSL支持',
    @@slow_query_log AS '慢查询日志',
    @@log_bin AS 'binlog';

-- 检查危险账号
SELECT user, host FROM mysql.user
WHERE user='' OR authentication_string=''
   OR (user='root' AND host NOT IN ('localhost','127.0.0.1','::1'));
```

定期检查，输出异常项，逐项加固。

## 20.11 本章总结

| 层面 | 加固措施 |
|------|---------|
| 初始化 | mysql_secure_installation |
| 网络 | 不暴露公网、改端口、bind-address、SSL |
| 账号 | 强密码、最小权限、防暴力破解、定期审计 |
| 文件 | 配置文件/数据目录权限、local_infile=OFF、secure_file_priv |
| 功能 | 禁符号链接、禁 FILE 权限、禁无用插件 |
| 补丁 | 及时更新 |
| 审计 | 错误日志、慢查询日志、binlog、通用日志、审计插件 |
| 原则 | 纵深防御、最小暴露面 |

## 本章练习

1. 运行 `mysql_secure_installation`，完成安全初始化。
2. 检查你的 MySQL：root 能否远程登录？有没有匿名账号？
3. 配置 `local_infile=OFF` 和 `secure_file_priv`，重启验证。
4. 检查 `@@secure_file_priv` 的值，理解它限制了什么。
5. 开启慢查询日志，写一条慢查询（如 `SELECT SLEEP(3)`），观察日志。
6. 用本章的检查清单逐项检查你的数据库，列出不达标项并修复。
7. 思考：为什么"改端口"作用有限？真正有效的防御是什么？
8. 思考：local_infile 和 secure_file_priv 如何防止注入攻击读取服务器文件？
