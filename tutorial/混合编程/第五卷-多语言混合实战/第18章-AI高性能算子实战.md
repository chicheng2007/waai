## 18.1 为什么 AI 需要自定义算子

### 18.1.1 AI 框架的分层（复习）

```
Python API → 绑定层 → C++ 核心 → CUDA/CPU 内核
```

你在 Python 里写 `torch.relu(x)`，实际执行的是 C++/CUDA 内核。**自定义算子**就是当你需要的操作框架没有提供，或内置实现不够快时，自己写一个底层内核。

### 18.1.2 什么时候需要自定义算子

- **框架没有的操作**：特殊的激活函数、自定义损失函数、领域特定运算
- **性能不够**：内置操作有临时内存分配、多次 kernel launch，融合成一个算子更快
- **硬件特性**：针对特定 CPU 指令集（AVX/SIMD）或加速器优化
- **隐私/安全**：在算子内做加密、脱敏，避免数据出内存

### 18.1.3 案例：算子融合

PyTorch 里写：

```python
x = torch.relu(w @ x + b)
```

分解为三个操作：矩阵乘法 → 加偏置 → ReLU，每次都读写内存（3 次内存往返）。自定义融合算子一次完成，避免中间结果落内存，快很多。这就是 FlashAttention 的核心思想之一。

## 18.2 用 Rust 实现自定义算子

### 18.2.1 场景：快速 Top-K 选择

大模型推理中常需要从词表（几万维）中选 top-k 个 token。我们用 Rust 实现一个高效的 top-k。

```rust
use pyo3::prelude::*;
use numpy::{PyReadonlyArray1, PyArray1, ToPyArray};
use rayon::prelude::*;

/// 返回 top-k 的索引（按值降序）
#[pyfunction]
fn top_k_indices<'py>(
    py: Python<'py>,
    values: PyReadonlyArray1<f32>,
    k: usize,
) -> PyResult<&'py PyArray1<usize>> {
    let v = values.as_slice()?;

    // 用部分排序（比全排序快）
    let mut indexed: Vec<(usize, f32)> = v.iter().cloned().enumerate().collect();
    indexed.select_nth_unstable_by(k, |a, b| {
        b.1.partial_cmp(&a.1).unwrap_or(std::cmp::Ordering::Equal)
    });
    indexed.truncate(k);
    indexed.sort_unstable_by(|a, b| b.1.partial_cmp(&a.1).unwrap());

    let result: Vec<usize> = indexed.into_iter().map(|(i, _)| i).collect();
    Ok(result.to_pyarray(py))
}
```

`select_nth_unstable_by` 是部分排序（O(n)），比全排序（O(n log n)）快。对于词表几万维、k=50 的场景，这个优化很显著。

Python 使用：

```python
import numpy as np
import fastops

logits = np.random.randn(50000).astype(np.float32)
top = fastops.top_k_indices(logits, 50)
print(top[:10])
```

### 18.2.2 场景：量化（Quantization）算子

大模型量化（把 float32 转成 int8）能大幅减少内存和加速推理。用 Rust 实现：

```rust
use pyo3::prelude::*;
use numpy::{PyReadonlyArray1, PyArray1, ToPyArray};

/// int8 量化：把 float32 映射到 [-128, 127]
#[pyfunction]
fn quantize_int8<'py>(
    py: Python<'py>,
    values: PyReadonlyArray1<f32>,
    scale: f32,
) -> PyResult<&'py PyArray1<i8>> {
    let v = values.as_slice()?;
    let result: Vec<i8> = v.iter().map(|&x| {
        let q = (x / scale).round();
        q.clamp(-128.0, 127.0) as i8
    }).collect();
    Ok(result.to_pyarray(py))
}

/// 反量化
#[pyfunction]
fn dequantize_int8<'py>(
    py: Python<'py>,
    values: PyReadonlyArray1<i8>,
    scale: f32,
) -> PyResult<&'py PyArray1<f32>> {
    let v = values.as_slice()?;
    let result: Vec<f32> = v.iter().map(|&x| x as f32 * scale).collect();
    Ok(result.to_pyarray(py))
}
```

Python 使用：

```python
weights = np.random.randn(1_000_000).astype(np.float32)
scale = 0.01
quantized = fastops.quantize_int8(weights, scale)
print(f"压缩比: {weights.nbytes / quantized.nbytes:.0f}x")  # 4x
restored = fastops.dequantize_int8(quantized, scale)
print(f"误差: {np.abs(weights - restored).mean():.6f}")
```

**这就是ybrid 编程在 AI 的价值**：Python 做算法设计和实验，Rust 做底层数据转换，兼顾开发效率和运行时性能。

## 18.3 用 C++/pybind11 实现 PyTorch 自定义算子

### 18.3.1 方法 A：C++ 扩展（cpp_extension）

PyTorch 提供 `torch.utils.cpp_extension`，基于 pybind11。

创建 `custom_ops.cpp`：

```cpp
#include <torch/extension.h>
#include <vector>

// 自定义带偏置的 ReLU（融合操作）
torch::Tensor biased_relu(torch::Tensor x, torch::Tensor bias) {
    // 检查
    TORCH_CHECK(x.is_floating_point(), "x 必须是浮点张量");
    // 用 PyTorch 的 aten 操作
    return (x + bias).clamp_min(0);
}

// 手写循环版本（展示底层控制）
torch::Tensor scale_add(torch::Tensor x, double scale, double add) {
    auto result = torch::empty_like(x);
    auto x_ptr = x.data_ptr<float>();
    auto r_ptr = result.data_ptr<float>();
    int64_t n = x.numel();
    for (int64_t i = 0; i < n; i++) {
        r_ptr[i] = x_ptr[i] * scale + add;
    }
    return result;
}

PYBIND11_MODULE(TORCH_EXTENSION_NAME, m) {
    m.def("biased_relu", &biased_relu, "带偏置的ReLU");
    m.def("scale_add", &scale_add, "缩放加常数");
}
```

Python 侧即时编译加载：

```python
import torch
from torch.utils.cpp_extension import load

custom_ops = load(
    name="custom_ops",
    sources=["custom_ops.cpp"],
    verbose=True,
)

x = torch.randn(1000, requires_grad=True)
bias = torch.randn(1000)
y = custom_ops.biased_relu(x, bias)
```

### 18.3.2 方法 B：完整自定义 autograd Function

要让自定义算子支持反向传播，需要继承 `torch.autograd.Function`：

```python
import torch

class ScaleAddFunction(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, scale, add):
        ctx.save_for_backward(x)
        ctx.scale = scale
        return custom_ops.scale_add(x, scale, add)

    @staticmethod
    def backward(ctx, grad_output):
        x, = ctx.saved_tensors
        # d/dx (x*scale + add) = scale
        return grad_output * ctx.scale, None, None

def scale_add(x, scale=1.0, add=0.0):
    return ScaleAddFunction.apply(x, scale, add)
```

这样 `scale_add` 就能参与自动微分，集成进神经网络训练。

### 18.3.3 CUDA 算子（进阶）

要真正发挥 GPU 性能，需要写 CUDA 内核：

```cpp
#include <torch/extension.h>
#include <cuda_runtime.h>

__global__ void scale_add_kernel(const float* x, float* out, float scale, float add, int n) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < n) out[idx] = x[idx] * scale + add;
}

torch::Tensor scale_add_cuda(torch::Tensor x, double scale, double add) {
    auto result = torch::empty_like(x);
    int n = x.numel();
    int threads = 256;
    int blocks = (n + threads - 1) / threads;
    scale_add_kernel<<<blocks, threads>>>(
        x.data_ptr<float>(), result.data_ptr<float>(), scale, add, n);
    return result;
}
```

加载时指定 CUDA 源：

```python
custom_ops = load(
    name="custom_ops", sources=["custom_ops.cpp", "custom_ops.cu"],
    extra_cuda_cflags=["-O3"], verbose=True
)
```

## 18.4 SIMD：CPU 级并行

### 18.4.1 什么是 SIMD

SIMD（Single Instruction Multiple Data）用一条指令处理多个数据。现代 CPU 支持 AVX2/AVX-512（一次处理 8/16 个 float）。

编译器自动向量化通常能利用 SIMD，但手写可以进一步控制。

### 18.4.2 Rust 里的 SIMD（std::simd，实验性）

```rust
#![feature(portable_simd)]
use std::simd::f32x8;

fn simd_scale_add(data: &[f32], scale: f32, add: f32) -> Vec<f32> {
    let scale_v = f32x8::splat(scale);
    let add_v = f32x8::splat(add);
    let mut result = Vec::with_capacity(data.len());

    let mut i = 0;
    while i + 8 <= data.len() {
        let v = f32x8::from_slice(&data[i..i+8]);
        let r = v * scale_v + add_v;
        result.extend_from_slice(&r.to_array());
        i += 8;
    }
    // 处理剩余
    for &x in &data[i..] { result.push(x * scale + add); }
    result
}
```

> **注意**：`std::simd` 目前需要 nightly Rust。生产环境可用 `packed_simd` 或 `wide` crate，或依赖编译器自动向量化。

### 18.4.3 C++ 里的自动向量化

```cpp
// 写规整的循环，编译器会自动用 SIMD
#pragma GCC optimize("O3", "tree-vectorize")
void scale_add(float* data, int n, float scale, float add) {
    for (int i = 0; i < n; i++) {
        data[i] = data[i] * scale + add;  // 编译器自动向量化
    }
}
```

关键是让循环**连续、无分支、无依赖**，编译器才能向量化。

## 18.5 评估算子加速方案

### 18.5.1 决策流程

1. **框架有现成算子吗？** 先试内置，可能已经很快
2. **能用算子融合吗？** 把多个操作合并，减少内存往返
3. **需要 CPU 还是 GPU？** GPU 适合大规模并行，CPU 适合小数据/低延迟
4. **用 Rust 还是 C++？**
   - 已有 PyTorch 生态 → C++/CUDA（cpp_extension）
   - 独立 AI 服务、安全考虑 → Rust（PyO3）
5. **数据转换开销大吗？** 用零拷贝 numpy buffer

### 18.5.2 加速效果评估模板

```python
import timeit
import numpy as np

data = np.random.randn(10_000_000).astype(np.float32)

def baseline(x):
    return np.clip(x * 0.5 + 0.1, 0, None)

def accelerated(x):
    return fastops.scale_add_relu(x, 0.5, 0.1)

for name, fn in [("numpy", baseline), ("Rust", accelerated)]:
    t = timeit.timeit(lambda: fn(data), number=100)
    print(f"{name}: {t/100*1000:.2f} ms")
```

**注意**：numpy 已经优化了基础操作，简单算子可能加速有限。Rust/C++ 的优势在**复杂融合算子**和**自定义逻辑**。

## 18.6 本章总结

| 知识点 | 内容 |
|--------|------|
| 自定义算子动机 | 框架没有、性能不够、硬件特性、隐私安全 |

| SIMD | 一条指令多数据；Rust std::simd（nightly）、C++ 自动向量化 |
| 评估 | 先试内置→融合→选 CPU/GPU→选语言→零拷贝 |
