## 3.1 开发环境总览

混合编程涉及多种工具链，先把它们装齐。以下以 **Linux（Ubuntu/Debian）** 为主，同时标注 macOS/Windows 差异。

### 3.1.1 必备工具清单

| 工具 | 用途 | 安装方式（Ubuntu） |
|------|------|-------------------|
| Python 3.8+ | 胶水层 | 系统自带或 pyenv |
| GCC/G++ | C/C++ 编译器 | `sudo apt install build-essential` |
| make / cmake | 构建工具 | `sudo apt install cmake` |
| Rust + cargo | Rust 工具链 | `curl https://sh.rustup.rs \| sh` |
| Go | Go 工具链 | 官网下载或用 apt |
| pkg-config | 库配置查询 | `sudo apt install pkg-config` |
| gdb / lldb | 调试器 | `sudo apt install gdb` |

### 3.1.2 验证安装

```bash
python3 --version      # Python 3.8+
gcc --version          # GCC 9+
g++ --version
cmake --version
cargo --version        # Rust 1.70+
go version             # Go 1.20+
```

> **小白问：我只学 Python+C/C++，Rust 和 Go 也要装吗？**
> 不用。按你学的卷装即可：
> - 只学第二卷（Python+C/C++）→ Python + GCC + make
> - 学第三卷（PyO3）→ 加上 Rust
> - 学第四卷（Go）→ 加上 Go
>
> 但建议都装上，因为第五卷的实战项目会混合使用。

### 3.1.3 macOS 用户

- 安装 Xcode 命令行工具：`xcode-select --install`
- 用 Homebrew 安装其他工具：`brew install cmake rust go`
- 注意 macOS 的动态库扩展名是 `.dylib`，且默认不允许加载未签名的库（有 SIP 限制，开发时用相对路径一般没问题）

### 3.1.4 Windows 用户

- 安装 **MSYS2** 或 **MinGW-w64** 提供 GCC（推荐 MSYS2：`pacman -S mingw-w64-x86_64-gcc`）
- 或者用 **Visual Studio Build Tools**（MSVC 编译器）
- Python 用官方安装包；Rust 用 rustup-init.exe；Go 用官方 msi
- 动态库扩展名是 `.dll`，注意 `dll` 要和 Python 的位数一致（64 位 Python 配 64 位 dll）

## 3.2 第一个混合程序：编译 C 库，用 Python 调用

现在动手做一件里程碑式的事：**编译一个真正的 C 共享库，然后用 Python 调用它。**

### 3.2.1 写 C 代码

创建 `libfast.c`：

```c
// libfast.c —— 我们的第一个跨语言模块
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

// 1. 简单的加法
int add(int a, int b) {
    return a + b;
}

// 2. 求数组最大值（演示指针）
int array_max(int *arr, int len) {
    if (len <= 0) return 0;
    int max = arr[0];
    for (int i = 1; i < len; i++) {
        if (arr[i] > max) max = arr[i];
    }
    return max;
}

// 3. 字符串反转：返回一个新分配的字符串（演示 malloc）
// 注意：调用方必须用 free_string 释放！
char* reverse_string(const char* s) {
    int len = strlen(s);
    char* result = (char*)malloc(len + 1);  // 调用方负责释放
    for (int i = 0; i < len; i++) {
        result[i] = s[len - 1 - i];
    }
    result[len] = '\0';
    return result;
}

// 4. 配套的释放函数（谁分配谁释放）
void free_string(char* p) {
    free(p);
}

// 5. 打印一句问候（观察输出）
void hello_from_c(void) {
    printf("Hello from C! 这是原生代码在说话。\n");
}
```

### 3.2.2 编译成共享库

```bash
# Linux
gcc -shared -fPIC -O2 libfast.c -o libfast.so

# macOS
gcc -shared -fPIC -O2 libfast.c -o libfast.dylib
# 或 clang -shared -fPIC -O2 libfast.c -o libfast.dylib
```

参数解释：

| 参数 | 含义 |
|------|------|
| `-shared` | 生成共享库（而不是可执行文件） |
| `-fPIC` | Position Independent Code，位置无关代码，共享库必须 |
| `-O2` | 优化级别 2，让编译器生成更快的代码 |
| `-o libfast.so` | 输出文件名 |

Windows（MinGW）:

```bash
gcc -shared -O2 libfast.c -o libfast.dll
```

### 3.2.3 用 Python 调用

创建 `call_fast.py`：

```python
import ctypes
import os

# 根据平台加载正确的库文件
if os.name == 'nt':          # Windows
    lib_name = './libfast.dll'
elif sys.platform == 'darwin':  # macOS
    lib_name = './libfast.dylib'
else:                         # Linux
    lib_name = './libfast.so'

lib = ctypes.CDLL(lib_name)
print(f"已加载库: {lib_name}")

# --- 1. 调用 add ---
lib.add.argtypes = [ctypes.c_int, ctypes.c_int]
lib.add.restype = ctypes.c_int
print(f"add(3, 5) = {lib.add(3, 5)}")

# --- 2. 调用 array_max ---
lib.array_max.argtypes = [ctypes.POINTER(ctypes.c_int), ctypes.c_int]
lib.array_max.restype = ctypes.c_int
ArrType = ctypes.c_int * 5
arr = ArrType(3, 9, 2, 7, 5)
print(f"array_max([3,9,2,7,5]) = {lib.array_max(arr, 5)}")

# --- 3. 调用 reverse_string ---
lib.reverse_string.argtypes = [ctypes.c_char_p]
lib.reverse_string.restype = ctypes.c_void_p  # 返回指针，稍后手动释放
ptr = lib.reverse_string("hello".encode('utf-8'))
reversed_str = ctypes.string_at(ptr).decode('utf-8')
print(f"reverse_string('hello') = '{reversed_str}'")

# 关键：释放 C 分配的内存
lib.free_string.argtypes = [ctypes.c_void_p]
lib.free_string(ptr)
print("已释放 C 侧内存")

# --- 4. 调用 hello_from_c ---
lib.hello_from_c()
```

运行结果：

```
已加载库: ./libfast.so
add(3, 5) = 8
array_max([3,9,2,7,5]) = 9
reverse_string('hello') = 'olleh'
已释放 C 侧内存
Hello from C! 这是原生代码在说话。
```

**恭喜，你完成了第一个跨语言调用！** 虽然细节还很多，但本质就是这个流程：编译库 → 加载库 → 声明签名 → 调用 → 处理内存。

> **注意**：上面代码用了 `sys` 但没 import，这是故意留给你的小练习——运行前加上 `import sys`。这也是编程中常见的坑：跨平台代码别忘了导入所有模块。

## 3.3 头文件与链接：概念澄清

### 3.3.1 头文件（`.h`）的作用

头文件存放函数声明（不写实现），供其他 C/C++ 代码 `#include`。它的作用是**告诉编译器「有这样的函数存在」**。

```c
// libfast.h
#ifndef LIBFAST_H
#define LIBFAST_H

int add(int a, int b);
int array_max(int *arr, int len);
char* reverse_string(const char* s);
void free_string(char* p);

#endif
```

`#ifndef/#define/#endif` 是**include guard**，防止头文件被重复包含导致重复定义错误。

> **小白问：Python 调用 C 库需要头文件吗？**
> 不需要直接 include，但你需要**手动把头文件里的声明翻译成 Python 的类型声明**（就像上面 `argtypes`/`restype` 做的）。cffi 工具可以直接读头文件自动生成绑定，这就是它的优势（第 5 章讲）。

### 3.3.2 链接过程回顾

从第 5 章（C/C++ 卷）我们知道编译分四步：预处理 → 编译 → 汇编 → **链接**。链接器做的事：

1. 把多个目标文件（`.o`）合并
2. 解析符号引用（「这个 `add` 函数的实现在哪？」）
3. 如果是动态链接，记录依赖的库名

生成共享库时，导出的符号必须可见。默认 GCC 会导出所有非 `static` 的函数。可以用 `-fvisibility=hidden` 配合 `__attribute__((visibility("default")))` 精确控制导出哪些符号（安全工具常用，减小攻击面）。

### 3.3.3 动态库搜索路径

Python 加载 `./libfast.so` 用了相对路径，但如果库在系统其他地方，怎么找？

- **Linux**：按 `LD_LIBRARY_PATH` 环境变量、`/etc/ld.so.conf`、默认路径（`/lib`、`/usr/lib`）搜索
- **macOS**：`DYLD_LIBRARY_PATH`、`@rpath`
- **Windows**：可执行文件所在目录、PATH、系统目录

常见问题：「`OSError: libfast.so: cannot open shared object file`」——库不在搜索路径里。解决办法：

1. 用绝对路径或相对路径明确指定（推荐）
2. 设置 `LD_LIBRARY_PATH`
3. Linux 下运行 `sudo ldconfig` 更新缓存

## 3.4 构建工具：从手动编译到自动化

单个文件用 `gcc` 命令就够了，但项目变大后需要构建工具。

### 3.4.1 Makefile 基础

创建 `Makefile`：

```makefile
CC = gcc
CFLAGS = -shared -fPIC -O2 -Wall

all: libfast.so

libfast.so: libfast.c
	$(CC) $(CFLAGS) libfast.c -o libfast.so

clean:
	rm -f libfast.so
```

运行 `make` 编译，`make clean` 清理。`-Wall` 开启所有警告，帮你发现问题。

### 3.4.2 CMake：跨平台构建

CMake 能根据平台生成对应的构建文件（Makefile/VS 工程），是大型项目标配。

创建 `CMakeLists.txt`：

```cmake
cmake_minimum_required(VERSION 3.10)
project(fastlib C)

# 生成共享库
add_library(fast SHARED libfast.c)

# 设置输出名（去掉 lib 前缀的平台上也能统一）
set_target_properties(fast PROPERTIES OUTPUT_NAME "fast")

# 编译时定义宏（可选）
target_compile_definitions(fast PRIVATE FASTLIB_EXPORTS)
```

构建：

```bash
mkdir build && cd build
cmake ..
cmake --build .
# Linux 生成 libfast.so，macOS 生成 libfast.dylib，Windows 生成 fast.dll
```

CMake 的价值：一套配置，多平台编译。pybind11、PyO3 等项目都用 CMake 或类似的构建系统。

### 3.4.3 各语言的构建工具对照

| 语言 | 构建工具 | 产物 |
|------|---------|------|
| C/C++ | make / cmake | `.so`/`.dylib`/`.dll` |
| Cython | setup.py / pyproject.toml | `.so`（Python 扩展） |
| pybind11 | setup.py / cmake | `.so`（Python 扩展） |
| Rust | cargo | `.rlib`/`.so`，maturin 出 wheel |
| Go | go build | 可执行文件或 `.so`（cgo） |

## 3.5 调试混合程序

出 bug 时怎么查？混合程序的调试比单语言复杂，但有一些套路。

### 3.5.1 Python 侧调试

- `print` / `logging` 大法
- `pdb`（Python 调试器）：`python -m pdb script.py`
- 检查 `argtypes`/`restype` 是否声明正确（**90% 的 ctypes bug 源于此**）

### 3.5.2 C 侧调试

用 `gdb` 调试 Python 进程中的 C 代码：

```bash
gdb --args python3 call_fast.py
(gdb) break array_max     # 在 C 函数设断点
(gdb) run                 # 运行
(gdb) bt                  # 查看调用栈
```

macOS 用 `lldb`：

```bash
lldb -- python3 call_fast.py
(lldb) breakpoint set --name array_max
(lldb) run
```

### 3.5.3 常见错误速查

| 错误现象 | 可能原因 | 解决 |
|---------|---------|------|
| `undefined symbol: xxx` | 符号名不对（C++ 名称修饰） | 用 `extern "C"` 导出 |
| `cannot open shared object file` | 库路径不对 | 用绝对路径或设 LD_LIBRARY_PATH |
| 程序崩溃（Segmentation fault） | 参数类型/指针错误、越界 | 检查 argtypes，用 gdb 定位 |
| 返回值是乱码 | restype 没声明或声明错 | 设置正确 restype |
| 结果偶尔错、偶尔对 | 内存被破坏（溢出/UAF） | 用 AddressSanitizer 检测 |
| 字符串是乱码 | 编码不匹配 | UTF-8 编解码，检查 `\0` |

### 3.5.4 AddressSanitizer：内存错误检测器

编译 C 库时加 `-fsanitize=address`，能自动检测缓冲区溢出、UAF：

```bash
gcc -shared -fPIC -fsanitize=address -g libfast.c -o libfast_asan.so
```

运行时如果发生内存错误，会打印详细报告（哪一行、什么类型的错误）。这是安全开发的利器，第 10 章（安全卷）会深入用。

## 3.6 跨平台注意事项

### 3.6.1 库文件命名

| 平台 | 动态库 | 静态库 |
|------|--------|--------|
| Linux | `libxxx.so` | `libxxx.a` |
| macOS | `libxxx.dylib` | `libxxx.a` |
| Windows | `xxx.dll` (+ `xxx.lib` 导入库) | `xxx.lib` |

### 3.6.2 调用约定差异

Windows x86-64 用 `rcx/rdx/r8/r9` 传参，Linux/macOS 用 `rdi/rsi/rdx/...`。用工具（ctypes/pybind11）时它们会处理，但你写的 C 代码如果用了 `__stdcall` 等非默认约定，要特别小心。

### 3.6.3 路径分隔符

Python 里用 `os.path.join()` 或 `pathlib.Path` 拼路径，别硬编码 `/` 或 `\`。

### 3.6.4 数据类型大小

再次强调：`long` 在 Linux 是 8 字节、Windows 是 4 字节。跨平台代码用 `<stdint.h>` 的 `int32_t`/`int64_t` 明确宽度。
