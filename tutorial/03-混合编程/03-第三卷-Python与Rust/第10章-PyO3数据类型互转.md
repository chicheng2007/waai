# 第 10 章 PyO3 数据类型互转

## 本章目标

读完这一章，你将能够：

- 深入理解 PyO3 的类型转换机制（`FromPyObject` 与 `IntoPy`）
- 高效处理字符串（避免不必要的拷贝）
- 处理列表、元组、字典、集合的转换
- 用 `PyObject` 和 `PyAny` 操作任意 Python 对象
- 与 numpy 数组互操作（零拷贝 buffer 协议）
- 在 Rust 里调用 Python 函数、访问 Python 模块
- 理解 GIL 与 `Python<'py>` 令牌的作用

## 10.1 类型转换的底层机制

PyO3 的类型转换靠两个 trait：

- **`FromPyObject`**：Python 对象 → Rust 类型（函数参数）
- **`IntoPy<PyObject>`**：Rust 类型 → Python 对象（函数返回值）

当你写：

```rust
#[pyfunction]
fn process(items: Vec<i64>) -> Vec<i64> { ... }
```

PyO3 在编译时生成代码：调用方传入的 Python `list` 通过 `FromPyObject` 转成 `Vec<i64>`；返回的 `Vec<i64>` 通过 `IntoPy` 转成 Python `list`。

### 10.1.1 转换的拷贝代价

理解拷贝对性能很重要：

| 转换 | 是否拷贝 |
|------|---------|
| Python `int` → `i64` | 值复制（小，快） |
| Python `str` → `String` | **拷贝**（UTF-8 内容复制） |
| Python `list` → `Vec<T>` | **逐元素拷贝** |
| Python `bytes` → `Vec<u8>` | **拷贝** |
| Python 对象 → `PyObject` | 只增加引用计数（无内容拷贝） |

**大数据的转换开销可能超过计算本身**。这就是本章要解决的：如何在必要时避免拷贝。

## 10.2 字符串处理：避免拷贝

### 10.2.1 String vs &str vs PyString

```rust
use pyo3::prelude::*;
use pyo3::types::PyString;

// 方式一：String（会拷贝到 Rust 的 String）
#[pyfunction]
fn upper_owned(s: String) -> String {
    s.to_uppercase()
}

// 方式二：&str（还是拷贝，但从 Python str 的 UTF-8 借用）
#[pyfunction]
fn upper_borrow(s: &str) -> String {
    s.to_uppercase()
}

// 方式三：&PyString（不拷贝内容，直接操作 Python 字符串对象）
#[pyfunction]
fn upper_pystring(s: &PyString) -> PyResult<String> {
    let rust_str = s.to_str()?;  // 这里借用，不拷贝
    Ok(rust_str.to_uppercase())
}
```

`&PyString` 让你拿到 Python 字符串对象的引用，`to_str()` 返回 `&str` 借用（底层是 Python 字符串的 UTF-8 表示）。只有当你需要拥有数据时才拷贝。

### 10.2.2 Cow：按需拷贝

```rust
use std::borrow::Cow;

#[pyfunction]
fn maybe_upper(s: &str) -> Cow<str> {
    if s.chars().all(|c| !c.is_lowercase()) {
        Cow::Borrowed(s)   // 无需改动，直接借用
    } else {
        Cow::Owned(s.to_uppercase())  // 需要改动才拷贝
    }
}
```

`Cow`（Clone on Write）在不需要修改时避免拷贝。

### 10.2.3 返回字符串

```rust
#[pyfunction]
fn concat(a: &str, b: &str) -> String {
    format!("{}{}", a, b)  // 返回 String → Python str（拷贝，不可避免）
}
```

返回给 Python 时必须创建新 Python 字符串对象，拷贝不可避免。大量字符串返回时要考虑批量（一次返回 list）。

## 10.3 容器类型转换

### 10.3.1 Vec 与 list

```rust
#[pyfunction]
fn double_list(nums: Vec<i64>) -> Vec<i64> {
    nums.into_iter().map(|x| x * 2).collect()
}
```

注意 `nums` 是从 Python list **拷贝**来的 `Vec`，修改它不影响原 Python list。返回新 `Vec` 又拷贝回 Python list。

### 10.3.2 tuple

```rust
#[pyfunction]
fn split_sum(pair: (i64, i64)) -> i64 {
    pair.0 + pair.1
}
```

Python 调用：`split_sum((3, 5))`。

### 10.3.3 HashMap 与 dict

```rust
use std::collections::HashMap;

#[pyfunction]
fn invert_map(m: HashMap<String, i64>) -> HashMap<i64, String> {
    m.into_iter().map(|(k, v)| (v, k)).collect()
}
```

Python dict → Rust HashMap（拷贝）→ 处理 → Python dict（拷贝）。

### 10.3.4 HashSet 与 set

```rust
use std::collections::HashSet;

#[pyfunction]
fn unique(items: Vec<String>) -> HashSet<String> {
    items.into_iter().collect()
}
```

### 10.3.5 Option 与 None

```rust
#[pyfunction]
fn first_or_none(items: Vec<i64>) -> Option<i64> {
    items.first().copied()  // 空列表 → None
}
```

Python：`first_or_none([])` → `None`。

## 10.4 用 PyObject / PyAny 操作任意对象

有时候你不知道传入的是什么类型，或者需要动态调用 Python 对象的方法。这时用 `PyObject`（拥有引用）和 `PyAny`（借用视图）。

### 10.4.1 PyAny 基础

```rust
use pyo3::prelude::*;

#[pyfunction]
fn describe(obj: &PyAny) -> PyResult<String> {
    // 获取对象的类型名
    let type_name = obj.get_type().name()?;
    // 转成字符串表示
    let repr = obj.repr()?;
    Ok(format!("类型: {}, 表示: {}", type_name, repr.to_str()?))
}
```

### 10.4.2 类型判断与Extract

```rust
use pyo3::prelude::*;

#[pyfunction]
fn process_dynamic(obj: &PyAny) -> PyResult<String> {
    // 尝试提取为 i64
    if let Ok(n) = obj.extract::<i64>() {
        return Ok(format!("整数: {}", n));
    }
    // 尝试提取为 String
    if let Ok(s) = obj.extract::<String>() {
        return Ok(format!("字符串: {}", s));
    }
    Ok("其他类型".to_string())
}
```

`extract::<T>()` 尝试把 `PyAny` 转成具体 Rust 类型，失败返回 Err。

### 10.4.3 调用对象的方法

```rust
#[pyfunction]
fn call_upper(obj: &PyAny) -> PyResult<String> {
    // 调用 Python 对象的 upper() 方法
    let result = obj.call_method0("upper")?;
    result.extract::<String>()
}
```

### 10.4.4 访问属性

```rust
#[pyfunction]
fn get_attr(py: Python, module_name: &str, attr: &str) -> PyResult<PyObject> {
    let module = py.import(module_name)?;
    let value = module.getattr(attr)?;
    Ok(value.into_py(py))  // 转成 PyObject 拥有引用
}
```

## 10.5 `Python<'py>` 令牌与 GIL

你会注意到很多 PyO3 函数第一个参数是 `py: Python`。这是 **GIL 令牌**，表示当前线程持有 GIL。

### 10.5.1 为什么需要它

PyO3 用类型系统保证：**要操作 Python 对象，必须持有 GIL**。`Python<'py>` 就是持有 GIL 的证明。没有它，无法调用大多数 Python API。

### 10.5.2 获取 GIL

如果函数没声明 `py: Python` 参数，可以手动获取：

```rust
use pyo3::prelude::*;

fn rust_internal_function() {
    Python::with_gil(|py| {
        // 这里持有 GIL，可以操作 Python 对象
        let sys = py.import("sys").unwrap();
        // ...
    });
}
```

### 10.5.3 释放 GIL

长时间纯 Rust 计算时应释放 GIL，让其他 Python 线程运行：

```rust
#[pyfunction]
fn heavy_compute(n: u64) -> u64 {
    pyo3::Python::with_gil(|py| {
        py.allow_threads(|| {
            // 这里 GIL 已释放，不能碰 Python 对象
            (0..n).sum()
        })
    })
}
```

`py.allow_threads(|| {...})` 释放 GIL 执行闭包，结束后自动重新获取。**第 12 章会深入讲 GIL 与性能**。

## 10.6 numpy 数组：零拷贝互操作

numpy 数组是 Python 科学计算的核心。PyO3 可以通过 `numpy` crate 或 buffer 协议操作它。

### 10.6.1 用 numpy crate

Cargo.toml：

```toml
[dependencies]
pyo3 = { version = "0.20", features = ["extension-module"] }
numpy = "0.20"
```

代码：

```rust
use numpy::{PyArray1, PyReadonlyArray1};
use pyo3::prelude::*;

/// 数组求和（零拷贝读取）
#[pyfunction]
fn array_sum(arr: PyReadonlyArray1<f64>) -> f64 {
    let slice = arr.as_slice().unwrap();  // 借用 numpy 数组内存，零拷贝
    slice.iter().sum()
}

/// 数组缩放（返回新数组）
#[pyfunction]
fn array_scale<'py>(py: Python<'py>, arr: PyReadonlyArray1<f64>, factor: f64)
    -> &'py PyArray1<f64>
{
    let slice = arr.as_slice().unwrap();
    let result: Vec<f64> = slice.iter().map(|x| x * factor).collect();
    PyArray1::from_vec(py, result)  // 转成 numpy 数组返回
}
```

```python
import numpy as np
import fastlib

arr = np.array([1.0, 2.0, 3.0, 4.0])
print(fastlib.array_sum(arr))        # 10.0
print(fastlib.array_scale(arr, 2.0)) # [2. 4. 6. 8.]
```

`PyReadonlyArray1` 直接借用 numpy 数组的内存（零拷贝），适合读取。

### 10.6.2 可写数组

```rust
use numpy::PyArray1;

#[pyfunction]
fn array_scale_inplace(arr: &PyArray1<f64>, factor: f64) {
    unsafe {
        let slice = arr.as_slice_mut().unwrap();  // 需要 unsafe
        for x in slice.iter_mut() { *x *= factor; }
    }
}
```

原地修改 numpy 数组需要 `unsafe`（因为 Rust 无法保证 Python 侧没有其他引用）。**务必确保调用时没有别名冲突**，否则数据竞争。

> **安全提醒**：`unsafe` 是 Rust 里绕过编译器检查的逃生舱。用它能做 Zero-copy 等高性能操作，但正确性由程序员保证。安全关键代码中要严格控制 unsafe 范围并充分测试。

## 10.7 实战：Rust 里调用 Python 函数

混合编程不只是「Python 调 Rust」，有时也需要「Rust 调 Python」。比如 Rust 做核心逻辑，但某些规则/模型用 Python。

```rust
use pyo3::prelude::*;

#[pyfunction]
fn apply_python_rule(py: Python, rule_func: PyObject, value: i64) -> PyResult<bool> {
    // 调用 Python 传入的函数
    let result = rule_func.call1(py, (value,))?;
    result.extract(py)
}
```

Python 侧：

```python
import fastlib

def is_malicious(port):
    return port in [23, 445, 3389]

print(fastlib.apply_python_rule(is_malicious, 3389))  # True
print(fastlib.apply_python_rule(is_malicious, 80))    # False
```

这展示了 PyO3 的双向能力：**Rust 可以调用任意 Python 对象**，包括函数、类、模块。

## 10.8 内存与所有权边界（复习第 2 章）

结合第 2 章的心法，看 PyO3 如何处理内存边界：

| 场景 | PyO3 的做法 | 安全性 |
|------|------------|--------|
| Python list → Rust Vec | 逐元素拷贝成 Rust 拥有 | 安全，但有拷贝开销 |
| `&PyString` | 借用 Python 对象引用 | 安全，但需在 GIL 内使用 |
| numpy 零拷贝 | 借用内存（`PyReadonlyArray`） | 安全（只读） |
| numpy 原地修改 | `unsafe` + `as_slice_mut` | 程序员负责正确性 |
| 返回 Rust 数据 | 转成 Python 对象（拷贝） | 安全 |

**PyO3 的整体设计哲学**：默认安全（拷贝或借用检查），高性能操作需要显式 `unsafe` 或特定类型。这比 C API 的「默认不安全」进步巨大。

## 10.9 本章总结

| 知识点 | 内容 |
|--------|------|
| 转换机制 | `FromPyObject`（入）、`IntoPy`（出）；注意拷贝代价 |
| 字符串 | `String` 拷贝、`&PyString` 借用、`Cow` 按需拷贝 |

| 动态对象 | `PyObject`/`PyAny`、`extract`、`call_method0`、`getattr` |

| numpy | `PyReadonlyArray1` 零拷贝读；`as_slice_mut` 需 unsafe |
| 反向调用 | Rust 用 `call1` 调 Python 函数 |
| 内存边界 | 默认安全（拷贝/借用），高性能操作显式 unsafe |
