## 20.1 项目愿景：Sentinel 多语言 AI 安全平台

我们要设计一个名为 **Sentinel** 的平台，目标是：

> 在终端/网络上采集事件 → 高性能检测 → AI 智能分析 → 自动响应与报告

这是一个真实安全产品（EDR/NDR/SOC 平台）的缩影。它天然需要多种语言：

- **Go**：端侧采集 agent（单二进制部署、并发、跨平台）
- **Rust**：检测引擎（内存安全处理不可信数据、高性能规则匹配）
- **Python**：云端 AI 分析平台（模型、编排、API、报告）
- **C++**：极致性能的算子（如加密解密、协议解析、SIMD 计算）

```
│ - eBPF/日志采集 │  ───────> │ - 规则匹配        │ ───────> │ - 协议解析        │
│ - 并发上报      │  进程内   │ - 威胁打分        │  进程内  │ - 加密/SIMD       │
│ - 单二进制      │  (cgo/    │ - 内存安全        │ (FFI/   │ - 批处理          │
│                │  共享库)  │                  │ PyO3)   │                  │
└────────────────┘           └──────────────────┘          └──────────────────┘
```

**数据流**：

1. Go agent 在终端采集进程/网络事件
2. 本地调用 Rust 检测引擎做实时规则匹配（进程内，低延迟）
3. 可疑事件通过 gRPC/Kafka 上报到云端
4. Python 平台用 AI 模型做深度分析、关联、告警
5. 需要极致性能的操作（解密、特征提取）调用 C++ 算子
6. 结果入库、生成报告、触发响应

## 20.3 组件一：Go 采集 Agent

### 20.3.1 职责与选型理由

- **职责**：采集系统事件、轻量过滤、可靠上报
- **为什么 Go**：单二进制部署（末端机器无需 runtime）、goroutine 高并发、跨平台、网络编程强

### 20.3.2 核心骨架

```go
// agent/main.go
package main

import (
    "context"
    "log"
    "os"
    "os/signal"
    "sync"
    "syscall"
    "time"
)

type Event struct {
    Timestamp int64
    Type      string
    Source    string
    Data      string
}

type Agent struct {
    events  chan Event
    batch   []Event
    mu      sync.Mutex
    endpoint string
}

func NewAgent(endpoint string) *Agent {
    return &Agent{
        events: make(chan Event, 1000),
        endpoint: endpoint,
    }
}

// 采集循环（演示用模拟数据，实际接 eBPF/日志）
func (a *Agent) Collect(ctx context.Context) {
    ticker := time.NewTicker(100 * time.Millisecond)
    defer ticker.Stop()
    for {
        select {
        case <-ctx.Done():
            return
        case <-ticker.C:
            a.events <- Event{
                Timestamp: time.Now().Unix(),
                Type: "network",
                Source: "eth0",
                Data: "192.168.1.1:443",
            }
        }
    }
}

// 批量上报（减少网络调用）
func (a *Agent) Report(ctx context.Context) {
    ticker := time.NewTicker(5 * time.Second)
    defer ticker.Stop()
    for {
        select {
        case <-ctx.Done():
            return
        case ev := <-a.events:
            a.mu.Lock()
            a.batch = append(a.batch, ev)
            a.mu.Unlock()
        case <-ticker.C:
            a.flush()
        }
    }
}

func (a *Agent) flush() {
    a.mu.Lock()
    batch := a.batch
    a.batch = nil
    a.mu.Unlock()
    if len(batch) == 0 { return }
    // 实际：gRPC 上报到云端（见第 15 章）
    log.Printf("上报 %d 条事件", len(batch))
}

func main() {
    ctx, cancel := context.WithCancel(context.Background())
    defer cancel()

    agent := NewAgent("cloud:50051")
    var wg sync.WaitGroup
    wg.Add(2)
    go func() { defer wg.Done(); agent.Collect(ctx) }()
    go func() { defer wg.Done(); agent.Report(ctx) }()

    // 优雅退出
    sig := make(chan os.Signal, 1)
    signal.Notify(sig, syscall.SIGINT, syscall.SIGTERM)
    <-sig
    cancel()
    wg.Wait()
    log.Println("Agent 已退出")
}
```

**部署**：`go build` 得到单个二进制，拷贝到目标机器即可运行（第 10 章讲过 Go 的单二进制优势）。

## 20.4 组件二：Rust 检测引擎

### 20.4.1 职责与选型理由

- **职责**：对采集的事件做实时规则匹配和威胁打分
- **为什么 Rust**：处理不可信数据（攻击者构造的事件），内存安全是硬需求；高性能；可嵌入 Go agent（通过 cgo）也可作为独立服务

### 20.4.2 核心骨架（PyO3 暴露给 Python，也可用 cgo 给 Go）

```rust
// engine/src/lib.rs
use pyo3::prelude::*;
use std::collections::HashSet;

#[pyclass]
struct DetectionEngine {
    blacklist_ips: HashSet<String>,
    suspicious_ports: HashSet<u16>,
}

#[pymethods]
impl DetectionEngine {
    #[new]
    fn new() -> Self {
        let mut suspicious_ports = HashSet::new();
        for p in [23, 445, 3389, 1433, 3306] { suspicious_ports.insert(p); }
        DetectionEngine {
            blacklist_ips: HashSet::new(),
            suspicious_ports,
        }
    }

    fn add_blacklist_ip(&mut self, ip: String) {
        self.blacklist_ips.insert(ip);
    }

    /// 批量检测事件，返回可疑事件索引
    fn detect(&self, events: Vec<(String, String, String)>) -> Vec<usize> {
        pyo3::Python::with_gil(|py| {
            py.allow_threads(|| {
                events.iter().enumerate()
                    .filter_map(|(i, (src, dst, data))| {
                        if self.blacklist_ips.contains(src)
                           || self.blacklist_ips.contains(dst)
                           || data.contains("malware") {
                            Some(i)
                        } else { None }
                    })
                    .collect()
            })
        })
    }

    /// 威胁打分（0-100）
    fn threat_score(&self, event: (String, String, String)) -> u8 {
        let (src, dst, data) = event;
        let mut score = 0u8;
        if self.blacklist_ips.contains(&src) { score += 50; }
        if self.blacklist_ips.contains(&dst) { score += 50; }
        if data.contains("malware") { score += 30; }
        score.min(100)
    }
}

#[pymodule]
fn engine(_py: Python, m: &PyModule) -> PyResult<()> {
    m.add_class::<DetectionEngine>()?;
    Ok(())
}
```

**双重暴露**：同一个 Rust 引擎，既能通过 PyO3 给 Python 用，也能通过 cgo/共享库给 Go agent 用（第 14 章的技术）。这就是混合架构的灵活之处。

## 20.5 组件三：Python AI 分析平台

### 20.5.1 职责与选型理由

- **职责**：接收上报事件、AI 深度分析、告警、报告、API
- **为什么 Python**：AI 生态（PyTorch/Transformers）、FastAPI 快速开发、数据处理生态

### 20.5.2 核心骨架

```python
# platform/app.py
from fastapi import FastAPI, BackgroundTasks
from pydantic import BaseModel
from typing import List
import engine  # Rust 检测引擎
from ai_model import ThreatClassifier  # AI 模型
import asyncio

app = FastAPI(title="Sentinel AI 安全平台")

# 初始化组件
detector = engine.DetectionEngine()
detector.add_blacklist_ip("10.0.0.99")
classifier = ThreatClassifier()  # 加载 AI 模型

class EventBatch(BaseModel):
    events: List[dict]

@app.post("/ingest")
async def ingest(batch: EventBatch, background_tasks: BackgroundTasks):
    """接收 agent 上报的事件"""
    # 1. Rust 引擎快速检测
    tuples = [(e['src'], e['dst'], e['data']) for e in batch.events]
    suspicious = detector.detect(tuples)

    # 2. AI 深度分析（后台任务，不阻塞响应）
    flagged = [batch.events[i] for i in suspicious]
    background_tasks.add_task(analyze_and_alert, flagged)

    return {"received": len(batch.events), "suspicious": len(suspicious)}

async def analyze_and_alert(events):
    """AI 分析 + 告警"""
    for event in events:
        score = classifier.predict(event)
        if score > 0.8:
            await send_alert(event, score)

async def send_alert(event, score):
    """发送告警（演示）"""
    print(f"[ALERT] 威胁分数 {score:.2f}: {event}")

@app.get("/health")
async def health():
    return {"status": "ok", "components": ["rust-engine", "ai-model"]}
```

```python
class ThreatClassifier:
    def __init__(self):

        # self.model = torch.load("threat_model.pt")
        pass

    def predict(self, event: dict) -> float:
        # 特征提取（可调用 C++ 算子加速）
        data = event.get('data', '')
        features = self._extract_features(data)
        # 实际：self.model.predict(features)
```

## 20.6 组件四：C++ 高性能算子

### 20.6.1 职责与选型理由

- **职责**：极致性能的底层操作（加密解密、协议解析、大批量特征计算）
- **为什么 C++**：AI 框架生态（PyTorch C++）、成熟的加密库、SIMD 控制

### 20.6.2 示例：批量特征提取算子

```cpp
// ops.cpp
#include <pybind11/pybind11.h>
#include <pybind11/numpy.h>
#include <vector>

namespace py = pybind11;

// 批量计算事件的统计特征（SIMD 友好的连续循环）
py::array_t<double> batch_features(py::array_t<double> data) {
    auto buf = data.request();
    double* ptr = static_cast<double*>(buf.ptr);
    ssize_t n = buf.size;

    // 每 4 个值一组计算特征（演示）
    ssize_t out_n = n / 4;
    py::array_t<double> result(out_n);
    double* out = static_cast<double*>(result.request().ptr);

    for (ssize_t i = 0; i < out_n; i++) {
        double sum = ptr[i*4] + ptr[i*4+1] + ptr[i*4+2] + ptr[i*4+3];
        double max = ptr[i*4];
        for (int j = 1; j < 4; j++)
            if (ptr[i*4+j] > max) max = ptr[i*4+j];
        out[i] = sum / 4.0 + max;
    }
    return result;
}

PYBIND11_MODULE(ops, m) {
    m.def("batch_features", &batch_features, "批量特征提取");
}
```

## 20.11 混合系统故障排查速查表

多语言系统出错时，最难的是「不知道是哪一层出的问题」。这张表按现象帮你快速定位。

| 现象 | 最可能的层 | 排查方法 |
|------|-----------|---------|
| `ImportError: cannot import name xxx` | 绑定/打包 | 检查扩展模块是否编译、模块名是否匹配、`maturin develop` 是否执行 |
| `undefined symbol` | ABI/链接 | `nm -D lib.so` 查符号；C++ 用 `extern "C"`；检查依赖库 |
| Segmentation fault | 内存边界 | 参数类型错误、指针越界、UAF；用 gdb + AddressSanitizer |
| 结果数值错误但不崩溃 | 类型映射 | 检查 `argtypes`/`restype`；结构体对齐；字节序 |
| 程序莫名卡顿 | GIL/死锁 | 检查释放 GIL 的闭包是否碰了 Python 对象；回调锁顺序 |
| 内存持续增长 | 所有权 | C/Rust 分配的没释放；检查 `C.free`/`FreeString`/句柄 close |
| 中文乱码 | 编码 | UTF-8 编解码；C 字符串 `\0` 截断问题 |
| 只在某平台出错 | 平台差异 | int/long 大小、库扩展名、调用约定、路径分隔符 |
| 多线程偶发崩溃 | 数据竞争 | `go run -race`；Rust 检查 `unsafe` 块；Go 的 CGO 指针规则 |
| 性能不如预期 | 边界开销 | flamegraph；检查是否在循环里跨边界；是否拷贝了大数据 |

### 分层定位流程

1. **先确定哪一层**：给 Python / FFI 边界 / 核心各打一个时间点，看时间花在哪
2. **缩小到函数**：用 cProfile（Python）+ perf/flamegraph（系统级）
3. **复现最小化**：写一个最小复现脚本，去掉无关逻辑
4. **查边界**：90% 的混合 bug 在类型声明和内存边界
5. **验证修复**：加一个回归测试，防止再犯

## 本章练习（也是全套教程的最终挑战）

1. 按第 20 章的架构，搭建一个最小可运行的 Sentinel 原型（可以先只用 Python + Rust）。
2. 逐步加入 Go agent 和 C++ 算子，每加一个组件都写清楚理由（ADR）。
3. 为每个组件写测试，特别是跨语言边界的集成测试。
4. 用 flamegraph 分析整个系统，找出真实瓶颈并优化。
5. 写一份完整的项目文档：架构图、接口契约、部署指南、合规声明。
6. 把项目放到 GitHub，写好 README，让它成为你的作品集。
