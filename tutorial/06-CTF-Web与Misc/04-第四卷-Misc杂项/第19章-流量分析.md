# 第 19 章 流量分析：从 pcap 里挖出 flag

## 本章目标

读完这一章，你将能够：

- 理解 pcap 文件是什么、流量分析题在考什么
- 用 Wireshark 打开并浏览流量包
- 使用显示过滤器（display filter）精准定位数据包
- 掌握协议分层分析（TCP/UDP/HTTP/DNS）
- 追踪 TCP/UDP 流、提取传输的文件
- 应对常见流量题型（HTTP 传文件、DNS 隧道、USB 流量）

> 流量分析是 Misc 方向的经典题型：给你一个 `.pcap` 文件（网络抓包记录），让你从成千上万的数据包里找出 flag。它考的是"读懂网络通信"的能力——这和第 4 章的 HTTP 知识是贯通的。

---

## 19.1 什么是 pcap

pcap（Packet Capture）是网络抓包的文件格式，记录了网络上传输的每一个数据包的原始内容。Wireshark 打开它，能看到完整的通信过程。

**CTF 里的流量题**：出题人抓取（或构造）一段网络流量，把 flag 藏在里面——可能是一次 HTTP 请求的参数、一个传输的文件、DNS 查询的域名、USB 键盘的按键数据……

**任务**：从海量数据包里找到藏 flag 的那一个。

**小白问：flag 会怎么藏在流量里？**
> 形式多样：HTTP POST 上传了一个 flag.txt；某个 TCP 流里传了一段 Base64；DNS 查询的域名拼起来是 flag；甚至有人敲键盘的 USB 流量，能还原出输入的密码。这一年考不出花样。

## 19.2 Wireshark 基础操作

### 19.2.1 打开与界面

用 Wireshark 打开 pcap 文件，界面主要分三块：

| 区域 | 内容 |
|------|------|
| **Packet List**（顶部） | 所有数据包的列表：编号、时间、源地址、目的地址、协议、长度、简要信息 |
| **Packet Details**（中部） | 选中数据包的详细分层信息（物理层→以太网→IP→TCP→应用层） |
| **Packet Bytes**（底部） | 数据包的原始十六进制字节和 ASCII |

### 19.2.2 显示过滤器（核心技能）

流量包常有成千上万个包，必须用过滤器定位。在过滤栏输入表达式：

| 过滤器 | 含义 |
|--------|------|
| `http` | 只看 HTTP 包 |
| `dns` | 只看 DNS 包 |
| `tcp` / `udp` | 只看 TCP/UDP |
| `ip.src == 192.168.1.1` | 源 IP 是某地址 |
| `ip.dst == ...` | 目的 IP |
| `tcp.port == 80` | 端口 80 |
| `http.request` | HTTP 请求 |
| `http.response.code == 200` | 状态码 200 |
| `http contains "flag"` | 内容含 flag |
| `tcp contains "flag"` | TCP 内容含 flag |
| `frame contains "CTF"` | 任意位置含 CTF |

**组合**：`http && ip.src==192.168.1.1`、`tcp contains "flag" || dns`。

**快速技巧**：在 Packet Details 里右键某个字段 → "Prepare as Filter" → "Selected"，Wireshark 自动生成过滤表达式——新手神器。

### 19.2.3 追踪流（Follow Stream）

找到关键包后，右键 → **Follow → TCP Stream**（或 UDP Stream），能看到这次完整会话的双向通信内容（把分散的包拼成完整对话）。flag 常在这里直接显示。

## 19.3 常见题型与解法

### 19.3.1 题型一：HTTP 传输文件

**特征**：流量里有 HTTP POST 请求，或返回了一个文件。

**解法**：
1. 过滤 `http`
2. 找可疑请求（如 POST 到 `/upload`，或 GET 一个 `flag.txt`）
3. Follow TCP Stream 看内容
4. 或用 Wireshark 的 **File → Export Objects → HTTP**，直接导出传输的文件

**例子**：某 HTTP 响应体是一张图片，导出后发现图片里有 flag（结合第 17 章隐写）。

### 19.3.2 题型二：明文传输的 flag

**解法**：用过滤器搜关键词：

```
tcp contains "flag"
http contains "flag"
frame contains "CTF{"
```

直接在所有内容里搜 flag 字样——很多简单题就这么直接。

### 19.3.3 题型三：DNS 隧道 / DNS 查询泄露

**特征**：大量 DNS 查询，域名很奇怪（如 `a1b2.attacker.com`）。

**解法**：
1. 过滤 `dns`
2. 看查询的域名，把子域名部分按顺序拼起来，可能是编码的 flag
3. 例如 `flag{abc}.evil.com` 这种直接泄露，或每个查询的一个字符拼起来

### 19.3.4 题型四：TCP 流里的编码数据

**解法**：
1. Follow TCP Stream
2. 看到 Base64/Hex 字符串 → 用第 16 章方法解码
3. 有时数据分片在多个包里，要按序号拼接

### 19.3.5 题型五：USB 流量（键盘记录）

**特征**：协议是 USB，数据是**USB HID**（人机接口设备）的按键报告。

**解法**：USB 键盘流量里，每个数据包记录一个按键（8 字节的中断传输）。要按 USB HID 协议把按键码映射成字符——手工麻烦，用脚本：

```python
# 用 tshark 提取 USB 数据，再按 HID 映射表还原按键
tshark -r usb.pcap -Y "usb.capdata" -T fields -e usb.capdata > keys.txt
# 写脚本把 capdata 映射为字符
```

网上有现成的 USB 键盘流量解密脚本，CTF 里遇到直接找脚本改。

### 19.3.6 题型六：WiFi / 蓝牙流量

进阶题型，可能涉及 WPA 握手包爆破（用 aircrack-ng）、蓝牙数据解析。作为入门了解即可。

## 19.4 tshark：命令行流量分析

Wireshark 的命令行版，适合脚本化和批量处理：

```bash
# 读取 pcap，应用过滤器，输出指定字段
tshark -r traffic.pcap -Y "http" -T fields -e http.request.uri

# 提取所有 DNS 查询域名
tshark -r traffic.pcap -Y "dns.qry.name" -T fields -e dns.qry.name

# 提取 TCP 流内容
tshark -r traffic.pcap -q -z follow,tcp,ascii,0
```

当你需要处理大量数据或自动化时，tshark + Python 脚本比 GUI 高效。

## 19.5 排查流程

```
① 用 Wireshark 打开 pcap，看 Packet List 整体：有哪些协议？多少包？
② 用统计功能（Statistics → Protocol Hierarchy）看协议分布，找异常协议
③ 搜关键词：tcp/http contains "flag"/"CTF"/"key"
④ 按协议深入：
   - http → Export Objects 导文件 / Follow Stream
   - dns → 看查询域名
   - tcp → Follow Stream 看编码数据
   - usb → 脚本还原按键
⑤ 提取的数据 → 结合第 16 章解码 / 第 17 章隐写 / 第 18 章文件分析
⑥ 拿到 flag
```

**关键**：先看全局（协议分布）再深入，别一上来就逐包看——那是大海捞针。

## 19.5 深度拓展：协议细节与进阶流量题型

19.1–19.5 覆盖了流量题的主流解法。这一节深入协议层，补充一些进阶题型的处理思路。

### 19.5.1 理解 TCP 三次握手与流编号

Wireshark 里每个 TCP 连接都有编号（Stream 0、Stream 1……）。理解 TCP 连接生命周期有助于分析：

```
1. 客户端 → 服务器：SYN（我要连接）
2. 服务器 → 客户端：SYN-ACK（同意）
3. 客户端 → 服务器：ACK（确认）—— 连接建立
... 数据传输 ...
4. FIN / RST —— 连接关闭
```

**CTF 意义**：
- 如果一个连接只有 SYN 没有后续（SYN flood  scans），是扫描行为
- Follow TCP Stream 的编号对应这些连接——按编号逐个查看，找有数据的那个
- RST 异常关闭可能表示连接被拦截或出错

### 19.5.2 HTTP 流量深入

**导出文件的完整方法**：

```
Wireshark 菜单 → File → Export Objects → HTTP
→ 列表里是所有 HTTP 传输的文件（图片、脚本、文档）
→ 按 Content-Type 或 Size 排序，找可疑的
→ Save All 或单独保存
```

**重建请求/响应**：Follow TCP Stream 后，可以看到完整的请求+响应文本。如果传输的是 Base64 数据，直接复制出来解码（第 16 章）。

**分块传输（Chunked）**：HTTP 用 `Transfer-Encoding: chunked` 时，数据被分成多块。Wireshark 会自动重组，但手动分析原始字节时要理解 chunk 格式（每块前面是十六进制长度）。

### 19.5.3 DNS 隧道详解

DNS 隧道是把数据藏在 DNS 查询的域名里。识别特征：

- 大量查询同一个主域名（如 `xxx.evil.com`）
- 子域名部分很长很随机（如 `a3f9c2e1b7.evil.com`）
- 查询类型可能是 TXT、NULL 等非常见类型

**提取方法**：

```bash
# 提取所有 DNS 查询域名
tshark -r traffic.pcap -Y "dns.qry.name" -T fields -e dns.qry.name > domains.txt

# 过滤出可疑域名，取子域部分拼起来
grep "evil.com" domains.txt | cut -d. -f1 | tr -d '\n'
# 拼出来可能是 Base64/Hex 编码的 flag
```

**注意**：DNS 查询的域名不区分大小写，且长度有限制（单标签 63 字符，总长 253 字符），所以大数据要分片传——按序号拼接。

### 19.5.4 TLS/HTTPS 流量

如果流量是加密的（TLS），直接看不到内容。但 CTF 里可能：

- **提供了密钥日志文件**（SSLKEYLOGFILE）：Wireshark 配置后能解密
  ```
  Edit → Preferences → Protocols → TLS → (Pre)-Master-Secret log filename → 选 key 文件
  ```
- **加密前的握手信息泄露**：证书里可能有组织名等线索
- **题目其实考的是"识别哪些是加密流量"**——排除法找到明文的那部分

### 19.5.5 USB 键盘流量深入

USB HID 键盘的每个按键报告是 8 字节：

```
字节 0: modifier（Shift/Ctrl/Alt 等）
字节 2: 按键码（keycode）
```

**解码流程**：用 tshark 提取 `usb.capdata`，按 HID keycode 映射表（0x04=a, 0x05=b...）转成字符。

```python
# 简化示例
keycodes = {
    0x04:'a', 0x05:'b', 0x06:'c', 0x07:'d', 0x08:'e', 0x09:'f',
    0x0a:'g', 0x0b:'h', 0x0c:'i', 0x0d:'j', 0x0e:'k', 0x0f:'l',
    # ... 完整表网上可查
}
# 读 tshark 导出的 capdata，第 3 个字节（index 2）查表
```

**Shift 组合**：如果 modifier 字节含 0x02（左 Shift），字母要大写。

### 19.5.6 无线流量（WiFi）

进阶题型可能给 WiFi 抓包：

- **WPA/WPA2 握手包**：用 aircrack-ng + 字典爆破 WiFi 密码
  ```bash
  aircrack-ng -w wordlist.txt capture.cap
  ```
- **破解后解密流量**：Wireshark 配置 WPA 密码后能解密 802.11 数据

这类题需要额外知识，作为了解即可，遇到时查专门教程。

### 19.5.7 写脚本自动化分析

大量 pcap 分析时，用 Python + scapy 库更灵活：

```python
from scapy.all import rdpcap, TCP, Raw

packets = rdpcap("traffic.pcap")
for pkt in packets:
    if pkt.haslayer(TCP) and pkt.haslayer(Raw):
        data = pkt[Raw].load
        if b"flag" in data.lower():
            print("找到:", data)
```

scapy 能逐包读取、按层解析、提取载荷——比 Wireshark GUI 更适合批量处理和自动化。

### 19.5.8 流量题的思维模式

总结流量分析的核心思维：

1. **先看全局**：协议分布、连接数、时间跨度——判断题目类型
2. **找异常**：异常大的包、异常协议、异常域名、异常端口
3. **顺藤摸瓜**：找到可疑连接后 Follow Stream 看完整内容
4. **提取+解码**：导出的数据往往还要解码/解压/隐写分析
5. **交叉印证**：一个线索（如 key）可能用于解密另一部分流量

**关键**：流量题本质是"在通信记录里找异常"，和第 20 章日志分析是同一种思维——**从海量正常数据中定位异常点**。
