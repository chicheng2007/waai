# 第 18 章 压缩包与文件分析

## 本章目标

读完这一章，你将能够：

- 理解 ZIP 压缩包的结构与"伪加密"原理

## 18.1 ZIP 文件结构：理解伪加密的前提

要理解伪加密，得先知道 ZIP 文件的大致结构。一个 ZIP 由三部分组成：

```
[本地文件头][文件数据][中央目录]
```

每个文件条目在两个地方记录了"是否需要密码"的标志位：

1. **本地文件头**（Local File Header）里的通用标志位
2. **中央目录**（Central Directory）里的通用标志位

**正常加密**：两个地方的标志位都设为"加密"，解压时需要密码。

**伪加密**：只把**中央目录**的标志位设为加密，本地文件头没设。解压软件看中央目录，以为要密码；但数据其实没加密——**改一下标志位就能直接解压**。

这就是伪加密的本质：**利用"标志位"骗解压软件，实际数据没加密。**

---

## 18.2 识别与破解伪加密

### 18.2.1 识别

现象：打开 zip 时提示要密码，但你怀疑是假加密（题目没给密码、或给了可疑提示）。

判断：用 `zipinfo` 或 `unzip -Z -v` 看标志位，或用 010editor/Hex 编辑器看中央目录的加密位。

### 18.2.2 破解方法

**方法一：改标志位（治本）**

用十六进制编辑器（如 010editor、hexedit）找到中央目录里的加密标志位，把对应字节从 `09 00` 改成 `00 00`（或把 `01` 改 `00`）。

具体位置较繁琐，CTF 里更常用方法二。

**方法二：用工具一键修复**

```bash
# 用 zipclear 或 pseudo-encryption 修复脚本
# 或者直接用 7z 有时能忽略伪加密
7z x file.zip

# Python 脚本批量清除伪加密标志位
```

有个常用 Python 脚本能自动把中央目录的标志位清零：

```python
import struct

data = bytearray(open("encrypted.zip", "rb").read())
# 找中央目录标志 PK\x01\x02，把其后第 9 字节（加密位）清零
i = 0
while True:
    i = data.find(b"PK\x01\x02", i)
    if i == -1:
        break
    data[i+8] = 0   # 通用标志位第一个字节清零
    i += 4
open("fixed.zip", "wb").write(data)
```

修复后直接解压即可。

### 18.2.3 万能工具：ZipCrypto

其实还有个更简单的判断：**如果题目给了密码，那是真加密；如果没给密码却要密码，八成是伪加密**——先试伪加密修复。

## 18.3 真加密：密码爆破

如果是真加密（有密码但不知道），用爆破：

### 18.3.1 用 fcrackzip

```bash
# 字典爆破
fcrackzip -D -p /usr/share/wordlists/rockyou.txt -u file.zip

# 暴力破解（指定字符集和长度）
fcrackzip -b -c 'a1' -l 1-6 -u file.zip
```

### 18.3.2 用 hashcat（更快）

```bash
# 提取 zip 的哈希
zip2john file.zip > hash.txt

# hashcat 爆破（zip 是 17200 类型）
hashcat -m 17200 hash.txt wordlist.txt
```

### 18.3.3 爆破技巧

- **先用字典**（rockyou.txt 等），成功率最高
- 题目若有提示（如"密码是 4 位数字"），用 masked attack 缩小范围
- **ZIP 密码可能在别处**：先看图片元数据、注释里有没有密码提示（呼应第 17 章）

## 18.4 文件头识别与修复

### 18.4.1 文件头（Magic Number）

每种文件开头有特定的字节序列，是它的"身份证"：

| 文件类型 | 文件头（十六进制） |
|---------|------------------|
| ZIP | `50 4B 03 04` (PK) |
| PNG | `89 50 4E 47` |
| JPG | `FF D8 FF` |
| GIF | `47 49 46 38` (GIF8) |
| PDF | `25 50 44 46` (%PDF) |
| ELF | `7F 45 4C 46` |
| RAR | `52 61 72 21` |

**常见考点**：题目把文件头删了/改了，导致打不开。用十六进制编辑器把文件头改回来即可修复。

### 18.4.2 用 file 识别

```bash
file mystery.bin
```

如果 `file` 识别不出，或识别结果和扩展名不符，就可能有文件头问题。

### 18.4.3 修复方法

用 010editor/hexedit 打开，在开头填入正确的文件头字节，保存后就能打开。

**经典题**：给一个没有扩展名、文件头被删的 zip，先补 `50 4B 03 04`，再解压。

## 18.5 文件分离：binwalk 与 foremost

有时候一个文件里**藏着另一个完整文件**（如图片后面追加了 zip）。这就是第 17 章提过的"追加数据"，这里系统讲提取方法。

### 18.5.1 binwalk 分析

```bash
# 扫描文件里藏了什么
binwalk image.jpg

# 输出示例：
# DECIMAL     HEXADECIMAL     DESCRIPTION
# 0           0x0             JPEG image data
# 52342       0xCC76          Zip archive data, at least v2.0 to extract
```

`52342` 字节处开始有个 zip——藏在这里！

### 18.5.2 提取

```bash
# binwalk 自动提取（用 -e）
binwalk -e image.jpg
# 提取的文件在 _image.jpg.extracted/ 目录

# 或用 foremost（按文件头 carving）
foremost image.jpg -o output_dir
```

提取出的 zip 可能就是伪加密的（结合 18.2 破解），解压得到 flag。

### 18.5.3 手动提取

如果工具提取失败，可以手动：用 `dd` 按偏移量切割：

```bash
# 从 52342 字节处开始，提取 1000 字节
dd if=image.jpg of=hidden.zip bs=1 skip=52342 count=1000
```

## 18.7 实战排查流程

拿到一个压缩包/可疑文件：

```
① file → 确认类型和文件头是否完好
② 如果是 zip 且要密码 → 先判断是否伪加密（无提示密码就试修复）
③ 真加密 → 看注释/元数据找密码提示 → 爆破
④ 解出的文件 → 继续用 file/exiftool/binwalk 检查（可能套娃）
⑤ 如果是图片等载体 → binwalk 看有没有藏文件 → foremost 提取
⑥ 提取出的文件 → 循环回到 ①
⑦ 最终拿到 flag（可能是编码的，结合第 16 章解码）
```

**CTF 常见"套娃"**：zip 里藏图片，图片里 LSB 藏另一个 zip，那个 zip 伪加密——一层套一层。用上面的流程循环处理即可。

## 18.8 本章总结

| 知识点 | 核心要点 |
|--------|---------|
| ZIP 结构 | 本地文件头 + 数据 + 中央目录；两处都有加密标志位 |
| 伪加密 | 只改中央目录标志位，数据没加密；改标志位即可解 |
| 识别伪加密 | 无密码提示却要密码 → 八成伪加密 |
| 真加密爆破 | fcrackzip / hashcat + 字典 |
| 文件头 | 每种文件有 magic number；被删要补回 |
| 文件分离 | binwalk 扫描 + foremost/-e 提取 + dd 手动切 |
| 排查流程 | file → 伪加密判断 → 爆破 → 分离 → 循环套娃 |
