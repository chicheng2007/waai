# 第 17 章 隐写术：图片、音频里的秘密

## 本章目标

读完这一章，你将能够：

- 理解隐写的本质："把信息藏在载体的冗余里"
- 用 file/binwalk/exiftool/strings 做隐写题的"标准四板斧"
- 掌握 LSB 隐写的原理与提取（Stegsolve/zsteg）
- 了解图片元数据隐写、音频隐写、文档隐写
- 建立起系统的隐写题排查流程

> 隐写术（Steganography）是 Misc 方向最有魅力的部分——一张看似普通的图片，被你"挖"出隐藏的 flag，成就感极强。这一章从工具到原理，给你一套完整的排查方法。

---

## 17.1 什么是隐写

**隐写 vs 加密**：
- 加密：把信息变成看不懂的密文（一眼就知道"这里有秘密"）
- 隐写：把信息藏在看似正常的文件里（看不出这里有秘密）

**类比**：加密是把信锁进保险箱——小偷一眼知道有宝贝但打不开；隐写是把信纸裁成细条卷进地毯里——小偷看地毯就是地毯，根本不知道有信。

**原理**：图片、音频等文件格式里有很多"冗余空间"——不影响正常显示/播放的部分。把秘密数据藏进这些冗余里，文件看起来、用起来都正常，但用特定工具能提取出隐藏信息。

---

## 17.2 标准四板斧：拿到文件先跑这四个命令

任何隐写题（其实任何 Misc 文件题），第一步都是信息收集。记住这"四板斧"：

```bash
# 1. 确认真实文件类型（扩展名可能骗人）
file image.jpg

# 2. 看元数据（作者、注释、GPS、软件信息）
exiftool image.jpg

# 3. 看有没有藏/拼接别的文件
binwalk image.jpg

# 4. 搜可打印字符串（flag 可能明文藏着）
strings image.jpg | grep -i "flag\|ctf\|{\|}"
```

这四步可能直接出答案，也可能告诉你下一步方向：

| 命令 | 可能发现 |
|------|---------|
| `file` | 扩展名是 jpg 实际是 png / zip |
| `exiftool` | Comment/Author 字段里藏着 flag |
| `binwalk` | 图片后面追加了一个 zip（藏了 flag 文件） |
| `strings` | 明文/Base64 的 flag |

**小白问：为什么 `file` 很重要？**
> 因为文件扩展名只是个"标签"，可以随便改。真正决定文件类型的是开头的"文件头"（magic number）。`file` 命令读文件头判断真实类型。见过太多题把 zip 改名成 jpg，用 `file` 一秒识破。

## 17.3 LSB 隐写：最经典的图片隐写

### 17.3.1 原理

图片由像素组成，每个像素的颜色用 RGB 三个通道表示，每个通道是 0–255 的 8 位值。比如某个红色通道值是 `11110010`。

**LSB（Least Significant Bit，最低有效位）隐写**：把每个通道值的**最后 1 位**（最低位）替换成秘密数据的位。比如把 `11110010` 的最后一位 `0` 改成 `1`。

**为什么看不出来**？因为改最低位只让颜色变化 1/255——人眼完全无法察觉。但把所有像素的最低位按顺序提取出来，拼起来就是隐藏的数据。

```
原始像素 R 通道: 11110010 11110011 11110000 ...
隐藏数据:        1        0        1        ...
修改后:          11110011 11110010 11110001 ...
                 （只改最后一位）
```

### 17.3.2 工具

**Stegsolve**（Java GUI 工具）：CTF 图片隐写标配。

```
1. 打开图片
2. 点 "Analyse" → "Frame Browser" 看各颜色通道的位平面
3. 逐个查看 LSB 平面（Red/Green/Blue 的 bit 0），有时能直接看到 flag 图像或二维码
4. "Extract Data" 可以提取 LSB 数据
```

**zsteg**（命令行，针对 PNG/BMP）：

```bash
zsteg image.png            # 自动检测各种 LSB 隐写
zsteg image.png -a         # 详细模式，尝试所有组合
```

zsteg 会自动尝试各通道、各位平面的组合，直接输出发现的 flag 或隐藏数据——非常强大。

### 17.3.3 提取后通常还要解码

LSB 提取出来的数据常是 Base64/Hex 编码的，要结合第 16 章解码。有时提取出的 bits 需要按 8 位一组转成 ASCII。

## 17.4 其他图片隐写手法

| 手法 | 工具/方法 |
|------|----------|
| **元数据隐写** | `exiftool` 看 Comment/Description/Software 等字段 |
| **追加数据** | `binwalk` 发现 appended zip → `foremost` 提取 |
| **图片头后藏数据** | 十六进制编辑器看 JPG 的 `FFD9` 结束符后面有没有多余数据 |
| **PNG 块隐写** | 检查 PNG 的 tEXt/iTXt 块（可用 pngcheck） |
| **颜色通道/灰度** | Stegsolve 切换通道，某些通道下能看到隐藏文字 |
| **GIF 多帧** | 用 Stegsolve 的 Frame Browser 逐帧看，flag 可能藏在某帧 |
| **JPEG DCT 隐写** | 用 steghide/stegdetect（需密码时爆破） |

**steghide**（JPEG/BMP 隐写）：

```bash
# 提取（可能需要密码）
steghide extract -sf photo.jpg
# 常见密码：空密码、题目名、flag

# 检测是否用了 steghide
stegdetect photo.jpg
```

## 17.5 音频隐写

音频文件（WAV/MP3）也能藏信息：

| 手法 | 工具 |
|------|------|
| **频谱隐写** | 用 Audacity 看频谱图（Spectrogram），flag 可能以图像形式藏在高频区 |
| **LSB 隐写** | 类似图片，藏在采样值最低位 |
| **摩斯密码** | 音频里听滴答声（第 16 章 Morse） |
| **DTMF 拨号音** |  telephone 按键音，解码得数字 |
| **SSTV** | 慢扫描电视，音频里藏图像 |

**Audacity 看频谱**：打开音频 → 切换视图为"频谱图（Spectrogram）"→ 调整频率范围，隐藏的文字/图像会出现在频谱里。这是音频隐写题的经典套路。

## 17.6 文档与其他隐写

| 载体 | 手法 |
|------|------|
| **Word/PDF** | 隐藏文字（白色字体）、元数据、注释 |
| **文本** | 零宽字符隐写（在字符间插入不可见的 zero-width 字符） |
| **压缩包** | 注释字段、伪加密（第 18 章） |
| **NTFS 交替数据流** | Windows 文件里藏数据 |

**零宽字符隐写**：在文本里插入 U+200B（零宽空格）等不可见字符，肉眼看不到，但编码后能解出信息。用脚本提取这些特殊字符的排列即可解码。

## 17.7 系统排查流程

拿到一张图/一个音频，按这个顺序排查：

```
① file → 确认真实类型
② exiftool → 看元数据
③ binwalk → 看有没有藏别的文件（有则 foremost 提取）
④ strings → 搜明文/编码 flag
⑤ 根据类型深入：
   - PNG/BMP → zsteg / Stegsolve 看 LSB 和通道
   - JPG → steghide / Stegsolve / 看 FFD9 后数据
   - GIF → Frame Browser 逐帧
   - 音频 → Audacity 频谱 / 听摩斯
⑥ 提取出的数据 → 结合第 16 章解码
```

**关键**：**按顺序排查，别跳步**。很多时候 flag 就在元数据里（②），你却直接去搞 LSB（⑤），白费功夫。

## 17.7 深度拓展：隐写的原理与更多手法

前面讲了工具和流程。这一节深入原理，并补充一些 CTF 里会遇到的进阶隐写手法。理解原理能让你面对"没见过的隐写"时也有思路。

### 17.7.1 为什么隐写能做到"看不见"

隐写的本质是**利用载体的冗余（redundancy）**。一张图片、一段音频里，有大量"改了也不影响正常使用"的数据位。隐写就是把秘密塞进这些冗余位。

- **JPEG**：有损压缩，DCT 系数的微小改动不影响视觉
- **PNG**：无损，但像素颜色值的最低位改动人眼不可见
- **音频**：采样值的最低位改动不影响听感
- **文件容器**：文件末尾追加数据、注释字段，播放器/查看器会忽略

**关键认知**：隐写并不意味着"加密"。很多隐写数据提取出来就是明文或 Base64——它只是"藏"，不是"锁"。

### 17.7.2 LSB 隐写的数学原理

一个像素的红色通道是 0–255 的 8 位值，比如 `10110010`（178）。把它最低位从 0 改成 1，变成 `10110011`（179）——颜色变化 1/255，约 0.4%，人眼几乎无法分辨。

如果 secret 是字符串，先转成二进制（每个字符 8 位），然后把这些位依次写进像素通道的最低位：

```
秘密 "A" = 01000001
写进前 8 个像素的 R 通道最低位 → 每个像素只动最后 1 位
```

提取时反过来：读取每个像素 R 通道的最低位，每 8 位组成一个字符。

**为什么 zsteg 能自动提取**：它会尝试"每个通道 × 每个位平面 × 多种位顺序（LSB/MSB）× 行/列顺序"的所有组合，找到能拼出可读文本的组合。

### 17.7.3 PNG 块结构隐写

PNG 文件由一系列"块（chunk）"组成：

| 块类型 | 作用 | 隐写可能 |
|--------|------|---------|
| IHDR | 图像头信息 | |
| **tEXt / iTXt / zTXt** | 文本元数据 | 直接藏 flag！ |
| IDAT | 压缩的图像数据 | LSB 隐写在这里 |
| IEND | 结束标志 | 后面可追加数据 |

**检查方法**：

```bash
# 列出 PNG 所有块
pngcheck -v image.png

# 或用 Python 解析块
python3 -c "
import struct
data = open('image.png','rb').read()
i = 8
while i < len(data):
    length = struct.unpack('>I', data[i:i+4])[0]
    ctype = data[i+4:i+8]
    print(ctype, length)
    i += 12 + length
"
```

如果看到 tEXt 块，用 `exiftool` 或直接提取里面的文本——flag 可能就直接躺在里面。

### 17.7.4 颜色通道与位平面

Stegsolve 的 "Colour Planes" 功能能显示每个颜色通道（R/G/B/A）的每个位平面（bit 0 到 bit 7）。

**原理**：bit 7（最高位）是图像的主要信息，bit 0（最低位）是细节噪声。隐写常藏在 bit 0/1，因为改动它们对画面影响最小。

**查看技巧**：
- 逐个字节地面切换，观察哪个平面出现"异常的图案"（如突然出现文字、二维码）
- Alpha 通道（透明度）也是常见 hiding spot——有些图看起来正常，但 alpha 平面里藏着图

### 17.7.5 GIF 多帧隐写

GIF 支持多帧动画。Stegsolve 的 "Frame Browser" 能逐帧查看。

**考点**：flag 可能藏在某一帧里（其他帧是干扰），或者藏在帧与帧的"差异"里。逐帧看一遍，注意异常帧。

### 17.7.6 音频隐写深入

**频谱隐写**：人耳听觉范围是 20Hz–20kHz。把信息画在高频段（如 18kHz 以上）的频谱图里，听不出来，但用 Audacity 的频谱视图能看到文字/图像。

**SSTV（慢扫描电视）**：把图像编码成音频信号，听起来像奇怪的啸叫，但用专门软件（如 QSSTV）能还原出图像，flag 就在图里。

**DTMF（双音多频）**：电话按键音，每个按键是两个特定频率的叠加。用工具解码音频里的按键音，得到一串数字——可能是 flag 的 ASCII 码。

**MP3 隐写**：MP3 的帧里有冗余位，工具如 mp3stego 能藏/取数据（通常需要密码）。

### 17.7.7 文档隐写

**Word 文档**：
- 隐藏文字：字体设为"隐藏"（Word 选项里），肉眼看不到，但选中/取消隐藏后能看到
- 文档属性：文件 → 信息 → 属性，作者/公司/批注可能藏 flag
- 用 `unzip docx`（docx 本质是 zip）解压，检查 `docProps/` 和 `word/` 里的 XML

**PDF**：
- `exiftool` 看元数据
- `pdftotext` 提取文字
- 隐藏在图层/注释里的内容

**文本零宽字符**：
- U+200B（零宽空格）、U+200C、U+200D 等不可见字符
- 把它们编码进文本，肉眼完全看不出
- 检测和解码：

```python
text = open("hidden.txt", encoding="utf-8").read()
# 找出所有零宽字符
zwsp = [c for c in text if c in '\u200b\u200c\u200d\ufeff']
print(len(zwsp))  # 数量本身可能编码信息
# 常见编码方式：连续零宽空格的数量代表一个字符的 ASCII
```

### 17.7.8 隐写与加密的区别（再强调）

CTF 里"隐写"和"密码"常结合：

- **隐写**：把数据藏起来（藏在图片、音频、文件结构里）——解决"在哪"
- **加密/编码**：把数据变乱（Base64、AES、古典密码）——解决"是什么"

一道典型的综合题：`图片 LSB 隐写 → 提取出 Base64 → 解码得到 ROT13 → 再解码才是 flag`。所以解隐写题时，提取出数据后要**继续判断编码类型**（第 16 章），别以为提取出来就结束了。
