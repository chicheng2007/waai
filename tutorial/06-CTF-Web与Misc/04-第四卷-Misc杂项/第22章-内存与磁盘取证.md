# 第 22 章 内存与磁盘取证

## 本章目标

读完这一章，你将能够：

- 理解内存取证与磁盘取证的区别和适用场景
- 用 Volatility 分析内存镜像（进程、文件、密码）
- 了解常见的内存取证考点（进程藏 flag、cmd 命令、文件提取）
- 了解磁盘取证基础（挂载镜像、删除文件恢复）
- 掌握取证题的通用排查流程

> 内存与磁盘取证是 Misc 的高阶内容。给你一个 `.raw`/`.dmp` 内存镜像或磁盘镜像，你要从中找出 flag——可能藏在某个进程里、一段命令行历史里、一个已删除但仍在内存里的文件中。这一章收尾第四卷。

## 22.1 取证基础：内存 vs 磁盘

| | 磁盘取证 | 内存取证 |
|---|---------|---------|
| **对象** | 硬盘镜像（.img/.E01） | 内存快照（.raw/.dmp/.mem） |
| **内容** | 持久化存储的文件（含已删除文件的残留） | 某一时刻的运行状态：进程、网络连接、内存中的文件/密码 |
| **特点** | 数据"静态"，删除可恢复 | 数据"易失"，关机就没了——包含磁盘上没有的"活"信息 |
| **工具** | Autopsy、photorec、挂载分析 | Volatility |
| **CTF 常见度** | 中 | 高（内存题更常考） |

**关键认知**：内存里藏着很多"磁盘上看不到"的东西——进程的命令行参数、解密后的密码、已删除但还驻留内存的文件、网络连接。所以 CTF 里内存取证题很多。

## 22.2 Volatility：内存取证神器

Volatility 是内存取证的标准工具（Kali 可安装，新版是 Volatility 3）。

### 22.2.1 第一步：确定系统版本

内存分析需要知道镜像来自什么操作系统（Windows 哪个版本、Linux 内核版本），因为数据结构不同。

```bash
# Volatility 2
volatility -f memory.raw imageinfo

# Volatility 3
vol.py -f memory.raw windows.info
```

输出会建议用哪个 profile（系统配置）。

### 22.2.2 常用命令（Volatility 2 语法）

```bash
# 列出进程
volatility -f memory.raw --profile=Win7SP1x64 pslist

# 列出进程（含隐藏进程，用 psscan）
volatility -f memory.raw --profile=Win7SP1x64 psscan

# 查看命令行参数（超常用！flag 常在这里）
volatility -f memory.raw --profile=Win7SP1x64 cmdline

# 列出网络连接
volatility -f memory.raw --profile=Win7SP1x64 netscan

# 提取内存中的文件
volatility -f memory.raw --profile=Win7SP1x64 filescan | grep flag
volatility -f memory.raw --profile=Win7SP1x64 dumpfiles -Q 0x地址 -D ./output

# 提取进程内存
volatility -f memory.raw --profile=Win7SP1x64 memdump -p PID -D ./output

# 浏览器历史、剪贴板等
volatility -f memory.raw --profile=Win7SP1x64 iehistory
volatility -f memory.raw --profile=Win7SP1x64 clipboard
```

### 22.2.3 常见 flag 藏法

| 藏法 | 用什么命令发现 |
|------|--------------|
| 进程的命令行参数里有 flag | `cmdline` |
| 内存里有 flag.txt 文件 | `filescan` + `dumpfiles` |
| flag 在某个进程内存里 | `memdump` + strings 搜 |
| 隐藏进程 | `psscan`（对比 pslist） |
| 剪贴板里有 flag | `clipboard` |
| 浏览器访问记录 | `iehistory` / Chrome 相关插件 |

**CTF 典型流程**：

```
① imageinfo → 确定 profile
② pslist / psscan → 看有哪些进程，找可疑的
③ cmdline → 看进程命令行，flag 常在运行的命令里
④ filescan | grep -i flag → 找 flag 文件，dumpfiles 提取
⑤ memdump 可疑进程 → strings 搜 flag
⑥ 提取的数据 → 结合第 16/17 章解码/分析
```

## 22.3 磁盘取证基础

### 22.3.1 挂载磁盘镜像

```bash
# 用 losetup 挂载
sudo losetup -f -P disk.img
sudo mount /dev/loop0p1 /mnt/analysis

# 然后像普通文件系统一样浏览
ls /mnt/analysis
```

### 22.3.2 删除文件恢复

文件删除后，数据往往还留在磁盘上（只是标记"可覆盖"）。用工具恢复：

```bash
# photorec / extundelete / foremost
photorec disk.img
extundelete disk.img --restore-all
```

### 22.3.3 文件时间戳分析

文件的创建/修改/访问时间（MAC 时间）能还原事件顺序：

```bash
stat file
# 或
exiftool file | grep -i date
```

CTF 里可能通过时间戳判断哪个文件是攻击者在特定时间留下的。

## 22.4 取证题通用流程

```
① 看文件类型：file 确认是内存镜像还是磁盘镜像
② 内存 → Volatility：imageinfo → 进程/命令行/文件 → 提取
   磁盘 → 挂载 / photorec 恢复 / 时间戳分析
③ 找关键词：strings 镜像 | grep -i flag（暴力但有效）
④ 提取的数据 → 解码/隐写/文件分析（前面各章）
⑤ 拿到 flag
```

**一个实用技巧**：无论什么镜像，先跑一遍：

```bash
strings memory.raw | grep -iE "flag\{|ctf\{|CTF\{"
```

可能直接搜到明文 flag——简单粗暴但常常有效。
