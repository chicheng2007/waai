# 第 20 章 日志分析与取证

## 本章目标

读完这一章，你将能够：

- 理解日志在安全分析中的作用（还原"发生了什么"）
- 认识常见日志类型（Web 访问日志、系统日志、认证日志）
- 用 grep/awk 等工具分析日志，发现攻击痕迹
- 从日志中还原攻击过程（暴力破解、扫描、入侵）
- 理解日志取证的思路与 flag 常见藏法

> 日志分析是 Misc 与真实安全（应急响应/蓝队）结合最紧密的题型。给你一份日志文件，你要像侦探一样从记录里还原出"谁、什么时候、做了什么"。这既是 CTF 考点，也是真实的安全技能。

## 20.1 日志是什么：系统的"监控录像"

日志（log）是系统/应用记录的事件流水账。就像商场的监控录像，出事后可以回看"发生了什么"。

**CTF 里的日志题**：给你一份日志（access.log、auth.log 等），flag 或线索藏在某条记录里——可能是一次攻击请求的参数、一个可疑 IP 的访问记录、一串编码的用户代理。

**日志分析的本质**：**从大量正常记录中，找出"不正常的那几条"。**

---

## 20.2 常见日志类型

### 20.2.1 Web 访问日志（access.log）

记录每次 HTTP 请求。Apache 常见格式：

```
192.168.1.100 - - [25/Nov/2026:10:15:32 +0800] "GET /index.php?id=1 HTTP/1.1" 200 1234 "-" "Mozilla/5.0"
```

解读：

| 字段 | 含义 |
|------|------|
| `192.168.1.100` | 客户端 IP |
| `[25/Nov/2026:10:15:32]` | 时间 |
| `"GET /index.php?id=1 HTTP/1.1"` | 请求方法、路径、协议 |
| `200` | 状态码 |
| `1234` | 响应字节数 |
| `"Mozilla/5.0"` | User-Agent |

**CTF 关注点**：奇怪的 URL 参数（注入 payload）、异常的 User-Agent、大量 404（扫描）、某个 IP 的高频请求（爆破）。

### 20.2.2 认证日志（auth.log / secure）

记录登录尝试：

```
Nov 25 10:20:01 server sshd[1234]: Failed password for root from 192.168.1.200 port 22 ssh2
Nov 25 10:20:05 server sshd[1235]: Accepted password for admin from 192.168.1.201 port 22 ssh2
```

**CTF 关注点**：大量 `Failed password`（暴力破解）、成功的登录来自可疑 IP、异常时间登录。

### 20.2.3 其他日志

| 日志 | 内容 |
|------|------|
| 系统日志（syslog/messages） | 系统事件、服务状态 |
| 防火墙日志 | 被拦截的连接 |
| 应用日志 | 业务操作记录 |
| 数据库日志 | SQL 查询记录 |

## 20.3 分析工具：grep / awk / sort / uniq

日志是纯文本，Linux 命令行三剑客就是最好的工具（呼应第 6 章文本处理）。

### 20.3.1 grep 搜索

```bash
# 搜包含 flag 的行
grep -i "flag" access.log

# 搜注入特征
grep -iE "union|select|or 1=1" access.log

# 搜失败登录
grep "Failed password" auth.log

# 排除正常请求
grep -v "200" access.log
```

### 20.3.2 awk 提取字段

```bash
# 提取所有客户端 IP（第 1 列）
awk '{print $1}' access.log | sort | uniq -c | sort -rn

# 这条命令：提取 IP → 排序 → 计数 → 按次数倒序
# 结果能看出哪个 IP 访问最多（可能是攻击者）
```

```bash
# 统计状态码（第 9 列，视日志格式而定）
awk '{print $9}' access.log | sort | uniq -c
```

### 20.3.3 综合示例：发现暴力破解

```bash
# 找出失败次数最多的 IP
grep "Failed password" auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn | head

# 看这个 IP 的所有操作
grep "192.168.1.200" auth.log
```

**这就是日志分析的日常**：用命令快速统计、筛选、排序，从数据里找出" outliers（异常点）"。

## 20.4 还原攻击过程

CTF 日志题常让你还原完整的攻击链。思路：

```
① 找异常 IP：访问量异常高、大量 404、来自陌生地区
② 看这个 IP 干了什么：按时间排序它的所有请求
③ 识别攻击阶段：
   - 扫描（大量 404，探测目录）
   - 注入（URL 里有 union/select/' or）
   - 爆破（大量 POST 登录请求）
   - 利用（上传 shell.php、访问可疑文件）
   - 窃取（下载敏感文件）
④ 找 flag：可能在某次请求的参数里、User-Agent 里、或成功访问的文件路径里
```

**例子**：一个 IP 先大量 404 扫目录，然后访问 `/admin.php`，接着 POST 了带 `<?php system(...)>` 的参数，最后 GET `/shell.php?cmd=cat /flag`——完整攻击链还原，flag 可能在最后一次请求的响应或参数里。

## 20.5 flag 的常见藏法

| 藏法 | 怎么找 |
|------|--------|
| 藏在 User-Agent | 看每条请求的 UA，找异常长的/编码的 |
| 藏在 URL 参数 | grep 可疑参数名（如 `?key=flag{...}`） |
| 藏在 Referer | 检查 Referer 字段 |
| 藏在时间戳 | 某些请求的间隔/时间编码成信息 |
| 藏在状态码序列 | 200/404 的排列组成二进制/摩斯 |
| 藏在请求顺序 | 按某种顺序请求特定资源，拼成信息 |

**脑洞题**：日志里的状态码序列（404/200）对应二进制（0/1），转成 ASCII 就是 flag。这类题需要跳出"看内容"的思维，看"模式"。

---

## 20.6 日志取证的思路

从"蓝队视角"总结取证思路：

1. **时间线**：按时间排序所有事件，建立"事件时间线"
2. **溯源**：找出攻击源 IP、攻击时间、攻击手法
3. **影响面**：攻击者访问/修改了哪些资源，有没有拿到敏感数据
4. **证据固化**：保存日志原件（真实场景要算哈希保证完整性）
5. **报告**：写清楚"发生了什么、怎么发生的、如何防御"

CTF 里通常只需做到"找到 flag"，但理解完整取证流程，能让你对日志题有更深的认识——也呼应了本系列"攻防一体"的理念。
