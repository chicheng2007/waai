# 第 5 章 信息收集与目录扫描

## 本章目标

读完这一章，你将能够：

- 理解"信息收集"在 Web 解题中的决定性作用
- 掌握查看源代码、robots.txt、响应头的收集技巧
- 用 dirsearch/ffuf 扫描隐藏目录和文件
- 识别常见的技术栈泄露（框架、CMS、编程语言）
- 理解 .git 泄露、备份文件泄露等经典考点
- 建立起"凡是可以访问的，都值得看一眼"的收集习惯

> 很多新手觉得信息收集"不起眼"，总想直接上高级 payload。但实战中，**80% 的题目突破口藏在信息收集阶段**——出题人把线索留在了注释里、备份文件里、robots.txt 里。这一章就是教你"把角落翻一遍"。

---

## 5.1 为什么信息收集最重要

回顾第 3 章的解题四步：观察 → 假设 → 验证 → 归纳。**信息收集就是"观察"这一步在 Web 题里的具体展开。**

一个残酷的事实：新手对着一个 Web 题发呆三小时，往往不是因为技术不够，而是因为他只看到了页面显示的那一屏内容，没去看源代码、没扫目录、没看响应头。而答案可能就静静躺在 `/flag.txt` 或 `source.php` 里，只要扫一下就能发现。

**信息收集的目标**：把这个网站"里里外外摸一遍"，回答三个问题：

1. **它是什么做的？**（技术栈：Apache/Nginx？PHP/Python？什么框架/CMS？）
2. **它有哪些"门"？**（有哪些页面、目录、接口、参数？）
3. **它"忘了藏"什么？**（注释、备份、配置文件、调试页面、敏感路径？）

---

## 5.2 页面源代码：最容易忽略的金矿

**第一件事，永远是查看源代码**。浏览器按 `Ctrl+U`（或右键→查看页面源代码）。

### 5.2.1 要找什么

```html
<!DOCTYPE html>
<html>
<head>
    <title>News Site</title>
    <!-- TODO: remove debug param before deploy -->
    <!-- admin panel: /admin_h3dd3n/ -->
</head>
<body>
    <form action="search.php" method="GET">
        <input type="hidden" name="debug" value="0">
        <input type="text" name="q">
    </form>
    <script src="/js/app.js"></script>
</body>
</html>
```

这段源代码里藏着三个线索：

1. **HTML 注释**：`<!-- admin panel: /admin_h3dd3n/ -->` —— 直接告诉你隐藏后台路径！出题人常把线索留在注释里（以为用户看不到，但查看源代码就能看到）。
2. **隐藏表单字段**：`<input type="hidden" name="debug" value="0">` —— 有个 `debug` 参数，页面上不显示，但你用 Burp 改成 `debug=1` 可能触发调试模式，泄露更多信息。
3. **JS 文件**：`/js/app.js` —— 前端脚本里可能有 API 地址、密钥、逻辑线索，值得点开看。

### 5.2.2 批量查找线索

源代码长时，用搜索快速定位关键词：

```
Ctrl+F 搜索：flag、admin、debug、password、key、secret、todo、hint、test、backup
```

**小白问：注释真的会被出题人当线索吗？**
> 在 CTF 里这是经典套路，因为"查看源代码"是基本技能，出题人用它来考你会不会看。真实世界里，开发者也经常把敏感信息（密码、内网地址）误留在注释里——这是真实存在的信息泄露漏洞。

## 5.3 robots.txt 与其他"公开的秘密"

### 5.3.1 robots.txt

`/robots.txt` 是网站告诉搜索引擎"哪些目录不要抓取"的文件。讽刺的是，它等于公开告诉攻击者"这些目录存在"：

```
User-agent: *
Disallow: /admin/
Disallow: /backup/
Disallow: /flag_backup.zip
```

看到 `Disallow` 里的路径，**直接去访问**。出题人经常把关键路径写在这里。

### 5.3.2 其他值得直接访问的路径

| 路径 | 可能内容 |
|------|---------|
| `/robots.txt` | 禁止抓取的路径（线索） |
| `/sitemap.xml` | 网站所有页面列表 |
| `/.git/` | Git 仓库泄露（见 5.5） |
| `/.DS_Store` | macOS 目录元数据，泄露文件名 |
| `/phpinfo.php` | PHP 配置页，泄露大量环境信息 |
| `/index.php.bak` | 备份文件（见 5.4） |
| `/admin/` | 后台入口 |
| `/flag.txt` | 有时 flag 就这么直白 |

养成习惯：拿到一个站，先手动访问 `/robots.txt` 和 `/index.php`（看默认页技术栈）。

## 5.4 备份文件与源码泄露

### 5.4.1 常见备份文件

开发者编辑文件时常留下备份，Web 服务器如果配置不当会直接提供下载：

| 文件名 | 来源 |
|--------|------|
| `index.php.bak` | 手工备份 |
| `index.php~` | vim/编辑器自动备份 |
| `index.php.swp` | vim 交换文件 |
| `www.zip` / `backup.zip` | 整站打包备份 |
| `.index.php.swp` | 隐藏交换文件 |

**套路**：访问 `http://target.com/index.php.bak`，如果服务器把它当静态文件返回，你就拿到了源码。源码里可能有数据库密码、flag、漏洞逻辑。

### 5.4.2 用 dirsearch 扫描

手工猜备份文件效率太低，用工具批量探测：

```bash
# 安装（Kali 自带或用 pip）
pip install dirsearch

# 基本扫描
dirsearch -u http://target.com

# 指定扩展名（扫 .bak/.zip/.php 等）
dirsearch -u http://target.com -e php,bak,zip,txt

# 用字典
dirsearch -u http://target.com -w /usr/share/wordlists/dirb/common.txt
```

工具会批量请求成千上万个可能路径，把返回 200/403/500 的"有意思的"结果列出来。

**ffuf**（更快的现代工具）：

```bash
ffuf -u http://target.com/FUZZ -w wordlist.txt -mc 200,301,302,403
```

`FUZZ` 是占位符，会被字典里的每个词替换。`-mc` 指定显示哪些状态码。

### 5.4.3 扫描的注意事项

- **只在授权靶场扫描**：dirsearch 会发大量请求，对真实未授权站点扫描可能违法/影响业务。CTF 靶场随便扫。
- **控制速率**：`-t 20` 限制线程数，避免把靶场打挂（有些靶场挂了会重置，浪费时间）。
- **看懂结果**：不是所有 200 都有用，要一个个人工判断。403（存在但没权限）和 500（服务器报错）也值得关注。

## 5.5 .git 泄露：一个经典大考点

### 5.5.1 什么是 .git 泄露

很多网站用 Git 管理代码。如果部署时把 `.git` 目录一起放到了 Web 根目录，攻击者就能通过它**还原整个项目源码和历史记录**——包括已经删除的敏感文件、数据库密码、flag。

### 5.5.2 探测与利用

先访问 `http://target.com/.git/HEAD`，如果返回 `ref: refs/heads/master` 之类内容，说明存在泄露。

利用方法：

```bash
# 用 git-dumper 一键拉取
git-dumper http://target.com/.git/ ./loot

# 或手工：用 wget 递归下载 .git 目录
wget -r http://target.com/.git/
cd target.com/.git
git checkout .   # 还原源码
```

拉取后你可以：

- `git log` 看提交历史，找删除前的敏感文件
- `git show <commit>` 看某个提交的内容
- 直接读源码找漏洞和 flag

**CTF 里 .git 泄露是高频考点**，看到站点就该访问一下 `/.git/HEAD` 试试。

## 5.6 技术栈识别

知道网站用什么技术，才能"对症下药"。收集方法：

### 5.6.1 从响应头看

```bash
curl -I http://target.com
```

```
Server: nginx/1.18.0
X-Powered-By: PHP/7.4.3
```

直接告诉你 Web 服务器和后端语言。

### 5.6.2 从 Cookie 名看

| Cookie 名 | 暗示的技术 |
|----------|-----------|
| `PHPSESSID` | PHP |
| `JSESSIONID` | Java (Tomcat/JSP) |
| `ASP.NET_SessionId` | ASP.NET |
| `connect.sid` | Node.js (Express) |

### 5.6.3 从页面特征看

- URL 以 `.php` 结尾 → PHP；`.jsp` → Java；`.asp` → ASP
- 报错页面样式（Tomcat 的错误页、Django 的调试页）
- 默认图标、特定框架的 JS/CSS 文件名

### 5.6.4 用工具识别

```bash
# whatweb 识别技术栈
whatweb http://target.com

# nmap 探测服务版本
nmap -sV target.com
```

识别技术栈后，可以针对性地查"这个框架的已知漏洞"——Vulhub 靶场就是干这个的。

## 5.7 综合实战：把站点翻一遍

假设给你一个目标 `http://ctf.site:8000`，按这个顺序收集：

```bash
# 1. 访问主页，查看源代码（浏览器 Ctrl+U），搜关键词
# 2. 看响应头
curl -I http://ctf.site:8000

# 3. 直接访问常见敏感路径
curl http://ctf.site:8000/robots.txt
curl http://ctf.site:8000/.git/HEAD
curl http://ctf.site:8000/index.php.bak

# 4. 目录扫描
dirsearch -u http://ctf.site:8000 -e php,bak,zip,txt

# 5. 技术栈识别
whatweb http://ctf.site:8000
```

如果这五步下来你找到了 `/admin_h3dd3n/` 目录、`index.php.bak` 源码、或 `.git` 仓库——恭喜，突破口大概率就在这里。下一步就是分析找到的东西（源码审计、后台利用），那是后面章节的事。

**信息收集的心法**：**把所有"门"都找出来，然后一扇扇推开看**。flag 往往就在某扇你没推开的门后面。

## 5.8 本章总结

| 知识点 | 核心要点 |
|--------|---------|
| 信息收集价值 | 80% 突破口在收集阶段；先看再打 |
| 页面源代码 | Ctrl+U；找注释、隐藏字段、JS 文件、关键词 |
| robots.txt | "禁止抓取"的路径等于公开线索，直接访问 |
| 敏感路径 | sitemap、phpinfo、admin、flag.txt 都值得试 |
| 备份文件 | .bak/.swp/~/.zip；源码泄露的经典方式 |
| dirsearch/ffuf | 批量扫目录文件；只看授权靶场 |
| .git 泄露 | 访问 /.git/HEAD 探测；git-dumper 还原源码（高频考点） |
| 技术栈识别 | 响应头、Cookie 名、URL 后缀、whatweb/nmap |
| 心法 | 把所有门找出来，一扇扇推开看 |

## 本章练习

1. 打开你熟悉的一个网站，查看源代码，搜索 `flag/admin/debug/password` 等关键词（只观察学习，不利用）。
2. 访问几个网站的 `/robots.txt`，看看它们"禁止"了哪些路径。
3. 在 DVWA 靶场上用 dirsearch 扫一遍（`-e php,bak,txt`），看看发现了什么。
4. 用 `curl -I` 查看三个不同网站的响应头，识别它们的 Server 和 X-Powered-By。
5. 搭建一个有 `.git` 目录的测试站点（或直接找一个 CTF 的 git 泄露题），用 git-dumper 还原源码。
6. 思考：为什么开发者"以为用户看不到"的注释和备份文件，会成为漏洞？（从"信任边界"角度想）
