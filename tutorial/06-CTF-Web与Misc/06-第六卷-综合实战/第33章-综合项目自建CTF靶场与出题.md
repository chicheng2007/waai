## 33.1 为什么要出题

**"出题人视角"带来的提升**：

1. **深度理解**：你要知道漏洞的每个细节——触发条件、绕过可能、flag 藏哪——才能真正掌握它
2. **全局思维**：设计一道题要考虑难度曲线、提示设计、解题路径，锻炼系统设计能力
3. **防止眼高手低**：你以为懂了，出题时才发现很多细节没想清楚
4. **回馈社区**：好的题目能帮到很多学习者

**一个事实**：很多安全高手都是从"出题"和"写 Writeup"中成长的。会解题是"消费者"，会出题是"生产者"——生产者对知识的理解深一个层次。

---

## 33.2 一道好题的设计原则

| 原则 | 说明 |
|------|------|
| **考点明确** | 一道题聚焦一个（或一串）明确的知识点，不为了难而难 |
| **难度适中** | 有挑战但可解；太简单没收获，太难让人放弃 |
| **线索合理** | 线索要"藏得住但找得到"——不能毫无头绪，也不能一眼看穿 |
| **可复现** | 环境稳定，每个人解题体验一致 |
| **有提示机制** | 准备 hint，卡住时能逐步给线索 |
| **flag 规范** | 用标准格式 `flag{...}` 或赛事名格式，方便自动验证 |
| **合规** | 靶场隔离，不造成真实危害 |

**出题的大忌**：
- 脑洞题（考点不成立，纯靠猜）
- 多解（预期解法外的捷径太多）
- 环境不稳定（一会能解一会不能）

## 33.3 出题实战：设计一道 Web 注入题

以 SQL 注入为例，走一遍出题流程：

### 33.3.1 确定考点

考点：联合查询注入（第 6 章）——从探测注入点到爆出 flag。

### 33.3.2 设计解题路径

```
1. 玩家访问首页，看到新闻列表功能 /news?id=1
2. 玩家加 ' 探测 → 报错 → 发现注入
3. 用 ORDER BY 判断列数
4. 用 UNION 找显示位
5. 爆库 → 爆表 → 爆列 → 拿 flag
```

### 33.3.3 编写应用（PHP)

```php
<?php
// index.php - 一个有 SQL 注入的新闻页面（仅用于教学靶场）
$conn = mysqli_connect("localhost", "root", "password", "ctf_db");

// 故意保留的注入点（教学用途，真实世界绝不能这样写！）
$id = $_GET['id'] ?? 1;
$sql = "SELECT title, content FROM news WHERE id = $id";
$result = mysqli_query($conn, $sql);

if ($row = mysqli_fetch_assoc($result)) {
    echo "<h1>{$row['title']}</h1>";
    echo "<p>{$row['content']}</p>";
}
?>
```

### 33.3.4 准备数据库和 flag

```sql
CREATE DATABASE ctf_db;
USE ctf_db;

CREATE TABLE news (id INT, title VARCHAR(100), content TEXT);
INSERT INTO news VALUES (1, '欢迎', '这是第一篇新闻');
INSERT INTO news VALUES (2, '公告', '第二篇新闻');

CREATE TABLE secrets (id INT, flag VARCHAR(100));
INSERT INTO secrets VALUES (1, 'flag{sql_1nj3ct_1s_st1ll_al1v3}');
```

### 33.3.5 设计提示（hint）

- Hint 1（免费）："看看 URL 里的参数能改吗？"
- Hint 2（扣分）："试试在数字后面加个单引号"
- Hint 3（扣分）："用 UNION 把 secrets 表联合出来"

### 33.3.6 测试

- 自己按预期路径解一遍，确认能拿到 flag
- 让朋友（不知道答案）试解，观察他们卡在哪——优化线索
- 检查有没有非预期解（如直接访问 secrets.php）

## 33.4 出题实战：设计一道 Misc 隐写题

### 33.4.1 考点

LSB 隐写 + Base64 编码（第 16、17 章）。

### 33.4.2 制作题目

```python
# 用 Python 把 flag 的 Base64 藏进图片的 LSB（简化示意）
from PIL import Image

img = Image.open("cover.png")
flag_b64 = "ZmxhZ3{m Counting..."  # 实际是 base64 编码的 flag
bits = ''.join(format(ord(c), '08b') for c in flag_b64)

# 把 bits 写进前 N 个像素的红色通道最低位
idx = 0
for px in img.getdata():
    if idx >= len(bits):
        break
    r, g, b = px[:3]
    r = (r & 0xFE) | int(bits[idx])  # 改最低位
    idx += 1
img.save("stego.png")
```

玩家需要用 zsteg/Stegsolve 提取 LSB 数据，再 Base64 解码拿 flag。

### 33.4.3 设计线索

- 题目描述："这张图看起来很普通，但似乎有点不一样……"
- Hint："试试看每个像素的最低位"

## 33.5 用 Docker 容器化题目

把题目打包成 Docker 镜像，方便分发和部署：

```dockerfile
# Dockerfile for SQL injection challenge
FROM php:7.4-apache

# 复制应用代码
COPY index.php /var/www/html/
COPY init.sql /docker-entrypoint-initdb.d/

# 暴露端口
EXPOSE 80
```

```bash
# 构建镜像
docker build -t my-ctf-sqli .

# 运行
docker run -d -p 8080:80 my-ctf-sqli

# 玩家访问 http://127.0.0.1:8080
```

**进阶**：用 docker-compose 编排多容器题目（Web + 数据库分离），更接近真实环境（呼应第 27 章靶场搭建）。

## 33.6 搭建个人 CTF 平台

想把多道组织起来？可以用现成的 CTF 平台框架：

| 平台 | 特点 |
|------|------|
| **CTFd** | 最流行的开源 CTF 平台，一键 Docker 部署 |
| **GZCTF** | 国产，功能强大，界面友好 |
| **FBCTF** | Facebook 开源，支持地图模式 |

**用 CTFd 搭建**：

```bash
# Docker 一键部署 CTFd
git clone https://github.com/CTFd/CTFd.git
cd CTFd
docker compose up -d

# 访问 http://127.0.0.1:8000，按向导初始化
```

部署后你可以：
- 添加题目（Web/Misc 等分类）
- 设置分值、hint、flag
- 看选手排名、提交记录
- 组织一场小型比赛

## 33.7 组织一场小型比赛

如果你想和朋友们办一场比赛：

```
1. 准备题目：5–10 道，覆盖 Web/Misc，难度递进（签入→简单→中等）
2. 部署平台：CTFd，配置题目、flag、分值、hint
3. 制定规则：时间、排名规则、是否允许联网查资料
4. 测试：自己和朋友先试解，确认环境稳定
5. 开赛：通知选手，监控平台状态
6. 赛后：收集反馈、写赛后 Writeup、改进题目
```

**组织比赛是综合能力的体现**——技术（出题）+ 工程（部署）+ 沟通（规则）+ 分析（反馈）全用上了。这是对你学习成果的终极检验。
