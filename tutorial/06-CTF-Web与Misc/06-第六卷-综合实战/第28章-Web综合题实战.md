# 第 28 章 Web 综合题实战：从线索到 flag 的完整推演

## 本章目标

读完这一章，你将能够：

- 把前面学的 Web 漏洞知识串成一套完整的解题流程
- 面对一道未知 Web 题，知道从哪里入手、如何层层深入
- 体验"信息收集 → 漏洞识别 → 利用 → 拿 flag"的全过程
- 学会在卡住时系统性地切换思路

> 前面五卷是"分项训练"，这一卷是"实战比赛"。本章用几道模拟的综合题，带你走一遍真实 CTF 的解题推演——重点不是记住某道题的答案，而是学会**面对未知题目时的思考方式**。

---

## 28.1 综合题的特点

真实 CTF 的 Web 题往往不是单一漏洞，而是：

- **多漏洞组合**：信息泄露 → 注入 → 越权 → 上传，一环扣一环
- **有过滤/绕过**：出题人加了各种限制，需要创造性绕过
- **线索隐蔽**：flag 不直接给，要一步步挖

**应对方法**：严格执行第 3 章的"观察 → 假设 → 验证 → 归纳"循环，每拿到新信息就更新假设，绝不跳步。

## 28.2 实战一：一道"信息管理后台"题

### 题目描述

给你一个网址 `http://ctf.example:8000`，页面是一个简单的"用户登录/注册"系统，提示"管理员藏着一个秘密"。

### 第一步：信息收集（第 5 章）

```bash
# 1. 查看源代码（Ctrl+U）——发现注释
<!-- TODO: remove test account: test/test before production -->

# 2. 看响应头
curl -I http://ctf.example:8000
# X-Powered-By: PHP/7.4  → 是 PHP 站

# 3. 扫目录
dirsearch -u http://ctf.example:8000 -e php,bak,txt
# 发现 /admin.php（403）、/config.php.bak（200！）

# 4. 访问备份文件
curl http://ctf.example:8000/config.php.bak
```

**突破**：`/config.php.bak` 泄露了数据库配置，甚至可能直接有 flag 线索。假设注释里的 `test/test` 是测试账号。

### 第二步：登录与漏洞识别

用 `test/test` 登录，进入用户中心。发现一个"查询个人信息"功能：`/userinfo?id=3`。

**假设**：id 参数可能越权或注入（第 6、12 章）。

**验证**：

```
改 id=1 → 看到别人的信息 → 水平越权存在！
改 id=3' → 报错 → SQL 注入也可能存在！
```

### 第三步：深入利用

```
① 用 SQL 注入爆库：
   /userinfo?id=-3' UNION SELECT 1,group_concat(table_name),3 FROM information_schema.tables WHERE table_schema=database()--
   → 发现 secrets 表

② 爆列、拿数据：
   /userinfo?id=-3' UNION SELECT 1,group_concat(flag),3 FROM secrets--
   → 拿到 flag 或下一层线索
```

**若 flag 在 admin.php**：注释提示有 admin.php 但 403。用 test 账号的 Cookie 访问，或找越权方式（改 Cookie 里的 role 字段，第 12 章）。

### 本题知识点串联

```
信息收集（注释/备份文件）→ 弱账号登录 → 越权/注入识别 → 联合注入拿数据
涉及章节：第 5、6、12 章
```

## 28.3 实战二：一道"图片上传 + 文件包含"题

### 题目描述

一个网站有"上传头像"功能和"查看图片"功能（`?file=avatar.jpg`）。

### 推演过程

**① 观察**：
- 上传功能：试传一个 PHP 文件（第 8 章手法）
- 查看功能：`?file=avatar.jpg` 参数控制文件名——**可能是文件包含漏洞**（第 9 章相关）

**② 假设**：file 参数可能能读取任意文件（LFI，本地文件包含）。

**③ 验证**：

```
?file=../../etc/passwd   → 读到 passwd → LFI 确认
?file=php://filter/convert.base64-encode/resource=index.php  → 读到源码 base64
```

**④ 深入**：
- 读源码发现上传的白名单逻辑和文件保存路径
- 上传一个图片马（第 8 章），用文件包含去"包含"它执行其中的 PHP 代码
- 或直接读 `/flag`

**⑤ 拿 flag**：`?file=/flag` 或包含图片马后执行 `system('cat /flag')`。

**知识点串联**：文件包含（LFI）→ php://filter 读源码 → 上传绕过 → 图片马 + 包含执行。涉及第 8、9、16 章。

## 28.4 实战三：一道"SSRF + 内网 Redis"题

### 题目描述

一个"网页截图"功能：`?url=...`，服务器会访问你给的 URL 生成截图。

### 推演过程

**① 观察**：这是典型的"服务器 fetch URL"场景 → SSRF（第 10 章）。

**② 验证**：

```
?url=http://127.0.0.1:80   → 返回本地服务内容 → SSRF 确认
?url=file:///etc/passwd    → 读本地文件成功
```

**③ 探测内网**：

```
?url=http://127.0.0.1:6379   → Redis 端口（返回 Redis 报错信息）
```

**④ 利用**：用 gopher 协议打 Redis（第 10 章），写 WebShell 或直接读 flag。

**⑤ 遇过滤**：如果过滤了 `127.0.0.1`，用进制 IP / DNS 绕过（第 10.4 节）。

**知识点串联**：SSRF 识别 → 内网探测 → gopher 打 Redis → 绕过过滤。涉及第 10 章。

## 28.5 综合题的通用解题框架

从上面三道题，提炼一个通用框架：

```
1. 信息收集（第 5 章）
   源代码 / 响应头 / 目录扫描 / 备份文件 / 技术栈

2. 功能点分析
   列出网站所有功能：登录、查询、上传、下载、URL 参数……
   每个功能点 = 一个潜在的漏洞入口

3. 漏洞识别（第 6–15 章）
   对每个功能点，判断可能的漏洞类型
   用最小 payload 验证

4. 深入利用
   确认漏洞后，系统性地扩大战果
   遇到过滤 → 绕过（第 6.7/7.4/8.4/10.4 节）

5. 拿 flag
   flag 位置：数据库 / 文件 / 内网服务 / 管理页面

6. 归纳（第 3、31 章）
   记录完整思路，形成 Writeup
```

**关键心态**：**一道题卡住时，回到第 1 步重新信息收集**——80% 的卡壳是因为漏了线索。

## 28.6 卡住时的检查清单

| 检查项 | 是否做了？ |
|--------|-----------|
| 查看页面源代码了吗？ | ☐ |
| 看响应头了吗？ | ☐ |
| 扫目录了吗（robots.txt/.git/备份）？ | ☐ |
| 试过所有功能点和参数了吗？ | ☐ |
| 试过改请求方法（GET→POST）吗？ | ☐ |
| 试过改 HTTP 头（XFF/Referer/UA）吗？ | ☐ |
| 看过 JS 文件里的接口/密钥吗？ | ☐ |
| 用 AI 讨论过思路吗（第 26 章）？ | ☐ |
| 适时看了 hint / Writeup 吗？ | ☐ |

逐项打勾，往往能找到遗漏的突破口。
