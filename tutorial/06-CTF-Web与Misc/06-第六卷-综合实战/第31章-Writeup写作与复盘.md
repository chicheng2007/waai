# 第 31 章 Writeup 写作与复盘：把经验变成能力

## 本章目标

读完这一章，你将能够：

- 理解 Writeup 的价值（对别人、对自己）
- 掌握一份好 Writeup 的标准结构
- 写出清晰、可复现、有深度的 Writeup
- 用 Writeup 做知识管理和能力固化
- 建立自己的技术博客/作品集

> 很多人做完题就结束了——这是最大的浪费。**Writeup（解题记录）是把"一次性经验"变成"长期能力"的关键动作**。能讲清楚，才是真懂。这一章教你写好 Writeup，它是你能力成长的复利工具。

---

## 31.1 为什么要写 Writeup

### 31.1.1 对自己的价值

1. **固化能力**：写下来逼你重新梳理思路，发现"以为懂了其实没懂"的地方
2. **知识库**：积累成个人资料库，遇到类似题能快速查阅
3. **暴露盲区**：写的时候卡壳的地方，正是你理解的薄弱点
4. **成长记录**：几个月后回头看，直观看到自己的进步

### 31.1.2 对别人的价值

1. **帮助他人**：你的思路可能帮到卡住的人
2. **建立声誉**：持续写高质量 Writeup，会在安全社区建立个人品牌
3. **团队贡献**：团队赛后 Writeup 是全队的共同财富

**核心**：**教是最好的学**。写 Writeup 就是"教别人"的过程。

---

## 31.2 一份好 Writeup 的标准结构

```
## 题目信息
- 赛事/平台、题目名、方向、难度、分值

## 题目描述
（原题给出的信息、附件、网址）

## 解题过程
### 1. 信息收集 / 初步观察
（你做了什么，看到了什么）

### 2. 分析与假设
（你为什么这么判断，依据是什么）

### 3. 验证与利用
（具体 payload / 工具 / 操作步骤，配截图或代码）

### 4. 拿到 flag
flag{...}

## 漏洞原理
（这题考的知识点是什么，为什么会这样）

## 踩坑与反思
（你走过的弯路、犯的错、学到的教训）

## 防御建议
（作为开发者，怎么防这个漏洞）——攻防一体
```

**关键要素**：
- **可复现**：别人照着你的步骤能做出来
- **有思考**：不只贴 payload，要写"为什么"
- **有反思**：写下你踩的坑——这对读者最有帮助

## 31.3 写作示例

以第 28 章的"信息管理后台"题为例：

```markdown
## 题目：信息中心（Web，难度：中，300分）

### 1. 信息收集
查看源代码，发现注释：`<!-- TODO: remove test/test -->`。
扫目录发现 `/config.php.bak` 可访问，泄露了数据库配置。

### 2. 分析与假设
注释暗示存在 test/test 测试账号。登录后有 `/userinfo?id=3` 功能，
id 参数可疑——可能是越权或 SQL 注入。

### 3. 验证与利用
- 改 id=1 能看到他人信息 → 水平越权
- 输入 id=3' 报错 → 存在 SQL 注入
- 构造联合注入：
  `?id=-3' UNION SELECT 1,group_concat(flag),3 FROM secrets--`
  → 拿到 flag

### 4. flag
flag{1nf0_l3ak_1s_d4ng3rous}

### 漏洞原理
本题串联了三个问题：源码注释泄露测试账号（信息泄露）、
参数未校验归属（越权）、SQL 语句拼接（注入）。

### 踩坑与反思
一开始只盯着登录框爆破，浪费了 20 分钟——
应该先查看源代码！信息收集真的最重要。

### 防御建议
- 生产环境删除调试注释和测试账号
- 备份文件不放在 Web 目录
- 参数化查询防注入，服务端校验资源归属防越权
```

看，这就是一份完整、清晰、有思考的 Writeup。

## 31.4 写作技巧

| 技巧 | 说明 |
|------|------|
| **及时写** | 解题后马上写，记忆最清晰；拖久了细节全忘 |
| **配图/代码** | 关键步骤配截图或 payload，方便读者复现 |
| **写"为什么"** | 不只写"我做了 X"，要写"为什么做 X" |
| **记录失败** | 走过的弯路最有价值——读者能少踩坑 |
| **标注来源** | 参考了别人的 Writeup 要注明，尊重原创 |
| **攻防兼备** | 加上防御建议，体现完整理解 |
| **持续更新** | 有新的理解就回来补充 |

## 31.5 用 Writeup 做知识管理

把 Writeup 整理成个人知识库（呼应第 25.8 节的速查表）：

```
my-ctf-notes/
├── web/
│   ├── sqli-labeled.md      # 注入题 Writeup 集合
│   ├── xss-notes.md
│   └── ssrf-notes.md
├── misc/
│   ├── stego-notes.md
│   └── forensics-notes.md
└── cheatsheet.md            # 速查表（第 25 章）
```

按方向/漏洞类型归档，积累几十篇后，你就有了一份**自己写的、最贴合你理解的百科全书**——比任何外部资料都好用。

**工具**：本地 Markdown 文件夹 + Git（版本管理）、Notion、Obsidian（双链笔记）都可以。GitHub 上建个公开仓库存 Writeup，还能当作品集。

## 31.6 Writeup 与职业发展

持续写 Writeup 能带来实际收益：

- **作品集**：求职时展示你的能力和表达能力（安全岗位非常看重）
- **社区影响力**：在技术社区/博客发表，建立个人品牌
- **教学能力**：能写清楚 = 能传授 = 进阶到更高阶岗位
- **面试素材**：面试常被问"讲一道你印象深的题"——Writeup 就是现成答案

第 32 章会讲"从 CTF 到真实安全能力"，Writeup 是连接两者的桥梁之一。

## 本章练习

1. 把第 28 章或第 29 章的一道实战题，按本章结构写一份完整 Writeup。
2. 找一道你最近解出的题，写 Writeup，重点写"踩坑与反思"部分。
3. 建立你的 Writeup 知识库目录结构（本地文件夹或 Git 仓库）。
4. 在 GitHub 建一个仓库存放你的 Writeup，写一份 README 介绍它。
5. 找一篇社区高赞 Writeup，分析它为什么写得好——列出 3 个值得学习的点。
6. 思考：写 Writeup 时"卡住写不下去"的地方，说明了什么？（提示：那就是你的知识盲区）
