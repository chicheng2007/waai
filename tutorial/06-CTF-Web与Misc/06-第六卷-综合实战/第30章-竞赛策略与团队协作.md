# 第 30 章 CTF 竞赛策略与团队协作

## 本章目标

读完这一章，你将能够：

- 理解 CTF 比赛的得分机制与时间策略
- 掌握个人参赛的选题与时间分配方法
- 了解团队分工与协作的最佳实践
- 学会在比赛压力下保持高效
- 知道如何赛后复盘、持续提升

> 技术相当的两支队伍，成绩可能差很多——差别往往在"策略"上：会不会选题、会不会分配时间、会不会协作。这一章讲"怎么打比赛"，是从"会做题"到"会赢"的关键。

---

## 30.1 CTF 得分机制

### 30.1.1 解题模式（Jeopardy）计分

- 每道题有固定分值，通常按难度递增（简单 100 分、中等 300 分、困难 500 分）
- 有些比赛有 **dynamic scoring（动态分值）**：解出的人越多，分值越低——鼓励早期解出难题
- 有些有 **一血（First Blood）** 奖励：第一个解出的人/队有额外加分
- 提交 flag 正确即得分，错误一般不扣分（但可能有限频）

### 30.1.2 时间

比赛通常持续 24–72 小时。这是**体力活+脑力活**的组合—— How you 分配这几十个小时，直接决定成绩。

## 30.2 个人参赛策略

### 30.2.1 选题策略

**原则：先易后难，广撒网再深挖。**

```
① 开局先扫一遍所有题目，按方向和难度分类
② 先做"签入题"和简单题——快速拿分、建立信心、熟悉平台
③ 遇到卡住的题，设一个时间上限（如 40 分钟），到点就换题
④ 中后期再回头攻难题——此时可能已有新线索/灵感
⑤ 临近结束，检查有没有"低分但没做"的题，捡漏
```

**常见错误**：
- 死磕一道难题到最后——时间全耗光，简单题没做
- 只做自己擅长的方向——不擅长的方向也有送分题

### 30.2.2 时间管理

| 阶段 | 策略 |
|------|------|
| 开局 1 小时 | 快速扫题 + 拿下所有签入/简单题 |
| 中期 | 主攻中等题，卡住就换 |
| 后期 | 回头攻难题 + 捡漏 + 检查 |
| 最后 1 小时 | 只做有把握的，确保已得分的 flag 提交成功 |

**休息很重要**：24 小时比赛不睡觉，后半程效率极低。合理休息（每 2 小时歇 10 分钟，睡 4–6 小时）反而总分更高。

### 30.2.3 工具与笔记准备

**赛前准备好**（比赛时没时间装）：

- 工具齐全（第 25 章的工具箱）
- 速查表（第 25.8 节）
- 脚本模板（第 24 章的脚本存好，随时改）
- 笔记模板（第 3.9、31 章）
- flag 接收服务器（XSS 题用，第 24.8 节）

## 30.3 团队协作

### 30.3.1 分工

团队赛（通常 3–10 人）的关键是**按方向分工**：

| 角色 | 负责 |
|------|------|
| Web 手 | Web 漏洞题（第 6–15 章） |
| Misc 手 | 隐写/流量/取证（第 16–22 章） |
| Crypto 手 | 密码题（第 21 章 + 深入） |
| PWN/Reverse 手 | 二进制题（本教程未展开） |
| 通用/协调 | 扫题、捡漏、写 Writeup、盯 flag 提交 |

**原则**：每人主攻擅长方向，同时留意其他方向的简单题。

### 30.3.2 协作工具

- **即时通讯**：建群，发现线索随时同步（"这个站有 .git 泄露""这道 MISC 解出 base64 了"）
- **共享文档**：共享笔记，记录每道题的进度、假设、已试方法——避免重复劳动
- **任务看板**（如 Trello/飞书）：标记"进行中/已解出/放弃"
- **flag 管理**：指定一人统一提交，避免重复/错交

### 30.3.3 协作心法

- **通气**：发现问题立刻说，别自己闷头卡——队友可能正好擅长
- **不重复**：开工前问一句"谁在做这道题？"
- **互补**：一个方向卡住，队友换个方向可能突破
- **复盘**：解出后分享思路，全队学习（也是写 Writeup 的素材）

---

## 30.4 比赛压力下的高效

| 挑战 | 应对 |
|------|------|
| 卡壳焦虑 | 记住"卡住是常态"，换题或看 hint，别钻牛角尖 |
| 时间压力 | 按选题策略，设时间上限 |
| 信息过载 | 用笔记记录，别靠脑子记所有线索 |
| 疲劳 | 合理休息，保持节奏 |
| 被"假 flag"骗 | 提交验证，别自嗨 |

---

## 30.5 赛后复盘

比赛结束不等于学习结束。**复盘是提升最快的一环**：

1. **整理 Writeup**：把解出的题写成 Writeup（第 31 章）——固化能力
2. **看别人的 Writeup**：学习没解出的题的思路——补短板
3. **分析失分**：哪些题本该做对却没做？为什么？（知识盲区/粗心/时间分配）
4. **更新知识库**：把新学到的 payload、工具、手法加进自己的速查表
5. **制定下一步**：根据暴露的短板，决定接下来学什么

**关键**：**一场比赛的收获 = 解出的题 + 没解出但看懂的题**。只看自己解出的题，成长有限。

---

## 30.6 从新手到高手

一条现实的成长路径：

| 阶段 | 目标 | 做法 |
|------|------|------|
| 入门 | 能解签入题 | 学完本教程 + 靶场（第 27 章） |
| 进阶 | 能稳定解中等题 | 平台刷题（BuuCTF/NSSCTF）+ 写 Writeup |
| 熟练 | 能攻难题 | 专项突破（Web 深挖或 Misc 深挖） |
| 高手 | 团队核心 | 参加实战比赛 + 复现 CVE + 贡献工具 |

**没有捷径，只有刻意练习**。每道题的"观察→假设→验证→归纳"都在积累你的模式库。量变引起质变。

## 30.7 本章总结

| 知识点 | 核心要点 |
|--------|---------|
| 计分 | 固定/动态分值、一血奖励、错误一般不扣分 |
| 选题 | 先易后难、卡住换题、后期捡漏 |
| 时间 | 分阶段分配、合理休息 |
| 赛前准备 | 工具、速查表、脚本模板、笔记模板 |
| 团队协作 | 按方向分工、共享笔记、通气不重复 |
| 复盘 | 写 Writeup + 看别人的 + 分析失分 + 更新知识库 |

## 本章练习

1. 选一场即将到来的 CTF，制定你的"选题策略"和"时间分配计划"。
2. 组一个（或模拟一个）3 人队，讨论分工方案，写下来。
3. 准备你的"赛前工具包"：工具、速查表、脚本模板、笔记模板（检查是否齐全）。
4. 回顾你最近一次比赛/练习，用 30.5 的复盘框架分析得失。
5. 思考：如果你在比赛中卡在一道题 1 小时，你会怎么决策？（写下你的判断标准）
