# 第 1 章 CTF 是什么，为什么从 Web 和 Misc 开始

## 本章目标

读完这一章，你将能够：

- 用大白话向别人解释"CTF 是干什么的"
- 说清楚 CTF 的几种赛制和五大方向
- 理解为什么零基础最适合从 Web + Misc 入手
- 知道去哪里练题、怎么看自己的水平
- 建立起"合法竞技场"的正确认知

> 本章不涉及任何技术细节，只帮你建立整体认知。就像学开车前先搞懂"交规、路况、车的组成"，而不是一上来就踩油门。

---

## 1.1 一个生活类比：CTF 就是"安全界的密室逃脱"

想象一下密室逃脱：你被关在一个房间里，线索藏在各种地方——画框后面、书页夹缝、密码锁里。你要通过观察、推理、组合线索，一步步解开谜题，最后拿到"通关钥匙"。

**CTF 就是这个模式的网络安全版本**：

- "房间" = 主办方搭建的靶场（一个有漏洞的网站、一段神秘的数据包、一张藏了信息的图片）
- "线索" = 系统里故意留下的漏洞、编码、隐藏数据
- "通关钥匙" = **flag**，一段格式固定的字符串，比如 `flag{this_is_a_test}` 或 `NSSCTF{d41d8cd98f00}`
- "解谜过程" = 你用各种技术手段找到 flag

当你找到 flag，提交到比赛平台，系统会验证是否正确。正确就得分，这就是"夺旗"——把对方的旗帜（flag）夺过来。

**小白问：flag 长什么样？**
> 通常是一段带花括号的字符串，如 `flag{hello_world}`。它只是个"凭证"，证明你确实解出来了。真实世界里的 flag 不是密码，也不通向任何真实系统——它只是比赛计分的凭据。

## 1.2 CTF 的三大赛制

CTF 比赛按玩法主要分为三类，了解它们能帮你选择合适的练习方式。

### 1.2.1 解题模式（Jeopardy）

这是最常见、最适合新手的模式，也是本教程默认针对的模式。

**玩法**：主办方出一系列独立的题目，按难度和类型分类（Web、Misc、Crypto、PWN、Reverse）。你自由选题，解出一道得相应分数。题目之间彼此独立，像考试里的"选择题+解答题"。

**特点**：
- 时间灵活（比赛通常持续 24–72 小时，也可以赛后无限期"复现"）
- 题目独立，卡住一道可以换一道
- 分数由易到难递增，新手也能拿到基础分

**适合**：入门练习、个人打靶。**本教程所有例子都是解题模式。**

### 1.2.2 攻防模式（AwD，Attack With Defense）

**玩法**：每支队伍有自己的一台"靶机"（一个带漏洞的服务），既要攻击别人的靶机拿 flag，又要修补自己靶机的漏洞防止被攻击。攻防同时进行，得分=攻击得分+防守扣分。

**特点**：
- 强度高，实时对抗，考验速度和团队配合
- 需要快速审计代码、写攻击脚本、打补丁
- 通常只有高手队伍参与

**适合**：进阶选手。零基础阶段了解即可。

### 1.2.3 混合模式

解题 + 攻防的结合，比如先解题解锁攻击权限。大型赛事常用。

**小白问：我应该参加哪种？**
> 从解题模式开始。攻防模式需要极强的代码审计和自动化能力，那是几个月甚至几年后的目标。先能独立解出 Web/Misc 基础题，再谈攻防。

## 1.3 CTF 的五大方向

CTF 题目传统上分为五大方向。理解每个方向"在玩什么"，才能明白为什么本套选 Web + Misc 作为切入点。

| 方向 | 中文 | 在玩什么 | 入门门槛 |
|------|------|---------|---------|
| **Web** | Web 安全 | 找网站漏洞：注入、上传、越权……拿到 flag | 低 |
| **Misc** | 杂项 | 隐写、编码、取证、流量分析……各种"脑洞"题 | 低 |
| **Crypto** | 密码学 | 破译加密：古典密码、RSA、哈希…… | 中（需数学） |
| **PWN** | 二进制漏洞利用 | 利用程序内存漏洞（溢出、UAF）拿到 shell | 高（需汇编/系统） |
| **Reverse** | 逆向工程 | 反编译程序，看懂它的逻辑，找出 flag 或算法 | 高（需逆向基础） |

### 1.3.1 Web 方向：最贴近真实业务的漏洞

Web 题给你一个（ usually 故意有漏洞的）网站，你要利用漏洞拿到 flag。常见漏洞：

- **SQL 注入**：在输入框里构造特殊内容，让数据库吐出不该给的数据（第 6 章）
- **XSS**：让网页执行你注入的脚本（第 7 章）
- **文件上传**：绕过限制上传 WebShell，进而控制服务器（第 8 章）
- **SSRF / 反序列化 / JWT / SSTI / XXE**（第三卷进阶）

**为什么适合入门**：结果直观——你构造的输入要么成功要么失败，反馈快；靶场工具成熟（DVWA、sqli-labs 一键搭建）；而且这些漏洞真实世界大量存在，学完就能理解新闻里的安全事件。

### 1.3.2 Misc 方向：包罗万象的"脑洞"题

Misc（Miscellaneous，杂项）是最灵活的方向，什么都可能考：

- **编码解码**：Base64、Hex、摩斯密码、URL 编码……（第 16 章）
- **隐写术**：图片、音频里藏了肉眼看不见的信息（第 17 章）
- **文件分析**：压缩包伪加密、文件头损坏修复（第 18 章）
- **流量分析**：给一个 pcap 包，从中找出传输的 flag（第 19 章）
- **日志/内存/磁盘取证**：从日志、内存镜像里挖证据（第 20、22 章）
- **密码学入门**：一些简单的古典密码和 RSA（第 21 章）

**为什么适合入门**：不需要底层二进制知识，靠观察力、工具和逻辑就能解；成就感强——一张看似普通的图片，被你"变"出隐藏的 flag，特别有满足感。

### 1.3.3 其他三方向为什么暂不展开

- **Crypto**：需要数论、群论基础，入门曲线陡。本套只在第 21 章做基础覆盖，够应付 Misc 里的简单密码题。
- **PWN / Reverse**：需要汇编、操作系统、二进制格式知识。它们是本系列**系统语言卷**之后的方向——先打好 C/C++ 和 Linux 基础，再学 PWN 会顺很多。本套不做展开，避免劝退零基础读者。

**小白问：只学 Web + Misc 够打比赛吗？**
> 够打入门级比赛，也能拿到不少分。很多新手赛前三个月主攻这两个方向就能上分。等你有基础了，再按需扩展 Crypto/PWN/Reverse。

## 1.4 CTF 与真实安全的区别

这点必须讲清楚，否则容易误解。

| 维度 | CTF | 真实安全（渗透测试/防护） |
|------|-----|--------------------------|
| 环境 | 隔离靶场，随便打 | 生产系统，有业务在跑，操作要谨慎 |
| 授权 | 天然授权 | 必须有书面授权、范围、时间窗 |
| 目标 | 拿 flag（一个字符串） | 找漏洞并修复、写报告、验证修复 |
| 规则 | 有明确规则，题目设计可控 | 无规则，情况复杂多变 |
| 失败成本 | 几乎为零，重启靶机即可 | 可能造成业务中断、数据损坏 |

**关键认知**：CTF 是**训练场**，不是真实战场。在 CTF 里可以尽情尝试各种 payload，但在真实系统里，同样操作可能违法或造成损害。你在 CTF 里培养的思维（观察、假设、验证、归纳）是有价值的，但**工具使用时必须切换场景意识**。

这也是本教程反复强调合规的原因——把能力用对地方。

## 1.5 去哪里练题

### 1.5.1 新手靶场（先打这些）

| 靶场 | 方向 | 特点 |
|------|------|------|
| **DVWA** | Web | 经典中的经典，漏洞分低/中/高/不可能四个等级，带源码 |
| **sqli-labs** | Web/SQLi | SQL 注入专项，从入门到进阶 65 关 |
| **Pikachu** | Web | 国产，中文友好，漏洞全面 |
| **Upload-labs** | Web/上传 | 文件上传专项 21 关 |
| **Vulhub** | 综合 | 一键 Docker 起各种真实 CVE 环境 |

第 27 章会手把手教你搭建这些靶场。现在你只需要知道它们存在。

### 1.5.2 CTF 练习平台

| 平台 | 说明 |
|------|------|
| **BuuCTF** | 国内老牌，题目丰富，有大量真题复现，适合新手 |
| **NSSCTF** | 国内新兴平台，活动多，新手友好 |
| **CTFtime** | 国际赛事日历与成绩榜，找比赛用 |
| 各高校/企业赛 | 很多比赛结束开放复现，可下载题目 |

### 1.5.3 如何选择第一道题

新手最容易犯的错：一上来挑最难的题，卡三小时崩溃放弃。正确的做法：

1. 从**签入题**（sign-in / 简单题）开始——通常送分，帮你熟悉平台操作
2. 按方向筛选，只做 Web 和 Misc 的入门题
3. 一道题卡超过 40 分钟没思路，就去看 Writeup（别人的解题记录），**看懂思路比死磕更重要**
4. 看懂后，**自己关掉 Writeup 重新做一遍**——这一步是能力内化的关键

## 1.6 怎么看 Writeup 才有效

Writeup 是别人写的解题过程记录。新手常犯两种错：

- **错误一**：直接抄 flag 提交，不看过程——等于没学
- **错误二**：从头到尾读一遍，觉得自己懂了——其实只是"看起来懂"

**正确的读法**：

1. 先自己尝试，卡住了再看
2. 只看第一步的提示，然后合上，自己往下推
3. 实在推不动再看下一步，如此反复
4. 读完后，用自己的话复述整个思路，并**独立重做一遍**

第 31 章会教你写自己的 Writeup，这是巩固能力的最好方式。

## 1.7 补充：CTF 的起源、发展与赛事体系

了解 CTF 的历史，能帮你理解它的定位和价值——它不是一个"游戏"，而是安全人才培养体系的重要一环。

### 1.7.1 CTF 的起源

CTF 的概念最早可追溯到 1996 年。在拉斯维加斯的 DEF CON（全球最著名的黑客大会）上，一群安全爱好者发起了一场"夺旗"比赛——参赛者要破解密码、突破系统、拿到对方机器上的"旗子"。这就是 CTF 的雏形。

2001 年，首届 DEF CON CTF 正式举办，此后每年一届，成为全球 CTF 界的"世界杯"。DEF CON CTF 的难度极高，只有全球顶尖队伍才能参与——它是安全圈的顶级荣誉。

### 1.7.2 CTF 在中国的兴起

中国的 CTF 文化起步稍晚但发展迅猛：

- **2011 年左右**：国内开始出现第一批 CTF 比赛（如 XCTF 前身）
- **2014–2016 年**：XCTF 联赛等全国性赛事兴起，高校开始成立安全社团
- **2017 年至今**：腾讯、阿里、360 等企业赛事蓬勃发展；高校 CTF 课程普及；NSSCTF、BuuCTF 等练习平台出现

如今，CTF 已成为国内网络安全人才培养的重要渠道——很多安全从业者的入行起点就是 CTF。企业在招聘安全岗位时，CTF 成绩也是重要的能力参考。

### 1.7.3 为什么企业和高校重视 CTF

| 视角 | 价值 |
|------|------|
| **企业** | 发现人才（CTF 高手往往实战能力强）、检验产品安全、提升品牌 |
| **高校** | 实践教学（安全课太抽象，CTF 提供动手场景）、培养兴趣、以赛促学 |
| **个人** | 证明能力、建立履历、获得奖金/offer、结识同好 |

CTF 把"枯燥的安全理论"变成了"有趣的闯关游戏"，极大降低了学习门槛——这正是它风靡全球的原因。

### 1.7.4 主流赛事一览（了解）

| 赛事 | 说明 |
|------|------|
| **DEF CON CTF** | 全球顶级，高手云集 |
| **XCTF** | 中国首个国际级联赛，高校参与广 |
| **Tianfu Cup（天府杯）** | 中国的顶级实战赛事 |
| **强网杯** | 国内知名赛事 |
| **各大企业赛** | 腾讯、阿里等，常有机会直接拿 offer |
| **CTFtime** | 全球赛事日历，查比赛用 |

**新手建议**：不必追顶级赛事，从面向新人的比赛（很多平台有"新手赛"）和练习平台开始，积累经验后再挑战高难度赛事。

### 1.7.5 CTF 的局限（客观看待）

CTF 虽好，但也要认清它的局限（第 1.4、32.1 节详述）：

- CTF 题目是"设计出来"的，考点明确；真实漏洞往往更隐蔽、更混乱
- CTF 只考"攻破"，不考"修复、报告、沟通"——这些是真实工作的必备能力
- 过度沉迷 CTF 的"炫技"打法，可能忽视工程能力和合规意识

**正确的态度**：把 CTF 当作**起点和训练场**，用它建立兴趣和基本功，然后向更广阔的安全领域（渗透测试、应急响应、安全开发、二进制安全）拓展。本教程第 32 章会详细讲这条转化路径。

| 你学到的 | 核心要点 |

## 本章练习

1. 用你自己的话，向一个完全不懂的朋友解释"CTF 是干什么的"。
2. 打开 CTFtime 网站，找一场最近的比赛，看看它的题目分类。
3. 在 BuuCTF 或 NSSCTF 注册账号，浏览一下 Web 和 Misc 方向的题目列表。
4. 思考：为什么教程把合规声明放在最前面？（想清楚这个问题，比学任何技术都重要）
5. 明确你的学习目标：是想打比赛拿分，还是想理解漏洞原理做防御？把答案写在纸上。
