# 第 27 章 CTF 靶场搭建

## 本章目标

读完这一章，你将能够：

- 理解靶场在 CTF 学习中的作用
- 用 Docker 一键搭建 DVWA、sqli-labs、Vulhub 等主流靶场
- 搭建 Upload-labs、Pikachu 等专项靶场
- 理解靶场的隔离与安全使用原则
- 建立自己的"随身练兵场"

> 前面四章讲的知识和工具，都需要一个"能合法随便打"的地方来练——这就是靶场。这一章教你搭好自己的靶场，随时开练。搭靶场本身也是 Linux/网络技能的实践（呼应 Linux 卷）。

---

## 27.1 为什么需要靶场

真实网站不能随便测试（违法），CTF 比赛平台有时间限制。靶场是**属于你自己的、永久可用的、合法授权的练习环境**：

- 想打多少次打多少次
- 打挂了重启/快照还原即可
- 有源码可看，能对照理解漏洞原理
- 从易到难，循序渐进

**核心原则**：**靶场只监听本地（127.0.0.1）或内网，绝不暴露到公网**。否则你的"漏洞靶场"可能被人利用，反而成为攻击入口。

---

## 27.2 Docker：靶场搭建的最佳方式

传统搭建要配 LAMP 环境（Linux+Apache+MySQL+PHP），繁琐易错。Docker 让一切变成一行命令。

### 27.2.1 Docker 基础

```bash
# 安装 Docker（Kali/Ubuntu）
sudo apt install docker.io
sudo systemctl start docker

# 基本命令
docker pull 镜像名          # 拉镜像
docker run -d -p 端口映射 镜像名  # 运行容器
docker ps                   # 看运行中的容器
docker stop 容器ID          # 停止容器
docker rm 容器ID            # 删除容器
```

`-d` 后台运行，`-p 宿主端口:容器端口` 做端口映射（如 `-p 8081:80` 表示访问本机 8081 就是容器的 80）。

**小白问：Docker 是什么？**
> 可以理解为"轻量级虚拟机"——把应用和它的环境打包成一个"容器"，一键运行，不用手动配环境。靶场都被打包成 Docker 镜像，拉下来就能用。

## 27.3 DVWA：综合入门靶场

第 2 章已经用过，这里给完整搭建方式：

```bash
# 方式一：Docker 一键
docker run -d -p 8081:80 vulnerables/web-dvwa

# 访问 http://127.0.0.1:8081
# 点 "Create / Reset Database" 初始化
# 默认账号 admin / password
```

DVWA 分四个安全等级（Low/Medium/High/Impossible），覆盖暴力破解、SQL 注入、XSS、文件上传、命令注入、CSRF 等——**新手第一个靶场，非它莫属**。

**用法**：每学一个漏洞（第二卷），就在 DVWA 对应模块（选 Low 等级）亲手打一遍，然后看源码理解原理，再调高等级尝试绕过。

## 27.4 sqli-labs：SQL 注入专项

```bash
# Docker 镜像
docker run -d -p 8082:80 acgpiano/sqli-labs

# 访问 http://127.0.0.1:8082
# 先点页面上的 "Setup/reset Database for labs" 初始化
```

sqli-labs 有 65 关（Less-1 到 Less-65），从基础联合注入到盲注、宽字节、堆叠注入、WAF 绕过全覆盖——**学第 6 章 SQL 注入时，这里是主战场**。

**学习路径**：Less-1 到 Less-10（基础注入）→ Less-11 到 Less-20（POST/盲注）→ 后面进阶。每关尝试手工，不看答案。

## 27.6 Pikachu：国产综合靶场

```bash
# 项目地址：https://github.com/zhuifengshaonianhanlu/pikachu
```

## 27.7 Vulhub：真实 CVE 靶场

```bash
# 项目地址：https://github.com/vulhub/vulhub
git clone https://github.com/vulhub/vulhub.git
cd vulhub

# 进入某个漏洞目录，一键起环境
cd flask/ssti
docker compose up -d

# 访问 http://127.0.0.1:端口
```

Vulhub 收录了数百个真实 CVE 环境（如 Log4j、Shiro、SSTI、各种 RCE）——**学第三卷进阶漏洞时，用 Vulhub 复现真实漏洞**。每个目录有 README 说明漏洞原理和利用方法。

**注意**：Vulhub 里的漏洞是"真"漏洞，起环境后别暴露到公网，只在本地用。

## 27.8 靶场使用守则

| 守则 | 原因 |
|------|------|
| **只监听本地/内网** | 防止靶场被外部利用 |
| **打完及时停止容器** | 节省资源、减少暴露面 |
| **定期更新镜像** | 修复靶场本身的问题 |
| **快照/备份** | 打挂了快速恢复 |
| **看源码学习** | 靶场的最大价值是"可对照源码理解原理" |
| **遵守授权** | 靶场是给你的合法沙盒，但别把手法用到外网 |

## 27.9 靶场学习路线

```
入门：DVWA（Low → Impossible，全模块过一遍）
  ↓
专项：sqli-labs（SQL 注入）+ Upload-labs（上传）
  ↓
综合：Pikachu（漏洞全面）
  ↓
进阶：Vulhub（真实 CVE 复现，学第三卷进阶漏洞时）
  ↓
实战：CTF 平台刷题（BuuCTF / NSSCTF）
```

**方法**：每打通一个靶场/关卡，写一条笔记（漏洞类型、payload、原理、防御）——呼应第 3 章的归纳。这些笔记就是你自己的能力库。

## 本章练习

1. 安装 Docker，用一行命令起 DVWA，确认能访问和登录。
2. 搭建 sqli-labs，初始化数据库，打通 Less-1 到 Less-4。

5. 检查你的靶场端口是否只监听本地（用 `netstat` 或 `ss` 查看）。
6. 整理一份"靶场通关笔记"，记录你打通的每一关和学到的 payload。
