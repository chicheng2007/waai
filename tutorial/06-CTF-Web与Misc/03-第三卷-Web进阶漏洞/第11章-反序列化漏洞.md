# 第 11 章 反序列化漏洞

## 本章目标

读完这一章，你将能够：

- 理解序列化与反序列化的概念（对象 ↔ 字符串的转换）
- 说清楚反序列化漏洞的本质："还原对象时触发了恶意代码"
- 认识 PHP 的魔术方法（__wakeup、__destruct 等）如何被利用
- 了解 Java 反序列化漏洞的基本思路
- 知道 Shiro、Log4j 等经典反序列化 CVE
- 掌握反序列化漏洞的防御方法

> 反序列化是 CTF 进阶阶段的高频考点，也是真实世界里无数严重 CVE 的根源。它比前面的漏洞"抽象"一些，但一旦理解，你会发现它逻辑非常优雅。这一章用类比帮你跨过理解门槛。

---

## 11.1 概念：序列化与反序列化

### 11.1.1 一个生活类比：家具的拆装

**序列化**就像把一件组装好的家具**拆成零件、打包成一个箱子**，方便运输和存放。

**反序列化**就是把箱子里的零件**重新组装回家具**。

程序里也是这样：

- **对象**（一个数据结构，有属性和方法）在内存里，不方便传输/存储
- **序列化**：把对象转换成一个字符串（或字节流），能存进数据库、Cookie、网络传输
- **反序列化**：把字符串还原回对象

**漏洞在哪**？如果攻击者能篡改那个"箱子里的零件"（序列化后的字符串），而"组装过程"（反序列化）会自动执行某些动作——攻击者就能在组装时触发恶意操作。

比如家具说明书说"组装完后自动通电"，攻击者往箱子里塞了个危险的零件，组装时一通电就出问题。

**核心一句话**：**反序列化会把数据还原成对象，而还原过程可能自动调用代码；如果数据可控，代码就可控。**

---

## 11.2 PHP 序列化格式

PHP 用 `serialize()` 把对象转成字符串。看一个例子：

```php
<?php
class User {
    public $name = "admin";
    public $isAdmin = false;
}
$u = new User();
echo serialize($u);
?>
```

输出：

```
O:4:"User":2:{s:4:"name";s:5:"admin";s:7:"isAdmin";b:0;}
```

解读这串"密码"：

| 片段 | 含义 |
|------|------|
| `O:4:"User"` | 对象（Object），类名长度 4，类名 User |
| `:2:` | 有 2 个属性 |
| `s:4:"name"` | 属性名：字符串，长度 4，值 name |
| `s:5:"admin"` | 属性值：字符串，长度 5，值 admin |
| `s:7:"isAdmin";b:0` | 属性 isAdmin，布尔值 false |

理解这个格式很重要——因为攻击者就是**修改这串字符串**里的值（比如把 `b:0` 改成 `b:1`，把 isAdmin 变成 true），再让服务器反序列化它。

**反序列化函数**：`unserialize()` 把这串字符串还原成对象。

## 11.3 魔术方法：漏洞的"扳机"

PHP 对象有一批**魔术方法**，在特定时机自动调用。反序列化时，某些魔术方法会**自动触发**——这就是漏洞的"扳机"。

| 魔术方法 | 触发时机 |
|---------|---------|
| `__wakeup()` | 反序列化时立即调用 |
| `__destruct()` | 对象销毁时调用（脚本结束也会触发） |
| `__toString()` | 对象被当字符串使用时 |
| `__invoke()` | 对象被当函数调用时 |
| `__call()` | 调用不存在的方法时 |

**漏洞示例**：

```php
<?php
class Logger {
    public $filename = "log.txt";
    function __destruct() {
        file_put_contents($this->filename, "logged");  // 销毁时写文件
    }
}
// 假设服务器反序列化用户可控的数据
$data = $_COOKIE['data'];
unserialize($data);
?>
```

`__destruct()` 在对象销毁时自动执行，把 `$this->filename` 当路径写文件。攻击者构造一个序列化的 Logger 对象，把 `filename` 改成 `shell.php`，内容改成 PHP 代码：

```
O:6:"Logger":1:{s:8:"filename";s:9:"shell.php";}
```

服务器反序列化这个对象 → 脚本结束时触发 `__destruct()` → 往 `shell.php` 写入内容 → 配合其他手法可得 WebShell。

**这就是反序列化漏洞的逻辑**：**攻击者控制反序列化对象的属性，而魔术方法会用这些属性执行敏感操作。**

## 11.4 CTF 中的反序列化利用

### 11.4.1 构造 POP 链

真实场景里，单个魔术方法往往不能直接拿 flag，需要把多个类的方法**串起来**——这叫 **POP 链**（Property-Oriented Programming chain，面向属性编程链）。

思路：找到一系列类，类 A 的 `__destruct` 调用类 B 的方法，类 B 的方法又调用类 C 的敏感操作……攻击者精心构造嵌套对象，让反序列化后触发一整条链，最终执行危险操作（如文件读取、命令执行）。

**CTF 里的典型流程**：

```
① 审计源码，找出所有类和魔术方法
② 找"入口"（哪个魔术方法在反序列化时触发）
③ 找"终点"（哪个方法能做危险操作，如 file_get_contents、system）
④ 串起中间的类，构造 POP 链
⑤ 序列化恶意对象，提交给反序列化入口
```

### 11.4.2 PHP 反序列化的字符串逃逸

有一种巧妙技巧：利用序列化字符串的长度字段做"逃逸"，篡改属性值。比如过滤器把某些字符替换（如把 `"` 转义），导致长度与实际不符，攻击者可以借此注入额外的属性。

这是 CTF 里 PHP 反序列化的经典进阶考点，需要精确计算字符串长度。

### 11.4.3 __wakeup 绕过（CVE-2016-7124）

老版本 PHP 里，如果序列化字符串中声明的属性个数**大于实际属性个数**，`__wakeup()` 就不会被调用——用来绕过 `__wakeup` 里的检查/重置逻辑。

```
O:4:"User":2:{...}   → 改成 O:4:"User":3:{...}（属性数虚报为 3）
```

## 11.5 Java 反序列化（了解）

Java 生态里反序列化漏洞更普遍、危害更大，因为很多框架（如 Apache Commons Collections、Shiro、Jackson、Fastjson）都涉及反序列化。

**基本原理**：Java 用 `ObjectInputStream.readObject()` 反序列化。如果反序列化的类有 `readObject()` 方法且里面做了危险操作，或利用" gadget 链"（类似 PHP 的 POP 链）调用危险方法，就能 RCE。

**CTF/真实世界经典案例**：

| 漏洞 | 说明 |
|------|------|
| **Apache Shiro** | 记住我功能的 Cookie 反序列化，默认密钥可预测 → RCE |
| **Log4Shell (Log4j2, CVE-2021-44228)** | 日志里的 `${jndi:ldap://...}` 触发 JNDI 加载远程恶意类 → RCE |
| **Fastjson** | JSON 反序列化 `@type` 指定类 → 反序列化漏洞 |
| **WebLogic / Struts2** | 多个经典反序列化 RCE CVE |

**小白问：Java 反序列化 CTF 题怎么做？**
> 通常用工具 **ysoserial** 生成 payload（它内置了各种 gadget 链），配合靶场复现。Java 反序列化需要 Java 基础，CTF 里有专门的 Java 方向。作为 Web 进阶学习者，你先理解"反序列化 = 还原对象时执行代码"这个核心概念，具体到 Java 可后续深入。

## 11.6 反序列化漏洞的防御

| 措施 | 说明 |
|------|------|
| **避免反序列化不可信数据** | 根本解法：不要反序列化用户可控的数据 |
| **使用安全格式** | 用 JSON 等纯数据格式，不用语言原生序列化 |
| **签名/加密** | 若必须传序列化数据，加签名防止篡改 |
| **白名单类** | 限制反序列化的类（如 Java 的 JEP 290） |
| **避免危险魔术方法** | 魔术方法里不做敏感操作 |
| **及时打补丁** | 更新有漏洞的库（Shiro/Log4j/Fastjson 等） |

**根本原则**：**序列化数据本质是可执行代码的载体，绝不能信任外部传入的序列化数据。**

## 11.7 本章总结

| 知识点 | 核心要点 |
|--------|---------|
| 序列化/反序列化 | 对象 ↔ 字符串；反序列化还原对象时可能自动执行代码 |
| PHP 格式 | `O:类名长度:"类名":属性数:{属性}` |
| 魔术方法 | `__wakeup`/`__destruct` 等自动触发，是漏洞"扳机" |
| POP 链 | 串联多个类的方法，从入口到危险操作 |
| 绕过技巧 | 字符串逃逸、`__wakeup` 属性数绕过 |
| Java 生态 | ysoserial、Shiro、Log4j、Fastjson 等经典 CVE |
| 防御 | 不反序列化不可信数据 + 用 JSON + 签名 + 白名单类 |
