# 第 10 章 SSRF 服务端请求伪造

## 本章目标

读完这一章，你将能够：

- 理解 SSRF 的本质："让服务器替你发请求"
- 识别 SSRF 的常见出现场景
- 掌握用 SSRF 探测内网、读取本地文件、攻击内网服务的手法
- 理解 gopher 协议打内网服务的进阶技巧
- 知道 DNS rebinding、进制 IP 等绕过手法
- 掌握 SSRF 的防御方法

> SSRF 是近年 CTF 和真实安全的热点漏洞。它的危害在于"借刀杀人"——攻击者不直接访问目标，而是让有权限的服务器替自己去访问，从而突破网络边界。这是第三卷第一个进阶漏洞。

---

## 10.1 一个生活类比：被利用的传达室

想象一栋大楼，外人进不去，但有个传达室（服务器）可以帮你传话、代你办事。你说"帮我去 3 楼拿份文件"，传达室就去了。

正常情况下这很方便——比如"帮我从官网下载个图片"。但如果坏人对传达室说："帮我去机房把主服务器的密码本拿来"，而传达室**不核实这个请求是否合理**就照办——坏人就借传达室之手，拿到了他本不可能接触的东西。

**SSRF 就是这个道理**：服务器提供了"根据我给的 URL 去 fetch 内容"的功能（如图片抓取、网页预览），攻击者把 URL 改成内网地址或本地文件，服务器就替他访问了本来访问不到的地方。

**核心一句话**：**服务器根据用户提供的 URL 发起请求，而用户能控制这个 URL 指向哪里。**

---

## 10.2 SSRF 长什么样：常见场景

| 场景 | 例子 |
|------|------|
| 图片/网页抓取 | `?url=http://example.com/image.jpg` —— 服务器去下载这个图片显示 |
| 网页预览/转码 | 输入一个网址，服务器生成快照 |
| 在线翻译 | 输入 URL，服务器抓取内容翻译 |
| 文件导入 | "从 URL 导入"功能 |
| Webhook 测试 | 填写回调地址，服务器测试连通性 |

**典型代码**（PHP）：

```php
<?php
$url = $_GET['url'];
$content = file_get_contents($url);   // 服务器去请求这个 URL
echo $content;
?>
```

访问 `?url=http://example.com`，服务器去抓 example.com 的内容返回给你。看起来正常。但如果我访问：

```
?url=file:///etc/passwd
```

服务器就去读自己的 `/etc/passwd` 文件并返回——**本地文件读取**。

或者：

```
?url=http://127.0.0.1:8080/admin
```

服务器去访问自己的内网管理后台——**内网探测**。

---

## 10.3 SSRF 能做什么

### 10.3.1 探测内网与端口扫描

服务器通常位于内网，能访问外网访问不到的内部服务。用 SSRF 可以：

```
?url=http://127.0.0.1:80       → 探测本机 80 端口
?url=http://192.168.1.1:8080   → 探测内网其他主机
?url=http://127.0.0.1:3306      → 探测 MySQL 端口
```

通过响应内容、响应时间、报错差异，判断端口是否开放、服务是什么——**把服务器当成内网扫描器**。

### 10.3.2 读取本地文件

用 `file://` 协议：

```
?url=file:///etc/passwd
?url=file:///proc/self/environ   # 环境变量，可能有 flag
?url=file:///var/www/html/config.php  # 数据库配置
```

### 10.3.3 攻击内网服务

这是 SSRF 危害最大的地方。很多内网服务（Redis、Memcached、Elasticsearch）默认无认证，且只监听内网。通过 SSRF 可以从外网间接操作它们：

- **Redis 未授权访问**：通过 SSRF 让服务器连内网 Redis，写入 WebShell 或 SSH key
- **云元数据服务**：访问 `http://169.254.169.254/latest/meta-data/` 窃取云服务器凭证（真实世界的高危场景）

### 10.3.4 gopher 协议：万能攻击通道

`gopher://` 协议允许发送任意 TCP 数据。通过它，攻击者可以构造任意协议的请求（Redis 命令、MySQL 查询、SMTP 邮件），让服务器发给内网服务——**相当于把服务器变成攻击内网的跳板**。

```
?url=gopher://127.0.0.1:6379/_*1%0d%0a$8%0d%0aflushall%0d%0a...
```

这串编码解码后是发给 Redis 的命令。CTF 里的 SSRF 真题常用 gopher 打 Redis/MySQL。

**小白问：gopher 为什么这么强？**
> 因为它能发"原始 TCP 数据"——不受 HTTP 格式限制，你想发什么协议就发什么。只要服务器支持 gopher 协议（很多 fetch 库支持），就能攻击任何基于 TCP 的内网服务。

## 10.4 绕过手法

出题人常会限制 URL（如"必须以 http://example.com 开头"、禁止内网 IP）。绕过方法：

### 10.4.1 进制 IP 表示

```
127.0.0.1 的等价表示：
- 八进制：0177.0.0.1
- 十六进制：0x7f.0.0.1
- 十进制整数：2130706433
- 省略写法：127.1、0x7f.1
```

服务器/库可能解析这些为 127.0.0.1，但字符串过滤没拦住。

### 10.4.2 DNS 解析绕过

```
http://127.0.0.1.nip.io     → 解析到 127.0.0.1
http://localhost
http://[::1]                → IPv6 的 localhost
```

用能解析到内网 IP 的域名（如 nip.io 这种泛解析服务）绕过字符串黑名单。

### 10.4.3 DNS Rebinding（DNS 重绑定）

服务器可能先解析域名、检查 IP 是否内网、再去请求。攻击者控制一个域名，让第一次 DNS 查询返回公网 IP（通过检查），第二次返回内网 IP（实际请求时）——**检查和使用之间的时间差**被利用。

### 10.4.4 302 跳转绕过

服务器检查了初始 URL（合法），但请求跟着 302 跳转到内网地址——如果库会自动跟随跳转，就绕过了。

### 10.4.5 @ 符号与特殊 URL

```
http://example.com@127.0.0.1/    → 实际访问 127.0.0.1（@ 前是用户名）
http://127.0.0.1#example.com      → 片段不发送
```

## 10.5 实战流程

拿到一个可疑的 URL 参数：

```
① 观察：找"服务器会去请求某个 URL"的功能点
② 假设：可能是 SSRF
③ 验证：
   ?url=http://127.0.0.1        → 看是否返回本地服务内容
   ?url=file:///etc/passwd      → 看是否读到本地文件
④ 深入：
   - 扫描内网端口（改端口号看响应）
   - 尝试 gopher 打 Redis/MySQL
   - 尝试云元数据 169.254.169.254
⑤ 遇过滤：用进制 IP / DNS 绕过 / 302 跳转
```

**CTF 典型考点 flag 位置**：内网的某个服务里、本地文件里、Redis 里，或通过云元数据拿到的凭证里。

---

## 10.6 SSRF 的防御

| 措施 | 说明 |
|------|------|
| **白名单** | 只允许访问指定的域名/IP，最有效 |
| **解析后校验 IP** | 解析域名得到 IP，禁止内网/本地地址段 |
| 禁用危险协议 | 只允许 http/https，禁 file/gopher/dict 等 |
| **禁止跟随跳转** | 防止 302 绕过 |
| 统一错误信息 | 避免通过报错差异探测端口 |
| 网络隔离 | 服务器最小化内网访问权限 |

**最难防御的点**：DNS rebinding（要用"解析后锁定 IP 再连接"的方式防御）。理解绕过手法，才能设计真正有效的防御。

## 10.7 本章总结

| 知识点 | 核心要点 |
|--------|---------|
| SSRF 本质 | 服务器按用户给的 URL 发请求，URL 可控 |
| 场景 | 图片抓取、网页预览、URL 导入等"服务器 fetch"功能 |
| 危害 | 内网探测、本地文件读取（file://）、打内网服务（gopher）、云元数据 |
| gopher | 发任意 TCP 数据，攻击 Redis/MySQL 等内网服务 |
| 绕过 | 进制 IP、DNS 泛解析、DNS rebinding、302 跳转、@ 符号 |
| 防御 | 白名单 + 解析后校验 IP + 禁危险协议 + 禁跳转 |

## 本章练习

1. 用 DVWA 或专门 SSRF 靶场，测试 `?url=http://127.0.0.1` 看返回什么。
2. 尝试 `file:///etc/passwd`，确认能否读本地文件（在授权靶场）。
3. 把 127.0.0.1 转成十六进制、十进制、八进制表示，测试哪些能绕过过滤。
4. 查资料了解 gopher 协议打 Redis 的原理（不必实战，理解 payload 结构）。
5. 思考：为什么"先解析域名检查 IP，再请求"仍可能被 DNS rebinding 绕过？
