# 第 4 章 函数、方法与接口

## 本章目标

- 理解 Go 的函数式特性（闭包、 defer）
- 掌握方法（method）
- 掌握接口（interface）
- 理解 Go 的"组合优于继承"哲学

Go 没有 class 和继承，用 struct + 方法 + 接口实现面向对象，更简洁灵活。

---

## 4.1 函数进阶

### 4.1.1 闭包

```go
func counter() func() int {
    count := 0
    return func() int {
        count++
        return count
    }
}

func main() {
    c := counter()
    fmt.Println(c())  // 1
    fmt.Println(c())  // 2
}
```

### 4.1.2 可变参数

```go
func sum(nums ...int) int {
    total := 0
    for _, n := range nums {
        total += n
    }
    return total
}

sum(1, 2, 3)
sum([]int{1, 2, 3}...)   // 展开切片
```

### 4.1.3 defer（延迟执行）

```go
func process() {
    defer fmt.Println("最后执行")   // 函数返回前执行
    fmt.Println("先执行")
}
```

defer 常用于资源清理（关闭文件、释放锁），类似其他语言的 finally：

```go
func readFile(path string) {
    f, err := os.Open(path)
    if err != nil { return }
    defer f.Close()   // 确保关闭，即使后面出错
    // ... 使用 f
}
```

> **多个 defer**：按"后进先出"（LIFO）顺序执行。

## 4.2 方法

方法是绑定到类型上的函数：

```go
type PortRule struct {
    IP     string
    Port   int
    Action string
}

// 值接收者
func (r PortRule) Describe() string {
    return fmt.Sprintf("%s:%d -> %s", r.IP, r.Port, r.Action)
}

// 指针接收者（能修改接收者）
func (r *PortRule) SetAction(action string) {
    r.Action = action
}

func main() {
    rule := PortRule{IP: "192.168.1.1", Port: 22, Action: "ALLOW"}
    fmt.Println(rule.Describe())
    rule.SetAction("DENY")
    fmt.Println(rule.Describe())
}
```

**值接收者 vs 指针接收者**：

- 值接收者：复制一份，不能修改原对象
- 指针接收者：操作原对象，能修改

> 需要修改对象，或对象很大（避免复制开销），用指针接收者。

## 4.3 接口

接口定义方法集合，类型隐式实现（不需要显式声明）：

```go
type Analyzer interface {
    Analyze() string
    Severity() int
}

type Malware struct { Name string }

// Malware 实现了 Analyzer（隐式）
func (m Malware) Analyze() string { return "分析恶意软件: " + m.Name }
func (m Malware) Severity() int   { return 9 }

type Phishing struct { URL string }
func (p Phishing) Analyze() string { return "分析钓鱼: " + p.URL }
func (p Phishing) Severity() int   { return 7 }

func report(a Analyzer) {
    fmt.Printf("%s (等级 %d)\n", a.Analyze(), a.Severity())
}

func main() {
    report(Malware{Name: "WannaCry"})
    report(Phishing{URL: "http://fake.com"})
}
```

> **Go 的接口哲学**：小接口、隐式实现。类型不需要声明"我实现了某某接口"，只要方法匹配就自动满足。这让代码解耦、易测试。

## 4.4 组合优于继承

Go 没有继承，用**嵌入**（embedding）实现组合：

```go
type BaseScanner struct {
    Target string
}

func (b BaseScanner) Scan() string {
    return "扫描 " + b.Target
}

type PortScanner struct {
    BaseScanner   // 嵌入
    Ports []int
}

func main() {
    ps := PortScanner{
        BaseScanner: BaseScanner{Target: "127.0.0.1"},
        Ports: []int{22, 80},
    }
    fmt.Println(ps.Scan())   // 继承了 BaseScanner 的方法
}
```

> 组合比继承更灵活，避免了继承层次的复杂性。

## 4.5 空接口与类型断言

```go
// interface{} 能接受任何类型（Go 1.18+ 可用 any）
func printAny(v interface{}) {
    fmt.Println(v)
}

// 类型断言
func describe(v interface{}) {
    if s, ok := v.(string); ok {
        fmt.Println("字符串:", s)
    } else if n, ok := v.(int); ok {
        fmt.Println("整数:", n)
    }
}
```

## 4.6 接口的最佳实践

### 4.6.1 接受接口，返回结构体

Go 的一句名言："**Accept interfaces, return structs**"（接受接口，返回具体类型）：

```go
// 好：参数用接口（灵活），返回具体类型（调用者能用所有方法）
func processReader(r io.Reader) *bytes.Buffer {
    buf := &bytes.Buffer{}
    buf.ReadFrom(r)
    return buf
}

// 不好：返回接口会限制调用者只能看到接口的方法
func bad() io.Reader { ... }
```

含义：函数参数尽量用接口（接受多种实现），返回值尽量用具体类型（不隐藏能力）。

### 4.6.2 小接口原则

```go
// 好：小而专的接口
type Reader interface { Read(p []byte) (int, error) }
type Closer interface { Close() error }

// 组合
type ReadCloser interface {
    Reader
    Closer
}

// 不好：大而全的接口（强制实现者实现所有方法）
type BigInterface interface {
    Read()
    Write()
    Close()
    Flush()
    Seek()
    // ... 10 个方法
}
```

标准库里的 `io.Reader`、`io.Writer`、`fmt.Stringer` 都是小接口的典范。

### 4.6.3 接口 nil 陷阱

```go
var r io.Reader = nil
fmt.Println(r == nil)   // true

var buf *bytes.Buffer = nil
r = buf                  // r 不是 nil 了！
fmt.Println(r == nil)    // false！接口里有类型信息（*bytes.Buffer），只是值为 nil
```

> **坑**：把 nil 指针赋给接口，接口本身不为 nil。调用方法时会 panic。这是 Go 常见的隐蔽 bug，写代码时要注意。
