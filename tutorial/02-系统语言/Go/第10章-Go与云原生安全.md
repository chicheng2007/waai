# 第 10 章 Go 与云原生安全

## 本章目标

- 理解云原生安全的核心领域
- 理解 Go 在容器/K8s 安全中的地位
- 了解供应链安全工具
- 用 Go 做简单的容器安全检查

云原生（Cloud Native）是当今 IT 架构的主流，而 Go 是云原生的事实语言——Docker、Kubernetes 都是 Go 写的。做云安全，Go 是必备技能。

---

## 10.1 云原生安全概述

### 10.1.1 核心领域

| 领域 | 内容 | 典型工具 |
|------|------|---------|
| 容器安全 | 镜像漏洞、运行时安全 | Trivy、Falco |
| K8s 安全 | 配置错误、权限、网络策略 | kube-bench、kube-hunter |
| 供应链安全 | 依赖漏洞、SBOM | Syft、Grype |
| 基础设施安全 | 云配置、IAM | ScoutSuite、Prowler |

### 10.1.2 为什么 Go 是云原生安全的首选

- Docker、K8s 本身就是 Go 写的，生态天然契合
- 容器镜像小（静态二进制），适合做 sidecar/探针
- 并发强，适合处理大量 API 调用
- 跨平台，各架构都能编译

## 10.2 容器安全基础

### 10.2.1 镜像漏洞扫描概念

容器镜像由多层组成，每层可能包含有漏洞的软件包。扫描就是检查镜像里的包版本是否命中漏洞库（CVE）。

```go
// 概念示例：解析镜像配置，检查基础镜像
package main

import (
    "encoding/json"
    "fmt"
)

type ImageConfig struct {
    Architecture string   `json:"architecture"`
    Config       struct {
        User  string   `json:"User"`
        Env   []string `json:"Env"`
        Cmd   []string `json:"Cmd"`
    } `json:"config"`
    History []struct {
        CreatedBy string `json:"created_by"`
    } `json:"history"`
}

func checkImage(data []byte) {
    var cfg ImageConfig
    json.Unmarshal(data, &cfg)
    
    fmt.Println("架构:", cfg.Architecture)
    
    // 安全检查：是否以 root 运行
    if cfg.Config.User == "" || cfg.Config.User == "root" {
        fmt.Println("[警告] 容器以 root 运行，建议降权")
    }
}
```

### 10.2.2 常见容器安全问题

- 以 root 运行容器
- 特权模式（privileged）
- 挂载宿主机敏感目录
- 镜像包含敏感信息（密钥、token）
- 未限制资源（CPU/内存）

## 10.3 K8s 安全

### 10.3.1 常见风险

- RBAC 权限过大
- 未启用网络策略
- Secret 明文存储
- API Server 暴露
- 容器逃逸

### 10.3.2 用 Go 调用 K8s API

```go
// 需要 client-go: go get k8s.io/client-go
import (
    "context"
    "fmt"
    "k8s.io/client-go/kubernetes"
    "k8s.io/client-go/rest"
)

func listPods() {
    config, err := rest.InClusterConfig()
    if err != nil { return }
    
    clientset, err := kubernetes.NewForConfig(config)
    if err != nil { return }
    
    pods, err := clientset.CoreV1().Pods("").List(context.TODO(), metav1.ListOptions{})
    if err != nil { return }
    
    for _, pod := range pods.Items {
        fmt.Printf("%s/%s\n", pod.Namespace, pod.Name)
    }
}
```

## 10.4 供应链安全

### 10.4.1 SBOM（软件物料清单）

SBOM 记录软件包含的所有组件，是供应链安全的基础。Go 项目的依赖都在 `go.mod`/`go.sum` 里。

```bash
# 生成依赖列表
go list -m all

# 检查已知漏洞（需安装 govulncheck）
govulncheck ./...
```

### 10.4.2 Go 供应链安全工具

- **govulncheck**：Go 官方漏洞检测工具
- **Syft**：生成 SBOM
- **cosign**：镜像签名验证

## 10.5 容器逃逸与运行时安全

容器安全不仅是镜像漏洞，还包括运行时安全。理解这些攻击手法，才能设计有效的检测规则。

### 10.5.1 常见容器逃逸手法

1. **特权模式逃逸**：容器以 `--privileged` 启动，拥有几乎等同宿主机的权限，可直接挂载宿主机磁盘。
2. **挂载逃逸**：把宿主机的 `/` 或 `/var/run/docker.sock` 挂进容器，就能操作宿主机。
3. **内核漏洞逃逸**：利用内核漏洞（如 Dirty Cow）突破命名空间隔离。
4. **Cgroup 逃逸**：通过 cgroup 通知机制在宿主机执行命令。

### 10.5.2 运行时检测（Falco 思路）

Falco 是云原生的运行时安全工具（部分用 C++/Go），通过 eBPF 监控系统调用，检测异常行为：

```go
// 概念示例：检测容器内是否启动了 shell
// 真实 Falco 用 eBPF 内核探针，这里演示检测逻辑的思想

type SecurityEvent struct {
    Process string
    ContainerID string
    Timestamp int64
}

func detectAnomaly(event SecurityEvent) (bool, string) {
    // 规则1：容器内启动交互式 shell 可疑
    suspiciousShells := map[string]bool{
        "bash": true, "sh": true, "zsh": true,
    }
    if suspiciousShells[event.Process] && event.ContainerID != "" {
        return true, "容器内启动交互式 shell: " + event.Process
    }
    
    // 规则2：容器进程访问敏感路径
    // ...
    return false, ""
}
```

> **蓝队视角**：这类检测规则的核心就是"识别偏离基线的行为"——和第 29 章的异常检测思想完全一致，只是场景从网络流量变成了系统调用。

## 10.6 供应链安全深入

### 10.6.1 SolarWinds 事件的启示

2020 年的 SolarWinds 攻击是典型的供应链攻击：攻击者在软件构建过程中植入后门，导致全球大量机构中招。这证明了一件事：**你的安全取决于你最弱的供应商**。

### 10.6.2 SLSA 框架

SLSA（Supply-chain Levels for Software Artifacts）是 Google 提出的供应链安全框架，分 4 个等级：

| 等级 | 要求 |
|------|------|
| L1 | 有构建脚本和来源记录 |
| L2 | 使用托管构建服务，有签名 |
| L3 | 构建过程可审计、防篡改 |
| L4 | 可重现构建、双人审查 |

Go 在这方面的优势：`go.sum` 文件锁定依赖哈希，`govulncheck` 检查已知漏洞，`cosign` 做镜像签名——这些都在帮你提升供应链安全等级。

### 10.6.3 依赖混淆攻击

攻击者发布一个与内部包同名的公开包，诱导构建系统下载恶意版本。Go 通过模块路径（含域名，如 `github.com/company/pkg`）天然防御了这类攻击——这是设计上的安全优势。
