# 第 7 章 内存布局与动态内存管理

## 本章目标

- 理解程序的内存布局（栈、堆、全局区、代码区）
- 掌握 malloc/free 动态内存管理
- 理解栈溢出、堆溢出的原理
- 理解内存泄漏

这一章是理解 C/C++ 安全漏洞的理论核心。搞懂内存布局，你就明白了漏洞为什么发生、怎么利用、怎么防御。

## 7.1 程序的内存布局

一个 C 程序运行时，内存大致分成这些区域：

```
高地址
┌─────────────────┐
│      栈 (Stack)  │  ← 局部变量、函数参数、返回地址；向下增长
├─────────────────┤
│      ↓    ↑     │
│   空闲内存空间   │
│      ↓    ↑     │
├─────────────────┤
│      堆 (Heap)   │  ← malloc 分配的内存；向上增长
├─────────────────┤
│  全局/静态区(.bss/.data) │ ← 全局变量、static 变量
├─────────────────┤
│      代码区(.text)│  ← 程序的机器指令（只读）
低地址
```

### 7.1.1 各区域特点

| 区域 | 存什么 | 生命周期 | 增长方向 | 特点 |
|------|--------|---------|---------|------|
| 栈 | 局部变量、参数、返回地址 | 函数调用期间 | 向低地址 | 自动分配释放，速度快，空间小 |
| 堆 | malloc 分配的内存 | 手动管理 | 向高地址 | 灵活，空间大，易产生漏洞 |
| 全局区 | 全局变量、static | 整个程序 | 固定 | 自动清零 |
| 代码区 | 机器指令 | 整个程序 | 固定 | 只读，不可写 |

### 7.1.2 用代码观察

```c
#include <stdio.h>
#include <stdlib.h>

int global_var = 10;        // 全局区

int main() {
    int local_var = 20;     // 栈
    int *heap_var = malloc(sizeof(int));  // 堆
    *heap_var = 30;
    static int static_var = 40;  // 全局区（静态）
    
    printf("全局变量: %p\n", (void*)&global_var);
    printf("局部变量: %p\n", (void*)&local_var);
    printf("堆变量:   %p\n", (void*)heap_var);
    printf("静态变量: %p\n", (void*)&static_var);
    printf("main函数: %p\n", (void*)&main);  // 代码区
    
    free(heap_var);
    return 0;
}
```

观察地址：栈地址通常很高（0x7ffd...），堆地址在中间，代码区地址较低。

## 7.2 栈与栈溢出

### 7.2.1 栈的工作方式

每次函数调用，会在栈上压入一个**栈帧**（stack frame）：

```
调用 func() 时：
┌─────────────┐
│ 参数         │
│ 返回地址     │ ← 函数结束后要回哪里继续执行
│ 局部变量     │
│ ...         │
└─────────────┘
```

**返回地址是攻击者的目标**——如果覆盖它，就能控制程序跳转到任意位置执行。

### 7.2.2 栈溢出漏洞

```c
#include <stdio.h>
#include <string.h>

void vulnerable(char *input) {
    char buffer[8];        // 栈上只有 8 字节
    strcpy(buffer, input); // 没有长度检查！
    printf("%s\n", buffer);
}

int main() {
    char huge[100];
    memset(huge, 'A', sizeof(huge));
    huge[99] = '\0';
    vulnerable(huge);      // 传入超长字符串 → 栈溢出！
    return 0;
}
```

发生什么：

```
栈布局（溢出前）：
[buffer 8字节][其他局部变量][返回地址][...]

溢出后（input 有 99 个 'A'）：
[AAAAAAAA][AAAAAAAA][AAAAAAAA][AAAAAAAA]...
  覆盖了 buffer  覆盖了其他  覆盖了返回地址！
```

当 `vulnerable` 函数返回时，会跳转到 `0x41414141`（'A' 的 ASCII），程序崩溃。攻击者如果能精确构造内容，就能让程序跳转到恶意代码。

> **这就是最经典的缓冲区溢出攻击原理**。CTF 里的 `ret2text`、`ret2shellcode`、`ROP` 都是基于这个原理。

### 7.2.3 栈保护机制

现代编译器有防护：

```bash
# 栈保护（默认开启，检测栈溢出）
gcc -fstack-protector-all program.c -o program

# 查看是否开启
gcc -Wall program.c -o program
```

还有 NX（栈不可执行）、ASLR（地址随机化）、Canary（栈金丝雀）等机制。第 10 章会讲攻防对抗。

## 7.3 堆与动态内存管理

### 7.3.1 malloc/free

```c
#include <stdlib.h>
#include <stdio.h>

int main() {
    // 分配 10 个 int 的空间
    int *arr = (int*)malloc(10 * sizeof(int));
    if (arr == NULL) {
        printf("内存分配失败\n");
        return 1;
    }
    
    // 使用
    for (int i = 0; i < 10; i++) {
        arr[i] = i;
    }
    
    // 释放（必须！）
    free(arr);
    arr = NULL;   // 防止悬垂指针
    
    return 0;
}
```

### 7.3.2 内存泄漏

```c
void leak() {
    int *p = malloc(100);
    // 忘记 free！
    // 函数结束，p 消失，但分配的内存还在，无法再访问 → 内存泄漏
}

// 如果 leak() 被调用很多次，内存会被耗尽
```

> **危害**：长期运行的服务（服务器、嵌入式系统）如果有内存泄漏，最终会因内存耗尽而崩溃。

**检测工具**：

```bash
# Valgrind（Linux）检测内存泄漏
valgrind --leak-check=full ./program
```

### 7.3.3 常见堆错误

```c
// 1. 重复释放（Double Free）
int *p = malloc(sizeof(int));
free(p);
free(p);   // 错误！重复释放

// 2. 使用已释放内存（Use-After-Free）
int *q = malloc(sizeof(int));
free(q);
*q = 10;   // 错误！UAF

// 3. 堆溢出
char *buf = malloc(8);
strcpy(buf, "超长的字符串...");  // 写超出分配的 8 字节

// 4. 内存越界读写
int *arr = malloc(5 * sizeof(int));
arr[5] = 100;   // 越界！只分配了 5 个元素（下标 0-4）
```

> **安全重点**：堆溢出、UAF、Double Free 是现代漏洞利用的"主力军"。浏览器（Chrome、Safari）的大量漏洞都是堆相关。攻击者利用堆管理器的实现细节，通过精心构造的内存操作，实现任意代码执行。

### 7.3.4 calloc 与 realloc

```c
// calloc：分配并清零
int *arr = (int*)calloc(10, sizeof(int));  // 10个元素，全为0

// realloc：调整已分配内存大小
arr = (int*)realloc(arr, 20 * sizeof(int));  // 扩到20个元素
```

## 7.4 AI 视角：为什么性能重要

理解内存布局对 AI 也很有价值：

```c
// 缓存友好 vs 缓存不友好
// 二维数组按行访问（连续内存，快）
int matrix[1000][1000];
for (int i = 0; i < 1000; i++)
    for (int j = 0; j < 1000; j++)
        sum += matrix[i][j];   // 连续访问，CPU 缓存命中率高

// 按列访问（跳跃内存，慢很多）
for (int j = 0; j < 1000; j++)
    for (int i = 0; i < 1000; i++)
        sum += matrix[i][j];   // 跳着访问，缓存命中率低
```

AI 的矩阵运算极其看重内存访问模式。理解内存布局，才能写出高性能的计算代码（这也是 NumPy、PyTorch 内部做的事）。

## 7.5 堆的实现原理（glibc malloc 简析）

理解堆漏洞，需要略微了解堆管理器是怎么工作的。以 glibc 的 ptmalloc 为例：

### 7.5.1 chunk 结构

malloc 分配的内存块叫 chunk，布局如下：

```
分配态 chunk:
┌─────────────────────────┐
│ prev_size (8字节)        │  ← 前一个 chunk 的大小（有时复用）
│ size (8字节)             │  ← 本 chunk 大小 + 标志位
│ user data ...           │  ← malloc 返回的是这里的地址
└─────────────────────────┘

空闲态 chunk:
┌─────────────────────────┐
│ prev_size               │
│ size                    │
│ fd (前向指针)            │  ← 空闲链表用
│ bk (后向指针)            │
└─────────────────────────┘
```

**关键点**：用户数据的前面就是 chunk 头（size 字段）。堆溢出时，如果覆盖了下一个 chunk 的 size 字段，就能欺骗堆管理器，这就是很多堆利用手法的基础。

### 7.5.2 空闲链表（bins）

释放的 chunk 会被放进不同大小的链表（bins）：

- **tcache**：每个线程的小块缓存（最快）
- **fastbin**：小块（≤ 64 字节），单链表
- **smallbin / largebin**：按大小分类的双向链表
- **unsorted bin**：刚释放的 chunk 临时存放处

Double Free 攻击就是利用 fastbin/tcache 的链表管理漏洞：同一 chunk 释放两次，会让链表出现环，下次 malloc 时返回同一个地址两次，攻击者借此实现任意地址写。

### 7.5.3 为什么理解这些

```
堆溢出 → 覆盖 chunk 元数据 → 欺骗堆管理器 → 任意地址读写 → 劫持控制流
```

这就是堆利用的攻击链。作为防守方：

- 用 ASan 等工具在测试阶段发现堆错误
- 用安全编码避免越界和 UAF
- 用现代分配器（如 hardened malloc）增加利用难度
- 关注编译器的堆保护机制

> **学习建议**：堆利用是二进制安全的高级话题，需要系统学习。推荐在 CTF 平台（如 pwn.college、HackTheBox）上练习。理解原理比记住利用手法更重要。

## 7.6 AI 视角：为什么性能重要（续）

### 7.6.1 内存对齐

CPU 访问内存时按"字长"对齐访问最快。数据结构要合理排列：

```c
// 差：会有内存空洞（padding）
struct Bad {
    char a;      // 1 字节 + 7 字节填充
    double b;    // 8 字节
    char c;      // 1 字节 + 7 字节填充
};  // 总共 24 字节，实际数据只有 10 字节

// 好：按大小从大到小排列
struct Good {
    double b;    // 8 字节
    char a;      // 1
    char c;      // 1 + 6 字节填充
};  // 总共 16 字节
```

AI 处理海量数据时，结构体的内存布局直接影响缓存命中率和性能。

### 7.6.2 紧凑布局与 SIMD

```c
// 结构体数组（AoS）vs 数组结构体（SoA）
// AoS：适合面向对象，但 SIMD 不友好
struct Particle { float x, y, z; };
struct Particle particles[1000];

// SoA：连续存储同类数据，SIMD 友好（AI/图形常用）
struct Particles {
    float x[1000];
    float y[1000];
    float z[1000];
};
```

SoA 布局让 CPU 可以一次加载多个 x 坐标做并行计算（SIMD），这是高性能计算库（NumPy、PyTorch）内部常用的技巧。
