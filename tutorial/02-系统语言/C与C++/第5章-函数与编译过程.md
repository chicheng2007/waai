## 5.1 函数基础

### 5.1.1 定义与调用

```c
#include <stdio.h>

// 函数定义
int add(int a, int b) {
    return a + b;
}

int main() {
    int result = add(3, 5);
    printf("结果: %d\n", result);   // 8
    return 0;
}
```

### 5.1.2 函数声明（原型）

如果函数定义在调用之后，需要先声明：

```c
#include <stdio.h>

int add(int a, int b);   // 声明（原型）

int main() {
    printf("%d\n", add(3, 5));
    return 0;
}

int add(int a, int b) {  // 定义
    return a + b;
}
```

> 声明告诉编译器"有这个函数，参数和返回类型是什么"，这样编译器才知道怎么检查调用。

## 5.2 参数传递：值传递 vs 地址传递

这是 C 语言的核心概念，也是理解指针的钥匙。

### 5.2.1 值传递（默认）

```c
#include <stdio.h>

void change(int x) {
    x = 100;   // 只改了副本
}

int main() {
    int a = 5;
    change(a);
    printf("%d\n", a);   // 5，没变！
    return 0;
}
```

值传递：把值的**副本**传给函数，函数内修改不影响原变量。

### 5.2.2 地址传递（用指针）

```c
#include <stdio.h>

void change(int *p) {
    *p = 100;   // 修改指针指向的内存
}

int main() {
    int a = 5;
    change(&a);           // 传地址
    printf("%d\n", a);    // 100，变了！
    return 0;
}
```

地址传递：传的是变量的地址，函数内通过指针修改原变量。

> **这就是 C 语言的精髓**：想让函数修改外部变量，就传地址。这也是后面"指针"章节的基础。

### 5.2.3 实战：交换两个变量

```c
void swap(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

int main() {
    int x = 3, y = 7;
    swap(&x, &y);
    printf("x=%d, y=%d\n", x, y);   // x=7, y=3
    return 0;
}
```

## 5.3 头文件与多文件编程

### 5.3.1 为什么要分文件

大项目不可能所有代码写一个文件。通常：

- `.h` 头文件：放函数声明、宏定义、类型定义
- `.c` 源文件：放函数实现

### 5.3.2 示例

**math_utils.h**：

```c
#ifndef MATH_UTILS_H      // 防止重复包含（include guard）
#define MATH_UTILS_H

int add(int a, int b);
int multiply(int a, int b);

#endif
```

**math_utils.c**：

```c
#include "math_utils.h"

int add(int a, int b) { return a + b; }
int multiply(int a, int b) { return a * b; }
```

**main.c**：

```c
#include <stdio.h>
#include "math_utils.h"   // 用双引号表示自定义头文件

int main() {
    printf("%d\n", add(3, 5));
    return 0;
}
```

### 5.3.3 编译多文件

```bash
# 方法一：一起编译
gcc main.c math_utils.c -o program

# 方法二：分别编译再链接
gcc -c main.c -o main.o
gcc -c math_utils.c -o math_utils.o
gcc main.o math_utils.o -o program
```

## 5.4 编译过程深入

### 5.4.1 四个阶段详解

```
1. 预处理 (cpp)
   - 处理 #include（展开头文件）
   - 处理 #define（宏替换）
   - 处理 #if（条件编译）
   命令: gcc -E hello.c -o hello.i

2. 编译 (cc1)
   - 把预处理后的代码翻译成汇编
   命令: gcc -S hello.i -o hello.s

3. 汇编 (as)
   - 汇编翻译成机器码（目标文件 .o）
   命令: gcc -c hello.s -o hello.o

4. 链接 (ld)
   - 把目标文件和库链接成可执行文件
   命令: gcc hello.o -o hello
```

### 5.4.2 常见错误

**错误 1：undefined reference to `xxx`**

原因：链接时找不到函数实现（声明了但没定义，或没链接对应的 .o 文件）。

解决：检查函数是否实现，编译时是否包含了所有 .c 文件。

**错误 2：implicit declaration of function**

原因：调用函数前没有声明。

解决：包含正确的头文件，或添加函数原型。

**错误 3：multiple definition**

原因：函数在多个文件中重复定义（通常是在 .h 里写了函数实现）。

解决：头文件里只放声明，实现放 .c 文件。

## 5.5 预处理指令

```c
#define PI 3.14159                    // 宏定义
#define MAX(a, b) ((a) > (b) ? (a) : (b))  // 带参数的宏

#ifdef DEBUG                          // 条件编译
    printf("调试信息\n");
#endif

#include <stdio.h>                    // 系统头文件
#include "myheader.h"                 // 自定义头文件
```

> **宏的坑**：带参数的宏要加括号，否则优先级问题会导致错误。`#define SQUARE(x) x*x`，`SQUARE(1+2)` 会变成 `1+2*1+2 = 5` 而不是 9。写成 `((x)*(x))` 才对。

## 5.6 回调函数（进阶）

函数可以作为参数传递：

```c
#include <stdio.h>

// 回调函数
void process(int n, void (*callback)(int)) {
    for (int i = 0; i < n; i++) {
        callback(i);
    }
}

void print_num(int x) {
    printf("%d ", x);
}

int main() {
    process(5, print_num);   // 输出: 0 1 2 3 4
    return 0;
}
```

回调在事件驱动、信号处理中很常见，也是很多库的接口设计基础。

## 5.7 Makefile：自动化构建

多文件项目用 make 管理构建：

```makefile
# Makefile
CC = gcc
CFLAGS = -Wall -g -O2
TARGET = program
SRCS = main.c math_utils.c
OBJS = $(SRCS:.c=.o)

$(TARGET): $(OBJS)
	$(CC) $(CFLAGS) -o $@ $^

%.o: %.c
	$(CC) $(CFLAGS) -c -o $@ $<

clean:
	rm -f $(OBJS) $(TARGET)

.PHONY: clean
```

使用：

```bash
make          # 编译（只重新编译改动的文件）
make clean    # 清理
```

> **价值**：`make` 只重新编译修改过的文件，大型项目能节省大量时间。理解 Makefile 是读懂 C/C++ 开源项目的基础。现代项目也有用 CMake 的，原理类似。

## 5.8 静态库与动态库

```bash
# 创建静态库
gcc -c math_utils.c -o math_utils.o
ar rcs libmath.a math_utils.o
gcc main.c -L. -lmath -o program   # 链接静态库

# 创建动态库（Linux）
gcc -fPIC -c math_utils.c -o math_utils.o
gcc -shared -o libmath.so math_utils.o
gcc main.c -L. -lmath -o program
LD_LIBRARY_PATH=. ./program   # 运行时指定库路径
```

**静态库 vs 动态库**：

| 特性 | 静态库 (.a) | 动态库 (.so/.dll) |
|------|-----------|------------------|
| 链接时机 | 编译时 | 运行时 |
| 可执行文件大小 | 大（包含库代码） | 小 |
| 更新 | 需重新编译 | 替换库文件即可 |
| 部署 | 单文件方便 | 需带库文件 |

> **安全视角**：动态库劫持是一种攻击手法——攻击者把恶意的 `.so` 放到程序的搜索路径里，程序加载时就执行了恶意代码。理解库搜索机制对防御这类攻击很重要。
