# 第 8 章 并发编程：线程与消息传递

## 本章目标

- 掌握 Rust 的线程创建
- 理解所有权如何防止数据竞争
- 掌握消息传递（channel）
- 掌握共享状态（Mutex、Arc）
- 理解 Rust 并发的安全保证

Rust 的口号之一是"无畏并发"（Fearless Concurrency）。 thanks to 所有权系统，Rust 能在编译期就防止数据竞争——这在 C/C++ 里是出了名的难题。

---

## 8.1 线程基础

```rust
use std::thread;
use std::time::Duration;

fn main() {
    let handle = thread::spawn(|| {
        for i in 1..5 {
            println!("子线程: {}", i);
            thread::sleep(Duration::from_millis(100));
        }
    });
    
    for i in 1..3 {
        println!("主线程: {}", i);
        thread::sleep(Duration::from_millis(100));
    }
    
    handle.join().unwrap();   // 等待子线程结束
}
```

`thread::spawn` 创建新线程，返回 JoinHandle。`join()` 等待线程结束。

### 8.1.1 move 闭包

```rust
use std::thread;

let v = vec![1, 2, 3];
let handle = thread::spawn(move || {
    println!("向量: {:?}", v);   // 需要 move 把 v 移入线程
});
handle.join().unwrap();
```

必须用 `move`，因为线程可能比主线程活得久，需要把数据的所有权移入线程。Rust 编译器会强制检查——这就是安全保证。

## 8.2 消息传递（Channel）

Rust 推崇"通过消息传递来共享数据"，而不是"通过共享数据来通信"。

```rust
use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();   // 创建通道
    
    thread::spawn(move || {
        let ports = vec![22, 80, 443];
        for port in ports {
            tx.send(port).unwrap();   // 发送
        }
    });
    
    for received in rx {   // 接收（迭代直到通道关闭）
        println!("收到端口: {}", received);
    }
}
```

`mpsc` = multiple producer, single consumer（多生产者单消费者）。

### 8.2.1 多生产者

```rust
let (tx, rx) = mpsc::channel();

for i in 0..3 {
    let tx_clone = tx.clone();   // 克隆发送端
    thread::spawn(move || {
        tx_clone.send(i).unwrap();
    });
}

drop(tx);   // 丢弃原发送端，否则 rx 会一直等待

for received in rx {
    println!("{}", received);
}
```

## 8.3 共享状态（Mutex + Arc）

有时候确实需要多个线程共享同一份数据。Rust 用 `Mutex`（互斥锁）+ `Arc`（原子引用计数）：

```rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let counter = Arc::new(Mutex::new(0));   // 共享的可变计数器
    let mut handles = vec![];
    
    for _ in 0..10 {
        let counter_clone = Arc::clone(&counter);
        let handle = thread::spawn(move || {
            let mut num = counter_clone.lock().unwrap();  // 加锁
            *num += 1;
            // 离开作用域自动解锁（RAII）
        });
        handles.push(handle);
    }
    
    for handle in handles {
        handle.join().unwrap();
    }
    
    println!("最终结果: {}", *counter.lock().unwrap());   // 10
}
```

**部件解释**：

- `Mutex<T>`：互斥锁，保证同一时刻只有一个线程访问数据
- `Arc<T>`：原子引用计数，允许多个线程共享所有权
- `lock().unwrap()`：获取锁，返回 MutexGuard（自动解锁）

### 8.3.1 为什么需要 Arc

`Rc<T>` 也能引用计数，但不是线程安全的（非原子）。`Arc<T>` 用原子操作，适合多线程。

> **Rust 的安全保证**：你**不能**在没有同步机制（Mutex 等）的情况下，让多个线程修改同一数据。编译器会拒绝。这从根本上消除了数据竞争。
>
> ```rust
> let mut v = vec![1, 2, 3];
> // 编译错误！不能直接共享可变数据
> // thread::spawn(|| v.push(4));
> ```

## 8.4 数据竞争：Rust 如何防止

数据竞争三要素：

1. 两个线程同时访问同一数据
2. 至少一个在写
3. 没有同步

Rust 的类型系统保证：

- 不可变引用（`&T`）可以共享，但不能写
- 可变引用（`&mut T`）可以写，但不能共享（同一时刻唯一）
- 跨线程传递要求类型实现 `Send` 和 `Sync`

```rust
// 编译时保证：要么多个读，要么一个写，不能同时
// 这是借用规则在并发场景的延伸
```

对比 C++：

```cpp
// C++：编译通过，运行时数据竞争（未定义行为）
std::vector<int> v;
std::thread t1([&]{ v.push_back(1); });
std::thread t2([&]{ v.push_back(2); });
```

## 8.5 实战：并发端口扫描器

```rust
use std::sync::mpsc;
use std::thread;
use std::net::TcpStream;
use std::time::Duration;

fn scan_port(ip: &str, port: u16) -> bool {
    let addr = format!("{}:{}", ip, port);
    TcpStream::connect_timeout(
        &addr.parse().unwrap(),
        Duration::from_millis(200)
    ).is_ok()
}

fn main() {
    let ip = "127.0.0.1";
    let (tx, rx) = mpsc::channel();
    let mut handles = vec![];
    
    // 分块扫描
    let chunk_size = 100;
    for chunk in (1..=1000u16).collect::<Vec<_>>().chunks(chunk_size) {
        let tx = tx.clone();
        let ports: Vec<u16> = chunk.to_vec();
        let ip_str = ip.to_string();
        
        handles.push(thread::spawn(move || {
            for port in ports {
                if scan_port(&ip_str, port) {
                    tx.send(port).unwrap();
                }
            }
        }));
    }
    drop(tx);
    
    // 收集结果
    let mut open_ports = vec![];
    for port in rx {
        open_ports.push(port);
    }
    
    for handle in handles { handle.join().unwrap(); }
    
    open_ports.sort();
    println!("开放端口: {:?}", open_ports);
}
```

> **伦理提示**：仅在授权环境（本机）运行扫描器。

## 8.6 Send 与 Sync：并发安全的标记

Rust 用两个 trait 在编译期保证并发安全：

- **Send**：类型可以安全地转移到另一个线程（所有权 transfer）
- **Sync**：类型可以安全地在多个线程间共享引用（`&T` 是 Send）

```rust
// 编译器自动为大部分类型实现 Send/Sync
fn spawn_thread<T: Send + 'static>(value: T) {
    thread::spawn(move || {
        // 只有 Send 类型能移入线程
        println!("{:?}", value);
    });
}
```

**哪些类型不是 Send/Sync**：

- `Rc<T>`：引用计数非原子，不能跨线程（用 `Arc<T>` 替代）
- `RefCell<T>`：运行时借用检查，非线程安全（用 `Mutex<T>` 替代）
- 裸指针：编译器无法保证安全

> **编译期保证的威力**：如果你不小心把 `Rc` 用在多线程，编译器直接报错，强制你换成 `Arc`。C++ 里这类错误通常要到运行时才暴露（或者永远不被发现，成为隐患）。

### 8.6.1 'static 约束

`thread::spawn` 要求闭包是 `'static` 的，因为线程可能比当前函数活得久：

```rust
// 错误：借用局部变量
let s = String::from("hello");
thread::spawn(|| println!("{}", s));   // 编译错误！s 可能失效

// 正确：move 转移所有权
thread::spawn(move || println!("{}", s));   // OK
```

## 8.7 异步编程简介（tokio）

除了线程，Rust 还有异步并发（async/await），由 tokio 运行时驱动：

```rust
// Cargo.toml: tokio = { version = "1", features = ["full"] }
use tokio::time::{sleep, Duration};

#[tokio::main]
async fn main() {
    // 并发执行多个异步任务
    let t1 = async { sleep(Duration::from_secs(1)).await; "任务1" };
    let t2 = async { sleep(Duration::from_secs(1)).await; "任务2" };
    
    // join! 并发等待两个任务（总共约1秒，不是2秒）
    let (r1, r2) = tokio::join!(t1, t2);
    println!("{}, {}", r1, r2);
}
```

**async vs 线程**：

| 维度 | 线程 | async |
|------|------|-------|
| 调度 | OS/运行时抢占 | 协作式（await 点让出） |
| 开销 | 每线程 MB 级栈 | 每任务更小 |
| 适合 | CPU 密集、阻塞操作 | IO 密集、高并发网络 |

> **安全工具场景**：写高并发网络扫描器、爬虫、API 服务，tokio 异步性能更好。初学先掌握线程/Channel，再学 async。
