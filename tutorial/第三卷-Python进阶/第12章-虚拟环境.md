## 12.1 为什么需要虚拟环境

### 12.1.1 依赖冲突问题

假设你同时做两个项目：

- 项目 A（老系统）：需要 `requests==2.20.0`
- 项目 B（新系统）：需要 `requests==2.31.0`

如果都装在系统 Python 里，后装的会覆盖先装的，导致其中一个项目跑不起来。这就是**依赖冲突**。

### 12.1.2 解决方案：隔离

虚拟环境给每个项目一个独立的 Python 环境：

```
系统 Python
    ├── 项目A的虚拟环境（requests 2.20.0）
    ├── 项目B的虚拟环境（requests 2.31.0）
    └── 项目C的虚拟环境（...)
```

每个环境互不干扰，想装什么版本就装什么版本。

> **类比**：虚拟环境就像给每个项目一个独立的"工具箱"。项目 A 的工具箱里放 A 需要的工具，项目 B 的放 B 的，不会混在一起。

## 12.2 使用 venv（Python 内置）

### 12.2.1 创建虚拟环境

```bash
# 进入你的项目目录
cd my_project

# 创建虚拟环境（env 是环境名，可自定义）
python -m venv env
```

macOS/Linux 上用 `python3`：

```bash
python3 -m venv env
```

执行后会生成一个 `env/` 文件夹，里面包含了独立的 Python 解释器和包管理器。

### 12.2.2 激活虚拟环境

```bash
# Windows (cmd)
env\Scripts\activate

# Windows (PowerShell)
env\Scripts\Activate.ps1

# macOS / Linux
source env/bin/activate
```

激活后，命令行提示符前面会出现 `(env)`：

```
(env) C:\my_project>
```

这表示你现在在虚拟环境里，用 `pip install` 装的库只会装到这个环境。

> **Windows PowerShell 注意**：如果激活时报错"禁止运行脚本"，需要以管理员身份执行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`。

### 12.2.3 验证隔离

```bash
# 激活后查看已安装的包（应该很少）
pip list

# 装一个包
pip install requests

# 退出虚拟环境
deactivate

# 在系统环境查看（应该没有 requests 或版本不同）
pip list
```

### 12.2.4 删除虚拟环境

直接删除 `env/` 文件夹即可。

> **注意**：不要把虚拟环境文件夹提交到 Git（体积大且包含平台特定文件）。应该在 `.gitignore` 里忽略它。

## 12.3 requirements.txt：依赖清单

### 12.3.1 导出依赖

```bash
pip freeze > requirements.txt
```

会生成一个文本文件，记录当前环境所有包及版本：

```
numpy==1.24.3
pandas==2.0.3
requests==2.31.0
scikit-learn==1.3.0
```

### 12.3.2 安装依赖

别人拿到你的项目后，一键安装所有依赖：

```bash
pip install -r requirements.txt
```

### 12.3.3 生成精简版依赖

`pip freeze` 会把所有间接依赖也列出来，很啰嗦。如果只想记录直接依赖，可以用 `pipreqs`：

```bash
pip install pipreqs
pipreqs . --encoding=utf8 --force
```

它会扫描代码里的 import，只列出真正用到的包。

## 12.4 其他环境管理工具

### 12.4.1 conda（数据科学常用）

Anaconda 自带的工具，能管理 Python 环境，还能管理非 Python 的包（如 CUDA）。

```bash
# 创建环境
conda create -n myenv python=3.11

# 激活
conda activate myenv

# 安装包
conda install numpy

# 导出环境
conda env export > environment.yml

# 从文件创建
conda env create -f environment.yml
```

**conda vs venv**：

| 工具 | 优点 | 缺点 |
|------|------|------|
| venv | Python 内置，轻量 | 只管 Python 包 |
| conda | 功能强，能管非 Python 依赖 | 重量级，慢 |

AI 领域（需要 CUDA、cuDNN）常用 conda；纯 Python 项目用 venv 就够了。

### 12.4.2 poetry（现代项目管理）

poetry 是新一代的 Python 项目管理工具，用 `pyproject.toml` 管理依赖，更规范：

```bash
poetry new myproject
poetry add numpy
poetry install
```

初学阶段先掌握 venv + pip 即可，poetry 了解即可。

## 12.5 Git 基础与 GitHub 上传

既然你要把教程传到 GitHub，这里讲一下 Git 的基础使用。

### 12.5.1 Git 是什么

Git 是版本控制系统，能记录文件的每一次修改，随时回退，也方便多人协作。GitHub 是在线托管 Git 仓库的平台。

### 12.5.2 基本工作流程

```
工作区（你编辑的文件）
    ↓ git add
暂存区（准备提交的文件）
    ↓ git commit
本地仓库（已保存的版本）
    ↓ git push
远程仓库（GitHub）
```

### 12.5.3 常用命令

```bash
# 初始化仓库（在项目目录执行）
git init

# 查看状态
git status

# 添加文件到暂存区
git add README.md
git add .          # 添加所有文件

# 提交
git commit -m "提交说明"

# 关联远程仓库
git remote add origin https://github.com/你的用户名/仓库名.git

# 推送到 GitHub
git push -u origin main
```

### 12.5.4 .gitignore 文件

在项目根目录创建 `.gitignore`，列出不想提交的文件：

```
# 虚拟环境
env/
venv/
.venv/

# Python 缓存
__pycache__/
*.pyc
*.pyo

# 敏感信息
.env
config_secret.py
secrets.txt

# IDE 配置
.vscode/
.idea/

# 操作系统文件
.DS_Store
Thumbs.db
```

> **安全提示**：永远不要把密码、API Key、token 等敏感信息提交到 GitHub！用环境变量或 `.env` 文件（并加入 `.gitignore`）管理。
