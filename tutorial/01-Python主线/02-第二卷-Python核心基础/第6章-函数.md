## 6.1 为什么需要函数

### 6.1.1 一个痛点场景

假设你要在一个程序里多次检查 IP 是否合法：

```python
# 不用函数：重复写三遍
ip1 = "192.168.1.1"
if ip1.count(".") == 3:
    parts = ip1.split(".")
    if all(0 <= int(p) <= 255 for p in parts):
        print("合法")
    else:
        print("不合法")

ip2 = "999.1.1.1"
if ip2.count(".") == 3:
    parts = ip2.split(".")
    if all(0 <= int(p) <= 255 for p in parts):
        print("合法")
    else:
        print("不合法")

# ... 重复 N 遍
```

问题：

1. **重复**：同样的逻辑写很多遍
2. **难维护**：如果要改逻辑，得改 N 处
3. **易出错**：复制粘贴容易漏改

### 6.1.2 用函数解决

```python
def is_valid_ip(ip):
    """检查 IP 地址是否合法"""
    parts = ip.split(".")
    if len(parts) != 3:
        return False
    try:
        return all(0 <= int(p) <= 255 for p in parts)
    except ValueError:
        return False

# 调用
print(is_valid_ip("192.168.1.1"))   # True
print(is_valid_ip("999.1.1.1"))     # False
print(is_valid_ip("not an ip"))     # False
```

`is_valid_ip` 就是一个函数。它把"检查 IP 合法性"这个功能打包起来，用的时候喊一声名字就行。

### 6.1.3 函数的好处

1. **代码复用**：写一次，用无数次
2. **隐藏细节**：调用者不需要知道内部怎么实现，只需要知道"传进去什么、返回什么"
3. **易于维护**：改一处，所有调用都生效
4. **便于协作**：不同的人写不同的函数，像搭积木一样组合

> **核心思想**：函数就是"Black Box"（黑盒）。你关心的是它的**输入**（参数）和**输出**（返回值），而不是内部怎么运作。这个概念是理解一切库和框架的基础——你调用 `print()` 时，也不需要知道它内部怎么把文字显示到屏幕上。

## 6.2 定义和调用函数

### 6.2.1 基本语法

```python
def 函数名(参数1, 参数2, ...):
    """文档字符串（可选）"""
    函数体
    return 返回值
```

要点：

- 用 `def` 关键字定义
- 函数名后加括号和冒号
- 函数体缩进
- `return` 可选（没有则默认返回 `None`）

### 6.2.2 最简单的函数

```python
def greet():
    print("你好，世界!")

# 调用函数
greet()
greet()
greet()
```

### 6.2.3 带参数的函数

```python
def greet(name):
    print(f"你好, {name}!")

greet("小明")
greet("小红")
```

### 6.2.4 带返回值的函数

```python
def add(a, b):
    return a + b

result = add(3, 5)
print(result)   # 8
```

**`return` 的作用**：

1. 把计算结果"交出来"给调用者
2. **立即结束函数**（return 后面的代码不会执行）

```python
def check(x):
    if x > 0:
        return "正数"
    print("这行在 x>0 时不会执行")
    return "非正数"
```

### 6.2.5 返回多个值

Python 的函数可以返回多个值（本质上是返回一个元组）：

```python
def get_ip_info(ip):
    parts = ip.split(".")
    return parts[0], len(parts)

first, count = get_ip_info("192.168.1.1")
print(first)   # 192
print(count)   # 4
```

## 6.3 参数详解

### 6.3.1 位置参数（必填参数）

最常见的参数形式，调用时按顺序传入：

```python
def power(base, exponent):
    return base ** exponent

print(power(2, 3))   # 8
print(power(3, 2))   # 9
```

顺序错了结果就错了，所以调用时要注意。

### 6.3.2 关键字参数

调用时用 `参数名=值` 的形式，可以打乱顺序：

```python
def power(base, exponent):
    return base ** exponent

print(power(exponent=3, base=2))   # 8，顺序无所谓
```

关键字参数的优点：

1. 调用更清晰，看代码就知道每个值是什么
2. 可以跳过有默认值的参数

### 6.3.3 默认参数

定义函数时给参数一个默认值，调用时不传就用默认值：

```python
def greet(name, greeting="你好"):
    print(f"{greeting}, {name}!")

greet("小明")              # 你好, 小明!
greet("小红", "早上好")     # 早上好, 小红!
greet("小刚", greeting="嗨") # 嗨, 小刚!
```

> **经典大坑：可变对象作为默认参数**
>
> ```python
> def add_item(item, lst=[]):   # 错误示范！
>     lst.append(item)
>     return lst
>
> print(add_item("a"))   # ['a']
> print(add_item("b"))   # ['a', 'b'] —— 不是 ['b']！
> ```
>
> 原因：默认参数 `[]` 在函数定义时创建一次，之后所有调用共享同一个列表。
>
> **正确写法**：
> ```python
> def add_item(item, lst=None):
>     if lst is None:
>         lst = []
>     lst.append(item)
>     return lst
> ```
>
> 记住这条铁律：**默认参数永远不要用可变对象（列表、字典、集合）**。

### 6.3.4 可变位置参数 *args

当你不知道要传多少个参数时，用 `*args`（arguments 的缩写）：

```python
def sum_all(*args):
    print("收到的参数:", args)   # args 是一个元组
    return sum(args)

print(sum_all(1, 2, 3))        # 6
print(sum_all(1, 2, 3, 4, 5))  # 15
```

`*args` 把多余的位置参数收集成一个元组。

### 6.3.5 可变关键字参数 **kwargs

`**kwargs` 把多余的关键字参数收集成一个字典：

```python
def build_config(**kwargs):
    print("收到的配置:", kwargs)
    return kwargs

config = build_config(host="127.0.0.1", port=8080, debug=True)
# 收到的配置: {'host': '127.0.0.1', 'port': 8080, 'debug': True}
```

### 6.3.6 参数定义的完整顺序

如果混用各种参数，顺序必须是：

```
位置参数 → 默认参数 → *args → 关键字参数 → **kwargs
```

```python
def example(a, b, c=10, *args, d=20, **kwargs):
    print(a, b, c, args, d, kwargs)

example(1, 2, 3, 4, 5, d=99, x=100)
# a=1, b=2, c=3, args=(4,5), d=99, kwargs={'x': 100}
```

> **注意**：`*args` 之后的参数（`d=20`）必须用关键字方式传入，称为"仅限关键字参数"。

### 6.3.7 参数传递的陷阱：可变对象

```python
def modify(lst):
    lst.append(99)
    print("函数内:", lst)

my_list = [1, 2, 3]
modify(my_list)
print("函数外:", my_list)
# 函数内: [1, 2, 3, 99]
# 函数外: [1, 2, 3, 99] —— 外部列表也被改了！
```

**原因**：Python 传参传的是"对象的引用"。列表是可变对象，函数内修改会影响外部。

**如何避免**：在函数内复制一份

```python
def modify_safe(lst):
    lst = lst.copy()   # 或 lst[:]
    lst.append(99)
    return lst

my_list = [1, 2, 3]
result = modify_safe(my_list)
print("外部:", my_list)   # [1, 2, 3] 没被改
print("结果:", result)    # [1, 2, 3, 99]
```

> **规则**：对于 int、str、bool、tuple 等不可变对象，函数内修改不影响外部；对于 list、dict、set 等可变对象，函数内修改**会**影响外部。不确定时就在函数内复制一份。

## 6.4 变量作用域

### 6.4.1 局部变量 vs 全局变量

```python
global_var = "我是全局"

def test():
    local_var = "我是局部"
    print("函数内可见:", global_var, local_var)

test()
print("函数外可见:", global_var)
# print(local_var)   # 报错！局部变量在函数外不可见
```

规则：

- 在函数内部定义的变量是**局部变量**，只在函数内有效
- 在函数外部定义的是**全局变量**，整个文件都可见（在函数内可以读取）
- 函数执行完，局部变量就被销毁了

### 6.4.2 global 关键字

如果想在函数内修改全局变量，需要用 `global` 声明：

```python
count = 0

def increment():
    global count   # 声明要修改全局变量
    count += 1

increment()
increment()
print(count)   # 2
```

> **注意**：如果不加 `global`，`count += 1` 会在函数内创建一个同名的局部变量，不会影响全局。

> **建议**：尽量少用全局变量。全局变量让代码难以追踪和测试。更好的做法是通过参数和返回值传递数据。

### 6.4.3 LEGB 规则（了解即可）

Python 查找变量名的顺序，遵循 LEGB 规则：

1. **L**ocal（局部）：当前函数内
2. **E**nclosing（嵌套）：外层函数
3. **G**lobal（全局）：模块级别
4. **B**uilt-in（内置）：Python 自带的名字（如 `print`、`len`）

从内到外依次查找，找到就用，找不到就报错 `NameError`。

## 6.5 递归函数

函数可以调用自己，这叫递归。

### 6.5.1 经典例子：阶乘

```python
def factorial(n):
    if n == 1:
        return 1              # 基线条件（终止递归）
    return n * factorial(n - 1)  # 递归条件

print(factorial(5))   # 120 (5*4*3*2*1)
```

递归的两个要素：

1. **基线条件（base case）**：什么时候停止递归（否则无限递归）
2. **递归条件**：把问题分解成更小的同类问题

> **注意**：递归必须有终止条件，否则会 `RecursionError: maximum recursion depth exceeded`（Python 默认最多递归 1000 层）。

### 6.5.2 递归的适用场景

递归适合处理"树形结构"问题，比如：

- 遍历目录/文件夹（目录里套目录）
- 解析 JSON/XML 等嵌套数据
- 某些算法（快速排序、二分查找）

```python
# 递归遍历目录（安全脚本常用）
import os

def list_files(path, indent=0):
    for item in os.listdir(path):
        full_path = os.path.join(path, item)
        if os.path.isdir(full_path):
            print("  " * indent + f"[目录] {item}")
            list_files(full_path, indent + 1)   # 递归进入子目录
        else:
            print("  " * indent + f"[文件] {item}")

# list_files(".")
```

> **小白问**：递归和循环有什么区别？
>
> **答**：理论上它们能互相转换。循环更直观、性能更好；递归更优雅、适合树形结构。初学阶段优先用循环，遇到树形结构再考虑递归。

## 6.6 lambda 匿名函数

### 6.6.1 基本语法

`lambda` 用来定义小巧的匿名函数（没有名字的函数）：

```python
# 普通函数
def add(a, b):
    return a + b

# 等价的 lambda
add_lambda = lambda a, b: a + b

print(add_lambda(3, 5))   # 8
```

语法：`lambda 参数: 表达式`。表达式的结果自动返回。

### 6.6.2 常见用途：作为其他函数的参数

```python
# 排序时用 lambda 指定排序规则
students = [("小明", 85), ("小红", 92), ("小刚", 78)]

# 按成绩（元组的第二个元素）排序
students.sort(key=lambda x: x[1])
print(students)
# [('小刚', 78), ('小明', 85), ('小红', 92)]
```

```python
# 过滤
numbers = [1, 2, 3, 4, 5, 6]
evens = list(filter(lambda x: x % 2 == 0, numbers))
print(evens)   # [2, 4, 6]

# 映射
squares = list(map(lambda x: x ** 2, numbers))
print(squares)   # [1, 4, 9, 16, 25, 36]
```

> **注意**：lambda 只能写单个表达式，不能写多行语句。复杂的函数还是用 `def`。

## 6.7 综合实战：重构日志分析器

用函数重构第 5 章的日志分析器：

```python
def parse_logs(logs):
    """解析日志，返回每个用户的失败次数"""
    failed_count = {}
    for username, status in logs:
        if status == "FAILED":
            failed_count[username] = failed_count.get(username, 0) + 1
    return failed_count

def find_suspects(failed_count, threshold=2):
    """找出失败次数超过阈值的可疑用户"""
    return [u for u, c in failed_count.items() if c >= threshold]

def generate_report(logs, threshold=2):
    """生成完整的分析报告"""
    failed_count = parse_logs(logs)
    suspects = find_suspects(failed_count, threshold)
    
    print("=== 登录安全分析报告 ===\n")
    print("失败次数统计:")
    for username, count in failed_count.items():
        flag = " [可疑]" if count >= threshold else ""
        print(f"  {username}: {count} 次{flag}")
    
    print(f"\n可疑账户({len(suspects)}个):")
    print("  " + (", ".join(suspects) if suspects else "无"))
    
    return suspects

# 使用
logs = [
    ("admin", "SUCCESS"),
    ("root", "FAILED"),
    ("admin", "FAILED"),
    ("guest", "FAILED"),
    ("admin", "SUCCESS"),
    ("root", "FAILED"),
]

suspects = generate_report(logs, threshold=2)
```

**观察改进之处**：

1. 每个函数职责单一（`parse_logs` 只解析，`find_suspects` 只找可疑用户）
2. 可复用（`parse_logs` 可以用于其他日志分析）
3. 易测试（可以单独测试每个函数）
4. 易修改（改阈值只需改参数）

这就是**模块化思维**，是专业编程的核心。

## 6.8 本章总结

| 知识点 | 核心内容 |
|--------|---------|
| 函数定义 | `def 函数名(参数):` + 缩进函数体 |
| return | 返回值 + 立即结束函数；可返回多个值（元组） |
| 位置参数 | 按顺序传入 |
| 关键字参数 | `参数名=值`，可打乱顺序 |
| 默认参数 | `参数=默认值`；**永远别用可变对象作默认值** |
| *args / **kwargs | 收集多余的位置/关键字参数 |
| 参数陷阱 | 可变对象传参会共享引用，需要时 `.copy()` |
| 作用域 | 局部 vs 全局；`global` 声明；LEGB 规则 |
| 递归 | 基线条件 + 递归条件；谨慎使用 |
| lambda | 匿名函数，常用于 `sort`、`map`、`filter` 的 key |
