## 20.1 什么是机器学习

### 20.1.1 重新定义

还记得第 1 章的比喻吗？教孩子认识猫，靠的是"看很多例子自己总结规律"。

**机器学习 = 让计算机从数据中自动学出规律，并用这些规律对新数据做预测或决策。**

用数学语言表达：

```
输入数据 X  →  模型（学习到的规律 f） →  输出预测 y
```

训练过程就是不断调整 f 的参数，让 f(X) 尽可能接近真实结果。

### 20.1.2 一个具体的例子

假设你想做一个"恶意邮件检测器"：

1. 收集 1000 封邮件，其中 500 封正常、500 封垃圾
2. 人工标注每封邮件的类别（这就是"标签"）
3. 从邮件里提取特征：包含"免费""中奖"等词的个数、邮件长度、链接数量...
4. 把特征和标签喂给算法，算法学出一个"判断规则"
5. 用这个规则判断新邮件是不是垃圾邮件

机器学到的"规则"可能是：`如果"免费"出现次数>2 且 链接数>5，则 90% 是垃圾邮件`。这条规则是人没写、机器自己总结的。

## 20.2 机器学习的三种类型

### 20.2.1 监督学习（Supervised Learning）

**特点**：训练数据**带有标签**（正确答案）。

两类主要任务：

**分类（Classification）**：预测离散类别

- 邮件是垃圾还是正常？
- 这个连接是攻击还是正常流量？
- 这个文件是恶意软件还是正常软件？

**回归（Regression）**：预测连续数值

- 这套房子多少钱？
- 明天的温度是多少？
- 这个网站的访问量是多少？

> **安全应用**：恶意软件检测（分类）、攻击流量识别（分类）是安全领域最常见的监督学习任务。

### 20.2.2 无监督学习（Unsupervised Learning）

**特点**：训练数据**没有标签**，算法自己找规律。

两类主要任务：

**聚类（Clustering）**：把相似的数据自动分组

- 把客户分成不同群体
- 把日志按行为模式聚类

**异常检测（Anomaly Detection）**：找出与众不同的数据

- 找出异常流量
- 发现异常登录行为

> **安全应用**：异常检测是安全的杀手级应用！因为攻击样本往往稀少且多变，很难全部标注，而无监督的异常检测不需要标签，能发现"从未见过的攻击"。第 16 章的 3σ 检测就是一种最简单的异常检测。

### 20.2.3 强化学习（Reinforcement Learning）

**特点**：智能体在环境中通过"试错"学习，根据奖励/惩罚调整行为。

- AlphaGo 下围棋
- 自动驾驶
- 游戏 AI

> 强化学习在安全领域也有应用（如自动化渗透测试的智能体），但复杂度高，本教程不做深入，了解即可。

## 20.3 核心术语

| 术语 | 含义 | 例子（恶意文件检测） |
|------|------|---------------------|
| 特征（Feature） | 数据的属性 | 文件大小、熵值、导入的函数 |
| 标签（Label） | 正确答案 | 恶意 / 正常 |
| 样本（Sample） | 一条数据 | 一个文件 |
| 训练集（Training Set） | 用来训练模型的数据 | 80% 的已标注文件 |
| 测试集（Test Set） | 用来检验模型的数据 | 20% 的已标注文件 |
| 模型（Model） | 学到的规律 | 判断规则 |
| 训练（Training） | 学习规律的过程 | 喂数据调参数 |
| 预测（Prediction） | 对新数据做判断 | 判断新文件是否恶意 |

### 20.3.1 特征工程：AI 项目最关键的一步

**特征工程 = 把原始数据转换成"算法能理解、且有意义"的特征。**

比如判断一个文件是否恶意，原始文件是一堆字节，算法看不懂。你要提取特征：

- 文件大小
- 字节熵值（恶意软件常加壳，熵值高）
- 是否调用敏感 API（如 CreateRemoteThread）
- 是否加壳/混淆
- 数字签名的有无

> **经验之谈**：在机器学习项目里，**特征工程往往比选什么算法更重要**。好的特征让简单算法也能有不错效果；差的特征再牛的算法也救不了。这就是"Garbage in, garbage out"（垃圾进，垃圾出）。

## 20.4 过拟合与欠拟合

### 20.4.1 两种失败模式

**欠拟合（Underfitting）**：模型太简单，连训练数据的规律都没学好。

- 表现：训练集表现差，测试集也差
- 原因：模型太简单、特征太少、训练不够
- 解决：增加特征、换更复杂的模型、训练更久

**过拟合（Overfitting）**：模型太复杂，把训练数据的"噪声"也记住了，死记硬背而非举一反三。

- 表现：训练集表现极好，测试集表现差
- 原因：模型太复杂、训练数据太少、训练过头
- 解决：增加数据、正则化、简化模型、早停

```python
# 类比：
# 欠拟合 = 学生没好好学，考试啥都不会
# 过拟合 = 学生把练习题答案背下来了，但换个题型就不会了
# 理想 = 学生真正理解了知识，能举一反三
```

### 20.4.2 如何避免过拟合

1. **更多数据**：数据越多越难死记硬背
2. **训练集/测试集分离**：用测试集检验真实水平
3. **交叉验证**：多轮划分训练/测试，结果更可靠
4. **正则化**：限制模型复杂度（后面讲）
5. **早停**：训练到测试集表现开始下降就停

## 20.5 机器学习项目标准流程

```
1. 明确问题     → 要解决什么？分类还是回归？
2. 收集数据     → 获取数据，了解数据
3. 探索分析     → EDA，看分布、找规律（第四卷的技能）
4. 特征工程     → 清洗、转换、提取特征
5. 划分数据集   → 训练集/测试集
6. 选择模型     → 选算法
7. 训练模型     → 喂数据学习
8. 评估模型     → 用测试集看效果
9. 调优         → 调参数、改进特征
10. 部署应用    → 做成能用的产品
```

这个流程你会反复用到，务必记住。

## 20.6 评估指标（安全领域特别重要）

### 20.6.1 准确率不够用

假设你要检测恶意软件，10000 个文件里只有 100 个恶意（1%）。如果一个模型"无脑判断所有文件都正常"，准确率高达 99%！但它一个恶意都没抓到。

所以**准确率在不平衡数据（安全场景常见）里会骗人**，需要更全面的指标。

### 20.6.2 混淆矩阵

|  | 预测为正（恶意） | 预测为负（正常） |
|--|----------------|----------------|
| **实际为正（恶意）** | TP（真正例） | FN（漏报） |
| **实际为负（正常）** | FP（误报） | TN（真负例） |

### 20.6.3 关键指标

```python
# 精确率（Precision）：预测为恶意的里面，有多少真的是恶意
# 关心"误报多不多"——安全告警太多会淹没分析师
precision = TP / (TP + FP)

# 召回率（Recall）：所有恶意文件里，抓到了多少
# 关心"漏报多不多"——漏掉一个恶意可能是灾难
recall = TP / (TP + FN)

# F1 分数：精确率和召回率的调和平均
f1 = 2 * precision * recall / (precision + recall)
```

**安全场景的取舍**：

- **病毒查杀**：宁可误报也别漏报 → 优先召回率
- **告警系统**：误报太多分析师会麻木 → 优先精确率
- 一般情况：看 F1 综合指标

> **小白问**：为什么安全场景特别在意这些指标？
>
> **答**：因为安全数据极度不平衡（恶意样本远少于正常样本），且误报/漏报的代价都很高。选对评估指标，才能正确判断模型好坏。这是安全 AI 和通用 AI 的一个重要区别。

## 20.7 本章总结

| 概念 | 核心要点 |
|------|---------|
| 机器学习 | 从数据中学规律，对新数据做预测 |
| 监督学习 | 有标签；分类（离散）+ 回归（连续） |
| 无监督学习 | 无标签；聚类 + 异常检测 |
| 特征工程 | 把原始数据变成有意义的特征；最关键的一步 |
| 训练/测试集 |  Separation，检验真实水平 |
| 过拟合/欠拟合 | 死记硬背 vs 没学会 |
| 标准流程 | 问题→数据→EDA→特征→划分→模型→训练→评估→调优→部署 |
| 评估指标 | 准确率（不平衡时不可靠）、精确率、召回率、F1 |
