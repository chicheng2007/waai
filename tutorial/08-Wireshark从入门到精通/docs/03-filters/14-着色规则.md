# 第十四章 着色规则与数据包标记

默认的配色方案已经能区分常见协议，但 Wireshark 允许你自定义着色规则（Coloring Rules），用颜色突出显示你关心的数据包。合理使用着色，能让海量数据中的异常包「跳」出来。

## 14.1 着色规则对话框

通过菜单 `View → Coloring Rules`（或 `Ctrl + Shift + K`）打开着色规则对话框。

对话框列出当前的着色规则，每条规则包含：

- **名称**：规则的描述性名字。
- **过滤器**：规则使用的显示过滤器表达式。
- **前景色/背景色**：匹配包显示的文字颜色和背景颜色。
- **启用状态**：可以勾选启用/禁用某条规则。

规则按列表顺序匹配，**第一条匹配的规则生效**，因此把更具体的规则放在前面。

## 14.2 创建自定义规则

点击 `+` 新建规则，填写：

1. **Name**：如「RST 连接重置」。
2. **Filter**：如 `tcp.flags.reset == 1`。
3. **Colors**：点击颜色块选择前景色和背景色，如背景设为浅红、文字设为深红。

创建后，列表中**所有匹配该过滤器的包**都会以指定颜色高亮显示。

### 14.2.1 实用着色规则推荐

| 名称 | 过滤器 | 建议颜色 |
| --- | --- | --- |
| TCP RST | `tcp.flags.reset == 1` | 红色背景 |
| TCP 重传 | `tcp.analysis.retransmission` | 橙红背景 |
| DNS 查询 | `dns.flags.response == 0` | 浅蓝背景 |
| HTTP 错误 | `http.response.code >= 400` | 黄色背景 |
| 大包 | `frame.len > 1400` | 浅紫背景 |
| 私有 IP | `ip.addr in {192.168.0.0/16, 10.0.0.0/8}` | 浅绿背景 |
| 指定主机 | `ip.addr == 10.0.0.100` | 醒目黄色 |

## 14.3 着色规则的启用与禁用

- 可以批量禁用所有规则（`Disable All`），恢复无颜色的列表。
- 也可以临时关闭着色：菜单 `View → Colorize Packet List`，取消勾选。快捷键 `Ctrl + Shift + C`。
- 禁用着色在导出或截图时有时更清晰。

## 14.4 快速着色：Colorize Conversation

在数据包列表右键 → `Colorize Conversation` → 选择颜色，可以给**整个会话**（同一四元组的所有包）快速着色。这在分析多个并发连接时特别有用——用不同颜色区分不同会话，追踪每个连接的过程。

## 14.5 数据包标记（Mark）

着色规则是自动的、持续的；标记（Mark）是手动的、临时的。

- 选中包按 `Ctrl + M`（或右键 → `Mark Packet`）给它打标记。
- 标记的包在 No. 列会有特殊图标（默认黑色背景）。
- 用菜单 `Edit → Find Next Marked Packet`（`Ctrl + Shift + M`）在标记间跳转。
- 再次按 `Ctrl + M` 取消标记。

标记适合在分析过程中「 bookmark」关键包，比如第一次重传、异常响应的位置。

## 14.6 配置文件的着色规则

着色规则属于配置文件（Profile）的一部分（见第九章）。你可以为不同场景准备不同的着色方案：

- 排障 Profile：突出 RST、重传、ICMP 错误。
- 安全 Profile：突出扫描特征、异常 DNS、POST 请求。

## 14.7 着色的注意事项

1. **规则顺序**：具体规则放前面，通用规则放后面，避免被通用规则「抢先匹配」。
2. **颜色辨识度**：选择对比度合适的颜色，避免文字看不清。
3. **不要过度着色**：规则太多会让列表变成「彩虹」，反而失去重点。通常 5~10 条规则足够。
4. **性能影响**：大量复杂着色规则在高速抓包时会有轻微性能开销。

## 14.8 小结

- 着色规则用显示过滤器 + 颜色自动高亮匹配的包。
- 规则按列表顺序匹配，第一条生效，具体规则放前面。
- 推荐为 RST、重传、HTTP 错误、大包等设置醒目颜色。
- `Colorize Conversation` 可快速给整个会话着色，区分并发连接。
- 标记（Mark）是手动临时标注关键包的方法。
- 着色规则属于配置文件，可按场景切换。
