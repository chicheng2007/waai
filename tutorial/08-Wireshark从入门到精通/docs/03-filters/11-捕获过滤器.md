# 第十一章 捕获过滤器（BPF）

捕获过滤器（Capture Filter）在数据包被捕获**之前**生效，决定「哪些包应该被抓取并保存」。它基于 BPF（Berkeley Packet Filter）语法，是 tcpdump 等工具通用的语法体系。掌握 BPF，你就能在源头上控制数据量。

## 11.1 捕获过滤器 vs 显示过滤器

先厘清一个关键区别：

| 对比项 | 捕获过滤器（BPF） | 显示过滤器（Display Filter） |
| --- | --- | --- |
| 生效时机 | 抓包之前 | 抓包之后（显示/分析时） |
| 语法 | BPF 语法 | Wireshark 显示过滤器语法 |
| 被过滤的数据 | **永久丢失**，无法恢复 | 仍保存在文件中，取消过滤即可恢复 |
| 表达式示例 | `tcp port 80` | `tcp.port == 80` |
| 用途 | 减少捕获量、降低性能开销 | 精确筛选分析对象 |

> **原则**：如果不确定要不要某个包，就用显示过滤器（宽松抓包，精细分析）。只有在数据量极大、明确知道只需要特定流量时，才用捕获过滤器。

## 11.2 BPF 语法基础

一个 BPF 表达式由「限定符 + ID」组成，基本形式为：

```
[协议限定符] [方向限定符] [类型限定符] ID
```

### 11.2.1 类型限定符（Type）

指定 ID 的类型：

- `host`：主机（IP 或主机名）
- `net`：网络号
- `port`：端口
- `portrange`：端口范围

如果省略，默认是 `host`。

### 11.2.2 方向限定符（Dir）

指定数据传输方向：

- `src`：源
- `dst`：目的
- `src or dst`：源或目的（默认）
- `src and dst`：源和目的同时满足

### 11.2.3 协议限定符（Proto）

指定协议类型：

- `ether`、`ip`、`ip6`、`arp`、`rarp`
- `tcp`、`udp`、`icmp`、`icmp6`
- `vlan`、`mpls`、`wlan` 等

如果省略，匹配所有协议。

## 11.3 常用过滤表达式

### 11.3.1 按主机过滤

```
host 192.168.1.10          # 与该主机相关的所有包
src host 192.168.1.10      # 源地址是该主机的包
dst host 192.168.1.10      # 目的地址是该主机的包
```

### 11.3.2 按网络过滤

```
net 192.168.1.0/24         # 与该网段相关的包
src net 10.0.0.0/8         # 源地址属于该网段
net 192.168.1.0 mask 255.255.255.0   # 用子网掩码表示
```

### 11.3.3 按端口过滤

```
port 80                    # 源或目的端口为 80
src port 53                # 源端口为 53（DNS 响应常见）
dst port 443               # 目的端口为 443（HTTPS 请求）
portrange 1000-2000        # 端口在 1000~2000 之间
```

注意：端口过滤通常需要配合协议限定符，如 `tcp port 80`，否则可能同时匹配 TCP 和 UDP 的 80 端口。

### 11.3.4 按协议过滤

```
tcp                        # 所有 TCP 包
udp                        # 所有 UDP 包
icmp                       # 所有 ICMP 包
arp                        # 所有 ARP 包
ip                         # 所有 IPv4 包
ip6                        # 所有 IPv6 包
```

### 11.3.5 逻辑组合

BPF 支持 `&&`（and）、`||`（or）、`!`（not）：

```
tcp port 80 && host 192.168.1.10        # 与该主机的 HTTP 通信
src 10.0.0.1 && dst port 443            # 从 10.0.0.1 发往 443 端口
! arp                                   # 排除 ARP
(tcp port 80 || tcp port 443) && ! host 192.168.1.1   # 80 或 443，排除某主机
```

注意 BPF 中 `!` 的优先级，必要时用括号明确逻辑。

## 11.4 进阶技巧

### 11.4.1 按 MAC 地址过滤

```
ether host 00:11:22:33:44:55     # 与该 MAC 相关的包
ether src 00:11:22:33:44:55      # 源 MAC
ether dst ff:ff:ff:ff:ff:ff      # 广播帧
```

### 11.4.2 按包长度过滤

```
less 64                    # 长度 <= 64 字节的包
greater 1000               # 长度 >= 1000 字节的包
```

### 11.4.3 按 TCP 标志位过滤

BPF 可以直接检查 TCP 标志位字节（tcp[13] 是标志位偏移）：

```
tcp[tcpflags] & tcp-syn != 0     # SYN 包
tcp[tcpflags] & tcp-ack != 0     # ACK 包
tcp[tcpflags] & tcp-rst != 0     # RST 包
tcp[tcpflags] & tcp-fin != 0     # FIN 包
'tcp[13] & 2 != 0'               # SYN 包（传统写法，需加引号）
```

其中 `tcp[tcpflags]` 是 TCP 标志位的符号化写法，可读性更好。

### 11.4.4 按 VLAN 过滤

```
vlan                       # 所有带 VLAN 标签的帧
vlan 100                   # VLAN ID 100
vlan && ip                 # VLAN 中的 IP 包
```

## 11.5 常见实战范例

**只抓某主机的 HTTP/HTTPS 流量：**

```
host 192.168.1.100 && (tcp port 80 || tcp port 443)
```

**只抓 DNS 查询（UDP 53）：**

```
udp port 53
```

**抓取除本机 SSH 外的所有流量：**

```
not (host 192.168.1.10 && tcp port 22)
```

**抓取 ICMP（ping）流量：**

```
icmp or icmp6
```

## 11.6 注意事项

1. **语法错误**：BPF 表达式有误时，Wireshark 会用红色背景提示，并阻止开始捕获。仔细检查括号和空格。
2. **主机名解析**：BPF 可以使用主机名（如 `host www.example.com`），但解析在捕获启动时进行，且会触发 DNS 查询。建议使用 IP 地址。
3. **大小写**：BPF 关键字必须小写。
4. **IPv6**：IPv6 流量用 `ip6` 协议限定符，地址中包含冒号时注意语法。

## 11.7 小结

- 捕获过滤器基于 BPF 语法，在抓包前生效，被过滤的包永久丢失。
- 基本结构：`协议 + 方向 + 类型 + ID`，如 `tcp dst port 80`。
- 支持主机、网络、端口、协议、MAC、包长度、TCP 标志位等过滤维度。
- 逻辑组合用 `&&`、`||`、`!`，注意优先级。
- 不确定时用显示过滤器（宽松抓包、精细分析）更安全。
