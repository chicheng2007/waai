# 第二章 网络协议基础

在使用 Wireshark 之前，我们需要先建立一套网络协议的基本概念。Wireshark 解析的是协议，如果你不了解协议的分层与封装，看到的就只是一堆十六进制数字，无法理解其含义。本章用尽量通俗的方式梳理必备基础知识。

## 2.1 为什么需要协议

两台计算机要通信，必须预先约定好一套规则，比如：

- 数据用什么格式组织？
- 地址怎么表示？
- 出错怎么办？
- 谁先发、谁后发？
- 发完了怎么确认对方收到？

这套规则就是**协议（Protocol）**。网络协议之于计算机，如同语言之于人类。只有双方都「说」同一种协议，通信才能成立。

互联网使用着一整套协议，称为**协议族（Protocol Suite）**，其中最著名的是 TCP/IP 协议族。

## 2.2 分层模型：OSI 与 TCP/IP

为了让复杂的网络问题变得可管理，人们采用「分层」的思想。每一层只关心自己职责范围内的事，向上层提供服务，使用下层提供的能力。

### 2.2.1 OSI 七层模型

OSI（Open Systems Interconnection，开放系统互连）参考模型是一个理论框架，共七层：

| 层号 | 层名 | 英文 | 核心职责 | 典型协议/设备 |
| --- | --- | --- | --- | --- |
| 7 | 应用层 | Application | 为应用程序提供网络服务 | HTTP、FTP、SMTP、DNS |
| 6 | 表示层 | Presentation | 数据格式转换、加密、压缩 | TLS、JPEG、ASCII |
| 5 | 会话层 | Session | 建立、管理、终止会话 | NetBIOS、RPC |
| 4 | 传输层 | Transport | 端到端可靠传输、端口寻址 | TCP、UDP |
| 3 | 网络层 | Network | 逻辑寻址、路由选择 | IP、ICMP、路由器 |
| 2 | 数据链路层 | Data Link | 物理寻址、成帧、差错检测 | 以太网、ARP、交换机 |
| 1 | 物理层 | Physical | 比特流传输、电气特性 | 网卡、网线、集线器 |

记忆口诀（从下到上）：**物、数、网、传、会、表、应**。

### 2.2.2 TCP/IP 四层模型

OSI 是理论模型，现实世界中占统治地位的是 TCP/IP 模型，通常分为四层：

| TCP/IP 层 | 对应 OSI 层 | 典型协议 |
| --- | --- | --- |
| 应用层 | 应用、表示、会话 | HTTP、DNS、FTP、SMTP、SSH |
| 传输层 | 传输 | TCP、UDP |
| 网络层（网际层） | 网络 | IP、ICMP、ARP、IGMP |
| 网络接口层 | 数据链路、物理 | 以太网、Wi-Fi、PPP |

协议数据在不同层次有不同的叫法：

- 传输层：**段（Segment）**（TCP）或 **数据报（Datagram）**（UDP）
- 网络层：**包（Packet）**
- 数据链路层：**帧（Frame）**
- 物理层：**比特（Bit）**

Wireshark 的数据包列表默认显示的是「帧」，展开协议树后可以看到各层的协议首部。

## 2.3 封装与解封装

发送数据时，数据从应用层往下传递，每经过一层就被加上一个首部（Header），这个过程叫**封装（Encapsulation）**：

```
应用层数据（如 HTTP 请求）
   ↓ 加 TCP 首部（源端口、目的端口、序号等）
TCP 段
   ↓ 加 IP 首部（源 IP、目的 IP、TTL 等）
IP 包
   ↓ 加以太网首部（源 MAC、目的 MAC、类型）
以太网帧
   ↓ 转换为比特流
物理网络传输
```

接收方则执行相反的过程——**解封装（Decapsulation）**：从以太网帧中取出 IP 包，从 IP 包中取出 TCP 段，从 TCP 段中取出应用数据，最终交给应用程序。

在 Wireshark 的协议详情窗格里，你会清晰地看到这种嵌套结构：

```
Frame 123: 1514 bytes on wire
Ethernet II, Src: aa:bb:cc:dd:ee:ff, Dst: 11:22:33:44:55:66
Internet Protocol Version 4, Src: 192.168.1.10, Dst: 93.184.216.34
Transmission Control Protocol, Src Port: 54321, Dst Port: 80
Hypertext Transfer Protocol
    GET / HTTP/1.1\r\n
```

这正是分层封装最直观的体现。

## 2.4 三种关键地址

理解网络通信，必须分清三种地址：

### 2.4.1 MAC 地址（物理地址）

- 工作在**数据链路层**。
- 48 位（6 字节），通常写成 `00:1A:2B:3C:4D:5E`。
- 烧录在网卡（NIC）中，理论上全球唯一。
- 用于在**同一个局域网**内定位设备。
- 在 Wireshark 中显示为 `Ethernet II, Src: ..., Dst: ...`。

### 2.4.2 IP 地址（逻辑地址）

- 工作在**网络层**。
- IPv4 为 32 位，通常写成 `192.168.1.10`；IPv6 为 128 位。
- 由网络管理员或 DHCP 分配，可以变化。
- 用于**跨网络**寻址，是互联网的基础。
- 在 Wireshark 中显示为 `Internet Protocol Version 4, Src: ..., Dst: ...`。

### 2.4.3 端口号（Port）

- 工作在**传输层**。
- 16 位，范围 0~65535。
- 用于区分同一台主机上的不同应用程序。
- 常见端口：80（HTTP）、443（HTTPS）、53（DNS）、22（SSH）、25（SMTP）、3389（RDP）。
- 在 Wireshark 中显示为 `Src Port` 和 `Dst Port`。

一个完整的通信端点可以用「IP + 端口」表示，称为**套接字（Socket）**，例如 `192.168.1.10:54321`。一次 TCP 连接由四元组唯一确定：**源 IP、源端口、目的 IP、目的端口**。

## 2.5 从 MAC 到 IP：ARP 的作用

发送方要封装以太网帧，必须知道接收方的 MAC 地址。但应用程序通常只知道对方的 IP 地址。**ARP（地址解析协议）**负责把 IP 地址解析为 MAC 地址：

1. 主机 A 想给同一局域网的主机 B 发数据，但不知道 B 的 MAC。
2. A 广播一个 ARP 请求：「谁的 IP 是 192.168.1.20？请告诉我你的 MAC。」
3. 主机 B 收到后单播回复：「我是 192.168.1.20，我的 MAC 是 xx:xx:xx:xx:xx:xx。」
4. A 把结果缓存到 ARP 缓存表，后续直接使用。

Wireshark 中过滤 ARP 流量非常简单，输入 `arp` 即可。ARP 欺骗攻击也是安全分析中的常见主题（见第十六章）。

## 2.6 客户端—服务器与对等网络

- **客户端—服务器（C/S）模式**：一方发起请求（客户端），另一方响应（服务器）。如浏览器访问网站。
- **对等网络（P2P）**：每台主机既是客户端又是服务器。如 BitTorrent。

理解通信模式有助于判断数据流的方向，在 Wireshark 中分析「谁先发起连接」时很重要。

## 2.7 一次完整的网页访问：全流程拆解

让我们把上面的知识串起来。当你在浏览器输入 `http://www.example.com` 并回车，背后发生了什么？

1. **DNS 解析**：浏览器需要把域名解析成 IP。
   - 查询本地 DNS 缓存。
   - 没有则向 DNS 服务器发送查询（UDP，53 端口）。
   - 收到 DNS 响应，得到 IP 地址。
2. **ARP 解析**（如目标不在本地网络）：通过 ARP 找到网关的 MAC 地址。
3. **TCP 三次握手**：客户端与服务器的 80 端口建立连接。
   - 客户端发 SYN。
   - 服务器回 SYN+ACK。
   - 客户端发 ACK。
4. **HTTP 请求**：客户端发送 `GET / HTTP/1.1`。
5. **服务器响应**：返回 `HTTP/1.1 200 OK` 和网页内容。
6. **连接关闭或复用**：TCP 四次挥手关闭，或保持连接复用。

如果这一切都发生，你在 Wireshark 中依次会看到 DNS、ARP、TCP、HTTP 等协议的数据包。**这就是 Wireshark 分析的基本逻辑——按时间和协议还原通信过程。**

## 2.8 小结

- 协议是网络通信的规则，TCP/IP 是现实中的主流协议族。
- OSI 七层模型（物数网传会表应）帮助理解分层，TCP/IP 四层模型更贴近实际。
- 数据发送时逐层封装（加首部），接收时逐层解封装。
- MAC 地址用于局域网寻址，IP 地址用于跨网寻址，端口用于区分应用。
- ARP 负责把 IP 解析为 MAC。
- 一次网页访问涉及 DNS → ARP → TCP 握手 → HTTP 请求/响应 → 连接关闭的完整流程。
