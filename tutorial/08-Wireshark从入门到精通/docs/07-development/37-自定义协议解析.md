# 第三十七章 自定义协议解析实战

本章通过一个完整的例子，演示如何为一个私有协议编写 Lua Dissector，让 Wireshark 能够解析它。这是第三十五章协议逆向的延续——当你理解了协议结构，就用 Dissector 把它固化下来。

## 37.1 定义协议格式

假设我们逆向出一个设备协议，运行在 TCP 端口 8888，格式如下：

```
┌────────┬────────┬──────────┬──────────┬──────────┐
│ Magic  │ Version│ Type     │ Length   │ Payload  │
│ 2 字节 │ 1 字节 │ 1 字节   │ 2 字节   │ Length字节│
│ 0xCAFE │        │          │          │          │
└────────┴────────┴──────────┴──────────┴──────────┘
```

- **Magic**：固定 `0xCAFE`，标识协议。
- **Version**：版本号，如 1。
- **Type**：消息类型，1=请求，2=响应，3=心跳。
- **Length**：Payload 长度。
- **Payload**：文本数据。

## 37.2 编写 Dissector

创建 `myproto.lua`：

```lua
-- 定义协议
local myproto = Proto("myproto", "My Private Protocol v1")

-- 定义字段
local F = ProtoField
myproto.fields = {
    F.uint16("myproto.magic",   "Magic",   base.HEX),
    F.uint8 ("myproto.version", "Version", base.DEC),
    F.uint8 ("myproto.type",    "Type",    base.DEC, {
        [1] = "Request",
        [2] = "Response",
        [3] = "Heartbeat"
    }),
    F.uint16("myproto.length",  "Length",  base.DEC),
    F.string("myproto.payload", "Payload")
}

-- 类型名称映射
local type_names = {[1]="Request", [2]="Response", [3]="Heartbeat"}

function myproto.dissector(buf, pinfo, tree)
    -- 数据长度检查
    if buf:len() < 6 then
        return 0
    end

    local magic = buf(0, 2):uint()
    -- 验证魔数
    if magic ~= 0xCAFE then
        return 0
    end

    local version = buf(2, 1):uint()
    local msg_type = buf(3, 1):uint()
    local length = buf(4, 2):uint()

    -- 设置列表中的 Protocol 列
    pinfo.cols.protocol = "MYPROTO"
    -- 设置 Info 列
    local info = type_names[msg_type] or ("Unknown(" .. msg_type .. ")")
    pinfo.cols.info = "MyProto " .. info

    -- 构建协议树
    local t = tree:add(myproto, buf(), "My Private Protocol")
    t:add(myproto.fields[1], buf(0, 2))
    t:add(myproto.fields[2], buf(2, 1))
    local type_field = t:add(myproto.fields[3], buf(3, 1))
    type_field:append_text(" (" .. (type_names[msg_type] or "Unknown") .. ")")
    t:add(myproto.fields[4], buf(4, 2))

    -- 解析 Payload
    if buf:len() >= 6 + length and length > 0 then
        t:add(myproto.fields[5], buf(6, length))
    end

    return buf:len()
end

-- 注册到 TCP 端口 8888
local tcp_port = DissectorTable.get("tcp.port")
tcp_port:add(8888, myproto)
```

## 37.3 使用与验证

1. 把 `myproto.lua` 放到插件目录。
2. 重启 Wireshark 或重新加载 Lua 插件。
3. 打开使用该协议的抓包文件（或实时抓包）。
4. 原来显示为 `TCP` 的包现在显示为 `MYPROTO`。
5. 展开协议树可以看到解析出的字段。
6. 在过滤器框输入 `myproto.type == 1` 可以过滤请求包。

## 37.4 处理多个消息和边界

TCP 是字节流，一个包可能包含多条消息，或一条消息跨多个包。完整的 Dissector 需要处理这些情况：

```lua
function myproto.dissector(buf, pinfo, tree)
    local offset = 0
    while offset + 6 <= buf:len() do
        local magic = buf(offset, 2):uint()
        if magic ~= 0xCAFE then break end
        local length = buf(offset + 4, 2):uint()
        if offset + 6 + length > buf:len() then
            -- 消息不完整，等待更多数据
            pinfo.desegment_len = 6 + length - buf:len()
            return
        end
        -- 解析这一条消息...
        offset = offset + 6 + length
    end
end
```

`pinfo.desegment_len` 告诉 Wireshark 需要更多字节才能完成解析，Wireshark 会重组跨包的数据。

## 37.5 调试与排错

- 用 `print()` 输出变量值到终端。
- 魔数不匹配时返回 0，Wireshark 会尝试其他 Dissector。
- 使用 `ProtoField` 的第一个参数（如 `myproto.type`）作为过滤器字段名。
- 如果解析结果没出现，检查端口注册是否正确、插件是否加载。

## 37.6 小结

- 自定义 Dissector 让 Wireshark 理解私有协议。
- 核心：定义 Proto、ProtoField，实现 dissector 函数（解析 buffer、设置列、构建树），注册到端口。
- 处理 TCP 字节流边界时用 `pinfo.desegment_len` 重组跨包消息。
- 字段的过滤器名（如 myproto.type）可在显示过滤器中使用。
