# 第十六章 以太网与 ARP

本章从数据链路层开始协议解析之旅。以太网（Ethernet）是最常见的数据链路层技术，ARP 则是局域网通信的基石。理解它们，是看懂 Wireshark 中每一个包的前提。

## 16.1 以太网帧结构

以太网帧的格式如下（Ethernet II，即 DIX 标准，最常见）：

```
┌──────────┬──────────┬─────────┬──────────────────┬──────────┐
│ 目的 MAC │ 源 MAC   │ 类型    │ 数据（46~1500B） │ FCS      │
│ 6 字节   │ 6 字节   │ 2 字节  │                  │ 4 字节   │
└──────────┴──────────┴─────────┴──────────────────┴──────────┘
```

- **目的 MAC（Destination）**：接收方的物理地址。
- **源 MAC（Source）**：发送方的物理地址。
- **类型（Type）**：指明上层协议，常见值：
  - `0x0800`：IPv4
  - `0x86DD`：IPv6
  - `0x0806`：ARP
  - `0x8100`：VLAN 标签（802.1Q）
- **数据（Payload）**：上层协议的数据，最小 46 字节（不足则填充），最大 1500 字节（MTU）。
- **FCS（帧校验序列）**：CRC 校验值，用于检查传输错误。

> **注意**：Wireshark 通常看不到 FCS，因为网卡在接收时已校验并剥离，除非启用「在抓包中包含 FCS」选项。此外，帧的前导码（Preamble，8 字节）和帧间隙也不在 Wireshark 显示范围内。所以 Wireshark 显示的最小帧长是 60 字节（不含 FCS），而不是标准中的 64 字节。

## 16.2 在 Wireshark 中查看以太网帧

选中任意一个包，展开 `Ethernet II` 层，你会看到：

```
Ethernet II, Src: 00:11:22:33:44:55, Dst: 66:77:88:99:aa:bb
    Destination: 66:77:88:99:aa:bb
        Address: 66:77:88:99:aa:bb
        .... ..0. .... .... .... .... = LG bit: Globally unique address
        .... ...0 .... .... .... .... = IG bit: Individual address (unicast)
    Source: 00:11:22:33:44:55
        ...0 .... = LG bit: Globally unique address (factory default)
        .... ...0 = IG bit: Individual address (unicast)
    Type: IPv4 (0x0800)
```

Wireshark 贴心地解析了 MAC 地址中的两个标志位：

- **LG bit（Locally Administered）**：第一个字节的第 2 位。0 = 全球唯一（厂商分配），1 = 本地管理（可手动修改）。
- **IG bit（Individual/Group）**：第一个字节的最低位。0 = 单播，1 = 组播/广播。

例如 `ff:ff:ff:ff:ff:ff` 是广播地址，IG 位为 1。

## 16.3 三种 MAC 地址类型

- **单播（Unicast）**：发给特定设备。目的 MAC 的第一个字节最低位为 0。
- **组播（Multicast）**：发给一组设备。目的 MAC 的第一个字节最低位为 1，如 `01:00:5e:xx:xx:xx`（IPv4 组播映射）。
- **广播（Broadcast）**：发给局域网所有设备，MAC 为 `ff:ff:ff:ff:ff:ff`。

在 Wireshark 中，过滤广播帧：

```
eth.dst == ff:ff:ff:ff:ff:ff
```

过滤组播帧：

```
eth.addr[0] & 1 == 1
```

## 16.4 VLAN 与 802.1Q

虚拟局域网（VLAN）通过 802.1Q 标签在以太网帧中插入 4 字节：

```
┌──────────┬──────────┬──────┬──────┬─────────┬──────┬─────┐
│ 目的 MAC │ 源 MAC   │ 0x8100│ TCI  │ 类型    │ 数据 │ FCS │
│ 6 字节   │ 6 字节   │ 2字节 │2字节 │ 2 字节  │      │     │
└──────────┴──────────┴──────┴──────┴─────────┴──────┴─────┘
```

TCI（Tag Control Information）含：

- **Priority（PCP）**：3 位，服务质量优先级（0~7）。
- **DEI**：1 位，丢弃资格指示。
- **VLAN ID**：12 位，VLAN 编号（1~4094）。

Wireshark 中，带 VLAN 标签的帧会显示 `802.1Q Virtual LAN` 层。过滤特定 VLAN：

```
vlan.id == 100
```

## 16.5 ARP 协议详解

### 16.5.1 ARP 的作用

ARP（Address Resolution Protocol，地址解析协议）把 IPv4 地址解析为 MAC 地址。这是局域网通信的关键一步——IP 数据包最终必须封装成以太网帧，而封装需要知道下一跳的 MAC 地址。

### 16.5.2 ARP 报文格式

```
┌────────────┬────────────┬──────┬──────┬──────┬──────────────┬────────────┬──────────────┬────────────┐
│ 硬件类型   │ 协议类型   │硬件长│协议长│ 操作 │ 发送方 MAC   │ 发送方 IP  │ 目标 MAC     │ 目标 IP    │
│ 2 字节     │ 2 字节     │1字节 │1字节 │2字节 │ 6 字节       │ 4 字节     │ 6 字节       │ 4 字节     │
└────────────┴────────────┴──────┴──────┴──────┴──────────────┴────────────┴──────────────┴────────────┘
```

- **硬件类型**：1 = 以太网。
- **协议类型**：0x0800 = IPv4。
- **操作（Opcode）**：1 = ARP 请求，2 = ARP 响应。
- **发送方 MAC/IP**：发送者的地址。
- **目标 MAC/IP**：目标地址（请求时目标 MAC 为 00:00:00:00:00:00）。

### 16.5.3 ARP 工作流程

1. 主机 A（192.168.1.10）想访问主机 B（192.168.1.20），但不知道 B 的 MAC。
2. A 检查本地 ARP 缓存，没有 B 的记录。
3. A 广播 ARP 请求：「谁的 IP 是 192.168.1.20？告诉 192.168.1.10。」
   - 以太网目的 MAC = `ff:ff:ff:ff:ff:ff`
   - ARP 操作 = request
   - 目标 MAC = `00:00:00:00:00:00`
4. 局域网所有主机收到请求，只有 B 匹配 IP。
5. B 单播 ARP 响应：「我是 192.168.1.20，我的 MAC 是 xx:xx:xx:xx:xx:xx。」
6. A 收到响应，更新 ARP 缓存，开始通信。

在 Wireshark 中，一次正常的 ARP 交互就是「一请求一响应」两个包。用过滤器 `arp` 查看。

### 16.5.4 免费 ARP（Gratuitous ARP）

主机主动发送 ARP 请求查询自己的 IP，用于：

- **检测 IP 冲突**：如果有其他主机响应，说明 IP 被占用。
- **更新其他主机的 ARP 缓存**：如 VRRP 主备切换时，新主设备发免费 ARP 通告自己的 MAC。

特征：ARP 请求中发送方 IP = 目标 IP。Wireshark 会标注 `Gratuitous ARP`。

### 16.5.5 ARP 欺骗（ARP Spoofing）

ARP 协议没有认证机制，任何主机都可以发送伪造的 ARP 响应，声称某个 IP 对应自己的 MAC。攻击者利用这一点：

1. 攻击者向主机 A 发送伪造 ARP 响应：「192.168.1.1（网关）的 MAC 是攻击者的 MAC。」
2. A 更新 ARP 缓存，把发往网关的流量发给攻击者。
3. 攻击者可以窃听、篡改流量（中间人攻击）。

**在 Wireshark 中检测 ARP 欺骗**：

- 观察短时间内大量 ARP 响应包。
- 同一个 IP 对应不同的 MAC 地址。
- 频繁的免费 ARP。
- 非网关主机声称自己是网关。

过滤器辅助：

```
arp.opcode == 2                      # 所有 ARP 响应
arp.src.proto_ipv4 == 192.168.1.1    # 声称是网关的 ARP 包
```

## 16.6 小结

- 以太网帧结构：目的 MAC(6) + 源 MAC(6) + 类型(2) + 数据 + FCS(4)。
- 类型字段 0x0800=IPv4，0x0806=ARP，0x86DD=IPv6，0x8100=VLAN。
- MAC 地址分单播、组播、广播；LG/IG 位有特定含义。
- VLAN 通过 802.1Q 标签（4 字节）标识，VLAN ID 1~4094。
- ARP 把 IP 解析为 MAC：广播请求 + 单播响应，结果缓存。
- ARP 无认证，易被欺骗；Wireshark 可通过异常 ARP 包检测欺骗攻击。
