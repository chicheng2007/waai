# 第二十五章 无线与隧道协议

本章介绍两类特殊协议：无线局域网协议（802.11）和隧道/封装协议（GRE、IPSec、VPN）。无线协议分析有其独特性（需要特殊网卡和抓包模式），隧道协议则涉及多层封装。理解它们，能让你应对更复杂的网络环境。

## 25.1 802.11 无线协议基础

802.11 是无线局域网（Wi-Fi）的标准族，常见版本：

| 标准 | 频段 | 速率 |
| --- | --- | --- |
| 802.11a | 5 GHz | 54 Mbps |
| 802.11b | 2.4 GHz | 11 Mbps |
| 802.11g | 2.4 GHz | 54 Mbps |
| 802.11n | 2.4/5 GHz | 600 Mbps |
| 802.11ac | 5 GHz | 1 Gbps+ |
| 802.11ax（Wi-Fi 6） | 2.4/5 GHz | 更高速率 |

### 25.1.1 802.11 帧类型

802.11 帧有三种主要类型：

- **管理帧（Management）**：建立/维持连接，如 Beacon（信标）、Probe Request/Response、Association Request/Response、Authentication、Deauthentication。
- **控制帧（Control）**：辅助数据传输，如 RTS/CTS、ACK、PS-Poll。
- **数据帧（Data）**：承载上层数据（IP 包）。

### 25.1.2 捕获无线流量

捕获 802.11 流量有特殊要求：

1. **无线网卡必须支持 Monitor Mode（监听模式）**，普通网卡的混杂模式不足以捕获 802.11 帧。
2. Linux 下常用 `airmon-ng` 开启监听模式：

```bash
sudo airmon-ng start wlan0
```

3. 选择对应的虚拟接口（如 `wlan0mon`）开始捕获。
4. Windows 下需要支持 Monitor Mode 的特定网卡和驱动（如 Npcap 配合兼容网卡）。

### 25.1.3 Wireshark 中的 802.11 帧

```
802.11 Beacon frame, SN=123, FN=0, Flags=........
    Frame Control Field: 0x8000
        .... ..00 = Version: 0
        .... 00.. = Type: Management frame (0)
        .... 0000 = Subtype: Beacon (8)
    Duration: 0x0000
    Destination address: ff:ff:ff:ff:ff:ff
    Source address: 00:11:22:33:44:55
    BSSID: 00:11:22:33:44:55
    SSID: MyWiFi
    Supported data rates: 1, 2, 5.5, 11 Mbps
```

**Beacon 帧**由 AP 定期广播（通常每 100ms），宣告网络的存在（SSID、速率、安全方式等）。

### 25.1.4 常用过滤

```
wlan                                     # 所有 802.11 帧
wlan.fc.type_subtype == 0x08             # Beacon 帧
wlan.fc.type_subtype == 0x04             # Probe Request
wlan.fc.type_subtype == 0x0b             # Authentication
wlan.fc.type_subtype == 0x00             # Association Request
wlan.ssid == "MyWiFi"                    # 特定 SSID
wlan.bssid == 00:11:22:33:44:55          # 特定 BSSID
wlan.fc.retry == 1                       # 重传帧
wlan_radio.signal_dbm < -70              # 信号弱（需支持无线元数据）
```

### 25.1.5 无线安全分析

- **Deauth 攻击**：攻击者发送伪造的 Deauthentication 帧，强制客户端断开连接。特征是大量 Deauth 帧（`wlan.fc.type_subtype == 0x0c`）。
- **Evil Twin（恶意热点）**：伪造的 AP 广播相同 SSID，诱导客户端连接。
- **WPA 握手捕获**：捕获四次握手（EAPOL 包，`eapol`），可用于离线密码破解（需要合法授权）。
- **Hidden SSID**：Beacon 中 SSID 为空，但 Probe Response/Association 中可能暴露。

> **法律与道德提示**：无线安全测试必须在授权环境下进行。未经授权抓包、破解他人 Wi-Fi 违反法律。

## 25.2 隧道与封装协议

隧道协议把一种协议的数据包封装在另一种协议中传输。Wireshark 会逐层解析这些封装。

### 25.2.1 GRE（通用路由封装）

GRE（Generic Routing Encapsulation，协议号 47）是一种简单的隧道协议，把 IP 包封装在 IP 包中：

```
外层 IP 首部 | GRE 首部 | 内层 IP 首部 | 数据
```

Wireshark 中可以看到：

```
Internet Protocol Version 4, Src: 1.1.1.1, Dst: 2.2.2.2
Generic Routing Encapsulation (IP)
    Flags and Version: 0x0000
    Protocol Type: IP (0x0800)
Internet Protocol Version 4, Src: 10.0.0.1, Dst: 10.0.1.1  # 内层 IP
```

过滤：`gre`。

### 25.2.2 IPSec

IPSec（IP Security）是一套加密协议，提供网络层安全：

- **AH（Authentication Header，协议号 51）**：认证和完整性，不加密。
- **ESP（Encapsulating Security Payload，协议号 50）**：加密 + 认证。

两种模式：

- **传输模式**：只加密载荷，IP 首部保留。
- **隧道模式**：加密整个原始 IP 包，添加新的外层 IP 首部（常用于 VPN）。

Wireshark 中 ESP 包显示为加密数据。要解密需要配置 SA（Security Association）密钥（见 `Edit → Preferences → Protocols → ESP`）。

过滤：`esp || ah`。

### 25.2.3 VPN 相关

- **IPSec VPN**：用 IPSec 实现，企业站点互联常用。
- **SSL/TLS VPN**：如 OpenVPN（基于 TLS），端口 1194。
- **WireGuard**：现代 VPN，基于 UDP，端口通常 51820。
- **PPTP/L2TP**：较老的 VPN 协议，安全性较差。

### 25.2.4 VLAN 与 MPLS

- **VLAN（802.1Q）**：已在第十六章介绍，通过 4 字节标签隔离二层网络。
- **MPLS（多协议标签交换）**：在 IP 包外添加标签（4 字节），用于运营商网络流量工程。Wireshark 中显示为 `MPLS` 层。

过滤：`mpls`。

### 25.2.5 VXLAN（虚拟可扩展局域网）

VXLAN 是数据中心常用的overlay网络技术，把二层帧封装在 UDP 中（端口 4789）：

```
外层 IP | UDP(4789) | VXLAN 首部 | 内层以太网帧
```

过滤：`vxlan || udp.port == 4789`。

## 25.3 封装层次的分析思路

面对多层封装的包，Wireshark 的协议树会从外到内逐层展开。分析时：

1. **从外到内理解路径**：外层地址是隧道端点的地址，内层地址是实际通信的地址。
2. **注意 MTU 影响**：封装增加了首部开销，可能导致分片或丢包（如 VXLAN 增加 50 字节，需要调整 MTU）。
3. **解密配置**：加密的隧道（IPSec ESP）需要密钥才能看内层内容。
4. **逐层过滤**：Wireshark 允许按任意层的字段过滤，如 `ip.src == 1.1.1.1 && ip.src == 10.0.0.1`（外层 + 内层）。

## 25.4 小结

- 802.11 帧分管理帧（Beacon、Probe、Auth、Assoc）、控制帧（ACK、RTS/CTS）、数据帧。
- 捕获无线流量需支持 Monitor Mode 的网卡，Linux 用 airmon-ng 开启。
- 无线安全分析关注 Deauth 攻击、Evil Twin、WPA 握手、隐藏 SSID。
- 隧道协议：GRE（协议 47）、IPSec（AH 51/ESP 50）、VXLAN（UDP 4789）等把包封装在包中。
- Wireshark 逐层展开封装，分析时注意外层/内层地址、MTU 影响和解密配置。
