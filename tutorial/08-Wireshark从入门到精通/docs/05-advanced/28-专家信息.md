# 第二十八章 专家信息与告警

Wireshark 内置了一个「智能诊断」系统——专家信息（Expert Information）。它会扫描所有数据包，把符合特定异常模式（如重传、乱序、错误校验和、应用错误）的包分级标注。善用专家信息，能让你在海量数据中快速定位问题包。

## 28.1 打开专家信息

菜单 `Analyze → Expert Information`。打开的窗口按严重级别分组列出所有专家信息条目：

| 级别 | 颜色 | 含义 |
| --- | --- | --- |
| Error（错误） | 红色 | 严重的协议错误，如校验和错误、非法字段 |
| Warning（警告） | 黄色 | 可疑情况，如重传、乱序、重复 ACK |
| Note（注意） | 蓝色 | 值得注意但不一定异常，如连接建立/关闭 |
| Chat（聊天） | 青色 | 一般 protocol 信息，如请求/响应配对 |
| Comment（注释） | 灰色 | 用户添加的包注释 |

### 28.1.1 窗口内容

每条专家信息包含：

- **Severity**：级别。
- **Group**：所属协议组（TCP、ICMP、DNS 等）。
- **Message**：具体消息（如 `Retransmission`）。
- **Count**：出现次数。
- **First / Last**：首次和最后一次出现的包序号。

点击某条信息，Wireshark 会跳转到对应的包。

## 28.2 常见专家消息解读

### 28.2.1 TCP 相关

| 消息 | 级别 | 含义 | 分析方向 |
| --- | --- | --- | --- |
| Retransmission | Warning | 重传 | 网络丢包、拥塞 |
| Fast Retransmission | Warning | 快速重传 | 收到 3 个重复 ACK |
| Spurious Retransmission | Warning | 虚假重传 | 数据其实已收到，可能是乱序导致 |
| Duplicate ACK | Note | 重复 ACK | 可能丢包 |
| Out-of-Order | Note/Warning | 乱序 | 多路径、QoS 差异 |
| Zero Window | Warning | 零窗口 | 接收方处理慢 |
| Window Update | Note | 窗口更新 | 接收方恢复接收能力 |
| Connection Reset (RST) | Note | 连接重置 | 异常断开 |
| Previous segment not captured | Warning | 前一段未捕获 | 抓包丢包或真实丢包 |

### 28.2.2 IP / ICMP 相关

| 消息 | 含义 |
| --- | --- |
| Bad checksum | 校验和错误（可能是网卡卸载导致的假象） |
| Fragmented IP protocol | IP 分片 |
| Time-to-live exceeded | TTL 超时 |
| Destination unreachable | 目的不可达 |

### 28.2.3 应用层相关

- DNS：响应码错误、查询超时。
- HTTP：错误状态码、畸形请求。
- TLS：握手失败、告警消息。

## 28.3 专家信息实战用法

### 28.3.1 快速定位问题

分析一个抓包文件时的高效流程：

1. 打开专家信息，先看 Error 和 Warning 级别。
2. 按 Count 排序，找出出现次数最多的异常。
3. 点击具体条目跳转到包，结合上下文分析。
4. 用对应的显示过滤器（如 `tcp.analysis.retransmission`）筛出所有同类包。

### 28.3.2 判断抓包质量

「Previous segment not captured」（前一段未捕获）大量出现，通常意味着**抓包本身丢包了**（抓包主机性能不足、磁盘太慢），而不是网络真的丢包。这时需要先解决抓包质量问题（见第三十九章），否则分析结论不可靠。

### 28.3.3 校验和错误的陷阱

`Bad checksum` 经常是**假阳性**。现代网卡把校验和计算卸载到硬件，Wireshark 收到包时校验和字段还没填充，所以显示错误。这不是真的网络错误。

解决：在 `Edit → Preferences → Protocols → TCP/UDP/IPv4` 中取消勾选「Validate checksum if possible」，或在抓包时禁用网卡的校验和卸载（Linux: `ethtool -K eth0 rx off tx off`）。

## 28.4 专家信息的局限

- 它基于预定义规则，不能替代人工分析。
- 某些警告可能是正常现象（如快速重传有时是合理的）。
- 需要结合上下文（协议、场景、时间）判断，不能看到警告就下结论。

## 28.5 小结

- 专家信息按 Error、Warning、Note、Chat、Comment 五级分类标注异常包。
- 常见 TCP 专家消息：重传、快速重传、乱序、重复 ACK、零窗口、RST。
- 实战流程：先看高级别 → 按次数排序 → 跳转分析 → 用过滤器筛出同类。
- 注意「前一段未捕获」可能反映抓包质量问题；校验和错误常是网卡卸载导致的假象。
- 专家信息是线索，不是结论，需结合上下文判断。
