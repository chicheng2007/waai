## 21.2 用 LangChain 重写 Agent

ch20 的原生骨架让你理解原理，现在用 LangChain 做生产级实现。LangChain 提供了现成的 Agent、工具、记忆抽象，省去手写解析的麻烦。

### 安装

```bash
pip install langchain langchain-community langchain-openai
```

### 定义工具

```python
from langchain.tools import tool

@tool
def grep_log(file: str, pattern: str) -> str:
    """在日志文件中搜索关键词，返回匹配的行。file是.log文件路径，pattern是搜索关键词。"""
    import subprocess
    if not file.endswith(".log"):
        return "错误：只能读取 .log 文件"
    r = subprocess.run(["grep", pattern, file], capture_output=True, text=True, timeout=10)
    return r.stdout[:2000] or "无匹配"

@tool
def analyze_log(log_line: str) -> str:
    """用取证模型分析单条日志，返回结论/依据/建议三段式分析。"""
    from scripts.inference import ForensicQA
    qa = ForensicQA("/path/to/Qwen2.5-7B-Instruct", "outputs/v2")
    return qa.analyze(log_line)

@tool
def list_files(directory: str) -> str:
    """列出目录下的文件。"""
    import os
    return "\n".join(os.listdir(directory))

tools = [grep_log, analyze_log, list_files]
```

LangChain 的 `@tool` 装饰器自动从函数的类型注解和 docstring 生成工具定义——比手写 JSON Schema 方便得多。

### 创建 Agent

```python
from langchain_openai import ChatOpenAI
from langchain.agents import initialize_agent, AgentType
from langchain.memory import ConversationBufferMemory

llm = ChatOpenAI(
    base_url="http://localhost:1234/v1",
    api_key="not-needed",
    model="local-model",
    temperature=0.1
)

memory = ConversationBufferMemory(memory_key="chat_history", return_messages=True)

agent = initialize_agent(
    tools=tools,
    llm=llm,
    agent=AgentType.CHAT_CONVERSATIONAL_REACT_DESCRIPTION,
    memory=memory,
    verbose=True,  # 打印思考过程，方便调试
    max_iterations=10,  # 防止死循环
    handle_parsing_errors=True
)
```

### 运行

```python
result = agent.run("分析 starsea_firewall.log，找出所有可疑 IP 和异常事件，生成研判报告")
print(result)
```

LangChain 自动处理 ReAct 循环、工具调用、记忆管理。你要做的只是定义工具和目标。

## 21.3 加入我们的取证模型

这个项目的核心亮点是：**Agent 的大脑用通用模型调度，具体分析用我们微调的取证模型**。

```python
# 混合架构：
# - 通用 Qwen（本地）：负责规划、工具选择、报告生成
# - 微调取证模型：负责具体的日志分析（analyze_log 工具）

@tool
def analyze_log(log_line: str) -> str:
    """用微调的取证模型分析日志，返回专业三段式分析。"""
    qa = ForensicQA(
        base_path="/path/to/Qwen2.5-7B-Instruct",
        adapter_path="outputs/v2"  # ch15 训练的模型
    )
    return qa.analyze(log_line)
```

这样，Agent 用通用模型的推理能力做调度，用专用模型的专业能力做分析。**这是最实用的架构**——既有通用推理，又有专业深度。

## 21.4 报告生成

Agent 分析完，生成结构化报告：

```python
REPORT_PROMPT = """基于以下分析发现，生成一份日志研判报告。

发现：{findings}

报告格式：
## 摘要
（一句话总结）

## 关键发现
1. ...
2. ...

## 时间线
| 时间 | 事件 | 严重程度 |

## 建议
1. ...
"""

def generate_report(findings):
    return llm.invoke(REPORT_PROMPT.format(findings=findings)).content
```

示例输出：

```
## 摘要
日志中发现来自外部地址 203.0.113.5 的端口扫描行为，以及疑似数据外传活动。

## 关键发现
1. 02:03 左右，203.0.113.5 对 10.0.2.10 发起多端口扫描（严重）
2. 04:15 左右，内网主机向外部地址传输超大数据（严重）
3. 05:00 左右，多次登录失败（中等）

## 时间线
| 时间 | 事件 | 严重程度 |
|---|---|---|
| 02:03 | 端口扫描 | 高 |
| 04:15 | 数据外传 | 高 |
| 05:00 | 登录爆破 | 中 |

## 建议
1. 立即封禁 203.0.113.5
2. 核查数据外传的目标和内容
3. 检查相关账户是否存在弱口令
```
