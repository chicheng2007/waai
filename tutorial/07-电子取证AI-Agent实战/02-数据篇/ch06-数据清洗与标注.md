## 6.1 原始数据有多脏

上一章我们合成了 `starsea_firewall.log`，看起来挺规整。但真实数据远没这么干净。实际采来的日志常见问题：

- **格式不统一**：不同设备的时间戳格式不一样（`2026-10-15 10:00:00`、`10/15/2026 10:00`、`1697354400` 时间戳）；
- **缺失字段**：有的记录少了 IP，有的少了端口；
- **重复记录**：同一事件被多个设备记录，或者采集中重复抓取；
- **编码问题**：中文日志有 GBK、UTF-8 混用，出现乱码；
- **噪音数据**：健康检查、心跳包等无意义流量占大头；
- **异常值**：流量大小字段出现负数或离谱的数字（采集错误）。

如果不处理这些，模型学到的就是一堆垃圾规律。清洗的目标就是：**让每一条数据都规范、完整、可信**。

## 6.2 清洗五步法

我把清洗流程总结成五步，照着做基本不会漏。

### 第一步：统一格式

把所有时间戳转成统一的 ISO 格式，把所有字段按固定顺序排列。

```python
import pandas as pd
from datetime import datetime

# 读取原始日志（假设是 CSV 格式）
df = pd.read_csv("starsea_firewall.log", sep=" ", header=None,
                 names=["time", "action", "flow", "size"])

# 统一时间戳
df["time"] = pd.to_datetime(df["time"], errors="coerce")

# 拆分 "10.0.1.2->10.0.2.10:80" 这样的字段
df[["src", "dst_port"]] = df["flow"].str.extract(r'([^>]+)->[^:]+:(\d+)')
df["dst"] = df["flow"].str.extract(r'->([^:]+):')[0]

print(df.head())
```

`errors="coerce"` 是关键：无法解析的时间戳会变成 `NaT`（空值），后面统一处理，不会让程序崩掉。

### 第二步：处理缺失

缺失数据不能简单删除（可能丢失关键信息），也不能随便填。策略：

| 缺失情况 | 处理方式 |
|---|---|
| 时间戳缺失 | 删除该条（无法做时序分析） |
| IP 缺失 | 标记为 `UNKNOWN`，保留记录 |
| 端口缺失 | 填 `0`，加一个 `port_missing` 标志位 |
| 流量大小缺失 | 填中位数，加标志位 |

**加标志位**是个好习惯：让模型知道"这个字段是补的"，而不是被假数据误导。

```python
# 标记缺失
df["port_missing"] = df["dst_port"].isna().astype(int)
df["dst_port"] = df["dst_port"].fillna("0")

# 时间戳缺失的删除
before = len(df)
df = df.dropna(subset=["time"])
print(f"删除了 {before - len(df)} 条无时间戳记录")
```

### 第三步：去重

完全相同的记录通常是采集重复。但注意：**真实环境里，相同内容的不同时间记录可能是正常事件**，不能盲目去重。

```python
# 基于所有字段去重（保留第一条）
df = df.drop_duplicates()
```

如果要更精细，可以基于"时间窗口 + 关键字段"去重，比如同一 IP 在同一秒的相同请求。

### 第四步：过滤噪音

健康检查、心跳包这类流量没有分析价值，可以过滤。但要小心：**别把真正的攻击过滤掉**。

```python
# 过滤掉明显的心跳包（极小流量 + 固定端口）
noise = (df["size"] < 100) & (df["dst_port"].isin(["80", "443"]))
df = df[~noise]
```

### 第五步：异常值处理

流量大小出现负数或超大值，多半是采集错误，要标记或修正。

```python
# 标记异常流量值
df["size_anomaly"] = (df["size"] < 0) | (df["size"] > 1e12)
print(f"发现 {df['size_anomaly'].sum()} 条异常大小记录")
```

注意：我们**不直接删除**异常值，而是标记。因为这些"异常"可能正是攻击（大流量外传），删了就丢了线索。标记后让后续分析决定。

## 6.3 给数据打标签

清洗完要打标签。标签是监督学习的"标准答案"。取证数据有几种标签方式：

### 方式一：二分类标签（正常/异常）

最简单。给每条记录打上 `normal` 或 `anomaly`。适合做异常检测模型。

```python
# 根据我们合成时的规则打标签
# 异常 IP 段、异常端口扫描、大流量都是异常
df["label"] = "normal"
df.loc[df["src"].str.startswith("203.0.113."), "label"] = "anomaly"
df.loc[df["size"] > 50_000_000, "label"] = "anomaly"
```

### 方式二：多分类标签（异常类型）

更细：把异常分成端口扫描、爆破、外传等类型。这样模型不只判断"有没有问题"，还能说"是什么问题"。

```python
def label_type(row):
    if row["size"] > 50_000_000:
        return "large_transfer"
    if str(row["src"]).startswith("203.0.113.") and row["dst_port"] == "22":
        return "brute_force"
    if str(row["src"]).startswith("203.0.113."):
        return "suspicious_external"
    return "normal"

df["label_detail"] = df.apply(label_type, axis=1)
```

### 方式三：模型辅助标注

数据量大、人工标不过来时，可以用大模型辅助标注：把日志片段发给本地 Qwen，让它判断类型，人工抽查校正。

```python
from openai import OpenAI
client = OpenAI(base_url="http://localhost:1234/v1", api_key="not-needed")

def label_by_llm(log_line):
    prompt = f"""你是取证分析师。判断下面这条日志属于哪类：
正常流量 / 端口扫描 / 登录爆破 / 数据外传 / 其他
只输出类别名称，不要解释。

日志：{log_line}"""
    resp = client.chat.completions.create(
        model="local-model",
        messages=[{"role": "user", "content": prompt}],
        temperature=0.1
    )
    return resp.choices[0].message.content.strip()
```

**注意**：模型辅助标注一定要人工抽查（比如抽 10%），因为模型会出错。这就是"人在回路"。

## 6.4 质量检查（不能跳过）

清洗和标注完，做一次质量检查：

```python
# 1. 看标签分布是否均衡
print(df["label"].value_counts())

# 2. 看缺失率
print(df.isna().sum())

# 3. 看数据范围
print(df.describe())

# 4. 随机抽样人工看几条
print(df.sample(10))
```

重点检查：

- **标签分布**：如果异常只占 0.01%，模型会倾向于全判正常（类别不平衡），需要过采样或调整；
- **缺失率**：某个字段 90% 缺失，这个字段基本没用，考虑删掉；
- **抽样目检**：随机看 20 条，标签对不对？格式对不对？

**类别不平衡**是取证数据的常见问题。异常本来就是极少数。处理方法：

- **过采样**：复制少数类样本（简单但可能过拟合）；
- **欠采样**：减少多数类样本（简单但丢信息）；
- **SMOTE**：合成少数类样本（进阶）；
- **调整损失权重**：让模型更重视少数类（模型篇讲）。

本书的合成数据里异常占 5%，还算可控。真实数据可能更极端。

## 6.5 保存成标准格式

清洗好的数据，保存成模型能直接读的格式。常用两种：

### CSV（简单，适合表格数据）

```python
df.to_csv("starsea_clean.csv", index=False, encoding="utf-8")
```

### JSONL（每行一个 JSON，适合大模型训练）

```python
import json
with open("starsea_clean.jsonl", "w", encoding="utf-8") as f:
    for _, row in df.iterrows():
        f.write(json.dumps(row.to_dict(), ensure_ascii=False) + "\n")
```

JSONL 的好处是：**每行独立**，方便按行读取、打乱、分块。大模型训练框架（如 Hugging Face）普遍支持。

## 6.6 数据版本管理

一个容易被新手忽略的点：**数据也要版本管理**。

你清洗出一版数据，调模型时发现有问题，改了清洗逻辑，又出一版。如果没有版本记录，你根本不知道模型是用哪版数据训的。

简单做法：

- 每次清洗保存一个新文件，带版本号：`starsea_v1.csv`、`starsea_v2.csv`；
- 建一个 `DATA.md` 记录每版的改动（上一章提过）；
- 记录数据处理脚本的 Git commit。

专业做法是用 DVC（Data Version Control），类似数据的 Git。新手先用简单版就行。

## 6.7 动手任务

1. **跑通清洗脚本**：把 6.2 节的代码整理成一个 `clean_logs.py`，对上一章生成的 `starsea_firewall.log` 做清洗，输出 `starsea_clean.csv`。

3. **质量检查**：执行 6.4 的检查代码，记录标签分布。异常占比是多少？
4. **人工抽查**：随机抽 20 条，肉眼核对标签对不对。错了几条？分析原因。
5. **保存 JSONL**：把清洗后的数据存成 JSONL 格式，准备给下一章用。

完成这些，你手里就有一份干净的、带标签的数据集了。

## 6.8 小结

- 原始数据很脏：格式不一、缺失、重复、乱码、噪音、异常值；
- 清洗五步：统一格式 → 处理缺失 → 去重 → 过滤噪音 → 异常值处理（标记而非删除）；
- 打标签三种方式：二分类、多分类、模型辅助（需人工抽查）；
- **质量检查不能跳过**：看标签分布、缺失率、抽样目检；
- 类别不平衡是常见坑，可用过采样/欠采样/SMOTE/损失权重处理；
- 保存成 CSV 或 JSONL；数据也要版本管理。
