## 引子：凌晨三点的取证现场

先讲一个场景，你感受一下。

某为公司发现内网被入侵，核心客户数据在半夜被打包外传。安全团队接到报警时，手里只有三样东西：一台被隔离的服务器镜像（500GB）、一周的防火墙日志（约 2TB）、以及一封员工报告的可疑邮件。

分析师小李要在天亮前给出初步判断：攻击者怎么进来的、动了什么、数据有没有拿走。他打开取证工具，导出日志，用 grep 和 Excel 一点点翻。2TB 日志里有几千万条记录，其中绝大多数是正常流量。他得先知道该找什么特征，才能写对过滤条件。写错了，要么漏掉关键线索，要么被淹没在噪音里。

这就是电子取证的日常：**数据海量、时间紧迫、线索隐蔽、知识门槛高**。小李不是不努力，是人脑处理不了这个量级的信息。

现在换一种可能：如果有一个 AI 助手，能把 2TB 日志读一遍，自动挑出异常的时间段、陌生的 IP、异常大的数据外传，生成一份"可疑事件时间线"，小李只需要核对和深挖——同样的工作，可能从 8 小时压缩到 40 分钟。

这不是科幻。这正是这本书要带你实现的东西：**一个能帮你读日志、看样本、理线索的取证 AI / Agent**。

## 1.1 什么是电子取证

在讲 AI 之前，先把"电子取证"本身说清楚，否则后面无从谈起。

**电子取证（Digital Forensics）**，简单说就是：从数字设备里找出证据，回答"发生了什么、谁干的、怎么干的"。它有几个典型场景：

- **事件响应（IR）**：公司被攻击了，搞清楚攻击路径和影响范围；
- **司法取证**：涉及法律案件，提取的证据要能上法庭，对流程和完整性要求极高；
- **恶意软件分析**：拿到一个可疑样本，搞清楚它干了什么、怎么传播的；
- **合规审计**：检查系统有没有违规操作、数据有没有泄露。

取证工作有个鲜明特点：**它是一个"从海量噪音里找少量信号"的过程**。这跟 AI 擅长的事情高度重合——AI 最擅长的就是从大量数据里找模式、做分类、生成摘要。

一个标准取证流程大致是这样：

```
识别(Identification) → 保全(Preservation) → 采集(Acquisition)
→ 分析(Analysis) → 记录(Documentation) → 呈现(Presentation)
```

这六步里，AI 最能帮上忙的是**分析**环节，其次是采集和记录。我们在第二章详细展开这个流程。

## 1.2 传统取证的四大痛点

为什么需要 AI？因为传统取证有几个绕不开的痛点。这些痛点不是"工具不够好"，而是**人力本身的极限**。

### 痛点一：数据量爆炸

前面说过，2TB 日志、500GB 镜像是常态。一个中型企业的安全设备每天产生的数据可能上 TB。分析师不可能逐条看。传统做法是写规则、写脚本过滤，但规则只能覆盖"你已知的攻击模式"。对于未知的、变异的攻击，规则无能为力。

**这就是 AI 的价值**：它不依赖精确规则，而是能识别"看起来不对劲"的异常模式。

### 痛点二：大量重复劳动

取证工作里有大量机械性任务：把日志按时间排序、把不同来源的事件对齐、把 IP 归属查一遍、把常见的进程名标注出来。这些活儿不难，但极耗时间，而且容易出错。

这类任务特别适合交给 AI Agent 自动化——**让机器干机械活，让人干判断活**。

### 痛点三：知识门槛高

取证是个交叉学科：你要懂操作系统（Windows/Linux 内部机制）、懂网络（协议、流量）、懂文件格式（PE/ELF、内存结构）、懂攻击手法（各种漏洞利用）、还得懂法律（证据链、合规性）。

一个新手分析师面对一个内存镜像，光是"该看哪些结构"就要学几个月。**AI 可以把专家经验"编码"进来**，让新手也能得到专家级的提示。这就是我们后面要做的"取证问答模型"。

### 痛点四：人手严重不足

安全行业缺人，这是共识。企业在增长，攻击在增多，但分析师的数量增长很慢。AI 不是要取代分析师，而是**让一个分析师能顶三个用**。

## 1.3 AI 能帮什么：四个层次

"AI + 取证"不是一个笼统的概念。我把它拆成四个层次，从易到难，也是这本书的进阶路线。

### 层次一：辅助分析（最容易，也最实用）

这是 AI 最成熟的应用：**让它读、让它总结、让它分类**。

- 把一段日志丢给大模型，让它"总结这里面发生了什么异常"；
- 把一个可疑进程的命令行丢给它，让它"判断这是不是常见的系统进程"；
- 让它把几百条告警按严重程度排序。

这个层次**不需要训练模型**，写好 Prompt 就能做。对应本书 ch16-ch20 的 Agent 基础部分。

### 层次二：流程自动化

在层次一的基础上，让 AI 能**调用工具**：查 IP 归属、读文件、跑脚本、查数据库。这就是 Agent 的核心能力。

比如一个"日志研判 Agent"：接到任务后，自己决定先读哪份日志、用什么命令过滤、把结果写到哪里，最后给出结论。对应本书 ch17、ch21。

### 层次三：专用模型（需要训练）

通用大模型虽然强，但它不懂你的具体业务。比如你们公司有一套自己的日志格式和告警规则，通用模型不认识。这时候需要**用你自己的数据微调一个专用模型**，让它学会你们的"行话"。

这是本书第三部分的重点：从 LoRA 原理到实际微调，训练一个懂取证的问答模型。

### 层次四：推理与决策（进阶）

最高层次是让 Agent 具备**多步推理和规划能力**：面对一个复杂案件，自己拆解成子任务，一步步执行，根据中间结果调整策略。

这对应 ch19 的规划与多步任务，以及 ch23 的多智能体协作。这是前沿方向，也是本书的进阶内容。

## 1.4 为什么是现在

你可能会问：AI 不是早就有了吗，为什么现在才谈"取证 AI"？因为三个条件最近才同时成熟。

**第一，大模型能力跃升。** 2023 年之后，开源大模型（Llama、Qwen 等）的能力大幅提升，已经能理解复杂的技术文本。Qwen3.5 这类模型对中文技术内容的表现尤其好——这对中文取证场景很关键。

**第二，开源生态完善。** LLaMA-Factory、unsloth、Hugging Face 这些工具，把"微调一个模型"从博士级难度降到了学生级难度。你不需要自己写训练框架，改改配置就能跑。

**第三，硬件成本下降。** 一张 8GB 显存的消费级显卡，配合量化技术和 LoRA，就能微调一个 7B/9B 的模型。这在几年前是不可想象的。这本书的所有实操都基于这个现实——**你手里的显卡就够用**。

## 1.6 贯穿全书的案例：某为公司数据泄露案

为了让抽象的概念落地，全书用一个虚拟案例贯穿：**某为公司数据泄露案**（我们称之为"星海案"）。

案情设定：

> 星海公司发现客户数据在夜间被外传。安全团队获得：一周防火墙日志、一台服务器镜像、一封可疑邮件。目标是搞清楚：攻击者如何进入、执行了什么、泄露了多少数据。

这本书里的每个技术点，都会回到这个案例：

- ch05-ch09：把星海案的日志整理成训练数据集；
- ch10-ch15：微调一个能回答"这段日志是不是异常"的模型；
- ch16-ch20：搭一个能自动查日志、理时间线的 Agent；
- ch21：做出完整的"AI 日志研判工具"。

到这本书结束，你会有一个围绕真实场景的完整作品。

## 1.8 小结

- 电子取证的本质是**从海量噪音里找少量信号**，这正好是 AI 擅长的；
- 传统取证的四大痛点：数据爆炸、重复劳动、知识门槛、人手不足；
- AI 能帮的四个层次：辅助分析 → 流程自动化 → 专用模型 → 推理决策，也是本书的进阶路线；
- 现在做这件事的时机成熟：大模型能力、开源生态、硬件成本三者齐备；
- 全书用"星海案"贯穿，让你最终做出一个真实的作品。
