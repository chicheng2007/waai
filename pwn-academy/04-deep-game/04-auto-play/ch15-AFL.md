# 第 15 关 · AFL：机器人试错工厂

## 🎬 游戏开场

如果说 angr 是"聪明的解题机器人",AFL 就是"勤劳的试错机器人军团"。

AFL(American Fuzzy Lop)做的事很简单粗暴:

1. 准备一堆种子输入。
2. 让程序反复用变异后的输入运行(随机改字节、翻转、拼接)。
3. 监控哪些输入让程序崩溃或走到新路径。
4. 把"有趣"的输入留下来继续变异。

游戏比喻:派一万个机器人拿着随机的钥匙疯狂试锁,谁试出"咔哒"一声(崩溃/新路径),就把这把钥匙记下来继续改进。爬着爬着,就找到了能打开漏洞大门的钥匙。

---

## 🧠 核心概念（游戏版）

### 1. 模糊测试(fuzzing)是什么?

**核心思想**:用大量随机/半随机的输入轰炸程序,期望撞出异常(崩溃、断言失败)。

它不"理解"程序,纯靠数量 + 智能的变异策略。但对找内存破坏漏洞(栈溢出、UAF)极其有效——因为这些漏洞一触发就崩溃,很容易被检测到。

### 2. AFL 的智能之处

AFL 不是纯随机,它有**代码覆盖率反馈**:

- 它在程序里插桩(instrumentation),记录每次运行"走了哪些代码路径"。
- 如果一个变异输入走到了**新路径**,就保留它作为下一步变异的种子。
- 这样它能逐渐"探索"到程序深处,而不是在入口瞎撞。

游戏比喻:机器人不只乱试,还会记笔记"这把钥匙多转了半圈,进了一点点"——然后专注改进这把钥匙,一步步深入。

### 3. 基本用法

```bash
# 编译时插桩
afl-gcc -g -O0 target.c -o target

# 准备种子输入目录
mkdir seeds && echo "AAAA" > seeds/seed1

# 开始fuzz
afl-fuzz -i seeds -o findings ./target @@

# 查看结果
ls findings/crashes/    # 让程序崩溃的输入
```

`@@` 表示 AFL 会把输入放到文件里作为参数传给程序(对需要读文件的程序)。

### 4. 在 PWN 中的用途

- **找未知漏洞**:给一个有漏洞的程序,让 AFL 自动找到崩溃输入。
- **辅助解题**:某些题的输入空间大,AFL 帮你先撞出一个崩溃,再分析。
- **libraries/真实软件**:AFL 是工业界挖洞的常用工具。

### 5. AFL 的局限

- 需要源码或二进制插桩(qemu 模式可 fuzz 无源码二进制,但慢)。
- 对需要复杂交互(网络协议、多步骤状态机)的程序效果差。
- 崩溃 ≠ 可利用,还得人工分析能不能变成 exp。

## 🎯 本关任务:跑一次 AFL

用一个故意有 `gets(buf)` 漏洞的小程序:

```c
#include <stdio.h>
int main(){ char buf[16]; gets(buf); printf("%s\n", buf); }
```

```bash
afl-gcc -g -O0 -fno-stack-protector afl.c -o afl_target
mkdir seeds && echo "test" > seeds/s
afl-fuzz -i seeds -o out ./afl_target
```

等几分钟,看 `out/crashes/` 里 AFL 找到的崩溃输入。观察它是不是用超长字符串触发了溢出。
