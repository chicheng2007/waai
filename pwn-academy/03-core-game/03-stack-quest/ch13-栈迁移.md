# 第 13 关 · 栈迁移：换个大点的战场

## 🎬 游戏开场

你在打一场仗，但你被限制在一张**很小的桌子**（栈空间）上摆你的乐高 ROP 链。你的链条需要 20 块积木，可这张桌子只放得下 3 块。

怎么办？

聪明的你想到：**桌子小，但仓库大啊**（.bss 段这种又大又可写的地方）。于是你施了个"移形换影"：

1. 先把乐高积木都搬到仓库里摆好。
2. 然后改一下"战场坐标"，让游戏以为**仓库就是新的桌子**。
3. 游戏继续按规则执行 `ret`，但这次它从仓库里拿积木——你的完整链条终于能展开了。

这就是 **栈迁移（stack pivot）**：把栈"搬迁"到一块更大、我们更能控制的地方，在那里从容执行 ROP。

---

## 🧠 核心概念（游戏版）

### 1. 什么时候需要栈迁移？

- 溢出的空间太小，放不下完整 ROP 链。
- 栈地址未知（ASLR），但有个已知的可写地址（如 .bss）。
- 题目只给你一次写入机会，写到了别处而不是栈上。

### 2. 关键机关：leave; ret

还记得第 4 关函数收尾的 `leave; ret` 吗？

```asm
leave   ; 等价于 mov rsp, rbp ; pop rbp
ret     ; 从新的 rsp 指向的地方弹出地址，跳过去
```

拆开看，`leave` 做了两件事：

1. `mov rsp, rbp` —— 把栈顶指针 rsp 设成 rbp 的值。
2. `pop rbp` —— 从栈顶弹一个值给 rbp。

**攻击点**：如果我们能控制 `rbp` 的值（通过栈溢出覆盖旧 rbp），那么在 `leave` 时，`rsp` 就会被设成我们伪造的 rbp——**栈"瞬间移动"到了我们指定的地方！**

游戏比喻：`rbp` 是"战桌的坐标牌"，你偷偷把坐标牌换成仓库的地址，`leave` 时管理员就把战场搬到了仓库。

### 3. 完整攻击流程

假设我们想把栈迁到 `.bss` 段的一块可写缓冲区 `target`（地址已知，因为非 PIE）：

**第一步：把 ROP 链提前放到 target**

这可能需要程序本身的某个写入功能（比如它让你往全局数组写东西）。

**第二步：溢出覆盖 rbp 和返回地址**

```python
payload  = b'A' * offset_to_rbp   # 填满buf到rbp
payload += p64(target)            # 伪造 rbp = target（新战场坐标）
payload += p64(leave_ret_addr)    # 返回地址 = leave; ret 指令的地址
```

**第三步：程序收尾时发生的事**

```
函数结尾执行 leave; ret：
  ① mov rsp, rbp    → rsp = target（栈搬到 target）
  ② pop rbp         → 从 target 弹一个值（ target 处的内容）
  ③ ret             → 从 target+8 弹出地址，跳过去
```

所以你在 `target` 处的布局要这样安排：

```
target  →  ┌──────────────────┐
           │  伪造的 rbp 值     │ ← 被 pop 掉
           ├──────────────────┤
           │  ROP gadget1 地址  │ ← ret 跳这里
           ├──────────────────┤
           │  ROP gadget2 地址  │
           ├──────────────────┤
           │  ...              │
           └──────────────────┘
```

### 4. 找 leave; ret

```bash
ROPgadget --binary ./vuln | grep "leave ; ret"
# 或者用函数末尾自带的 leave; ret（如 main 结尾）
```

### 5. 另一种迁移：xchg rax, rsp

除了改 rbp，还有别的"搬家"指令：

- `xchg rax, rsp`：把 rax 和 rsp 交换。
- `mov rsp, rax`：直接把 rax 设给 rsp。

配合能控制 rax 的 gadget（如 `pop rax; ret`），也能实现栈迁移。这类 gadget 叫 **stack pivot gadget**，ROPgadget 可以用 `--search "rsp"` 找。

## 🔧 真实世界对照

| 游戏说法 | 真实术语 |
| --- | --- |
| 移形换影 | 栈迁移 / stack pivot |
| 战桌坐标牌 | rbp（栈基址） |
| 仓库 | 已知可写地址（.bss） |
| 搬家指令 | `leave; ret` / `xchg rax, rsp` |

**栈迁移的本质**：**控制 rsp**。因为 ret 总是从 rsp 指向的地方取地址，所以只要让 rsp 指向我们布置好 ROP 链的地方，就能接管程序流程。这与"覆盖返回地址"是殊途同归——都是控制 rip。

## 🎯 闯关任务：用 .bss 当新战场

程序：

```c
// pivot.c
char target[64];   // 全局缓冲区，在.bss，地址固定（非PIE）
void vuln() {
    char buf[16];
    read(0, buf, 100);   // 栈溢出
}
int main(){
    read(0, target, 64); // 可以往target写东西
    vuln();
}
```

```bash
gcc -g -O0 -fno-stack-protector -no-pie pivot.c -o pivot
```

任务步骤：

1. 用 `nm pivot | grep target` 找到 target 地址。
2. 第一轮输入：把 ROP 链（`pop rdi; /bin/sh; system`）写到 `target+8` 开始处（前面 8 字节放伪造 rbp）。
3. 第二轮输入：栈溢出，覆盖 rbp 为 `target`，返回地址为 `leave; ret`。
4. 观察程序是否成功"搬栈"并执行你的链。

这个任务有点难，但打通它，你对栈的理解会上升一个维度。

**第 14 关 · printf 嘴瓢：格式化字符串漏洞**

如果游戏里有个 NPC，你说什么它都照抄，但当你说"帮我喊出第 5 个玩家的血量"时，它居然真的去喊了——这就是**格式化字符串漏洞**。

`printf(user_input)` 让用户输入直接当格式串，导致 `%p` 能泄露栈上任意值、`%n` 能往任意地址写。我们将学会这种"用话术操控游戏"的黑魔法。
