# 第 4 关 · 栈：叠盘子与回城卷轴

## 🎬 游戏开场

想象你在一个自助餐厅，桌上有一根柱子，专门用来**叠盘子**。

规则很简单：

- 有新任务（函数调用）来了，就往柱子顶上**放一个新盘子**（push）。
- 任务做完了，就从柱子顶上**拿走盘子**（pop）。
- **只能从顶上拿**——你不能抽中间的盘子。这叫后进先出（LIFO: Last In First Out）。

每个盘子代表一次函数调用，盘子上写着这次任务的**私人物品**（局部变量）。而每个盘子的最底部，压着一张**回城卷轴（返回地址）**——写着"这个任务做完后，回到哪个任务继续"。

这就是**栈（stack）**。它是 PWN 世界的主战场，一半以上的经典漏洞都发生在这里。

---

## 🧠 核心概念（游戏版）

### 1. 栈的方向：往低地址长

游戏里有个违反直觉的设定：栈这根柱子是**倒着长的**——新盘子放在**更低的门牌号**上。

```
高地址  0xffff0000  ┌──────────────┐  ← 栈底（老盘子在这）
                    │   main的盘子  │
                    ├──────────────┤
                    │   func的盘子  │
                    ├──────────────┤
低地址  0xfffeff00  │  下一个盘子   │  ← 栈顶（rsp 指这里）
          ↑         └──────────────┘
       新盘子往这个方向长
```

- `rsp`（栈顶指针）永远指向**最新盘子的顶**。
- 新任务来了：`rsp` 减小（往低地址走），腾出空间放盘子。
- 任务结束：`rsp` 增大（往高地址走），盘子被丢弃。

### 2. 栈帧 = 一个任务的私人盘子

每次调用函数，会在栈上形成一个**栈帧（stack frame）**，里面装着：

```
高地址
  ┌─────────────────┐
  │ 调用者的栈帧     │
  ├─────────────────┤
  │ 返回地址         │ ← 关键！call 指令压进来的"回城卷轴"
  ├─────────────────┤
  │ 旧的 rbp         │ ← 上一个底座（保存现场）
  ├─────────────────┤  ← rbp 指向这里（当前底座）
  │ 局部变量1        │  ← 比如 char buf[16]
  │ 局部变量2        │
  ├─────────────────┤  ← rsp 指向这里（栈顶）
低地址
```

**两个关键角色**：

- `rbp`（栈基址）：像任务的"底座"，固定不动，用来定位局部变量（`[rbp-0x10]` 之类的）。
- `rsp`（栈顶）：像"current 手指"，随着压栈出栈上下移动。

### 3. 回城卷轴（返回地址）的来历

第 3 关说过，`call` 指令做两件事：

1. 把"下一条指令的地址"（返回地址）压到栈上。
2. 跳到被调函数。

被调函数干完活后 `ret` 指令做一件事：

> **从栈顶弹出一个值，跳过去执行。**

正常情况下，弹出的就是 `call` 当初压进去的返回地址，程序正常返回。

**但你想到了什么？**

> 如果我能在函数运行期间，改写栈上那个返回地址……

**那么 `ret` 就会跳到我指定的地方！** 这就是栈溢出的全部魔法。

### 4. 函数调用的完整剧本

用 `add(2, 3)` 举例，栈上发生的事：

```
main 调用 add 之前：
  栈上只有 main 的盘子

执行 call add：
  ① 压栈：返回地址（main 里 call 之后那条指令的地址）
  ② 跳到 add

add 内部：
  ③ push rbp       → 保存 main 的底座
  ④ mov rbp, rsp   → 建立 add 的底座
  ⑤ sub rsp, 0x20  → 给局部变量腾出 32 字节空间

add 结束：
  ⑥ mov rsp, rbp   → 收回局部变量空间
  ⑦ pop rbp        → 恢复 main 的底座
  ⑧ ret            → 弹出返回地址，跳回 main
```

第 ⑥⑦⑧ 步通常被编译器写成一条 `leave` + `ret`。**记住 `leave; ret` 这个组合**，它后面会反复出现。

## 🔧 真实世界对照

| 游戏说法 | 真实术语 |
| --- | --- |
| 盘子柱 | 栈（stack） |
| 盘子 | 栈帧（stack frame） |
| 回城卷轴 | 返回地址（return address） |
| 底座 | 栈基址寄存器 `rbp` |
| 柱顶手指 | 栈顶指针 `rsp` |
| 往低地址长 | 栈向低地址生长 |
| 后进先出 | LIFO |

**补充**：现代程序常用 `-fomit-frame-pointer` 优化，不再用 `rbp` 当底座，而是直接用 `rsp` 定位局部变量。但对新手来说，理解 `rbp` 版本更直观，我们后面也主要用这个模型。

## 🎯 闯关任务：亲眼看看栈

写个程序，打印局部变量和返回地址的位置关系：

```c
// stack.c
#include <stdio.h>
void func() {
    char buf[16];
    long *ret;
    printf("buf 地址:  %p\n", buf);
    ret = (long*)(buf + 24);   // 大概的位置（因编译器而异）
    printf("返回地址:  %p\n", *ret);
}
int main() { func(); return 0; }
```

编译运行：

```bash
gcc -O0 -g -fno-stack-protector stack.c -o stack
./stack
```

你会看到 buf 的地址和返回地址的地址相差不远——它们在同一根盘子柱上。

用 gdb 看得更清楚：

```bash
gdb ./stack
(gdb) break func
(gdb) run
(gdb) info frame          # 查看栈帧信息
(gdb) x/20gx $rsp         # 以十六进制查看栈顶开始的20个8字节
```

在输出里找 `0x000000000040....` 这样的值——那就是返回地址（代码段地址）。记住它的位置。

> **思考题**：如果 `buf` 是 `gets(buf)` 读入的，而我输入超过 16 字节，会发生什么？\
> 答案是：数据会一路往高地址写，覆盖 rbp、**覆盖返回地址**。这就是下一大关的起点。

## 📌 本关小结

| 你学会了 | 一句话记忆 |
| --- | --- |
| 栈 | 倒着长的盘子柱，后进先出 |
| 栈帧 | 一次函数的私人盘子 |
| 返回地址 | 压在盘子底部的回城卷轴 |
| rbp / rsp | 底座 / 柱顶手指 |
| ret | 弹栈顶跳过去执行 |

**核心伏笔**：栈溢出的本质是——**局部变量和返回地址住在同一根柱子（栈）上，而且局部变量的写法可以往上蔓延**。只要输入够长，就能涂改回城卷轴。
