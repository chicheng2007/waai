# 第 16 关 · 堆：城市储物柜租赁系统

## 🎬 游戏开场

在栈上,你只能叠盘子——后进先出,规规矩矩。但游戏里还有一片更自由的区域:**储物柜中心**,也就是**堆(heap)**。

这里没有"只能从顶上拿"的规矩。你可以:

- 随时租一个柜子(`malloc`)
- 用完后退租(`free`)
- 先退后面的柜子,再退前面的——随便

就像一个自助储物柜大厅:墙上无数格子,你刷卡租一格,存东西,用完了退卡。系统负责记录哪些格子空着、哪些被占用。

**堆利用,就是想办法骗这个租赁系统**——比如退租后偷偷留着钥匙、把同一个柜子退租两次、或者骗管理员把柜子租到不该租的地方。

这一关,我们先认识这个系统的基本规则。

---

## 🧠 核心概念(游戏版)

### 1. 堆是什么?

**堆**是程序运行时,向系统申请的一大片内存区域。和栈的区别:

| | 栈(stack) | 堆(heap) |
| --- | --- | --- |
| 管理方式 | 系统自动分配释放 | 程序员手动 malloc/free |
| 生长方向 | 往低地址 | 往高地址 |
| 生命周期 | 函数结束就回收 | 直到 free 或程序结束 |
| 灵活性 | 后进先出,死板 | 随便租随便退 |

游戏比喻:栈是"自助餐盘子柱",堆是"储物柜大厅"。

### 2. malloc 和 free:租赁管理员

```c
char *p = malloc(32);   // 租一个32字节的柜子,返回柜子地址(钥匙)
strcpy(p, "hello");     // 往柜子里存东西
free(p);                // 退租
```

- `malloc(size)`:系统找一块合适的空闲内存,标记为占用,返回它的地址。
- `free(ptr)`:把这块内存标记为空闲,还回"回收系统"。

**关键**:`free` 之后,`p` 这个指针还指向原来的地址——但那个柜子已经不属于你了!这就是后面 UAF 漏洞的根源。

### 3. 堆在内存里的位置

```
高地址
  ┌──────────────┐
  │    栈         │ ← 往低地址长
  ├──────────────┤
  │     ...      │
  ├──────────────┤
  │    堆         │ ← 往高地址长（brk）
  ├──────────────┤
  │  .bss/.data  │ ← 全局变量
  ├──────────────┤
  │  .text       │ ← 代码
  └──────────────┘
低地址
```

堆的起始位置叫 **brk**,程序通过移动 brk 向系统"要地"。

### 4. chunk:柜子的标签头

系统管理堆时,把内存切成一块块,每块叫 **chunk(块)**。每个 chunk 长这样:

```
  ┌──────────────────┐
  │ prev_size        │ ← 前一个chunk的大小(某些情况用)
  ├──────────────────┤
  │ size             │ ← 本chunk的大小 + 标志位
  ├──────────────────┤  ← 从这里开始是用户数据（mem指针指这）
  │ 用户数据区        │ ← malloc 返回的地址指向这里
  │ (chunk头之后的)   │
  └──────────────────┘
```

**游戏比喻**:每个柜子前面挂着一个**标签牌**(chunk头),写着"这个柜子多大、前一个柜子多大"。你租到的"钥匙"(malloc返回值)其实指向柜子内部,标签牌在钥匙指向位置的前面。

为什么重要?因为堆利用的很多技巧就是**篡改标签牌上的数字**,骗系统做出错误判断。

### 5. 谁在管理?ptmalloc/glibc

Linux 上,堆管理器是 **glibc 的 ptmalloc**。它维护一套复杂的"空闲柜子登记表"(bin),决定:

- 你 malloc 时,从哪个回收箱里找柜子给你
- 你 free 时,把柜子放到哪个回收箱

不同版本的 glibc,规则不一样——这就是进阶版要深入研究的。基础版我们先记住这套系统的**大致逻辑**,具体的 bin 分类下一关讲。

| 游戏说法 | 真实术语 |
| --- | --- |
| 储物柜中心 | 堆(heap) |
| 租柜子 | malloc() |
| 退租 | free() |
| 钥匙 | 返回的指针 |
| 柜子标签牌 | chunk header |

## 🎯 闯关任务:观察堆的增长

写程序:

```c
// heap.c
#include <stdio.h>
#include <stdlib.h>
int main() {
    char *a = malloc(32);
    char *b = malloc(32);
    printf("a = %p\nb = %p\n", a, b);
    printf("差值 = %ld\n", b - a);
    free(a);
    free(b);
}
```

```bash
gcc -g heap.c -o heap
./heap
```

观察:
1. 两次 malloc 的地址差多少?(通常是 0x20 = 32 字节,说明连续分配)
2. 用 gdb 在 free 前后查看那块内存,看看 free 之后里面被写了什么(会出现一些指针——这就是回收系统的线索,下一关讲)。
