# 第 10 章 真实比赛堆题复盘

> 这一章复盘一道典型的 glibc 2.35 堆题，展示从审计到 getshell 的完整思路。

---

## 10.1 题目描述

程序是一个笔记管理系统，功能：

- `add(idx, size, content)`：分配笔记
- `delete(idx)`：删除笔记（UAF：指针不清零）
- `edit(idx, content)`：编辑笔记
- `show(idx)`：查看笔记

保护：Full RELRO、Canary、NX、PIE。glibc 2.35（无 hooks）。

---

## 10.2 审计过程

```bash
checksec ./chall
# Full RELRO, Canary, NX, PIE

./libc.so.6
# GNU C Library (Ubuntu GLIBC 2.35-0ubuntu3.1)
```

**关键发现**：

1. delete 后指针不清零 → UAF
2. edit 可以修改已释放的 chunk → tcache poisoning / fd 控制
3. show 可以读取已释放的 chunk → 泄露
4. Full RELRO → GOT 不可写
5. glibc 2.35 → hooks 被移除 → 需要 IO_FILE 利用

---

## 10.3 利用思路

```text
1. 泄露 libc：分配大块 → free → unsorted bin leak
2. 泄露堆地址：tcache 结构的 fd 经过 safe-linking 编码，需要堆地址解码
3. tcache poisoning：修改 fd → 分配到 _IO_2_1_stdout_ 附近
4. IO_FILE 利用：House of Apple → getshell
```

### 10.3.1 关键点：安全链接的绕过

glibc 2.35 的 fd 经过 safe-linking 编码，伪造 fd 需要知道 chunk 地址：

```python
# 泄露堆地址
# 方法：UAF 读 tcache chunk 的 fd，解码得到另一个 chunk 的地址
# 或者利用 unsorted bin chunk 的 fd（指向 main_arena，泄露 libc 后推算堆）

fake_fd = (chunk_user_addr >> 12) ^ target_addr
```

## 10.5 解题思路总结

面对 glibc 2.35 的堆题，标准思路：

```text
1. 信息泄露（libc + heap）— 这是 safe-linking 时代必须的
2. tcache poisoning 到 IO_FILE 结构
3. House of Apple 构造
4. 触发 exit → getshell
```

**与 2.31 的区别**：目标从 `__free_hook` 变成了 IO_FILE；多了 safe-linking 的编码步骤。
