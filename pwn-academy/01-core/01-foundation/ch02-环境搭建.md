# 第 2 章 搭建你的第一次犯罪现场：环境配置

> 工欲善其事，必先利其器。这一章我们不讲任何漏洞原理，只做一件事：把一个顺手的 PWN 实验环境搭起来。

---

## 2.1 先选一个战场

PWN 实验对操作系统有要求——绝大多数工具链和漏洞利用技术都是围绕 Linux 设计的，所以我们的主场是 Linux。你有三种选择：

| 方案 | 优点 | 缺点 | 适合谁 |
| --- | --- | --- | --- |
| 虚拟机（VirtualBox / VMware） | 隔离性好，随便折腾不怕搞坏系统 | 占用资源较多，性能略差 | **新手首选** |
| WSL（Windows Subsystem for Linux） | 性能好，和 Windows 无缝切换 | 部分底层功能受限，调试体验略差 | Windows 用户 |
| 物理机装 Linux | 性能最好 | 需要单独设备或双系统 | 进阶用户 |

本教程以**虚拟机 + Ubuntu 22.04** 为例。如果你用 WSL，命令基本通用，只是某些涉及内核的操作（比如加载内核模块）会有限制，后面遇到时我会单独说明。

> 💡 **提示**：为什么选 Ubuntu 22.04？因为它的软件源丰富、教程资料多、glibc 版本（2.35）是目前 CTF 题目的主流版本之一。如果你之后想复现老题目的环境，可以用 Docker 或安装 Ubuntu 20.04（glibc 2.31）。

---

## 2.2 安装虚拟机

如果你已经装好了虚拟机，可以跳过这一节。

**第一步：下载虚拟机软件**

- VirtualBox（免费）：https://www.virtualbox.org/
- VMware Workstation Player（免费用于个人）：https://www.vmware.com/

两者都可以，VirtualBox 更轻量，VMware 的性能和快照功能更强。选一个你顺眼的。

**第二步：下载 Ubuntu 镜像**

到 Ubuntu 官网（https://ubuntu.com/download/desktop）下载 22.04 LTS 的 ISO 镜像。

**第三步：创建虚拟机**

在虚拟机软件里新建一个虚拟机，建议配置：

- **内存**：至少 4GB（推荐 8GB）
- **硬盘**：至少 40GB
- **CPU**：2 核以上
- **网络**：NAT 或桥接（保证能上网）

然后挂载 ISO 镜像，启动虚拟机，按提示完成 Ubuntu 安装。

安装完成后，先做两件事：

```bash
# 更新软件源
sudo apt update && sudo apt upgrade -y
```

以及把系统语言设成英文（可选，但可以避免一些编码问题）——当然如果你喜欢中文界面也没问题。

## 2.3 安装编译与调试基础工具

打开终端（Ctrl+Alt+T），依次执行：

```bash
# 基础编译工具（gcc、make 等）
sudo apt install -y build-essential

# gdb 调试器
sudo apt install -y gdb

# Python 3 与 pip
sudo apt install -y python3 python3-pip python3-dev

# git 与常用工具
sudo apt install -y git wget curl vim net-tools

# 32 位程序运行支持（重要！很多题目是 32 位的）
sudo apt install -y libc6:i386 libncurses5:i386 libstdc++6:i386
```

最后那条 `libc6:i386` 千万别忘了装，否则你运行 32 位程序时会遇到「No such file or directory」这种莫名其妙的错误。

验证一下：

```bash
gcc --version
gdb --version
python3 --version
```

都能正常输出版本号就 OK。

---

## 2.4 安装 pwntools

**pwntools** 是 CTF PWN 方向的「瑞士军刀」，是 Python 的一个库，用来写利用脚本（exp）。没有它，你写 exp 的效率会低十倍。

安装方法：

```bash
sudo pip3 install pwntools
```

> ⚠️ **注意**：如果提示 pip 版本过旧，先执行 `sudo pip3 install --upgrade pip`。如果安装过程中出现编译错误，可能是缺少 Python 开发头文件，执行 `sudo apt install python3-dev` 后再试。

验证安装：

```bash
python3 -c "from pwn import *; print(pwnlib.__version__)"
```

能输出版本号（比如 `4.11.0`）就成功了。

pwntools 我们会在第六篇专门讲，这里你只需要知道它是干什么的、怎么装好。

---

## 2.5 安装 gdb 调试插件：pwndbg

原生的 gdb 对 PWN 来说太难用了——你不想每次都手动输入 `x/20gx $rsp` 来看栈内容。所以我们需要一个调试插件，让 gdb 能「开挂」。

主流插件有 **pwndbg** 和 **gef** 两个，功能类似，选一个即可。这里以 pwndbg 为例。

```bash
# 克隆仓库
git clone https://github.com/pwndbg/pwndbg ~/pwndbg

# 进入目录并安装
cd ~/pwndbg
./setup.sh
```

安装脚本会自动把配置写入 `~/.gdbinit`。安装完成后，启动 gdb 时会自动加载 pwndbg：

```bash
gdb
```

如果看到这样的启动信息，说明成功了：

```
pwndbg: loaded 171 commands. Type pwndbg [filter] for a list.
pwndbg: created $rebase, $ida gdb functions (can be used with print/break)
pwndbg>
```

pwndbg 常用命令预览（后面会详细讲）：

- `checksec`：查看程序保护机制
- `stack`：查看栈内容
- `heap`：查看堆块信息
- `x/20gx 地址`：以 8 字节为单位查看内存
- `disassemble`：反汇编当前函数

如果 `./setup.sh` 因为网络问题失败，可以手动安装：

```bash
cd ~/pwndbg
python3 -m pip install -r requirements.txt
echo "source ~/pwndbg/gdbinit.py" >> ~/.gdbinit
```

## 2.6 其他趁手的工具

再装几个常用工具：

```bash
# checksec：检查二进制保护机制（pwndbg 自带，但独立版也装一个）
sudo apt install -y checksec

# ROPgadget：寻找 ROP gadget
sudo pip3 install ropgadget

# ropper：另一个找 gadget 的工具
sudo pip3 install ropper

# one_gadget：找 libc 中的一键 getshell 地址（需要 Ruby）
sudo apt install -y ruby ruby-dev
sudo gem install one_gadget

# seccomp-tools：分析 seccomp 沙箱规则
sudo gem install seccomp-tools
```

验证：

```bash
checksec --version
ROPgadget --version
one_gadget --help
```

如果某些工具因为网络问题装不上，不用着急，用到时再装即可。教程会在首次使用某个工具时给出安装说明。

## 2.7 编译你的第一个漏洞程序

现在，让我们写一个最简单的程序，感受一下「有漏洞」的程序长什么样。

创建一个文件 `vuln.c`：

```c
#include <stdio.h>

void vulnerable() {
    char buf[64];
    gets(buf);          // 危险！gets 不检查输入长度
    printf("You said: %s\n", buf);
}

int main() {
    vulnerable();
    return 0;
}
```

这个程序用了 `gets()` 读取用户输入，而 `gets()` 不会检查输入是否超过 `buf` 的 64 字节——这就是经典的**栈溢出漏洞**。

编译时我们故意关闭所有保护，方便练习：

```bash
# 编译 64 位版本（关闭 Canary、栈不可执行、PIE）
gcc -g -O0 -fno-stack-protector -z execstack -no-pie -o vuln64 vuln.c

# 编译 32 位版本
gcc -m32 -g -O0 -fno-stack-protector -z execstack -no-pie -o vuln32 vuln.c
```

参数解释：

- `-g`：加入调试符号，方便 gdb 调试
- `-O0`：关闭优化，让汇编代码和 C 代码一一对应
- `-fno-stack-protector`：关闭 Canary（栈保护）
- `-z execstack`：让栈可执行（允许在栈上运行 shellcode）
- `-no-pie`：关闭 PIE（地址随机化）

运行一下：

```bash
./vuln64
```

输入 `hello`，它会回显 `You said: hello`。

现在输入 100 个 `A`：

```bash
python3 -c "print('A'*100)" | ./vuln64
```

程序会输出一行 `You said: AAAA...`，然后——Segmentation fault（段错误）。恭喜，你刚刚**利用**了一个栈溢出漏洞（虽然只是让它崩溃，但这正是利用的第一步）。

用 checksec 看看它的保护情况：

```bash
checksec --file=vuln64
```

你会看到类似这样的输出：

```
RELRO:    Partial RELRO
Stack:    No canary found
NX:       NX disabled
PIE:      No PIE
```

这就是我们故意制造的「新手村」程序：一点防护都没有。

## 2.8 关闭 ASLR

还有一件事：Linux 系统默认开启 **ASLR（地址空间布局随机化）**，它会让程序每次运行时栈地址、libc 地址都不同。对新手来说，这会让调试变得困难（你看到的地址和实际运行的地址对不上）。

在开发/学习环境里，可以临时关闭 ASLR：

```bash
# 查看当前状态（2 = 完全开启）
cat /proc/sys/kernel/randomize_va_space

# 关闭 ASLR（需要 root）
sudo sysctl -w kernel.randomize_va_space=0

# 恢复开启
sudo sysctl -w kernel.randomize_va_space=2
```

> ⚠️ **注意**：关闭 ASLR 只是为了方便学习。CTF 比赛的远程环境一定是开启 ASLR 的，所以从栈篇中期开始，我们会学习在 ASLR 开启的情况下如何泄露地址。别养成依赖关闭 ASLR 的习惯。

## 2.9 环境检查清单

在开始后面的学习前，请确认以下几点：

- [ ] gcc 能编译 32 位和 64 位程序
- [ ] gdb 启动后能看到 pwndbg 的提示
- [ ] `python3 -c "from pwn import *"` 不报错
- [ ] checksec、ROPgadget 能正常运行
- [ ] 关闭了 ASLR（学习阶段）
- [ ] `vuln64` 程序能编译并运行，输入超长字符串会崩溃

全部打勾，你的「犯罪现场」就布置好了。
