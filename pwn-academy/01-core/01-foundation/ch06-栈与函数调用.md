# 第 6 章 栈与函数调用的真相

> 栈溢出为什么能覆盖返回地址？偏移量到底怎么算？要回答这些问题，你必须对函数调用时栈上发生的每一个字节了如指掌。这一章，我们就用 gdb 把栈「解剖」给你看。

---

## 6.1 栈是什么

**栈（Stack）** 是内存中一块特殊的区域，用来支持函数调用。它的特点是「后进先出」（LIFO, Last In First Out）——最后压入的数据最先弹出。

栈在内存中**向低地址方向生长**：

```text
高地址  0x7fffffffe000  ┌──────────────┐
                        │   已用空间    │
                        ├──────────────┤  ← rsp 指向这里（栈顶）
                        │   未用空间    │
低地址  0x7ffff0000000  └──────────────┘
```

当你执行 `push` 时，rsp **减小**（栈顶向低地址移动）；执行 `pop` 时，rsp **增大**。

> ⚠️ **注意**：很多人会搞混栈的生长方向和数组的增长方向。数组从低地址向高地址写（`buf[0]` 在低地址，`buf[63]` 在高地址），而栈向低地址生长。当一个数组溢出时，多出来的数据会**向高地址**写，正好覆盖栈上位于它「上方」的返回地址。记住这个画面。

### 栈里都存什么

- 函数的返回地址
- 保存的寄存器（如 rbp）
- 局部变量
- 函数参数（超过 6 个时）
- 临时数据、对齐填充

---

## 6.2 栈帧：一次调用的完整单元

每当函数被调用时，会在栈上分配一块专属区域，叫做**栈帧（Stack Frame）**。栈帧由 `rbp`（基址指针）和 `rsp`（栈指针）界定：

```text
          高地址
    ┌─────────────────┐
    │  调用者的栈帧    │
    ├─────────────────┤
    │  返回地址        │ ← [rbp+8]
    ├─────────────────┤
    │  保存的 rbp      │ ← [rbp]   当前函数栈帧底部
    ├─────────────────┤
    │  局部变量 1      │ ← [rbp-8]
    ├─────────────────┤
    │  局部变量 2      │ ← [rbp-16]
    ├─────────────────┤
    │  临时空间/对齐   │ ← rsp
    └─────────────────┘
          低地址
```

**关键关系**：

- `rbp` 指向栈帧底部（高地址端），在函数体内保持不变
- `rsp` 指向栈顶（低地址端），会随 push/pop 变化
- 局部变量通过 `[rbp - 偏移]` 访问
- **返回地址在 `[rbp + 8]`**（64 位下 8 字节）
- **调用者的 rbp 在 `[rbp]`**

这也解释了为什么覆盖返回地址需要「填充到 rbp + 8」——你要先填满局部变量，再填满保存的 rbp，才能碰到返回地址。

## 6.3 call、ret 与 leave：三个关键指令

### 6.3.1 call 指令

```asm
callfunc 地址
```

`call` 做了两件事：

```text
1. 把「call 指令的下一条指令地址」（返回地址）压入栈
   → rsp -= 8; [rsp] = 返回地址
2. 跳转到目标函数（rip = 目标地址）
```

相当于：

```asm
push 返回地址
jmp 函数地址
```

### 6.3.2 ret 指令

```asm
ret
```

`ret` 做了两件事：

```text
1. 从栈顶弹出一个值到 rip
   → rip = [rsp]; rsp += 8
2. 程序从新的 rip 处继续执行
```

相当于：

```asm
pop rip
```

**这就是栈溢出的舞台**：如果我们在溢出时把栈顶的值改成了 `system` 的地址，那么 `ret` 就会让程序跳到 `system` 去执行。

### 6.3.3 leave 指令

```asm
leave
```

`leave` 是函数尾声的一部分，等价于：

```asm
mov rsp, rbp    ; 把栈顶恢复到栈帧底部
pop rbp         ; 弹出调用者的 rbp
```

执行完 `leave` 后，rsp 正好指向**返回地址**。紧接着的 `ret` 就会弹出返回地址并返回。

所以经典的栈溢出 payload 结构是：

```text
[ 填充数据 ][ 伪造的 rbp ][ 目标函数地址 ]
              ↑               ↑
           覆盖 [rbp]      覆盖 [rbp+8]（返回地址）
```

## 6.4 用 gdb 观察一次完整的函数调用

理论讲得再多，不如亲眼看一遍。我们用一段简单的代码来演示：

```c
// frame.c
#include <stdio.h>

int add(int a, int b) {
    int result = a + b;
    return result;
}

int main() {
    int x = add(3, 4);
    printf("result = %d\n", x);
    return 0;
}
```

编译并调试：

```bash
gcc -g -O0 -no-pie -o frame frame.c
gdb ./frame
```

在 gdb 里设置断点并单步：

```gdb
# 在 main 和 add 处下断点
break main
break add
run

# 单步执行（step into）
s
# 查看寄存器
info registers rsp rbp rip
# 查看栈内容
x/20gx $rsp
# 查看汇编
disassemble /r
```

你会观察到这样的过程：

**进入 main 后**：

```text
rsp = 0x7fffffffe100
rbp = 0x7fffffffe110
```

**call add 时**，返回地址被压栈：

```text
rsp = 0x7fffffffe0f8    （减小了 8）
[rsp] = 0x55555555516a  ← 返回地址（call 的下一条指令）
```

**进入 add 后**（执行 push rbp; mov rbp, rsp）：

```text
rsp = 0x7fffffffe0f0
rbp = 0x7fffffffe0f0    （新的栈帧）

栈布局：
0x7fffffffe0f0: [保存的 rbp]  ← rbp 指向这里
0x7fffffffe0f8: [返回地址]    ← rbp+8
0x7fffffffe100: [main 的 rbp]
0x7fffffffe108: [main 的返回地址]
```

**add 返回时**（leave; ret）：

```text
leave → rsp = rbp = 0x7fffffffe0f0; pop rbp → rsp = 0x7fffffffe0f8
ret   → rip = [0x7fffffffe0f8] = 返回地址; rsp = 0x7fffffffe100
```

回到了 main，栈也恢复原状。

> 🔥 **实战**：自己动手调试一遍。每次执行 `ni`（单步跳过）或 `si`（单步进入）后，用 `x/20gx $rsp` 观察栈的变化。用 `p $rsp` 和 `p $rbp` 看指针的变化。这种直观的感受比看十遍教程都有用。

## 6.5 局部变量与返回地址的位置关系

现在我们把栈溢出的画面补全。假设有这个函数：

```c
void vulnerable() {
    char buf[64];
    gets(buf);
}
```

栈布局（十六进制地址仅为示意）：

```text
高地址  0x7fffffffe120  ┌────────────────┐
                        │  调用者的栈帧   │
        0x7fffffffe118  ├────────────────┤
                        │  返回地址       │ ← 8 字节（64 位）
        0x7fffffffe110  ├────────────────┤
                        │  保存的 rbp     │ ← 8 字节
        0x7fffffffe108  ├────────────────┤
                        │  buf[63] ...   │
                        │  ...           │
        0x7fffffffe0c8  │  buf[0]        │ ← 64 字节
                        ├────────────────┤
        0x7fffffffe0c0  │  其他临时空间   │ ← rsp
低地址                  └────────────────┘
```

`gets(buf)` 从 `buf[0]`（低地址 `0x7fffffffe0c8`）开始写，向高地址方向填充。当输入超过 64 字节时：

1. 先覆盖 buf 本身的 64 字节
2. 再覆盖保存的 rbp（8 字节）
3. 再覆盖返回地址（8 字节）

所以偏移量（从 buf 起始到返回地址）= 64 + 8 = **72 字节**。

> ⚠️ **注意**：实际偏移不一定是 64 + 8！编译器可能会额外分配空间（对齐、对齐canary 等）。正确的做法是用 gdb 或 pwntools 的 cyclic 工具**实际测量**（第 8 章会讲）。

## 6.6 栈上还有哪些东西

除了上面提到的，栈帧里还可能有：

### 6.6.1 Canary（栈保护）

如果编译时开启 `-fstack-protector`，会在局部变量和保存的 rbp 之间插入一个随机的 Canary 值：

```text
[ 局部变量 ][ Canary ][ 保存的 rbp ][ 返回地址 ]
```

函数返回前会检查 Canary 是否被修改，如果被修改就调用 `__stack_chk_fail` 终止程序。这就是第 12 章要讲的内容。

### 6.6.2 栈对齐

x86-64 的 ABI 要求调用的函数入口处 rsp 必须是 16 字节对齐的。编译器有时会在栈上插入填充字节来满足这个要求。这就是为什么有时候你会看到 `sub rsp, 0x18` 而不是 `sub rsp, 0x10`。

### 6.6.3 超过 6 个的参数

x86-64 下前 6 个参数走寄存器，第 7 个及以后的参数放在调用者的栈上（返回地址之后）。

## 6.7 32 位与 64 位栈的差异

| 特性 | x86-64 | x86（32 位） |
| --- | --- | --- |
| 指针大小 | 8 字节 | 4 字节 |
| 参数传递 | 前 6 个走寄存器 | 全部走栈 |
| 返回地址大小 | 8 字节 | 4 字节 |
| 保存的 rbp/ebp | 8 字节 | 4 字节 |
| 常见栈地址 | `0x7ffff...` | `0xffffd...` |
| 指令 | `mov rax, [rbp-8]` | `mov eax, [ebp-4]` |

32 位下栈溢出的偏移量计算更简单（返回地址离 buf 更近），而且参数全在栈上，构造 ROP 链时不需要找 `pop rdi; ret` 这样的 gadget（因为参数直接压栈）。所以**新手可以从 32 位题入手**。

---

## 6.8 小结

这一章我们解剖了栈：

- **栈向低地址生长**，push 让 rsp 减小，pop 让 rsp 增大
- **栈帧**由 rbp（底部）和 rsp（顶部）界定，局部变量通过 `[rbp - offset]` 访问
- **返回地址在 `[rbp+8]`**（64 位），调用者的 rbp 在 `[rbp]`
- **call** = push 返回地址 + jmp；**ret** = pop rip；**leave** = mov rsp,rbp + pop rbp
- **栈溢出**就是覆盖局部变量之外的保存 rbp 和返回地址，从而控制 ret 的目标
- **Canary、栈对齐、额外参数**都会影响栈布局和偏移量计算
- **32 位和 64 位的栈**在指针大小、参数传递方式上有明显差异
