# 第 4 章 汇编基础：与机器对话

> 汇编语言看起来像天书，但它其实是所有语言里最「诚实」的——每条指令只做一件事，没有隐藏的魔法。学会了它，你就能看懂程序真正在做什么。

---

## 4.1 为什么 PWN 必须懂汇编

先说一个残酷的事实：**你在 CTF 比赛里拿到的 PWN 题，绝大多数没有源代码。** 你只有一个编译好的二进制文件。要知道程序在做什么、漏洞在哪里，你必须能读懂反汇编出来的代码。

而且，当你构造 ROP 链时，你需要找「gadget」——一小段以 `ret` 结尾的指令序列，比如 `pop rdi; ret`。如果你不懂汇编，你甚至不知道自己在找什么。

好消息是：**汇编比你想的简单。** x86-64 的常用指令就二三十条，寄存器就那么十几个。这一章结束后，你应该能读懂一个简单函数的反汇编代码。

---

## 4.2 x86-64 寄存器全景

寄存器是 CPU 内部的高速存储单元。你可以把它们理解成 CPU 的「随身小本本」，访问速度比内存快几百倍。

### 4.2.1 通用寄存器

x86-64 有 16 个 64 位通用寄存器：

| 寄存器 | 传统用途 | 在 PWN 中的意义 |
| --- | --- | --- |
| `rax` | 累加器，存放函数返回值 | 系统调用号也放这里 |
| `rbx` | 基址寄存器 | 常被用作通用存储 |
| `rcx` | 计数器 | 第 4 个参数 |
| `rdx` | 数据寄存器 | 第 3 个参数 |
| `rsi` | 源变址寄存器 | 第 2 个参数 |
| `rdi` | 目的变址寄存器 | **第 1 个参数（最重要！）** |
| `rbp` | 基址指针 | 指向当前栈帧的底部 |
| `rsp` | 栈指针 | **指向栈顶** |
| `r8` ~ `r15` | 扩展寄存器 | 第 5、6 个参数用 r8、r9 |

**务必记住这几个**：

- `rsp`：栈顶指针，push/pop 操作都会改变它
- `rbp`：栈帧基址，常用来定位局部变量
- `rdi`：第一个参数，`system("/bin/sh")` 时里面放的就是 `/bin/sh` 的地址
- `rax`：返回值和系统调用号

### 4.2.2 寄存器的不同宽度

同一个物理寄存器可以用不同的名字访问不同宽度：

```text
64 位:  rax
32 位:  eax      （只访问低 32 位）
16 位:  ax       （只访问低 16 位）
8 位:   al       （低 8 位）
8 位:   ah       （8~15 位，仅部分寄存器支持）
```

举例：

```asm
mov rax, 0x123456789abcdef0   ; rax = 0x123456789abcdef0
mov eax, 0x11111111           ; rax = 0x0000000011111111（高 32 位被清零！）
mov al, 0x22                  ; rax = 0x0000000011111122
```

> ⚠️ **注意**：往 32 位寄存器（如 eax）写入数据时，高 32 位会被**自动清零**。这是 x86-64 的一个规则，在构造 ROP 时经常会影响结果。

### 4.2.3 特殊寄存器

- **`rip`**：指令指针，指向下一条要执行的指令的地址。控制流劫持的本质就是修改 rip。
- **`eflags`**：标志寄存器，保存上一条指令的结果状态（零标志 ZF、进位标志 CF 等），条件跳转指令根据它决定要不要跳。

## 4.3 常见指令速查

### 4.3.1 数据传送

| 指令 | 作用 | 示例 |
| --- | --- | --- |
| `mov dst, src` | 把 src 复制到 dst | `mov rax, rbx` |
| `lea dst, [src]` | 取地址（load effective address） | `lea rdi, [rip+0x2e]` |
| `push src` | 压栈（rsp 减 8，然后写入） | `push rbp` |
| `pop dst` | 弹栈（读取，然后 rsp 加 8） | `pop rbp` |
| `xchg a, b` | 交换两个操作数 | `xchg rax, rbx` |

`mov` 和 `lea` 的区别经常让人困惑：

```asm
mov rax, [rbx]      ; 把 rbx 指向的内存里的内容加载到 rax
lea rax, [rbx]      ; 把 rbx 的值（地址）本身放到 rax
```

注意 Intel 语法里 `[]` 表示「取内存」，没有 `[]` 表示立即数或寄存器。

### 4.3.2 算术运算

| 指令 | 作用 | 示例 |
| --- | --- | --- |
| `add dst, src` | dst += src | `add rax, 1` |
| `sub dst, src` | dst -= src | `sub rsp, 0x40` |
| `mul src` | rax = rax × src | `mul rbx` |
| `div src` | rax ÷ src，商在 rax，余在 rdx | `div rbx` |
| `inc dst` | dst += 1 | `inc eax` |
| `dec dst` | dst -= 1 | `dec ecx` |
| `neg dst` | 取负 | `neg eax` |

### 4.3.3 逻辑运算

| 指令 | 作用 |
| --- | --- |
| `and dst, src` | 按位与 |
| `or dst, src` | 按位或 |
| `xor dst, src` | 按位异或（清寄存器常用 `xor eax, eax`） |
| `not dst` | 按位取反 |
| `shl dst, n` | 左移（等价于 ×2ⁿ） |
| `shr dst, n` | 右移 |

`xor eax, eax` 是汇编里最常见的清零方式，比 `mov eax, 0` 更短（机器码只有 2 字节），这在写 shellcode 时很重要。

### 4.3.4 比较与跳转

| 指令 | 作用 |
| --- | --- |
| `cmp a, b` | 比较 a 和 b（实质是 a - b，设置标志位） |
| `test a, b` | 按位与并设置标志位（常用于检查是否为 0） |
| `jmp label` | 无条件跳转 |
| `je / jz` | 相等 / 为零时跳转 |
| `jne / jnz` | 不相等 / 不为零时跳转 |
| `jg / jl` | 大于 / 小于时跳转（有符号） |
| `ja / jb` | 高于 / 低于时跳转（无符号） |
| `call label` | 调用函数（push 返回地址 + jmp） |
| `ret` | 返回（pop 到 rip） |

### 4.3.5 栈操作指令

```asm
push rax          ; rsp -= 8; [rsp] = rax
pop  rbx          ; rbx = [rsp]; rsp += 8
```

记住栈是**向低地址生长**的：push 时 rsp 减小，pop 时 rsp 增大。

## 4.4 函数调用的汇编视角

来看一个简单的函数：

```c
int add(int a, int b) {
    return a + b;
}

int main() {
    int result = add(3, 4);
    return result;
}
```

编译并反汇编：

```bash
gcc -g -O0 -no-pie -o add add.c
objdump -d -M intel add | less
```

你会看到类似这样的代码（简化后）：

```asm
<main>:
  push rbp                  ; 保存调用者的 rbp
  mov  rbp, rsp             ; 建立新栈帧
  sub  rsp, 0x10            ; 分配 16 字节局部变量空间
  mov  esi, 0x4             ; 第 2 个参数 b = 4
  mov  edi, 0x3             ; 第 1 个参数 a = 3
  call <add>                ; 调用 add，返回值在 eax
  mov  DWORD PTR [rbp-0x4], eax   ; result = eax
  mov  eax, DWORD PTR [rbp-0x4]   ; return result
  leave                     ; 销毁栈帧（等价于 mov rsp, rbp; pop rbp）
  ret                       ; 返回

<add>:
  push rbp
  mov  rbp, rsp
  mov  DWORD PTR [rbp-0x4], edi   ; a 存到栈上
  mov  DWORD PTR [rbp-0x8], esi   ; b 存到栈上
  mov  edx, DWORD PTR [rbp-0x4]   ; edx = a
  mov  eax, DWORD PTR [rbp-0x8]   ; eax = b
  add  eax, edx                   ; eax = a + b
  pop rbp
  ret
```

注意几点：

1. **参数传递**：`a` 在 `edi`，`b` 在 `esi`（32 位形式，因为 int 是 4 字节）
2. **返回值**在 `eax`
3. **栈帧**用 `push rbp; mov rbp, rsp` 建立，用 `leave` 销毁
4. 局部变量通过 `[rbp - 偏移]` 访问

这套「序言-尾声」（prologue-epilogue）是每个函数的标准结构，记住它：

```asm
; 函数序言
push rbp
mov  rbp, rsp
sub  rsp, N        ; N 是局部变量空间大小

; 函数体
...

; 函数尾声
leave
ret
```

## 4.5 寻址方式

理解指令中的操作数怎么写，是读懂汇编的关键：

```asm
mov rax, 0x1234              ; 立即数：rax = 0x1234
mov rax, rbx                 ; 寄存器：rax = rbx
mov rax, [0x601000]          ; 直接寻址：rax = 内存中 0x601000 处的值
mov rax, [rbx]               ; 间接寻址：rax = rbx 指向的内存的值
mov rax, [rbx+0x8]           ; 基址+偏移：rax = [rbx+8]
mov rax, [rbx+rcx*4]         ; 变址寻址：常用于数组访问
mov rax, [rip+0x2004]        ; RIP 相对寻址：访问全局变量/字符串
```

RIP 相对寻址在 64 位程序中非常常见（因为 PIE 的位置无关代码需要它），形式为 `[rip + offset]`，意思是「当前指令地址 + offset」。

## 4.6 手写一段 shellcode

现在来点好玩的：手写一个能在 Linux x86-64 上获得 shell 的机器码。

系统调用 `execve("/bin/sh", NULL, NULL)` 可以启动一个 shell。在 x86-64 中：

- 系统调用号放在 `rax`（execve 是 59，即 0x3b）
- 参数放在 `rdi`、`rsi`、`rdx`
- 执行 `syscall` 指令触发系统调用

问题是我们不能直接用字符串 `"/bin/sh"` 的地址（不知道它在哪里），所以常用的技巧是**把字符串压到栈上**：

```asm
; execve("/bin/sh", NULL, NULL) shellcode
; 注意：/bin/sh 的 8 字节表示为 0x68732f6e69622f（小端序）

xor   eax, eax           ; rax = 0
push  rax                ; 压入 8 字节 0（作为字符串结尾）

; 构造 "/bin/sh\0"：分两次压入（因为立即数只有 64 位，且不能包含 0）
mov   rbx, 0x68732f6e69622f   ; "/bin/sh" 的小端表示
push  rbx                ; 栈上现在有 "/bin/sh\0"

mov   rdi, rsp           ; rdi = 指向 "/bin/sh" 的指针
push  rax                ; rax = 0
push  rdi                ; 压入 "/bin/sh" 指针（argv[0]）
mov   rsi, rsp           ; rsi = argv 数组指针
xor   edx, edx           ; rdx = 0（envp = NULL）
mov   al, 0x3b           ; rax = 59（execve 的系统调用号）
syscall                  ; 执行系统调用
```

对应的机器码（shellcode）可以用 nasm 编译并用 `objdump` 提取，或者直接用 pwntools：

```python
from pwn import *
context.arch = 'amd64'
sc = asm(shellcraft.amd64.linux.sh())
print(sc.hex())
```

输出大概是：

```
6a3b58994882f3ff57150f0687a31d231f6567a5a8f
```

（不同版本的 pwntools 生成的 shellcode 可能略有不同）

**为什么需要手写 shellcode？** 因为有些题目会用 seccomp 禁用 `execve`，这时你需要手写 ORW（open/read/write）shellcode 来读 flag；有些题目栈不可执行，你需要用 ROP 来实现同样的功能。这些都会在后面讲。

> 🔥 **实战**：用 `gcc -z execstack` 编译第二章的 `vuln.c`，尝试把这段 shellcode 作为输入发送，看看能不能拿到一个 shell。提示：需要精确计算偏移量，这会在第 8 章讲。现在先感受一下「输入一段字节就能获得 shell」的震撼。

## 4.7 小结

这一章我们讲了汇编的骨架：

- **寄存器**：rax（返回值/系统调用号）、rdi/rsi/rdx（前三个参数）、rsp（栈顶）、rbp（栈帧基址）、rip（指令指针）
- **指令**：mov/lea/push/pop、算术运算、逻辑运算、cmp/test + 跳转、call/ret
- **函数调用**：参数走寄存器（x86-64），返回值在 rax，栈帧用 push rbp / mov rbp, rsp 建立
- **寻址方式**：立即数、寄存器、直接/间接寻址、RIP 相对寻址
- **shellcode**：把 `/bin/sh` 压栈，设置参数，执行 execve 系统调用

汇编不需要死记硬背。建议把本章的示例代码自己敲一遍，用 objdump 反汇编，对照着看。看多了自然就熟了。
