# 第 14 章 格式化字符串漏洞原理

> 一个看起来无害的 `printf(user_input)`，泄漏整个进程的内存、改写任意地址。格式化字符串漏洞是「信息泄露之王」，也是很多复杂利用的第一步。

---

## 14.1 本章目标

读完本章，你将理解：

- printf 家族的可变参数是怎么工作的
- 为什么 `printf(user_input)` 是漏洞
- `%n` 格式符为什么危险
- x86-64 下格式化字符串的参数布局

## 14.2 printf 的可变参数机制

`printf` 的函数原型是：

```c
int printf(const char *format, ...);
```

第一个参数是**格式字符串**，后面的 `...` 是**可变数量的参数**。printf 会解析格式字符串里的格式符（`%d`、`%s`、`%x` 等），按顺序取出后面的参数，格式化后输出。

```c
printf("Hello %s, you are %d years old\n", name, age);
//       ^^^^               ^^
//       第1个格式符        第2个格式符
//       取第1个参数 name    取第2个参数 age
```

**关键问题**：printf 怎么知道有多少个参数、每个参数的类型？答案是——**它不知道**。printf 完全依赖格式字符串里的格式符数量来决定读几个参数。

```c
printf("Hello %s, you are %d years old\n");  // 没有提供参数！
// printf 会从栈上/寄存器里「随便」取两个值当作 name 和 age
```

这就是漏洞的根源：**当格式字符串由用户控制时，用户可以决定 printf 读多少数据、按什么类型读**。

## 14.3 漏洞的成因

看这段代码：

```c
void vulnerable() {
    char buf[100];
    scanf("%s", buf);
    printf(buf);           // 漏洞！格式字符串是用户控制的
}
```

用户输入的 `buf` 直接作为 printf 的格式字符串。如果用户输入：

```text
%p %p %p %p
```

printf 会把 `%p` 解释为「打印一个指针」，然后依次取出后面的参数（实际上并不存在的参数）并打印出来。这些「参数」来自哪里？来自 printf 调用时的寄存器和栈——也就是**栈上残留的数据**。

所以 `%p %p %p %p` 会打印出栈上的 4 个值——可能包括返回地址、Canary、libc 地址等敏感信息！

### 14.3.1 危险的格式符

| 格式符 | 含义 | 在漏洞利用中的作用 |
| --- | --- | --- |
| `%p` | 打印指针（地址） | 泄露栈地址、libc 地址、Canary |
| `%x` / `%Nx` | 打印十六进制整数 | 泄露内存值（32 位常用） |
| `%s` | 打印字符串 | 打印任意地址的内容（泄露内存） |
| `%n` | **把已输出字符数写入指针指向的地址** | **任意地址写** |
| `%c` | 打印字符 | 配合 `%n` 控制写入的数值 |

**`%n` 是最危险的**。它不输出数据，而是**写内存**：

```c
int count;
printf("abc%n", &count);   // count 被设置为 3（因为前面输出了 3 个字符）
```

`%n` 会把「到此为止已经输出的字符数」写入它对应的参数（一个指针）指向的地址。如果格式字符串是用户控制的，用户就能让 printf 往任意地址写数据——这是**任意地址写原语**，非常强大。

## 14.4 x86-64 下格式化字符串的参数布局

理解「printf 取的参数在哪里」是利用的关键。

在 x86-64（System V ABI）下，调用 printf 时：

- **rdi**：格式字符串的地址（第一个参数）
- **rsi, rdx, rcx, r8, r9**：第 2~6 个参数（如果有的话）
- **栈**：第 7 个及以后的参数

当格式字符串里有 `%p` 时，printf 按顺序取参数：

```text
第 1 个 %p → rsi
第 2 个 %p → rdx
第 3 个 %p → rcx
第 4 个 %p → r8
第 5 个 %p → r9
第 6 个 %p → [rsp]         ← 栈上第一个参数
第 7 个 %p → [rsp+8]
第 8 个 %p → [rsp+0x10]
...
```

**重要**：我们要泄露的栈上数据（返回地址、Canary 等）位于栈上，需要通过第 6 个及以后的 `%p` 才能访问到。

pwntools 有个便捷的方法：发送 `%p` 序列，观察输出。

```python
payload = b'|'.join([b'%' + str(i).encode() + b'$p' for i in range(1, 31)])
p.sendline(payload)
output = p.recvline()
# 输出：value1|value2|...|value30
```

`%N$p` 表示「打印第 N 个参数」（`$` 是位置参数语法）。这样能一次性看到前 30 个参数的值，从中识别出栈上敏感数据的位置。

### 14.4.1 确定偏移量

所谓「偏移量」，指的是**你要泄露的数据是 printf 的第几个参数**。

例如，如果栈上的 Canary 出现在输出的第 12 个值里，那么 Canary 的偏移量就是 12，用 `%12$p` 可以精确打印它。

偏移量还和输入缓冲区在栈上的位置有关。通常做法是：

1. 发送一个含有标记字符串的输入，比如 `AAAAAAAA`
2. 用 `%N$p` 遍历，找到输出中等于 `0x4141414141414141`（AAAA 的十六进制）的那个位置
3. 该位置就是偏移量的基准

```python
payload = b'AAAAAAAA'
for i in range(1, 40):
    p.sendline(payload + b'%' + str(i).encode() + b'$p')
    out = p.recvline()
    if b'41414141' in out:
        print(f'Found at offset {i}')
        break
```

## 14.5 格式化字符串利用的两种原语

### 14.5.1 信息泄露

用 `%N$p` / `%N$s` 读取内存：

```python
# 泄露第 8 个参数（栈上的值）
payload = b'%8$p'

# 泄露第 8 个参数指向的字符串（如果第 8 个参数是个指针）
payload = b'%8$s'
```

`%N$s` 的含义：把第 N 个参数当作指针，打印它指向的内存。如果第 N 个参数正好指向 GOT 表，就能打印出 GOT 表的内容（libc 地址）。

要读取指定地址的内容，需要先把目标地址放到栈上（作为输入的一部分），然后用 `%N$s` 指向它。

### 14.5.2 任意地址写

`%N$hn` 表示「把已输出字符数写入第 N 个参数指向的地址的**低 2 字节**」（`h` = half，2 字节；`hh` = 1 字节；不加 = 4 字节；`l` = 8 字节）。

构造任意写的步骤：

1. 把目标地址放在输入缓冲区里（栈上）
2. 确定目标地址在 printf 参数中的位置（偏移量）
3. 用 `%N$hn` 往那个地址写入指定数值

```python
from pwn import *

target_addr = 0x404020    # 要写的地址（比如 GOT 表项）
value = 0x1234            # 要写入的值

# 用 pwntools 一键生成
payload = fmtstr_payload(offset, {target_addr: value})
```

`fmtstr_payload` 会自动计算需要输出多少字符、用哪种宽度格式符（`%Nc`）来凑出目标值。

## 14.6 动手实验：看看栈上有什么

写一个简单的程序：

```c
// fmt.c
#include <stdio.h>

int secret = 0x12345678;

int main() {
    char buf[100];
    printf("Input: ");
    scanf("%s", buf);
    printf(buf);           // 漏洞
    printf("\n");
    return 0;
}
```

编译并运行：

```bash
gcc -g -O0 -no-pie -fno-stack-protector -o fmt fmt.c
./fmt
Input: %p %p %p %p %p %p %p %p
0x7f8a3b4c5680 0x7fff1234 0x401234 0x7f8a... ...
```

你会看到一串地址。用 `%N$s` 尝试读取其中的地址指向的内容，用 `%n` 尝试写入——这就是下一章的内容。

## 14.7 常见坑

1. **64 位下地址含有 `\x00`**：地址的高字节通常是 `\x00`，而 scanf/gets 遇到 `\x00` 可能截断。解决：把地址放在输入的末尾，或者使用能读二进制数据的函数（read）。
2. **输出长度限制**：`%100000c` 这种格式符会输出十万个字符，可能超出缓冲区或超时。用 `%hn`（2 字节写）代替完整 4/8 字节写，减少输出量。
3. **偏移量因环境而异**：本地和远程的栈布局可能不同（环境变量影响），偏移量需要重新计算。
4. **栈对齐**：格式化字符串漏洞通常不涉及栈对齐问题，但如果后续要用它来改写返回地址触发 ROP，还是要考虑。

## 14.8 小结

这一章我们讲了格式化字符串漏洞的原理：

- **成因**：`printf(user_input)` 让用户控制格式字符串，从而控制 printf 读多少参数、按什么类型读
- **`%p`**：泄露栈上数据（地址、Canary、libc 指针）
- **`%s`**：读取任意地址的内存
- **`%n`**：写入任意地址（最危险的格式符）
- **参数布局**：x86-64 下第 1~5 个参数在寄存器，第 6 个开始在栈上
- **偏移量**：目标数据在 printf 参数列表中的位置，需要实际测量
