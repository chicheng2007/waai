# 贡献指南

感谢你愿意为《从零开始的 Pwner 生活》添砖加瓦！以下是写作与提交规范。

## 章节结构模板

每章建议使用如下结构：

```markdown
# 第 N 章 章节标题

> 一句话导语，点明本章要解决什么问题。

## 本章目标
（读者读完本章应掌握什么）

## 正文
（分小节展开，多用类比、图示说明和调试截图描述）

## 动手实验
（给出一个可运行的最小示例，鼓励读者自己敲）

## 常见坑
（列出新手容易踩的坑）

## 小结
（三到五句话总结本章要点）
```

## 写作规范

1. **语气**：像一位耐心的学长在带学弟，口语化但不失严谨。避免「显然」「不难看出」这类劝退词汇。
2. **原理优先**：解释「为什么」，而不只是「怎么做」。给出 payload 时必须说清每个字节的含义。
3. **代码**：所有代码使用带语法高亮的围栏代码块，并注明语言（c / python / bash / asm）。
4. **图示**：内存布局、链表结构等尽量用 ASCII 图或表格表示，避免依赖外部图片。
5. **版本标注**：涉及 glibc 行为时，必须标注测试的 glibc 版本（如 2.31 / 2.35）。
6. **免责声明**：涉及攻击性技术时，提醒读者仅在授权环境使用。

## 提交流程

1. Fork 本仓库，创建分支 `ch01-xxx`
2. 按规范撰写内容，放在对应篇目的目录下
3. 在 `SUMMARY.md` 中更新章节链接
4. 提交 Pull Request，说明修改内容与动机
