# 第 17 章 堆基础：malloc 与 free 的世界

> 堆是 PWN 的分水岭。从这里开始，我们不再和返回地址直接打交道，而是深入研究 glibc 如何管理内存——然后欺骗它。

---

## 17.1 什么是堆

**堆（Heap）** 是程序运行时用于动态分配内存的区域。当你不知道需要多少内存、或者需要在函数返回后依然保留数据时，就要用堆。

```c
int *p = malloc(sizeof(int) * 10);   // 在堆上分配 40 字节
free(p);                              // 释放
```

堆和栈的区别：

| 特性 | 栈（Stack） | 堆（Heap） |
| --- | --- | --- |
| 管理方式 | 编译器自动分配/释放 | 程序员手动 malloc/free |
| 生长方向 | 向低地址 | 向高地址（通常） |
| 生命周期 | 函数作用域 | 直到 free 或程序结束 |
| 分配效率 | 高（只需移动 rsp） | 低（需要复杂的管理算法） |
| 碎片问题 | 无 | 有 |
| 权限 | 不可执行（NX） | 不可执行（NX） |

堆的管理者通常是 **glibc 的 malloc 实现**，学名叫 **ptmalloc**（pthreads malloc）。我们后面说的「堆」，很大程度上就是在说 ptmalloc 的数据结构和算法。

---

## 17.2 堆从哪里来：brk 与 mmap

程序向内核申请堆内存有两种方式：

### 17.2.1 brk：扩展数据段

`brk`（program break）是数据段（`.data`/`.bss`）的结束地址。调用 `brk()` 或 `sbrk()` 可以移动这个边界，从而扩大或缩小堆。

```text
低地址  ┌─────────────┐
        │   .text     │
        ├─────────────┤
        │   .data     │
        ├─────────────┤
        │   .bss      │
        ├─────────────┤ ← 初始 brk
        │             │
        │    堆       │ ← 向高地址增长
        │             │
        ├─────────────┤ ← 当前 brk
        │   未映射    │
        ├─────────────┤
        │   共享库    │
        │   (libc)    │
        ├─────────────┤
        │    栈       │
高地址  └─────────────┘
```

**小块内存**（默认小于 128KB）通过 brk 分配。堆从 `.bss` 末尾开始，向高地址增长。

### 17.2.2 mmap：独立映射

**大块内存**（默认 ≥ 128KB，由 `mmap_threshold` 控制）通过 `mmap()` 单独映射一块区域。这块内存不连续于主堆，通常位于共享库和栈之间（地址形如 `0x7f...`）。

```c
// 阈值可以通过 mallopt 修改
mallopt(M_MMAP_THRESHOLD, 128 * 1024);
```

> 💡 **提示**：判断一个指针指向的是主堆还是 mmap 区域，看地址形态：主堆地址紧跟着程序的 BSS（比如 `0x555555559000` 附近，无 PIE 时是 `0x804b000` 附近），mmap 区域是 `0x7f...` 开头。

## 17.3 第一次 malloc：堆的初始化

当一个程序第一次调用 `malloc` 时，发生了什么？

1. glibc 通过 `brk` 向内核申请一大块内存（通常是 132KB），作为**主堆区（main arena）**
2. 从这块内存里切出一小块返回给用户
3. 剩下的部分叫做 **top chunk**（Top Chunk），作为「储备」，后续 malloc 从它里面切

用 gdb 观察：

```c
// heap_basic.c
#include <stdlib.h>
#include <stdio.h>

int main() {
    char *p = malloc(0x10);
    char *q = malloc(0x20);
    printf("p = %p, q = %p\n", p, q);
    free(p);
    free(q);
    return 0;
}
```

```bash
gcc -g -O0 -no-pie -o heap_basic heap_basic.c
gdb ./heap_basic
```

在 `free(p)` 处下断点，查看堆：

```gdb
break 11
run
# pwndbg 的 heap 命令
heap
# 查看 chunk 信息
vis_heap_chunks
```

你会看到两个已分配的 chunk 和一个 top chunk。

## 17.4 malloc_chunk 结构体

glibc 把堆内存切成一个个**块（chunk）**。每个 chunk 前面有一个头部，记录大小和状态：

```c
struct malloc_chunk {
    size_t prev_size;    // 前一个 chunk 的大小（仅当前一个空闲时有效）
    size_t size;         // 当前 chunk 的大小 + 标志位
    struct malloc_chunk* fd;   // 双向链表指针（仅空闲时有效）
    struct malloc_chunk* bk;   // 双向链表指针（仅空闲时有效）
    ...
};
```

**已分配 chunk 的布局**：

```text
            低地址
    ┌──────────────────────┐
    │   prev_size (8B)     │  ← 仅当前一块空闲时有意义，否则被数据占用
    ├──────────────────────┤
    │   size (8B)          │  ← chunk 总大小（含头部），低 3 位是标志位
    ├──────────────────────┤
    │                      │
    │   user data          │  ← malloc 返回的地址指向这里
    │   (用户可用的空间)     │
    │                      │
    └──────────────────────┘
            高地址
```

**空闲 chunk 的布局**：

```text
    ┌──────────────────────┐
    │   prev_size          │
    ├──────────────────────┤
    │   size               │
    ├──────────────────────┤
    │   fd (前驱指针)       │  ← 空闲 chunk 才有，指向链表中的下一个
    ├──────────────────────┤
    │   bk (后继指针)       │  ← 指向链表中的上一个
    ├──────────────────────┤
    │   剩余空间...         │
    └──────────────────────┘
```

**size 字段的低 3 位标志**：

- **PREV_INUSE (0x1)**：前一个 chunk 是否在使用中
- **IS_MMAPPED (0x2)**：是否由 mmap 分配
- **NON_MAIN_ARENA (0x4)**：是否属于非主线程 arena

由于 chunk 大小总是 8（或 16）字节对齐，size 的低 3 位一定是 0，glibc 就拿它们当标志位用。

> ⚠️ **关键概念**：malloc 返回给用户的地址是 `chunk + 16`（跳过 prev_size 和 size），也就是 user data 的起始位置。用户写数据时，实际上是从 user data 开始写的。**能写的空间比 chunk 的 size 小 8 字节**（因为 size 字段本身被用户数据复用了，准确说是 size - 8）。这个「8 字节的偏差」在堆利用中至关重要。

## 17.5 malloc 的分配流程（简化版）

当调用 `malloc(n)` 时，glibc 大致按以下顺序处理：

1. **计算实际需要的 chunk 大小**：`request2size(n)` = 对齐到 16 字节，并加上头部开销
   - 公式：`(n + 8 + 15) & ~15`（最小 32 字节）
2. **检查 tcache**：如果 tcache 里有合适大小的 chunk，直接返回（最快）
3. **检查 fastbin / smallbin**：找对应大小的空闲 chunk
4. **遍历 unsorted bin**：找合适的 chunk，找不到就把它归类到对应的 bin
5. **检查 largebin**：找更大的 chunk 并切割
6. **从 top chunk 切一块**：如果以上都没有
7. **扩展堆或 mmap**：如果 top chunk 不够

释放 `free(p)` 时：

1. 检查合法性（双 free、地址对齐等）
2. 如果是 tcache 大小且 tcache 没满 → 放入 tcache
3. 否则根据大小放入 fastbin / unsorted bin
4. 如果和相邻的空闲 chunk 相邻 → 合并（consolidate）

> 💡 **提示**：这里提到的 tcache / fastbin / smallbin / largebin / unsorted bin 是 glibc 管理空闲 chunk 的不同「容器」。下一章会详细讲。现在你只需要知道：free 后的 chunk 不是「消失」了，而是被挂进了某个链表，等待复用。

## 17.6 用 gdb 观察堆

pwndbg 提供了强大的堆调试命令：

```gdb
# 显示所有 chunk（地址、大小、状态）
heap

# 可视化 chunk 布局
vis_heap_chunks

# 查看 arena 信息（bins 的链表头）
arenas

# 查看 tcache
tcache

# 查看 bins
bins
```

> 🔥 **实战**：用 gdb 调试 `heap_basic.c`，在每次 malloc 和 free 后暂停，用 `heap` 和 `vis_heap_chunks` 观察 chunk 的 size 字段、PREV_INUSE 标志的变化。特别注意 free 之后，chunk 的 fd/bk 指针是怎么被写入的。这些观察会让你对后面的堆利用技术有直观的认识。

## 17.7 glibc 版本的重要性

**这是堆利用最容易被忽视、也最容易踩坑的一点。**

glibc 的堆实现在不同版本间差异很大：

| glibc 版本 | Ubuntu 版本 | 重要变化 |
| --- | --- | --- |
| 2.23 | 16.04 | 经典 ptmalloc，无 tcache，fastbin 检查少 |
| 2.27 | 18.04 | 引入 tcache（无 key 检查） |
| 2.29 | 19.04 | tcache 加入 key 字段（防 double free） |
| 2.31 | 20.04 | 当前主流题目版本之一 |
| 2.34 | 22.04 | 移除 malloc_hook / free_hook，引入新的保护 |
| 2.35 | 22.04 | 当前主流，移除 hook 影响很多经典利用 |

**做堆题前，第一件事是确认 glibc 版本**：

```bash
# 本地 libc 版本
ldd --version

# 题目提供的 libc
./libc.so.6

# pwntools 里
libc = ELF('./libc.so.6')
print(libc.version)   # 如果符号被 strip，用 strings 找 "GNU C Library"
```

本教程会以 **2.31 和 2.35** 两个版本为主线讲解，遇到版本差异时单独标注。

## 17.8 小结

这一章我们建立了堆的基础认知：

- **堆**用于动态分配内存，由 glibc 的 ptmalloc 管理
- 小块内存通过 **brk** 分配（主堆），大块通过 **mmap** 分配
- 第一次 malloc 会初始化主堆，剩下的空间叫 **top chunk**
- 每个 chunk 有头部（prev_size、size）和用户数据区
- **size 的低 3 位**是标志位（PREV_INUSE、IS_MMAPPED、NON_MAIN_ARENA）
- malloc 按 tcache → fastbin → smallbin → unsorted bin → largebin → top chunk 的顺序找内存
- free 后的 chunk 挂进各种 bin，等待复用
- **glibc 版本差异巨大**，做堆题必须先确认版本

下一章我们深入剖析 chunk 结构和各种 bin 的组织方式——这是所有堆利用技术的理论基础。
