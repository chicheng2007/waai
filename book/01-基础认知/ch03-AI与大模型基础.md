# ch03 AI 与大模型基础

> **本章目标**：用尽量少的数学、尽量多的大白话，讲清楚大语言模型（LLM）到底是什么、它怎么"学会"说话、以及为什么它能用来做取证分析。读完你不需要会推导公式，但要知道模型的能力边界在哪。

## 3.1 先别怕：大模型没那么玄乎

很多人一听"神经网络""Transformer"就头大，觉得必须学完线性代数和概率论才能碰 AI。其实不是。

你可以把大语言模型理解成一个**超级 autocomplete（自动补全）**：你给它一段文字，它预测"下一个字最可能是什么"，然后一个字一个字往下接。就这么简单。

它之所以显得"聪明",是因为：

1. 它读了海量的文本（几乎整个互联网），见过各种表达方式；
2. 它的"预测"能力极强，强到能生成看起来很有逻辑的段落；
3. 通过训练，它学会了遵循指令、进行推理。

**这跟取证有什么关系？** 因为取证分析本质上也是"读文本 → 找规律 → 下结论"。大模型读过海量技术文档、日志样例、安全文章，所以它能理解日志、识别异常模式、生成分析报告。这就是它能当取证助手的根本原因。

## 3.2 从感知机到 Transformer：一句话历史

不用记细节，只要知道这条演进线：

```
感知机(1950s) → 神经网络 → 循环神经网络RNN(能处理序列)
→ 注意力机制Attention → Transformer(2017) → 大模型时代
```

几个关键节点：

- **感知机**：最早的人工神经元，输入一堆数字，加权求和，输出结果。它是所有神经网络的老祖宗。
- **RNN**：能处理有先后顺序的数据（比如句子），但记不住太远的内容。
- **Transformer（2017 年，论文《Attention Is All You Need》）**：引入了"注意力机制"，能同时关注句子里所有词的关系，解决了 RNN 记不住长内容的问题。**现代大模型几乎都基于 Transformer。**

你只需要记住：**Transformer 是一种擅长理解"词与词之间关系"的结构**，这让它能理解长文本、复杂逻辑。

## 3.3 几个你必须知道的概念

后面会反复用到这些词，先混个脸熟。

### Token（词元）

模型不是按"字"或"词"处理文本，而是按 **token**。一个 token 大约等于：英文 4 个字符，中文 1-2 个字。

比如"你好世界"可能是 2-4 个 token。模型有"上下文长度"限制，比如 8192 token，意思是它一次最多能"看"这么多内容。

**取证里的意义**：日志动辄几 GB，不可能一次全塞给模型。这就是为什么要先做数据筛选、分块处理——本书数据篇会详细讲。

### 参数（Parameters）

模型里的"知识"存在一堆数字里，这些数字叫参数。7B 模型就是 70 亿个参数，9B 就是 90 亿。参数越多，理论上能记住的东西越多，但需要的显存也越大。

**这解释了硬件限制**：一个 9B 模型用 16bit 精度加载大约要 18GB 显存，你的 8GB 显卡装不下。但用 4bit 量化后只要约 5-6GB，就能跑了。量化是本书的关键技术。

### 预训练与微调

- **预训练（Pre-training）**：模型在海量通用文本上学习，学会语言规律和世界知识。这一步成本极高，大公司才做得起，我们不做。
- **微调（Fine-tuning）**：在预训练模型基础上，用你自己的数据再训练一轮，让它适应特定任务。这一步我们做得起，也是本书的核心。

打个比方：**预训练相当于读完中小学和大学，微调整相当于入职培训**。我们不用重新培养一个"学生"，只要给现成的"毕业生"做岗前培训就行。

### 提示词（Prompt）

你给模型的输入指令。写好 Prompt 是一门学问，后面 ch16 专门讲。相同的模型，Prompt 写得好不好，效果可能差好几倍。

## 3.4 大模型为什么会"幻觉"

这是用 AI 做取证必须警惕的问题。

**幻觉（Hallucination）**：模型会一本正经地编造不存在的事实。比如你问它"这条日志里的 IP 是哪国的"，它可能编一个看似合理但错误的答案。

为什么会这样？因为模型的本质是"预测下一个最可能的字"，它追求的是"听起来对"，而不是"事实对"。当它不知道答案时，它不会说"我不知道"，而是倾向于编一个。

**对取证的启示**（非常重要）：

1. **永远核实**：AI 给出的 IP 归属、结论、时间线，都要用工具复核；
2. **给它依据**：把真实的日志内容放进 Prompt，让它"基于这些内容回答"，而不是凭空问；
3. **人在回路**：AI 辅助，人做最终判断（上一章的红线四）。

本书后面设计 Agent 时，会专门加"验证"环节，就是为了对抗幻觉。

## 3.5 为什么选 Qwen 系列

本书以 **Qwen（通义千问）** 系列模型为主，原因：

1. **中文能力强**：取证日志和文档大量是中文，Qwen 对中文的理解明显优于同尺寸的国外模型；
2. **开源友好**：Qwen 有多个尺寸（0.5B 到几百 B），小尺寸版本适合消费级显卡；
3. **生态完善**：LLaMA-Factory、unsloth 等微调框架对 Qwen 支持很好；
4. **本地可跑**：Qwen3.5-9B 的量化版能在 8GB 显存上跑，正好匹配你的硬件。

你本地已经装了 LM Studio + Qwen3.5-9B，这就是最好的起点——**先用它当"免费助教"，把本书的概念拿去问它**。

## 3.6 大模型怎么用在取证上：三种范式

把前面的内容串起来，大模型用于取证有三种范式，从简到难：

### 范式一：直接问答（零训练）

把日志贴给模型，直接问"这里面有什么异常"。

- 优点：零成本，马上能用；
- 缺点：受上下文长度限制，日志太长塞不下；结果不稳定。

适合：快速验证想法、处理小段文本。对应本书 ch16。

### 范式二：检索增强（RAG）

先把大量日志存入向量数据库，问问题时先检索出相关的片段，再喂给模型。

- 优点：能处理海量数据；
- 缺点：需要搭建检索系统。

适合：大规模日志查询。对应本书 ch19 会涉及。

### 范式三：微调专用模型

用自己的取证数据微调一个模型，让它专门懂你的业务。

- 优点：懂行话、结果稳定、可离线部署；
- 缺点：需要数据和训练。

适合：长期、专业的取证工作。对应本书 ch10-ch15。

这三种范式不是互斥的，实际项目往往组合使用。本书会带你都走一遍。

## 3.7 动手任务

1. **和本地模型对话**：打开 LM Studio，加载 Qwen3.5-9B，问它三个问题：
   - "请用大白话解释什么是 Transformer"
   - "给你一段防火墙日志你会怎么分析"
   - "你怎么防止自己产生幻觉"
   体会它的能力和局限。
2. **感受 token**：找一个在线的 token 计数器，数一段中文和一段英文各占多少 token。建立对"上下文长度"的直觉。
3. **幻觉测试**：故意问模型一个你确定它不知道的问题（比如编一个不存在的日志格式），看它会不会编答案。记录下来。

---

## 3.8 小结

- 大模型本质是个超级 autocomplete，一个字一个字预测输出；
- 演进线：感知机 → RNN → Transformer（2017）→ 大模型；
- 关键概念：token、参数、预训练/微调、Prompt、上下文长度；
- **幻觉是取证的大敌**：永远核实、给依据、人在回路；
- 选 Qwen 系列：中文强、开源、小尺寸能本地跑；
- 三种应用范式：直接问答、RAG、微调专用模型。
