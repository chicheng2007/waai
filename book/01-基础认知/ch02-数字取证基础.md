## 2.1 取证的六步流程

上一章提了一句取证流程，这一章展开讲。国际通行的电子取证流程可以概括成六步，记住它，后面所有工作都在这六步框架里。

```
1. 识别 (Identification)   —— 搞清楚要查什么、证据在哪
2. 保全 (Preservation)     —— 保护现场，防止证据被破坏
3. 采集 (Acquisition)      —— 把证据完整地复制出来
4. 分析 (Analysis)         —— 从证据里找线索
5. 记录 (Documentation)    —— 把每一步操作记下来
6. 呈现 (Presentation)     —— 把结论整理成报告
```

### 第一步：识别

接到任务，先明确目标：是查入侵？查数据泄露？还是查内部违规？目标不同，要找的证据完全不同。这一步最容易被新手跳过，结果就是"大海捞针"。

**AI 在识别阶段能帮忙**：比如用大模型快速理解案件描述，提取出"关键词"和"要找的证据类型"，帮你列一个初步清单。

### 第二步：保全

这是法律上最关键的一步。原则只有一条：**不要修改原始证据**。

具体做法包括：给原始磁盘做只读镜像、计算哈希值（MD5/SHA-256）证明数据未被改动、记录操作时间和操作人。一旦你在原始证据上写了东西，证据链的完整性就断了，法庭上可能不被采信。

**为什么要强调这个？** 因为很多 AI 工具会"自作主张"地修改数据。如果你让一个脚本直接处理原始日志并覆盖保存，就毁了证据。本书后面所有的数据处理，都强调**在副本上操作、保留原始数据**——这是取证的第一铁律。

### 第三步：采集

把证据从原始媒介复制出来。这里有个关键概念：**位级镜像（bit-by-bit image）**。不是简单复制文件，而是把整个磁盘按扇区完整复制，包括已删除但还没被覆盖的数据。

常用工具：`dd`（Linux）、FTK Imager（Windows，免费）、`dc3dd`。

### 第四步：分析

这是取证的核心，也是 AI 最能发力的环节。分析包括：

- **日志分析**：从系统日志、应用日志、网络日志里找异常；
- **文件分析**：检查文件内容、元数据、时间戳；
- **内存分析**：从内存镜像里找进程、网络连接、注入代码；
- **恶意代码分析**：逆向分析可疑程序的行为。

本书的 AI 工具主要服务这一环节。

### 第五步：记录

每一步操作都要记录：做了什么、用什么工具、结果是什么。这不是形式主义，而是为了让别人能复核你的工作，也为了法庭上能证明你的结论可靠。

**AI 在这里能帮忙**：自动把分析过程生成结构化记录。比如 Agent 每执行一步，自动写日志——这比人工记录更完整、更不容易遗漏。

### 第六步：呈现

把结论写成报告。报告要清楚回答：发现了什么、证据是什么、结论的把握有多大。这一步 AI 也能帮忙——把分析结果自动整理成报告初稿，人工审核修改。

## 2.2 证据类型：你要跟什么东西打交道

取证分析师每天面对的证据，大致分这几类。了解它们，你才知道 AI 该处理什么格式的数据。

### 日志类（最常用，也是本书重点）

| 类型 | 例子 | 特点 |
|---|---|---|
| 系统日志 | Windows 事件日志、Linux syslog | 结构化程度中等，量大 |
| 网络日志 | 防火墙、IDS、代理日志 | 量极大，格式多样 |
| 应用日志 | Web 服务器访问日志、数据库日志 | 格式相对规整 |
| 安全设备告警 | EDR、WAF 告警 | 噪音多，误报多 |

这类数据是**文本为主**，特别适合用大模型处理。本书的"星海案"主要就是日志分析。

### 文件类

包括文档、图片、可执行文件等。分析时关注：文件类型识别（魔数）、哈希、元数据、时间戳（MAC 时间：修改/访问/创建）。

### 内存类

内存镜像里藏着很多磁盘上没有的信息：正在运行的进程、网络连接、解密后的密钥、注入的 shellcode。分析工具主要是 Volatility。这是进阶内容，本书项目二会涉及。

### 网络流量类

抓包文件（pcap），分析协议、连接、传输内容。工具是 Wireshark / tshark。

## 2.3 常用工具链

工欲善其事，必先利其器。这一节列一个工具清单，你不需要现在全会，但要知道有这些东西。

| 类别 | 工具 | 用途 | 备注 |
|---|---|---|---|
| 镜像获取 | FTK Imager, dd | 制作磁盘镜像 | FTK Imager 免费 |
| 哈希计算 | sha256sum, md5sum | 验证完整性 | 命令行就能做 |
| 日志分析 | grep, jq, pandas | 过滤、解析日志 | 本书大量使用 Python |
| 文件分析 | file, exiftool, binwalk | 识别文件类型、提取元数据 | exiftool 很强大 |
| 内存分析 | Volatility 3 | 内存取证 | 进阶 |
| 流量分析 | Wireshark, tshark | 抓包分析 | tshark 可脚本化 |
| 恶意代码 | strings, objdump, IDA/Ghidra | 逆向分析 | Ghidra 免费 |

**和 AI 的关系**：这些工具产出的是"结构化或半结构化的数据"，正是大模型的输入。本书做的 Agent，本质上就是**让大模型学会调用这些工具、理解它们的输出**。比如让 Agent 自动调用 `tshark` 分析流量，再把结果喂给大模型总结。

## 2.4 法律与伦理红线（非常重要）

这一节请认真读。取证是和法律强相关的领域，越界可能违法。

### 红线一：授权

**任何取证操作，都必须在合法授权下进行。** 对别人的电脑、网络、系统做取证，必须有明确授权（书面授权最好）。未经授权的"取证"，在法律上可能就是"非法侵入计算机系统"。

本书所有案例都是**虚拟的**，所有实操都用**你自己搭建的环境**（如本地虚拟机、公开数据集）。切勿对真实系统动手。

### 红线二：证据完整性

前面说过，不要修改原始证据。这既是技术要求，也是法律要求。记住：**永远在副本上工作**。

### 红线三：隐私保护

日志和证据里往往包含个人信息（姓名、IP、账号）。处理时要注意：必要时脱敏、不要随意传播、遵守数据保护法规（如个人信息保护法）。

### 红线四：AI 的边界

用 AI 辅助取证时，要清楚：**AI 的结论不能直接作为法律证据**。AI 会犯错（幻觉），它的输出只能作为"线索"和"辅助判断"，最终结论必须由人审核确认。

这一点在司法场景尤其重要。如果你把 AI 生成的报告直接当证据交上去，而 AI 产生了幻觉，后果很严重。本书后面会反复强调"人在回路（human-in-the-loop）"——AI 辅助，人决策。

> **一句话总结这一节**：技术可以大胆学，操作必须守红线。授权、完整、隐私、人工审核，这四条是底线。

现在把取证六步和 AI 的能力对上号，你就明白这本书的知识地图了：

## 2.6 动手任务

1. **画流程图**：把取证六步流程用自己的话画成一张图（纸笔或工具都行），每步写一个关键词。
2. **装三个小工具**：`file`、`exiftool`、`sha256sum`。找个自己电脑上的文件，用它们看看输出。（Linux 自带大部分，Windows 可用 Git Bash 或 WSL）
3. **哈希实验**：对一个文本文件算 SHA-256，改一个字符再算一次，观察变化。体会"完整性验证"的含义。
4. **红线自查**：写下三条你绝不会越过的取证红线。

## 2.7 小结

- 取证六步：识别、保全、采集、分析、记录、呈现；AI 主战场在"分析"；
- 证据类型：日志、文件、内存、流量；本书以日志为主；
- 工具链：镜像、哈希、日志分析、文件分析、内存分析、流量分析、逆向；
- **四条红线**：授权、证据完整、隐私保护、人工审核（AI 结论不能直接当证据）；
- AI 与取证流程的对应表，就是本书的知识地图。
