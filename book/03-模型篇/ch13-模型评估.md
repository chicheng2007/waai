## 13.1 为什么评估很难

评估大模型很难，因为它没有唯一正确答案。同一个问题，可能有多种合理回答。这跟传统机器学习（分类、回归）不一样——后者有明确的标准答案。

取证 AI 的评估还要面对几个特殊问题：

- **回答是长文本**：怎么判断一段分析"对不对"？
- **幻觉**：模型可能编造细节，字面通顺但事实错误；
- **主观性**："分析得好不好"有主观成分。

所以需要组合多种评估方法，从不同角度判断。

---

## 13.2 三种评估方法

### 方法一：Exact Match（精确匹配）

最简单：模型的回答和标准答案完全一致才算对。

```python
def exact_match(pred, ref):
    return pred.strip() == ref.strip()
```

优点：客观、快。缺点：太严格，模型换个说法就算错。适合评估"结论词"（如事件类型）。

### 方法二：LLM-as-Judge（用模型当裁判）

用一个强模型（如本地 Qwen 或 GPT）当裁判，让它评估回答质量。这是现在很流行的方法。

```python
from openai import OpenAI
client = OpenAI(base_url="http://localhost:1234/v1", api_key="not-needed")

def judge(question, reference, answer):
    prompt = f"""你是评估专家。判断模型回答的质量，打 1-5 分。

问题：{question}
标准答案：{reference}
模型回答：{answer}

评分标准：
5分：完全正确，格式规范，依据充分
4分：基本正确，略有瑕疵
3分：部分正确，有遗漏
2分：大部分错误
1分：完全错误或答非所问

只输出数字分数："""
    resp = client.chat.completions.create(
        model="local-model",
        messages=[{"role": "user", "content": prompt}],
        temperature=0.1, max_tokens=10
    )
    return int(resp.choices[0].message.content.strip()[0])
```

**注意**：用模型当裁判也有偏差（它可能偏爱某种风格）。所以要：
- 用和分析模型不同裁判模型（避免"自己评自己"）；
- 人工抽查一批，校准裁判的可靠性。

### 方法三：人工评估

最可靠但最慢。抽一批样本，人来看、人打分。适合最终验收。

**实际做法**：三者结合。日常迭代用精确匹配 + LLM-as-Judge，最终验收做人工评估。

## 13.3 构建评估集

评估集就是 ch09 留出的 `starsea_val.jsonl`。但还要做一件事：**单独准备一批"难题"**。

### 分层评估集

| 层级 | 内容 | 考什么 |
|---|---|---|
| L1 单条判断 | 单条日志 | 基础识别能力 |
| L2 事件分类 | 单条 + 类型 | 分类准确性 |
| L3 多事件关联 | 多条日志 | 关联推理 |
| L4 开放分析 | 一批日志 | 综合分析 |

如果不分层，你可能只看到平均分，不知道模型在哪层不行。分层评估能定位弱点。

### 保留"未见过的场景"

评估集里要有训练集没覆盖的场景。比如训练数据都是 2026-10-15 的日志，评估集可以放 2026-10-16 的。这样能测出模型是真学会了规律，还是背下了具体样本。

## 13.4 自动化评估脚本

写一个脚本，跑一遍验证集，输出各项指标：

```python
# eval.py
import json
from collections import defaultdict
from openai import OpenAI

client = OpenAI(base_url="http://localhost:1234/v1", api_key="not-needed")

val = [json.loads(l) for l in open("starsea_val.jsonl")]
val = val[:100]  # 先评 100 条，快

results = defaultdict(list)

for item in val:
    question = item["messages"][1]["content"]
    reference = item["messages"][2]["content"]

    # 让微调模型回答
    resp = client.chat.completions.create(
        model="starsea-lora",  # 已加载微调模型的本地服务
        messages=item["messages"][:2],
        temperature=0.1, max_tokens=200
    )
    answer = resp.choices[0].message.content.strip()

    # 精确匹配：提取结论词
    def get_conclusion(text):
        if "端口扫描" in text: return "port_scan"
        if "登录爆破" in text: return "brute_force"
        if "数据外传" in text: return "large_transfer"
        if "正常流量" in text: return "normal"
        return "unknown"

    ref_c = get_conclusion(reference)
    pred_c = get_conclusion(answer)
    results["exact"].append(1 if pred_c == ref_c else 0)

    # 裁判打分
    results["judge"].append(judge(question, reference, answer))

# 汇总
print(f"结论准确率: {sum(results['exact'])/len(results['exact']):.3f}")
print(f"裁判平均分: {sum(results['judge'])/len(results['judge']):.2f}")
```

## 13.5 关键指标

### 准确率（Accuracy）

结论正确的比例。最直观，但类别不平衡时会误导——如果 90% 是正常流量，模型全猜"正常"也有 90% 准确率。

### 精确率、召回率、F1

对取证更有意义的是对**异常类**的识别能力：

- **精确率（Precision）**：模型说"异常"的里面，真异常的比例（少误报）；
- **召回率（Recall）**：真异常里面，被模型找出来的比例（少漏报）；
- **F1**：两者的调和平均。

```python
from sklearn.metrics import classification_report

print(classification_report(y_true, y_pred))
```

**取证场景更看重召回率**：宁可多报几个可疑（误报），也不要漏掉真正的攻击（漏报）。因为漏报的代价更大。所以评估时要特别看 recall。

### 格式合规率

我们的模型被要求按"结论/依据/建议"三段式回答。检查它遵守格式的比例：

```python
def format_ok(text):
    return all(k in text for k in ["结论", "依据", "建议"])

compliance = sum(format_ok(a) for a in answers) / len(answers)
print(f"格式合规率: {compliance:.3f}")
```

这个指标衡量微调是否成功塑造了回答风格。

## 13.6 对比基线

评估要有参照物。至少对比：

| 对比对象 | 目的 |
|---|---|
| 微调前（原模型） | 看微调有没有提升 |
| 不同 epoch 的版本 | 看训练多少轮最好 |
| 不同超参的版本 | 选最优配置 |

把结果做成表格：

| 模型 | 结论准确率 | 异常召回率 | 格式合规率 | 裁判分 |
|---|---|---|---|---|
| 原模型 Qwen-7B | 0.62 | 0.45 | 0.20 | 2.8 |
| 微调 v1（2 epoch） | 0.85 | 0.78 | 0.92 | 4.2 |
| 微调 v2（3 epoch） | 0.88 | 0.81 | 0.95 | 4.3 |

有了这样的表，你才知道模型到底进步了多少，选哪个版本。

## 13.7 过拟合的识别

过拟合的典型表现：

- **训练集表现很好，验证集差很多**：说明模型背下了训练数据；
- **loss 先降后升**：训练后期的信号；
- **回答变得僵硬**：只会用训练数据里的原话。

如果发现过拟合：

1. 减少 epoch；
2. 增加数据多样性（ch08 的增强）；
3. 降低 LoRA rank（减少模型容量）；
4. 加正则化（如 dropout）。

## 13.9 小结

- 评估难在"长文本没有唯一答案"，要组合多种方法；
- 三种方法：精确匹配、LLM-as-Judge、人工评估；
- 评估集要分层，还要有"未见过的场景"；
- 关键指标：准确率、精确率、召回率、F1、格式合规率；
- **取证更看重召回率**：宁可误报，不可漏报；
- 评估要有基线对比，做成表格；
- 警惕过拟合：训练好、验证差。
