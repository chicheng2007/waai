# 第十章 捕获选项深入

点击工具栏的「捕获选项」按钮（齿轮图标）或菜单 `Capture → Options`，打开捕获选项对话框。这里控制着抓包阶段的几乎所有行为。掌握这些设置，能让你「抓到该抓的包，不抓无关的包」。

## 10.1 捕获选项对话框结构

对话框主要包含以下区域：

1. **Capture 区域**：接口列表、混杂模式、捕获过滤器、快照长度。
2. **Output 区域**：是否立即保存到文件、文件名、文件格式、环形缓冲。
3. **Display 区域**：捕获时的显示选项（实时更新列表、自动滚动）。
4. **Stop Capture 区域**：自动停止条件（按包数、时间、文件大小）。

## 10.2 接口选择

顶部接口列表列出所有可用网卡。可以同时勾选多个接口，Wireshark 会同时捕获多个接口的流量（多接口捕获）。每个接口可以单独设置捕获过滤器和混杂模式。

接口列表中还会显示链路层类型（如 Ethernet）和接口状态。

## 10.3 混杂模式（Promiscuous Mode）

混杂模式决定网卡是否接收「不是发给它」的帧：

- **开启**：网卡接收局域网内所有帧（包括广播、组播、发给其他主机的帧）。这是抓包分析的常规选择。
- **关闭**：网卡只接收发给自己的帧和广播帧。

> **注意**：在交换机网络中，混杂模式只能抓到本VLAN内广播/组播的流量以及发给本机的流量，无法抓到其他两台主机之间的单播通信——因为交换机按 MAC 地址转发，不会把别人的单播帧发到你的端口。想抓全网流量需要端口镜像（SPAN）或网络分流器（TAP）。在共享介质（如早期集线器）或无线网络环境中，混杂模式才能看到更多流量。

## 10.4 捕获过滤器（Capture Filter）

捕获过滤器输入框位于接口列表中每个接口的行内，或对话框顶部的全局位置。它基于 **BPF（Berkeley Packet Filter）** 语法，在抓包**之前**生效——只有符合过滤器的包才会被捕获和保存。

例如：

- `host 192.168.1.10`：只抓与该主机相关的包。
- `tcp port 80`：只抓 80 端口的 TCP 流量。
- `not arp`：排除 ARP 包。

捕获过滤器语法详见第十一章。要区分它和显示过滤器：**捕获过滤器决定「抓什么」，显示过滤器决定「显示什么」**。捕获过滤器一旦设置，被过滤掉的包永远丢失，无法事后恢复，所以要谨慎使用。

## 10.5 快照长度（Snaplen）

快照长度指定每个包最多捕获多少字节，默认通常是 262144 字节（足够大）。相关设置：

- `Capture the entire packet (snaplen)`：捕获完整包。
- `Limit packet length to ... bytes`：只抓前 N 字节。

**使用场景**：如果你只关心协议首部（如 IP/TCP 头部），不关心载荷内容，可以把 snaplen 设为 128 或 256 字节。这样能大幅减少文件大小、提高捕获性能。但代价是丢失应用层数据（如 HTTP 内容、传输的文件）。

> **提示**：以太网标准 MTU 是 1500 字节，加上各层首部，完整帧通常不超过 1514 字节。如果设为 128 字节，你只能看到链路层、网络层、传输层的首部，看不到应用数据。

## 10.6 捕获文件输出设置

在 Output 区域，可以选择：

- **不保存**：仅在内存中捕获，关闭后丢失。适合临时观察。
- **保存到文件**：勾选后指定文件名和格式（pcapng / pcap）。
- **使用多个文件**：按时间间隔、文件大小或包数自动分割文件。
- **环形缓冲（Ring Buffer）**：设置文件数量和每个文件的大小上限，循环覆盖旧文件。

### 10.6.1 环形缓冲的用途

假设你要抓一个持续数小时的间歇性问题，但不知道问题何时发生。设置环形缓冲（如 10 个文件，每个 100MB），Wireshark 会持续抓包并轮流覆盖最旧的文件。问题发生后，你立即停止捕获，最近的 1GB 流量（10×100MB）被保留下来，很可能包含问题发生时的包。

## 10.7 自动停止条件

Stop Capture 区域可以设置自动停止条件，满足任一条件即停止：

- **捕获 N 个包后停止**
- **捕获 N 秒/分钟后停止**
- **文件大小达到 N MB/GB 后停止**

例如，设置「捕获 10000 个包后停止」，可以避免忘记停止导致磁盘被撑爆。在长时间无人值守抓包时很有用。

## 10.8 显示选项

Display 区域控制捕获过程中的实时显示：

- **Update list of packets in real time**：实时更新列表（默认开启）。关闭可提高捕获性能。
- **Automatic scrolling in live capture**：自动滚动到最新包。

在高速网络（如千兆以上）抓包时，实时更新列表会消耗大量 CPU 和内存，可能导致丢包。此时可以关闭实时更新，只抓不显示，事后再分析文件。

## 10.9 捕获性能建议

高速网络抓包的注意事项：

1. **关闭实时列表更新**（见上）。
2. **关闭名称解析**（见第九章），避免 DNS 查询开销。
3. **使用足够大的 snaplen**（如只分析首部则调小）。
4. **使用快速磁盘（SSD）**保存文件，避免磁盘 I/O 成为瓶颈。
5. **设置合适的捕获过滤器**，减少数据量。
6. 极端高速场景下，考虑用专用硬件或 `dumpcap` 命令行抓包。

## 10.10 小结

- 捕获选项对话框控制接口、混杂模式、捕获过滤器、快照长度、输出和停止条件。
- 混杂模式能抓到局域网广播/组播流量，但交换机下单播流量需端口镜像/TAP。
- 捕获过滤器在抓包前生效，被过滤的包无法恢复，需谨慎。
- Snaplen 可设为较小值以只抓首部，但会丢失应用层数据。
- 环形缓冲适合长时间抓包，自动保留最近的流量。
- 高速网络抓包时关闭实时更新和名称解析，提升性能。
