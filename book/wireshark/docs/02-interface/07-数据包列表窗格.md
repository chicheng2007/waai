# 第七章 数据包列表窗格

数据包列表窗格（Packet List Pane）是 Wireshark 界面的「仪表盘」。每一行代表一个捕获到的数据包（帧），所有分析都从这里开始。本章详细解读这个窗格的每一列及其背后的含义。

## 7.1 默认列释义

默认情况下，列表包含以下列：

| 列名 | 含义 | 示例 |
| --- | --- | --- |
| No. | 数据包的序号，按捕获顺序递增 | 42 |
| Time | 时间戳，默认是相对于第一个包的秒数 | 1.234567 |
| Source | 源地址（IP 或 MAC，取决于最高层协议） | 192.168.1.10 |
| Destination | 目的地址 | 93.184.216.34 |
| Protocol | Wireshark 识别出的最高层协议 | TCP / HTTP / DNS |
| Length | 帧长度（字节） | 1514 |
| Info | 协议的关键信息摘要 | 54321 → 80 [SYN] Seq=0 |

### 7.1.1 No. 列

序号是 Wireshark 给每个包分配的编号，从 1 开始。它反映的是**捕获顺序**，不是时间排序（虽然通常一致）。在讨论问题时，用「第 N 个包」来指代非常方便。

### 7.1.2 Time 列

时间列的显示格式可以调整：右键点击列标题 → `Time Display Format`，可选：

- **Seconds Since Beginning of Capture**（默认）：相对第一个包的秒数，适合分析时间间隔。
- **UTC Date and Time**：绝对 UTC 时间。
- **Local Date and Time**：本地时间。
- **Seconds Since Previous Displayed Packet**：与上一个显示包的间隔，分析时延很好用。

时间精度通常为微秒（6 位小数），高精度抓包可达纳秒。

### 7.1.3 Source 与 Destination 列

这两列显示的是「最顶层可识别的地址」。例如：

- 一个 HTTP 包，显示的是 IP 地址。
- 一个纯 ARP 包，显示的是 MAC 地址。
- 一个纯以太网帧（如 STP），显示的是 MAC 地址。

如果你想固定显示某种地址，可以在列设置中添加专门的「IP 源地址」「MAC 源地址」列（见第九章）。

### 7.1.4 Protocol 列

显示 Wireshark 解析出的**最高层协议**。例如一个承载 HTTP 的 TCP 包显示为 HTTP，而一个纯 TCP 控制包（如 SYN）显示为 TCP。

注意：协议列显示的结果取决于 Wireshark 的协议解析和「Decode As」设置。如果协议识别错误（比如自定义端口上的 HTTP 被识别为 TCP），可以用右键 → `Decode As` 强制指定。

### 7.1.5 Length 列

帧的长度，单位是字节。以太网帧的典型范围是 64~1514 字节（不含前导码和 FCS）。超过 1514 的可能是巨型帧（Jumbo Frame）或 VLAN 标签导致的。

**长度异常是重要线索**：

- 大量 60~64 字节的小包：可能是 ACK 洪水或扫描。
- 持续 1514 字节的大包：可能是大文件传输或流量攻击。
- 长度 0 或异常小：可能是畸形包。

### 7.1.6 Info 列

信息摘要是最有用的列，它概括了包的关键内容。不同协议显示不同信息，例如：

- DNS：`Standard query 0x1234 A www.example.com`
- TCP：`54321 → 80 [SYN] Seq=0 Win=64240 Len=0 MSS=1460`
- HTTP：`GET /index.html HTTP/1.1`
- ICMP：`Echo (ping) request id=0x0001, seq=1/256, ttl=64`

学会读懂 Info 列，能大幅提升分析速度。

## 7.2 行的颜色含义

默认配色方案中，行的背景色有含义：

- **浅紫色**：TCP 流量
- **浅蓝色**：UDP 流量
- **浅绿色**：HTTP 流量
- **浅黄色/金色**：DNS 流量
- **黑色背景 + 红色字**：专家信息标记为错误（Error）的包
- **浅红色背景**：警告（Warning）级别的包

颜色规则可以自定义（见第十四章）。

## 7.3 列的排序与调整

- **排序**：点击列标题按该列排序，再点一次切换升序/降序。例如按 Time 排序可还原时间顺序，按 Protocol 排序可把同类协议聚在一起。
- **调整宽度**：拖动列标题之间的分隔线。
- **隐藏/显示列**：`View → Columns`，或使用右键菜单。
- **改变列顺序**：在 `View → Columns` 中上下移动。

## 7.4 选择、标记与跳转

- **多选**：按住 `Ctrl` 或 `Shift` 点击，可选择多个包。
- **标记（Mark）**：`Ctrl + M` 给选中包打标记，标记的包会在 No. 列显示一个图标（默认黑色背景）。标记便于在大量包中快速定位关注对象。
- **跳转**：`Ctrl + Home` 到第一个包，`Ctrl + End` 到最后；右键 → `Go to Packet`（或 `Ctrl + G`）输入序号直接跳转。
- **相对跳转**：右键 → `Go to Next Packet in Conversation` 可在同一会话中跳转。

## 7.5 右键菜单常用功能

在数据包上右键，弹出丰富的上下文菜单，常用的有：

- **Follow → TCP/UDP/HTTP Stream**：跟踪完整会话（非常常用）。
- **Prepare as Filter**：以此包的字段为模板生成显示过滤器。
- **Conversation Filter**：过滤出相关会话的流量。
- **Colorize Conversation**：给该会话着特殊颜色。
- **Decode As**：强制按指定协议解析。
- **Export Selected Packet Bytes**：导出选中包或指定字段的字节。
- **Mark Packet / Unmark Packet**：标记/取消标记。
- **Edit Packet Comment**：添加注释。

其中 **Prepare as Filter** 和 **Follow Stream** 是日常分析的高频操作，务必熟练掌握。

## 7.6 从列表快速定位问题

看列表时，养成以下习惯：

1. **先看协议分布**：如果某个协议占比异常高，可能有问题。
2. **看时间间隔**：突然出现的大间隔可能意味着网络中断或超时。
3. **看重复信息**：大量相同的重传包（`[TCP Retransmission]`）说明链路质量差。
4. **看异常标志**：如 `[RST]` 突然出现，可能是连接被拒绝或重置。
5. **看长度突变**：连续大包后突然出现小包，可能是某个阶段结束。

## 7.7 小结

- 列表窗格的默认列：No.、Time、Source、Destination、Protocol、Length、Info。
- 时间格式可切换为绝对时间或相对间隔，便于不同场景分析。
- Info 列浓缩了包的核心信息，读懂它能大幅提升效率。
- 行颜色反映协议类型或专家告警级别。
- 右键菜单中的 Follow Stream、Prepare as Filter 是高频功能。
- 从列表看协议分布、时间间隔、重传、RST 等异常，能快速定位问题方向。
