# 第三十九章 大规模抓包优化

在高速网络（千兆、万兆）或长时间抓包场景中，Wireshark 可能面临性能瓶颈——丢包、卡顿、磁盘撑满。本章介绍如何优化抓包性能，确保抓到完整可靠的数据。

## 39.1 性能瓶颈的来源

抓包是一个「生产—消费」过程：网卡收到包 → 内核 → 抓包引擎 → 磁盘/内存 → 显示。任何环节跟不上都会丢包：

- **网卡/驱动**：处理能力不足或配置不当。
- **内核/协议栈**：缓冲区太小，包到达太快来不及处理。
- **CPU**：实时解析、显示消耗大量 CPU。
- **磁盘**：写入速度跟不上（尤其是机械硬盘）。
- **内存**：大流量下缓冲区溢出。

## 39.2 优化策略

### 39.2.1 抓包阶段优化

1. **关闭实时显示**：捕获选项中取消「Update list of packets in real time」，只抓不显示。
2. **关闭名称解析**：避免 DNS 反查开销。
3. **使用捕获过滤器**：在源头减少数据量。
4. **调整快照长度（snaplen）**：只抓首部（如 128 字节）可减少 90% 数据量（当不需要载荷时）。
5. **使用环形缓冲**：避免磁盘写满。

### 39.2.2 系统层面优化（Linux）

**增大网卡缓冲区**：

```bash
# 查看当前设置
ethtool -g eth0
# 增大接收环形缓冲区
ethtool -G eth0 rx 4096
```

**关闭卸载功能**（避免校验和卸载导致的解析问题，也能减少某些开销）：

```bash
ethtool -K eth0 rx off tx off gso off
```

**调整内核网络缓冲区**：

```bash
sysctl -w net.core.rmem_max=134217728
sysctl -w net.core.rmem_default=134217728
```

**使用 AF_PACKET 的 TPACKET_V3**（dumpcap 默认使用，提高抓包效率）。

### 39.2.3 使用命令行工具

- **dumpcap** 是 Wireshark 的底层抓包引擎，比图形界面轻量得多：

```bash
dumpcap -i eth0 -w capture.pcapng -b filesize:100000 -b files:10
```

这个命令抓包并按 100MB 分割，最多保留 10 个文件（环形缓冲）。

- 在服务器上用 `tcpdump` 抓包，再传到本地分析，也是常见做法。

### 39.2.4 磁盘优化

- 使用 SSD 而非机械硬盘。
- 抓包文件放在独立的磁盘/分区，避免与其他 I/O 竞争。
- 使用快速文件系统（ext4/xfs）。
- 实时监控磁盘空间，设置告警。

## 39.3 判断抓包是否丢包

Wireshark 提供几个指标判断抓包质量：

- **状态栏**：捕获时显示丢包计数（`Dropped: N`）。
- **统计 → Capture File Properties**：显示丢包信息。
- **专家信息**：大量 `Previous segment not captured` 可能意味着抓包丢包。
- **capinfos**：显示接口的丢包统计。

如果丢包率高，说明抓包不可靠，需要先解决性能问题，否则分析结果不可信。

## 39.4 长时间抓包策略

### 39.4.1 环形缓冲配置

在捕获选项中设置：

- 输出多个文件，每个 100~500MB。
- 文件数量根据磁盘空间和问题回溯需求确定（如 20 个文件 × 100MB = 2GB）。
- 循环覆盖最旧文件。

用 dumpcap 命令：

```bash
dumpcap -i eth0 -w /data/cap.pcapng -b filesize:100000 -b files:20 -b duration:300
```

（每个文件 100MB 或 300 秒，取先到者，最多 20 个文件。）

### 39.4.2 定时抓包

用 cron 定时抓包（如每小时抓 5 分钟）：

```bash
# crontab: 每小时的第 0 分抓 5 分钟
0 * * * * timeout 300 dumpcap -i eth0 -w /data/cap-$(date +\%Y\%m\%d-\%H).pcapng
```

### 39.4.3 触发式抓包

当检测到异常时启动抓包（需要与外部监控系统联动），避免 24 小时持续抓包。

## 39.5 分析阶段优化

大文件分析同样需要优化：

- **先分割再分析**：用 editcap 把大文件分成小块。
- **先过滤再保存**：用 tshark 提取关注的流量到新文件。
- **用 tshark 而非图形界面**：命令行批量处理更快。
- **增加内存**：Wireshark 解析大文件需要大量内存。
- **关闭不必要的协议解析**：`Analyze → Enabled Protocols` 禁用用不到的协议。

## 39.6 小结

- 抓包性能瓶颈可能在网卡、内核、CPU、磁盘任一环节。
- 抓包时关闭实时显示和名称解析、使用过滤器、调整 snaplen、用环形缓冲。
- Linux 下可增大网卡缓冲区、调整内核参数、关闭卸载功能。
- dumpcap 比图形界面轻量，适合服务器长时间抓包。
- 通过状态栏丢包计数、`Previous segment not captured` 等判断抓包质量。
- 长时间抓包用环形缓冲或定时/触发式策略。
- 大文件分析先分割、过滤，再深入分析。
