# 第二十四章 其他应用层协议

本章快速浏览一些常见的应用层协议：文件传输（FTP）、邮件（SMTP/POP3/IMAP）、远程登录（SSH/Telnet）、网络管理（SNMP）、时间同步（NTP）、目录服务（LDAP）、文件共享（SMB）等。虽然它们不像 HTTP 那样频繁出现在日常抓包中，但在企业网络和企业安全分析中非常常见。

## 24.1 FTP（文件传输协议）

FTP 使用两个连接：

- **控制连接**：端口 21，传输命令和响应（整个会话期间保持）。
- **数据连接**：用于传输文件内容（主动模式端口 20，被动模式动态端口）。

### 24.1.1 主动模式 vs 被动模式

- **主动模式（PORT）**：客户端打开一个端口并告诉服务器，服务器从端口 20 主动连接客户端。防火墙环境下容易失败。
- **被动模式（PASV）**：客户端发送 PASV 命令，服务器打开一个随机端口并告诉客户端，客户端连接该端口。更常用，适合客户端有防火墙的场景。

### 24.1.2 Wireshark 分析 FTP

```
ftp                                      # 所有 FTP 控制连接
ftp.request.command == "USER"            # 用户名
ftp.request.command == "PASS"            # 密码
ftp.response.code == 230                 # 登录成功
```

> **安全提示**：FTP 明文传输，用户名、密码、文件内容都能被抓包看到。生产环境应使用 SFTP 或 FTPS。

在 Wireshark 中，FTP 数据连接的内容会被识别为 `FTP-DATA`，可以用 Follow TCP Stream 查看传输的文件。

## 24.2 邮件协议：SMTP、POP3、IMAP

### 24.2.1 SMTP（简单邮件传输协议）

- 端口 25（明文）、465（SMTPS）、587（提交）。
- 用于**发送**邮件，从客户端到服务器，以及服务器之间中继。
- 命令：HELO/EHLO、MAIL FROM、RCPT TO、DATA、QUIT。

```
smtp                                     # SMTP 流量
smtp.req.command == "MAIL FROM"          # 发件人
smtp.req.command == "RCPT TO"            # 收件人
```

### 24.2.2 POP3（邮局协议 v3）

- 端口 110（明文）、995（POP3S）。
- 用于**接收**邮件，下载到本地后通常删除服务器副本。
- 命令：USER、PASS、LIST、RETR、QUIT。

### 24.2.3 IMAP（互联网消息访问协议）

- 端口 143（明文）、993（IMAPS）。
- 用于**接收**邮件，支持服务器端邮件管理（文件夹、搜索、标记），比 POP3 更强大。

> **安全提示**：明文的 SMTP/POP3/IMAP 会暴露邮件内容和登录凭据。现代邮件服务普遍使用 SSL/TLS 加密（端口 465/995/993 或 STARTTLS）。

## 24.3 SSH（安全外壳协议）

- 端口 22。
- 加密的远程登录和命令执行协议，替代不安全的 Telnet。
- Wireshark 能看到 SSH 握手版本字符串和加密后的数据包，但看不到命令内容。
- SSH 也用于 SFTP（安全文件传输）和端口转发。

```
ssh                                      # SSH 流量
ssh.protocol                             # SSH 版本字符串
```

SSH 分析通常只能确认「有 SSH 连接」，无法看到内容（除非有密钥）。在安全分析中，异常的 SSH 连接（大量来自同一 IP、非工作时间）值得关注。

## 24.4 Telnet（远程登录，已过时）

- 端口 23。
- 明文传输，包括用户名、密码和所有命令。
- **极易被窃听**，已被 SSH 取代。如果在网络中发现 Telnet 流量，通常是安全隐患。

```
telnet                                   # Telnet 流量
telnet.data                              # Telnet 数据
```

在 Wireshark 中 Follow TCP Stream 可以看到完整的登录过程（包括明文密码），是很好的安全教学素材。

## 24.5 SNMP（简单网络管理协议）

- 端口 161（查询）、162（Trap 告警）。
- 用于网络设备（路由器、交换机、服务器）的管理和监控。
- 版本：SNMPv1/v2c（明文团体字，不安全）、SNMPv3（加密认证）。
- 数据以 OID（对象标识符）形式组织，通过 MIB 库解析为可读名称。

```
snmp                                     # SNMP 流量
snmp.community                           # 团体字（v1/v2c 的"密码"）
```

Wireshark 会根据 MIB 库把 OID 解析为名称（如 `1.3.6.1.2.1.1.1.0` → `sysDescr.0`）。SNMPv2c 的团体字是明文传输的，泄露后攻击者可读取设备信息甚至修改配置。

## 24.6 NTP（网络时间协议）

- 端口 123，基于 UDP。
- 用于网络设备的时间同步。
- 对日志分析、安全取证至关重要（时间一致性是关联分析的基础）。

```
ntp                                      # NTP 流量
ntp.mode                                 # NTP 模式（客户端/服务器/广播）
```

NTP 也曾被用于放大攻击（NTP Amplification），是 DDoS 的一种手段。

## 24.7 LDAP（轻量目录访问协议）

- 端口 389（明文）、636（LDAPS）。
- 用于访问目录服务（如 Active Directory），查询用户、组、组织信息。
- Windows 域环境中大量使用。

```
ldap                                     # LDAP 流量
ldap.query                               # LDAP 查询
ldap.baseObject                          # 查询基准 DN
```

LDAP 分析在排查域认证问题、检测 LDAP 注入/枚举攻击时有用。

## 24.8 SMB（服务器消息块协议）

- 端口 445（直接 TCP）、139（NetBIOS）。
- 用于 Windows 文件共享、打印机共享、命名管道。
- SMBv1 已被证明不安全（永恒之蓝等漏洞），应使用 SMBv2/v3。

```
smb || smb2                              # SMB 流量
smb2.cmd                                 # SMB2 命令
```

SMB 流量分析在排查文件共享问题、检测勒索软件的横向移动（如通过 SMB 传播）时很重要。

## 24.9 其他值得了解的协议

| 协议 | 端口 | 用途 |
| --- | --- | --- |
| RDP | 3389 | Windows 远程桌面 |
| VNC | 5900 | 图形远程桌面 |
| SIP | 5060 | VoIP 信令 |
| RTP | 动态 | VoIP 语音数据 |
| MQTT | 1883 | 物联网消息传输 |
| CoAP | 5683 | 受限设备 Web 协议 |
| Modbus | 502 | 工业控制协议 |
| MySQL | 3306 | 数据库 |
| Redis | 6379 | 缓存/数据库 |

Wireshark 对以上协议都有解析能力。物联网和工控协议（MQTT、Modbus）的解析是 Wireshark 的特色功能之一。

## 24.10 小结

- FTP 用控制连接（21）+ 数据连接（主动 20 / 被动动态），明文不安全。
- 邮件协议：SMTP（发送，25/465/587）、POP3（接收，110/995）、IMAP（接收，143/993）。
- SSH（22）加密远程登录，Telnet（23）明文已淘汰。
- SNMP（161/162）网络管理，v1/v2c 团体字明文，v3 安全。
- NTP（123）时间同步，对日志分析很重要。
- LDAP（389/636）目录服务，Windows 域环境常用。
- SMB（445）文件共享，注意 SMBv1 的安全风险。
