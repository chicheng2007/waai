# 第二十七章 流量图与图表

本章深入 Wireshark 的可视化分析工具：Flow Graph（流量图）、TCP Stream Graphs（TCP 流图表）和 I/O Graph 的高级用法。图表能把抽象的数据变成直观的趋势，是发现性能问题和理解协议交互的利器。

## 27.1 Flow Graph（流量图）

菜单 `Statistics → Flow Graph`。

### 27.1.1 配置选项

- **Flow type**：
  - **All packets**：显示所有包。
  - **Displayed packets**：只显示当前过滤后的包。
  - **Any relay**：指定中继节点。
- **Address type**：IP、MAC、端口等。
- **Node addresses**：选择显示在图上的地址字段。
- **Display**：可选择显示协议、时间、序号等信息。

### 27.1.2 解读流量图

流量图中，每个参与者是一条竖线，包用箭头表示：

```
  Client              Server
    |                   |
    |----[SYN]--------->|
    |<---[SYN,ACK]------|
    |----[ACK]--------->|
    |----[GET /]------->|
    |<---[200 OK]-------|
    |<---[FIN,ACK]------|
    |----[ACK]--------->|
```

**用途**：

- 验证协议交互顺序是否正确。
- 发现异常的包顺序（如乱序、重复）。
- 展示给非技术人员看时非常直观。

## 27.2 TCP Stream Graphs（TCP 流图表）

菜单 `Statistics → TCP Stream Graphs`，这是 TCP 性能分析的强大工具集。使用前需要先选中一个 TCP 包（Wireshark 会自动识别其所属的流）。

### 27.2.1 Time-Sequence Graph（时序图）

展示序列号随时间的变化：

- 横轴：时间。
- 纵轴：序列号（相对）。
- 正常的发送是一条平稳上升的曲线。
- **平缓的斜线**：稳定的数据传输，斜率即吞吐量。
- **水平线**：停顿（可能在等待 ACK 或超时）。
- **曲线突然跳跃**：重传或快速重传。
- **阶梯状**：交互式应用（如 SSH，数据量小且间歇）。

### 27.2.2 Throughput Graph（吞吐量图）

展示吞吐量随时间的变化（字节/秒）：

- 观察实际传输速率。
- 发现速率骤降的时间点。
- 评估链路性能是否符合预期。

### 27.2.3 Round Trip Time Graph（往返时间图）

展示 RTT 随时间的变化：

- 稳定的低 RTT：健康的网络。
- RTT 突然增大：网络拥塞、路由变化、处理延迟。
- RTT 剧烈波动（抖动）：对实时应用（VoIP、视频）影响大。

### 27.2.4 Window Size Graph（窗口大小图）

展示接收窗口随时间的变化：

- 窗口持续很小：接收方处理慢，可能成为瓶颈。
- 窗口降为 0：接收方缓冲区满（零窗口），发送方暂停。
- 窗口逐步增大：慢启动过程。

### 27.2.5 TCP Trace（tcptrace）图

综合视图，同时展示数据和 ACK 的流动，包含时序、RTT、窗口等多维度信息。适合深入分析复杂的 TCP 行为。

## 27.3 I/O Graph 高级用法

I/O Graph 支持添加多条曲线，每条用独立的显示过滤器：

```
曲线1：tcp               # 所有 TCP 流量
曲线2：tcp.analysis.retransmission   # 重传
曲线3：udp.port == 53    # DNS
```

**分析技巧**：

- 把「总流量」和「重传」画在一起，看重传是否与流量峰值相关（拥塞导致丢包 → 重传）。
- 对比不同协议的流量随时间的变化。
- 设置 Y 轴单位（packets/s、bytes/s、bits/s）。
- 设置时间区间（1 秒、10 秒等）来观察不同粒度。

## 27.4 图表分析实战案例

### 案例：文件传输很慢

1. 选中一个 TCP 流，打开 Throughput Graph。
2. 发现吞吐量周期性骤降。
3. 打开 Window Size Graph，看到接收窗口周期性降到很小。
4. 结论：接收方应用处理慢，窗口小限制了吞吐量（接收方瓶颈），而非网络问题。

### 案例：视频会议卡顿

1. 打开 RTT Graph，发现 RTT 从 30ms 波动到 300ms。
2. 打开 I/O Graph，发现波动时刻总流量激增。
3. 结论：网络拥塞导致延迟抖动，影响实时应用。

## 27.5 小结

- Flow Graph 图形化展示包交互顺序，验证协议流程。
- TCP Stream Graphs 包括时序图、吞吐量图、RTT 图、窗口图、tcptrace 图。
- 时序图看序列号变化识别重传/停顿；吞吐量图看速率；RTT 图看延迟；窗口图看流量控制。
- I/O Graph 可叠加多条过滤器曲线，对比分析。
- 图表分析的关键是「从图表定位异常时间点，回到列表看具体包」。
