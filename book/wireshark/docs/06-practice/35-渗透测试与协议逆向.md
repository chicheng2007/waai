# 第三十五章 渗透测试与协议逆向

本章介绍 Wireshark 在渗透测试和协议逆向中的应用。这两个场景中，Wireshark 既是观察工具，也是理解未知系统的窗口。

> **法律与道德提示**：渗透测试必须在明确的书面授权下进行。协议逆向应遵守相关法律法规和软件许可协议。

## 35.1 渗透测试中的 Wireshark

### 35.1.1 信息收集阶段

- 被动收集：抓取目标网络的广播流量、ARP、mDNS、SSDP 等，发现存活主机和服务。
- 分析泄漏信息：明文协议泄露的用户名、主机名、共享名、版本信息。

过滤器示例：

```
arp || mdns || ssdp || nbns          # 局域网发现协议
```

### 35.1.2 漏洞利用阶段

- 验证 Exploit 是否成功发送了预期的包。
- 观察目标服务的响应，判断漏洞是否触发。
- 分析崩溃前的最后一个包，辅助调试。

### 35.1.3 后渗透阶段

- 观察内网的横向移动（SMB、RDP、WMI 连接）。
- 检查凭据传输（明文协议的密码、NTLM 哈希）。
- 发现内网其他主机和服务。

### 35.1.4 清理验证

- 确认后门通信是否正常。
- 检查是否留下可追踪的流量特征。

## 35.2 CTF 中的流量分析

CTF（Capture The Flag）竞赛的 Misc/Forensics 方向经常出现流量分析题。常见题型：

### 35.2.1 直接找 Flag

- 用 `Ctrl + F` 在包中搜索 `flag`、`ctf`、关键字。
- 搜索模式选择「String」，在整个抓包中搜索。

### 35.2.2 协议还原

- HTTP 传输的文件：`Export Objects → HTTP`。
- FTP 传输的文件：`Follow TCP Stream` 或 `Export Objects → FTP-DATA`。
- 从 TCP 流中提取数据：Follow Stream，另存为二进制。

### 35.2.3 隐藏数据

- 数据藏在协议字段中（如 IP ID、TCP 序号、TTL 的最低字节）。
- 数据藏在包的时间间隔中（莫尔斯电码等）。
- 数据藏在 DNS 查询名中（DNS 隧道）。
- 数据藏在 ICMP 的载荷中。

### 35.2.4 加密/编码

- 提取数据后需要解码：Base64、Hex、ROT13、异或等。
- 可能需要从流量中找到密钥（如 TLS 密钥、加密密钥）。

### 35.2.5 解题技巧

1. 先看 Protocol Hierarchy，了解有哪些协议。
2. 关注不常见的协议或异常字段。
3. Follow Stream 还原会话。
4. 导出所有对象，逐个检查。
5. 用 tshark 提取字段值，分析规律。
6. 注意统计特征（包长度、时间间隔、序号）。

## 35.3 协议逆向基础

协议逆向是指通过分析流量，推断未知协议的结构和语义。这在分析私有协议、恶意软件通信、物联网设备协议时很有用。

### 35.3.1 逆向步骤

1. **收集样本**：在可控环境下产生多组通信流量（正常操作、不同命令）。
2. **观察整体**：识别使用的传输层协议（TCP/UDP）、端口、通信模式（请求—响应/推送）。
3. **识别边界**：找出消息的起始和结束（固定长度？长度字段？分隔符？）。
4. **分析字段**：对比多个样本，找出固定字段、变化字段。
   - 固定值：可能是魔数、版本、命令码。
   - 变化值：可能是序列号、时间戳、长度、校验和。
5. **推断语义**：结合操作行为，推断字段含义（如发送「打开」命令后某个字段变化）。
6. **验证假设**：构造包发送给设备，观察响应是否符合预期。

### 35.3.2 实用技巧

- **多次对比**：同一操作执行多次，看哪些字节恒定、哪些变化。
- **单变量法**：每次只改变一个输入，观察流量中对应的变化。
- **关注长度字段**：找到长度字段就能确定消息边界。
- **识别常见编码**：ASCII 字符串、整数（大端/小端）、校验和（CRC32、MD5）。
- **利用字节窗格**：选中字段看高亮的字节，对照协议树。

### 35.3.3 编写自定义 Dissector

当你理解了协议结构，可以编写 Lua Dissector 让 Wireshark 解析它（见第三十六章）。这样后续分析就方便多了。

## 35.4 实战案例：分析一个未知 TCP 协议

假设发现某设备通过 TCP 端口 9999 通信，你想理解其协议。

**步骤**：

1. 抓包，过滤 `tcp.port == 9999`。
2. Follow TCP Stream，观察载荷的十六进制和 ASCII。
3. 发现每条消息以 `AA BB` 开头（魔数），接下来 2 字节是长度，再后面是数据。
4. 对比多条消息，发现长度字段后是 ASCII 命令（如 `OPEN`、`CLOSE`、`STATUS`）。
5. 最后 4 字节可能是 CRC32 校验和。
6. 推断协议格式：`魔数(2) + 长度(2) + 命令(变长) + 校验和(4)`。
7. 编写 Dissector 验证（第三十六章）。

## 35.5 小结

- 渗透测试中 Wireshark 用于信息收集、验证利用、后渗透观察。
- CTF 流量分析题：找 Flag、协议还原、隐藏数据、解码。
- 解题技巧：看协议分布、Follow Stream、导出对象、tshark 提取、注意统计特征。
- 协议逆向步骤：收集样本 → 观察整体 → 识别边界 → 分析字段 → 推断语义 → 验证。
- 对比法和单变量法是推断字段含义的核心技巧。
