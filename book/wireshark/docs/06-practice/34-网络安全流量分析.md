# 第三十四章 网络安全流量分析

Wireshark 是安全分析师的必备工具。本章介绍常见的攻击行为在流量中的特征，以及如何用 Wireshark 检测扫描、暴力破解、恶意软件通信、数据泄露等安全事件。

> **法律与道德提示**：本章知识仅用于授权环境下的安全防御、检测和合法的渗透测试。未经授权监控、分析他人网络流量是违法的。

## 34.1 流量分析在安全中的价值

- **检测**：发现网络中的异常行为和攻击迹象。
- **取证**：还原攻击过程，作为电子证据。
- **溯源**：追踪攻击来源、影响范围。
- **狩猎（Threat Hunting）**：主动搜索潜伏的威胁。

## 34.2 网络扫描的检测

### 34.2.1 端口扫描

攻击者用扫描器（如 Nmap）探测目标开放的端口。特征：

- 短时间内大量不同目的端口的 SYN 包，来自同一源。
- SYN 扫描：`tcp.flags.syn == 1 && tcp.flags.ack == 0`。
- 大量 RST 响应（端口关闭）：`tcp.flags.reset == 1`。

检测过滤器：

```
tcp.flags.syn == 1 && tcp.flags.ack == 0    # 大量 SYN
ip.src == 可疑IP && tcp.flags.syn == 1
```

分析技巧：用 Conversations 或 Endpoints 统计，看某个 IP 是否连接了大量不同端口。

### 34.2.2 主机发现（Ping Sweep）

攻击者 ping 整个网段寻找在线主机。特征：

- 短时间内 ICMP Echo Request 发往大量不同 IP。
- 过滤 `icmp.type == 8`，看目的 IP 分布。

### 34.2.3 操作系统指纹识别

Nmap 等工具发送特制的畸形包，根据响应推断操作系统。特征：异常的标志位组合、异常 TTL、特殊 TCP 选项。

## 34.3 暴力破解的检测

### 34.3.1 SSH/FTP/RDP 暴力破解

特征：

- 大量连接尝试，每次认证失败。
- 短时间内来自同一 IP 的大量登录请求。

过滤器示例：

```
tcp.port == 22 && tcp.len > 0           # SSH 数据
ftp.request.command == "USER"           # FTP 登录尝试
```

SSH 是加密的，看不到用户名密码，但可以看到连接频率和会话数量。FTP/Telnet 明文，可以看到尝试的用户名和密码。

### 34.3.2 Web 登录爆破

特征：大量 POST 请求到登录接口，来自同一 IP 或 UA。

```
http.request.method == "POST" && http.request.uri contains "login"
```

结合 HTTP 统计看请求频率和来源分布。

## 34.4 恶意软件通信检测

### 34.4.1 C2（命令与控制）通信

- **心跳包**：定期（如每 60 秒）发送小包到 C2 服务器。
- **异常域名**：DGA（域名生成算法）产生的随机域名，查询大量不存在的域名（NXDOMAIN）。
- **异常端口**：非标准端口上的持续连接。

检测思路：

```
dns.flags.response == 1 && dns.resp.code == 3     # NXDOMAIN（域名不存在）
len(dns.qry.name) > 40                            # 超长随机域名
```

### 34.4.2 DNS 隧道

攻击者把数据编码到 DNS 查询的子域名或 TXT 记录中外传。特征：

- 超长子域名、高熵（随机）的域名。
- 大量 TXT 记录查询。
- 同一域名的大量子域查询。

过滤器：

```
len(dns.qry.name) > 50
dns.qry.type == 16
```

### 34.4.3 数据外泄

- 异常大的出站流量（尤其到陌生 IP）。
- 非工作时间的大量数据传输。
- 传输到非常见协议端口的数据。

用 Conversations 按字节排序，找出流量最大的出站会话。

## 34.5 Web 攻击检测

### 34.5.1 SQL 注入

HTTP 请求中包含 SQL 关键字：

```
http.request.uri contains "SELECT"
http.request.uri contains "UNION"
http.request.uri contains "1=1"
http contains "OR 1=1"
```

### 34.5.2 XSS（跨站脚本）

```
http.request.uri contains "<script"
http contains "alert("
```

### 34.5.3 目录遍历

```
http.request.uri contains "../"
http.request.uri contains "%2e%2e"
```

### 34.5.4 WebShell 通信

- 异常 POST 请求到 .php/.jsp 路径。
- 请求和响应中包含 base64 编码、eval、system 等特征。

## 34.6 拒绝服务攻击（DoS/DDoS）

- **SYN Flood**：大量 SYN 包，无后续 ACK，耗尽服务器连接队列。
  - `tcp.flags.syn == 1 && tcp.flags.ack == 0` 的数量异常。
- **UDP Flood**：大量 UDP 包耗尽带宽。
- **HTTP Flood**：大量 HTTP 请求耗尽 Web 服务器资源。
- **反射放大攻击**：利用 DNS/NTP/SSDP 服务器放大流量（伪造源地址为受害者）。

用 I/O Graph 看流量峰值，用 Endpoints 找攻击源。

## 34.7 分析工作流

安全事件响应的流量分析流程：

1. **确认范围**：受影响主机、时间段。
2. **宏观分析**：Protocol Hierarchy、Conversations、Endpoints 找异常。
3. **微观分析**：针对可疑会话，Follow Stream 看内容。
4. **特征提取**：提取攻击的 IoC（IP、域名、文件哈希、User-Agent）。
5. **关联分析**：结合日志、威胁情报验证。
6. **报告**：整理证据链。

## 34.8 小结

- 扫描检测：大量 SYN、ICMP Sweep、异常标志组合。
- 暴力破解：大量登录尝试，SSH 看频率、FTP 看明文凭据。
- C2 通信：定期心跳、DGA 域名、NXDOMAIN、异常端口。
- DNS 隧道：超长子域名、大量 TXT 查询。
- Web 攻击：URI 中的 SQL/XSS/遍历特征。
- DDoS：流量峰值、SYN Flood、反射放大。
- 安全分析流程：范围 → 宏观 → 微观 → IoC → 关联 → 报告。
