# 第三十二章 网络故障排查方法论

前面我们学习了 Wireshark 的各种功能，本章开始进入实战。网络故障排查不是随意地翻包，而是有一套系统的方法论。掌握这套方法，你才能从海量数据中快速定位问题。

## 32.1 排查的基本原则

### 32.1.1 先问清问题

在抓包之前，先问清楚：

- 什么现象？（打不开？慢？间歇性？）
- 什么时候发生的？持续多久？
- 影响范围？（单人？全网？特定应用？）
- 最近有什么变更？（配置、设备、上线？）
- 能否复现？

这些问题的答案决定了抓包策略。

### 32.1.2 自顶向下 vs 自底向上

- **自顶向下**：从应用层开始排查（先看 HTTP 状态码，再看 TCP，再看网络）。适合应用层故障。
- **自底向上**：从物理层开始（先确认链路通，再看 IP，再看传输）。适合连通性问题。
- **分而治之**：从中间层（网络层 ping、传输层 telnet 端口）开始，快速定位在哪一层出问题。

### 32.1.3 抓包位置很关键

- **问题主机上抓**：看该主机发出和收到的包。
- **服务器端抓**：看服务器是否收到请求、是否响应。
- **中间设备抓**（如网关、防火墙）：看流量是否经过、是否被拦截。
- **两端都抓**：对比两端抓包，定位问题发生在哪一段（这招非常有效）。

## 32.2 抓包策略

### 32.2.1 抓全量还是过滤

- 问题明确（如「访问某网站失败」）：用捕获过滤器缩小范围，如 `host 目标IP`。
- 问题模糊（如「网络时好时坏」）：先抓全量，事后用显示过滤器分析。
- 高速网络：考虑只抓首部（snaplen）或用环形缓冲。

### 32.2.2 抓多长时间

- 能复现的问题：复现前后各抓一段时间。
- 间歇性问题：用环形缓冲长时间抓，问题发生后立即停止保存。
- 偶发问题：可能需要多次、长时间抓包。

### 32.2.3 避免干扰

- 关闭后台自动更新、云同步等产生无关流量的程序。
- 关闭 Wireshark 的 IP 反向名称解析（避免 DNS 查询干扰）。
- 确认抓包主机本身性能足够（避免抓包丢包）。

## 32.3 分析流程

拿到抓包文件后，按以下流程分析：

### 步骤一：了解概况

- `capinfos` 或状态栏：时长、包数、大小。
- Protocol Hierarchy：协议分布。

### 步骤二：定位关键流量

- 用显示过滤器筛出相关流量（按 IP、端口、协议）。
- Conversations 找出相关会话。

### 步骤三：检查连接建立

- TCP：三次握手是否成功？有无 RST？
- DNS：解析是否成功？返回什么 IP？
- ARP：是否解析到正确 MAC？

### 步骤四：检查数据传输

- 有无重传、乱序、重复 ACK？
- 序列号/确认号是否连续？
- 窗口是否正常？

### 步骤五：检查连接关闭

- 正常四次挥手，还是 RST 异常终止？

### 步骤六：综合判断

- 结合专家信息、统计图表、时间线，形成结论。

## 32.4 常见故障类型的排查路径

### 32.4.1 完全不通

```
检查物理连接 → ARP 是否正常 → DNS 是否解析 → TCP 握手是否完成 → 应用是否响应
```

### 32.4.2 时通时断

```
看丢包/重传 → 看是否有周期性中断 → 看设备日志 → 看是否负载均衡切换
```

### 32.4.3 慢

```
看 RTT → 看重传率 → 看窗口 → 看服务器响应时间 → 看带宽利用率
```

## 32.5 排查中的思维陷阱

- **不要先入为主**：不要带着预设结论去看包，容易选择性忽略反证。
- **注意抓包本身的影响**：Wireshark 可能改变网络行为（如名称解析的 DNS 查询、混杂模式）。
- **区分因果**：重传可能是原因，也可能是结果（拥塞的后果）。
- **注意时间同步**：两端抓包时，主机时间可能不同步，影响对比。
- **多点验证**：单点的抓包可能不全面，重要结论要多点验证。

## 32.6 工具配合

Wireshark 不是唯一工具，排查时配合使用：

- `ping` / `traceroute`：快速检查连通性和路径。
- `telnet` / `nc`：测试端口是否开放。
- `dig` / `nslookup`：测试 DNS。
- `curl -v`：测试 HTTP，显示详细过程。
- `netstat` / `ss`：查看本机连接状态。
- `tcpdump`：在服务器上快速抓包。

## 32.7 小结

- 排查前先问清问题现象、时间、范围、变更。
- 自顶向下/自底向上/分而治之三种思路灵活选择。
- 抓包位置决定能看到什么，两端对比是定位问题的有效手段。
- 分析流程：概况 → 定位流量 → 检查建立 → 检查传输 → 检查关闭 → 综合判断。
- 避免先入为主、注意抓包干扰、区分因果、多点验证。
